# 二叉搜索树BST

##  基本概念与定义
### 什么是二叉搜索树
二叉搜索树（Binary Search Tree，简称 BST），也常被称为二叉排序树、二叉查找树，是一种特殊的二叉树结构。它的核心设计思想是利用"左小右大"的性质，将数据组织成一棵便于快速查找的树。

**递归定义**：

+ 空树是一棵二叉搜索树
+ 若根节点的左子树非空，则**左子树上所有节点的值都小于根节点的值**
+ 若根节点的右子树非空，则**右子树上所有节点的值都大于根节点的值**
+ 根节点的左右子树本身也都必须是二叉搜索树

:::color1
注意：**<u><font style="color:#DF2A3F;">是左子树"所有节点"都小于根，而不仅仅是左孩子节点；右子树同理</font></u>**。这是 BST 最核心的不变式。

:::

### 关键性质
![](https://cdn.nlark.com/yuque/0/2026/png/42876865/1786515715436-cd3b30cd-ef60-47a9-bc7d-a9f8d336e518.png)

**最重要的推论**：**<u><font style="color:#DF2A3F;">对二叉搜索树进行中序遍历（左→根→右），得到的一定是一个严格递增的有序序列。</font></u>**

例如上图这棵树的中序遍历结果为：

```plain
9 → 15 → 19 → 23 → 27 → 31 → 37 → 42 → 50 → 58 → 67
```

这个性质非常重要，它是 BST 很多算法的基础，也是验证一棵树是否是合法 BST 的常用方法。

### BST 与堆的区别
很多同学容易把 BST 和堆（Heap）搞混，这里做个对比：

| 特性 | 二叉搜索树 (BST) | 二叉堆 (Heap) |
| :---: | :---: | :---: |
| **大小关系** | 左子树全 < 根 < 右子树全 | 根节点 ≥ 或 ≤ 所有子节点（全局） |
| **左右子树** | 有严格的大小区分 | 左右子树没有大小区分 |
| **最顶层元素** | 中值（相对中间大小） | 最大值（大顶堆）或最小值（小顶堆） |
| **遍历有序性** | 中序遍历全局有序 | 层序遍历满足堆序，不是全局有序 |
| **主要用途** | 动态查找、<font style="color:rgb(51, 51, 51);">有序遍历</font> | 优先队列、TopK 问题 |


### 存储结构
BST 通常采用二叉链表存储，每个节点包含数据域和两个指针域。C 语言描述如下：

```c
typedef int ElemType;  // 关键字类型，这里以int为例
typedef struct BSTNode {
    ElemType data;              // 数据域（关键字）
    struct BSTNode *lchild;     // 左孩子指针
    struct BSTNode *rchild;     // 右孩子指针
} BSTNode, *BSTree;
```

## 查找操作
[700. 二叉搜索树中的搜索 - 力扣（LeetCode）](https://leetcode.cn/problems/search-in-a-binary-search-tree/)

查找是 BST 最核心的操作，插入、删除等操作都建立在查找的基础上。

从根节点开始，逐层向下比较：

1. 如果树为空，直接返回查找失败
2. 将目标值与当前节点比较：
    - 相等 → 查找成功，返回该节点
    - 目标值 < 当前节点值 → 去左子树继续找
    - 目标值 > 当前节点值 → 去右子树继续找
3. 走到空指针还没找到 → 查找失败

![](示意图-查找过程.png)![](https://cdn.nlark.com/yuque/0/2026/png/42876865/1786516041849-b1238940-a251-4959-bee7-c72a5903f2c2.png)

**示例**：在上图的树中查找值为 31 的节点

1. 31 < 42 → 进入左子树（节点 23）
2. 31 > 23 → 进入右子树（节点 31）
3. 31 == 31 → 查找成功！总共比较了 3 次

**查找失败示例**：查找值为 55 的节点

1. 55 > 42 → 右子树（58）
2. 55 < 58 → 左子树（50）
3. 55 > 50 → 右子树（空）→ 查找失败，共比较 3 次



```c
// 在树T中查找key，成功返回节点指针，失败返回NULL
BSTNode* SearchBST(BSTree T, ElemType key) {
    if (T == NULL)
        return NULL;                // 空树，查找失败
    else if (key == T->data)
        return T;                   // 匹配成功
    else if (key < T->data)
        return SearchBST(T->lchild, key);  // 去左子树找
    else
        return SearchBST(T->rchild, key);  // 去右子树找
}
```

```c
BSTNode* SearchBST_NonRecur(BSTree T, ElemType key) {
    BSTNode *p = T;
    while (p != NULL && p->data != key) {
        if (key < p->data)
            p = p->lchild;   // 关键字更小，走左边
        else
            p = p->rchild;   // 关键字更大，走右边
    }
    return p;  // 找到返回节点，找不到返回NULL
}
```

## 插入操作
[701. 二叉搜索树中的插入操作](https://leetcode.cn/problems/insert-into-a-binary-search-tree/)

BST 的插入非常巧妙：**新插入的节点一定是叶子节点**。

过程：

1. 先按照查找逻辑从根往下走
2. 如果树中已存在相同关键字 → 插入失败（BST 一般不允许重复关键字）
3. 如果走到空指针（查找失败），这个位置就是插入点
4. 创建新节点挂到这个空位置上

![](示意图-插入.png)![](https://cdn.nlark.com/yuque/0/2026/png/42876865/1786518019425-8344112f-630f-44fe-896a-01cd2860e3bb.png)

**示例**：在树中插入值 25

1. 查找路径：42 → 23 → 31 → 27
2. 25 < 27，而 27 的左孩子为空 → 插入到这里
3. 新节点 25 成为 27 的左孩子，是叶子节点



**代码实现：**注意这里形参用了**引用类型 **`&T`，因为当树为空或者走到空指针时，我们需要直接修改父节点的指针（或者修改根指针本身）。

```c
// 插入成功返回1，失败（关键字已存在）返回0
int InsertBST(BSTree &T, ElemType key) {
    if (T == NULL) {
        // 走到空位置，创建新节点插入
        T = (BSTNode*)malloc(sizeof(BSTNode));
        T->data = key;
        T->lchild = T->rchild = NULL;
        return 1;
    }
    else if (key == T->data)
        return 0;  // 关键字已存在，不允许重复
    else if (key < T->data)
        return InsertBST(T->lchild, key);  // 插入到左子树
    else
        return InsertBST(T->rchild, key);  // 插入到右子树
}
```

> 为什么引用 `&T` 就能把节点挂上？因为递归调用走到 `T == NULL` 时，这个 T 不是普通的局部变量，它就是父节点那个指针的**别名**。给 T 赋值就是直接修改了父节点的左/右孩子指针。
>

## 构造（创建）二叉搜索树
构造 BST 非常简单：从空树开始，按照给定序列，逐个调用插入函数即可。

```c
void CreateBST(BSTree &T, ElemType arr[], int n) {
    T = NULL;  // 初始为空树
    for (int i = 0; i < n; i++) {
        InsertBST(T, arr[i]);  // 逐个元素插入
    }
}
```

**<u><font style="color:#DF2A3F;">同一组关键字，插入顺序不同，得到的 BST 形态可能完全不同！</font></u>**

例如用 7 个数字 `{15, 23, 31, 42, 50, 58, 67}`：

+ 按 `42, 23, 58, 15, 31, 50, 67` 插入 → 得到一棵矮胖的平衡树
+ 按 `15, 23, 31, 42, 50, 58, 67` 插入 → 得到一条右斜的单链
+ 按 `67, 58, 50, 42, 31, 23, 15` 插入 → 得到一条左斜的单链

这三种树的查找效率天差地别，我们在下一节详细分析。

## 删除操作
[450. 删除二叉搜索树中的节点 - 力扣（LeetCode）](https://leetcode.cn/problems/delete-node-in-a-bst/)

与插入节点类似，我们需要在删除操作后维持二叉搜索树的“左子树 < 根节点 < 右子树”的性质。首先，我们需要在二叉树中执行查找操作，获取待删除节点。接下来，根据待删除节点的子节点数量，删除操作需分为三种情况：

1. 当待删除节点的度为 0 时，表示待删除节点是叶节点，可以直接删除。 
2. 当待删除节点的度为 1 即只有左子树或右子树时，将待删除节点替换为其子节点即可。 
3. 当待删除节点的度为 2 即左右子树都存在时，我们无法直接删除它，而需要使用一个节点替换该节点。由于要保持二叉搜索树“左 < 根 < 右”的性质，因此这个节点可以是**右子树的最小节点（在右子树的最左下位置）或左子树的最大节点(左子树的最右下位置)，也就是该节点的中序前驱（或中序后继）。**

![](https://cdn.nlark.com/yuque/0/2026/png/42876865/1786518600824-e0baa1a9-303c-4f53-b23e-adbecccb854a.png)

删除节点代码**递归写法**：$ root $有左右子树，这时可以将 $ root $的后继节点（比 $ root $ 大的最小节点，即它的右子树中的最小节点，记为$ successor $）作为新的根节点替代 $ root $，并将 $ successor $ 从$ root $ 的右子树中删除，使得在保持有序性的情况下合并左右子树。

```c
TreeNode* deleteNode(TreeNode *root, int key) {
    if(root == NULL)  return NULL;
    if(root -> val < key){   
        root -> right = deleteNode(root -> right,key);
        return root;
    }   
    if(root -> val > key) {
        root -> left = deleteNode(root -> left,key);
        return root;
    }
    if(root -> val == key) {
        if(!root -> left && !root -> right) {   //情况1，被删除结点是叶节点，直接删除；
            delete root;  //释放被删除节点；
            return NULL;
        } 
        if(!root -> left) {   //情况2：被删除结点没有左子树，则直接返回其右子树；
            TreeNode *child = root->right;  //保存子树后释放当前节点；
            delete root; 
            return child;  
        } 
        if(!root->right) {    //情况3：被删除结点没有右子树，直接返回其左子树；
            TreeNode *child = root->left;  //保存子树后释放当前节点；
            delete root;  
            return child; 
        }
        TreeNode* successor = root -> right;   //用来寻找root的直接后继结点；
        while(successor -> left) {     //它的直接后继结点是它右子树的最左下结点；
            successor = successor -> left;
        }
        root -> val = successor -> val;  //复制后继值，避免直接移动节点造成指针错误；
        root -> right = deleteNode(root -> right, successor -> val);  //删除右子树中的重复后继节点；
        return root;  
    }
    return root;
}
```

删除示意图(删除17)：![](https://typora-darkmoon.oss-cn-nanjing.aliyuncs.com/image-20230818171250142.png)



当然也可以用当前结点的**直接前驱**来代替它，即它的左子树的最右下的结点；下面为关键部分的修改：

```c
TreeNode *predecessor = root->left;  //当前结点的直接前驱结点；
while (predecessor->right) {    //位于它的左子树最右下位置；
     predecessor= predecessor->right;
}
root->val = predecessor->val;  //复制前驱值，避免删除后继续访问已释放节点；
root->left = deleteNode(root->left, predecessor->val);  //删除左子树中的重复前驱节点；
return root; 
```

还有一种处理方式：若被删除节点有左右子树，将其左子树挂到其右子树的最左下结点的左子树位置，然后让该结点的右子树顶替他的位置，这样也可以删除该结点。

图例为下：由图可以看出，这样处理的话多次删除几个结点后，树就变成链表了，不推荐使用；



![](https://typora-darkmoon.oss-cn-nanjing.aliyuncs.com/image-20230818172944715.png)

```c
class Solution {
public:
    TreeNode* deleteNode(TreeNode* root, int key) 
    {
        if (root == nullptr)    return nullptr;
        if (key > root->val)    root->right = deleteNode(root->right, key);     // 去右子树删除
        else if (key < root->val)    root->left = deleteNode(root->left, key);  // 去左子树删除
        else    // 当前节点就是要删除的节点
        {
            if (! root->left)   return root->right; // 情况1，欲删除节点无左子
            if (! root->right)  return root->left;  // 情况2，欲删除节点无右子
            TreeNode* node = root->right;           // 情况3，欲删除节点左右子都有 
            while (node->left)          // 寻找欲删除节点右子树的最左节点
                node = node->left;
            node->left = root->left;    // 将欲删除节点的左子树成为其右子树的最左节点的左子树
            root = root->right;         // 欲删除节点的右子顶替其位置，节点被删除
        }
        return root;    
    }
};
```

:::color1
【注】：如果删除的结点位于叶子节点处，那么将其删除后再插入，树的形态与原来保持不变，因为BST插入结点后该结点成为叶子节点处，这个位置是唯一的；

          但是如果被删除的结点不是叶子节点，那么删除再插入其形态就会变化了，因为插入是在某个节点的左右空指针处，插入后它就成了叶子节点，而在原来的树中，它是非叶子节点；

:::

```c
class Solution {
public:
    TreeNode* deleteNode(TreeNode* root, int key) {
        TreeNode *cur = root, *curParent = nullptr;
        while (cur && cur->val != key) {
            curParent = cur;
            if (cur->val > key) {
                cur = cur->left;
            } else {
                cur = cur->right;
            }
        }
        if (!cur) {
            return root;
        }
        if (!cur->left && !cur->right) {
            cur = nullptr;
        } else if (!cur->right) {
            cur = cur->left;
        } else if (!cur->left) {
            cur = cur->right;
        } else {
            TreeNode *successor = cur->right, *successorParent = cur;
            while (successor->left) {
                successorParent = successor;
                successor = successor->left;
            }
            if (successorParent->val == cur->val) {
                successorParent->right = successor->right;
            } else {
                successorParent->left = successor->right;
            }
            successor->right = cur->right;
            successor->left = cur->left;
            cur = successor;
        }
        if (!curParent) {
            return cur;
        } else {
            if (curParent->left && curParent->left->val == key) {
                curParent->left = cur;
            } else {
                curParent->right = cur;
            }
            return root;
        }
    }
};
```

## 查找效率分析
和二分查找类似，我们用**平均查找长度 ASL** 来衡量 BST 的查找效率。

> 在查找运算中，需要对比关键字的次数称为查找长度，反映了查找操作的时间复杂度
>

![](示意图-效率对比.png)![](https://cdn.nlark.com/yuque/0/2026/png/42876865/1786545069664-60a0b727-4138-45d1-982f-f0ce9367ea1d.png)

**最好情况：平衡形态**

当插入顺序比较随机，树的形态比较匀称，接近完全二叉树时：

+ 树高约为 `⌊log₂n⌋ + 1`
+ 成功 ASL ≈ O(log₂n)
+ 查找效率和二分查找差不多

**最坏情况：单支树**

当插入序列本身有序（正序或逆序）时，BST 会退化成一条斜链：

+ 树高 = n
+ 成功 ASL = (n+1)/2 = O(n)
+ 查找效率和顺序查找一样低，完全失去了 BST 的优势

> 虽然最坏情况很差，但**数学上可以证明**：随机构造的 BST，平均查找长度仍然是 O(log₂n) 量级的，只是常数比平衡树稍大一些。
>
> 也正因为 BST 存在最坏退化的问题，后来才衍生出了**平衡二叉树（AVL树）**、**红黑树**等改进结构，保证树高始终是 O(log₂n)。
>

BST 和二分查找的平均时间复杂度都是 O(log₂n)，但二者适用场景不同：

| 对比维度 | 二分查找（有序顺序表） | 二叉搜索树（链式存储） |
| :---: | :---: | :---: |
| 存储结构 | 顺序存储（数组） | 链式存储 |
| 查找效率 | O(log₂n)，稳定 | O(log₂n) ~ O(n)，看树形 |
| 插入/删除 | O(n)，需要移动大量元素 | O(log₂n)，只需修改指针 |
| 适用场景 | 静态查找表，很少改动 | 动态查找表，频繁增删 |
| 判定树 | 唯一，形态固定 | 不唯一，随插入顺序变化 |


简单记忆：**静态用二分，动态用 BST**。





**考点与常见坑点总结**

1. **中序遍历有序**是 BST 的本质特征，给你一棵树问是不是 BST，直接中序遍历看是不是递增就行。
2. **插入的新节点一定是叶子**，这是 BST 插入的铁律。
3. **删除有双子树的节点**，用中序前驱（左子树最右）或中序后继（右子树最左）替换
4. **插入顺序决定树形**，同一个关键字集合可以对应多棵不同的 BST；但二分查找的判定树是唯一的。
5. **删除后再插入，树形可能改变**——这是很多同学想当然会错的点。
6. **BST 不允许重复关键字**，插入相同值会失败。如果需要重复值，可以约定放在左子树或右子树，但标准实现中都是不重复的。
