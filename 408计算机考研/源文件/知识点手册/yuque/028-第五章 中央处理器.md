### (二)指令执行过程
> 一条指令通常经历：
>
> 1. **取指**：根据 PC 从主存读取指令并送入 IR，同时更新 PC。
> 2. **译码**：分析操作码、寻址方式和寄存器编号。
> 3. **取数**：读取寄存器或主存中的源操作数。
> 4. **执行**：由 ALU 等部件完成运算。
> 5. **访存/写回**：按需要访问主存，并把结果写回寄存器或主存。
> 6. **检查异常和外部中断**：异常通常在执行指令时检测；外部中断通常在一条指令执行结束时采样和响应。 
>

### (三)数据通路的功能和基本结构
> 数据通路由两类元件组成：
>
> + **组合逻辑元件（操作元件）**：输出只取决于当前输入，如 ALU、加法器、移位器、多路选择器（MUX）等。
> + **时序逻辑元件（状态元件）**：能够保存状态，如 PC、IR、通用寄存器组、流水段寄存器等。
>
> 控制器发出的控制信号决定数据从哪里来、经过哪个操作元件、最后写入哪里。
>

### (四)控制器的功能和工作原理
控制器的任务是根据指令、时序信号和状态条件产生控制信号。常见实现方式如下：

|  | 硬布线控制器 | 微程序控制器 |
| :---: | :---: | :---: |
| 控制信号来源 | 组合逻辑电路直接产生 | 执行控制存储器中的微指令产生 |
| 速度 | 较快 | 较慢 |
| 设计与修改 | 复杂，修改和扩展困难 | 规整，修改和扩展较容易 |
| 常见应用 | RISC、高性能处理器 | 控制较复杂的指令系统 |

### (五)异常和中断机制
异常和中断都会使 CPU 暂停当前程序，转去执行相应的处理程序，但二者的来源和时点不同。

| 对比项 | 内部异常（exception） | 外部中断（interrupt） |
| :---: | :---: | :---: |
| 来源 | CPU 执行当前指令时在内部检测到 | CPU 外部设备或部件提出请求 |
| 与当前指令的关系 | 同步，通常由当前指令引起 | 异步，通常与当前指令无关 |
| 典型事件 | 除零、非法指令、缺页、越权、自陷 | 键盘输入、定时器到时、网卡收包 |
| 检测/响应时点 | 在当前指令执行过程中检测并按异常机制响应 | 通常在一条指令执行结束后采样并响应 |
| 能否屏蔽 | 不能用普通中断屏蔽位屏蔽 | 可分为可屏蔽中断和 NMI |


内部异常又分为：

| 类型 | 指令完成情况 | 处理后的典型返回位置 | 例子 |
| :---: | :---: | :---: | :---: |
| **故障（fault）** | 指令尚未成功完成 | 返回故障指令并重新执行 | 缺页、某些保护异常 |
| **陷阱（trap）** | 指令已经完成 | 返回下一条指令 | 系统调用、自陷、断点、单步 |
| **终止（abort）** | 发生严重且通常不可恢复的错误 | 一般不返回原程序 | 严重硬件故障 |

### (六)指令流水线
把一条指令的执行过程划分为 $ k $ 个功能段，并让多条指令在不同功能段中重叠执行，就形成了指令流水线。经典五段流水线为：

| 阶段 | 英文缩写 | 主要工作 |
| :---: | :---: | :---: |
| 取指 | IF | 根据 PC 读取指令，更新 PC |
| 译码/取数 | ID | 译码并读取寄存器操作数 |
| 执行 | EX | ALU 运算、有效地址计算或分支判断 |
| 访存 | MEM | 读取或写入数据存储器 |
| 写回 | WB | 把结果写入通用寄存器 |


常用公式如下：

+ 若忽略流水段寄存器延时，时钟周期至少为：$ T_{clk}\ge \max(t_1,t_2,\ldots,t_k) $
+ 若流水段寄存器延时为 $ t_r $，则：$ T_{clk}\ge \max(t_1,t_2,\ldots,t_k)+t_r $
+ $ k $ 级流水线连续执行 $ n $ 条指令且无阻塞时，总周期数为：$ k+n-1 $
+ 若执行过程中额外插入 $ s $ 个阻塞周期，则总时间为：$ T=(k+n-1+s)T_{clk} $
+ 实际吞吐率为 $ TP=n/T $；流水线稳定充满后的理想最大吞吐率为 $ 1/T_{clk} $。

#### 指令流水线的基本实现
#### 结构冒险、数据冒险和控制冒险的处理
| 冒险类型 | 产生原因 | 常用处理方法 |
| :---: | :---: | :---: |
| 结构冒险 | 多条指令同时争用同一硬件资源 | 增加/分离资源，或阻塞 |
| 数据冒险 | 后续指令所需数据尚未产生 | 转发、阻塞、编译调度、插入 `nop` |
| 控制冒险 | 分支结果或目标地址尚未确定 | 阻塞、分支预测、延迟分支、推测执行 |


数据相关通常包括：

+ **RAW（写后读，真相关）**：前指令写，后指令读；基本顺序流水线最需要处理的类型。
+ **WAR（读后写，反相关）**：前指令读，后指令写。
+ **WAW（写后写，输出相关）**：两条指令写同一位置。

在按序发射、按序执行、按序写回的经典五段流水线中，WAR 和 WAW 的操作次序不会颠倒，通常不会形成实际冒险；乱序执行处理器则必须处理它们。
