# 第七章  总线

## 7.1 总线概述
计算机的所有功能都是通过CPU执行指令实现的，而在执行指令的过程中，CPU、存储器和	IO 模块之间要不断地进行数据交换，所以，计算机所有功能的实现过程实际上是各种信息在计算机各部件间的交换过程。而在早期，各部件之间的信息交换通过专门的连线来进行，这种**分散连接方式**使得部件间数据交换的情况非常复杂，**在同一时间，每个部件都只能和一个部件交换信息**。随着计算机的不断发展，IO设备的种类和数量也不断增加，这种连接方式不但效率低下而且变得难以扩展，所以出现了**总线方式**。

![](https://cdn.nlark.com/yuque/0/2024/png/42876865/1731487277063-17e6fc56-666b-44f5-bf56-5333505b3e85.png)

**总线是实现多个部件之间数据交换的一组共享的信息传输线**，它具有**<font style="color:#DF2A3F;">分时</font>**和**<font style="color:#DF2A3F;">共享</font>**两个特点。

+ **<font style="color:#DF2A3F;">分时</font>**是指当多个设备挂接到总线上时，**同一时刻只能有一个设备向总线发送信息**，其他设备必须等待其他时间。
+ **<font style="color:#DF2A3F;">共享</font>**是指总线上挂接的多个设备**可以在不同的时间向总线发送信息，**并且能够同时从总线上接收相同的信息。

### 按功能层次划分
#### <font style="color:#DF2A3F;">片内总线</font>
片内总线是指芯片内部各组成部分之间的连接线，如CPU芯片内部**寄存器之间**、**寄存器与运算器(ALU)之间**的数据通路连接及**控制器与执行部件之间**的控制信号连接均属于片内总线。

![这根白色的内总线即片内总线](https://cdn.nlark.com/yuque/0/2024/png/42876865/1719405608257-309df45a-ddd5-4788-b8ff-e6b4115585a9.png)

#### <font style="color:#DF2A3F;">系统总线</font>
+ 计算机系统内各功能部件(**CPU、主存、IO接口（或各种IO模块）)之间**相互连接的总线。按系统总线传输信息内容的不同，又可分为3类：数据总线、地址总线和控制总线。（通常我们所说的总线是指这类总线）

![](https://cdn.nlark.com/yuque/0/2024/png/42876865/1731489096190-ecb27cea-472b-43a7-93bb-4c190ee7a7c3.png)

    1. **<font style="color:#DF2A3F;">数据总线</font>**：用来在各功能部件之间传输数据信息，这里的数据包括：
        * 程序运行时CPU和主存之间交换的**数据或指令**；
        * CPU从IO接口获取的**状态信息，中断类型号等信息**；
        * CPU向IO接口发出的**控制命令**；
        * **地址信息**（此时地址线和数据线复用）等

#### I/O总线
主要**用于连接中低速的 I/O 设备**，通过 I/O 接口与系统总线相连接，目的是**将低速设备与高速总线分离**，以提升总线的系统性能，常见的有SATA、PCI总线。或者说**用于各种外设控制器(即 I/O 接口，如显卡、网卡等)与主机相连**，通常是标准总线，如PCI总线、AGP 总线、PCIExpress 总线等

#### 通信总线（外部总线）
计算机系统之间或计算机系统与其他系统(如远程通信设备、测试设备)之间传送信息的总线（常见的有USB总线），通信总线也称外部总线。相对外部总线，系统总线和 IO 总线也可以称为内部总线。

### 按数据传送方式分类
按照总线内部数据线数量和数据传送方式的不同，总线可以分为串行总线和并行总线

#### 串行总线
串行总线**只含有一条双向数据线或两条单向数据线**，传输数据时可以实现逐位按序分时传送。

串行传输数据的**优点**在于对数据线传输特性要求不高，数据线较长的情况下仍可有效传送数据，所以**串行总线更适合远距离通信**。大多数的**通信总线**属于串行总线。

#### 并行总线
并行总线**含有多条双向数据线，传输数据时可以实现多位同时传送**。

**优点**：数据传输效率高。

**缺点**：各条数据线特性很难完全一致，当数据线较长的情况下，数据各位有可能无法同时到达接收端，并且相邻的数据线之间还会相互干扰，从而造成传输错误，所以**并行总线适合近距离通信**。大多数的**系统总线**属于并行总线。

:::info
提示：

+ 对于串行总线和并行总线的传输速度比较，很多人可能会很自然的认为并行总线的传输速度更快，因为它可以同时传送多位。但实际上，由于并行接口有多条并行且紧密的导线，当时钟频率提高到一定程度时，并行导线相互之间会产生严重的干扰，从而导致其传输速度不一定比串行总线快。
+ 对于串行传输的总线，提高时钟速度比并行传输总线容易得多，且几乎没有线间串扰。因而**<font style="color:#DF2A3F;">串行传输总线的速度可以比并行传输总线快得多。</font>**

:::

### 按时序控制方式分类
按照总线上时序控制方式的不同，总线可以分为同步总线和异步总线

#### 同步总线
同步总线指总线上连接的各部件或设备**通过统一的时钟，在规定的时钟节拍内进行规定的总线操作**，从而完成部件或设备之间的数据传输。

#### 异步总线
异步总线指总线上连接的各部件或设备**没有统一的时钟，而是依靠各自内部的定时操作**，通过**信号握手**的方式来进行规定的总线操作，从而完成部件或设备之间的数据传输。

> 提示：半同步总线既可以采用同步方式进行通信，也可以采用异步方式进行通信。由于在异步总线中引入了时钟信号，这类总线的就绪信号和应答信号在时钟的上升沿或下降沿有效，所以不会受到其他时间的信号干扰。
>

## 7.3  总线结构
### 单总线结构
![](https://cdn.nlark.com/yuque/0/2024/png/42876865/1731517852877-dcec60b6-19ed-4572-8b2b-5ec85d7f247b.png)

单总线结构将 CPU、主存、I/O设备(通过I/O 接口)都挂在一组总线上，允许 I/O 设备之间、I/O 设备与主存之间直接交换信息，而无须经过中间设备的干预。

> 【注意】
>
> 1. 单总线并不是指只有一根信号线，系统总线按传送信息的不同可细分为地址总线、数据总线和控制总线。
> 2. 由于单总线结构中，主存与IO设备共用一组地址线，因此主存和IO设备是统一编址的，CPU采用访问主存的方式去访问外设（这是竟成书上的说法，该说法应该有误，可见下一条来自谭志虎教材的说法）
> 3. 除CPU外，**DRAM(即主存)和所有IO设备都必须进行编址，以便CPU可以通过地址和命令直接访问**。编址方式**<font style="color:#DF2A3F;">既可以采用统一编址方式，也可以采用独立编址方式</font>**，如 **BIOS ROM 就与内存 DRAM 进行统一编址，而I/O 设备既可以统一编址，也可以独立编址**，如果采用**独立编址方式则需要通过专用的输入输出指令进行访问**，Intel x86 指令集就采用这种方式。
> 4. **CPU 通常具有总线仲裁器的功能**，注意DMA 控制器出现后，CPU不再是唯一的主设备，DMA 控制器也可以作为主设备申请系统总线使用权。协调设备与主存进行DMA传输，这种方式又称为**第三方 DMA。**
>

+ **优点**：总线结构简单，易于扩充外设。
+ **缺点**：由于所有部件都共享这组总线，为了防止冲突，**同一时刻最多只能有一个部件向总线传输信息，**这使得系统的工作效率降低。因此，这类总线一般适用于小型计算机或微型计算机。

### 多总线结构（重要）
随着计算机技术不断发展，CPU性能不断提升，高速外部设备(如高速网络、高速视频图形设备等)也不断涌现，总线的结构也在不断变化，逐渐向高性能方向发展，其总体发展趋势包括以下几种。

如图，**北桥芯片**和**南桥芯片**这两块超大规模集成电路芯片组成一个“芯片组”，是计算机中**各个组成部分相互连接和通信的枢纽**。主板上所有的存储器控制功能和 I/O控制功能几乎都集成在该芯片组内，它既实现了总线的功能，又提供了各种 I/O接口及相关的控制功能。

+ **北桥**是一个**主存控制器集线器**(Memory Controller Hub，MCH)芯片，**本质上是一个DMA(Direct Memory Access)控制器**，因此，可通过 MCH 芯片直接访问主存和显卡中的显存。
+ **南桥**是一个**I/O控制器集线器**(I/O Controller Hub，ICH)芯片，其中可以集成 USB 控制器、磁盘控制器、以太网控制器等各种外设控制器，也可以通过南桥芯片引出若干主板扩展槽，用以接插一些 I/O 控制卡。

![](https://cdn.nlark.com/yuque/0/2024/png/42876865/1731521852439-943c2bc8-691a-4106-8bfd-94d164622cf3.png)

如图所示，CPU 与主存之间由处理器总线(也称为前端总线)和存储器总线相连，各类 I/O 设备通过相应的设备控制器(例如 USB 控制器、显示适配卡、磁盘控制器)连接到I/O 总线上，而I/O 总线通过芯片组与主存和 CPU 连接。

传统上，总线分为处理器-存储器总线和I/O总线。处理器-存储器总线比较短，通常是高速总线，有的系统将处理器总线和存储器总线分开，中间通过北桥芯片(桥接器)连接，CPU 芯片通过CPU插座插在处理器总线上**，内存条通过内存条插槽插在存储器总线上。**

#### 处理器总线
早期的 Intel 微处理器的**处理器总线**称为**前端总线**，它是主板上**最快的总线**，主要用作处理器与北桥芯片进行信息交换。

处理器总线的传输速率单位实际上是 MT/s，通常所说的**总线传输速率单位 MHz** 是习惯上的称呼，实质是**时钟频率单位**。**早期的CPU总线每个时钟传送一次数据，因此时钟频率与数据传输速率一致**。但是，从 Pentium Pro 开始，在**每个总线时钟周期内传4次数据**，也就是说，**总线的数据传输速率等于总线时钟频率的4倍**，若时钟频率为333MHz，则数据传输速率为 1333MT/S。

Intel 公司推出 Core i7 时，北桥芯片的功能被集成到了 CPU 芯片内，**CPU 通过存储器总线(即内存条插槽)直接和内存条相连**，而在 CPU 芯片内部的核与核之间、CPU 芯片与其他 CPU 芯片之间，以及 CPU 芯片与 IOH(Input/Output Hub)芯片之间，则通过 **QPI(Quick Path Interconnect)总线**相连。

![](https://cdn.nlark.com/yuque/0/2024/png/42876865/1731570190304-f5f58208-4fb7-4f64-a3ed-7e1dfc3d84e9.png)

**QPI总线**是一种基于包传输的串行高速点对点连接协议，采用差分信号与专门的时钟信号进行传输。QPI总线有 20条数据线，发送方(TX)和接收方(RX)有各自的时钟信号，**每个时钟周期传输两次**。一个 QPI数据包包含 80位，需要两个时钟周期或4次传输才能完成整个数据包的传送。在每次传输的 20 位数据中，有 16 位是有效数据，其余4位用于循环冗余校验，以提高系统的可靠性。

由于 **QPI是双向的，在发送的同时也可以接收另一端传输来的数据**，这样，每个 QPI总线的带宽计算公式如下：

:::info
$ 每秒传输次数×每次传输的有效数据×2 $

:::

QPI总线的速度单位通常为 GT/s，若 QPI的时钟频率为 2.4GHz，则速度为 4.8GT/s，表示每秒钟传输 4.8G 次数据，并称该 QPI频率为 4.8GT/s。因此，QPI频率为 4.8GT/s 的总带宽为 4.8GT/s<font style="color:rgb(25, 27, 31);">×</font>2B<font style="color:rgb(25, 27, 31);">×</font>2=19.2GB/s。QPI频率为 6.4GT/s的总带宽为 6.4GT/s<font style="color:rgb(25, 27, 31);">×</font>2B<font style="color:rgb(25, 27, 31);">×</font>2=25.6GB/s。（袁书的该示例是20年真题原题）

#### I/O总线
I/O 总线用于为系统中的各种 I/O设备提供输入输出通路，在物理上通常是主板上的一些 I/O扩展槽。

![](https://cdn.nlark.com/yuque/0/2024/png/42876865/1731573294293-6528232b-34ec-4ed0-8e7b-5d032fbb937e.png)

**<font style="color:#DF2A3F;">【重点介绍PCI Express】(17真题考察)</font>**

+ 与前两代 I/O总线采用并行传输的同步总线不同，PCI-Express 总线采用**<font style="color:#DF2A3F;">串行传输方式</font>**。
+ 两个 PCI-Express 设备之间以一个链路(link)相连，每个链路可包含多条通路(lane)，可能的通路数为 1、2、4、8、16 或 32，PCIExpress×n表示具有n个通路的 PCI-Express 链路。
+ **每条通路由发送和接收数据线构成**，在发送和接收两个方向上都各有两条差分信号线，**可同时发送和接收数据**。在发送和接收过程中，**每个数据字节实际上被转换成了 10 位信息被传输**，以保证所有位都含有信号电平的跳变。
+ <font style="color:rgb(77, 77, 77);">PCIe是一种</font><font style="color:rgb(254, 44, 36);">串行总线</font><font style="color:rgb(77, 77, 77);">，采用双向连接的方式，可同时收发，是一种</font><font style="color:rgb(254, 44, 36);">双单工连接</font><font style="color:rgb(77, 77, 77);">。</font>

![](https://cdn.nlark.com/yuque/0/2024/png/42876865/1731574371961-d2f9fcbd-5bce-4dcf-9c50-7fd6e3d546fb.png)

+ PCI-Express 1.0规范支持通路中每个方向的发送或接受速率为 2.5Gb/s。因此，PCIExpress 1.0 总线的总带宽计算公式(单位为 GB/s)为：$ 2.5Gb/s×2×通路数/10 $
+ 根据上述公式可知，在 PCI-Express 1.0 规范下，PCIExpressx1 的总带宽为 <font style="color:rgb(0,0,0);">2.5Gb/s * 2 * 1 / 10 =</font>0.5GB/s，PCI-Expressx2的总带宽为 1GB/s，PCI-Expressx16 的总带宽为 8GB/s。

## 7.4 总线的性能指标
1. **<font style="color:#601BDE;">总线宽度</font>**：它是指数据总线的根数，用位(bit)表示，如8位、16 位、32 位等。在并行传输总线中数据总线宽度直接决定了可并发传输的位数。
2. **<font style="color:#601BDE;">总线时钟频率</font>**：它是总线时钟周期的倒数，同步传输总线中传输双方拥有完全同步的时钟信号，时钟频率越快，传输速率越快：早期总线的时钟频率和 CPU 是同频的，后来 **CPU发展太快，总线时钟开始独立于 CPU 时钟。**
3. **<font style="color:#601BDE;">总线传输周期</font>**：指**一次总线操作完成所需要的时间，包括总线申请阶段、寻址阶段、传输阶段和结束阶段4个阶段的时间**，简称总线周期；通常包括多个总线时钟周期，总线的时钟频率越高，总线周期就越短：另外**如果采用地址复用技术，则会增加总线周期**。通常一个总线周期只能传输一个总线宽度的数据。

> + **<font style="color:#601BDE;">总线传输周期：</font>****在总线上完成一次总线事务所用的时间。通常由若干个总线时钟周期组成，简称为总线周期。**
>

4. **<font style="color:#601BDE;">单时钟传输次数</font>**：指一个总线时钟周期内传输数据的次数，通常该值为1；DDR技术在时钟上、下跳沿分别传输一次数据，该值为2；QDR技术下其值为4(总线内部时钟为两个相位相差 90°的时钟)。目前该值最高的是AGPx8总线，单时钟可以传输8次。**总线的实际工作频率=总线时钟频率x单时钟传输次数。**
5. **<font style="color:#601BDE;">总线带宽</font>**：指在总线上的最大数据传输速率，通常不考虑总线传输周期中总线申请和寻址等阶段的开销，单位是$ MB/s(MBps) $或$ GB/s $($ 1MB=10^6字节，1GB=10^9字节 $);注意通信领域和磁存储领域并没有使用1024作为基本单位。

**总线带宽计算公式如下：同步总线带宽=(总线宽度/8)x总线时钟频率*单时钟传输次数**

6. 总线负载能力：指总线上连接的设备数量。

### 总线复用技术
总线的信号线分为**专用**和**复用**两种。**专用信号线只用于传输一种信号**，系统总线的3种总线就是专用总线。而**复用总线**是**指一组传输线具有多种用途，用于分时传送不同类型的信息**。常见的有：

+ **地址总线和数据总线复用**，即地址总线和数据总线共用一组物理线缆，某一时刻该总线传输地址信号，另一时刻传输数据信号。总线复用技术可以减少引脚数目，PCI总线就是典型的复用总线。
+ 同一功能的线缆也可以复用，例如 **DRAM 芯片的行列地址线就是复用的**，在不同的时钟周期分别传送行、列地址，大大减少了芯片的引脚数。
+ **串行总线**也可以看作一个非常极端的总线复用，所有的信息都是通过同一根线缆或两根线缆(差分模式)进行传递的。

**总线复用的优缺点**

+ 优点：可以提高总线的利用率，减少引脚数目和布线空间，降低成本;
+ 缺点是控制模块复杂，另外**<font style="color:#DF2A3F;">分时传送机制还会引起总线性能下降</font>**<font style="color:#DF2A3F;">。</font>

## 7.5 总线事务
**总线事务**是指**从请求总线到完成总线使用的操作序列，通常是指总线上一对设备之间完成一次信息交换的过程**。我们将发出事务请求且能获得总线控制权的设备称为**主设备**，做出响应的设备称为**从设备**。

> **【注意】一条总线上可以同时挂接多对主从设备，但在某一个总线传输周期内，只能有一个主设备获得总线控制权，且该主设备仅能与一个从设备进行通信。**
>

总线事务是在一个总线周期内发生的一系列活动，总线周期可以分为总线请求、总线仲裁、设备寻址、数据传输和总线释放这五个阶段。

1. **总线请求**。当CPU或DMA等**主设备**需要使用总线时，发出总线传输申请。
2. **总线仲裁**。当有多个主设备同时发出总线请求时，由总线仲裁机构决定哪个申请者获得下一个传输周期的总线控制权。
3. **设备寻址**。主设备获得了总线控制权后，将要访问的**从设备**地址及相关命令发送到总线上，启动参与本次数据传输的从设备。
4. **数据传输**。主设备与从设备进行数据交换，数据在两设备之间进行单向或双向传送。

> 提示：在该阶段中，主设备和从设备之间通常只能传输一个字长的数据，
>

5. **总线释放**。主设备不再占用系统总线，其在总线上的相关信息均被撤除，总线控制权被释放。

:::info
**<font style="color:#DF2A3F;">总线事务（袁书定义）</font>**：通常把**在总线上一对主从设备之间的一次信息交换过程称为一个总线事务**。总线事务类型由其操作性质来定义。例如，**存储器读事务**是指将数据从主存取出到处理器，**存储器写事务**是指将数据写到主存。

**典型的总线事务类型有****<font style="color:#DF2A3F;">存储器读、存储器写、I/O读、I/O写、中断响应等。</font>**

**<font style="color:#DF2A3F;">总线突发(猝发)传送方式（成组传送事务）</font>**

> 2014年考察定义
>

指在数据传输中一次性传送在地址上连续的一批数据。该方式只需获得这批数据的首地址，就可以在传输阶段传送地址连续的多个单元的数据。**在这批数据的传输过程中，总线将一直被占用，直到这批数据全部传送完毕，总线才会被释放**。由于总线突发传送方式在多个总线周期内只需要传送一次首地址与控制信息，所以其传输速度要比普通传送方式更快。

> + 非突发传送方式在每个传送周期内都先传送地址，再传送数据，主、从设备之间通常每次只能传输一个字长的数据。
> + 在突发传送事务中，每个总线周期仍只传送一个计算机字长的信息，但不释放总线，直到一组信息全部传送完毕再释放总线。

**<font style="color:#DF2A3F;">总线分离事务通信</font>**[**<font style="color:#DF2A3F;">链接</font>**](about:blank)

> 又叫总线事务分离、分离事务协议、拆分总线事务，其实这个知识点放在异步定时方式那会更好
>

读操作是由从设备到主设备的数据传送，而写操作是由主设备到从设备的数据传送。一般情况下，主设备先以一个总线时钟周期发出命令和从设备地址，经过一定的延迟再开始数据传送。为了提高总线利用率，减少延时损失，在分离事务通信中将总线传输过程分为两个阶段：

1. 第一个阶段主设备完成寻址阶段任务后让出总线控制权供其他主设备使用;
2. 从设备准备好数据后重新申请总线，完成第二个阶段的数据传送任务。

> 袁书上对这种方式的定义：将一个事务过程分成两个子过程，
>
> + 在**第一个子过程**中，主控设备A在获得总线使用权后，将请求的事务类型(总线命令)、地址以及其他有关信息(如标识主控设备身份的编号等)发送到总线上，从设备B记录下这些信息。主控设备发完这些信息后便立即释放总线，这样其他设备便可使用总线;
> + 在**第二个子过程**中，从设备B收到主控设备 A发来的信息后，就按照其请求的命令进行相应的操作，当准备好主控设备所需的数据后，从设备B便请求使用总线，一旦获得使用权，则从设备B就将主控设备A的编号及所需的数据等送到总线上，这样主控设备 A便可接收数据。
>

优点：通过在不传送数据期间释放总线，使得其他申请者能使用总线

缺点：这种方式的控制相当复杂，开销也大，并且事务响应时间也会变长

**未采用事务分离**：

CPU获取总线控制权后，作为主设备，将地址从其内部的MAR给到主存。在主存准备好数据前，CPU一直占据着总线控制权数据准备好后，主存向CPU申请总线控制权，在获得总线控制权后将数据传输出去。

**采用事务分离：**

## 7.6 总线定时
![画板](https://cdn.nlark.com/yuque/0/2024/jpeg/42876865/1731598399734-f83de863-3d7b-498e-ae19-9e46a11ffcd9.jpeg)

主设备获得总线使用权后，就可以开始使用总线与从设备传送信息，实现具体的总线事务。而具体总线事务的每一个步骤、总线上的每一个信号、何时开始、何时结束就是总线的定时问题

常见总线通信定时方式有同步方式、异步方式、半同步方式和分离事务通信方式4种。

### 7.6.1 同步定时
同步定时方式是指进行信息交换的两部件或设备均**通过统一的时钟进行同步**，即它们都必须使用同一个时钟，在规定的时钟节拍内进行规定的总线操作。传统的总线大多是同步总线，它采用公共的时钟信号进行定时。挂接在总线上的所有设备都 从时钟线上获得定时信号。

> 同步总线的传输协议非常简单，只要在规定的第几个时钟周期内完成特定的操作即可。 例如，对于处理器通过总线访问存储器的操作来说，可以规定以下“**存储器读操作**”协议： 主控设备(即处理器)在第一个时钟周期发送地址和存储器读命令(可利用控制线表明请求的类型为“存储器读”)。 从设备(即存储器)总是在第 5 个时钟周期将数据放到总线上作为响应，处理器也在第 5 个时钟周期从数据线上取数据
>
> ![](https://cdn.nlark.com/yuque/0/2024/png/42876865/1731598153422-1b0fdc8f-c7f3-42cf-935f-f864da100d05.png)
>
> 存储器同步写流程也基本相同，主设备将地址、状态、数据、命令全部准备好，等待若干固定节拍后假定存储器已经完成写操作，撤除所有地址、数据、命令信息即可，如图所示，图中写入操作的总线传输周期长度是固定的。
>
> ![](https://cdn.nlark.com/yuque/0/2024/png/42876865/1731598441503-71917313-fe96-4b36-a8ca-d3dfd257f0bc.png)
>

:::info
**优点**：主从设备协调简单，传输速率高。

**缺点**：

    - 总线定时以最慢设备所花时间为标准，所以同步总线**适合于存取时间相差不大的多个功能部件之间的通信**
    - 由于时钟偏移问题，导致**同步总线不能过长**，否则将会降低总线传输效率。（因为同步总线通常采用并行传输方式，即总线的数据线条数为 8 位、16 位、32 位或 64 位等， 同时并行传输的这些数据位信号的定时必须相同，因此，实现更快传送速度、更长传输线的总线时，会导致传送到另一端时的波形发生变形，从而导致所有位中最快和最慢的位信号之间 的时间偏差较大）
    - 此外同步定时中主、从设备都是默认对方正常工作的，**可靠性不高**

**【适用场合：适用于总线长度短、设备速度相近且传输可靠性高的应用场合，如直接与CPU相连的系统总线。**

:::

### 7.6.2 异步定时
> 由于同步总线的上述问题，现在越来越多的总线采用异步串行方式进行传输。因为串行总线 每次在一根信号线上传送数据位，传输速率可以比并行总线高得多，而且，因为每个位各自 传输，因而传输时延的细微变化不会影响其他数据位的传送。**通过多个数据通道的组合，可 以实现比传统并行总线高得多的数据传输带宽。**
>

异步总线方式是指在**没有统一的时钟限制下**，只依靠各部件或设备内部的定时操作，以**信号握手**的方式进行规定的总线操作，即通过请求信号和确认信号来协调发送方和接收方的动作。进行信息交换的双方不需要由公共的时钟来规定请求和应答的时间，所以**总线周期的长度不再相同。而且有效规避了同步定时中的时钟偏移问题，总线传输距离更长。**

异步总线方式的优点在于总线周期灵活可变，主从设备不需要强制同步，**可以支持速度不同的两个设备**挂接到同一总线上。缺点在于逻辑更复杂；

**根据请求和回答信号的撤销是否互锁，异步定时方式又可分为不互锁、半互锁和全互锁三种方式。**

<details class="lake-collapse"><summary id="ua72998c8"><span class="ne-text">一个帮助于理解三种异步定时方式的例子</span></summary><p id="u1661a76f" class="ne-p"><strong><span class="ne-text">假设小明想约小莉吃饭</span></strong><span class="ne-text">。</span></p><ol class="ne-ol"><li id="uf6a79cb9" data-lake-index-type="0"><strong><span class="ne-text">场景一(类比全互锁方式)</span></strong><span class="ne-text">：小明刚认识小莉，第一次约她吃饭。小明给小莉发了一条微信消息：“明天去吃饭吧”。然后等待小莉回复，过了一会儿小莉回复：“可以啊”。然后也等待小明回复。当小明收到回复后，他认为约定成功，然后回复小莉：“那明天见”。当小莉收到回复后，她也认为约定成功。该场景中，小明和小莉都必须等到对方回复之后才会认为约定成功，由于双方需要等待对方的回复，所以约定过程比较缓慢。</span></li><li id="ue9f6ea01" data-lake-index-type="0"><strong><span class="ne-text">场景二(类比半互锁方式)</span></strong><span class="ne-text">：小明和小莉逐渐熟悉，第二次约她吃饭。小明给小莉发了一条微信消息：“明天去吃饭吧”。然后等待小莉回复，过了一会儿小莉回复：“可以啊”。但由于熟悉，小莉此时认为约定已成功，不再等待小明回复。当小明收到回复后，他也认为约定成功。该场景中，小明需要等待小莉回复才会认为约定成功，而小莉在给小明发送过回复信息后就会认为约定成功，由于小莉不再需要等待小明回复，所以约定过程有所加快。</span></li><li id="u87d15d32" data-lake-index-type="0"><strong><span class="ne-text">场景三(类比不互锁方式)</span></strong><span class="ne-text">：小明和小莉成为了好友，第三次约她吃饭。小明给小莉发了一条微信消息：“明天去吃饭吧”。由于是好友，小明直接默认约定成功，小莉在收到邀约信息后，也直接认为约定成功。该场景中，在小明不等待小莉回复和小莉没有回复的情况下双方都认为约定成功，由于双方都不需要等待对方的回复，所以约定过程变得很快。在这三个场景中，小明相当于主设备，小莉相当于从设备，而小明和小莉互发消息约定的过程相当于主从设备通过请求信号和回答信号进行信号握手的过程。</span></li></ol></details>
![](https://cdn.nlark.com/yuque/0/2024/png/42876865/1731599754936-abe2aa44-9639-4166-ab9d-2bb5cb9bdb18.png)

1. **不互锁方式**

主从设备双方不存在互锁，即主设备发出的请求信号和从设备发出的回答信号都可以自动撤销，不必等待对方的信号。因此，不互锁方式是三种方式中速度最快的。如图(a)所示。

2. **半互锁方式**

主设备一方存在互锁关系，即主设备发出的请求信号必须等接收到从设备的回答信号之后才能撤销，但从设备的回答信号不受限制，仍然可以自动撤销。如图(b)所示。

3. **全互锁方式**

主设备和从设备双方都存在互锁关系。即不仅主设备发出的请求信号必须等接收到从设备的回答信号之后才能撤销，同样，从设备发出的回答信号也必须等发送方的请求信号撤销之后才能撤销。如图(c)所示。

### 7.6.3 半同步定时方式
半同步定时方式保留了同步定时的特点，如所有地址、命令、数据信号的发出时间都严格参照系统时钟的某个前沿开始，而接收方都采用系统时钟后沿时刻来进行判断识别：同时，又像异步定时那样，允许不同速度的设备和谐地工作。为此增设一条 Wait 响应信号线。	

例如，某个半同步总线总是从某个时钟开始，在每个时钟到来时，采样 Wait 信号，若无效，则说明数据未准备好，下个时钟到来时，再采样 Wait 信号，直到检测到有效，再去数据线上取数据。**半同步定时适用于系统工作速度不高，但又包含了由许多速度差异较大的各类设备组成的简单系统。**

:::info
半同步定时同时具有同步和异步定时的优势，既保留了同步定时所有信号都由公共时钟定时的特点，又保留了异步通信允许不同速率的设备协同工作的特点，可以有效解决异步传输中的噪声敏感问题。

:::

以上三种定时方式都从主设备发出地址和读/写命令开始，直到数据传输结束，在整个传输周期中，总线的使用权完全由主设备及由其选中的从设备占据。其实，从设备在准备数据的阶段，总线纯属空闲等待，为进一步挖掘总线的潜力，又提出了分离式定时方式。
