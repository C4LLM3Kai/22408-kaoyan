###  虚拟存储器的基本概念
#### 虚拟存储器的相关概念和工作原理
虚拟存储器并非独立的物理存储硬件，而是一套由**<u><font style="color:#DF2A3F;">硬件与操作系统协同实现</font></u>**的内存管理技术，是计算机层次化存储体系中的核心设计，其核心定位是解决以下痛点：

1. **突破物理主存的容量限制**：计算机物理主存的容量远小于外存，且不同设备的主存配置存在显著差异。**虚拟存储器**为程序员提供了**<u>远超物理主存大小的连续、统一编程地址空间</u>**，让程序开发彻底摆脱物理内存大小对程序设计的约束。
2. **弥合CPU与外存的访问效率鸿沟**：CPU无法直接对磁盘、固态硬盘等外存进行寻址访问，所有外存中的程序代码与数据，必须先载入主存才能被CPU读取和执行。虚拟存储器基于**<font style="color:#DF2A3F;">程序的局部性原理</font>**，通过主存缓存高频访问的外存数据，减少CPU对低速外存的直接依赖，大幅提升程序的整体执行效率。
3. **支撑多进程的安全高效并发**：现代通用操作系统需要同时运行多个用户进程，**<u>每个进程都需要独立、不受干扰的地址空间</u>**。虚拟存储器**<u>为每个进程提供了私有的、完全隔离的虚拟地址空间</u>**，从底层保障进程间互不干扰；即使多个进程的总代码与数据容量超过物理主存大小，也能在有限的主存资源中稳定、安全地并发运行。



从存储体系架构来看，虚拟存储器以**<u>物理主存（DRAM）为核心缓存</u>**、以联机工作的**磁盘/固态硬盘等外存为后备存储载体**，二者通过统一的地址编址体系整合为一个有机整体。对应用程序员而言，这套体系就像一个单一的、可被CPU直接访问的超大容量主存，开发过程中只需面向这套虚拟地址空间编写程序，使用统一的**虚拟地址（VA， Virtual Address）** 完成指令与数据的寻址，无需关注数据实际存储在主存还是外存中。

虚拟存储器的落地实现，必须依靠**操作系统（OS）软件**与**<font style="color:#DF2A3F;">内存管理单元（MMU， Memory Management Unit）硬件</font>**的深度协同，核心工作流程分为两大核心环节：

1. **虚拟地址到物理地址的转换**  
	CPU执行程序时发出的是**虚拟地址**，首先会交由CPU芯片内部集成的**MMU**硬件处理。MMU会通过操作系统预设的页表/段表映射规则，将程序使用的虚拟地址（VA）转换为可被主存识别的**物理地址（PA， Physical Address）**，完成寻址的核心转换。

![](https://cdn.nlark.com/yuque/0/2026/png/42876865/1777479000078-28135e44-69b5-42ed-a8be-cacc13a20fbd.png)

2. **异常检测与闭环处理**  
在地址转换的全过程中，MMU会同步完成**<u><font style="color:#DF2A3F;">地址合法性与数据可用性校验</font></u>**，识别两类核心异常场景并触发对应处理：
    - **若目标数据未载入主存（数据缺失）**：MMU会触发**缺页异常**，CPU随即从用户态陷入操作系统内核，由内核的缺页异常处理程序完成目标数据从外存到主存的载入，同时更新地址映射关系，处理完成后返回用户态，重新执行触发异常的原指令；
    - 若出现**地址越界、访问权限不符等存储保护违规**：MMU会触发内存保护异常，由操作系统对违规行为进行对应处理（如终止违规进程、抛出内存访问错误等），从底层保障内存访问的安全性与进程间的地址隔离。

#### Cache-主存层次与主存-辅存层次
现代计算机主要通过构建两个层次来全面优化存储系统：

![](https://cdn.nlark.com/yuque/0/2026/png/42876865/1775291615980-48eb602e-2d8f-4021-b41f-cf2144877dd6.png)

**① ****<font style="color:#DF2A3F;">Cache - 主存层次</font>**

+ **主要目的：** 缓解 CPU 与主存**速度不匹配**的问题。
+ **实现方式：** 数据调度完全由**硬件自动完成**。
+ **透明性：** 对**所有程序员**（包括系统程序员和应用程序员）都是**透明**的（即程序员无需关心其内部数据调度逻辑）。

**② ****<font style="color:#DF2A3F;">主存 - 辅存层次</font>**

+ **主要目的：** 解决存储系统的**容量不足**问题（逐渐发展形成了**虚拟存储系统**，让程序员可以使用远大于实际主存的虚拟地址空间进行编程）。
+ **实现方式：** 由**硬件和操作系统共同完成**。
+ **透明性：** 对**应用程序员透明**，但对**系统程序员不透明**（系统程序员需要编写调度等底层逻辑）。

![内存和外存的关系](https://cdn.nlark.com/yuque/0/2026/png/42876865/1775288259791-57234ac8-a247-488d-8f52-cadcf7a7daa0.png)

⭐**Cache-主存层次与主存-辅存层次的异同点**

**一、 两个层次的相同点**

这两个层次在工作原理和管理机制上有以下核心共性：

1. **理论基础：** 都是基于**程序访问的局部性特点**，将相邻的局部信息从慢速存储器复制到快速存储器中。
2. **需要解决映射问题：** 都必须考虑慢速存储器和快速存储器之间的地址映射关系。
3. **需要解决替换问题：** 当快速存储器已满，且需要装入新块时，都需要考虑替换策略（把哪一块替换出去）。
4. **缺失时的调入机制：** 当在快速存储器中找不到所需信息（缺失）时，都需要从慢速存储器中将包含该信息的块调入到快速存储器中。

**二、 两个层次的不同点**

由于所处位置和引入目的不同，两者在具体实现上存在显著差异：

| 对比维度 | **Cache - 主存层次** | **主存 - 辅存层次** |
| :--- | --- | --- |
| **位置与访问权限** | 最靠近 CPU。CPU 可**直接访问** Cache 和主存。 | 远离 CPU。CPU **不能直接访问**辅存，辅存需与主存直接交换数据。 |
| **引入目的** | **<font style="color:#DF2A3F;">解决速度问题</font>**：**加快 CPU 访问信息的速度**。 | **<font style="color:#DF2A3F;">解决容量问题</font>**：采用虚拟存储器机制，**扩大系统的存储容量**，使编程不受内存大小限制。 |
| **交换的数据单位** | 称为**<font style="color:#DF2A3F;">主存块 (Block)</font>**，通常较小，一般为 **8 ~ 128B**。 | 称为**<font style="color:#DF2A3F;">页 (Page)</font>**，通常较大，一般为 **4KB ~ 64KB**（因缺页损失远大于 Cache 缺失，页太小会降低效率）。 |
| **缺失处理** | 由处理器（**<font style="color:#DF2A3F;">硬件</font>**）直接实现。 | 由操作系统（**<font style="color:#DF2A3F;">软件</font>**）实现。 |
| **映射方式** | 可灵活选择**直接映射、全相联映射或组相联映射**。 | 均采用**<font style="color:#DF2A3F;">全相联映射</font>**方式。 |
| **映射的实现介质** | 映射关系完全由**硬件**实现，使用 Cache 行中的**标志 (Tag)** 字段描述。 | 映射关系由**操作系统**实现，使用**页表**来描述。 |
| **写策略** | 可以采用**直写 (Write-through)** 和 **回写 (Write-back)** 两种策略。 | 都采用**回写 (Write-back)** 策略（因为直接写磁盘的开销过大，无法容忍直写策略）。 |


:::color1
cache与主存之间的数据交换单位是**数据块**，而页式虚拟存储器中，主存与辅存的数据交换单位是**页面**。cache由SRAM，主存由DRAM、辅存由磁盘等外设组成，容量关系为cache容量 << 主存容量 << 辅存容量，访问速度关系为cache访问速度 >> 主存访问速度 >> 辅存访问速度（主存比cache慢10~100倍，辅存比主存慢约10000倍）。

因此，页式虚拟存储器的**缺页处理代价远大于cache未命中的处理代价**，所以页面大小通常设置得更大，主流为4KB，也支持更大容量的页面；而cache与主存之间的数据块大小通常为16B、32B、64B等，远小于虚拟页面大小。

由于缺页处理代价极高，主存与辅存之间采用**全相联映射方式**以提升命中率；同时因辅存访问速度远低于主存，写操作默认采用**写回法**，而非直写法。

:::



#### 虚拟地址空间 vs 物理地址空间
+ **虚地址VA(Virtual Address)**：应用程序视角中的连续逻辑地址，构成统一的虚拟内存空间，也叫逻辑地址；
+ **物理地址PA(Physical Address)**：硬件实际使用的内存单元地址；

通过内存管理单元MMU和页表的动态转换，连续的虚拟地址可被映射到分散的物理地址上。

### 页式虚拟存储器
#### 页式虚拟存储器概述（更详细的内容见 OS 第三章）
在页式虚拟存储器中，主存和虚拟地址空间被划分为大小完全相等的页面（简称页），外存与主存之间以**页**为单位交换信息：

+ **虚拟页VP(Virtual Page)**：虚拟地址空间中的页，简称虚页，也叫逻辑页；
+ **物理页PP(Physical Page)**：主存空间中的页，简称实页，也叫页框、页帧。

页式虚拟存储器采用**请求分页**的核心思想：

+ 仅将进程中活跃的页面（包含当前访问的指令/数据）从辅存调入主存，非活跃页面保留在辅存中；
+ 当访问的指令/数据所在页面不在主存时，触发**缺页异常**，由操作系统从辅存将缺失页面调入主存。

虚拟页式存储器采用**<u><font style="color:#DF2A3F;">全相联映射</font></u>**，即每个虚拟页可存放到主存中任意一个空闲物理页。

#### 页表
对于每个进程，都需要建立虚拟页与主存物理页/磁盘存储位置的映射关系，该关系通过**页表PT(Page Table)** 记录。程序被加载到主存运行时成为进程，进程是程序的执行实例，是操作系统资源分配和调度的基本单位。

采用虚拟存储器的系统中，操作系统会为**每个进程创建独立的页表**，实现虚拟地址空间到物理地址空间的映射。页表中的每一行称为一个页表项，核心字段及说明如下：

| 字段名称 | 别名 | 核心作用与取值规则 |
| --- | --- | --- |
| 有效位 | 装入位 | + 有效位=1：虚拟页已从辅存调入主存，存放位置字段存储物理页号；   <br/>+ 有效位=0：虚拟页未调入主存，若存放位置为NULL表示未分配物理内存，不为NULL 时记录该页在磁盘上的起始地址 |
| 脏位 | 修改位 | 标记虚拟页是否被修改，配合写回法使用：<br/>+ 脏位=1：页面已被修改，替换时需写回辅存；   <br/>+ 脏位=0：页面未被修改，可直接替换无需写回 |
| 引用位 | 替换控制位/使用位 | 记录页面的访问情况，配合替换策略使用： LRU算法中作为LRU位 |
| 访问权限位 | 保护位 | 定义页面的访问权限，实现存储保护，可选权限：可读可写、只读、只可执行 |

#### PTBR 页表基址寄存器
<font style="color:rgb(32, 32, 32);">PTBR 是一个</font>**<font style="color:rgb(32, 32, 32);">硬件寄存器</font>**<font style="color:rgb(32, 32, 32);">，存储当前进程</font>**<font style="color:rgb(32, 32, 32);">页表在物理内存中的起始地址（根地址）</font>**<font style="color:rgb(32, 32, 32);">。</font>

<font style="color:rgb(32, 32, 32);">MMU 每次翻译虚拟地址时，都以 PTBR 中的值为起点，去内存中找页表、完成地址翻译。它是 MMU 与页表之间的"入口指针"。（CPU 给出虚拟地址 VA，可划分为虚拟页号VPN + 页内偏移offset，页表项地址 = PTBR + VPN × 页表项大小 ，访问主存中的页表得到页表项，将里面的物理页号和页内偏移拼接在一起得到物理地址。）</font>

**<font style="color:#DF2A3F;">进程切换时 PTBR 的变化</font>**<font style="color:rgb(32, 32, 32);">：每个进程都有</font>**<font style="color:rgb(32, 32, 32);">自己独立的页表</font>**<font style="color:rgb(32, 32, 32);">，存在内存的不同位置。操作系统在进程切换时，只需修改 PTBR 的值，MMU 就能立刻切换到新进程的地址空间。这是虚拟存储器实现</font>**<font style="color:rgb(32, 32, 32);">进程地址空间隔离</font>**<font style="color:rgb(32, 32, 32);">的核心机制，进程 A 和进程 B 可以使用完全相同的虚拟地址，但因为 PTBR 不同，翻译出的物理地址完全不同，互不干扰。</font>

<font style="color:rgb(32, 32, 32);">PTBR 存储的是物理地址，这一点很关键：PTBR 中存放的必须是</font>**<font style="color:rgb(32, 32, 32);">物理地址</font>**<font style="color:rgb(32, 32, 32);">，而不是虚拟地址。</font>

<font style="color:rgb(32, 32, 32);">原因很简单：MMU 翻译地址时，需要先找到页表，如果页表的地址本身也是虚拟地址，就形成了"先有鸡还是先有蛋"的死循环——翻译虚拟地址需要页表，找页表又需要先翻译虚拟地址。</font>

<font style="color:rgb(32, 32, 32);"></font>

**<font style="color:rgb(32, 32, 32);">PTBR 与 TLB 的关系</font>**<font style="color:rgb(32, 32, 32);">：每次通过 PTBR 查页表都要访问内存，代价很高（数十~数百周期）。TLB 正是为了减少这种开销而存在的：</font>

```plain
有 TLB 时:                          无 TLB（或TLB缺失）时:
                                    
CPU发出VA                            CPU发出VA
    │                                   │
    ▼                                   ▼
查 TLB（快，1~4周期）              PTBR + VPN → 页表项地址
    │                                   │
  命中                               访问内存取页表项（慢，~100周期）
    │                                   │
    ▼                                   ▼
直接得到PA                          得到PA
（完全不需要 PTBR 和内存）
```

<font style="color:rgb(32, 32, 32);">TLB 命中时，PTBR 完全用不上；只有 TLB 缺失时，MMU 才通过 PTBR 去内存查页表。</font>**<font style="color:rgb(32, 32, 32);">TLB 的本质是对"PTBR + 页表查询"这个慢操作的缓存。</font>**

**<font style="color:rgb(32, 32, 32);">多级页表下 PTBR 的含义</font>**<font style="color:rgb(32, 32, 32);">：如果系统使用多级页表，PTBR 存储的是</font>**<font style="color:rgb(32, 32, 32);">最顶层页表（页目录）的物理基址</font>**<font style="color:rgb(32, 32, 32);">。</font>

:::color1
**<font style="color:rgb(32, 32, 32);">一句话总结： PTBR 是 MMU 访问页表的入口指针，存储当前进程页表根的物理地址。进程切换时 OS 修改 PTBR，即完成地址空间切换；TLB 命中时 PTBR 被绕过，TLB 缺失时 MMU 从 PTBR 出发遍历页表完成翻译。</font>**

:::



#### 地址映射及转换
<font style="color:rgb(0,0,0);">对于采用虚存机制的系统，指令中给出的地址是虚拟地址，所以，CPU执行指令时，首先要将</font>**<u><font style="color:#DF2A3F;">虚拟地址转换为主存物理地址</font></u>**<font style="color:rgb(0,0,0);">，才能到主存取指令和数据。</font>**<font style="color:rgb(0,0,0);">地址转换</font>**<font style="color:rgb(0,0,0);">(address </font>

<font style="color:rgb(0,0,0);">translation)工作由 CPU 中的</font>**<font style="color:rgb(0,0,0);">存储器管理部件(MMU)</font>**<font style="color:rgb(0,0,0);">来完成。 </font>

由于页式虚拟存储器中，**物理页与虚拟页大小完全一致**，因此二者的页内偏移位数完全相同，简称页内偏移字段。

    - 物理地址 = 物理页号 + 物理页内偏移
    - 虚拟地址 = 虚拟页号 + 虚拟页内偏移

虚拟存储器容量大于主存容量，因此**虚拟页号的位数大于物理页号的位数**。

<font style="color:rgb(0,0,0);">分页式虚拟存储管理方式下，地址变换过程如下图所示。首先 </font>**<font style="color:rgb(0,0,0);">MMU </font>**<font style="color:rgb(0,0,0);">根据</font>**<font style="color:rgb(0,0,0);">页表基址寄存器</font>**<font style="color:rgb(0,0,0);">的内容，找到主存中对应的</font>**<font style="color:rgb(0,0,0);">页表起始位置(即页表基地址)，</font>**<font style="color:rgb(0,0,0);">然后将虚拟地址高位字段中的虚页号作为索引，找到对应的页表项，若装入位（有效位）为1，则取出物理页号，和虚拟地址中的页内地址拼接，形成访问主存时实际的物理地址；若装入位为0，则说明缺页，需要操作系统进行缺页处理。</font>

> 页表属于进程控制信息，存放在进程地址空间的内核区，每个进程的页表常驻主存。**页表基址寄存器PTBR** 记录页表在主存中的首地址，进程切换时仅需修改PTBR的值，即可完成页表的快速切换。

##### 最基础的访存流程
###### 页面命中时的访问流程
![](https://cdn.nlark.com/yuque/0/2026/png/42876865/1777634778371-7d701981-8fab-488c-9874-9c46e307ce31.png)

1. CPU送出指令中的虚拟地址，交由MMU进行地址转换；
2. MMU通过PTBR和虚拟地址中的虚拟页号，生成页表项地址，访问主存中的对应页表项；
3. 主存向MMU返回页表项；
4. 页表项有效位=1，确认页面已调入主存，通过物理页号+页内偏移拼接物理地址，访问主存对应数据；
5. 主存向CPU返回目标数据。



###### 页面缺失（缺页）时的访问流程
步骤1~3与页面命中流程完全一致；  
4. 页表项有效位=0，MMU触发缺页异常，调用操作系统内核的缺页异常处理程序；  
5. 若主存已满，通过替换算法选定待淘汰页面；若该页面脏位=1，需先将页面写回磁盘，否则直接丢弃；  
6. 缺页处理程序（由硬件和操作系统协作完成）从磁盘调入目标页面到主存，更新页表对应表项；  
7. 缺页处理完成后，返回原进程，重新执行触发缺页的指令，此次执行将命中页面，按命中流程的步骤 2-5 完成访存。

##### 结合cache的访存流程
主存中的数据可分为两类：存储页表内容的**页表块**、存储程序数据的**数据块**。cache会缓存主存中的高频访问数据，因此常用的页表块也会被载入cache。

###### 最理想情况
页表项在cache中命中、数据也在cache中命中，仅需2次cache访问即可获取数据。

1. CPU发出虚拟地址，交由MMU转换；
2. MMU通过PTBR和虚拟页号生成页表项地址，在cache中查找对应页表项；
3. 页表项命中，cache向MMU返回页表项；
4. 页表项有效位=1，拼接得到物理地址，通过物理地址在cache中查找目标数据块；
5. 数据块命中，向CPU返回目标数据。

![](https://cdn.nlark.com/yuque/0/2026/png/42876865/1777643207401-d59e816c-73fe-4d82-afd6-30c38de87b2e.png)

###### 较糟糕情况
无缺页（页面在主存中），但页表项在cache中缺失、数据也在cache中缺失，需2次主存访问获取数据。

1. CPU发出虚拟地址，交由MMU转换；
2. MMU通过PTBR和虚拟页号生成页表项地址，在cache中查找对应页表项；
3. 页表项在cache中缺失，通过页表项地址访问主存获取页表项；
4. 将页表项所在数据块载入cache
5. 向MMU返回页表项；
6. 页表项有效位=1（页表项所在页面已载入主存），该页表项中的存放位置字段里记录了物理页号，再结合虚拟页号末尾的页内偏移字段，拼接得到物理地址，在cache中查找目标数据块；
7. 数据块在cache中缺失，通过物理地址访问主存获取数据块；
8. 将目标数据所在数据块载入cache
9. 向CPU返回目标数据。

![](https://cdn.nlark.com/yuque/0/2026/png/42876865/1777644703840-3ec1346c-eee8-4ca9-9bb0-345a7eb77426.png)



###### 最糟糕情况
在较糟糕情况的基础上，访问目标数据块触发缺页异常，需访问磁盘获取数据，访存性能损耗最大。（前面 6 步与较糟糕情况一样，但是后面访问主存也缺失，因此得从磁盘将对应页面调入内存和 cache）



综上，**<u><font style="color:#DF2A3F;">虚拟存储技术会对存储器的访问性能产生影响。</font></u>**

##### 使用快表TLB加速地址转换
<font style="color:#231f20;">ca</font><font style="color:#231f20;">che虽然可以缓存部分经常访问的页表块，但这种数据块的粒度较大，并不能充分利用虚拟存储器访问的局部性。为了进一步降低虚拟存储器地址转换的硬件开销，现代处理器都维护着一个</font>转换旁路缓冲区<font style="color:#231f20;">（Translation Look-aside Buffer，TLB），</font>**<font style="color:#231f20;">用于缓冲经常访问的页表项</font>**<font style="color:#231f20;">。</font>

<font style="color:#231f20;">TLB本质上就是一个容量较小的cache，为提高查找速度，</font>**<u><font style="color:#DF2A3F;">大多采用全相联或组相联方式</font></u>**<font style="color:#231f20;">，且采用</font>**<u><font style="color:#DF2A3F;">随机替换算法</font></u>**<font style="color:#231f20;">。TLB离CPU更近，访问速度更快，所以通常将TLB表称为</font>**<u><font style="color:#DF2A3F;">快表</font></u>**<font style="color:#231f20;">，而将主存中的页表称为</font>**<u><font style="color:#DF2A3F;">慢表</font></u>**<font style="color:#231f20;">。</font>

font-size: 14px">。面对庞大的现代应用程序，TLB 缺失（TLB Miss）是不可避免且相对频繁的。</span></li><li id="u1e09ae8f" data-lake-index-type="0"><strong><span class="ne-text" style="color: rgb(31, 31, 31); font-size: 14px">Cache 的“兜底”作用：</span></strong><span class="ne-text" style="color: rgb(31, 31, 31); font-size: 14px"> 当 TLB 缺失时，现代处理器的 MMU必须去主存中顺藤摸瓜地查找页表项 。在真正去访问慢速主存之前，MMU 生成了页表项的物理地址后，会</span><strong><span class="ne-text" style="color: rgb(31, 31, 31); font-size: 14px">先去 Cache 中查找</span></strong><span class="ne-text" style="color: rgb(31, 31, 31); font-size: 14px">。</span></li></ul><ul class="ne-list-wrap"><ul ne-level="1" class="ne-ul"><li id="u01f81d9c" data-lake-index-type="0"><strong><span class="ne-text" style="color: rgb(31, 31, 31); font-size: 14px">Cache 命中：</span></strong><span class="ne-text" style="color: rgb(31, 31, 31); font-size: 14px"> 如果运气好，该页表项所在的主存块已经被加载到了 Cache 中，MMU 就可以直接从 Cache 里以较快的速度拿到页表项，避免了惩罚极高的主存访问 </span><span class="ne-text" style="color: rgb(31, 31, 31); font-size: 14px">。</span></li><li id="u5c927cb9" data-lake-index-type="0"><strong><span class="ne-text" style="color: rgb(31, 31, 31); font-size: 14px">Cache 缺失：</span></strong><span class="ne-text" style="color: rgb(31, 31, 31); font-size: 14px"> 如果 Cache 里也没有，MMU 才会真正向主存发起读取请求，拿到页表项后，还会顺手把这个页表块装入 Cache 中，以便下次相邻的页表项查询能直接在 Cache 里命中 。</span></li></ul></ul><p id="ua1f0c209" class="ne-p"><span class="ne-text" style="color: rgb(31, 31, 31); font-size: 14px">在现实的现代架构（如 x86-64 或 ARM64）中，操作系统通常采用 4 级甚至 5 级多级页表。这意味着发生一次 TLB Miss，MMU 为了翻译一个地址，最多需要连着读 4 到 5 次内存（依次查询页全局目录、页上级目录、页中间目录、页表等）。</span></p><p id="u59692140" class="ne-p"><span class="ne-text" style="color: rgb(31, 31, 31); font-size: 14px">如果这 4~5 次访问每次都要去读百纳秒级别的物理主存（DRAM），那计算机的性能就会被严重拖垮。幸运的是，顶层的页目录项由于被海量使用，几乎 100% 常驻在 L1/L2 Cache 中。普通页表项也有很大比例在 L2 或 L3 Cache 中。</span></p><p id="ubeedf60e" class="ne-p"><strong><span class="ne-text" style="color: rgb(31, 31, 31); font-size: 14px">总结来说：TLB</span></strong><span class="ne-text" style="color: rgb(31, 31, 31); font-size: 14px"> 负责第一道防线，加速的是“虚拟地址直接翻译出物理地址”这一过程 ； </span><strong><span class="ne-text" style="color: rgb(31, 31, 31); font-size: 14px">Cache</span></strong><span class="ne-text" style="color: rgb(31, 31, 31); font-size: 14px"> 负责第二道防线，它不仅缓存程序的数据，也缓存着页表的数据，用来在 TLB 缺失时，大幅缩短“去内存查页表”的取数时间 。两者各司其职，缺一不可。</span></p></details>
###### 全相联方式的TLB工作逻辑
全相联模式下，虚拟地址划分为：虚拟页号 + 虚拟页内偏移。MMU将虚拟页号与TLB内所有页表项的tag标记进行并行比较，若tag匹配且有效位=1，则TLB命中，直接获取物理页号，与页内偏移拼接得到物理地址。

![](https://cdn.nlark.com/yuque/0/2026/png/42876865/1778000730135-31f91a8c-b51e-40dd-bb19-146491a9612c.png)

###### 组相联方式的TLB工作逻辑
组相联模式下，虚拟地址划分为：TLB标记 + TLB组索引 + 虚拟页内偏移。  
以2路组相联为例：

1. MMU通过TLB组索引定位到对应的TLB组（每组包含2个页表项）；
2. 将TLB标记与组内2个表项的标记并行比较，结果与有效位做逻辑与运算，生成选择信号；
3. 选中的物理页号与页内偏移拼接，得到最终物理地址。

![](https://cdn.nlark.com/yuque/0/2026/png/42876865/1778002469106-84a4289f-f5c3-4d29-8b6b-564a256fc2d0.png)

##### 基于TLB、cache的完整访存流程
采用虚拟存储器技术的计算机，需要硬件（MMU、TLB等）与操作系统协同工作：

1. 操作系统引导完成前，CPU使用物理地址访问主存，处于**实地址模式（实模式）**；
2. 操作系统引导完成后，CPU进入**保护模式（虚地址模式）**，使用虚拟地址访问主存。

![](https://cdn.nlark.com/yuque/0/2026/png/42876865/1778005561748-a2b0944e-ee46-49fa-8d58-3e81ef64b92e.png)

> 关键说明：cache缺失处理由**硬件**完成；缺页处理由**操作系统（软件）完成；TLB缺失处理可由硬件**完成，也可由操作系统通过TLB缺失异常处理程序（**软件**）完成。
