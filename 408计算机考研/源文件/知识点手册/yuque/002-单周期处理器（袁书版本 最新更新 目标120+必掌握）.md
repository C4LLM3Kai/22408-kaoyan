# 单周期处理器（袁书版本 最新更新 目标120+必掌握）

<font style="color:#000000;">本讲义围绕一台 MIPS 风格的</font>**<font style="color:#000000;">单周期处理器</font>**<font style="color:#000000;">展开：</font>**<u><font style="color:#DF2A3F;">每个时钟周期执行一条指令，信号从一个状态单元出发，经过若干组合逻辑部件，在时钟沿到达另一个状态单元</font></u>**<font style="color:#000000;">。讲义按指令功能逐步扩展数据通路——先讲取指部件，再依次加入 R 型运算、I 型立即数运算、访存（lw/sw）、条件分支（beq）和无条件跳转（j），最终覆盖 11 条目标指令：add、sub、subu、slt、sltu、ori、addiu、lw、sw、beq、j。</font>

:::warning
**<font style="color:#000000;">学习目标</font>**

1. <font style="color:#000000;">能说清每张图“从 PC 出发、信号怎么走、结果在何时写入”的完整路径；</font>
2. <font style="color:#000000;">能解释每个新部件和每个控制信号存在的理由；</font>
3. <font style="color:#000000;">能对照控制信号总表，说出任意一类指令各控制信号的取值；</font>
4. <font style="color:#000000;">能区分通路中哪些是组合逻辑、哪些是时序（状态）动作。</font>

:::

:::color2
**<font style="color:#000000;">学习建议：</font>**

**<font style="color:#000000;">先顺着这份讲义捋清楚单周期数据通路；然后尝试看着指令的格式 字段划分和功能描述，自己手画草图画一遍，哪怕边看边画也会有很大的帮助，这样包能彻底掌握单周期数据通路以及后续的流水线数据通路，如果能坚持做完这项工作，遇到 24 年和 26 年这样的计组大题将会游刃有余，对做选择题也会大有裨益；</font>**

:::

下面我们讲的单周期处理器支持执行一下 11 条 MIPS 风格的指令

| 指令 | 功能 | 说明 |
| --- | --- | --- |
| add rd, rs, rt   sub rd, rs, rt | $ \mathrm{M[PC]},\ \mathrm{PC}\leftarrow\mathrm{PC}+4 $   $ \mathrm{R[rd]}\leftarrow\mathrm{R[rs]}\pm\mathrm{R[rt]} $ | 从 PC 所指的内存单元中取指令，并 PC 加 4；从 rs、rt 中取数后相加减，若溢出则异常处理，否则结果送 rd |
| subu rd, rs, rt | $ \mathrm{R[rd]}\leftarrow\mathrm{R[rs]}-\mathrm{R[rt]} $ | 从 rs、rt 中取数后相减，结果送 rd（不进行溢出判断） |
| slt rd, rs, rt | $ \text{if}\ (\mathrm{R[rs]}<\mathrm{R[rt]}) $   $ \mathrm{R[rd]}\leftarrow 1 $   $ \text{else}\ \mathrm{R[rd]}\leftarrow 0 $ | 从 rs、rt 中取数后按带符号整数来判断两数大小，小于则 rd 中置 1，否则 rd 中清 0（不进行溢出判断） |
| sltu rd, rs, rt | $ \text{if}\ (\mathrm{R[rs]}<\mathrm{R[rt]}) $   $ \mathrm{R[rd]}\leftarrow 1 $   $ \text{else}\ \mathrm{R[rd]}\leftarrow 0 $ | 从 rs、rt 中取数后按无符号数来判断两数大小，小于则 rd 中置 1，否则 rd 中清 0（不进行溢出判断） |
| ori rt, rs, imm16 | $ \mathrm{R[rt]}\leftarrow\mathrm{R[rs]}\mid\mathrm{ZEXT}(\mathrm{imm16}) $ | 从 rs 取数、将 imm16 进行零扩展，然后两者按位或，结果送 rt |
| addiu rt, rs, imm16 | $ \mathrm{R[rt]}\leftarrow\mathrm{R[rs]}+\mathrm{SEXT}(\mathrm{imm16}) $ | 从 rs 取数、将 imm16 进行符号扩展，然后两者相加，结果送 rt（不进行溢出判断） |
| lw rt, rs, imm16 | $ \mathrm{Addr}\leftarrow\mathrm{R[rs]}+\mathrm{SEXT}(\mathrm{imm16}) $   $ \mathrm{R[rt]}\leftarrow\mathrm{M[Addr]} $ | 从 rs 取数、将 imm16 进行符号扩展，然后两者相加，结果作为访存地址 Addr，从 Addr 中取数并送 rt |
| sw rt, rs, imm16 | $ \mathrm{Addr}\leftarrow\mathrm{R[rs]}+\mathrm{SEXT}(\mathrm{imm16}) $   $ \mathrm{M[Addr]}\leftarrow\mathrm{R[rt]} $ | 从 rs 取数、将 imm16 进行符号扩展，然后两者相加，结果作为访存地址 Addr，将 rt 送 Addr 中 |
| beq rs, rt, imm16 | $ \mathrm{Cond}\leftarrow\mathrm{R[rs]}-\mathrm{R[rt]} $   $ \text{if}\ (\mathrm{Cond}\ \text{eq}\ 0) $   $ \mathrm{PC}\leftarrow\mathrm{PC}+4+(\mathrm{SEXT}(\mathrm{imm16})\times 4) $ | 做减法以比较 rs 和 rt 中内容的大小，并计算下条指令地址，然后根据比较结果修改 PC。转移目标地址采用相对寻址，基准地址为下条指令地址（即 PC+4），位移量为立即数 imm16 经符号扩展后的值的 4 倍。因此，转移目标指令的范围为相对于当前指令的前 32767 到后 32768 条指令 |
| j target | $ \mathrm{PC}\leftarrow\mathrm{PC}\langle31{:}28\rangle\ \Vert\ \mathrm{target}\langle25{:}0\rangle\ \Vert\,00 $ | 第一步无须进行 PC+4 而直接计算目标地址，符号 $ \Vert $ 表示“拼接”，PC 最后两位为 00 |

###  单周期处理器的取指令部件
![](https://cdn.nlark.com/yuque/0/2026/png/42876865/1789656182598-5f964f3b-6c70-422f-827c-33575866c017.png)

![](https://cdn.nlark.com/yuque/0/2026/png/42876865/1789723425937-e75544c3-cdf0-407a-bb95-53899d6ffc40.png)

:::color1
取指部件由三部分构成：

+ **PC（程序计数器）**：状态单元，存放当前指令地址，由 CLK 边沿触发更新；
+ **指令存储器**：只读，输入地址、输出指令字 Instruction[31:0]，**<font style="color:#DF2A3F;">本质上是一块组合逻辑</font>**；
+ **下地址逻辑**：根据当前指令计算下一条指令的地址，结果在时钟边沿送回 PC。

工作过程：PC 中的地址一路送入指令存储器，经过一段"取数时间"后指令字被送出；另一路送入下地址逻辑。指令字一出存储器，各字段立即沿**专用数据通路**分流——操作码送控制器产生控制信号，rs、rt（rd）送寄存器堆选择寄存器，立即数字段送符号扩展单元。与此同时，下地址逻辑算出的地址在下一个时钟边沿写入 PC，开始下一条指令的取指。

:::

:::warning
**<font style="color:#DF2A3F;">两个"无须控制信号"的设计</font>**

**1. 指令存储器只读，无须读控制信号。** 指令存储器专门存放指令，**CPU 对它只有读操作、没有写操作**。**读操作可视为组合逻辑**：地址端一给出地址，经过固定的取数延迟，输出端就稳定给出对应指令；地址一变，输出随之改变，中间既不需要三态门，也不需要读使能之类的控制信号。

**2. ****<font style="color:#DF2A3F;">PC 每周期必更新，无须写使能</font>****。** 单周期处理器一个时钟周期执行完一条完整指令，每来一个时钟边沿 PC 必然更新一次，不存在"这个周期要不要写 PC"的选择。因此 **PC 只需接 CLK，不需要写使能（WE）信号**。

:::

:::success
下地址逻辑负责区分两种情况（内部具体硬件设计往后看就能看到）：

+ **顺序执行**：下条地址 = PC + 4（MIPS 按字节编址，一条指令占 4 字节）；
+ **转移执行**：
    - **分支指令（branch）**：先判断分支条件，条件满足时，由 PC+4 与符号扩展后的偏移量相加得到转移目标地址；
    - **跳转指令（jump）**：由指令中的跳转目标字段直接拼装目标地址。

:::

指令字取出来，各字段沿**专用通路同时**送往对应部件：

| 指令字段 | 位段 | 送往部件 | 作用 |
| --- | --- | --- | --- |
| <font style="color:rgb(0, 0, 0);">op（操作码）</font> | [31:26] | 主控制器 | 译码产生控制信号 |
| rs | [25:21] | 寄存器堆读地址端 Ra | 指定第一个源寄存器 |
| rt | [20:16] | 寄存器堆读地址端 Rb | 指定第二个源寄存器 |
| rd | [15:11] | 寄存器堆写地址端 Rw | 指定目的寄存器 |
| funct | [5:0] | ALU 控制单元 | <font style="color:rgb(0, 0, 0);">与 AluOp 共同决定 ALUctr</font> |


这些连接是固定的、指令一定会被译码，所以中间**不设三态门、不需要额外控制信号**：PC 一变，操作码、寄存器编号、funct 全部跟着确定，这正是组合逻辑"输入一变、输出即变"的特点。

:::color1
**R 型指令的控制信号**分两级产生：

1. **主控制器**对 op[31:26] 译码。R 型指令 op 字段全 0，主控制器据此做两件事：置 **RegWr=1**（本指令最后要写回寄存器），输出 **AluOp**（告诉后级"这是 R 类运算"）。
2. **ALU 控制单元**再用 AluOp 和 funct[5:0] 共同译码，产生 **ALUctr** 操作编码，5 条指令一一对应：add→加法、sub/subu→减法、slt/sltu→比较置 1。ALUctr 送入 ALU 选择运算功能。

注意：**所有控制信号在本时钟周期内必须保持稳定**，不能中途变化，否则 ALU 输出和写回数据都会抖动。

:::

:::warning
ALU 按 ALUctr 对 busA、busB 完成运算，产生两个输出：

+ **结果**：32 位（slt/sltu 时是比较结果 0/1 再扩展为 32 位）；
+ **Overflow 溢出标志**：add、sub 需要判断溢出，**溢出时 Overflow=1**；subu、slt、sltu 不发生溢出陷入。

ALU 结果经写回总线 **busW** 送到寄存器堆写数据端 **WD**，写地址端 **Rw=rd**，保证写进指令指定的目的寄存器。

**写使能**由与门给出：**WE = RegWr · ¬Overflow**（Overflow 先经非门取反，再与 RegWr 相与）：

    - 正常情况：RegWr=1、不溢出（Overflow=0）→ ¬Overflow=1 → **WE=1，允许写入**；
    - add/sub 溢出：Overflow=1 → ¬Overflow=0 → **WE=0，结果丢弃，转****<font style="color:#DF2A3F;">异常处理程序</font>**；
    - 其他不需要写回的指令：主控制器令 RegWr=0，WE 同样为 0。

**真正的写入发生在下一个时钟上升沿**：寄存器堆在该边沿采样 Rw、WD、WE，把 WD 上的数据锁入 rd 编号的寄存器。因此写寄存器堆是全通路中为数不多的时序动作，Rw、WD、WE 必须在时钟沿之前稳定（满足建立时间）。

:::

#### <font style="color:rgb(0,0,0);">I 型立即数运算指令的数据通路</font>
![](https://cdn.nlark.com/yuque/0/2026/png/42876865/1789726313138-57e5488e-65ac-474e-b59c-b1b79e3fd54c.png)

![](https://cdn.nlark.com/yuque/0/2026/png/42876865/1789738318563-4f4de0b1-3deb-4c0e-8f7d-8ac954f6e846.png)

本图在 R 型数据通路基础上扩展，使它既能执行 R 型指令，又能执行两条 I 型立即数运算指令 **ori**（按位或）和 **addiu**（立即数加，不判溢出）。I 型指令格式为：$ \begin{array}{|c|c|c|c|}
\hline
\text{OP (6位)} & \text{rs (5位)} & \text{rt (5位)} & \text{立即数 Immediate (16位)} \\
\hline
\end{array} $

与 R 型相比，指令里**没有 rd、shamt、funct**，但多了 16 位立即数；而且**目的寄存器就是 rt**。为处理立即数，通路新增三个部件：

| **<font style="color:rgb(0, 0, 0);">新增部件</font>** | **<font style="color:rgb(0, 0, 0);">控制信号</font>** | **<font style="color:rgb(0, 0, 0);">作用</font>** | **<font style="color:rgb(0, 0, 0);">两端取值</font>** |
| :---: | :---: | :---: | :---: |
| <font style="color:rgb(0, 0, 0);">MUX(1)（写地址选择）</font> | <font style="color:rgb(0, 0, 0);">RegDst</font> | <font style="color:rgb(0, 0, 0);">选择写回的目的寄存器编号</font> | <font style="color:rgb(0, 0, 0);">0=rd（R 型）；1=rt（I 型）</font> |
| <font style="color:rgb(0, 0, 0);">扩展器</font> | <font style="color:rgb(0, 0, 0);">ExtOp</font> | <font style="color:rgb(0, 0, 0);">把 16 位立即数扩展为 32 位</font> | <font style="color:rgb(0, 0, 0);">零扩展 / 符号扩展</font> |
| <font style="color:rgb(0, 0, 0);">MUX(2)（ALU B 口选择）</font> | <font style="color:rgb(0, 0, 0);">ALUSrc</font> | <font style="color:rgb(0, 0, 0);">选择 ALU 第二操作数</font> | <font style="color:rgb(0, 0, 0);">0=busB（来源寄存器堆）；1=扩展后的立即数</font> |


:::color2
**<font style="color:#000000;">写地址：RegDst 与 MUX(1)</font>**

R 型结果写 rd，I 型结果写 rt，所以写地址端 Rw 前加一个二选一 MUX：

+ **RegDst = 0 → 选 Rd**（[15:11]），R 型指令走此路；
+ **RegDst = 1 → 选 Rt**（[20:16]），ori、addiu 走此路。

<font style="color:#000000;">MUX(1) 输出接寄存器堆写地址 Rw。</font>

:::

:::warning
**<font style="color:#000000;">立即数扩展：零扩展与符号扩展</font>**

ALU 是 32 位的，16 位立即数必须先扩展：

+ **ori 是按位逻辑运算**，高 16 位应补 0，即**零扩展 ZEXT**（ExtOp=0）；
+ **addiu 是算术运算**，必须保留正负号，即**符号扩展 SEXT**（最高位是 1 则高 16 位全补 1，ExtOp=1）。

扩展器输入接 imm16，输出 32 位立即数送 MUX(2) 的 1 输入端；扩展方式由主控制器给出的 **ExtOp** 决定

:::

:::color3
**<font style="color:#000000;">ALU 第二操作数：ALUSrc 与 MUX(2)</font>**

+ **ALUSrc = 0 → 选 busB = R[rt]**：R 型指令，两个操作数都在寄存器里；
+ **ALUSrc = 1 → 选扩展器输出的 32 位立即数**：I 型指令，R[rs] 与立即数运算。

A 口不变，始终是 busA = R[rs]。

:::

> R 型靠"op→AluOp、funct→ALUctr"两级译码；I 型指令 op 本身就唯一确定了操作（ori、addiu 的 op 各不相同），所以**主控制器对 op 译码后，通过 AluOp 直接命令 ALU 控制单元产生确定的 ALUctr**：
>
> + ori → **ALUctr = or**（按位或）；
> + addiu → **ALUctr = addu**（加法，**不做溢出判断**）。
>
> 同时主控制器置 **RegWr=1**（结果要写回）、**RegDst=1**（写 rt）、**ALUSrc=1**（B 口用立即数），并按指令给出 ExtOp。
>

#### <font style="color:rgb(0,0,0);">load/store 指令的数据通路</font>
![](https://cdn.nlark.com/yuque/0/2026/png/42876865/1789740675197-3f62dd5b-f3ca-4770-8775-5508a040857b.png)

![](https://cdn.nlark.com/yuque/0/2026/png/42876865/1789749171939-5a1be05b-04b5-4d06-8a3d-487f702b40d3.png)

lw/sw 都是 I 型指令，功能为：

+ `lw rt, rs, imm16`：**R[rt] ← M[ R[rs] + SEXT(imm16) ]**
+ `sw rt, rs, imm16`：**M[ R[rs] + SEXT(imm16) ] ← R[rt]**

两者前半段完全相同：立即数符号扩展后与 R[rs] 相加得到**访存地址**；区别只在数据流向——**<u><font style="color:#DF2A3F;">lw 从存储器读数送 rt，sw 把 rt 的数据写入存储器</font></u>**。为此通路新增两样东西：

1. **<font style="color:#DF2A3F;">数据存储器</font>**：Adr 接地址、DataIn 接待写数据、WrEn 是写使能（MemWr）、输出端送出读出数据；
2. **写回****<font style="color:#DF2A3F;">多路选择器 MUX(3)</font>**：由 **MemtoReg** 控制，选择把 ALU 结果还是存储器读出数据经 busW 写入寄存器。

:::color1
**计算访存地址（与 I 型运算指令共用通路）**

1. 取指、字段分流同前：rs[25:21] 送 Ra，rt[20:16] 送 Rb 和 MUX(1)，imm16[15:0] 送扩展器；
2. R[rs] 经 busA 进 ALU 的 A 口；
3. 主控制器令 **ExtOp 选择符号扩展**（访存偏移量带正负号），**ALUSrc=1** 使 MUX(2) 选扩展后的立即数进 B 口；
4. **ALUctr=addu**：做不判溢出的加法，ALU 输出就是访存地址，送数据存储器的 **Adr**。

:::

| :---: | :---: | :---: |
| <font style="color:rgb(0, 0, 0);">Adr（地址）</font> | <font style="color:rgb(0, 0, 0);">ALU 输出</font> | <font style="color:rgb(0, 0, 0);">R[rs]+SEXT(imm16)</font> |

> <font style="color:#000000;">注意它与指令存储器的区别：指令存储器只读，被当作纯组合逻辑；数据存储器可写，是带 CLK 的状态单元——但它的</font>**<font style="color:#000000;">读</font>**<font style="color:#000000;">仍然是组合的，不占额外周期。</font>
>

:::warning
新增部件之二：**MUX(3) 与 MemtoReg**——写回数据从哪来

寄存器堆 WD 的数据来源现在有两种，MUX(3) 二选一：

+ **MemtoReg = 0 → 选 0 端（ALU 结果）**：R 型、I 型运算指令写回运算结果；
+ **MemtoReg = 1 → 选 1 端（存储器取出数据）**：lw 写回从内存读出的 32 位数。

选中的数据经 **busW** 送 WD；写地址由 MUX(1) 决定，lw 时 RegDst=1 选 Rt，与指令"结果送 rt"一致。sw 不写寄存器，**RegWr=0**。

:::

#### <font style="color:rgb(0,0,0);">beq 指令的数据通路</font>
![](https://cdn.nlark.com/yuque/0/2026/png/42876865/1789749774048-ba70e532-83be-49b6-89cc-6b291b852008.png)

`beq rs, rt, imm16`（相等则分支）：

+ **Cond ← R[rs] − R[rt]**；
+ 若 Cond = 0（两寄存器相等）：**PC ← PC+4 + (SEXT(imm16) × 4)**；
+ 否则顺序执行：**PC ← PC+4**。

它不写寄存器、不访存，只做两件事：**用减法判相等**、**算分支目标地址并决定 PC 来源**。为此通路在 lw/sw 版本上新增：

1. ALU 的 **Zero（ZF）标志** + 一个**与门**；
2. 一条**目标地址计算支路**：扩展器输出 → 左移 2 位 → 分支加法器（与 PC+4 相加）；
3. PC 输入端加 **MUX(4)**，在 PC+4 与分支目标之间二选一。

:::color1
**<u><font style="color:#DF2A3F;">判等</font></u>**：**复用 ALU 做一次减法**

1. rs 送 Ra、rt 送 Rb，R[rs] 经 busA、R[rt] 经 busB 到 ALU 两个输入端；
2. 控制信号 **ALUSrc=0**，MUX(2) 选 busB（不用立即数）；
3. **ALUctr=sub**，ALU 计算 R[rs]−R[rt]；
4. ALU 的 **ZF(Zero)** 标志：结果为 0 时 ZF=1（相等），否则 ZF=0。

减法的"结果"本身被丢弃，只用它的**零标志**。

:::

:::warning
**<u><font style="color:#DF2A3F;">目标地址</font></u>**：与判等并行的另一条组合逻辑链

在 ALU 做减法的同时，地址链也在算：

1. imm16 经扩展器**符号扩展**（ExtOp=符号，偏移量可正可负）；
2. **左移 2 位（×4）**：MIPS 指令定长 4 字节、按字节编址，指令条数偏移要乘 4 才变成字节地址；
3. 分支加法器把 **(SEXT(imm16)×4)** 与 **PC+4** 相加，得到分支目标地址，送 MUX(4) 的 **1** 端；
4. PC+4 由原来的加法器算好，同时送 MUX(4) 的 **0** 端。

这条链全是组合逻辑，与判等同时完成，不占额外周期。16 位偏移对应 ±2¹⁵ 条指令，即相对当前指令向前 32767 条、向后 32768 条。

:::

:::color4
**分支判定与 PC 更新**

+ 主控制器  令 **Branch=1**（其他指令 Branch=0）；
+ 与门输出 ** Branch · ZF**：
    - **输出0**（非 beq，或 beq 但不相等）→ MUX(4) 选 0，**PC ← PC+4**，顺序执行；
    - **输出1**（beq 且相等）→ MUX(4) 选 1，**PC ← 分支目标地址**，完成跳转；
+ 选中的地址在**时钟沿写入 PC**——**<u><font style="color:#DF2A3F;">beq 唯一发生的时序动作就是 PC 更新</font></u>**。

:::

### 无条件转移指令（Jump，j）的数据通路
![](https://cdn.nlark.com/yuque/0/2026/png/42876865/1789754248212-5d811831-1086-41b5-bdcd-f0eb1713570f.png)

**字段划分**：$ \begin{array}{|c|c|}
\hline
\text{OP (6位)} & \text{直接地址 Target Address (26位)} \\
\hline
\end{array} $

**目标地址计算方法**：

+ 将指令中的 26 位直接地址**左移 2 位**（末尾补两个 `0`，因为指令按字对齐，地址最后两位必为 0），得到 28 位。
+ 拼接上**当前 PC（或下一条指令 PC）的高 4 位**，最终组合成一个 32 位的绝对目标地址。
+ 公式：$ \text{Target\_PC} = PC[31:28] \mathbin{\Vert} (\text{target} \ll 2) $

跳转目标不经过 ALU 计算，而是直接由指令中的 26 位地址码"拼"出来。为此通路在 beq 版本上新增：

1. 指令 **target[25:0] → 左移 2 位**部件，输出 28 位 [27:0]；
2. 与 **PC+4 的高 4 位 [31:28]** 拼接，得到 32 位跳转目标地址；
3. PC 输入端再加一级 **MUX(5)**，由控制信号 **Jump** 选择。

:::color1
跳转目标地址：26 → 28 → 32 位的拼接

1. 取指后，指令低 26 位 target[25:0] 送入 **<<2（左移 2 位）**：因指令按字节编址、指令长 4 字节，26 位"指令字序号"要乘 4，低位自动补两个 0，得到 **28 位 [27:0]**；
2. 取**顺序下条指令地址 PC+4 的最高 4 位 [31:28]** 作为基址；
3. 两者拼接：**高 4 位（PC+4）＋ 26 位 target ＋ 低 2 位 00 = 32 位目标地址**。

为什么高 4 位跟 PC+4 走？这样跳转目标与当前指令一定落在同一个 256 MB 段内（2²⁸=256 MB）

:::

PC 前现在串了两级选择器：

+ **MUX(4)**：由 PCSrc = Branch·ZF 控制，0 选 PC+4、1 选 beq 分支目标；
+ **MUX(5)**：由 **Jump** 控制，0 选 MUX(4) 的结果（顺序或分支），**1 选 j 拼接目标**。

于是三种来源统一为：

| 情形 | Jump | PCSrc(Branch·ZF) | 下条地址 |
| --- | --- | --- | --- |
| 顺序执行 | 0 | 0 | PC+4 |
| beq 且相等 | 0 | 1 | PC+4+(SEXT(imm)×4) |
| **j 指令** | **1** | 任意 | **{PC+4[31:28],target,00}** |


Jump=1 时 MUX(5) 直接切到跳转目标，**无条件跳转优先级高于分支**。
