# 程序访问的局部性原理

### 一、 核心概念与本质
在较短时间间隔内，程序产生的地址往往集中在存储空间的一个很小范围，这种现象称为**程序访问的局部性** 。掌握局部性，核心在于区分时间和空间两个维度：

+ **时间局部性 ：** 强调“重复访问”。被访问的某个存储单元在一个较短的时间间隔内**<font style="color:#DF2A3F;">很可能又被访问</font>** 。
+ **空间局部性 ：** 强调“按序访问”。被访问的某个存储单元的**<font style="color:#DF2A3F;">邻近单元</font>**在一个较短的时间间隔内很可能也被访问 。

**为什么会出现局部性？**

+ **指令层面：** 程序由指令组成，指令在主存中按顺序连续存放；此外，循环程序段或子程序段通常会被重复执行 。
+ **数据层面：** 数据（尤其是数组等结构）在主存中一般也是连续存放的，常常被按序重复访问 。



**步长 k**：访问一个**<u>连续数组</u>**时，每隔 k 个元素访问一次。

+ 步长为 1 = **顺序引用模式**，是空间局部性最重要的来源
+ **步长越大，空间局部性越差**

```plain
步长1：访问 a[0], a[1], a[2], a[3]...     ← 空间局部性最好
步长N：访问 a[0][0], a[1][0], a[2][0]... ← 跨行访问，空间局部性差
```



### 二、 评判局部性的重要原则
在分析任何一段代码时，可以直接套用以下三条原则来快速定性：

1. **变量重复原则：** 对相同变量有重复访问的程序有良好的时间局部性 。
2. **步长最小原则：** 步长越小，空间局部性越好 。步长为1的引用模式（顺序引用）空间局部性极佳，而在内存中大步长跳跃会极大破坏空间局部性 。
3. **循环体原则：** 循环体一般具有良好的时间局部性和空间局部性；**<u><font style="color:#DF2A3F;">循环体越小、迭代次数越多，局部性越好 。</font></u>**<font style="color:rgb(51, 51, 51);">（循环体指令连续存放 → 空间好；反复执行 → 时间好）</font>



## 三、 经典代码场景分析
#### 场景一：一维数组的遍历
**代码特征：** 简单的 `for(i=0; i<N; i++) sum += v[i];` 结构 。

+ **对于标量变量 (**`**sum**`**, **`**i**`**)：** 在每次迭代中都被频繁引用，因此**时间局部性极好**。因为是单个变量（通常分配在寄存器中），探讨其空间局部性没有意义 。
+ **对于数组元素 (**`**v[i]**`**)：** 按照内存存储顺序被一个接一个读取，属于完美的**步长为1的引用模式**，因此**空间局部性极好**。但**<u>每个元素只被访问一次，所以时间局部性很差 。</u>**



#### 场景二：<font style="color:rgb(51, 51, 51);">行优先 vs 列优先遍历二维数组</font>
**前提**：数组元素按**行优先**方式存放在主存，M = N = 2048，每元素4字节。

![](https://cdn.nlark.com/yuque/0/2026/png/42876865/1776964530943-57646a7b-d88d-4b52-8c7f-118b64f4087c.png)

```c
// 程序段 P1：按行遍历（行优先访问）
int sum_array_rows(int a[M][N]) {
    int i, j, sum = 0;
    for (i = 0; i < M; i++)
        for (j = 0; j < N; j++)
            sum += a[i][j];      
    // 访问顺序：a[0][0], a[0][1], ..., a[0][2047], a[1][0]...
    return sum;
}

// 程序段 P2：按列遍历（列优先访问）
int sum_array_cols(int a[M][N]) {
    int i, j, sum = 0;
    for (j = 0; j < N; j++)
        for (i = 0; i < M; i++)
            sum += a[i][j];      
    // 访问顺序：a[0][0], a[1][0], ..., a[2047][0], a[0][1]...
    return sum;
}
```



**分析对比：**

| 分析对象 | P1（行遍历） | P2（列遍历） |
| :---: | :---: | :---: |
| 数组a 空间局部性 | **好**（步长1，与存放顺序一致） | **差**（步长N=2048，每次跨行跳8KB） |
| 数组a 时间局部性 | 差（每个元素只访问一次） | 差（每个元素只访问一次） |
| 变量 sum 时间局部性 | **好**（每次循环都访问） | **好**（每次循环都访问） |
| 变量 sum 空间局部性 | 无意义（标量，通常存寄存器） | 无意义 |
| for循环体 空间局部性 | **好**（指令连续存放） | **好**（指令连续存放） |
| for循环体 时间局部性 | **好**（内循环执行2048×2048次） | **好**（内循环执行2048×2048次） |


> **结论**：P1 和 P2 功能相同，但因内外循环顺序不同，P1 的空间局部性远优于 P2，**实际执行时间差异显著**（底层直接原因： Cache命中率不同）。
>



#### 场景三：<font style="color:rgb(51, 51, 51);">结构体数组的空间局部性比较</font>
```c
typedef struct {
    int vel[3];
    int acc[3];
} point;
point p[N];  // 结构体数组，按行优先顺序存放
```

```c
// clear1：先遍历vel，再遍历acc（两个分离的循环）
for (i = 0; i < n; i++) {
    for (j = 0; j < 3; j++) p[i].vel[j] = 0;
    for (j = 0; j < 3; j++) p[i].acc[j] = 0;
}

// clear2：在同一循环中同时清零vel和acc（合并）
for (i = 0; i < n; i++)
    for (j = 0; j < 3; j++) {
        p[i].vel[j] = 0;
        p[i].acc[j] = 0;   // vel[j] 与 acc[j] 不相邻，最大间隔 3×4=12B
    }

// clear3：外层按字段(j)，内层按元素(i)
for (j = 0; j < 3; j++)
    for (i = 0; i < n; i++) p[i].vel[j] = 0;// 相邻两次访问跨越整个结构体，间隔 6×4=24B
    for (i = 0; i < n; i++) p[i].acc[j] = 0;
    }
```

![](https://cdn.nlark.com/yuque/0/2026/png/42876865/1777105398226-c64698e1-ac31-4610-9caf-eb18582f228e.png)

分析：

+ **对于函数**`**clear1**`**，其数组访问顺序与在内存的存放顺序完全一致，因此，空间局部性最好**
+ **对于函数**`**clear2**`**，**其数组访问顺序在每个数组元素内跳越式访问，相邻两次访问的单元最大相差3个`int`型变量（相当于12B)，因此空间局部性比`clear1`差。若主存块大小比12B小，则大大影响命中率。
+ **对于函数**`**clear3**`**，其数组访问顺序与在内存的存放顺序不一致，**相邻两次访问的单元都相差6个`int`型变量（相当于24B）因此，空间局部性比`clear2`还差。若主存块大小比24B小，则大大影响命中率。

> **关键洞察**：结构体数组中，字段在结构体内是连续存放的，但不同结构体的同名字段之间有跨度。**按结构体（行）遍历比按字段（列）遍历的空间局部性好**，道理与二维数组行列遍历完全相同。
>

4. 阅读以下程序

```c
int val[N];       // 数组，顺序存放
int idx[N];       // 索引数组，存放0~N-1的随机排列

// 程序M
int sum = 0;
for(i = 0; i < N; i++)
    sum += val[i];

// 程序K
int sum = 0;
for(i = 0; i < N; i++)
    sum += val[idx[i]];  
```

以下说法正确的是（ ）。

A. M和K对 `<font style="color:rgb(96, 96, 96);background-color:rgb(236, 236, 236);">val</font>` 的空间局部性相同，因为都访问了所有元素  
B. K对 `<font style="color:rgb(96, 96, 96);background-color:rgb(236, 236, 236);">idx</font>` 有良好的空间局部性，对 `<font style="color:rgb(96, 96, 96);background-color:rgb(236, 236, 236);">val</font>` 的空间局部性取决于 `<font style="color:rgb(96, 96, 96);background-color:rgb(236, 236, 236);">idx</font>` 中值的分布

D. M 和 K 对 `**<font style="color:rgb(96, 96, 96);background-color:rgb(236, 236, 236);">val</font>**` 的时间局部性相同，且均表现出良好的时间局部性，因为两段程序都完整遍历了 `**<font style="color:rgb(96, 96, 96);background-color:rgb(236, 236, 236);">val</font>**` 的所有元素
