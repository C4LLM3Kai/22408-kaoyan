## 网络层的功能

网络层提供**主机到主机**的通信服务，任务是把分组经过**多个网络**和**多段链路**从源主机传到目的主机，可分解为**路由选择**（走哪条路径）与**分组转发**（分组到达时做什么动作），传输单位是**数据报**。TCP/IP 的网络层向上只提供**无连接的、尽最大努力交付**的数据报服务：分组可能出错、丢失、重复、失序或超时，可靠性由运输层负责。

| 对比方面 | 虚电路服务 | 数据报服务 |
| :--- | :--- | :--- |
| 核心思想 | 可靠通信由网络自身保证 | 可靠通信由用户主机保证 |
| 连接 | 必须先建立网络层连接 | 不需要建立连接 |
| 目的地址 | 仅连接建立阶段使用，之后只用虚电路号 | 每个分组都携带完整目的地址 |
| 分组转发 | 同一条虚电路的分组走同一路由 | 每个分组可独立走不同路由 |
| 分组顺序 | 总是按发送顺序到达 | 不一定按序到达 |
| 结点故障 | 经过该结点的所有虚电路被破坏 | 可另选路径，适应能力强 |
| 首部开销 | 小 | 大 |

:::warn 虚电路不等于可靠
虚电路能保证分组**按序**到达，但并不天然可靠。链路故障或拥塞丢包时网络层虚电路本身不重传：协议附加了确认与重传（如 X.25）才可实现可靠传输；无重传机制（如帧中继、ATM）则只是"面向连接但不可靠"。
:::

### 异构网络互连

**异构网络**指因特网中数以百万计的网络，其拓扑结构、寻址方案、性能以及所用协议都不尽相同。互连需要解决不同网络的接入机制、差错恢复方法、路由选择技术、寻址方案、最大分组长度、服务类型等问题。

**网络互连**通常指用**路由器**进行网络连接和路由选择。路由器是一台专用计算机（历史上文献也把网络层的路由器称为**网关**）。**中继系统按层次分为四类**：

| 中继系统层次 | 设备 | 互连效果 |
| :--- | :--- | :--- |
| 物理层 | 转发器、集线器 | 只是把一个网络扩大了，从网络层看仍是同一个网络 |
| 数据链路层 | 网桥、交换机 | 同上，仍属于同一个网络 |
| 网络层 | 路由器 | 真正的网络互连，各网络在网络层仍彼此独立 |
| 网络层以上 | 网关 | 应用层互连 |

因此**只用物理层或数据链路层的中继系统不叫网络互连**——它们没有把"网络"这个层次连接起来，只是扩大了同一个网络的规模。

**虚拟互连网络**（又称逻辑互连网络、**IP 网络**）：各种物理网络的异构性本来客观存在，但通过 **IP 协议**可使这些性能各异的网络在网络层上看起来像一个统一的网络。

:::key 为什么用 IP 而不是 MAC 地址统一寻址
若只用 MAC 地址通信，每台路由器的路由表就必须记录**所有主机和路由器各接口的 MAC 地址**：手工配置不可能完成；自动构建也会因路由信息含海量 MAC 地址而严重占用通信资源，还需极大存储空间与查表时延。用 **IP 地址按网络号寻址**，路由表只需记录**部分网络的网络地址**。这是两种地址并存的原因。
:::

### 路由与转发

- **路由选择（routing）**：根据路由协议**构造路由表**，经常或定期地与相邻路由器交换信息，动态更新维护路由表以决定最优路径。**涉及很多路由器**。
- **分组转发（forwarding）**：路由器根据**转发表**把收到的 IP 数据报从合适的端口转发出去。**仅涉及一个路由器**。

| | 路由表 | 转发表 |
| :--- | :--- | :--- |
| 来源 | 由**路由选择算法**生成 | 由路由表**导出** |
| 内容 | 目的网络、下一跳，还存放跳数、链路状态等算法参数 | 只保留转发必备条目，剔除算法相关附加信息 |
| 优化目标 | **最优化网络拓扑变化的计算** | **最优化查找过程** |
| 实现 | 一般用软件 | 可用软件也可用硬件 |

### SDN 基本概念

**软件定义网络**（Software Defined Network，**SDN**）采用**集中式的控制平面**和**分布式的数据平面**（转发平面），两个平面相互分离。控制平面利用**控制-数据接口**对数据平面上的路由器进行**集中式控制**。

传统路由器既有转发表又有路由选择软件（即既有数据平面又有控制平面），路由器之间传送**主机间的分组**和**路由信息**。SDN 体系结构中路由器中的路由软件都不存在了，因此路由器之间不再交换路由信息。

- **控制平面**中有一个在**逻辑上集中**的**远程控制器**，物理上可由不同地点的多个服务器组成。
- 远程控制器掌握各主机和整个网络的状态，为每个分组计算出**最佳路由**并为每个路由器生成转发表。**路由器的工作很单纯：收到分组、查转发表、转发分组。**
- 核心思想：**把控制层面和数据层面分离，让控制层面利用软件来控制数据层面的设备**，网络又变成**集中控制**的。

**OpenFlow 协议**是 SDN 体系结构中**控制层面与数据层面之间的通信接口**。传统数据层面的任务是按转发表转发分组，分两步：**匹配**（查转发表中的网络前缀，做**最长前缀匹配**）与**动作**（从匹配结果指明的接口转发）。SDN 的**广义转发**范围大大扩展：匹配可对各层（数据链路层、网络层、运输层）首部字段进行；动作不仅转发，还可**负载均衡**、**重写 IP 首部**（类似 NAT）、**阻挡或丢弃分组**（类似防火墙）。因此完成"匹配＋动作"的设备不再称路由器，而称"**OpenFlow 交换机**"或分组交换机；取代转发表的是"**流表**（Flow Table）"。

- 一个**流**是穿过网络的一种**分组序列**，序列中每个分组都**共享首部某些字段的值**（例如相同源、目的 IP 地址的一连串分组）。
- **流表由 SDN 远程控制器管理**，控制器通过安全信道用 OpenFlow 协议管理交换机的流表。
- 每个交换机必须有**一个或多个流表**，每个流表可含**多个流表项**。
- 每个流表项含三个字段：**首部字段值**（**匹配字段**）、**计数器**、**动作**。匹配不上的分组被丢弃或送往远程控制器。OpenFlow 交换机既处理链路层帧，也处理 IP 数据报与 TCP/UDP 报文。
- **计数器**记录已匹配的**分组数量**和**该流表项上次更新至今的时间**。
- **动作**可转发到指明端口、丢弃、复制后从多端口转发、重写各层首部。

**SDN 体系结构的接口**：

| 接口 | 连接对象 | 作用 |
| :--- | :--- | :--- |
| **北向接口** | 面向**上层应用**开发者 | 提供丰富 API，不必关心底层硬件细节 |
| **南向接口** | **控制器与转发设备**之间 | 建立双向会话；典型协议是 **OpenFlow**，可兼容不同硬件 |
| **东西向接口** | 控制器集群**内部控制器之间** | 增强控制平面的可靠性和可扩展性 |

SDN 的**四个关键特征**：基于流的转发；数据层面与控制层面分离；网络控制功能位于分组交换机之外；可编程的网络。

**优点**：全局集中式控制与分布式高速转发并存；可用自动化工具编程配置；采用开放接口协议后设备制造与功能软件开发相分离，降低成本。**问题**：集中管理易受攻击，崩溃则全网受影响；规模扩大后控制器可能成为性能瓶颈。

:::exam 真题考法
2022 年第 37 题考"SDN 控制器向数据平面的 SDN 交换机下发流表时使用的接口"，答案是**南向接口**。北向接口面向上层网络应用，东西向接口用于控制器之间协同。
:::

### 拥塞控制

**拥塞**指因出现过量的分组而引起网络性能下降的现象。判断方法是观察**吞吐量与网络负载**的关系：若负载增加而吞吐量明显小于正常值，则进入**轻度拥塞**；若吞吐量**随负载增大而下降**，则已**进入拥塞**。

**拥塞控制**要解决如何获取网络中发生拥塞的信息并据此控制，**避免因拥塞而出现分组丢失**，作用是确保网络能够承载所达到的流量：

- **开环控制**：设计网络时事先把拥塞因素考虑周到，力求不产生拥塞，是**静态的预防方法**，一旦启动中途不再修改，做决定时**不考虑当前网络状态**。手段包括确定何时可接收新流量、何时可丢弃分组及丢弃哪些分组、确定何种调度策略。
- **闭环控制**：事先不考虑拥塞因素，用监测系统监视，检测到哪里发生拥塞后把信息传到合适的地方以调整网络运行，基于**反馈环路**，是**动态的方法**。

**与流量控制的区别**：流量控制指发送方与接收方之间的**点对点通信量控制**，目的是**抑制发送方速率，使接收方来得及接收**；拥塞控制关注整个网络的负载，是全局性的。

## 路由算法

### 静态路由与动态路由

路由算法的目的是找到从源路由器到目的路由器的"最佳"路径（通常是费用最低的路径）。所有最短路径算法都依赖一个性质：**两点之间的最短路径也包含了路径上其他顶点间的最短路径**。

| 静态路由选择 | 动态路由选择 |
| :--- | :--- |
| 采用**人工配置**方式添加网络路由、默认路由、特定主机路由 | 路由器通过路由选择协议**自动获取**，路由器间彼此交换信息并按算法优化出路由表项 |
| **简单、开销小**，但不能及时适应网络状态变化 | **较复杂、开销较大**，但能较好地适应网络状态变化 |
| 一般只在**小规模网络**采用 | 适用于**大规模网络** |

**默认路由**用特殊前缀 `0.0.0.0/0` 表示：`0.0.0.0` 表示任意网络，`/0`（掩码 `0.0.0.0`）是**最短**网络前缀。全 0 掩码与任何目的地址按位与必为全 0，因此必然匹配。只要目的网络不在转发表中，就一律选择默认路由，通常用于路由器到互联网的路由。由于最长前缀匹配，**默认路由匹配优先级最低**。

**特定主机路由**对某台主机的 IP 地址专门指明路由，便于管理员控制与测试网络。若主机地址是 a.b.c.d，则目的网络是 `a.b.c.d/32`，掩码 `255.255.255.255` 是最**长**前缀，因此**匹配优先级最高**。

路由匹配优先级：**特定主机路由 > 最长前缀子网路由 > 默认路由**。

:::warn 静态路由配置的陷阱
可能出现两类问题：**路由条目配置错误，甚至导致路由环路**；**聚合路由条目时可能引入不存在的网络**（聚合后的地址范围大于原子网并集，把未分配地址也通告出去）。
:::

### 距离-向量路由算法

距离-向量算法是**分散型**的：路由器只掌握物理相连的邻居及链路费用，通过反复与邻居交换信息逐步收敛，其理论基础是 **Bellman-Ford 算法**。设 `d_x(y)` 为结点 x 到 y 的最短路径费用，`c(x,v)` 为 x 到邻居 v 的费用，则

$$d_x(y)=\min_{v}\{\,c(x,v)+d_v(y)\,\}$$

其中 **v 取遍 x 的所有邻居**。每个结点维护三组信息：到每个直连邻居的链路费用 `c(x,v)`；自己的**距离向量**；收到的**每个邻居的距离向量**。

**算法流程**：每个结点定期向每个邻居发送距离向量副本。当 x 从邻居 v 收到新距离向量时，先保存它，再用 Bellman-Ford 公式更新自己的距离向量；若自己的距离向量因此改变，则继续向每个邻居发送更新后的距离向量。

**收敛小例子**：三结点 x、y、z，`c(x,y)=2`、`c(x,z)=7`、`c(y,z)=1`。初始化时各结点只知道自己到直连邻居的费用：`d_x=(0,2,7)`、`d_y=(2,0,1)`、`d_z=(7,1,0)`。第一次交换后 x 计算 `d_x(y)=min{2+0, 7+1}=2`、`d_x(z)=min{2+1, 7+0}=3`，得 `d_x=(0,2,3)`。再次交换后若无变化则不再发送更新报文，算法进入**静止状态**（收敛）。

:::warn 更新报文的规模
更新报文大小与网络中结点数目成正比，大型网络将导致很大的更新报文，这是距离-向量算法可扩展性差的根本原因。最常见的距离-向量路由算法是 **RIP**，采用"跳数"作为距离度量。
:::

#### 路由环路与坏消息传得慢

距离-向量算法有一个固有问题：**好消息传得快，坏消息传得慢**，又称**路由环路**或**距离无穷计数问题**。

**环路如何形成**：B 到网络 N 的距离本是 1。当 N 真正不可达时，B 又可能从 A 那里学到"N 距离 2"，算得 `2+1=3` 认为经 A 可到 N；A 再从 B 学到 3、算得 4……两个路由器互相"欺骗"对方"你再加一跳就能到达"，距离在二者之间逐次加 1，直到 16 才停止。

**缓解措施**：

- 限制**最大 RIP 距离为 15**（16 表示不可达），使无穷计数在有限步内终止；
- **触发更新**：路由表变化时立即发送更新报文，而不仅是周期性发送；
- **水平分割**：记录收到某条路由信息的接口，不让同一信息再从该接口反向发回；
- **毒性逆转**：向学到此路由的那个接口通告时，**把距离直接置为 16**而不是不发。这比水平分割更彻底——不发报文时对方可能仍持旧信息，显式通告 16 能让对方立即删除该路由。

:::warn 措施只能缓解，不能彻底解决
距离-向量算法中每个路由器都缺少到目的网络整个路径的完整信息，无法判断所选路由是否出现环路。这与链路状态算法中每台路由器掌握全网拓扑形成根本差别。
:::

### 链路状态路由算法

**链路状态**（Link State，LS）指本路由器都和**哪些路由器相邻**，以及**相应链路的代价**。链路状态算法是**全局性**的：所有路由器掌握完整的网络拓扑和链路费用信息。

**主要思想**：每个结点都具有**全网拓扑结构图**（全网一致）；**主动测试所有相邻结点的状态**并**定期把链路状态传播给所有其他结点**；每个结点用 **Dijkstra 最短路径算法**计算到其他结点的最短路径。结点每收到一个链路状态报文就更新自己的"视野图"，一旦链路状态变化就用 Dijkstra 重新计算。

**Dijkstra 执行要点**：以本路由器为源点，维护"已确定最短路径的结点集合"，每次从集合外选出当前距离最小的结点加入集合，并用它**松弛**其所有邻居的距离，时间复杂度 $O(n^2)$（n 为结点数）。由于各路由器使用**同样的链路状态数据独立计算**，算出的路径必然一致，因此**从算法上保证了不会产生路由环路**。

**优点**：各结点用同样的链路状态数据独立计算路径，不依赖中间结点的计算，易于查找故障；链路状态报文仅运载单个结点关于直接链路的信息，**大小与网络结点数目无关**，所以规模可伸展性更好，**适用于大型或路由信息变化剧烈的互联网环境**。

**两类算法对比**：距离-向量算法中每个结点仅与直接邻居交谈，向邻居发送**自己的整个路由表**，报文大小取决于结点数目，代价较大；链路状态算法中每个结点通过**洪泛**与所有其他结点交谈，但只告诉它们**与自己直接相连的链路费用**。

### 层次路由

因特网规模非常大，且许多单位不愿让外界了解自己网络的布局细节，因此采用**分层次的路由选择协议**，特点有三个：**自适应**（动态路由选择，能较好适应网络状态变化）；**分布式**（各路由器通过相互间信息交互共同完成路由信息的获取与更新）；**分层次**（把整个因特网划分为许多较小的**自治系统**（Autonomous System，**AS**），内部和外部采用不同类别的路由选择协议）。

**自治系统**指在**单一的技术管理**下的一组路由器，这些路由器使用一种 AS 内部的路由选择协议和**共同的度量**确定 AS 内的路由，同时使用一种 AS 之间的路由协议确定 AS 之间的路由。一个 AS 内的所有网络都属于一个行政单位管辖，AS 内所有路由器必须连通。层次路由的效果是：路由器只知道自己所在区域内的目标地址如何路由，对其他区域的内部结构不知情，路由表规模因此大幅减小。

:::key 区域划分的代价与收益
分层次划分区域使交换信息的种类增多、OSPF 协议更复杂，但能使**每个区域内部交换路由信息的通信量大大减少**，从而让 OSPF 可用于规模很大的自治系统。这是典型的"用复杂度换可扩展性"。
:::

## IPv4

### IPv4 分组

IPv4 分组由**首部**和**数据部分**组成。首部前一部分长度固定，**共 20 B，是所有 IP 分组必须具有的**；后面是**可选字段**，长度可变（0～40 B），实际很少使用；当首部长度不是 4 字节整数倍时用**填充**补齐全 0 字节。

:::key 三个"基本单位"必须背熟
**首部长度以 4 B 为单位，总长度以 1 B 为单位，片偏移以 8 B 为单位。** 口诀"一种八片首饰"。IP 首部前两个字节往往以 `0x45` 开头，解题时可用于定位 IP 数据报的开始位置。
:::

**首部各字段逐项说明**：

| 字段 | 位数 | 含义与要点 |
| :--- | :--- | :--- |
| **版本** | 4 | IP 版本，IPv4 中该字段值是 4。通信双方的版本必须一致 |
| **首部长度** | 4 | **以 4 B 为单位**。最小取值 0101（5），乘 4 得 20 B，表示只有固定部分；最大取值 1111（15），得 60 B，表示含 20 B 固定部分和最大 40 B 可变部分 |
| **区分服务** | 8 | 用来获得更好的服务，实际上一直没有被真正使用过 |
| **总长度** | 16 | **首部＋数据载荷的长度和，单位字节 B**。最大 $2^{16}-1=65535$ B。以太网 MTU 为 1500 B，封装成帧时数据报总长度不能超过链路层 MTU |
| **标识** | 16 | 一个计数器，每产生一个数据报就加 1。**并不是"序号"**。同一数据报的所有分片**复制同一个标识号**，以便正确重装 |
| **标志** | 3 | 最低位 **MF**：MF=1 后面还有分片，MF=0 是最后一个分片。中间位 **DF**：**只有 DF=0 才允许分片**。最高位保留，必须为 0 |
| **片偏移** | 13 | 某片在原数据报中的相对位置，**以 8 B 为单位**。**除最后一个分片外，每个分片的数据长度一定是 8 B 的整数倍** |
| **生存时间 TTL** | 8 | 数据报可通过的路由器数的最大值，**防止被错误路由的数据报无限制兜圈**。以"跳数"为单位：路由器转发前减 1，不为 0 就转发，否则丢弃并发送 ICMP 时间超过报文 |
| **协议** | 8 | 指明数据载荷是何种 PDU。常用值：**ICMP=1，IGMP=2，TCP=6，UDP=17，OSPF=89** |
| **首部检验和** | 16 | **只检验首部，不包括数据部分**。因为每经过一个路由器某些字段（TTL、标志、片偏移等）都可能变化，都要重算检验和，不检验数据部分可减少计算量。IPv6 中路由器不再计算首部检验和 |
| **源 IP 地址** | 32 | 标识发送方 |
| **目的 IP 地址** | 32 | 标识接收方 |

:::warn 标志字段的位序
3 位标志从左到右依次是「保留位、DF、MF」，**最低位才是 MF**。若给出标志字段的十六进制值，必须展开为二进制后再按位判断。
:::

#### IP 数据报分片

**为什么要分片**：IP 数据报被封装在链路层的帧中，因此**链路层的 MTU**（最大传送单元）严格限制了 IP 数据报长度。以太网 MTU 为 **1500 B**，许多广域网 MTU 不超过 576 B。当数据报总长度大于链路 MTU 时，需要**把数据分装在多个较小的 IP 数据报中**，这些较小的数据报称为**片**。

**位置**：分片可由**源主机或路径上的路由器**进行；**重组只在目的主机**的网络层进行。每个分片独立传输，可能经过不同路径，甚至不一定按原次序到达。

**重组所用字段**：目的主机用**标识**、**标志**、**片偏移**完成重组。MF=1 表示还有后续片，MF=0 表示最后一片；片偏移确定该片应放在原始数据报的哪个位置。分片时**每个分片都复制原数据报首部的固定部分（20 B）**。

**DF=1 的情况**：不能分片而分组长度又超过 MTU 时，**丢弃该分组**，并用 **ICMP 差错报告报文**（终点不可达，代码"需要分片但设置了 DF 位"）向源主机报告。

:::key IP 分片完整计算步骤（必背）
设原数据报总长 $L$（首部 $H$ 字节，通常 20 B），链路 MTU 为 $M$。
1. 原数据部分长度 $D=L-H$。
2. 每片最多携带的数据长度：$d_{\max}=\left\lfloor\dfrac{M-H}{8}\right\rfloor\times 8$。
3. 分片个数 $n=\left\lceil\dfrac{D}{d_{\max}}\right\rceil$；前 $n-1$ 片各携带 $d_{\max}$ 字节，最后一片携带剩余 $D-(n-1)d_{\max}$ 字节（可以不是 8 的倍数）。
4. 每片**总长度字段** $=d_i+H$（**含首部**）。
5. 每片**片偏移字段** $=\dfrac{\text{该片之前已发送的数据字节数}}{8}$。
6. **MF**：前 $n-1$ 片为 **1**，最后一片为 **0**。所有片**标识相同**，DF 均为 0。
:::

**【算例 1】** 某 IPv4 数据报总长度 3820 B，采用 20 B 固定首部，需分片为长度不超过 1420 B 的数据报片。

解：$D=3820-20=3800$ B。每片最多 $1420-20=1400$ B，且 $1400=175\times 8$ 恰为 8 的整数倍，故 $d_{\max}=1400$。$n=\lceil 3800/1400\rceil=3$：$1400+1400+1000=3800$。

| 分片 | 数据长度/B | 总长度字段/B | 片偏移字段 | MF |
| :--- | :--- | :--- | :--- | :--- |
| 第 1 片 | 1400 | 1420 | 0 | 1 |
| 第 2 片 | 1400 | 1420 | $1400/8=175$ | 1 |
| 第 3 片 | 1000 | 1020 | $2800/8=350$ | 0 |

**【算例 2：真题型】** 2021 年第 36 题：路由器向 MTU=800 B 的链路转发总长度 1580 B 的 IP 数据报（首部 20 B），分片时每片尽可能大，则第 2 个分片的总长度字段和 MF 分别是多少？

解：$D=1580-20=1560$ B。每片最多 $800-20=780$ B，但除最后一片外必须是 8 的整数倍，故 $d_{\max}=\lfloor 780/8\rfloor\times 8=776$ B。$n=\lceil 1560/776\rceil=3$：$776+776+8=1560$。

| 分片 | 数据长度/B | 总长度字段/B | 片偏移字段 | MF |
| :--- | :--- | :--- | :--- | :--- |
| 第 1 片 | 776 | 796 | 0 | 1 |
| 第 2 片 | 776 | **796** | $776/8=97$ | **1** |
| 第 3 片 | 8 | 28 | $1552/8=194$ | 0 |

答案：**796，1**（选项 B）。

:::warn 分片三大易错点
1. **总长度字段包含首部**，第 2 片总长度是 $776+20=796$，不是 776，也不是 800。
2. **片偏移的单位才是 8 B**，不是"总长度必须是 8 的倍数"——第 3 片总长度 28 就不是 8 的倍数。
3. **只有除最后一片外的数据长度必须是 8 B 的整数倍**；最后一片可为任意长度。
:::

**【算例 3：两级分片】** 总长 1500 B（首部 20 B）的 IP 数据报先经 MTU=800 B 的链路 R1→R2，再经 MTU=400 B 的链路 R2→R3，求 R2 分出的各子分片参数。

解：第一级（MTU=800）：$D=1480$，$d_{\max}=\lfloor 780/8\rfloor\times 8=776$，分片为 $776+704$。

| R1 分片 | 数据/B | 总长度/B | 片偏移 | MF |
| :--- | :--- | :--- | :--- | :--- |
| F1 | 776 | 796 | 0 | 1 |
| F2 | 704 | 724 | 97 | 0 |

第二级（MTU=400）只需对 F1 再分：$d_{\max}=\lfloor(400-20)/8\rfloor\times 8=47\times 8=376$ B。F1 的 776 B 分为 $376+376+24$。**关键性质**：第二级分片的片偏移是在**原数据报**范围内的偏移，新片偏移 $=$ 父分片片偏移 $\times 8+$ 在父分片内的字节偏移。

| 由 F1 分出 | 数据/B | 总长度/B | 片偏移 | MF |
| :--- | :--- | :--- | :--- | :--- |
| 子片 1 | 376 | **396** | $(0+0)/8=0$ | 1 |
| 子片 2 | 376 | 396 | $(0+376)/8=47$ | 1 |
| 子片 3 | 24 | 44 | $(0+752)/8=94$ | **1** |

第三个子分片的 MF **仍是 1**，因为它由 F1 分出而 F1 的 MF=1，后面还有 F2；F2 的 MF=0 才表示整个数据报结尾。

#### 首部检验和的计算

**发送方**：① 把首部划分为若干个 **16 比特字**序列（20 B 固定首部正好 10 个字）；② 把**首部检验和字段置为全 0**；③ 用**反码算术运算**把所有 16 比特字相加；④ 把**和取反码**写入首部检验和字段。

**接收方**：把首部所有 16 比特字（此时含检验和）再用反码算术运算相加，并把和取反码。若首部无差错，结果必为 **0**，保留该数据报；否则认为出错，丢弃该数据报。

**二进制反码求和规则**（从低位到高位逐列）：0+0=0；0+1=1；1+1=0 并产生进位 1 加到下一列；**若最高位相加后产生进位，则结果要再加 1**（"进位绕回来加到末尾"）。

:::warn 首部检验和的两个易错点
1. **接收方发现检验和出错后直接丢弃数据报，不发送差错报告**（ICMP 差错报文不针对首部检验和错误）。
2. 该方法与 UDP、TCP 的检验和**计算方法相同**，但 **IP 校验没有伪首部**。这个算法常被称为因特网检验和（Internet Checksum），检错性能不如 CRC，但更易用软件实现。
:::

**【算例】** 对典型首部 `45 00 00 3C 1C 46 40 00 40 06 00 00 C0 A8 00 01 C0 A8 00 C7` 求首部检验和。

逐字相加（检验和字段先置 0）：`4500+003C+1C46+4000+4006+0000+C0A8+0001+C0A8+00C7`，按列运算得 `0x43FF6`。把高 16 位溢出部分 `4` 加回低 16 位：`0x3FF6+4=0x3FFA`。取反码得 **`0xC005`**。

**验证**：接收方把全部 10 个字（含 `C005`）相加得 `0x4FFFB`，进位 `4` 回加得 `0xFFFF`，取反码为 `0x0000`，校验通过。

### IPv4 地址与 NAT

#### IPv4 地址与分类编址

**定义**：IPv4 地址是给因特网上**每一个主机（或路由器）的每一个接口**分配的、全世界范围内唯一的 **32 比特标识符**，由**网络号和主机号**两部分组成：

$$\text{IP 地址}=\{\,<\text{网络号}>,<\text{主机号}>\,\}$$

用**点分十进制**表示：32 比特按 8 位一组分为 4 组，每组写十进制，用点分隔。

| | 网络号 | 主机号 |
| :--- | :--- | :--- |
| 标志 | 接口所连接到的**网络** | 主机（或路由器）的**接口** |
| 规则 | 同一网络中不同主机接口的**网络号必须相同** | 同一网络中不同主机接口的**主机号必须各不相同** |

**分类编址**：按左起第一个十进制数判断——小于 127 为 A 类，128～191 为 B 类，192～223 为 C 类，224～239 为 D 类，240～255 为 E 类。

| 类别 | 首位模式 | 网络号位数 | 网络号范围 | 可指派网络数 | 每网可分配地址数 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| A | 0 | 8 | 1～126 | $2^{7}-2=126$ | $2^{24}-2=16777214$ |
| B | 10 | 16 | 128.0～191.255 | $2^{14}=16384$ | $2^{16}-2=65534$ |
| C | 110 | 24 | 192.0.0～223.255.255 | $2^{21}=2097152$ | $2^{8}-2=254$ |
| D | 1110 | — | 224.0.0.0～239.255.255.255 | — | 多播地址，不分配给主机接口 |

A 类中**最小网络号 0 表示本网络不能指派**，**最大网络号 127 作为环回测试地址不能指派**，故可指派 A 类网络数为 $2^{8-1}-2=126$。最小环回地址 127.0.0.1，最大环回地址 127.255.255.254。

:::key "减 2" 的含义
- A 类网络数减 2：去掉网络号 0（本网络）和 127（环回）。
- 每个网络可分配地址数减 2：去掉**主机号全 0 的网络地址**和**主机号全 1 的广播地址**。
:::

**A、B、C 类都是单播地址**，只有单播地址可分配给主机（或路由器）的接口。**主机号全 0 是网络地址，主机号全 1 是广播地址，都不能分配。**

**一般不使用的特殊 IPv4 地址**：

| 网络号 | 主机号 | 地址示例 | 作源 | 作目的 | 用途 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| 全 0 | 全 0 | 0.0.0.0 | 可以 | **不可以** | 本网络的本主机（DHCP 初始态）；路由表中表示默认路由 |
| 全 0 | host-id | 0.0.0.5 | 可以 | **不可以** | 本网络上的某台特定主机 |
| 全 1 | 全 1 | 255.255.255.255 | **不可以** | 可以 | 只在本网络广播（路由器不转发），又称**受限广播地址** |
| net-id | 全 0 | 192.168.1.0 | 不可以 | 不可以 | **网络地址**，表示一个网络本身 |
| net-id | 全 1 | 192.168.1.255 | 不可以 | 可以 | 对网络 net-id 上所有主机广播，又称**直接广播地址**（可跨路由器，只被目标网络内主机接收） |
| 127 | 非全 0/全 1 | 127.0.0.1 | 可以 | 可以 | **本地软件环回测试**，目的地址为环回地址的数据报永远不会出现在任何网络上 |

:::key 特殊地址速记口诀
**全 0 的地址只能当源，不能当目的；全 1 的地址只能当目的，不能当源；127 开头源目都能用，但不走外网；主机号全 0/全 1 的地址永远不能分给主机用。** 路由器收到目的地址为 255.255.255.255 的分组不转发。
:::

**IP 地址的重要特点**：**只配网络号**（管理机构只分配网络号，主机号由单位自行分配）；**只转发网络号**（路由器仅根据目的网络号转发，减小路由表存储空间）；**一个接口一个地址**（路由器至少有两个以上 IP 地址，每个端口都有不同网络号的地址）；**同网同域**（用转发器或网桥连接的若干 LAN 仍属同一网络、同一广播域，网络号必须相同、主机号必须不同）；**众网平等**。

#### 网络地址转换 NAT

**背景与私有地址**：为网络安全划出了部分 IP 地址为私有 IP 地址。私有地址只用于 LAN，不用于 WAN 连接，必须通过网关用 NAT 转换为合法全球 IP 地址后才能出现在 Internet 上，且允许被 LAN 重复使用。**互联网中所有路由器对目的地址是私有地址的数据报一律不转发。** RFC 1918 规定的三个专用地址块：

| 类别 | 地址范围 | CIDR 前缀 |
| :--- | :--- | :--- |
| A 类 | 10.0.0.0～10.255.255.255 | 10.0.0.0/8 |
| B 类 | 172.16.0.0～172.31.255.255 | 172.16.0.0/12 |
| C 类 | 192.168.0.0～192.168.255.255 | 192.168.0.0/16 |

**定义**：网络地址转换（NAT）指把专用网络地址转换为公用地址，从而对外隐藏内部管理的 IP 地址，作用是连接内网和外网。**优点**是节省 IP 地址消耗（专用网只需一个全球 IP 地址就可与互联网连通，本地地址可重用）与降低安全风险（隐藏内部网络结构）。

**最基本的 NAT 与 NAPT**：因绝大多数网络应用使用 TCP 或 UDP，为更有效利用 NAT 路由器上的全球 IP 地址，现在常把 **NAT 转换与运输层端口号结合使用**。NAT 路由器用 **NAT 转换表**存储 **`{本地 IP 地址:端口} → {全球 IP 地址:端口}` 的映射**，正式名称是**网络地址与端口号转换**（Network Address and Port Translation，**NAPT**）。这种映射可让多个私有 IP 地址映射到一个全球 IP 地址，即内部专用网中**大量主机共用 NAT 路由器上的 1 个全球 IP 地址**。很多家用路由器就是 **NAPT 路由器**，但往往并不运行路由选择协议。

**NAT 工作原理（经典例子）**：主机 10.0.0.1（端口 3345）向 Web 服务器 128.119.40.186（端口 80）发请求。

1. NAT 路由器收到分组后生成新端口号 5001，把源地址改为 138.76.29.7（NAT 路由器的全球 IP 地址），源端口号改为 5001，并在 NAT 转换表中增加一个表项。
2. Web 服务器不知道分组已被改装，也不知道用户的专用地址，其响应分组目的地址是 138.76.29.7、目的端口号是 5001。
3. 响应分组到达 NAT 路由器后，通过转换表把目的 IP 地址改为 10.0.0.1、目的端口号改为 3345。

**同端口号的处理**：两个客户端 192.168.1.10 和 192.168.1.11 都用本地端口 1025 与服务器通信，二者都转换为公有地址 120.229.175.121，但用**不同的端口号**区分。这种转换表**自动生成**：TCP 情况下建立连接首次握手时的 SYN 包一经发出就生成表项，随收到关闭连接 FIN 包的确认应答而从表中删除。

:::key NAT 路由器与普通路由器的核心差别
**普通路由器**只处理网络层及以下数据，仅解析 IP 首部；**NAT 路由器**需要查看运输层端口号来维护 NAT 映射表，因此**同时作用于传输层、网络层及以下**。

报文修改规则：**出门改源 IP（变公网），进门改目的 IP（找内网）**。内网→外网修改**源 IP 地址、源端口号**；外网→内网修改**目的 IP 地址、目的端口号**。
:::

**NAT 的缺点与穿透问题**：NAT（和 NAPT）**对网络应用并不完全透明**；**通信必须由专用网内部发起**，因此**拥有内部专用地址的主机不能直接充当因特网中的服务器**——只有内网主机主动发起连接，NAT 设备才建立映射表，外网主机的返回报文依靠该映射转回内网；外网主机主动访问内网时 NAT 设备没有对应映射条目，报文无法转发到内网主机。对 P2P 这类需要外网主机主动与内网主机通信的应用，需要 **NAT 穿透技术**（端口转发、STUN、中继）。若配置**静态 NAT/端口映射**建立固定的 `外网IP:外网端口 ↔ 内网IP:内网端口` 对应关系，就能强行实现内网主机对外提供公网服务。

:::exam 真题考法
NAT 常与 CIDR 结合出综合题，核心是判断"分组经过某个 NAT 路由器后源/目的地址变成什么"。2016 年第 38 题中源地址换成 R2 外网接口地址 201.1.3.10，而**目的地址始终是最终的 Web 服务器地址 130.18.10.1**。铁律：**路由器转发不改变目的 IP 地址；只有 NAT 设备才按转换规则修改源或目的地址。**
:::

### 子网划分、路由聚集、子网掩码与 CIDR

#### 划分子网与子网掩码

**背景**：随着更多中小网络加入因特网，分类编址"不够灵活、容易造成大量 IPv4 地址资源浪费"的缺点暴露出来。申请新网络号需等待很长时间、花费更多费用，其他路由器还要新增路由条目，且浪费原网络中剩余的大量地址。若能**从主机号部分借用一些比特作为子网号**区分不同子网，就可利用原有网络中剩余的大量地址而不用申请新网络地址。

**定义**：划分子网是在 IP 地址中增加一个"**子网号字段**"，使两级 IP 地址变成三级：

$$\text{IP 地址}=\{\,<\text{网络号}>,<\text{子网号}>,<\text{主机号}>\,\}$$

**子网掩码**表明分类 IPv4 地址的主机号部分被借用了几个比特作为子网号。它也是 **32 比特**：左起多个**连续的比特 1** 对应**网络号和子网号**，之后的连续 0 对应**主机号**。把划分子网的 IPv4 地址与子网掩码逐比特**逻辑与**，就得到该地址所在**子网的网络地址**。

:::key 一句话结论
**只要给定了一个分类的 IPv4 地址及其相应的子网掩码，就可以得出子网划分的全部细节。** 这是子网划分所有计算题的解题总纲。
:::

**默认子网掩码**：所有网络都必须使用子网掩码；若未划分子网就使用默认掩码，**A、B、C 类分别为 255.0.0.0、255.255.0.0、255.255.255.0**。其他规定：路由器相互交换路由信息时必须告知对方本网络的子网掩码；转发时把目标地址与某网络掩码按位相与，结果与该网络地址一致则匹配成功；主机设置 IP 时必须设置子网掩码；**同属一个子网的所有主机及路由器相应端口必须设置相同掩码**；路由表主要信息是目的网络地址、子网掩码、下一跳地址。

**默认网关**是子网与外部网络连接的设备，即**连接本机或子网的路由器接口的 IP 地址**（离主机最近的路由器的接口地址）。主机发送数据时用子网掩码判定目的主机是否在同一子网：在则直接发送，不在则交给默认网关转发。

:::key 划分子网的核心结论
1. 划分子网增加子网数量，子网间传输需经路由器，因此**减小了广播域**；子网号占据主机号位，因此**减少每个子网的主机数量**。
2. **从一个 IP 地址本身无法判断该主机所连接的网络是否划分了子网**，单位外的网络看不见单位内的子网划分。
3. 划分子网只提高 IP 地址利用率，**不改变 IP 地址原有的类别归属**，也不增加"网络"数量。
4. 子网中主机号全 0 的地址是**子网的网络地址**，全 1 的是**子网的广播地址**，都不能指派给主机。
:::

#### 给定 IP 与掩码求网络地址、广播地址与可用地址范围

**标准解题步骤**：

1. **确定块大小**：找到掩码中发生变化（1→0）的那个字节，块大小 $=256-$ 该字节的十进制值。
2. **网络地址**：把 IP 中该字节的值**向下取到块大小的整数倍**，其后字节全部置 0。
3. **广播地址**：网络地址把主机位全部置 1，即"下一个块的起点减 1"。
4. **可用地址范围**：网络地址 $+1$ 到广播地址 $-1$，数量 $=2^{h}-2$（$h$ 为主机号位数）。

**【算例 1】** 主机 180.80.77.55，子网掩码 255.255.252.0，求所在子网的网络地址、广播地址与可用地址范围。

解：掩码 = **/22**。第三字节掩码 252，块大小 $=256-252=4$。第三字节 77 落在 $76\sim 79$ 块内（76 是 4 的整数倍）。

- 网络地址：**180.80.76.0**；广播地址：**180.80.79.255**；
- 可用范围：**180.80.76.1～180.80.79.254**，共 $2^{10}-2=1022$ 个。

（2012 年第 39 题考此型，目的地址可以是 180.80.79.255，选 D。）

**【算例 2】** 主机 168.16.84.24/20 所在子网的最小、最大可分配地址。解：/20 表示第三字节高 4 位属网络前缀，块大小 $=2^{4}=16$。84 落在 $80\sim 95$，故网络地址 **168.16.80.0**，广播地址 **168.16.95.255**，最小可分配 **168.16.80.1**，最大可分配 **168.16.95.254**。（2023 年第 39 题，选 B。）

**【算例 3】** 主机 183.80.72.48，掩码 255.255.192.0，求网络地址。解：掩码 = **/18**，第三字节块大小 $=256-192=64$。72 位于 $64\sim 127$ 块，网络地址 = **183.80.64.0**。（2022 年第 35 题，选 B。）

:::warn 最容易错的三处
1. **把掩码的"非 255 字节"换算错**：255.255.252.0 是 /22。用 $256-252=4$ 反推块大小最稳。
2. **误以为必须在 /24 边界**：块大小可落在任意字节。若掩码 255.255.255.128（/25），块大小为 128，块起点是 0 和 128。
3. **可用地址数忘记减 2**。
:::

#### 子网划分的完整步骤与综合大题

**定长划分的标准步骤**（已知网络地址与所需子网数或每子网主机数）：

1. **确定借位数 $s$**：若给定**子网个数 $k$**，取 $2^{s}\ge k$；若给定**每子网至少容纳 $x$ 台主机**，则主机位数 $h$ 满足 $2^{h}-2\ge x$，再据此反推 $s=n-h$（$n$ 为原主机位数）。
2. **写出新掩码**：前缀长度 $=32-h$，写成点分十进制。
3. **可用子网数** $=2^{s}$（定长划分下各子网掩码相同，子网数只能是 2 的整数次幂）。
4. **每子网地址数** $=2^{h}$，其中**可分配给主机的数量是 $2^{h}-2$**。
5. **列出各子网的网络地址与广播地址**：块大小 $=2^{h}$，第 $i$ 个子网的网络地址 = 原网络地址 $+i\times$ 块大小。
6. **写出可用地址范围**：网络地址 $+1$ 到广播地址 $-1$。

:::key 综合大题标准答题模板
以 2009 年第 47 题第 (1) 问为例：把 202.118.1.0/24 划分为 2 个子网，每个局域网需分配的 IP 地址数不少于 120 个。

**解**：每个局域网至少需 120 个可分配地址，$2^{h}-2\ge 120$ 即 $2^{h}\ge 122$，取 $h=7$（$2^{7}=128$，$2^{6}=64$ 不够）。前缀长度 $32-7=25$，子网掩码 **255.255.255.128**，块大小 128。

- 局域网 1：**202.118.1.0/25**，可分配 202.118.1.1～202.118.1.126，广播 202.118.1.127；
- 局域网 2：**202.118.1.128/25**，可分配 202.118.1.129～202.118.1.254，广播 202.118.1.255。

两子网各有 126 个可分配地址，满足要求（次序互换也正确）。
:::

**【算例：定长划分组合题】** 192.168.5.0/24 采用定长子网划分，掩码 255.255.255.248，求最大子网个数与每子网最大可分配地址个数。解：255.255.255.248 = **/29**，原网络 /24，借用 $29-24=5$ 位子网号，得 $2^{5}=32$ 个子网；每子网剩余 3 位主机号共 8 个地址，扣除网络地址和广播地址后最多分配 $2^{3}-2=6$ 个。（2010 年第 37 题，选 B：32，6。）

**【算例：反推最小子网】** 将 101.200.16.0/20 划分为 5 个子网，可能的最小子网的可分配 IP 地址数是多少？解：/20 含 $2^{12}=4096$ 个地址。完整划分为 5 个 CIDR 子网时各子网大小必须是 2 的幂且总和为 4096，可取 $2048+1024+512+256+256=4096$，故最小子网可有 256 个地址即 /24，可分配 $256-2=254$ 个。不能选 126：若最小子网只有 128 个地址，剩余 3968 个地址无法恰好由另外 4 个二进制地址块组成。（2019 年第 37 题，选 B。）

**【算例：判断不可能的子网】** 把一个 IP 网络划分为 3 个子网，其中一个子网是 192.168.9.128/26，下列不可能是另外两个子网之一的是？A. 192.168.9.0/25　B. 192.168.9.0/26　C. 192.168.9.192/26　D. 192.168.9.192/27

解：已知子网 `.128/26` 覆盖 `.128～.191`。选 A（`.0/25` 覆盖 `.0～.127`）时剩余 `.192～.255` 恰为 `.192/26`，三个子网完整划分，**A 可能**；选 C（`.192/26`）与 A 搭配同理，**C 可能**；选 D（`.192/27` 覆盖 `.192～.223`）时 `.128/26` 与 `.192/27` 同属父网络 `.128/25`，再取 `.0/25` 作第三个，**D 可能**；选 B（`.0/26` 覆盖 `.0～.63`）时尚未划分的地址为 `.64～.127` 与 `.192～.255` 两段**不连续**，无法用仅剩的**一个** CIDR 子网覆盖，**B 不可能**。答案 **B**。（2021 年第 35 题。）

:::warn 用"二叉树阀门"理解变长划分
把 CIDR 地址块看成二叉树，均分一次就是把节点一分为二。划分出 $k$ 个子网等价于在二叉树的 $k$ 个位置添加"阀门"，每个阀门对应的子树即为一个子网的地址范围。约束为**不重、不漏**：同一条根到叶子的路径上不能放多个阀门（防重叠），所有节点都必须被分配（防浪费）。阀门可放在**任意层级节点**（/25、/26、/27 均可）。
:::

#### 变长子网掩码与地址规划

| 定长子网掩码 FLSM | 变长子网掩码 VLSM |
| :--- | :--- |
| 每个子网**使用同一个子网掩码**，各子网网络前缀相同 | 每个子网**可使用不同子网掩码**，各子网网络前缀可不同 |
| 子网数量只能是 2 的整数次幂（2，4，8，……） | 子网数量**可以不是 2 的整数次幂**（3，5，6，7，9，11……） |
| 每子网地址数量相同，容易造成**地址资源浪费** | 每子网地址数量可不同，**尽可能减少浪费** |

**地址规划中必须考虑的三类地址消耗**：**终端主机**各分配 1 个可用主机 IP；**路由器接口**各分配 1 个独立 IP；**子网保留地址**（网络地址 1 个、广播地址 1 个）**不能分配给任何设备**。

**特殊情况**：连接两个路由器的点对点链路（无终端主机、只有 2 个路由器互连接口）仍需预留 1 个网络地址和 1 个广播地址，**合计需要 4 个 IP 地址**，因此通常分配一个 **/30** 地址块，恰好可分配 2 个地址给链路两端接口。

:::key 变长划分的核心原则
**每个子块的起点位置不能随便选取，只能选取主机号部分是块大小整数倍的地址作为起点。建议先为大的子块选取。**
:::

**【算例：变长划分综合应用题】** 地址块 218.75.230.0/24，需求为：网络 1 需 9 个地址，网络 2 需 28 个，网络 3 需 15 个，网络 4 需 13 个，网络 5（路由器间链路）需 4 个。用变长掩码分配。

解：按需求从大到小排序分配（"需 $x$ 个"指总共占用的地址数，含网络地址与广播地址）。

| 网络 | 需求总数 | 满足 $2^{h}\ge$ 需求的最小 $h$ | 块大小 | 前缀 | 分配的地址块 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| 网络 2 | 28 | $h=5$ | 32 | /27 | 218.75.230.0/27 |
| 网络 3 | 15 | $h=5$ | 32 | /27 | 218.75.230.32/27 |
| 网络 4 | 13 | $h=4$ | 16 | /28 | 218.75.230.64/28 |
| 网络 1 | 9 | $h=4$ | 16 | /28 | 218.75.230.80/28 |
| 网络 5 | 4 | $h=2$ | 4 | /30 | 218.75.230.96/30 |

| 子网 | 网络地址 | 可用地址范围 | 广播地址 |
| :--- | :--- | :--- | :--- |
| 218.75.230.0/27 | 218.75.230.0 | .1～.30 | 218.75.230.31 |
| 218.75.230.32/27 | 218.75.230.32 | .33～.62 | 218.75.230.63 |
| 218.75.230.64/28 | 218.75.230.64 | .65～.78 | 218.75.230.79 |
| 218.75.230.80/28 | 218.75.230.80 | .81～.94 | 218.75.230.95 |
| 218.75.230.96/30 | 218.75.230.96 | .97～.98 | 218.75.230.99 |

剩余 218.75.230.100～218.75.230.255 留作后用。注意每个子块**起点都是块大小的整数倍**：0、32 是 32 的倍数；64、80 是 16 的倍数；96 是 4 的倍数。若改用**定长掩码**，则必须满足最大需求 28，取 $h=5$、块大小 32、掩码 255.255.255.224（/27），划分出 $2^{3}=8$ 个等长子网、每网 30 个可用地址，总浪费远大于变长方案。

#### CIDR 无分类编址与路由聚合

**背景**：划分子网方法缓解了困难，但数量巨大的 C 类网（$2^{21}=2097152$ 个）每个网络只含 $2^{8}=256$ 个地址，并未得到充分使用，IPv4 地址仍在加速消耗。为此 IETF 提出**无分类编址**方法，即**无分类域间路由选择**（Classless Inter-Domain Routing，**CIDR**），它**消除了传统 A、B、C 类地址以及划分子网的概念**。

**CIDR 的地址结构**：**地址掩码**与子网掩码类似，由 32 比特构成，左起多个**连续的比特 1** 对应**网络前缀**，之后的连续 0 对应**主机号**：

$$\text{CIDR 地址}=\{\,<\text{网络前缀}>,<\text{主机号}>\,\}$$

**斜线记法**：在 IPv4 地址后面加斜线"/"，斜线后写上网络前缀所占的比特数量（即掩码中左起连续 1 的数量，位数不固定、可变长）。

**CIDR 地址块**：把网络前缀都相同的、连续的多个无分类 IPv4 地址组成一个 **CIDR 地址块**。只要知道块中任何一个地址，就可知道该块的全部细节：起始地址（主机号全 0 的网络地址）；最大地址（主机号全 1 的广播地址）；地址总数 $=2^{32-\text{前缀长度}}$；地址掩码；可分配给主机使用的地址数。

**【例】** 给定地址 128.14.35.7/20，求所在 CIDR 地址块的全部细节。解：/20 表示前 20 位是网络前缀、后 12 位是主机号。把后 12 位全部置 0 得网络地址 **128.14.32.0**；全部置 1 得最大地址 **128.14.47.255**（第三字节 $32+15=47$）；地址总数 $=2^{12}=4096$；最小可分配 128.14.32.1，最大可分配 128.14.47.254，可分配数 4094；地址掩码 **255.255.240.0**。

**CIDR 的优点**：可根据客户需要**分配适当大小的 CIDR 地址块**，从而更有效地分配地址空间。

**路由聚合**（又称**构造超网**）：一个 CIDR 地址块可以表示很多地址，因此路由表中可利用 CIDR 地址块来查找目的网络，这些地址的聚合称为路由聚合或超网。它使路由表中的一个项目可以表示多个原来传统分类地址的路由，有利于**减少路由器之间的信息交换**。关键规律：**网络前缀越长，地址块越小，路由越具体；前缀越短，地址块越大，可聚合的路由越多。** 若有多条路由条目匹配，则**选择网络前缀最长的那条**，称为**最长前缀匹配**。

:::key 路由聚合的标准解题步骤
1. 把待聚合的网络地址**写成二进制**（重点看"变化字节"那一段）。
2. 找出所有网络地址**从左起完全相同的连续比特位数**，即聚合后新前缀的长度。
3. **验证对齐**：聚合后的地址块必须是**严格的 2 的幂大小且起点对齐**。若各网络不能恰好拼成一个完整的 2 的幂地址块，则不能完全聚合（否则会引入不存在的网络）。
4. 写出聚合后的网络地址（共同前缀 + 全 0）与前缀长度。
:::

**【算例 1：真题型】** 某路由表中有转发接口相同的 4 条表项，目的网络为 35.230.32.0/21、35.230.40.0/21、35.230.48.0/21、35.230.56.0/21，求聚合后的目的网络地址。解：/21 表示第三字节高 5 位属于网络前缀，第三字节块大小 $=256-248=8$。四网依次覆盖第三字节 $32\sim 39$、$40\sim 47$、$48\sim 55$、$56\sim 63$。合并后正好覆盖 $32\sim 63$ 共 32 个连续值，$32=2^{5}$，对应第三字节高 3 位为前缀的一部分，故前缀长度 $16+3=19$。验证对齐：/19 的第三字节块大小 $=256-224=32$，起点须为 32 的整数倍，32 正好满足。**聚合结果：35.230.32.0/19**。（2018 年第 38 题，选 C。）

**【算例 2：两个 /25 聚合】** R2 到局域网 1（202.118.1.0/25）和局域网 2（202.118.1.128/25）的路由可聚合为一条。两块的块大小都是 128，起点为 0 和 128，恰好组成 $0\sim 255$ 的完整 /24 地址块，聚合为 **202.118.1.0/24**，掩码 **255.255.255.0**。（2009 年第 47 题第 (3) 问。）

**【算例 3：跨网段聚合】** R1 只有到 192.168.1.0/24 的路由。为把分组正确路由到 R2 后面的 192.168.2.0/25 与 192.168.2.128/25，需增加哪条路由？解：两块恰好组成 192.168.2.0/24，掩码 255.255.255.0，下一跳是同一链路上 R2 的接口地址（设为 192.168.1.2），而**不是 R1 自己的接口 .1**。（2011 年第 37 题，选 D。）

:::warn 路由聚合的两个陷阱
1. **下一跳写错**：聚合路由的下一跳是**邻居路由器的接口地址**，不是本路由器的接口地址。
2. **过度聚合**：聚合后的地址范围可能大于原有各子网范围的并集，从而"引入不存在的网络"。若题目允许引入无害的额外范围可以聚合；若明确要求不引入不存在的网络，则必须逐条列出或换用其他聚合方式。
:::

### ARP 协议、DHCP 协议与 ICMP 协议

#### 地址解析协议 ARP

**为什么需要两种地址**：在 IP 层抽象的互联网上只能看到 IP 数据报；虽然首部中有源 IP 地址，但**路由器只根据目的 IP 地址转发**；在局域网的链路层只能看见 MAC 帧。通过路由器转发时，IP 数据报在每个网络中都被路由器**解封装和重新封装**，MAC 帧首部的源、目的地址不断改变——硬件地址只具有**本地意义**，因此无法用 MAC 地址跨网络通信。

因此：数据报传送过程中，**源 IP 地址和目的 IP 地址保持不变**；**源 MAC 地址和目的 MAC 地址逐链路（逐网络）改变**。

**ARP 的作用**：无论网络层使用什么协议，在链路上传送数据帧时最终必须使用硬件地址，因此需要一种方法完成 IP 地址到 MAC 地址的映射，这就是**地址解析协议**（Address Resolution Protocol，**ARP**）。ARP 用于解决**同一局域网**上的主机或路由器的 IP 地址和硬件地址的映射问题。若目的主机与源主机不在同一局域网，则通过 ARP 找到本局域网上的某个路由器（默认网关）的硬件地址，把分组发给该路由器，剩下工作由下一个网络完成。

**ARP 高速缓存**：每台主机都设有一个 ARP 高速缓存（**ARP 表**），存放本局域网上各主机和路由器的 IP 地址到 MAC 地址的映射。

:::key ARP 请求广播、ARP 响应单播
**尽管 ARP 请求分组是广播发送的，但 ARP 响应分组是普通的单播。** ARP 广播只在子网中传播。ARP 高速缓存表项通过 ARP 自动获取，生命周期默认约两分钟，也可手工配置；ARP 表中 IP 与 MAC 的对应关系并非永久不变（例如主机更换了网卡）。
:::

**ARP 工作流程**：

1. 主机 A 要向**本局域网**上的主机 B 发送 IP 数据报时，先在**自己的 ARP 高速缓存中查看有无主机 B 的 IP 地址**。
2. 若有，查出对应硬件地址写入 MAC 帧，通过局域网把帧发往该硬件地址。
3. 若没有，用目的 MAC 地址为 **FF-FF-FF-FF-FF-FF**（48 比特全 1）的帧封装并**广播 ARP 请求分组**，使同一局域网里所有主机都收到。
4. 目标主机 B 收到后**先把请求中的源 IP 与源 MAC 映射存入自己的 ARP 表**，确认请求的目标 IP 是自己后，向 A 发出 ARP 响应分组（**单播**，只有 A 能收到），其中含 B 的 IP 与 MAC 映射。
5. A 收到响应后把该映射**写入 ARP 缓存**，然后按查到的硬件地址发送 MAC 帧。

:::key 跨网段的 ARP 过程（关键考点）
**ARP 不能跨网络使用**，但不同局域网可以多次 ARP。若源主机与目的主机**不在同一局域网**，则源主机通过 ARP 解析的是**本局域网内默认网关的硬件地址**，把分组发往默认网关，由网关转发至下一个网络。即**此时 ARP 请求的目标 IP 是网关的 IP，而不是最终目的主机的 IP。**

发送前的判定：主机用本机子网掩码与目的 IP 地址逐位按位与，对比结果与本机网络地址。一致则目的主机与本机在同一局域网（**直接交付**），ARP 查目的主机的 MAC；不一致属于**间接交付**，ARP 查默认网关的 MAC。
:::

**ARP 的四种典型情况**：

| 情况 | 发送方 | 目的 | ARP 解析的对象 |
| :--- | :--- | :--- | :--- |
| 1 | 主机 H1 | **本网络**上的主机 H2 | 目的主机 H2 的硬件地址 |
| 2 | 主机 H1 | **其他网络**上的主机 H3 | 与网 1 连接的路由器 R1 的硬件地址（默认网关） |
| 3 | 路由器 R1 | 与 R1 连接的**网 2** 上的主机 H3 | 目的主机 H3 的硬件地址 |
| 4 | 路由器 R1 | 网 3 上的主机 H4 | 与网 2 连接的路由器 R2 的硬件地址 |

**关于 ARP 属于哪一层**：由于 ARP 的主要用途是从网际层使用的 IP 地址解析出数据链路层使用的 MAC 地址，因此有的教材把 ARP 划归**网际层**，有的划归**数据链路层**，**这两种做法都是可以的**。

:::exam 真题考法
2012 年第 38 题直接考"ARP 协议的功能"（答案：根据 IP 地址查询 MAC 地址）。2015 年第 47 题第 (2) 问考"若主机 2 的 ARP 表为空，访问 Internet 时发出的第一个以太网帧的目的 MAC 地址是什么"——因为要先解析默认网关，所以**第一个帧是 ARP 请求帧，目的 MAC 是 FF-FF-FF-FF-FF-FF**。
:::

#### 动态主机配置协议 DHCP

**作用**：动态主机配置协议（Dynamic Host Configuration Protocol，**DHCP**）用于给主机**动态分配 IP 地址**及其他配置信息，基于 **UDP**（服务器端口 67、客户端端口 68）。

| 报文 | 发送方 | 含义 | 源 IP | 目的 IP | 目的 MAC |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **DISCOVER 发现** | 客户端 | "谁是 DHCP 服务器？" | 0.0.0.0 | 255.255.255.255 | 广播 MAC（全 F） |
| **OFFER 提供** | 服务器 | "我这有可用地址" | 服务器 IP | 255.255.255.255 | **客户端 MAC（二层单播）** |
| **REQUEST 请求** | 客户端 | "我就要这个地址" | 0.0.0.0 | 255.255.255.255 | 广播 MAC（全 F） |
| **ACK 确认** | 服务器 | "地址正式生效" | 服务器 IP | 255.255.255.255 | **客户端 MAC（二层单播）** |

:::key DHCP 报文的 IP 层与 MAC 层差异（高频考点）
**四个报文的 IP 层目的地址全是受限广播 255.255.255.255**，因为此时客户端还没配置 IP 地址，其 IP 层只认广播地址。而**服务器发出的 OFFER 和 ACK 在链路层使用单播**（目的 MAC 是客户端 MAC），这样网卡一看目的 MAC 是自己的就收下帧。**OFFER 报文中会提供 IP 地址、默认网关 IP、子网掩码、DNS 服务器 IP**。客户端用 **0.0.0.0** 作源地址，含义是"我不知道我是谁，但我现在就在这个网络里"。
:::

**租期**：DHCP 分配的 IP 地址有租用期，客户端在租期过半时应请求续租；不再使用时可以主动释放，使地址能被回收重用。

**DHCP 中继代理**：DHCP 使用广播而路由器默认不转发广播，因此 DHCP 服务器与客户端不在同一网段时广播报文无法到达服务器。解决办法是在各网段设置 **DHCP 中继代理**（relay agent），把客户端广播的 DHCP 报文以**单播**方式转发给 DHCP 服务器，并把应答转回客户端。

:::exam 真题考法
2015 年第 47 题第 (1) 问：DHCP 服务器可为主机 2～主机 N 动态分配 IP 地址的最大范围是什么？做法是把 /24 子网的可用地址 .1～.254 中**已被静态占用的地址**（路由器 .1、DHCP 服务器 .2、WWW 服务器 .3、主机 1 .4）排除，答案为 **111.123.15.5～111.123.15.254**；DISCOVER 报文的源、目的 IP 是 **0.0.0.0 和 255.255.255.255**。
:::

#### 网际控制报文协议 ICMP

**作用**：为了更有效地转发 IP 数据报以及提高交付成功的机会，网际层使用了**网际控制报文协议**（Internet Control Message Protocol，**ICMP**）。**主机或路由器**用它发送**差错报告报文**和**询问报文**。**ICMP 报文被封装在 IP 数据报中发送**，IP 首部协议字段值为 **1**。因此直接为 ICMP 提供服务的是 **IP**，而不是 TCP 或 UDP。

| 差错报告类型 | 触发条件 |
| :--- | :--- |
| **终点不可达** | 路由器或主机不能交付 IP 数据报时向源点发送。可按代码字段细分为目的网络不可达、目的主机不可达、目的协议不可达、目的端口不可达等 13 种 |
| **源点抑制** | 路由器或主机**因拥塞而丢弃数据报**时向源点发送，使源点放慢发送速率 |
| **时间超过** | 两类：① 路由器把 TTL 减 1 后结果为 0，丢弃数据报并向源点发送时间超过报文；② 终点在规定时间内未收到一个数据报的全部分片时丢弃已收分片，也向源点发送时间超过报文 |
| **参数问题** | 路由器或目的主机发现数据报首部中有字段值不正确时，丢弃该数据报并向源点发送参数问题报文 |
| **改变路由（重定向）** | 路由器把改变路由报文发给主机，让主机知道下次应把数据报发给另外的（更好的）路由器 |

**ICMP 询问报文**常用两种：**回送请求和回答**——由主机或路由器向特定目的主机发出，收到该报文的主机必须回送 ICMP 回送回答报文，用来**测试目的站是否可达及了解其状态**；**时间戳请求和回答**——请某主机或路由器回答当前日期和时间，时间戳回答报文中有一个 32 位字段，写入的整数表示从 1900 年 1 月 1 日起到当前时刻的秒数，用来**进行时钟同步和测量时间**。

:::warn 不应发送 ICMP 差错报告报文的几种情况
以下情况**不发送**：对 ICMP 差错报告报文本身不再发送差错报告报文；对第一个分片的数据报片的所有后续数据报片都不发送；对具有多播地址的数据报都不发送；对具有特殊地址（如 127.0.0.0 或 0.0.0.0）的数据报不发送。
:::

**PING（分组网间探测）** 用来**测试主机或路由器之间的连通性**。它是**应用层直接使用网际层 ICMP** 的一个例子，**并不使用运输层的 TCP 或 UDP**；所使用的 ICMP 报文类型是**回送请求和回答**。

**traceroute（跟踪路由）** 用于**探测 IP 数据报从源主机到目的主机要经过哪些路由器**。原理是源主机依次发送一串 TTL 分别为 1、2、3……的 IP 数据报，第 $i$ 个数据报到达第 $i$ 跳路由器时 TTL 减为 0，该路由器丢弃它并回送 **ICMP 时间超过**报文，源主机由此得知第 $i$ 跳路由器的地址；最后一个数据报到达目的主机时返回回送回答（或端口不可达），探测结束。UNIX 版本命令为 **traceroute**，运输层使用 **UDP**，网络层使用的 ICMP 报文类型**只有差错报告报文**；Windows 版本命令为 **tracert**，应用层**直接使用网际层的 ICMP 协议**，使用的 ICMP 报文类型有**回送请求和回答报文以及差错报告报文**。

:::exam 为什么 ping 不通、traceroute 显示 *
**ping 不通的常见原因**（按排查顺序）：① 目标主机不存在或未开机，ARP 解析不到，本地即报"请求超时"；② 中间路由器没有到达目标的路由，回送 **ICMP 终点不可达（网络不可达）**；③ 防火墙或安全策略主动丢弃 ICMP 回送请求/回答，表现为"请求超时"而非"不可达"；④ **子网掩码或默认网关配置错误**——主机用错误的掩码判断"目的在同一子网"，于是不去找网关而直接在本网段发 ARP 请求，永远得不到响应（2016 年第 39 题正是此情况）。

**traceroute 显示 `*` 的原因**：某一跳路由器**不回复 ICMP 时间超过报文**（可能被防火墙过滤、被管理员禁用 ICMP、或 CPU 过载丢弃了 ICMP 报文）。此时该跳信息无法获得，但 traceroute 仍继续探测后面的跳数。因此 `*` 通常意味着"该跳不可探测"，**不等于**"该跳不存在"或"链路中断"。
:::

## IPv6

### IPv6 的主要特点

引入 IPv6 的目的是**从根本上解决 IP 地址耗尽问题**。解决地址耗尽有三条途径：采用 CIDR 使地址分配更合理；采用 NAT 节省全球 IP 地址；采用具有更大地址空间的新版本 IPv6。**前两种只是延长 IPv4 使用寿命，只有第三种能从根本上解决问题。**

**IPv6 引进的主要变化**：

- **更大的地址空间（最重要）**：由 IPv4 的 **32 比特**增大到 **128 比特**。
- **扩展的地址层次结构**：可划分更多层次，更好地反映拓扑结构，使寻址与路由层次设计更灵活。
- **灵活的首部格式**：与 IPv4 首部**并不兼容**。IPv6 定义了许多可选的**扩展首部**，既提供更多功能，又提高路由器处理效率，因为路由器对逐跳扩展首部外的其他扩展首部都不处理。
- **改进的选项**：允许分组包含选项控制信息，因而可以包含新选项；IPv4 的选项则固定不变。
- **允许协议继续扩充**：IPv6 允许不断扩充功能，而 IPv4 的功能固定不变。
- **支持即插即用（自动配置）**：支持主机或路由器自动配置 IPv6 地址及其他网络配置参数，因此 **IPv6 不需要使用 DHCP**。
- **支持资源的预分配**：能为实时音视频等要求保证带宽和时延的应用提供更好的服务质量保证。
- **只有源主机才能分片**：IPv6 的分片是**端到端**的，不允许 IPv4 那样的路由器分片，可大大提高路由器转发速度。
- **首部固定**：基本首部长度固定为 **40 B**，而 IPv4 首部长度可变（须为 4 B 整数倍）。
- **取消了首部检验和**：加快路由器处理 IPv6 数据报的速度。
- **增大了安全性**：如身份鉴别、保密功能；**支持 QoS 保障**。注意 **IPv6 路由器收到过大的数据报时直接丢弃**（并回送 ICMPv6 报文），不像 IPv4 那样分片。

| IPv6 | IPv4 |
| :--- | :--- |
| 地址长度 128 bit（16 B） | 地址长度 32 bit（4 B） |
| 只有在源结点才能分片，传输过程中不能分片 | 传输过程中可以分片 |
| 基本首部固定 40 B | 首部长度可变，是 4 B 的整数倍 |
| 首部更简单灵活，取消许多字段（放在扩展首部中） | 首部固定部分包含更多字段 |
| 无首部检验和 | 有首部检验和 |

**IPv6 数据报的组成**：由**基本首部**和**有效载荷**（净负荷）两部分组成。**基本首部的字段只有 8 个，但长度增大到 40 B**；有效载荷由**零个或多个扩展首部**及其后面的数据部分构成（**扩展首部不属于 IPv6 数据报的基本首部**）。

| 字段 | 位数 | 含义 |
| :--- | :--- | :--- |
| 版本 | 4 | 协议版本，IPv6 对应值是 6 |
| 通信量类 | 8 | 区分不同 IPv6 数据报的类别或优先级 |
| 流标号 | 20 | 属于同一个流的报文具有相同流标号，用于资源分配 |
| **有效载荷长度** | 16 | **除基本首部外的字节数**，最大 65535 B（所有扩展首部都算在有效载荷之内） |
| 下一个首部 | 8 | 相当于 IPv4 的协议字段。无扩展首部时指明数据是何种 PDU；有扩展首部时标识后面第一个扩展首部的类型 |
| **跳数限制** | 8 | 类似 IPv4 的 TTL，源点设定限制值（最大 255），路由器每次转发减 1，减为零就丢弃。用来**防止 IPv6 数据报在因特网中永久兜圈** |
| 源地址 | 128 | 数据报发送端地址 |
| 目的地址 | 128 | 数据报接收端地址 |

**IPv6 相对 IPv4 取消或改名的字段**：取消**首部长度**（因长度固定 40 B）；取消**区分服务**（由通信量类和流标号实现其功能）；取消**总长度**（改用有效载荷长度）；取消**标识、标志和片偏移**（这些功能已包含在分片扩展首部中）；把**生存时间 TTL** 改称**跳数限制**；取消**协议**（改用下一个首部）；取消**首部检验和**；取消**选项**（改用扩展首部）。

:::key IPv6 扩展首部的设计意图
IPv4 数据报若在首部使用了选项字段，则整个传送路径中的**全部路由器**都要检查选项，降低了处理速度，而实际上很多选项路由器并不需要检查。因此 IPv6 把 IPv4 首部中的选项字段都放到扩展首部中，**由路径两端的源点和终点主机处理**，而路径中的所有路由器都不处理这些扩展首部（**除逐跳选项扩展首部外**）。
:::

### IPv6 地址

**三种基本地址类型**：**单播**——传统的点对点通信，一对一，**可作源地址或目的地址**；**多播**——一点对多点，数据报发送到一组计算机中的每一台，**只能作目的地址**（IPv6 没有采用广播的术语，而把广播看作多播的一个特例）；**任播**——终点是一组计算机，但**只交付其中的一台**（通常是最近的一台），**只能作目的地址**。

**IPv6 地址的表示形式**：

- **冒号十六进制记法**：把地址中的每 4 位用一个十六进制数表示，用冒号分隔每 16 位，128 位地址写成 8 组每组 4 位十六进制数。
- **"左侧零"省略**：两个冒号之间的十六进制数中最前面的一串 0 可以省略。
- **"连续零"压缩**：一连串连续的 0 可用一对冒号（`::`）取代，例如 `2001:0DB8:0000:0000:0000:0000:0000:0001` 可写成 `2001:DB8::1`。
- **在一个 IPv6 地址中只能使用一次"连续零"压缩**，否则会导致歧义。
- **冒号十六进制记法还可结合点分十进制的后缀**，例如 `::FFFF:192.168.1.1`。
- **CIDR 的斜线表示法在 IPv6 中仍然可用**，例如 `2001:DB8::/32`。

:::key IPv6 地址类型与前缀
| 地址类型 | 二进制前缀 | 说明 |
| :--- | :--- | :--- |
| 未指明地址 | 128 位全 0，记为 `::/128` | **不能用作目的地址**，只能用于还未配置 IPv6 地址的主机作为源地址 |
| 环回地址 | 128 位中仅最低位为 1，记为 `::1/128` | **IPv6 的环回地址仅此一个**（IPv4 的环回是一整个 /8 网段） |
| 多播地址 | 最高 8 比特为全 1，记为 `FF00::/8` | 功能与 IPv4 多播地址相同，占 IPv6 地址空间的 1/256 |
| 本地链路单播地址 | 最高 10 比特为 1111111010，记为 `FE80::/10` | 作用类似 IPv4 私有地址。即使网络未连接因特网也可用 TCP/IP，但不能与因特网上的其他主机通信 |
| 全球单播地址 | 除上述四种外的其他所有 IPv6 地址 | 用得最多的地址 |
:::

**IPv6 全球单播地址的三级结构**（这样设计是为了让路由器更快查找路由）：**全球路由选择前缀**占 **48 位**，相当于 IPv4 分类地址中的网络号；**子网标识符**占 **16 位**，用于各机构构建自己的子网；**接口标识符**相当于 IPv4 的主机号，位数有 **64 位**之多，完全足够给接口的硬件地址编码，因此 **IPv6 不需要使用地址解析协议 ARP 进行地址解析**。

### IPv4 向 IPv6 的过渡

**背景**：因特网上使用 IPv4 的路由器数量太大，让所有路由器都改用 IPv6 无法一蹴而就，因此只能**逐步演进**；另外，新部署的 IPv6 系统必须能够**向后兼容**，即必须能够接收和转发 IPv4 数据报，并能为 IPv4 数据报选择路由。

**双协议栈（Dual Stack）**：在完全过渡到 IPv6 之前，使一部分主机或路由器**装有 IPv4 和 IPv6 两套协议栈**，既可和 IPv6 系统通信，又可和 IPv4 系统通信，记为 **IPv6/IPv4**，表明它具有一个 IPv6 地址和一个 IPv4 地址。与 IPv6 主机通信时采用 IPv6 地址，与 IPv4 主机通信时采用 IPv4 地址；通过域名系统 DNS 查询目的主机采用的 IP 地址：若 DNS 返回 IPv4 地址，则源主机使用 IPv4 地址；若返回 IPv6 地址，则使用 IPv6 地址。

**隧道技术（Tunneling）**：当 IPv6 数据报要进入 IPv4 网络时，**把 IPv6 数据报重新封装成 IPv4 数据报**，即整个 IPv6 数据报成为 IPv4 数据报的数据载荷；封装有 IPv6 数据报的 IPv4 数据报在 IPv4 网络中传输；当 IPv4 数据报要离开 IPv4 网络时，再把其数据载荷（原来的 IPv6 数据报）取出并转发到 IPv6 网络。

:::warn IPv6 易错点
1. **IPv6 地址空间不是 IPv4 的 96 倍**，而是 $2^{128}/2^{32}=2^{96}$ 倍（2023 年第 40 题）。
2. **IPv6 基本首部长度固定 40 B**，不是可变的。
3. IPv6 的 **Hop Limit（跳数限制）等价于 IPv4 的 TTL**，都会被每个路由器减 1。
4. IPv6 的**有效载荷长度字段不包含基本首部**，但**包含所有扩展首部**。
5. IPv6 缺少"协议"字段（改用"下一个首部"）**并不影响指明上层协议**。
:::

## 路由协议

### 自治系统与域内、域间路由

**自治系统**（Autonomous System，**AS**）指在**单一的技术管理**下的一组路由器。每个 AS 内可能包括多个网络，**AS 号（ASN）全球唯一**。AS 在**逻辑上互不相交**，但在地理位置上可以相互交错；AS 之间必须通过**边界路由器**相互连接。AS 内使用 RIP 还是 OSPF 由该 AS 自己决定。

- **内部网关协议**（Interior Gateway Protocol，**IGP**）：一个自治系统内部使用的协议，如 **RIP 和 OSPF**。
- **外部网关协议**（Exterior Gateway Protocol，**EGP**）：自治系统之间使用的协议，目前使用最多的是 **BGP**。

若源主机和目的主机处于不同 AS（两 AS 可能使用不同 IGP），则数据报传到 AS 边界时需要用一种协议把路由选择信息传递到另一个 AS。每个 AS 自己决定内部运行哪个 IGP，但都有一个或多个路由器除运行本 AS 的 IGP 外还要运行外部网关协议。

:::warn IGP 与 EGP 是分类名称，不是具体协议
**外部网关协议 EGP 和内部网关协议 IGP 只是路由选择协议的分类名称，而不是具体的路由选择协议。** 名称中使用"网关"是因为因特网早期 RFC 文档中没有使用"路由器"而使用"网关"。统考中容易把 EGP 与 BGP 混淆。
:::

路由选择协议的三大功能：获取网络拓扑信息；选择最优路径（用 Dijkstra 单源最短路径算法等）；维护路由表。

### RIP 路由协议

**路由信息协议**（Routing Information Protocol，**RIP**）是 IGP 中最先得到广泛使用的协议之一。RIP 要求 AS 内的每一个路由器都维护从它自己到 AS 内其他每一个网络的**距离向量**（Distance-Vector，D-V）。

**度量**：RIP 用**跳数**（Hop Count）作为**度量**（Metric）。路由器到**直连网络**的距离定义为 **1**；到**非直连网络**的距离为**所经过的路由器数加 1**。一条路径最多**只能包含 15 个路由器**，**距离等于 16 相当于不可达**，因此 RIP 只适用于**小型互联网**。RIP 认为"好的路由"就是所通过路由器数量最少的路由；到达同一目的网络有多条距离相等的路由时可进行**等价负载均衡**。（有些厂商不严格按标准实现，例如思科把直连网络距离定义为 0；统考按标准文档"直连距离为 1"作答。）

**RIP 的三个重要特点**：**和谁交换信息**——仅和**相邻路由器**交换；**交换什么信息**——路由器**自己的路由表**，即到所在 AS 中各网络的最短 RIP 距离以及应经过的下一跳路由器；**何时交换信息**——**周期性交换**（约每 30 秒一次），为加快收敛，网络拓扑变化时要及时向相邻路由器通告变化后的路由信息，这称为**触发更新**。

**基本工作过程**：① 路由器刚开始工作时**只知道自己到直连网络的 RIP 距离为 1**；② 每个路由器**仅和相邻路由器周期性地交换并更新路由信息**；③ 若干次交换和更新后，每个路由器都知道到达本 AS 内各网络的最短距离和下一跳路由器，称为**收敛**。收敛指路由环境变化后各路由器调整路由表以适应拓扑变化、最终达到稳定状态（路由表与网络拓扑保持一致）。

**时间参数**：每隔约 **30 秒**向所有相邻路由器发送路由更新报文；若 **180 秒**（默认）没收到某条路由条目的更新报文，则把该条目标记为无效（RIP 距离置为 16）；若再过一段时间（如 **120 秒**）仍未收到，则将该条目从路由表中**删除**。

**RIP 报文的封装**：RIP 报文用运输层的 **UDP** 封装，**UDP 端口号为 520**。从封装角度看 RIP 属于**应用层**；但 RIP 的核心功能是路由选择，属于**网际层**。

#### RIP 的距离向量更新规则与计算题

:::key RIP 路由更新的四条规则（必背）
路由器收到相邻路由器（设为 X）发来的路由更新报文后，对报文中每条表项：

**第一步（修改）**：把报文中所有表项的"下一跳"都改为 **X**，所有"距离"字段的值**都加 1**。

**第二步（比对）**：

1. 本地路由表中**没有**该目的网络 → **添加**。
2. 本地**已有**且**下一跳就是 X** → **替换**（无条件更新，因为信息来自同一邻居）。
3. 本地已有、**下一跳不是 X** 且新距离**更小** → **更新**。
4. 本地已有、**下一跳不是 X** 且新距离**相等** → **可添加**（实现等价负载均衡）。
5. 本地已有、**下一跳不是 X** 且新距离**更大** → **不更新**。

**所有距离都要按"最大 15、16 表示不可达"处理**：算出的距离若 $\ge 16$ 一律记作 16，**不会出现 17**。
:::

**【算例：RIP 路由表更新完整计算】** 路由器 B 的原路由表如下，现收到相邻路由器 C 发来的路由更新报文，求 B 更新后的路由表。

| B 的原路由表 | | | | C 发来的报文 | |
| :--- | :--- | :--- | :--- | :--- | :--- |
| 目的网络 | 距离 | 下一跳 | | 目的网络 | 距离 |
| Net1 | 3 | A | | Net1 | 4 |
| Net2 | 4 | C | | Net2 | 2 |
| Net3 | 1 | 直接交付 | | Net5 | 1 |
| Net4 | 5 | D | | | |

**解**：第一步，把 C 报文中所有表项的下一跳改为 C、距离全部加 1，得 Net1 距离 5（下一跳 C）、Net2 距离 3（下一跳 C）、Net5 距离 2（下一跳 C）。

第二步逐条比对：

- **Net1**：原表有，下一跳是 A（≠ C），新距离 5 > 原距离 3 → **不更新**；
- **Net2**：原表有，下一跳是 **C（= C）** → 无条件**替换**；
- **Net5**：原表**没有** → **添加**。

| 更新后的表项 | 距离 | 下一跳 | 变化说明 |
| :--- | :--- | :--- | :--- |
| Net1 | 3 | A | 新路由劣势，不更新 |
| Net2 | 3 | C | 相同下一跳，无条件替换 |
| Net3 | 1 | 直接交付 | 未在报文中出现，保持不变 |
| Net4 | 5 | D | 未在报文中出现，保持不变 |
| Net5 | 2 | C | 新网络，添加 |

**【算例：等价负载均衡】** R1 当前有一条到 N 的路由（下一跳 R3，距离 5），现收到 R2 的更新报文包含 `<N, 7>`，且该 RIP 实现支持等价路由负载均衡。解：先把报文修改为下一跳 R2、距离 $7+1=8$。原表有 N，下一跳 R3 ≠ R2，新距离 8 > 原距离 5 → **不更新**。（若报文是 `<N, 4>`，则新距离 5 与原距离相等且下一跳不同，此时**可以添加**形成等价路由。）

**【算例：RIP 的 16 上限】** 2010 年第 35 题：R1 收到邻居 R2 的距离向量，其中包含 `<net1, 16>`，能得出什么结论？解：RIP 把 16 定义为无穷大即目的网络不可达。R2 通告 `<net1, 16>` 表示 R2 自己无法到达 net1；R1 即使再加上到邻居的 1 跳，结果仍按上限记为 16，因此 **R1 不能经 R2 到达 net1**。

**2016 年第 37 题**：若 R3 检测到网络 201.1.2.0/25 不可达并向 R2 通告一次新的距离向量，则 R2 更新后到达该网络的距离是多少？解：R3 把距离通告为 **16**。R2 经 R3 的候选距离理论上为 $16+1=17$，但 RIP 最大有效距离是 15，大于等于 16 的值都记作 16（不可达），不会出现 17，因此更新后的距离为 **16**。

**RIP 的优缺点**：**优点**是实现**简单**、路由器开销小；若某个路由器发现了更短的路由，在较短时间内便可传至所有路由器，俗称**"好消息传播得快"**。**缺点**：① 限制**最大距离为 15**，限制了 AS 规模；② 相邻路由器之间交换的是**完整路由表**，规模扩大后开销随之增大；③ **"坏消息传播得慢"**，收敛时间过长。因此规模较大的 AS 应使用 OSPF。

:::exam 真题考法
2024 年第 47 题第 (3) 问用 RIP 的交换周期算收敛时间：路由器同一时刻启动并立即交换初始距离向量，之后每隔 30 s 交换一次，**一轮只能把新信息再传播一跳**。对 210.2.3.0/24：R14 直连，R11、R15 在 $t=0$ 获得，R12、R13、R16 最迟在 $t=30$ s 获得，故全部获得至少需 **30 s**。对 210.2.4.0/24：R16 直连，R15 在 $t=0$ 获得，R13、R14 在 $t=30$ s 获得，R11、R12 最迟在 $t=60$ s 获得，故至少需 **60 s**。第 (1) 问考"AS4 内部路径可能超过 20 台路由器，RIP 不适用，应选 OSPF"。
:::

### OSPF 路由协议

**开放最短路径优先**（Open Shortest Path First，**OSPF**）是为了克服 RIP 的缺点而开发的。"**开放**"表明它不是受某一厂商控制而是公开发表的；"**最短路径优先**"是因为使用了 **Dijkstra** 提出的最短路径算法（SPF）。OSPF 基于**链路状态**而不像 RIP 基于距离向量；由于采用最短路径算法计算路由，**从算法上保证了不会产生路由环路**；**不限制网络规模，更新效率高，收敛速度快**。

**链路状态**指本路由器都和哪些路由器相邻，以及相应链路的"**代价**（cost）"；代价用来表示费用、距离、时延和带宽等，由网络管理人员决定。例如思科路由器中 OSPF 的代价算法是：$100\text{ Mb/s}$ 除以链路带宽，结果小于 1 仍记为 1，大于 1 且带小数的舍去小数。

**邻居关系的建立和维护**：相邻路由器之间通过交互**问候（Hello）分组**建立和维护邻居关系。问候分组封装在 **IP 数据报**中、发往**组播地址 224.0.0.5**，IP 首部**协议号字段取值为 89**。问候分组的**发送周期为 10 秒**；若 **40 秒**未收到某邻居的问候分组则认为该邻居不可达。每个路由器都会建立一张**邻居表**。

**链路状态通告 LSA**：每个路由器都会产生**链路状态通告**（Link State Advertisement，**LSA**），其中包含**直连网络**和**邻居路由器**两类链路状态信息。LSA 被封装在**链路状态更新**（Link State Update，**LSU**）分组中，采用**可靠的洪泛法**（Flooding）发送。

- **洪泛法**的要点是路由器**向自己所有的邻居路由器发送 LSU**，收到该分组的各路由器又把它转发给自己所有的邻居路由器（**但其上游路由器除外**），以此类推。洪泛不回传、不重复。
- **"可靠"**指收到 LSU 后要发送确认；**收到重复的更新分组无需再次转发**，但要发送一次确认。

**链路状态数据库 LSDB**：每个路由器都有一个**链路状态数据库**（Link State Database，**LSDB**）用于存储 LSA。通过各路由器洪泛发送封装有各自 LSA 的 LSU，**各路由器的 LSDB 最终将达到一致**。

**最短路径优先计算**：各路由器基于 LSDB 进行计算，构建出各自到达其他各路由器的最短路径即路由表，并周期性（默认 30 分钟）刷新链路状态。注意**路由表中不会存储完整路径，而只存储"下一跳"**。

**OSPF 的详细工作过程**：① **邻居发现与链路参数初始化**——通过 **Hello 分组**发现直连邻居、建立邻居关系，然后为去往各邻居的链路配置对应的**开销度量 metric**；② **LSDB 同步**——路由器向邻居发送 **DD 数据库描述分组**传递本地 LSDB 中所有 LSA 的摘要信息供双方比对，邻居逐条比对摘要后针对缺失、过期或更新的条目主动发送 **LSR 链路状态请求分组**，对方回复 **LSU 链路状态更新分组**携带所需 LSA 详细信息，邻居更新本地数据库后返回 **LSAck 链路状态确认分组**；③ **动态更新与路由计算**——链路状态变化时变动路由器泛洪发送 **LSU** 在区域内扩散最新拓扑，其他路由器接收后回复 **LSAck**，全网依据最新 LSDB 用 **Dijkstra 算法**重新计算最短路径并更新路由表；④ **转发**。

**OSPF 的五种分组类型**：

| 分组类型 | 作用 |
| :--- | :--- |
| **问候（Hello）** | 发现和维护邻居路由器的可达性 |
| **数据库描述（DD）** | 向邻居给出自己 LSDB 中所有链路状态项目的摘要信息 |
| **链路状态请求（LSR）** | 向邻居请求某些链路状态项目的详细信息 |
| **链路状态更新（LSU）** | 把链路状态信息用洪泛法对整个系统更新 |
| **链路状态确认（LSAck）** | 对链路状态更新分组的确认 |

**多点接入网络中的 OSPF 路由器**：若每台路由器都向其他 $(n-1)$ 个路由器发送问候分组和 LSU，洪泛数量会急剧增加。为减少洪泛数量，OSPF 采用：选举**指定路由器**（Designated Router，**DR**）和**备用指定路由器**（Backup Designated Router，**BDR**）；**所有非 DR/BDR 只与 DR/BDR 建立邻居关系**；**非 DR/BDR 之间通过 DR/BDR 交换信息**。

**OSPF 划分区域**：为使 OSPF 能用于规模很大的网络，OSPF 把一个 AS 再划分为若干个更小的范围，称为**区域**（area）。划分区域的好处是把利用洪泛法交换链路状态信息的范围局限于每一个区域而不是整个 AS，从而减少整个网络上的通信量。**洪泛不跨区域。**

| 路由器类型 | 含义 |
| :--- | :--- |
| **区域内路由器**（IR） | 所有接口都在同一个区域内 |
| **主干路由器**（BBR） | **只要在主干区域中的路由器**都称为主干路由器，因此主干路由器可兼作区域边界路由器 |
| **区域边界路由器**（ABR） | 连接主干区域和其他下层区域的路由器，即至少一个接口在主干区域、另一个接口在其他区域 |
| **自治系统边界路由器**（ASBR） | 与 AS 外部的路由器交换路由信息的路由器 |

**OSPF 特点小结**（与 RIP 逐条对比）：**和谁交换信息**——用**洪泛法**向本 AS 中**所有路由器**发送信息（RIP 仅向相邻的几个路由器发送）；**交换什么信息**——与本路由器相邻的所有路由器的**链路状态**，只是路由器知道的部分信息（RIP 发送的是本路由器所知道的全部信息即整个路由表）；**何时交换信息**——**只有当链路状态发生变化时**才用洪泛法发送（RIP 不管拓扑是否变化都定期交换）；**用什么传送信息**——OSPF 是**网络层协议**，不用 UDP 或 TCP 而**直接用 IP 数据报传送**（协议字段 **89**），而 RIP 是应用层协议、在运输层使用 UDP。

**OSPF 的其他补充特性**：允许对每条路由设置不同代价，对不同类型的业务可计算出不同路由；若到同一目的网络有多条相同代价的路径，可把通信量分配给这几条路径；支持可变长度子网划分和 CIDR；每个链路状态都带一个 32 位序号，序号越大状态越新；互联网规模很大时使用 OSPF 比 RIP 好得多，收敛很快且不存在坏消息传得慢的问题。

### BGP 路由协议

**协议定位**：边界网关协议（Border Gateway Protocol，**BGP**）属于**外部网关协议 EGP**，专门用于**自治系统之间的路由选择**，是因特网跨域路由的核心协议。

**为什么 AS 间不用 IGP**：① **无统一度量标准**——不同 AS 内部的度量维度不同（有的按时延、有的按带宽、有的按距离），无法用统一的"代价"计算全局最优路径；② **需支持策略选路**——AS 之间的路由选择必须考虑政治、经济、安全等策略（如过境收费、规避不可信 AS），这些由网络管理人员设置，但策略并不是 AS 之间的路由选择协议本身。

:::key BGP 的设计目标
**BGP 只能是力求寻找一条能够到达目的网络且比较好的路由（即不能兜圈子），而并非要寻找一条最佳路由。** BGP 交换的路由信息是**到达某个目的网络所要经过的各个自治系统序列**而不仅仅是下一跳。
:::

**路由机制：路径向量算法**。BGP 传递的路由信息 = **目的网络 + AS 路径序列（路径向量）**，并非距离或链路状态。通过携带完整经过的 AS 编号天然防环：**若收到的路由路径包含自身 AS 号，直接丢弃**。

**通信主体：BGP 发言人**——运行 BGP 协议、参与 BGP 会话的路由器。**eBGP 发言人**通常部署在 AS 边界，与其他 AS 的 BGP 发言人建立会话，交换跨 AS 的路由可达信息；**iBGP 发言人**位于同一 AS 内部，负责把外部学到的 BGP 路由在本 AS 内传播，**不一定在 AS 边界**。

**核心辨析**：**BGP 发言人不等同于边界路由器**，判定标准是**路由器是否运行 BGP 并参与 BGP 会话，与所处物理位置无关**。互相建立 BGP 会话的两台发言人互称**邻站（对等站）**。BGP 发言人一般同时运行本 AS 的 IGP，保障 AS 内部网络可达。

**传输方式**：BGP 属于**应用层协议**，基于 **TCP 179 端口**建立持久会话，依靠 TCP 保证可靠传输，无需协议自身维护确认与重传。

:::key 三个路由协议的封装方式（必背对比）
**RIP 用 UDP（端口 520）；OSPF 直接封装在 IP 数据报中（协议号 89）；BGP 用 TCP（端口 179）。** 2017 年第 37 题直接考这一点。
:::

**会话类型**：BGP 会话建立的前提是 BGP 邻居之间**先建立 TCP 连接**，再在该连接上交换 BGP 报文。

| 会话类型 | 建立对象 | 是否要求直连 | 核心作用 |
| :--- | :--- | :--- | :--- |
| **eBGP（外部 BGP）** | **两个 AS 的直连边界路由器**之间 | **要求物理直连** | 在自治系统之间交换跨域路由信息 |
| **iBGP（内部 BGP）** | **同一 AS 内部的 BGP 路由器**之间 | **不要求物理直连** | 在本 AS 内部同步从外部学到的 BGP 路由信息 |

:::warn iBGP ≠ IGP
**IGP** 解决"AS 内部数据包具体怎么走"的问题，计算内部最优路径；**iBGP** 解决"AS 内部同步外部路由信息"的问题，传递跨域可达性。两者功能不同，不能互相替代。
:::

传统 iBGP 要求同一 AS 内的路由器实现**全连接（Full Mesh）**：N 台 iBGP 路由器需要建立 $\dfrac{N(N-1)}{2}$ 条会话。**该全连接仅指 BGP 层面的逻辑会话连通，并不要求路由器之间物理直连。**

**BGP 路由的格式**：`目的网络 + BGP 属性`，核心两个属性：**AS-PATH** 记录该路由途经的自治系统序列，用于选路，同时**防止 AS 间路由环路**（若路径序列中出现重复 AS 则存在环路）；**NEXT-HOP** 表示通告该 BGP 路由的路由器对应的 IP 地址。

**BGP 路由传播的核心规则**：① **eBGP 跨 AS 传播**——向外部 AS 通告时在 AS-PATH 中**追加本 AS 编号**，同时把 NEXT-HOP 更新为**发送方边界路由器自身 IP**（例：AS2 的 R4 向 AS3 的 R6 通告 N1 的路由，AS-PATH 追加 AS2，路由变为 `(N1, [AS2 AS1], R4)`）；② **iBGP AS 内传播**——从 eBGP 获得外部路由后通过 iBGP 在 AS 内同步，**默认保持 AS-PATH、NEXT-HOP 不变**（例：R2 收到 R1 的 eBGP 路由后把 `(N1, AS1, R1)` 原样同步给 R3、R4、R5，三者的 BGP 下一跳均为 R1）；③ **iBGP 水平分割**——**从 iBGP 邻居学到的路由不得再转发给其他 iBGP 邻居**，因此传统 iBGP 要求全连接；④ **BGP 依赖 IGP 实现内部可达**——路由器通过 iBGP 知道"访问外网要交给对应的边界路由器转发"，但不负责内网路径计算，需要依靠 IGP 算出自己到该边界路由器的实际转发下一跳。

**BGP 的天然防环规则**：AS-PATH 记录该路由途经的所有 AS 编号。当一个 AS 收到 BGP 路由更新时，若发现**自身 AS 编号已存在于 AS-PATH 中**，说明接收会形成环路，因此**直接丢弃该路由**。

**BGP 工作流程精髓**：**交换对象**是与互为邻站的 BGP 发言人交换路由信息，跨 AS 通过 eBGP 邻站交互、同一 AS 内通过 iBGP 邻站同步；**交换内容**是网络可达性信息，即到达目的网络所需途经的 AS 路径序列；**更新机制**采用**增量更新**，仅在路由发生变化时通告有变动的部分，不做周期性全量刷新。

| BGP-4 的报文 | 作用 |
| :--- | :--- |
| **打开 OPEN** | 与相邻的另一个 BGP 发言人建立关系，使通信初始化 |
| **保活 KEEPALIVE** | 周期性地证实邻站的连通性 |
| **更新 UPDATE** | 通告某一条路由的信息，以及列出要撤销的多条路由 |
| **通知 NOTIFICATION** | 发送检测到的差错 |

想与另一个 AS 的 BGP 发言人**建立对等关系**时，向对方发送 **OPEN 报文**；若对方接受，就用 **KEEPALIVE 报文响应**。此后双方**周期性交换 KEEPALIVE 报文**（一般每隔 30 秒）。KEEPALIVE 报文只有 19 字节长（只用通用首部），不会造成太大开销。**UPDATE 报文是 BGP 的核心内容**：可以用它**撤销**曾经通知过的路由，也可以**宣布**增加新的路由；**撤销路由可以一次撤销多条，但增加新路由时每个 UPDATE 报文只能增加一条。**

**BGP 的路由选择顺序**（无策略约束时的常见比较顺序）：偏好值（自定义优先级）→ **AS-PATH 跳数最少** → **热土豆路由** → BGP 序号。**热土豆路由选择算法**：让分组通过最少的"代价"尽快离开本 AS（仅用于 AS 内部，此时分组还没到达 AS 边界）。

:::exam 真题考法
2024 年第 47 题第 (4)(5) 问是 BGP 的典型综合考法。第 (4) 问：R44 属 AS4、R13 属 AS1，二者之间通过 **eBGP（外部 BGP）会话**通告路由，使用 **UPDATE 报文**；R13 再通过 **iBGP（内部 BGP）会话**把该网络的可达性信息通告给同属 AS1 的 R14、R15。第 (5) 问给三条候选：经 R11 的 AS_PATH `AS2 AS8 AS19`（长度 3）、经 R12 的 `AS3 AS7 AS11 AS19`（长度 4）、经 R13 的 `AS4 AS10 AS19`（长度 3）。先比 AS_PATH 长度，R12 路径更长被排除；R11、R13 等长，无策略约束时再比较到 BGP 下一跳的内部代价（热土豆路由）：R14 到 R11 最近、R15 到 R13 最近，因此 **R14 的下一跳是 R11，R15 的下一跳是 R13**。
:::

### 三种路由协议对比

| 对比项 | RIP | OSPF | BGP |
| :--- | :--- | :--- | :--- |
| 类型 | 内部网关协议 IGP | 内部网关协议 IGP | 外部网关协议 EGP |
| 路由算法 | **距离-向量** | **链路状态** | **路径-向量** |
| 传递协议 | **UDP**（端口 520），应用层协议 | **IP**（协议号 89），网络层协议 | **TCP**（端口 179），应用层协议 |
| 路径选择 | 跳数最少 | 代价最低 | 较好，非最佳 |
| 交换结点 | 和本结点**相邻**的路由器 | 本自治系统**所有**路由器（洪泛） | 和本结点**相邻**的路由器（邻站） |
| 交换内容 | 自己知道的**全部信息**即整个路由表；不知道全网拓扑 | 相邻所有路由器的**链路状态**；只发送路由表的一部分 | 首次整个路由表；非首次只发变化部分 |
| 交换时机 | 周期性（约 30 s）+ 触发更新 | 链路状态变化时 | 路由变化时（增量更新） |
| 收敛速度 | 慢（坏消息传得慢） | 快 | — |
| 规模限制 | 最大 15 跳（16 为不可达） | 无限制 | 面向跨域 |
| 防环机制 | 最大距离 + 水平分割 + 毒性逆转（不能彻底解决） | 基于链路状态算法，天然无环 | AS-PATH 中出现自身 AS 号即丢弃 |

**为什么采用不同的传递协议**（常考简答）：RIP 是分布式的基于距离向量的路由选择协议，通过广播 UDP 报文交换路由信息；OSPF 是内部网关协议，要交换的信息量较大、应使报文长度尽量短，所以**不使用运输层协议**而直接采用 IP；BGP 是外部网关协议，在不同 AS 之间交换路由信息，网络环境复杂需要保证可靠传输，所以采用 TCP。

## IP 组播

### 组播的概念

**组播（多播）** 让源主机一次发送的单个分组抵达用一个**组地址**标识的若干目的主机，即**一对多的通信**。组播需要路由器支持，能运行组播协议的路由器称**多播路由器**。组播时仅需发送一份数据，**只在传送路径出现分岔时才将分组复制后继续转发**，可大大减轻发送者负担和网络负载。

| 方式 | 目标 | 地址 | 特点 |
| :--- | :--- | :--- | :--- |
| 单播 | 一个接收者 | 单播地址 | 源需为每个接收者各发一份，N 个接收者消耗 N 份带宽 |
| 广播 | 本网段所有主机 | 广播地址 | 不区分是否需要；路由器默认不转发受限广播 |
| 组播 | 一组加入该组的主机 | **组播地址（D 类）** | **源只发一份**，分岔处才复制，节省源端与主干链路带宽 |

多个单播可以仿真组播，但**一个组播所需的带宽小于多个单播带宽之和**；用多个单播仿真组播时路由器时延将很大，而处理一个组播分组的时延很小。

**组播数据报**：源地址是源主机的 IP 地址（大多为单播地址），目的地址是 IP 多播地址。注意事项：使用 **IGMP 协议**（IP 首部协议字段值是 **2**）；提供**"尽最大努力交付"**，不保证交付给组内所有成员；**对多播数据报不产生 ICMP 差错报文**；**多播机制仅应用于 UDP**（TCP 面向连接，会一对一地发送）。

### IP 组播地址

IP 组播地址就是 IPv4 中的 **D 类地址**：**前四位是 1110**，范围 **224.0.0.0～239.255.255.255**，即 **224.0.0.0/4**。**每个 D 类 IP 地址标志一个多播组**，主机可随时加入或离开；**多播地址只能用于目的地址，不能用于源地址**；**多播组成员的数量和所在的地理位置不受限制，一台主机可以属于几个多播组**；**非多播组成员也可以向多播组发送 IP 多播数据报**。

**D 类 IP 地址与以太网多播 MAC 地址的映射**：以太网多播 MAC 地址范围是 **01-00-5E-00-00-00 到 01-00-5E-7F-FF-FF**（以 `01-00-5E` 打头）；48 位 MAC 中可用的**低位 23 位与 D 类 IP 地址的低 23 位有一一对应关系**，D 类地址除 1110 前缀外可供分配 28 位，但其中**高 5 位无法映射**，因此共有 $2^{23}$ 个多播 MAC 地址；**多播 IP 地址与以太网 MAC 地址的映射关系不是唯一的**（32 个不同的 IP 多播地址可能映射到同一个 MAC 多播地址），因此主机收到多播数据报时要在 **IP 层用软件过滤**。

### IGMP 与组播路由

**网际组管理协议**（Internet Group Management Protocol，**IGMP**）是 TCP/IP 体系结构**网际层**中的协议，作用是让**连接在本地局域网上**的多播路由器知道本局域网上是否有主机（实际是主机中的某个进程）**加入或退出了某个多播组**。IGMP 报文被封装在 IP 数据报中传送，但它也**向 IP 提供服务**，因此不把它视为单独协议，而视为整个网际协议 IP 的一个组成部分。**IGMP 仅在本网络有效**：用它**并不能知道多播组包含的成员数量**，也**不能知道成员分布在哪些网络中**。三种报文类型：**成员报告报文**、**成员查询报文**、**离开组报文**。

**工作阶段**：① **加入阶段**——某主机加入新的多播组时，向该多播组的多播地址发送一个 IGMP 报文声明自己是成员；本地多播路由器收到后还要利用**多播路由选择协议**把这种组成员关系转发给其他多播路由器。② **维持阶段**——组成员关系是**动态的**，本地多播路由器**周期性地探询**局域网上的主机，只要对某个组有一台主机响应就认为该组活跃；经过几次探询后仍无任何主机响应，就认为本网络主机都已离开该组，不再把成员关系转发给其他多播路由器。

**查询路由器的选举**：同一网络中可能不止一个多播路由器，但没必要每个都周期性发送 IGMP 成员查询报文，只需选**一个查询路由器**发送，其他多播路由器被动接收响应并更新自己的多播组列表。选举方法：每个多播路由器若监听到源 IP 地址比自己的 IP 地址小的 IGMP 成员查询报文则退出选举，最后网络中 **IP 地址最小**的多播路由器成为查询路由器。

:::key 仅用 IGMP 不能在因特网上进行 IP 多播
连接在局域网上的多播路由器还必须和因特网上的其他多播路由器协同工作，以便用**最小的代价**把 IP 多播数据报传送给所有多播组成员，这就需要**多播路由选择协议**。
:::

**多播路由选择协议的主要任务**是在多播路由器之间为每个多播组建立一个**多播转发树**：该树**连接多播源和所有拥有该多播组成员的路由器**；IP 多播数据报只要沿着多播转发树洪泛就能被传送到所有拥有该组播组成员的多播路由器；之后在多播路由器直连的局域网内，通过**硬件多播**把数据报发送给该组所有成员。

| 类型 | 构造方式 | 特点 |
| :--- | :--- | :--- |
| **源基树**（源分布树、最短路径树） | **为每一个（源，组）对**分别构造以该源为根、覆盖所有组成员的最短路径树 | 路径最短、时延最小；但每个源都要维护一棵树，状态量为 $O(\text{源数}\times\text{组数})$，**可扩展性差**。代表：DVMRP、PIM-DM（密集模式） |
| **共享树**（核心树、汇聚点树） | 整个组只构造**一棵树**，以选定的**汇聚点（RP）**为根，源先把数据发给 RP，再由 RP 沿共享树分发 | 状态量只需 $O(\text{组数})$，**可扩展性好**；但路径未必最短，存在次优路径与 RP 单点瓶颈。代表：PIM-SM（稀疏模式）、CBT |

组播路由的核心难点在于：组播地址只标识"组"而不标识位置，路由器无法像单播那样仅凭目的地址查表确定唯一出口；同时组成员可随时加入/离开，路由器必须动态维护转发树，并在有多个入接口时正确判断该从哪个接口转发（依赖**反向路径转发 RPF** 检查）。

## 移动 IP

### 移动 IP 的概念

**移动 IP** 指移动站**以固定的 IP 地址实现跨越不同网络**的漫游功能，并保证基于 IP 的网络权限在漫游过程中不发生任何改变。其目标是把分组自动投递给**移动站**——把连接点从一个网络或子网改变到另一个网络或子网的主机。若需要在移动中进行 TCP 传输，则应一直保持这个 TCP 连接，可见**若要使移动站在移动中的 TCP 连接不中断，就必须使主机的 IP 地址在移动中保持不变**。

| 功能实体 | 含义 |
| :--- | :--- |
| **移动结点（移动站）** | 具有永久 IP 地址的移动主机 |
| **归属代理（本地代理）** | 在**归属网络**中代表移动节点执行移动管理功能的实体，通常就是连接在归属网络上的路由器 |
| **外地代理（外部代理）** | 在**被访网络**中帮助移动节点完成移动管理功能的实体，通常就是连接在被访网络上的路由器 |
| **归属地址（永久地址/主地址）** | 移动站在归属网络中的原始地址，**与归属网络的关联不变** |
| **转交地址（辅地址）** | 移动到被访网络后获得的临时地址，可以是外地代理的地址或动态配置的地址；**供移动站、归属代理及外地代理使用，各种应用程序都不会使用** |

### 移动 IP 通信过程

基本工作过程分为**代理发现、注册、分组路由与注销**四个阶段：

1. **归属网络内正常通信**：移动站 A 在归属网络时按传统 TCP/IP 方式通信。
2. **代理发现与注册**：A 漫游到被访网络时先通过代理发现找到外地代理，向外地代理登记并获得一个临时的**转交地址**；外地代理再向 A 的**归属代理**登记该转交地址。
3. **隧道转发**：归属代理知道 A 的转交地址后，构建一条通向转交地址的**隧道**，把截获的发给 A 的 IP 分组**再封装**（原始 IP 分组作为新 IP 分组的载荷），通过隧道发送给被访网络的外地代理。
4. **拆封与交付**：外地代理把封装的 IP 分组**拆封**，恢复成原始 IP 分组后发给移动站 A（外地代理向移动站发送分组时**直接使用移动站的 MAC 地址**）。
5. **移动站的发送**：A 在被访网络对外发送 IP 分组时**仍然使用自己的永久地址作为源地址**，此时无须通过归属代理转发，而是**直接通过被访网络的外地代理**发出。
6. **移动到另一被访网络**：在新外地代理登记后，新外地代理把 A 的新转交地址告诉其归属代理（覆盖旧的）。**无论如何移动，A 收到的 IP 分组都由归属代理转发。**
7. **注销**：A 回到归属网络时向归属代理注销转交地址，之后按原始方式通信。

:::key 移动 IP 中网络层的四个功能协议
支持移动性需要：① **移动站到外地代理的登记协议**；② **外地代理到归属代理的登记协议**；③ **归属代理数据报封装协议**；④ **外地代理拆封协议**。外地代理有两项功能：为移动站创建临时地址（转交地址）；及时把转交地址告诉其归属代理。
:::

:::warn 三角路由问题
移动 IP 的默认路由方式是**非对称**的：**去程**分组必须经归属代理隧道转发（因为通信对端只知道移动站的归属地址），而**回程**分组由移动站直接发出、不经归属代理。这样去程路径"对端 → 归属代理 → 外地代理 → 移动站"与回程路径"移动站 → 对端"在拓扑上构成一个**三角形**，称为**三角路由（triangle routing）问题**。后果是**去程路径被拉长**（即使对端与移动站当前在同一地区也要绕回归属网络），增加时延并浪费带宽；同时**归属代理成为单点瓶颈**。解决思路是**路由优化**：归属代理把移动站的当前转交地址通知通信对端，对端此后直接把分组发给转交地址，从而绕过归属代理形成直连路径；但这会引入对端需要缓存绑定信息、安全认证等新问题。
:::

:::exam 真题考法
移动 IP 属低频考点，考法一般是**概念辨析**：判断"归属地址/转交地址""归属代理/外地代理"的作用，或判断"移动站发送分组时源地址使用哪个地址"（答案：**仍使用归属地址**）、"移动站接收的分组由谁转发"（答案：**归属代理**）。注意移动 IP 的数据报是**间接**接收和发送；移动 IP 的分组路由可分为单播、广播与组播。
:::

## 网络层设备

### 冲突域和广播域

**冲突域**：连接到同一物理介质上的所有节点的集合，这些节点之间存在介质争用（OSI 第一层概念）。第一层设备（集线器、中继器）所连结点属同一个冲突域，**不能划分冲突域**；第二层（网桥、交换机）、第三层（路由器）设备都**可以划分冲突域**。

**广播域**：接受同样广播消息的节点集合（OSI 第二层概念）。第一、二层设备所连结点属同一个广播域；**路由器（第三层）可以划分广播域**；局域网（LAN）特指使用路由器分割的网络，也就是广播域。

设备互连能力：**路由器**可互联两个**不同网络层协议**的网段；**网桥**可互联两个**物理层和链路层不同**的网段；**集线器不能**互联两个物理层不同的网段。

:::key 一句判断法
**设备所在层次越高，能屏蔽的下层差异越多，但转发速度越慢。** 路由器是第三层设备，处理内容比第二层交换机更多，因而转发速度更慢、延迟更大。要抑制广播风暴只有**路由器**能做到：中继器、集线器工作在物理层不能隔离广播；网桥/二层交换机分隔冲突域但默认仍转发广播帧。
:::

### 路由器的组成和功能

**定义**：路由器是一种具有多个输入/输出端口的专用计算机，任务是**连接不同的网络（异构网络）并完成分组转发**。同一网络中传递数据无须路由器参与，而**跨网络通信必须通过路由器转发**；多个逻辑网络（多个广播域）互连时必须使用路由器；路由器可连接不同 LAN、不同 VLAN、不同 WAN，或把 LAN 和 WAN 互连，并可隔离广播域。

**交付的两种类型**：**直接交付**——源主机与目的主机连接在同一个网络上，无须通过路由器；**间接交付**——二者不在同一个网络上，路由器按转发表（由路由表得出）指出的路由把分组转发给下一个路由器。**判断方法**是路由器根据分组的**目的 IP 地址**与**接收端口的 IP 地址**是否属于同一子网来判断；**间接交付的最后一个路由器肯定是直接交付**。

**路由器体系结构的两个部分**：

**（1）路由选择部分（控制部分）**：**路由选择处理机**——根据所选定的路由选择协议构造路由表，同时经常或定期地与相邻路由器交换路由信息以不断更新和维护路由表；**路由选择协议**——用来更新路由表的算法；**路由表**——根据路由算法得出，一般包括从目的网络到下一跳的映射。

**（2）分组转发部分**：

| 组成部分 | 作用 |
| :--- | :--- |
| **交换结构** | 根据转发表对分组处理，把某个输入端口进入的分组从合适的输出端口转发出去。三种交换方式：通过**存储器**交换、通过**总线**交换、通过**互联网络**交换 |
| **输入端口** | 包括物理层、数据链路层和网络层的处理模块 |
| **输出端口** | 从交换结构接收分组，再发送到路由器外面的线路上 |

**缓冲队列与丢包**：端口在网络层的处理模块中设有**缓冲队列**，暂存等待处理或已处理完毕待发送的分组，还可进行必要的差错检测。**若分组处理的速率赶不上分组进入队列的速率，后面进入队列的分组就会因缓冲区满而被丢弃。**

**输入排队与输出排队都会导致丢包**：**输入排队**——当交换结构的处理速度低于所有输入端口到达速率之和时输入队列不断积累，此外**队头阻塞（HOL blocking）**（输入队列最前面的分组因其目的输出端口忙而被阻塞，导致排在它后面、目的端口空闲的分组也无法转发）会进一步降低吞吐量；**输出排队**——多个输入端口同时向同一输出端口发送时输出端口成为瓶颈，输出队列溢出丢包。因此**输入或输出队列产生溢出是造成分组丢失的重要原因**。

:::key 路由器的功能边界（高频辨析）
- 路由器是**网络层设备**，实现了网络模型的下三层：物理层、数据链路层和网络层。
- **若一个存储转发设备实现了某个层次的功能，则它可以互连两个在该层次上使用不同协议的网段。** 如网桥实现了物理层和数据链路层，可互连两个物理层和数据链路层不同的网段；但**中继器**实现了物理层却不能互连两个物理层不同的网段，因为**中继器不是存储转发设备，属于直通式设备**。
- 路由器向传输层及以上隐藏下层实现，所以物理层、数据链路层、网络层协议可以不同；而网络层之上的协议数据是路由器不能处理的，因此**网络层以上的高层协议必须相同**。使用特定路由器连接 IPv4 与 IPv6 网络，就是典型的**网络层协议不同而实现互连**的例子。
- **存储转发机制**：先接收整个分组，然后对分组做错误检查，出错就丢弃，否则存储该分组，最后根据路由选择协议把分组转发到合适端口。**路由器只能根据 IP 地址转发。**
- **完整路径问题**：每个路由器都根据路由表选择下一跳地址，只有到了下一跳路由器才知道再下一跳怎么走。**路由器和源主机都不知道分组要经过的完整路径。**
:::

:::exam 真题考法
2012 年第 37 题考"IP 路由器功能的描述"，正确的是"运行路由协议，设置路由表""监测到拥塞时，合理丢弃 IP 分组""根据目的 IP 地址将其转发到合适的输出线路上"；错误项是"对收到的 IP 分组头进行差错校验，确保传输的 IP 分组不丢失"——**IPv4 首部校验和只检查首部差错，发现错误通常丢弃分组；IP 提供尽力而为服务，不保证可靠交付**。2010 年第 38 题考"能够抑制广播风暴的设备"，答案是**仅路由器**。
:::

### 路由表与分组转发

**路由表的结构**：标准路由表有 **4 个项目：目的网络 IP 地址、子网掩码、下一跳 IP 地址、接口**。**划分子网后，路由表必须包含三项内容：目的网络地址、子网掩码和下一跳地址**（加上出接口共四项）。

**转发表**是从路由表得出的，表项与路由表项有直接对应关系，但格式不同，其结构应使**查找过程最优化**（路由表则需对网络拓扑变化的计算最优化）。转发表中含分组将要发往的目的地址以及分组的下一跳（实际为 MAC 地址）。可用一个默认路由代替所有具有相同"下一跳"的项目，并把默认路由设置得比其他项目优先级低。

**主机发送 IP 数据报的过程**：① **判断是否同属一个网络**——用本机子网掩码与目的 IP 地址逐位按位与，对比结果与本机网络地址；一致则目的主机与本机在同一局域网（**直接交付**），不一致则目的主机在外部网络（**间接交付**）。② **封装 MAC 帧并发送**——**同网**时通过 ARP 获取**目的主机**的 MAC 地址，封装成 MAC 帧后直接发送；**异网**时通过 ARP 获取**默认网关**的 MAC 地址，目的 MAC 字段填网关 MAC，把数据报交给默认网关，由路由器继续转发。

**路由器转发 IP 数据报的完整过程**：

1. **提取目的地址**：从收到的 IP 数据报首部提取目的 IP 地址 D。
2. **判断直连网络直接交付**：用路由器各直连接口的子网掩码分别与 D 逐位按位与，若结果与对应接口的网络地址匹配则说明目的主机在直连子网，执行**直接交付**（ARP 解析目的 IP 的 MAC，封装 MAC 帧从对应接口发出）；全部不匹配则进入路由表查表。
3. **匹配特定主机路由**：若存在目的地址为 D 的**特定主机路由（/32 前缀）**，转发给该路由指定的下一跳。
4. **匹配子网路由（最长前缀匹配）**：遍历所有子网表项，用每条表项的掩码与 D 按位与得 N，若 N 与该表项的目的网络地址匹配，则选择**前缀最长**的匹配项，转发给对应下一跳。
5. **匹配默认路由**：若子网路由无匹配项，检查是否存在 `0.0.0.0/0`，存在则转发给默认路由指定的下一跳。
6. **转发失败处理**：若无任何匹配路由，或 TTL 减为 0，则丢弃该 IP 数据报，并向源主机返回 ICMP 差错报告。

**分组转发的三个核心特点**：① **最长匹配**——采用 CIDR 时若有多个匹配前缀，应使用**最长前缀匹配**；为更快查找可按前缀长短把最长的排在第 1 行、按降序排列，这样从第 1 行开始查找，检索到匹配的就不必再继续。② **非完整路径**——转发表没有给分组指明到某个网络的完整路径，只指出应当先到某个下一跳路由器，到达后再继续查找其转发表。③ **MAC 帧变化**——得到下一跳路由器的 IP 地址后，并不直接把它填入待发送的数据报，而是通过 ARP 转换成 MAC 地址填入 MAC 帧首部，再据此找到下一跳路由器。**不同网络中传送时 MAC 帧的源、目的地址都要变化，而 IP 层的源、目的地址保持不变。**

:::key 最长前缀匹配查表计算题的标准解法
1. 对每条路由表项，**用该表项的掩码与目的 IP 地址按位与**，得到候选网络地址。
2. **比较候选网络地址是否等于该表项的目的网络地址**，相等则该表项匹配。
3. 在**所有匹配表项中选前缀最长的那条**（等价于掩码中 1 最多、块大小最小的那条）。
4. 若选中直连网络，则从对应接口直接交付；否则转发给表项给出的下一跳。
5. **默认路由 0.0.0.0/0 与任何地址都匹配（前缀长度 0），但优先级最低**，只有当没有其他表项匹配时才使用。
:::

**【算例：真题型最长前缀匹配】** 2015 年第 38 题路由表如下，收到目的地址为 169.96.40.5 的 IP 分组，转发接口是哪一个？

| 目的网络 | 下一跳 | 接口 |
| :--- | :--- | :--- |
| 169.96.40.0/23 | 176.1.1.1 | S1 |
| 169.96.40.0/25 | 176.2.2.2 | S2 |
| 169.96.40.0/27 | 176.3.3.3 | S3 |
| 0.0.0.0/0 | 176.4.4.4 | S4 |

**解**：/23 掩码 255.255.254.0，与 169.96.40.5 按位与得 169.96.40.0，**匹配**；/25 掩码 255.255.255.128，第四字节 5 落在 $0\sim 127$ 块内，得 169.96.40.0，**匹配**；/27 掩码 255.255.255.224，第四字节块大小 $256-224=32$，5 落在 $0\sim 31$ 块内，得 169.96.40.0，**匹配**；/0 与任何地址都匹配但前缀最短。三条具体路由都匹配，取前缀最长的 **/27**，因此从 **S3** 接口转发（选 C）。

**【算例：聚合路由与直连路由的优先级】** 2013 年第 47 题第 (2) 问：R2 路由表中同时有 194.17.20.0/23（下一跳 194.17.24.2，接口 S1）与 194.17.20.128/25（直接交付，接口 E0），收到目的地址 194.17.20.200 的分组，从哪个接口转发？**解**：194.17.20.200 同时匹配 194.17.20.0/23（覆盖 194.17.20.0～194.17.21.255）和 194.17.20.128/25（覆盖 194.17.20.128～194.17.20.255）。按最长前缀匹配选择 **/25**，从 **E0** 接口转发。这道题揭示一个重要设计技巧：**虽然 /23 也覆盖 /25 的范围，但由于 /25 更具体，直连子网的分组不会被错误地转发给 R3**，因此可用一条聚合路由加一条更具体的直连路由来缩减路由表规模而不出错。

**【算例：TTL 与跳数】** 2014 年第 43 题第 (2) 问：主机 192.1.1.130 向主机 192.1.7.211 发送 TTL=64 的 IP 分组，R1 通过哪个接口转发？目的主机收到的 TTL 是多少？**解**：目的主机位于 192.1.7.0/24，R1 使用聚合路由 192.1.6.0/23（下一跳 10.1.1.2，接口 L0），从 **L0** 发往 R2，随后经 R2、R4 到达目的子网。分组经过 R1、R2、R4 共 **3 台路由器**，每台转发前把 TTL 减 1，所以目的主机收到时 $TTL=64-3=61$。

:::key TTL 计算的关键
初值 $T$ 的分组经过 $k$ 台路由器后，目的主机收到的 TTL 为 $T-k$。**"经过的路由器数"包括发出分组的主机之后所有转发该分组的路由器，但不包括目的主机本身。** 若问"初始 TTL 至少设置为多少才能送达"，最坏路径上有 $k$ 台路由器要减 1，则初值至少为 $k+1$。2024 年第 47 题第 (2) 问中 AS3 内最坏路径经过 15 台路由器，故初始 TTL 至少为 **16**。
:::

**路由表与转发表的比较**：① 路由表根据路由选择算法得出、主要用途是路由选择、总是用软件实现，转发表可以用软件也可以用硬件实现；② **路由表不等于转发表**，分组的实际转发靠直接查找**转发表**；③ 由于转发表根据路由表生成、路由表又由路由算法得到，因此**路由算法决定了转发表中的值**；④ **转发**是路由器根据转发表把收到的 IP 数据报从合适端口转发出去，仅涉及一个路由器；**路由选择**涉及很多路由器，路由表是许多路由器协同工作的结果。

| 路由类型 | 目的网络地址 | 固定子网掩码 | 网络前缀 | 匹配优先级 |
| :--- | :--- | :--- | :--- | :--- |
| 特定主机路由 | 单个主机 IP | 255.255.255.255 | /32 | 最高 |
| 普通网段路由 | 目标网段 | 按需自定义 | /8～/30 | 中等 |
| 默认路由 | 0.0.0.0 | 0.0.0.0 | /0 | 最低 |

## 本章小结表

**一、IPv4 首部关键字段速查**

| 字段 | 位数 | 单位 | 关键结论 |
| :--- | :--- | :--- | :--- |
| 首部长度 | 4 | 4 B | 最小 5（20 B），最大 15（60 B） |
| 总长度 | 16 | 1 B | 最大 65535 B，含首部 |
| 标识 | 16 | — | 同一数据报所有分片标识相同；不是序号 |
| 标志 | 3 | — | 低 MF、中 DF、高保留（0）；DF=1 不许分片 |
| 片偏移 | 13 | 8 B | 除最后一片外数据长度是 8 B 的整数倍 |
| TTL | 8 | 跳 | 每台路由器减 1，为 0 则丢弃并发 ICMP 时间超过 |
| 协议 | 8 | — | ICMP=1，IGMP=2，TCP=6，UDP=17，OSPF=89 |
| 首部检验和 | 16 | — | 只检验首部；反码求和再取反码 |

**二、地址与编址方法演进**

| 阶段 | 地址结构 | 掩码/前缀 | 关键点 |
| :--- | :--- | :--- | :--- |
| 分类编址 | 网络号 + 主机号 | 255.0.0.0 / 255.255.0.0 / 255.255.255.0 | A/B/C/D/E 类；主机号全 0、全 1 不可分配 |
| 划分子网 | 网络号 + 子网号 + 主机号 | 子网掩码 | 从主机号借位；子网数只能是 2 的幂 |
| 无分类编址 CIDR | 网络前缀 + 主机号 | 斜线记法 /n | 消除类别概念；支持路由聚合与最长前缀匹配 |

**三、五类必考计算题的解法要点**

| 计算类型 | 核心公式或规则 | 易错点 |
| :--- | :--- | :--- |
| IP 分片 | $d_{\max}=\lfloor(MTU-20)/8\rfloor\times 8$；片偏移 = 之前数据字节数 ÷ 8；总长度含首部 | 总长度不必是 8 的倍数，只有片偏移单位是 8 B |
| 子网划分 | 块大小 $=256-$ 掩码中该字节的值；网络地址向下取整；可用数 $=2^{h}-2$ | 忘记减 2；块起点取错 |
| CIDR 聚合 | 取所有网络地址的最长共同前缀；验证起点是块大小整数倍 | 聚合引入不存在的网络；下一跳写成自己 |
| 路由表转发 | 逐条掩码按位与 → 匹配项取前缀最长 | 忽略默认路由优先级最低；误改目的 IP |
| RIP 更新 | 报文下一跳改 X、距离全部 +1；无则加、同下一跳则换、更小则改、等则加、更大则不改 | 忘记距离 +1；忘记 16 上限（不会出现 17） |

**四、ARP / DHCP / ICMP 对照**

| 协议 | 层次 | 承载 | 关键报文/类型 | 核心结论 |
| :--- | :--- | :--- | :--- | :--- |
| ARP | 网际层或数据链路层（两种划分都可） | 直接封装在链路层帧中 | 请求（广播）、响应（单播） | 只在本局域网内有效；跨网段解析的是默认网关的 MAC |
| DHCP | 应用层 | UDP（服务器 67、客户端 68） | DISCOVER / OFFER / REQUEST / ACK | 四个报文目的 IP 都是 255.255.255.255；OFFER、ACK 在链路层单播 |
| ICMP | 网际层 | IP（协议号 1） | 差错：终点不可达、源点抑制、时间超过、参数问题、改变路由；询问：回送请求/回答、时间戳 | ping 用回送请求和回答；traceroute 依赖时间超过；对组播数据报不发差错报文 |

**五、RIP / OSPF / BGP 对比**

| 对比项 | RIP | OSPF | BGP |
| :--- | :--- | :--- | :--- |
| 归属 | IGP（域内） | IGP（域内） | EGP（域间） |
| 算法 | 距离-向量 | 链路状态 | 路径-向量 |
| 承载 | UDP 520 | IP，协议号 89 | TCP 179 |
| 度量 | 跳数（最大 15，16 不可达） | 代价（带宽、时延等，可自定义） | AS-PATH 等属性 + 策略 |
| 交换范围 | 仅相邻路由器 | 洪泛至 AS 内所有路由器 | 仅邻站 |
| 收敛 | 慢 | 快 | 增量更新 |

**六、IPv4 与 IPv6 对照**

| 对比项 | IPv4 | IPv6 |
| :--- | :--- | :--- |
| 地址长度 | 32 bit | 128 bit |
| 基本首部长度 | 20 B 固定 + 0～40 B 可选 | 固定 40 B |
| 分片 | 源主机和路由器都可分片 | 只有源主机可分片 |
| 首部检验和 | 有 | **无** |
| TTL / 跳数限制 | TTL | 跳数限制（Hop Limit） |
| 上层协议标识 | 协议字段 | 下一个首部字段 |
| 选项 | 首部中的选项字段 | 扩展首部（路由器不处理，逐跳选项除外） |
| 地址配置 | 需 DHCP | 支持地址自动配置 |
| 地址解析 | 需 ARP | 不需要 ARP（接口标识符 64 bit 可直接编码） |
| 过渡技术 | — | 双协议栈、隧道技术 |

## 易错清单

:::warn 1. IP 分片的三个数字
**首部长度以 4 B 为单位，总长度以 1 B 为单位，片偏移以 8 B 为单位。** 算"每片最多携带多少数据"要先用 $\lfloor(MTU-20)/8\rfloor\times 8$ 向下取整；算"总长度"要记得加回 20 B 首部；看到"最后一片总长度不是 8 的倍数"不要怀疑自己算错——只有**除最后一片外**的数据长度必须是 8 的整数倍。
:::

:::warn 2. 可用地址数永远要减 2
子网/地址块内可分配给主机或路由器接口的地址数 $=2^{h}-2$，要减掉**网络地址（主机号全 0）**和**广播地址（主机号全 1）**。但若题目问的是"地址块中有多少个地址"，则**不减 2**（例如 /20 有 4096 个地址）。读题时必须分清问的是"地址总数"还是"可分配数"。
:::

:::warn 3. 特殊地址的方向性
**0.0.0.0 和 0.host-id 只能作源地址不能作目的地址；255.255.255.255 只能作目的不能作源；127.x.x.x 源、目的都可以但不走外网**；主机号全 0 的网络地址既不能作源也不能作目的。问"只能作源"或"只能作目的"时必须逐一核对方位。
:::

:::warn 4. 划分子网不改变网络号，也不能从 IP 地址判断
**从一个 IP 地址本身无法判断该主机所连接的网络是否进行了子网划分。** 划分子网只是把主机号再划分，**不改变原有类别归属**，也不增加"网络"数量——只提高 IP 地址利用率。反之，**给定 IP 与掩码就能算出子网划分的全部细节**。
:::

:::warn 5. 最长前缀匹配与默认路由
默认路由 `0.0.0.0/0` 与**任何**目的地址都匹配（全 0 掩码按位与结果必为全 0），但它的前缀长度是 **0**，所以只要有任何其他表项匹配就绝不会选中它。特定主机路由 `/32` 优先级最高。**做题时先找出所有匹配项再比前缀长度，不要一看到 0.0.0.0/0 就直接下结论。**
:::

:::warn 6. 路由器转发不改变目的 IP 地址
**路由器转发分组时只改写链路层的 MAC 帧首部（源 MAC、目的 MAC 逐跳变化），IP 首部中的源 IP 和目的 IP 全程不变**（除非经过 NAT 设备，或 TTL 减 1、检验和重算）。综合题问"经过某路由器后源/目的 IP 是什么"时，若该路由器不是 NAT 路由器，答案都是"不变"；"下一跳地址"是路由表里的字段，不会被写进 IP 首部。
:::

:::warn 7. ARP 请求的目标 IP 是网关而非最终目的主机
当目的主机不在同一局域网时，**ARP 解析的是默认网关（本网段路由器接口）的 MAC 地址**。另外，**ARP 响应是单播**（只有请求方能收到），不是广播。DHCP 的 OFFER 和 ACK 在**链路层**是单播（目的 MAC 是客户端），但**IP 层目的地址仍是 255.255.255.255**。
:::

:::warn 8. RIP 的 16 与"距离 17"
RIP 中距离等于 **16 就表示不可达**，**永远不会出现 17**。若邻居通告 `<net, 16>`，则自己经该邻居也到不了。同时注意：**同一邻居通告的路由无条件替换**；不同邻居通告且新距离相等时可以添加实现等价负载均衡，新距离更大则不更新。
:::

:::warn 9. 三类协议的封装方式必须记准
**RIP 用 UDP（端口 520）；OSPF 直接封装在 IP 数据报中（协议号 89），没有经过 TCP 或 UDP；BGP 用 TCP（端口 179）。** 从封装角度看 RIP 和 BGP 属于应用层、OSPF 属于网络层；但 RIP 的核心功能是路由选择，属于网际层。这个"封装层次"与"功能层次"的差别是常见陷阱。
:::

:::warn 10. IPv6 与 IPv4 的对比细节
IPv6 地址空间是 IPv4 的 $2^{96}$ 倍，**不是 96 倍**；IPv6 基本首部固定 **40 B**；IPv6 的**有效载荷长度不包含基本首部但包含扩展首部**；IPv6 **取消了首部检验和**；IPv6 **只有源主机能分片**；IPv6 **不需要 ARP**（接口标识符 64 bit 足以直接编码硬件地址，地址解析由邻居发现协议 ND 完成）；IPv6 **地址类型是单播、多播、任播三种**，没有广播类型（广播被看作多播的特例）。
:::

:::warn 11. 路由聚合的"引入不存在的网络"
聚合后的地址范围往往**大于**原有各子网地址范围的并集（这正是聚合能减少表项的原因）。工程上通常可以接受（额外地址范围没有实际主机，分组到达后会因无更具体路由而被丢弃或走默认路由），但在要求"不引入不存在的网络"的题目中必须谨慎。判断标准是：**待聚合的各网络是否恰好拼成一个完整的 2 的幂地址块范围且起点对齐**。
:::

:::warn 12. 拥塞控制与流量控制不要混为一谈
**流量控制**是发送方与接收方之间的**点对点**通信量控制，目的是抑制发送速率使接收方来得及接收；**拥塞控制**关注整个网络的负载，是全局性的。开环控制是**静态的预防方法**（启动后中途不再修改），闭环控制基于**反馈环路**，是**动态的方法**。
:::
