## 总线

### 总线的基本概念

**总线（bus）**是连接多个部件、供各部件之间交换信息的一组**共享**传输线。它的两个本质特征是：

- **分时**：同一时刻只允许一个部件（主设备）向总线发送信息，其他部件只能等待属于自己的时间段。
- **共享**：总线上挂接的多个部件可以在不同时刻分别获得使用权；从设备可以在同一时刻共同接收总线上广播的信息。

总线是为了替代早期「分散连接」而出现的。分散连接下，部件两两之间都要有专门连线，连线数量随部件数平方级增长，且同一时刻每个部件只能与一个部件通信，既难扩展又难维护。改成总线后，所有部件挂在一组公共线上，新增设备只需挂到总线上，可扩展性大幅提升，代价是同一时刻只能有一对主从设备通信，需要**总线仲裁**来解决争用。

:::key 总线 = 共享 + 分时
共享决定「大家都能用」，分时决定「同一时刻只有一个能发」。这两句话能推出后面所有结论：为什么需要仲裁、为什么需要定时、为什么带宽要按「每次传送多少字节 × 每秒传送多少次」算。
:::

#### 总线的分类

**按数据传送方式分：串行总线与并行总线。**

- **并行总线**：含多条双向数据线，一次可以同时传送多位。优点是单位时间内传送的数据量大；缺点是各条数据线的电气特性很难完全一致，线长增加后各位可能无法同时到达接收端（**时钟偏斜**），相邻线之间还会**串扰**，因此**并行总线只适合近距离通信**。大多数**系统总线属于并行总线**。
- **串行总线**：只有一条双向数据线或两条单向数据线，逐位按序传送。优点是线少、抗干扰好、传输距离长；缺点是同样时钟频率下单次传送量少。大多数**通信总线属于串行总线**。

:::warn 「并行一定比串行快」是错的
并行总线能同时传多位，在时钟频率较低时确实比串行快；但当频率提高到一定程度，并行线之间的串扰和偏斜会让数据无法恢复，反而提不上频率。串行总线线少、串扰小，容易把时钟频率做高，还能用多通道（多条链路）叠加带宽，所以**高速串行总线的实际速率完全可以超过并行总线**。统考考过这个结论：PCI-Express 就是高速**串行**总线，PCIe×16 是 16 条串行通路的组合，不是 16 位并行传输。同理，USB 的 D+、D− 是一对差分信号，两者共同表示一个串行数据状态，**不是「同时传输 2 位数据」**。
:::

**按功能层次分：片内总线、系统总线、通信总线。**

- **片内总线**：芯片**内部**各部件之间的连线，如 CPU 内部寄存器之间、寄存器与 ALU 之间、控制器与执行部件之间的连线。
- **系统总线**：计算机系统内各功能部件（CPU、主存、I/O 接口）之间相互连接的总线，是通常默认所指的「总线」。按传送信息内容又细分为三类：
  - **数据总线（data bus）**：传送**数据信息**。它是**双向**总线。这里的数据是广义的，包括 CPU 与主存之间交换的数据或指令、CPU 从 I/O 接口读入的状态字与中断类型号、CPU 写入 I/O 接口的命令字，以及地址/数据线复用时的地址信息。数据总线的条数称为**数据总线宽度**，它是衡量系统性能的重要指标。注意**MDR 的位数与数据总线宽度相等，但与存储字长不一定相等**。
  - **地址总线（address bus）**：给出数据总线上源数据或目的数据在主存单元或 I/O 端口中的**地址**，是**单向**总线（由主设备指向从设备）。地址线的位数决定 CPU 可直接寻址的空间大小，$n$ 根地址线最大可寻址 $2^n$ 个单元；**地址线位数 = MAR 位数**。
  - **控制总线（control bus）**：传送控制命令和时序信号，用于总线控制权协商、设备控制命令与应答等。**对其中某一根信号线是单向的（要么是 CPU 送往部件，要么是部件送往 CPU），但对整个控制总线而言是双向的**。常见控制信号包括存储器读/写、I/O 读/写、传输应答、总线请求/许可/忙、中断请求/响应、时钟与复位信号等。
- **通信总线（外部总线）**：计算机系统之间、或计算机系统与其他系统（远程通信设备、测试设备）之间传送信息的总线，如 USB。相对而言，系统总线与 I/O 总线也可统称为内部总线。

:::exam 数据线上「不可能」传什么
统考反复考一类题：问系统总线的**数据线**上不可能传输下列哪一项。判断依据是**看信号的性质属于数据还是属于控制**：
- 指令、操作数 → 数据线；
- I/O 接口的**命令字**、**状态字** → 数据线（它们本质是写入/读出寄存器的二进制数据）；
- **中断类型号** → 数据线（中断响应时由中断控制器送上数据总线）；
- **握手（应答）信号、读/写控制信号、总线请求/许可** → **控制总线**，不是数据线。

所以第 1 类题的标准答案是「握手信号」。第 2 类题问「I/O 总线的数据线上传输的信息包括」，答案是命令字、状态字、中断类型号三者都包括。
:::

**按传输定时方式分：同步总线与异步总线。** 同步总线用统一时钟定时，异步总线用握手信号定时。这一对概念放在「总线事务和定时」中展开。

:::warn 单总线结构不等于只有一根线
「单总线结构」是指 CPU、主存、I/O 设备（经 I/O 接口）全部挂在**一组**系统总线上，而不是说物理上只有一根信号线——这一组总线里仍然包含数据线、地址线、控制线。单总线的优点是结构简单、易扩充；缺点是所有部件共享一组线，同一时刻只能有一个部件向总线发送信息，系统效率受限，多用于小型机或微型机。
:::

### 总线的组成及性能指标

总线在物理上由**一组信号线**加**总线控制器（仲裁机构）**组成；逻辑上则包括三条信息通路（数据、地址、控制）以及总线控制权协商机制。评价一条总线，看下面六个指标。

#### 总线宽度

**总线宽度**指数据总线的根数，单位是位（bit），如 8 位、16 位、32 位、64 位。在并行总线中它直接决定一次能并发传送多少位数据，是带宽公式里的第一个因子。计算带宽时通常要先把它换算成字节：$W(\text{B}) = \text{总线宽度}/8$。

#### 总线时钟频率与总线工作频率

- **总线时钟频率** $f_{clk}$ 是总线时钟周期的倒数。同步总线中传输双方持有完全同步的时钟信号，时钟频率越高传输越快。
- **单时钟传输次数** $k$ 指一个总线时钟周期内传送数据的次数：普通总线取 1；**DDR**（Double Data Rate）在时钟的上升沿和下降沿各传送一次，取 2；QDR 取 4。
- **总线工作频率**（也称有效数据传输率）为

$$f_{work} = f_{clk} \times k$$

:::key 时钟频率 ≠ 工作频率
这是统考反复设的坑：**同步总线由时钟信号定时，但时钟频率不一定等于工作频率**。双沿传输时工作频率是时钟频率的 2 倍；反过来，如果一个总线周期占多个时钟周期，工作频率又会低于时钟频率。「时钟频率」与「工作频率」必须分开算。
:::

#### 总线传输周期

**总线传输周期**（简称**总线周期**）是指在总线上完成**一次总线事务**所用的时间，由若干个总线时钟周期组成。完整的总线周期一般包括总线请求、总线仲裁、设备寻址、数据传输、总线释放几个阶段。通常**一个总线周期只传送一个总线宽度的数据**。

两个推论要记住：

- 总线时钟频率越高，总线周期越短；
- **采用地址/数据线复用会加长总线周期**（地址和数据要分时传送），所以复用能省引脚，但不能提高速率，反而可能降低速率。

#### 总线带宽

**总线带宽（bus bandwidth）**是总线上最大的数据传输速率（单位时间传送的字节数），通常**不考虑**总线传输周期中总线请求、仲裁、寻址等开销，只按真正传送数据的部分计算。单位是 MB/s 或 GB/s，其中 **1 MB = $10^6$ B，1 GB = $10^9$ B**（总线带宽沿用通信与存储领域的十进制换算，不用 1024）。

$$BW = \frac{W}{8} \times f_{clk} \times k = \frac{W}{8} \times f_{work}$$

其中 $W$ 为总线宽度（bit），$f_{clk}$ 为时钟频率，$k$ 为单时钟传输次数，$f_{work}$ 为工作频率。

这个公式还有几种等价写法，考试里哪一种方便就用哪一种：

- **按「每次传送的字节数 × 每秒传送次数」写**：$BW = D \times f_{work}$，$D$ 为一次传送的字节数。若题目给的是「一个总线周期传送 $D$ 字节，一个总线周期占 $m$ 个时钟周期」，则 $BW = \dfrac{D}{m \cdot T_{clk}} = \dfrac{D \cdot f_{clk}}{m}$。
- **按「总线周期」写**：$BW = \dfrac{D}{T_{bus}}$，$T_{bus}$ 为总线传输周期。这就是题目里常见的 $W/(T)$ 形式：$BW = W_{\text{字节}} / T_{\text{总线周期}}$。
- **按「每秒传输次数」写**（串行高速总线，如 QPI、PCIe）：$BW = \text{GT/s} \times \text{每次有效字节数} \times \text{方向数}$。

:::key 四种表述，同一个式子
1. $BW = \dfrac{W}{8}\times f_{clk}\times k$
2. $BW = \dfrac{W}{8}\times f_{work}$
3. $BW = \dfrac{D}{T_{bus}}$（$D$ 为一个总线周期传送的字节数）
4. $BW = \dfrac{D\cdot f_{clk}}{m}$（$m$ 为一个总线周期占用的时钟周期数）

它们互相等价，区别只是题目给了哪几个量。做题第一步永远是：**先确定「一次传送多少字节」，再确定「每秒传送多少次」，两者相乘。**
:::

#### 总线带宽典型算例

:::exam 算例 1（时钟周期数与总线周期不相等，2009 年统考）
系统总线在一个总线周期中并行传输 4 B，一个总线周期占 **2 个时钟周期**，总线时钟频率 10 MHz，求总线带宽。

一个时钟周期传送 $4\text{ B}/2 = 2\text{ B}$，故

$$BW = 2\text{ B} \times 10\text{ MHz} = 20\text{ MB/s}$$

**陷阱**：直接算成 $4 \times 10 = 40$ MB/s 就忽略了一个总线周期占 2 个时钟周期。
:::

:::exam 算例 2（双沿传输 + 地址/数据线复用，2014 年统考）
同步总线采用数据线和地址线复用，地址/数据线 32 根，总线时钟频率 66 MHz，**每个时钟周期传送两次数据**（上升沿、下降沿各一次），求最大数据传输率。

32 根线在数据阶段一次传送 32 bit = 4 B，单时钟传输次数 $k = 2$：

$$BW = 4\text{ B} \times 66\text{ MHz} \times 2 = 528\text{ MB/s}$$

**注意**：题目问的是**峰值**传输率，地址/数据线复用只影响事务的时序结构，不需要在结果里再除以 2。
:::

:::exam 算例 3（多通道存储器总线，2019 年统考）
采用 3 通道存储器总线，内存条为 DDR3-1333（存储器总线工作频率 1333 MHz，总线宽度 64 位），求总带宽。

DDR3-1333 中的 1333 已经是**双倍传输后的有效工作频率**，不能再乘 2。单通道一次传送 8 B：

$$BW_{\text{单}} = 8\text{ B} \times 1333\text{ MHz} \approx 10.66\text{ GB/s},\qquad BW_{\text{总}} = 3 \times 10.66 \approx 32\text{ GB/s}$$
:::

:::exam 算例 4（串行全双工总线，2020 年统考）
QPI 是点对点全双工同步**串行**总线，每方向每次传输 20 位（16 位数据 + 4 位校验位），每个时钟周期传送 2 次，时钟频率 2.4 GHz。求总线带宽。

每秒传输次数 $= 2.4\text{ GHz} \times 2 = 4.8\text{ GT/s}$；每次有效数据 16 bit = 2 B；全双工两个方向同时传输：

$$BW = 4.8\text{ GT/s} \times 2\text{ B} \times 2 = 19.2\text{ GB/s}$$

**两个易错点**：4 位校验位不计入有效数据带宽；全双工的「×2」是方向数，不能漏。
:::

:::exam 算例 5（非突发事务逐次计算，2023 年统考）
存储器总线宽度 64 位，总线时钟频率 1 GHz，传输一个数据或地址需 1 个时钟周期，**不支持突发传送**。主存每次准备一个 64 位数据需 6 ns，主存块大小 32 B。求读取一个主存块的时间。

时钟周期 $= 1\text{ ns}$。总线宽度 64 位 = 8 B，一个 32 B 主存块需传送 $32/8 = 4$ 次。不支持突发，则每次都要单独走一次完整事务：送地址 1 个周期（1 ns）+ 主存准备 6 ns + 传数据 1 个周期（1 ns）= 8 ns。

$$T = 4 \times 8\text{ ns} = 32\text{ ns}$$
:::

:::warn 总线带宽与「实际数据传输率」不是一回事
**总线带宽是总线的固有性能指标**，只反映「有数据传送时」的最快速率，不受传送方式影响，也不把地址阶段、仲裁阶段、存储器准备时间算进去。如果题目问的是「处理器一直发起某类事务时总线的**实际**数据传输率」，那就要用「一批数据量 ÷ 完成这批数据所需的全部时间（含地址、准备、仲裁开销）」来算，两者的答案会明显不同。真题曾在选项中同时给出这两个数来迷惑考生（例如 2024 年那道给足干扰条件的题，答案只需按有数据传送的时钟周期算）。
:::

#### 总线复用

总线信号线分为**专用**与**复用**两类。专用信号线只传一种信号（系统总线的数据线、地址线、控制线就是专用总线）；**复用总线**是让一组传输线具有多种用途，**分时**传送不同类型的信息。常见形式：

- **地址总线与数据总线复用**：某时刻传地址，另一时刻传数据。PCI 总线是典型例子。
- **同一功能的线缆复用**：DRAM 芯片的**行、列地址线复用**，在不同时刻分别送行地址和列地址，大幅减少芯片引脚。
- **串行总线**可以看作最极端的总线复用：所有信息都通过一根（或一对差分）线传递。

复用的**优点**是提高总线利用率、减少引脚数目和布线空间、降低成本；**缺点**是控制逻辑复杂，且**分时传送机制会引起总线性能下降**（事务时间变长）。

:::warn 复用能提高速率吗？不能
「采用信号线复用技术可减少信号线数量」正确；「采用地址/数据线复用可提高同步总线数据传输率」**错误**。能提高数据传输率的是：**增加总线宽度、提高总线工作频率、支持突发传送**这三项。突发传送之所以有效，是因为它只送一次首地址就把连续多个数据传完，摊薄了地址和仲裁开销，**提高了有效**（实际）**数据传输率**。
:::

#### 其他性能指标

- **总线负载能力**：总线上可连接的设备数量，与总线的驱动能力和电气特性有关。
- **总线复用程度、是否支持突发、是否支持分离事务**：都是影响有效带宽的结构性因素。

### 总线事务和定时

#### 总线事务与突发传送

**总线事务（bus transaction）**是指在总线上**一对主从设备之间完成一次信息交换的过程**，即从请求总线到完成总线使用的操作序列。发起事务并能获得总线控制权的设备叫**主设备（master）**，被主设备寻址、被动响应的设备叫**从设备（slave）**。

:::key 一条总线上可以挂多对主从设备，但同一时刻只有一个活动主设备
主设备既可以发送数据给从设备，也可以接收从设备的数据，是主动的一方；从设备只能被动响应。如果主设备采用广播方式发送数据，则可以有多个从设备同时接收。**总线事务的类型由操作性质决定**，典型的有存储器读、存储器写、I/O 读、I/O 写、中断响应等。
:::

一个完整的总线周期可分五个阶段：

1. **总线请求**：CPU 或 DMA 等主设备需要使用总线时发出传输申请。
2. **总线仲裁**：多个主设备同时请求时，由总线仲裁机构决定谁获得下一个传输周期的总线控制权。
3. **设备寻址**：获得控制权的主设备把要访问的从设备地址及相关命令送到总线上，启动从设备。
4. **数据传输**：主从设备之间进行数据交换，数据单向或双向传送。该阶段通常一次只传送一个字长的数据。
5. **总线释放**：主设备不再占用总线，撤除相关信息，释放总线控制权。

:::exam 「一次总线事务」是常考的定义题
题干若描述「主设备只需给出一个首地址，从设备就能从首地址开始的若干连续单元读出或写入多个数据」，答案是**突发（猝发）传输**。要能与另外几组概念区分开：**并行/串行**描述一次通过几根通道传送数据位；**同步/异步**描述定时方式；它们都不是「事务的组织方式」。
:::

**总线突发（猝发）传送方式**（成组传送事务）：一次性传送地址上连续的一批数据。主设备只需给出这批数据的**首地址**，随后就可以在传输阶段连续传送多个地址连续单元的数据；**在这批数据传输过程中总线一直被占用，直到整批数据传完才释放**。

- 非突发方式：每个传送周期都要先送地址再送数据，主从设备之间通常每次只能传一个字长。
- 突发方式：每个总线周期仍只传一个计算机字长，但**不释放总线**，直到一组信息全部传完。

突发传送的代价是按地址递增规则访问，因此适用于连续成块的数据（存储器块读、Cache 行填充等）。它的收益是把「地址开销」摊薄到多个数据上，从而**提高总线的有效数据传输率**。

:::exam 算例（突发传送的事务时间，2012 年统考）
同步总线时钟频率 100 MHz、宽度 32 位、地址/数据线复用、每传一个地址或数据占 1 个时钟周期，支持突发传送。求一次「主存写」总线事务传输 128 位数据所需的最少时间。

时钟周期 $= 1/100\text{ MHz} = 10\text{ ns}$。复用线传首地址需 1 个周期 = 10 ns；32 位宽度下传 128 位需 $128/32 = 4$ 个周期 = 40 ns。

$$T = 10\text{ ns} + 40\text{ ns} = 50\text{ ns}$$

**陷阱**：漏掉地址周期会得到 40 ns；把复用误当成「要额外多除一次」会得到更离谱的数。题目说「至少」，意味着不计仲裁、存储器等待和额外应答时间。
:::

#### 总线定时：同步定时与异步定时

主设备获得总线使用权后，每一步操作何时开始、何时结束、信号保持多久，就是**总线定时**问题。常见有四种：**同步方式、异步方式、半同步方式、分离事务方式**，前两种是考纲重点。

**同步定时方式。** 进行信息交换的两部件或设备**通过统一的时钟进行同步**，即都必须使用**同一个时钟**，在规定时钟节拍内完成规定的总线操作。挂在总线上的所有设备都从时钟线上获得定时信号。例如规定「存储器读」协议：主设备在第 1 个时钟周期发送地址和存储器读命令，从设备总是在第 5 个时钟周期把数据放到总线上作为响应，处理器也在第 5 个周期取数。写操作的传输周期长度同样是固定的。

- **优点**：主从设备协调简单，传输协议简单，**传输速率高**。
- **缺点**：总线定时以**最慢设备**所花时间为标准，因此**适合存取时间相差不大的多个功能部件之间通信**；存在**时钟偏移**问题，所以**同步总线不能过长**，否则会降低传输效率；同步定时中主从设备默认对方正常工作，**可靠性不高**。
- **适用**：总线长度短、设备速度相近、可靠性要求高的场合，如直接与 CPU 相连的系统总线。

**异步定时方式。** **没有统一的时钟限制**，只依靠各部件或设备内部的定时操作，以**信号握手**的方式完成规定的总线操作：主设备发出**请求（Request）**信号，从设备收到后发出**回答（Acknowledge）**信号。由于不需要公共时钟规定请求与应答的时间，**总线周期的长度不再相同**，且有效规避了同步定时的时钟偏移问题，**总线传输距离更长**。

- **优点**：总线周期灵活可变，主从设备不需强制同步，**可以支持速度不同的两个设备挂在同一条总线上**。
- **缺点**：控制逻辑比同步方式复杂，速度比同步定时慢。

**根据请求和回答信号的撤销是否互锁，异步定时分为三种：**

| 方式 | 请求信号 REQ 何时撤销 | 回答信号 ACK 何时撤销 | 速度 | 可靠性 |
|---|---|---|---|---|
| **不互锁** | 发出后经过一段时间**自动撤销**，不等 ACK | 收到 REQ 后经过一段时间**自动撤销**，不等 REQ 撤销 | 最快 | 最差 |
| **半互锁** | **必须等收到 ACK 之后**才能撤销 | **自动撤销**，不受 REQ 约束 | 中等 | 中等 |
| **全互锁** | **必须等收到 ACK 之后**才能撤销 | **必须等 REQ 撤销之后**才能撤销 | 最慢 | 最高 |

:::key 三种握手方式的记忆口诀
**不互锁**：谁也不等谁，发完就撤 → 快而不可靠。
**半互锁**：主设备等从设备（请求等应答才撤），从设备不等主设备（应答自动撤）。
**全互锁**：互相等（请求等应答才撤，应答等请求撤了才撤）→ 最慢最可靠。

结论排序：**速度 不互锁 > 半互锁 > 全互锁；可靠性 全互锁 > 半互锁 > 不互锁**。
:::

**半同步定时方式。** 保留同步定时的特点：所有地址、命令、数据信号的发出时间都严格参照系统时钟的某个前沿开始，接收方采用系统时钟后沿判断识别；同时又像异步定时那样允许不同速度的设备协同工作。为此**增设一条 Wait 响应信号线**：总线在每个时钟到来时采样 Wait 信号，若无效说明数据未准备好，下个时钟再采样，直到有效才去数据线上取数据。

半同步兼有同步与异步的优点：所有信号仍由公共时钟定时，又允许不同速率设备协同工作，还能有效解决异步传输中的噪声敏感问题。**适用于系统工作速度不高、但由许多速度差异较大的设备组成的简单系统。**

:::warn 同步总线的时钟由谁提供
「同步通信方式中，同步时钟信号可由各设备提供」是**错误**说法。同步总线上的设备依据**统一的公共时钟**工作，该时钟通常由总线控制器或统一时钟源提供，**不能由各设备提供彼此独立的时钟**，否则就不叫同步总线了。
:::

:::exam 同步/异步常考结论汇总
- 异步通信中**全互锁协议最慢**（正确）。
- 异步通信中**非互锁协议可靠性最差**（正确）。
- 同步通信中时钟信号**可由各设备提供**（错误）。
- 半同步通信中**握手信号的采样由同步时钟控制**（正确）。
- 异步总线由握手信号定时，**一次握手过程完成的是一个总线宽度的数据交换，不是一位数据**（常说成「完成一位」是错的）。
- 同步总线的**时钟频率不一定等于工作频率**（正确）。
:::

#### 分离事务通信方式（拓展）

前面三种定时方式中，从主设备发出地址和读/写命令到数据传输结束，整个传输周期内总线使用权完全由主设备及被选中的从设备占据。但从设备准备数据的阶段，总线其实纯属空闲等待。**分离事务通信方式**把一个事务分成两个子过程：

1. 主设备获得总线后把事务类型（总线命令）、地址及其他信息（如主设备编号）送到总线上，从设备记录这些信息后，**主设备立即释放总线**，其他设备便可使用；
2. 从设备准备好数据后**重新申请总线**，获得使用权后把主设备编号和数据送上总线，主设备据此接收数据。

- **优点**：在不传送数据的间隙释放总线，让其他申请者使用，**提高总线利用率**。
- **缺点**：控制相当复杂、开销大，事务响应时间变长。

#### 总线仲裁

当多个主设备同时请求总线时，必须由**总线仲裁机构（总线控制器 / 仲裁器）**决定谁获得下一个传输周期的使用权。仲裁方式分为**集中式**与**分布式**两大类。

**集中式仲裁**：仲裁逻辑集中在一处（一般是 CPU 或专门的仲裁器），各主设备通过专门的控制线与它相连。

1. **链式查询方式**：所有设备共用一条**总线请求（BR）**线和一条**总线忙（BS）**线，另有一条**总线允许（BG）**线像链条一样从仲裁器依次穿过各设备。仲裁器收到请求后发出 BG 信号，BG 沿链依次传递，**第一个收到 BG 且自己有请求的设备**获得总线控制权，同时截断 BG 不再往下传。
   - 优点：**只用三根控制线**，结构简单，容易扩充（增减设备只需改链条连接）。
   - 缺点：**优先级固定**（离仲裁器越近越高），且**对故障敏感**——链条上某一级损坏，其后的设备都无法获得总线。
2. **计数器定时查询方式**：撤销 BG 线，改用一组**设备地址线**。仲裁器收到请求后启动计数器开始计数，计数值通过地址线送到各设备，**计数值与自己设备号相等且有请求的设备**获得控制权并停止计数。
   - 优点：优先级**可由计数器初值灵活改变**（每次从 0 开始 → 固定优先级；每次从中止点继续 → 循环优先级，各设备机会均等）；对故障不如链式敏感。
   - 缺点：需要 $\lceil \log_2 n\rceil$ 根地址线，控制线比链式多。
3. **独立请求方式**：每个设备都有一对独立的**总线请求线 BR** 和**总线允许线 BG**，直接连到仲裁器。
   - 优点：**响应速度快**（仲裁器可并行看到所有请求），**优先级灵活**（可由程序设定），对单个设备故障不敏感。
   - 缺点：**控制线数量多**（$2n$ 根），总线控制器复杂，扩展性受引脚限制。

**分布式仲裁**：不设中央仲裁器，每个主设备都带有仲裁逻辑和自己的仲裁号，各设备把仲裁号送到共享的仲裁线上，**每个设备各自判断自己是否胜出**（谁的仲裁号大谁赢），胜者获得总线。优点是可靠性高、无单点故障；缺点是逻辑分散、难以实现复杂的优先级策略。

:::exam 三种集中式仲裁的对比考法
常考「只用三根控制线」→ 链式查询；「优先级固定、对故障敏感」→ 链式查询；「优先级可循环改变」→ 计数器定时查询；「响应最快、控制线最多」→ 独立请求。
:::

## I/O 接口（I/O 控制器）

### I/O 接口的功能和基本结构

外部设备与主机在**工作速度、数据格式、时序控制**上差异极大，且各自有独立的时钟。因此必须在主机与外设之间设置专门的逻辑部件来解决同步协调、速度匹配和数据格式转换问题，这个部件就是 **I/O 接口（I/O interface）**，也叫**设备控制器**、**I/O 模块**、**适配器（adapter）**。

:::key I/O 接口不等于 I/O 设备
I/O 设备由**执行 I/O 操作的机械部分**（设备本体）和**执行控制 I/O 的电子部件**（接口/控制器）组成，通常把这两部分分开。所以：
- 磁盘**驱动器**是设备本体，**不是** I/O 接口；**磁盘控制器**才是接口。
- 打印机适配器、网络控制器、可编程中断控制器**都属于** I/O 接口。
:::

#### I/O 接口的功能

1. **数据缓冲**：用数据缓冲寄存器匹配 CPU 与外设之间的速度差异，起到「蓄水池」作用。
2. **错误检测**（以及必要的纠错）：如奇偶校验、CRC 校验、传输超时检测，把出错信息记入状态寄存器供 CPU 查询。
3. **控制与定时**：接收 CPU 的命令，产生设备所需的控制信号与时序，协调主机与外设的异步工作。
4. **数据格式转换**：如串行↔并行转换（串行接口）、字节↔字装配（不同字长的设备）、数模/模数转换等。
5. **与主机和设备的通信**：主机一侧按总线标准通信（地址译码、读写控制、中断请求），设备一侧按设备自身的电气与协议标准通信。
6. 此外还有**设备寻址**（让 CPU 能选中某个设备及其某个端口）与**状态检测**功能。

#### I/O 接口的基本结构

I/O 接口内部可分为两部分：连接总线的**总线接口**（必须按总线标准设计，属标准部分）和连接设备的**内部接口**（因设备而异，属非标准部分）。不论何种接口，一般都应包含下列部件：

1. **数据缓冲寄存器（DBR，数据端口）**：输入时存放从设备读来的数据等待 CPU 取走，输出时暂存 CPU 送来的数据等待送往设备。
2. **设备状态寄存器（状态端口）**：反馈设备状态，如**设备忙、设备就绪、设备错误**等。程序查询方式中 CPU 正是反复读它来判断设备状态。
3. **设备命令寄存器（控制寄存器，控制端口）**：接收 CPU 发来的设备控制命令，如设备复位、设备识别、读写控制、启动/停止。简单设备（如普通键盘、字符终端）可能根本没有命令寄存器。
4. **设备存储器**（非必需）：供设备自身运算和处理使用，如显卡中的显存。
5. **地址译码器和 I/O 控制逻辑**：接收地址线和控制线送来的信息，对控制寄存器中的**命令字**译码，把控制信号送到外设侧；同时把数据缓冲寄存器的数据送到外设或从外设接收数据；还要**收集外设状态到状态寄存器**。
6. **中断控制逻辑**：产生中断请求、接收中断响应、提供中断类型号（向量中断方式下），并参与中断屏蔽判断。

:::key 状态寄存器与控制寄存器为何常合二为一
**状态寄存器和控制寄存器在传送方向上是相反的**（状态字由接口送往 CPU，是读；命令字由 CPU 写入接口，是写），而且 CPU 对它们的访问在时间上一般是错开的，所以很多接口把二者合并成同一个寄存器，**通过读、写方向来区分**。这就是真题里「状态端口和控制端口可以合用同一个寄存器」这一说法的来源。
:::

#### 接口三组总线各传什么

与 I/O 接口相连的数据线、地址线、控制线都是双向的（因为 DMA 方式下接口本身也能当主设备），但传送内容不同：

- **数据线**：真正的 I/O 数据（经数据缓冲寄存器）、CPU 写入命令寄存器的**控制字/命令字**、CPU 从状态寄存器读出的**状态字**。
- **地址线**：I/O 端口或设备寄存器的地址（CPU 在访问时给出，由接口内的地址译码器识别并选中寄存器）；DMA 方式下接口作为主设备发出的**主存地址**。
- **控制线**：总线控制命令与时序信号（读/写、时钟）、总线控制权协商信号（DMA 请求）、应答信号、中断响应信号。

:::warn 「命令字走数据线」与「控制信号走控制线」不是一回事
CPU 向接口控制寄存器写入命令字时，命令字是一组**二进制数据值**，它在**数据总线**上传送；而读/写控制信号、握手信号是**控制信号**，在**控制总线**上传送。前者是「要做什么」（What），后者是「现在执行读还是写、什么时候有效」（How/When）。2011 与 2012 年都考过这个区分。
:::

### I/O 端口及其编址

把接口中 CPU 可访问的寄存器统称为 **I/O 端口（I/O port）**：数据缓冲寄存器简称**数据端口**，状态寄存器简称**状态端口**，控制寄存器简称**控制端口**。所有 I/O 端口编号组成的空间称为 **I/O 地址空间**。

访问这些端口的指令称为 **I/O 指令**（如 IA-32 的 `in`、`ins`、`out`、`outs`）。I/O 指令只能在操作系统内核的底层 I/O 软件中使用，因此**I/O 指令是特权指令**。

:::exam I/O 指令传送的是什么
I/O 指令由 CPU 执行，典型功能是「**通用寄存器 ↔ I/O 端口**」之间的数据传送。设备与端口之间的交换由接口电路和设备控制逻辑完成；CPU 的通用寄存器不会绕过接口直接连外设。所以「I/O 指令实现的数据传送发生在**通用寄存器和 I/O 端口之间**」是正确的。
:::

#### I/O 端口的两种编址方式

| 对比项 | **统一编址**（存储器映射编址） | **独立编址**（I/O 映射方式） |
|---|---|---|
| 概念 | 把 I/O 端口当成主存单元一样统一编址 | I/O 端口地址与存储器地址无关，各自独立 |
| 访问指令 | **不需要专门的 I/O 指令**，用普通访存指令（LOAD/STORE）即可读写端口 | 必须使用**专门的输入输出指令**（如 x86 的 IN/OUT） |
| 优点 | ① 端口编址空间大；② 读写控制逻辑简单；③ I/O 访问与主存访问共用一组指令，**保护机制可由分段/分页存储管理实现，无需专门保护机制** | ① 用专用 I/O 指令，程序清晰、便于编程；② **I/O 端口地址位数少，地址译码速度快**；③ **I/O 端口地址不占用主存地址空间** |
| 缺点 | ① **端口占用了主存地址空间，主存地址空间变小**；② 外设寻址时间长（地址位数多、译码慢） | ① I/O 指令类型少，一般只能对端口传送，程序设计灵活性差；② **需要 CPU 提供存储器读/写与 I/O 读/写两组控制信号**，增加控制逻辑复杂性 |
| 如何区分访问对象 | **通过地址码区分**（按地址范围判断是主存还是端口） | **通过不同指令区分**（I/O 指令的地址码给出端口号，不同指令产生不同的总线控制信号） |
| 典型处理器 | MIPS、ARM 等 RISC 处理器 | Intel x86 处理器 |

:::warn 统一编址与独立编址的两个反向陷阱
1. 「采用**独立编址**时，I/O 端口地址和主存地址**可能相同**」——正确。两者用不同地址空间，数值上重叠是允许的，靠指令（及相应的总线控制信号）来区分。
2. 「采用**统一编址**时，CPU **不能**用访存指令访问 I/O 端口」——**错误**。统一编址又称存储器映射 I/O，CPU 正是通过**普通访存指令**访问 I/O 端口。
:::

:::warn 统一编址的端口不能被 Cache 缓存
I/O 地址虽然映射到主存空间，但接口中的数据是**动态变化的**。若把端口内容放进 Cache，CPU 读到的就可能是过时副本，无法了解设备的实时状态变化。所以映射到主存空间的 I/O 区域必须标记为不可缓存。
:::

## I/O 方式

I/O 方式的发展主线是「**尽量减少主机对 I/O 控制的干预**」。从程序查询（CPU 全程参与）到程序中断（CPU 只在数据就绪时参与），再到 DMA（CPU 只做预处理和后处理），CPU 的参与度逐级降低，数据传输单位从「字节/字」变为「数据块」。

### 程序查询方式

**程序查询方式（程序直接控制方式）**：I/O 完全依靠 CPU 执行程序实现。CPU 要与设备交换数据时，先设置接口命令寄存器启动设备；设备准备期间，CPU **反复读取接口中的状态寄存器**查询设备是否就绪，据此决定是进行数据传送还是继续等待。反复查询的过程称为**轮询（polling）**。字符设备一次轮询传一个字节或字，块设备一次轮询可传一个数据块。

**基本查询流程（以有命令寄存器的复杂设备为例）：**

1. 读状态端口，判断设备是否就绪；未就绪则继续查询；
2. 就绪后，向控制端口写入命令与参数（写端口地址、传送长度、传送方向等），**启动设备**；
3. 再次不断查询状态端口，等待「命令执行完毕/数据就绪」；
4. 就绪后通过数据端口完成一次数据传送；
5. 若是成块传送，修改内存地址与计数器，回到第 3 步循环。

**两种查询策略：**

- **独占查询（忙等待，busy-waiting）**：启动设备后就一直查询状态寄存器直到设备就绪，期间 CPU 不能执行其他任务。一次轮询只传一个数据单元。适用于**单任务操作系统**；对**超高速设备**也可以接受（设备响应快，等待时间极短）。
- **定时查询**：CPU 启动设备的同时启动一个定时器，设备准备期间 CPU 不忙等而是继续工作，定时时间到产生定时中断，在中断服务程序中查询设备状态。缺点是**定时时间难以确定**：过短则数据未就绪白查，过长则数据已就绪却得不到及时处理。适用于**外设不支持中断的多任务系统**。

#### 查询方式下的 CPU 时间开销

核心思想：**开销 = 每秒查询次数 × 每次查询的 CPU 时间**。

$$T_{\text{CPU占空比}} = \frac{n_{\text{查询次数/秒}} \times t_{\text{每次查询}}}{1\text{ s}}$$

其中每秒查询次数由设备的数据率和每次传送的单位决定：

$$n_{\text{查询次数/秒}} = \frac{\text{设备数据传输率}}{\text{每次传送的字节数}}$$

每次查询耗时 $t$ 可以由「查询程序的时钟周期数 × 时钟周期」得到，也可以由「指令条数 × CPI × 时钟周期」得到。

:::exam 算例 1（定时查询开销，2011 年统考）
处理器主频 50 MHz，采用定时查询方式控制设备 A。查询程序运行一次至少用 **500 个时钟周期**；设备 A 工作期间为不丢数据每秒**至少查询 200 次**。求 CPU 用于设备 A 的 I/O 时间占整个 CPU 时间的百分比至少是多少。

每秒用于查询的时钟周期数 $= 200 \times 500 = 100\,000 = 0.1\text{ M}$；CPU 每秒共 $50\text{ M}$ 个时钟周期：

$$\frac{0.1\text{ M}}{50\text{ M}} = 0.2\%$$

也可以先算一次查询耗时 $500 / 50\text{ MHz} = 10\ \mu\text{s}$，每秒查询 200 次共占 $2\text{ ms}$，$2\text{ ms}/1\text{ s} = 0.2\%$，结果一致。
:::

:::exam 算例 2（查询间隔与开销，2018 年统考第 43 题第 1 问）
计算机主频 500 MHz，CPI 为 4，设备 A 的数据传输率为 2 MB/s，接口有 32 位数据缓冲寄存器，每次输入/输出至少执行 10 条指令。

**（1）最多间隔多长时间查询一次才不丢数据？**

设备准备一个 32 位（4 B）数据的时间为

$$t = \frac{4\text{ B}}{2\text{ MB/s}} = 2\ \mu\text{s}$$

超过 2 μs 不查，缓冲区数据未取走而新数据又到来，就会**覆盖丢失**，所以**最多每隔 2 μs 查询一次**。

**（2）CPU 用于设备 A 输入输出的时间占 CPU 总时间的百分比至少是多少？**

每次输入/输出需要 $10 \times 4 = 40$ 个时钟周期；每秒查询次数 $= 1\text{ s} / 2\ \mu\text{s} = 5\times10^5$ 次：

$$\frac{40 \times 5\times10^5}{500\times10^6} = \frac{2\times10^7}{5\times10^8} = 4\%$$
:::

:::exam 算例 3（查询方式对高速设备不可行的量化，袁春风教材例题的口径）
查询程序每次操作至少 400 个时钟周期，处理器主频 500 MHz。求三种设备下查询开销占比。

- 鼠标：每秒至少查询 30 次 → $\dfrac{30\times400}{500\times10^6} \approx 0.002\%$，可忽略。
- 软盘：16 位（2 B）为单位，50 kB/s → $\dfrac{50\text{ kB/s}}{2\text{ B}} = 25\text{ k}$ 次/秒 → $\dfrac{25\times10^3\times400}{500\times10^6} = 2\%$，偏高但尚可忍受。
- 硬盘：16 B 为单位，4 MB/s → $\dfrac{4\text{ MB/s}}{16\text{ B}} = 250\text{ k}$ 次/秒 → $\dfrac{250\times10^3\times400}{500\times10^6} = 20\%$，CPU 五分之一的时间用于查询，**不可取**。

结论：**设备越快、每次传送单位越小，查询方式的开销越大**，因此查询方式不适合高速成块传送。
:::

:::warn 「程序查询只适合慢速设备」不严谨
中断方式有额外开销（两次上下文切换 + 中断服务程序本身）。当设备准备数据的时间比这些开销还短时，用中断反而比忙等待轮询效率更低（中断成为瓶颈）。因此**程序查询方式并不一定只适合慢速设备**，一些高速设备（如 NVMe SSD 处理同步 I/O）也采用轮询方式。
:::

### 程序中断方式

#### 中断的基本概念

**中断（interrupt）**是指 CPU 在执行程序过程中，出现某些**来自 CPU 外部**的、与当前指令执行**无关**的紧急事件，CPU 暂停现行程序，转去执行相应的处理程序，处理完后返回断点继续执行。**异常（exception）**则是指令执行过程中在处理器内部发生的、与当前指令**同步相关**的特殊事件。

:::key 中断与异常的判定标准
判断依据是「**事件是否与当前指令同步相关**」，而不是名称里有没有「存储」「I/O」字样：
- 与当前指令同步 → **异常**（内部异常）：整数除以 0、访存缺页、存储保护错、非法指令。
- 与当前指令无关、来自 CPU 外部 → **中断**（外部中断）：DMA 传送结束、打印机缺纸、I/O 完成、时钟中断、电源故障。

注意区分：外部中断在**当前指令执行结束后**检测；异常在**当前指令执行过程中**检测。
:::

外部中断分为：

- **可屏蔽中断**：通过 `INTR` 线请求，受中断允许位（IA-32 中是 `EFLAGS` 的 `IF`）控制，**CPU 处于关中断状态时不会被响应**；优先级最低。
- **不可屏蔽中断（NMI）**：通过 `NMI` 线请求，用于电源掉电、硬件故障等紧急事件，**不受中断允许位和中断屏蔽字控制，关中断状态下也能响应**，优先级最高。NMI 的中断向量号通常固定，响应时不需要从外部读中断类型号。

**中断源的记录与判优。** 每个中断源设一个**中断请求标记触发器**，状态为 1 表示有请求；这些触发器可组成**中断请求标记寄存器**，可集中在 CPU 中，也可分散在各中断源中。CPU 在**每条指令执行的最后时刻自动检测中断请求引脚**，发现请求后按优先级决定是否响应、响应哪个。

**中断判优（中断响应优先级）**依据「该中断源若得不到及时响应，致使机器工作出错的严重程度」确定：

1. **不可屏蔽中断 > 内部异常 > 可屏蔽中断**；
2. 内部异常中，**硬件故障 > 软件中断**；
3. **DMA 中断请求优先于 I/O 设备传送的中断请求**；
4. I/O 传送类中断中，**高速设备优先于低速设备，输入设备优先于输出设备，实时设备优先于普通设备**。

判优可用**硬件**（链式排队器、中断控制器中的优先级编码器）或**软件**（按优先级从高到低逐级查询各中断源）实现。软件判优硬件简单、优先级可通过改变查询顺序灵活调整，但速度慢，可能无法实时响应。

:::warn 中断排队不是「先来先服务」
「中断控制器按所接收中断请求的**先后次序**进行中断优先级排队」是**错误**的。中断排队依据**预设的优先级**（固定优先级或轮询优先级），不是按请求到达的时间先后。
:::

#### 中断响应过程

**CPU 响应中断必须同时满足三个条件：**

1. **至少有一个未被屏蔽的中断请求**（中断请求触发器置 1，并已送排队器判优）；
2. **CPU 允许中断且处于开中断状态**（中断允许触发器 `EINT` = 1；**异常和不可屏蔽中断不受此限制**）；
3. **当前指令执行完毕**（外部中断，异常不受此限制），且没有更紧急的任务。

:::warn 三个条件里的常见错误说法
- 「一旦可屏蔽中断请求信号有效，CPU 将立即响应」——**错误**。请求有效 ≠ 立即响应，还要等当前指令结束、且处于开中断状态、且未被屏蔽。
- 「有中断请求时，CPU 立即暂停当前指令执行」——**错误**。CPU 不会打断正在执行的指令（这会破坏指令的原子性），只在指令边界响应。
- 「仅在用户态下 CPU 才能检测和响应中断」——**错误**。内核态下只要开中断且优先级条件满足，同样可以响应（这正是多重中断嵌套的基础）。
:::

CPU 响应中断后进入**中断响应周期**。该周期内的操作由**硬件直接实现**，称为**中断隐指令**。中断隐指令**不是指令系统中一条真正的指令**，只是「硬件自动完成的一系列操作」的虚拟说法。它完成的操作是：

1. **关中断**：置中断允许位为 0，屏蔽所有可屏蔽中断。目的是保证断点和现场在被完整保存之前不被新的中断打断。IA-32 中可通过特权指令 `sti`/`cli` 置位/清位 `IF`。
2. **保存断点**：把**指令无法直接读取**的 `PC` 和 `PSW`（程序状态字寄存器）内容**自动保存**到**栈或特定寄存器**中。断点一般是**下一条指令的地址**；但对异常则不一定——「缺页故障」的断点是发生页故障的**当前指令地址**（处理完要重新执行该指令），「陷阱」的断点是陷阱指令**后面一条指令**的地址。**断点与异常类型有关。**
3. **形成中断服务程序入口地址并送 PC**（**引出中断服务程序 / 中断源识别**）：若是特权级切换（用户态→内核态），硬件还会自动完成**用户栈到内核栈的切换**。

:::exam 中断隐指令到底做了哪些事
统考原题（2012 年）：响应外部中断的过程中，中断隐指令完成的操作，除保护断点外，还包括 —— 正确答案是 **Ⅰ 关中断** 与 **Ⅲ 形成中断服务程序入口地址并送 PC**；**Ⅱ「保存通用寄存器的内容」不属于中断隐指令**，那是进入中断服务程序后由软件完成的第一件事。

口诀：**中断隐指令 = 关中断 + 保护断点（PC/PSW）+ 找入口（中断源识别）**。
:::

**中断源的识别方式**有两种：

- **软件识别**：CPU 中设**原因寄存器（Cause）**记录异常原因或中断类型标志，操作系统用一个统一的查询程序按优先级顺序查原因寄存器，先查到的先处理。
- **硬件识别（向量中断方式）**：处理程序的首地址 PC 和初始 PSW 称为**中断向量（interrupt vector）**，所有中断向量集中存放构成**中断向量表**。每个中断源有唯一**中断类型号**，中断向量位置与类型号相关（类型 0 存第 0 表项，类型 1 存第 1 表项……）。也**由 CPU 外部的中断控制器**根据各 I/O 设备的中断请求和中断屏蔽情况，结合中断响应优先级，识别当前请求的中断类型号，并通过**数据总线**送到 CPU。

CPU 获得中断类型号后，据此计算**中断向量地址（VA）**，从向量表中取出中断服务程序入口地址送 PC，转去执行中断服务程序。

#### 中断处理过程

中断服务程序（软件）的执行流程，完整版（支持多重中断）为：

1. **关中断**（已由中断隐指令完成）；
2. **保存断点**（已由中断隐指令完成，保存 PC 和 PSW）；
3. **保存现场和旧屏蔽字**：现场信息指**用户可见的工作寄存器（通用寄存器等）**的内容，通过压栈指令保存，**由软件实现**；中断屏蔽字寄存器虽用户不可见，也由操作系统一并保存；
4. **设置新屏蔽字**（由 I/O 指令访问中断控制器完成）；
5. **开中断**：允许更高级中断请求得到响应，**实现中断嵌套**；
6. **执行中断服务例程**：这是中断请求的真正目的，如程序 I/O 中的数据输入/输出；
7. **关中断**：保证恢复现场和屏蔽字时不被中断；
8. **恢复现场和旧屏蔽字**；
9. **开中断**；
10. **中断返回**：最后一条指令通常是**中断返回指令 IRET**，返回到原程序断点继续执行。

对于**单级中断（不允许嵌套）**，去掉第 4、5 步和第 7、9 步中与开/关中断相关的部分，流程简化为：**保护现场 → 中断事件处理 → 恢复现场 → 开中断 → 中断返回**。

:::key 硬件做什么、软件做什么——一条界线
**硬件（中断隐指令）**：关中断、保存断点（PC、PSW）、中断源识别与引出服务程序、特权级与堆栈切换。
**软件（中断服务程序）**：保存通用寄存器等现场、设置新屏蔽字、执行服务操作、恢复现场与屏蔽字、中断返回。

记住这条界线，2018、2024 那类「谁负责保存什么」的题就不会错。：
- 2015 年统考：「处理外部中断时，应该由**操作系统**保存的是」→ 答案是**通用寄存器的内容**（PC 由硬件保存，TLB 和 Cache 内容不需要在单次中断中专门保存）。
- 2024 年统考：「保存断点和程序状态字在中断响应阶段完成」正确；「保存通用寄存器和设置新中断屏蔽字由软件实现」正确。
:::

**`IRET` 指令执行时完成的工作**：① 从内核栈弹出 `EIP`、`CS`、`EFLAGS`，恢复断点和程序状态；② 检查当前处理程序的 CPL 是否等于 CS 中最低两位，若相等说明中断前后处于同一特权级，`IRET` 结束；否则继续下一步；③ 从内核栈弹出 `SS` 和 `ESP`，恢复中断前的栈，即由内核态改回用户态并完成堆栈切换。执行完 `IRET`，CPU 自然回到被中断的进程继续执行。

:::warn 为什么断点要保存到栈里
为支持**异常或中断的嵌套**处理，大多数处理器把断点保存在**栈**中（如 80x86）。如果系统**不支持多重中断嵌套**，可以把断点保存在**特定寄存器**中而不必送栈（如 MIPS 用 `EPC` 寄存器专门存放断点），后者开销更小——因为访问栈就是访问存储器，比访问寄存器慢。
:::

#### 多重中断和中断屏蔽

- **单重中断**：CPU 在执行中断服务程序过程中，又出现新的更高优先级的中断请求，但 CPU **不予响应**，这就是单重中断。此时 CPU 在中断处理期间**一直处于关中断状态**。
- **多重中断（中断嵌套）**：CPU **暂停现行的中断服务程序**，转去处理新的中断请求。此时中断处理期间 CPU **并非始终关中断**——在保护好现场并设置新屏蔽字后会重新开中断。

**CPU 要具备多重中断功能，必须满足两个条件：**

1. 在中断服务程序中**提前设置开中断指令**；
2. **优先级别高的中断源有权中断优先级别低的中断源**。

**中断处理优先级与中断屏蔽。** 这里要区分两个不同概念：

| 对比项 | **中断响应优先级（中断判优）** | **中断处理优先级（中断屏蔽）** |
|---|---|---|
| 由谁决定 | 由**中断查询程序**或**硬件判优电路**决定，反映多个中断**同时请求**时哪个先被响应 | 由各自的**中断屏蔽字**（屏蔽字寄存器内容）**动态设定**，反映本中断与其他所有中断之间的处理优先关系 |
| 可否修改 | 响应优先级往往是硬件线路已设置好，**不便于改动** | 在多重中断系统中通常用**中断屏蔽字动态分配**，可在程序中执行 I/O 指令修改屏蔽字内容即可改变处理次序 |
| 生效时机 | **只**在当前无正在执行的中断、需要从队列中判优选择时使用 | **任何时刻立即生效**：一出现处理优先级更高的中断就立即响应并抢占 |
| 队列含义 | 队列中存放的是未被响应的中断，它们的处理优先级一定都比正在执行的中断低（否则早就抢占了） | 当处理优先级高的中断都执行完毕，中断返回**最初状态**，再从队列中取响应优先级最高的给予响应 |

**如果不使用中断屏蔽技术，处理优先级与响应优先级相同。**

**屏蔽字的设置规律：**

1. 一般用 **1 表示屏蔽，0 表示正常申请**；
2. 每个中断源对应**一个**屏蔽字（在处理该中断源的中断服务程序时，屏蔽字寄存器中的内容就是该中断源对应的屏蔽字）；
3. **屏蔽字中 1 越多，优先级越高**；**每个屏蔽字中至少有一个 1**（至少要能屏蔽自身的中断）。

:::exam 算例（屏蔽字计算，2011 年统考）
某计算机有五级中断 $L_4 \sim L_0$，中断屏蔽字为 $M_4M_3M_2M_1M_0$，$M_i = 1$ 表示对 $L_i$ 级中断进行屏蔽。**中断响应优先级从高到低**为 $L_0 \to L_1 \to L_2 \to L_3 \to L_4$；要求**中断处理优先级从高到低**为 $L_4 \to L_0 \to L_2 \to L_1 \to L_3$。求 $L_1$ 的中断处理程序中设置的中断屏蔽字。

**解题步骤：**

1. 写出要求的**处理优先级序列**：$L_4 \to L_0 \to L_2 \to L_1 \to L_3$。
2. 对目标中断 $L_1$：**处理优先级比它高的**允许打断它 → 对应位为 **0**；**它自己以及处理优先级比它低的**要屏蔽 → 对应位为 **1**。
3. 比 $L_1$ 高的有 $L_4$、$L_0$、$L_2$ → $M_4 = 0$、$M_0 = 0$、$M_2 = 0$；本级 $L_1$ 与更低的 $L_3$ → $M_1 = 1$、$M_3 = 1$。
4. 按 $M_4M_3M_2M_1M_0$ 排列：$0\,1\,0\,1\,0 = \mathbf{01010}$。

**关键**：屏蔽字由「**处理**优先级」决定，不是由「响应优先级」决定。题目给响应优先级只是为了增加干扰或后续提问。
:::

:::warn 中断屏蔽字≠响应优先级
「中断屏蔽字用于确定中断响应的优先级」是**错误**说法。响应优先级由硬件排队或优先级判定电路决定；**中断屏蔽字控制的是中断嵌套关系，即处理优先级**。这是 2024 年统考的原题考点。
:::

:::exam 多重中断的其他常见判断
- 「在一条指令执行结束时响应中断」正确；
- 「中断处理期间 CPU 处于关中断状态」在**多重中断**语境下**错误**（服务程序中会重新开中断）；在**单重中断**语境下则正确；
- 「中断请求的产生与当前指令的执行无关」正确（异步性）；
- 「CPU 通过采样中断请求信号检测中断请求」正确；
- 「CPU 处于关中断状态时也能响应 NMI 请求」正确。
:::

#### 中断方式与查询方式的对比

| 对比项 | 程序查询方式 | 程序中断方式 |
|---|---|---|
| CPU 参与方式 | CPU **全程主动轮询**，设备与 CPU **串行**工作 | CPU 启动设备后**继续执行原程序**，设备就绪时主动通知，CPU 与设备**并行**工作 |
| 谁发起数据传送 | CPU 轮询发现就绪后主动传送 | **设备主动**发出中断请求，CPU 被动响应 |
| 数据传送实现者 | CPU 执行查询程序 | CPU 执行**中断服务程序**（软件） |
| CPU 时间开销 | 与**查询次数**成正比，设备越快、传送单位越小开销越大 | 与**中断次数 × 每次中断开销**成正比；额外还有两次上下文切换开销 |
| 实时性 | 依赖查询频率，可能漏掉数据或浪费查询 | 由设备主动触发，实时性好，无需纠结轮询频率 |
| 适用场合 | 单任务系统、超高速设备、操作系统引导阶段 | 键盘、鼠标、针式打印机等**低速字符设备** |

:::warn 中断方式为什么不适合高速设备
设外设准备数据的时间为 $t_{dev}$，中断响应与处理时间为 $t_{int}$。为避免「前一数据未被取走、后一数据又到来造成覆盖」，必须满足

$$t_{dev} \ge t_{int}$$

即**外设准备数据的时间应不小于中断响应和处理时间**。「外设准备数据的时间应**小于**中断处理时间」是**错误**说法（2022 年统考考点）。设备越快，$t_{dev}$ 越小，而 $t_{int}$ 由几十到上千个时钟周期构成，很快就无法满足，因此高速设备应改用 DMA。
:::

#### 中断方式下的 CPU 开销与效率计算

$$T_{\text{CPU占空比}} = \frac{n_{\text{中断次数/秒}} \times C_{\text{每次中断时钟周期数}}}{f_{\text{CPU}}}$$

其中中断次数由设备数据率和**每次中断传送的数据量**决定：

$$n_{\text{中断次数/秒}} = \frac{\text{设备数据传输率}}{\text{每次中断传送的字节数}}$$

每次中断的时钟周期数 $C$ 通常由「中断响应周期数 + 中断服务程序指令数 × CPI + 其他开销」给出。

:::exam 算例 1（中断开销，2019 年统考）
设备以中断方式与 CPU 交换数据，CPU 主频 1 GHz，接口中数据缓冲寄存器为 32 位，设备数据传输率 50 kB/s，每次中断开销（含中断响应和中断处理）为 1000 个时钟周期。求 CPU 用于该设备 I/O 的时间占整个 CPU 时间的百分比**最多**是多少。

每次中断最多传送 32 位 = 4 B：

$$n = \frac{50\text{ kB/s}}{4\text{ B}} = 12.5\text{ k 次/秒}$$

每次中断耗时 $= 1000 / 1\text{ GHz} = 1\ \mu\text{s}$，每秒中断开销时间 $= 12.5\times10^3 \times 1\ \mu\text{s} = 12.5\text{ ms}$：

$$\frac{12.5\text{ ms}}{1\text{ s}} = 1.25\%$$
:::

:::exam 算例 2（中断 vs DMA 的开销对比，2010 年统考第 43 题）
CPU 主频 500 MHz，CPI = 5。外设数据传输率 0.5 MB/s，**以 32 位为传输单位**，中断服务程序 18 条指令，中断服务的其他开销相当于 2 条指令的执行时间。

**（1）中断方式下 CPU 用于该外设 I/O 的时间占比？**

每次中断的时钟周期数 $= 5 \times 18 + 5 \times 2 = 100$；每秒中断次数 $= 0.5\text{ MB/s} \div 4\text{ B} = 125\,000$：

$$\frac{100 \times 125\,000}{500\times10^6} = \frac{12.5\times10^6}{500\times10^6} = 2.5\%$$

**（2）数据传输率提高到 5 MB/s，改用 DMA，每次 DMA 传送块大小 5000 B，DMA 预处理 + 后处理总开销 500 个时钟周期，CPU 占比？**

每秒 DMA 次数 $= 5\text{ MB/s} \div 5000\text{ B} = 1000$：

$$\frac{1000 \times 500}{500\times10^6} = \frac{0.5\times10^6}{500\times10^6} = 0.1\%$$

同样吞吐量下，中断方式的开销是 DMA 的 **25 倍**，这就是高速设备必须用 DMA 的量化理由。
:::

:::exam 算例 3（中断允许的最大延迟，2014 年统考）
设备中断请求的响应和处理时间为 100 ns，每 400 ns 发出一次中断请求，中断响应所允许的最长延迟时间为 50 ns。求 CPU 用于该设备的 I/O 时间占整个 CPU 时间的百分比**至少**是多少。

$$\frac{100\text{ ns}}{400\text{ ns}} = 25\%$$

**陷阱**：那 50 ns 是「请求可以等待的上限」，等待期间 CPU 可以执行其他工作，**不属于** CPU 用于该设备 I/O 的时间，不能加进分子。这是本题设置 B、C 两个干扰项的原因。
:::

:::exam 算例 4（异步串行中断，2012 年统考第 43 题）
CPU 主频 50 MHz，CPI = 4。设备 D 以异步串行方式向主机传送 7 位 ASCII 字符，规程中有 1 位奇校验位和 1 位停止位，从 D 接收启动命令到字符送入 I/O 端口需要 0.5 ms。I/O 端口每收到一个字符申请一次中断，中断响应需 10 个时钟周期，中断服务程序共 20 条指令。

**（1）每传送一个字符在通信线上共需传输多少位？每秒最多可送多少个字符？**

$1$（起始位）$+ 7$（数据位）$+ 1$（校验位）$+ 1$（停止位）$= \mathbf{10}$ 位。每字符耗时 0.5 ms，故每秒最多 $1000/0.5 = \mathbf{2000}$ 个字符。

**（2）读取 1000 个字符所需时间，以及 CPU 用于该任务的时间（时钟周期数）？**

时钟周期 $= 1/50\text{ MHz} = 20\text{ ns}$。设备送字符到端口的耗时 $= 0.5\text{ ms} / 20\text{ ns} = 2.5\times10^4$ 个时钟周期；一次中断响应 10 个周期；中断服务程序前 15 条指令（第 15 条启动 D 工作）$= 4 \times 15 = 60$ 个周期。

单字符传送时间约 $2.5\times10^4 + 10 + 60 = 25\,070$ 个时钟周期，1000 个字符约

$$1000 \times 25\,070 = 2.507\times10^7\ \text{个时钟周期}$$

CPU 用于该任务的时间（每次响应 + 全部服务指令）$= 1000 \times (10 + 4 \times 20) = 1000 \times 90 = 9\times10^4$ 个时钟周期。

**（3）中断响应阶段 CPU 进行了哪些操作？** 关中断、保护断点和程序状态、识别中断源。
:::

#### 中断方式与 I/O 端口交换的信息

中断 I/O 方式下，CPU 与打印控制接口的 I/O 端口之间**可以**交换：打印字符（写数据端口）、设备状态（读状态端口）、控制命令（写控制端口）。**不可能**交换的是**主存地址**——数据由 CPU 通过指令搬运，接口不直接访问主存，不关心数据来自内存何处；主存地址是 DMA 控制器必须掌握的信息。

### DMA 方式

#### DMA 的基本概念

**直接内存访问（Direct Memory Access，DMA）**：在总线上设置 **DMA 控制器（DMAC）**，由 DMAC 临时接管总线，代替 CPU 控制外部设备与内存之间的**批量**数据交换。**数据无须由 CPU 寄存器中转**，完全消除了程序查询和程序中断方式中 CPU 进行实际数据传输的开销。

DMA 的工作轮廓是：

1. 传送前 CPU 访问 DMAC 接口，设置**主存地址、数据块长度、传输方向**等参数；
2. CPU 向设备的 I/O 接口发送命令和参数，**启动设备**；
3. 传输过程中 CPU 继续执行其他程序；设备需要传送时由 **DMAC 向 CPU 申请总线控制权**完成传输；
4. 一个数据块传送结束后，DMAC 通过**中断**方式请求 CPU 对缓冲区和 DMAC 进行**后处理**。

DMA **主要用于高速设备的块数据传输**（磁盘、显卡、网卡、声卡），也可用于内存之间的大批量数据搬移。

:::key DMA 的三句话概括
1. 请求的是**总线控制权**，不是 CPU 时间；
2. 实际数据传送由**硬件**完成，不由 CPU 执行程序完成，因此**不涉及现场保护**；
3. 传送单位是**数据块**，CPU 只在块传送开始（预处理）和结束（后处理）时参与。
:::

#### DMA 控制器的组成

DMAC 连接在系统总线上，**既可充当从设备（预处理阶段），也可充当主设备（数据传输阶段）**。其基本组成：

| 部件 | 作用 |
|---|---|
| **主存地址寄存器 / 地址计数器 AR** | 存放交换数据的**内存地址**。预处理阶段由 CPU 设置；每次 DMA 传送后**自动修改**（递增或递减），指向下一个内存单元 |
| **字计数器 WC** | 记录数据块长度。预处理阶段设置；每传送 1 个字或字节**自动减 1**；减到 0 时数据传送完毕，**发出 DMA 中断请求** |
| **数据缓冲寄存器 DBR** | DMAC 作从设备时接收 CPU 传来的数据，作主设备时暂存传输数据。若不经该寄存器而让数据直接经数据总线从设备到内存，则性能更好 |
| **命令寄存器 / 控制寄存器** | 接收 CPU 的控制命令（启动 DMA、传输方向、工作方式等） |
| **状态寄存器** | 向 CPU 反馈 DMAC 的状态（传输完成、发生错误及错误类型） |
| **DMA 控制逻辑（含中断机构）** | 含控制与时序电路、状态标志；负责修改地址计数器和字计数器、指定传输方向、对 DMA 请求与 CPU 响应进行协调和同步；**还支持中断机制**，一组数据交换完毕时向 CPU 发 DMA 中断请求 |

**握手信号：**

- DMAC 需要总线控制权时，通过系统总线中的 **HOLD（总线请求）** 信号向 CPU 发出请求；CPU 的总线控制器若允许，回送 **HLDA（总线响应/授权）** 信号。
- 支持 DMA 的 I/O 设备通过 **DREQ（DMA 请求）** 与 **DACK（DMA 应答）** 两条**专用控制线**与 DMAC 相连。这两条线**通常不属于系统总线**，而是 DMAC 与 I/O 接口之间的私有通道。
- 一个 DMAC 支持多个通路，每个通路各有独立的主存地址寄存器和字计数器，可同时为多个设备提供 DMA 服务。

:::key DMAC 的角色在换
- **预处理阶段**：CPU 是主设备，DMAC 是**从设备**（CPU 像访问普通 I/O 端口一样用 `OUT` 等指令写 DMAC 的寄存器）。
- **数据传输阶段**：DMAC 是**主设备**，CPU 变成旁观者。
:::

:::warn DMAC 连接的对象是「设备控制器」而不是「设备」
物理设备（硬盘、网卡）需要专门的设备控制器处理底层协议、时序与数据缓冲；DMAC 是通用的「搬运工」，无法直接理解成千上万种设备的具体细节。所以 **DMAC 沟通的对象应该是设备控制器（I/O 接口）**，而不是设备本体。同理，「DMAC 与设备之间」也不是数据传输通路的端点。
:::

#### DMA 传送过程

**（1）预处理阶段**

1. CPU 通过 **I/O 指令**把参数写入 DMAC：**主存地址寄存器 AR**（数据在主存的起始地址）、**字计数器 WC**（要传送的数据总量）、**控制/命令寄存器**（传输方向：设备→内存还是内存→设备）。
2. CPU 向 **I/O 接口（设备控制器）** 发送启动命令，命令中包含设备地址、磁盘扇区号等信息，写入设备控制器自己的寄存器（如设备地址寄存器 DAR）。
3. CPU 向 DMAC 控制寄存器写入「**启动 DMA**」命令位，然后**把发起 I/O 请求的进程挂起（阻塞）**，调度另一个就绪进程投入运行。

预处理结束时：DMAC 已掌握本次任务的所有细节，I/O 设备已开始准备数据，CPU 已完全脱身，**CPU 与 I/O 操作实现并行**。

**（2）数据传送阶段**（以周期挪用为例，本质是一个循环，每次循环传一个字）

1. **设备就绪，发出请求**：I/O 设备准备好一个数据字放入内部缓冲寄存器后，通过 `DREQ` 向 DMAC 发出 DMA 请求。
2. **DMAC 申请总线**：DMAC 通过 `HOLD`（或 `BREQ`）向 CPU 发出**总线请求**。
3. **CPU 授权总线**：CPU 在**当前机器周期（或总线事务/总线周期）结束后**响应，断开自己与总线的连接（总线驱动器进入高阻态），发出 `HLDA`。
4. **DMAC 主导数据传输**（在一个存储周期内完成）：把 **AR** 中的地址送上**地址总线**；向**控制总线**发出相应控制信号（如存储器写 `MEMW`、I/O 读 `IORD`）；通过 `DACK` 回应发出请求的设备；I/O 接口把数据字放上**数据总线**；主存的存储控制器把数据写入指定单元。
5. **更新状态并归还总线**：**AR 自动加 1（或减 1）**，**WC 自动减 1**；DMAC 撤销 `HOLD`，**立即把总线控制权归还 CPU**。CPU 可继续执行若干周期，直到下一次 `DREQ` 到来——这就是「周期窃取」的精髓。

循环直到 **WC 减为 0**，DMAC 通过 `INTR` 向 CPU 发出**中断请求**，数据传输阶段结束。

**（3）后处理阶段**

1. DMAC 通过 `INTR` 发出中断请求（触发原因：正常完成——WC 递减至 0；或异常中止——内存校验错、设备无响应等）。
2. CPU 响应中断、保存现场、转入中断服务程序。
3. CPU 通过 I/O 指令读取 DMAC 的**状态寄存器**，检查「传输完成」标志、「发生错误」标志及错误类型。
4. 根据状态决策：传输成功则**唤醒因 I/O 请求而阻塞的进程**；传输出错则做错误处理（重传、报错、终止任务）。
5. 中断返回，CPU 继续原程序。

:::key DMA 传送的三段与 CPU 的两次介入
**预处理**（CPU 设置参数 + 启动设备）→ **数据传送**（DMAC 硬件全权搬运，CPU 不参与）→ **后处理**（CPU 执行中断服务程序收尾）。

CPU 只在**首**（预处理）**尾**（后处理）介入；中间的海量搬运与 CPU 无关。所以 **不存在由 CPU 持续执行的「DMA 传送程序」**——那是 2023 年统考的错误选项。
:::

#### DMA 与 CPU 共享主存的三种方式

DMAC 和 CPU 都要访问主存，为避免访存冲突，常用三种方式：

| 方式 | 基本思想 | 工作过程 | 优点 | 缺点 |
|---|---|---|---|---|
| **停止 CPU 访存**（成组传送） | DMA 优先，一旦开始不传完不罢休 | DMAC 申请总线，CPU 在完成当前指令（或总线周期）后释放总线并**暂停/等待**；DMAC 在**连续多个存储周期**内把整块数据传完；传完归还总线，CPU 恢复 | **控制最简单**（请求、建立、归还只做一次）；**数据传输率最高**，适合大块高速传输 | 传输期间 CPU **无法响应任何中断**，实时性差；即使 CPU 当前不需要访存也被强制暂停，**CPU 时间被浪费** |
| **周期挪用**（周期窃取） | 按需分配，DMA 只在需要时借用**一个**存储周期 | 设备准备好一个字，DMAC 就申请一次总线；CPU 在当前机器周期结束后释放；DMAC 占用**一个**存储周期传完这个字后**立即归还** | CPU 与 DMA **分时交替**使用总线，CPU 不会被长时间阻塞，DMA 响应及时 | 每次搬一个字都要请求/仲裁/归还，有额外开销（整个挪用过程实际可能花 2～5 个存储周期）；若 DMA 与 CPU 同时访存，DMA 优先，CPU 被延缓 |
| **DMA 与 CPU 交替访存** | 把内存工作周期一分为二，各用一半 | 把每个内存工作周期固定划分为 $T_1$、$T_2$ 两段，**强制规定 CPU 只能在 $T_1$ 访存，DMAC 只能在 $T_2$ 访存** | **不需要总线请求**（时间预先分配好），CPU 感觉不到 DMA 的存在，可连续工作 | **硬件代价高**（需要复杂的时钟与内存控制逻辑）；**资源浪费**——某一方空闲时它的时间片就浪费了，**实质上使内存总带宽减半**；实际应用很少 |

:::warn 周期挪用不是一个块传完才还总线
「周期挪用方式下，在整个数据块传送过程中 CPU 不可以访问主存储器」是**错误**说法。周期挪用只在**需要传送数据时**窃取相应的存储周期，相邻两次 DMA 传送之间 CPU 仍可正常访存。只有「停止 CPU 访存」（成组/连续传送）方式下，CPU 才会在整个数据块传送期间被禁止访问主存。这正是 2020 年统考 512 B / 32 位缓冲寄存器那道题的正确选项与错误选项的分界。
:::

:::key 周期挪用与访存冲突
DMA 操作**不会修改 CPU 寄存器**，所以**不存在现场保护问题**。若周期挪用期间 CPU 不访问内存，则对 CPU 执行**没有性能影响**；若恰好也访问内存（形成访存冲突），则 **DMA 优先访问内存**——因为若 DMA 请求得不到及时响应，I/O 传输的数据可能丢失。周期挪用已成为 DMA 传输方式的主要方法。
:::

:::exam 算例（周期挪用的请求次数，2012 年统考第 43 题第 2 问）
CPU 主频 80 MHz，CPI = 4，平均每条指令访存 1.5 次，主存与 Cache 之间块大小 16 B，Cache 命中率 99%，存储器总线宽度 32 位。

**（1）MIPS 数与每秒 Cache 缺失次数？**

MIPS $= 80\text{ M} / 4 = 20$。每秒 Cache 缺失次数 $= 20\text{ M} \times 1.5 \times (1 - 99\%) = 300\,000$ 次/秒。

**（2）Cache 缺失时主存带宽需求？**

$16\text{ B} \times 300\,000/\text{s} = 4.8\text{ MB/s}$。

**（3）缺页时磁盘接口每秒发出的 DMA 请求次数至少是多少？**

缺页率 $0.0005\%$，故每秒缺页异常 $= 300\,000 \times 0.0005\% = 1.5$ 次。
页面大小 4 KB = 4096 B，磁盘 I/O 接口的数据缓冲寄存器 32 位 = 4 B，每传 4 B 发一次 DMA 请求：

$$1.5 \times \frac{4096}{4} = 1.5 \times 1024 = 1536\ \text{次/秒}$$

**（4）CPU 与 DMA 同时要求使用存储器总线时谁优先？为什么？**

**DMA 优先级更高**，因为若 DMA 请求得不到及时响应，I/O 传输的数据可能丢失。
:::

:::exam 算例（一个扇区读写中的总线请求次数，2015 年统考第 43 题第 3 问）
磁盘转速 7200 r/min，扇区 512 B，采用**周期挪用 DMA**，磁盘控制器数据缓冲区大小 64 位。

一个扇区读写中 DMA 控制器发出的总线请求次数 $= 512\text{ B} / 64\text{ b} = 512/8 = \mathbf{64}$ 次。若 CPU 检测到 DMA 请求时也需要访存，**DMAC 仍能获得总线使用权**，因为一旦磁盘开始读写就必须按时完成数据传送，否则会丢数据。
:::

#### DMA 与中断方式的对比

| 对比项 | **程序中断方式** | **DMA 方式** |
|---|---|---|
| **谁请求** | I/O 设备请求 CPU 的**处理时间**（请求 CPU 中断服务） | DMAC 请求**总线使用权**（总线控制权） |
| **谁响应、何时响应** | CPU 在**一条指令执行结束后**检测并响应 | CPU 在**一个总线事务（机器周期/总线周期）结束后**响应并让出总线 |
| **传输单位** | 字节或字（一次中断传一个字） | **数据块**（一次 DMA 传一整块） |
| **数据传送由谁完成** | CPU 执行**中断服务程序（软件）**完成 | **DMAC 硬件**直接控制总线完成，不经 CPU 寄存器 |
| **CPU 干预程度** | 每传一个字节/字都要 CPU 参与，**需保护和恢复现场** | CPU 只在**预处理**（设参数、启动）和**后处理**（结束中断处理）时介入，**不改变 CPU 现场** |
| **优先级** | 较低 | **DMA 请求优先级高于 CPU 访存，也高于普通 I/O 传送中断请求** |
| **功能范围** | 不仅能传数据，还能处理各种**随机事件**（故障、状态变化），灵活性高 | **仅用于数据传输**（也可用于内存间搬移） |
| **适用场合** | 键盘、鼠标、打印机等**低速字符设备** | 磁盘、SSD、网卡、显卡等**高速块设备** |

:::warn DMA 与中断对比题的三个经典错误项
1. 「中断 I/O 方式适用于**所有**外部设备」——错误。高速设备用中断会造成 CPU 开销过大。
2. 「DMA 方式**仅适用于**快速外部设备」——片面。DMA 技术上也用于低速设备，只是不划算（初始化开销大）。
3. 「DMA 方式下通过 **CPU 执行 DMA 传送程序**进行 I/O 操作」——错误。DMA 传送过程不存在 CPU 持续执行的传送程序。
:::

### 三种 I/O 方式的完整对比

| 对比项 | **程序查询方式** | **程序中断方式** | **DMA 方式** |
|---|---|---|---|
| 发起者 | CPU 主动轮询 | 设备主动发中断请求 | 设备/DMAC 向 CPU 申请总线 |
| CPU 与设备关系 | 串行（CPU 忙等） | 并行（CPU 执行原程序） | 并行（CPU 执行其他程序） |
| 数据传送实现者 | CPU 执行查询程序（软件） | CPU 执行中断服务程序（软件） | DMAC 硬件直接控制总线 |
| 传送单位 | 字节/字（或块，但 CPU 全程参与） | 字节/字 | 数据块 |
| CPU 介入时机 | 全程 | 每次数据就绪时 | 仅预处理与后处理 |
| 是否需要现场保护 | 不需要（无切换） | **需要**（保存/恢复现场） | 不需要（不改变 CPU 现场） |
| 请求的资源 | — | CPU 处理时间 | **总线使用权** |
| 响应时机 | 立即（查询到即处理） | 一条指令执行结束后 | 一个总线事务（机器周期）结束后 |
| CPU 开销公式 | $n_{\text{查询}} \times t_{\text{每次查询}}$ | $n_{\text{中断}} \times C_{\text{每次中断}}$ | $n_{\text{DMA块}} \times C_{\text{预/后处理}}$ |
| 数据是否经 CPU 寄存器 | 经过 | 经过 | **不经过** |
| 典型设备 | 单任务系统、引导阶段、超高速同步设备 | 键盘、鼠标、针式打印机 | 磁盘、SSD、网卡、显卡 |
| 优点 | 接口简单，不需额外硬件 | 消除轮询开销，实时性好，可处理随机事件 | CPU 开销极小，吞吐率最高，适合大块高速传输 |
| 缺点 | CPU 浪费严重，效率低 | 每次传送都要 CPU 参与，高速时开销过大 | 需要额外 DMAC 硬件，与 CPU 争用主存 |

## 本章小结表

| 考点 | 必背结论 |
|---|---|
| 总线两特点 | **共享**、**分时**；同一时刻只有**一个主设备**能发送信息 |
| 系统总线三类 | 数据总线（**双向**，宽度 = MDR 位数）、地址总线（**单向**，位数 = MAR 位数，决定 $2^n$ 寻址空间）、控制总线（单根单向、整体双向） |
| 串行 vs 并行 | 并行适合**近距离**（系统总线），串行适合**远距离**（通信总线）；**串行速率可以超过并行** |
| 总线带宽公式 | $BW = \dfrac{W}{8} \times f_{clk} \times k = \dfrac{W}{8}\times f_{work} = \dfrac{D}{T_{bus}} = \dfrac{D \cdot f_{clk}}{m}$ |
| 提高带宽的手段 | 增加总线宽度、提高工作频率、支持突发传送（**复用不能**提速） |
| 时钟频率 vs 工作频率 | $f_{work} = f_{clk} \times$ 单时钟传输次数；DDR 取 2，普通取 1 |
| 总线复用 | 优点：省引脚、提高利用率、降成本；缺点：控制复杂、**性能下降** |
| 突发传送 | 只送一次首地址，连续传多个数据，**期间不释放总线**；提高**有效**数据传输率 |
| 总线带宽 vs 实际传输率 | 带宽是**固有指标**，不受传送方式影响，不含地址/仲裁/准备开销 |
| 同步定时 | 统一时钟；协调简单、速率高；**以最慢设备为标准**、有时钟偏移、不能过长、可靠性不高 |
| 异步定时 | 握手信号，**总线周期长度可变**，可挂不同速度设备；逻辑复杂、速度较慢 |
| 三种互锁 | 速度：不互锁 > 半互锁 > 全互锁；可靠性：全互锁 > 半互锁 > 不互锁 |
| 半同步 | 公共时钟 + **Wait 信号线**；握手信号由时钟边沿采样 |
| 分离事务 | 请求与应答分两段，中间释放总线 → 提高**总线利用率** |
| 集中式仲裁 | 链式查询（3 根线，优先级固定，对故障敏感）；计数器定时查询（优先级可循环）；独立请求（最快，线最多，优先级灵活） |
| I/O 接口非设备 | 磁盘**驱动器**是设备；**控制器/适配器/网络控制器/中断控制器**是接口 |
| 接口三类寄存器 | **数据缓冲寄存器**（数据端口）、**状态寄存器**（状态端口）、**控制寄存器**（控制端口）；状态与控制方向相反，可**合用同一寄存器** |
| 数据线上传什么 | 指令、操作数、命令字、状态字、中断类型号；**握手信号走控制线** |
| 统一编址 | 端口与主存**同一地址空间**，用**访存指令**访问；占用主存空间、寻址慢；**保护机制可复用分页/分段**；端口**不能进 Cache** |
| 独立编址 | 独立地址空间，用**专用 I/O 指令**（x86 IN/OUT）；不占主存空间、译码快；指令类型少、需两组控制信号 |
| I/O 指令 | 传送发生在**通用寄存器 ↔ I/O 端口**之间；是**特权指令** |
| 程序查询 | CPU 与设备**串行**工作；开销 $= n_{\text{查询}} \times t_{\text{每次}}$；查询间隔必须 $\le$ 设备准备一个数据的时间 |
| 定时查询 | 定时器到时查状态；定时过短白查、过长丢数据 |
| 中断响应三条件 | 有**未被屏蔽**的请求；CPU **开中断**（异常和 NMI 不受限）；**当前指令执行完毕** |
| 中断隐指令 | **关中断 + 保存断点（PC/PSW）+ 找服务程序入口**；不清通用寄存器、不保存现场 |
| 断点差别 | 中断断点 = 下一条指令地址；缺页 fault 断点 = 当前指令地址；陷阱断点 = 陷阱指令后一条 |
| 服务程序流程 | 保存现场和旧屏蔽字 → 设置新屏蔽字 → 开中断 → 服务 → 关中断 → 恢复现场和屏蔽字 → 开中断 → 中断返回 |
| 单重 vs 多重 | 单重：处理期间**一直关中断**；多重：设新屏蔽字后**重新开中断**，允许嵌套 |
| 两种优先级 | **响应优先级**由硬件/查询程序定，解决「同时请求先响应谁」；**处理优先级**由**屏蔽字**动态定，决定能否被抢占 |
| 屏蔽字规则 | 1 屏蔽、0 允许；**1 越多优先级越高**；每个屏蔽字**至少一个 1**；由**处理优先级**决定，不是响应优先级 |
| 中断开销 | $T = \dfrac{n_{\text{中断}} \times C_{\text{每次}}}{f_{CPU}}$；须满足 $t_{dev} \ge t_{int}$ 才不丢数据 |
| DMAC 组成 | 主存地址寄存器 AR、字计数器 WC、数据缓冲寄存器 DBR、（命令/状态寄存器）、DMA 控制逻辑（含中断机构） |
| DMA 握手线 | HOLD（DMAC 请求）、HLDA（CPU 授权）；DREQ/DACK 是 DMAC 与 I/O 接口的**专用线**，不属系统总线 |
| DMA 三阶段 | **预处理**（CPU 设参数、启动设备）→ **数据传送**（DMAC 主设备搬运）→ **后处理**（结束中断，CPU 收尾） |
| AR/WC 变化 | 每传一次：AR ±1、WC −1；WC = 0 时发 DMA 中断请求 |
| 停止 CPU 访存 | 简单、速率最高；CPU 全程被暂停、无法响应中断 |
| 周期挪用 | 按需借**一个**存储周期，用完立即归还；CPU 可正常访存（除冲突时 DMA 优先）；挪用过程实际占 2～5 个存储周期 |
| 交替访存 | 时间片对半分配；无需总线请求；硬件复杂、**带宽减半**，实际少用 |
| DMA vs 中断 | 请求总线权 vs 请求 CPU 时间；块 vs 字；总线事务后响应 vs 指令后响应；硬件 vs 软件搬运；不保存现场 vs 保存现场 |

## 易错清单

:::warn 总线和 I/O 章 20 个高频陷阱
1. **并行总线不一定比串行总线快**。串行总线线少、串扰小，可把频率做高，实际速率可超过并行；PCIe、USB 都是串行。
2. **地址总线是单向的，控制总线整体是双向的**。DMA 控制器也能送主存地址，但地址总线的「单向」是指由主设备指向从设备。
3. **MDR 位数 = 数据总线宽度 ≠ 存储字长**；**MAR 位数 = 地址线位数**。
4. **时钟频率 ≠ 工作频率**。DDR 双沿传输时 $f_{work} = 2f_{clk}$；一个总线周期占多个时钟周期时二者又不同。
5. **DDR3-1333 的 1333 已是有效工作频率**，不能再乘 2；QPI 的「每秒传输次数」才是 $f_{clk}\times2$。
6. **总线带宽不考虑地址、仲裁、存储器准备时间**。题目问「实际数据传输率」时要另算，别把两者混用。
7. **地址/数据线复用会加长总线周期，不提高速率**；能提高速率的是加宽、提频、突发传送。
8. **突发传送的总线事务要算上首地址那一个周期**。2012 年那题漏掉地址周期就会算成 40 ns 而不是 50 ns。
9. **同步定时以最慢设备为标准**，所以只适合速度相近的设备；异步定时才能挂不同速度的设备。
10. **异步一次握手完成的是一个总线宽度的数据交换，不是一位**。
11. **全互锁最慢但最可靠，不互锁最快但最不可靠**；半互锁只锁主设备一侧。
12. **中断隐指令只做三件事**：关中断、保存断点（PC/PSW）、引出中断服务程序。**保存通用寄存器由软件做**（2012、2018 年都考过）。
13. **状态端口与控制端口可以合用同一个寄存器**，靠读/写方向区分。
14. **统一编址用访存指令访问端口**，不是「不能用访存指令」；**独立编址时端口地址与主存地址可以数值相同**，靠指令区分。
15. **映射到主存空间的 I/O 端口不能被 Cache 缓存**，否则读到的是过时副本，无法感知设备实时状态。
16. **中断响应优先级 ≠ 中断处理优先级**。屏蔽字改变的是**处理优先级**（能否被嵌套抢占），不是响应优先级（同时请求时先响应谁）。2011、2024 年两次考这个区分。
17. **屏蔽字按「处理优先级」写**：比本级处理优先级高的位写 0（允许打断），本级和更低的写 1。2011 年 $L_1$ 的答案是 01010。
18. **中断服务程序内的顺序**：保存现场 → 服务 → 恢复现场 → 开中断 → 中断返回（单级中断）；题干若限定「中断服务程序内」，就**不要**把硬件负责的关中断、保护断点写进去。
19. **中断方式要求 $t_{dev} \ge t_{int}$**，即外设准备数据的时间**不小于**中断处理时间，否则数据被覆盖丢失。
20. **周期挪用不是整块独占总线**。CPU 在相邻两次 DMA 传送之间仍可访存；只有「停止 CPU 访存」方式才在整个块传送期间禁止 CPU 访存。DMA 与 CPU 冲突时 **DMA 优先**，且 DMA 传送**不需要保护现场**（不修改 CPU 寄存器）。
