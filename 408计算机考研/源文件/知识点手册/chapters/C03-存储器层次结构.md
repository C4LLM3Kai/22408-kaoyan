## 存储器的分类

### 按存储介质分类

存储元件必须有**两个截然不同的物理状态**才能表示 0 和 1。按介质分三类：

| 介质 | 典型器件 | 说明 |
|---|---|---|
| 半导体存储器 | RAM、ROM、寄存器、Cache、SSD、U 盘 | 分 MOS 型与双极型两类；速度最快 |
| 磁表面存储器 | 磁盘（HDD）、磁带 | 靠磁头与磁介质相对运动做电磁转换；非易失；速度慢 |
| 光存储器 | CD-ROM、DVD-ROM | 靠激光在盘面凹坑上读取；非易失 |

:::warn SSD 不是磁盘，CD-ROM 不是 ROM
这是两个一字之差、考频极高的概念：
- **固态硬盘 SSD 是半导体存储器**，基于闪存 Flash 技术，本质属于电可擦除 ROM（EEPROM）。真正的「磁盘」是机械硬盘 HDD。
- **CD-ROM 是光存储器**（属于辅存），不是计算机术语里那个作为半导体芯片的 ROM。CPU 可以直接从 BIOS ROM 中取指执行，但绝不可能直接执行 CD-ROM 里的内容——辅存必须先调入主存。
:::

### 按存取方式分类

| 类型 | 全称 | 存取时间特点 | 典型器件 |
|---|---|---|---|
| **随机存取** RAM | Random Access Memory | **与地址无关**，是常数 | 内存、Cache |
| **顺序存取** SAM | Sequential Access Memory | 取决于信息所在位置；以「记录块」为单位编址 | 磁带 |
| **直接存取** DAM | Direct Access Memory | 先直接定位到区域，再在区域内顺序查找 | 磁盘、光盘 |
| **相联存取** AM/CAM | Associative / Content Addressed Memory | **按内容检索**，不需知道地址 | 快表 TLB、全相联 Cache 的标记比较 |

:::warn 三个反直觉结论
1. **ROM 和 RAM 都采用「随机存取」方式**。虽然习惯上把 ROM 与 RAM 并列，但 ROM 读取任一单元的时间同样与物理位置无关——都是地址译码后定位。区别只在于 ROM 存储区在程序执行中只能读，不能随意改写。
2. **并非所有半导体存储器都按地址访问**。全相联 Cache 的比较器、快表 TLB 是按内容访问（CAM）的，所以「半导体存储器都采用随机存取方式」是错的。
3. **光盘（CD-ROM）属于直接存取**，不是随机存取，也不是顺序存取。
:::

### 按信息可更改性与易失性分类

- **可读可写存储器**：RAM 芯片。
- **只读存储器**：ROM 芯片。名称属于历史遗留，现代 ROM（E²PROM、Flash）都能重写，只是写入慢、**不能随意写**。
- **易失性存储器**：断电后信息消失。RAM、Cache。
- **非易失性存储器**：断电后信息保持。ROM、磁表面存储器、光存储器。

### 按作用与存取速度分类

| 层次 | 实现器件 | 位置与特点 |
|---|---|---|
| **寄存器存储器** | 触发器 | CPU 内部，字长与机器字长相同；速度与 CPU 匹配，容量极小 |
| **高速缓冲存储器 Cache** | **SRAM** | CPU 与主存之间；现代集成于 CPU 内；容量小、价格高 |
| **主存储器 MM** | **主要用 DRAM** | CPU 可直接访问；可与 Cache、辅存交换数据 |
| **辅助存储器** | 磁盘、SSD | **CPU 不能直接访问**；容量极大、速度慢、位价格低 |

:::warn 主存不等于「全是 DRAM」
现代 PC 的主存由 **RAM 区 + ROM 区**组成：RAM 区存放运行中的程序和数据，由 DRAM 实现；ROM 区存放 BIOS 等固化程序，由 ROM 芯片实现。所以「系统的主存都用 DRAM 芯片实现」是错误的。某些嵌入式系统的主存甚至全由 ROM 元件构成。
:::

### 存储器的性能指标

#### 存取时间与存取周期

- **存取时间（Access Time）$T_A$**：启动一次存储器操作到该操作**真正完成**所经历的时间。读、写时间可能不同（DRAM 读慢写快，闪存读快写慢）。
  - 读出时间：从收到有效地址和读命令，到数据稳定地送上数据总线。
  - 写入时间：从收到有效地址、数据和写命令，到数据被可靠写入。
- **存取周期（Memory Cycle Time）$T_C$**：存储器进行两次**独立的、连续的**存取操作之间的**最小时间间隔**。它关注的是连续工作的吞吐能力。

$$T_C = T_A + T_R$$

其中 $T_R$ 为**恢复时间（Recovery Time）**。DRAM 是破坏性读出，读出后必须把数据重写回去并让位线电压复位；地址译码器、读写控制逻辑翻转后也需要时间稳定，这些就是恢复时间的来源。

:::key 存取周期 > 存取时间，用哪个要看清题目
- 问「读一次要多久」「单次访问延迟」→ 用**存取时间 $T_A$**。
- 问「连续读取的最小时间间隔」「最大带宽」「流水线启动下一体的间隔」→ 必须用**存取周期 $T_C$**。
:::

#### 存储器带宽

**存储器带宽（Bandwidth）**：单位时间内存储器能传输的连续最大数据量，单位 B/s、MB/s、GB/s。

$$B_m = \frac{W}{T_C}$$

$W$ 为数据位宽（字节数），$T_C$ 为存取周期。

**算例**：某主存存取周期 50 ns、存取时间 40 ns、数据总线宽 64 位。
- 位宽 $W = 64/8 = 8$ B；连续访问的最小间隔受存取周期约束，取 $T_C = 50$ ns。
- $B_m = 8 \text{ B} / (50 \times 10^{-9}\text{ s}) = 160 \times 10^{6}$ B/s $= 160$ MB/s。
- 题干中的「存取时间 40 ns」是干扰项。

提高带宽有两条路：**缩短 $T_C$**（提高工作频率，如 DDR 代际演进）与**增加 $W$**（双通道/四通道内存，位宽翻倍）。若 $W$ 固定，则带宽的极限就是总线的传输能力，与存储器内部能并行准备多少个字无关。

### 存储器的层次化结构

#### 为什么需要分层

理想存储器要同时满足**容量大、速度快、价格低**，但任何单一技术都做不到：SRAM 快而贵且小，磁盘大而便宜却慢，且 CPU 性能提升速度长期快于存储器，形成「性能鸿沟」。分层存储把不同速度、容量、成本的器件组合成金字塔，使整个系统**速度接近最高层、容量和单位成本接近最低层**。

从 CPU 往外，自上而下：寄存器 → Cache → 主存 → 辅存（磁盘/SSD）→ 远程存储。四条规律：**越往下，访问速度越慢、容量越大、位价格越低、被访问频次越低**。寄存器、Cache、主存统称**内部存储器**，CPU 可直接访问；辅存及以下为**外部存储器**，信息必须先调入主存。

#### 访问与调度规则

- **子集副本原则**：上一层内容是下一层内容的副本。Cache 中的数据在主存中，主存中的数据在辅存中（采用写回策略时，Cache 中的新数据可能暂时还不在主存里）。
- **逐层查找原则**：寄存器 → Cache → 主存 → 辅存。Cache 未命中访主存，主存没有访辅存。
- **数据传送只在相邻两层之间进行**，单位是**定长块**。辅存中找到的数据不能直接送 CPU，必须经历：辅存 → 主存 → Cache → 寄存器/CPU。
- **特例**：CPU 可以和主存直接交换信息（绕过 Cache）；主存是与 Cache、辅存同时打交道的枢纽。

#### Cache-主存层次与主存-辅存层次

| 对比维度 | Cache-主存层次 | 主存-辅存层次 |
|---|---|---|
| 位置与访问权限 | 最靠近 CPU，CPU 可直接访问两者 | CPU 不能直接访问辅存 |
| 引入目的 | **解决速度问题** | **解决容量问题**，形成虚拟存储器 |
| 交换单位 | **主存块 Block**，通常 8～128 B | **页 Page**，通常 4 KB～64 KB |
| 缺失处理 | **硬件**自动完成 | **操作系统（软件）**完成 |
| 映射方式 | 直接、全相联、组相联均可 | 一律**全相联** |
| 映射记录介质 | Cache 行的 Tag 字段 | 主存中的页表 |
| 写策略 | 直写或回写均可 | 一律**回写** |
| 透明性 | 对所有程序员透明 | 对应用程序员透明，**对系统程序员不透明** |

两者有四点共性：都基于**程序访问的局部性**；都要解决**地址映射**；都要解决**替换**；缺失时都要把包含目标信息的块从慢速层调入快速层。

:::warn 缺页代价远大于 Cache 缺失，所以页大、全相联、只回写
主存比 Cache 慢 10～100 倍，辅存比主存慢约 10000 倍。所以：页面远大于主存块（4 KB 对 32 B）；主存-辅存层次必须用**全相联**把冲突缺失降到最低；写操作**只能回写**——每次改主存都同步写磁盘是不可承受的。
:::

### 程序访问的局部性原理

在较短时间间隔内，程序产生的地址往往集中在存储空间的很小范围内，这叫**程序访问的局部性**，是分层存储能生效的全部前提。

- **时间局部性（Temporal Locality）**：某个存储单元在被访问后，短时间内**很可能再被访问**。来源：循环体、循环变量、高频调用的函数。
- **空间局部性（Spatial Locality）**：某个存储单元的**邻近单元**在短时间内很可能被访问。来源：顺序执行的指令、数组的连续元素。

**步长 $k$**：访问连续数组时每隔 $k$ 个元素访问一次。步长为 1 即顺序引用模式，是空间局部性最重要的来源；**步长越大，空间局部性越差**。

:::key 三条速判原则
1. **变量重复原则**：对同一变量有重复访问 → 时间局部性好。
2. **步长最小原则**：步长越小 → 空间局部性越好，步长为 1 最佳。
3. **循环体原则**：循环体一般时间和空间局部性都好；**循环体越小、迭代次数越多，局部性越好**。
:::

**算例（一维数组遍历）**

```c
for (i = 0; i < N; i++)
    sum += v[i];
```plain

- 标量 `sum`、`i`：每次迭代都被引用 → **时间局部性极好**；单变量，讨论空间局部性无意义。
- 数组元素 `v[i]`：按存储顺序逐个读取，步长为 1 → **空间局部性极好**；但每个元素只访问一次 → **时间局部性差**。

**算例（行优先 vs 列优先二维数组）**

数组按行优先存放，`M = N = 2048`，每元素 4 B。按行遍历 `a[i][j]`（内层 j 递增）时步长为 1，每取一个元素都能顺带命中同块内后续元素，空间局部性好；按列遍历（内层 i 递增）时相邻访问间隔 $N \times 4 = 8192$ B，远超一个 Cache 块，**每次访问几乎都缺失**，空间局部性极差。同样一份数据、同样的计算量，仅交换循环次序就可能让 Cache 缺失率相差十倍以上。

:::exam 局部性的统考考法
【2017-14】给出嵌套循环 `for(i=0..9) { temp=1; for(j=0..i) temp*=a[j]; ... }`，问数组 a 的访问局部性。答案是**时间局部性与空间局部性皆有**：内层循环顺序访问 `a[0..i]` 步长为 1（空间局部性好），且靠前的元素被外层循环反复重复访问（`a[0]` 访问 10 次、`a[1]` 访问 9 次，时间局部性好）。做题时要把「重复访问 → 时间」「按序访问 → 空间」两条分别对着代码数一遍，不要只凭感觉。
:::

## 半导体随机存取存储器

### 半导体存储芯片的内部结构与译码方式

一个半导体存储芯片由**存储矩阵**、**译码驱动电路**、**读写控制电路**三部分组成，并对外引出四类信号线：

| 信号线 | 方向 | 作用 |
|---|---|---|
| 地址线 | **单向**（入） | 送入地址，经译码器选中单元 |
| 数据线 | **双向** | 读出数据或写入数据 |
| 片选线 CS | 单向（入） | 选中该芯片；多片组成系统时用于字扩展 |
| 读写控制线 WE | 单向（入） | 下达读/写命令 |

相关术语：**记忆单元（存储元/位元）**是能表示 0/1 的物理器件；**存储单元**是具有相同地址的一组位，即一个编址单位；**存储体（存储矩阵/阵列）**是所有存储单元的集合。

#### 单译码结构（线选法）

$n$ 位地址直接送入一个 $n$–$2^n$ 译码器，每根输出线作为一条**字线**，被选中的字线激活整行存储单元，其上的所有位构成一个「字」被同时读写。这种芯片称为**字片式芯片**。

**致命缺陷**：地址位数多时输出线爆炸。例如 $n=16$ 时需要 $16$–$65536$ 译码器，输出 65536 根字线，硅片上布线密集、寄生电容极大、良率骤降，物理上不可实现。所以大容量芯片不用一维单译码。

#### 双译码结构（重合法）

地址译码器分成 X、Y 两组。以 4096 个单元、12 位地址为例：$A_0\sim A_5$ 送 X 译码器产生 64 条行选择线，$A_6\sim A_{11}$ 送 Y 译码器产生 64 条列选择线，行列交叉唯一确定一个单元。若地址为 `000000000001`，则 X 译码器第 2 根输出线 $x_1$ 有效、Y 译码器第 1 根输出线 $y_0$ 有效，选中单元 $(1,0)$。

被选中的行列交叉点上**只有一位**，所以这种芯片称为**位片式芯片**。若存储阵列采用三维结构（多个**位平面**），则不同位平面在同一行列交叉点上的多位构成一个存储字，被同时读写——这本质上就是**位扩展**。

$$\text{双译码结构译码输出线总数} = \text{行地址线数} + \text{列地址线数}$$

:::warn 单译码 vs 双译码
- 单译码（线选）：输出线 $=2^n$，线多、速度快，只适合小容量。
- 双译码（重合）：输出线 $=2^{n/2}\times 2$，线少，是大容量芯片的必然选择。
- 记忆锚点：**双译码的译码输出线总数 = 行地址线数 + 列地址线数**，而不是二者乘积，更不是 $2^n$。
:::

### 基本存储元件

存储单元电路必须具备四个条件：两种稳定状态；两状态可由外部信号控制互相转换；能被读出；无外部原因时信息能长期保存。

#### SRAM：六管静态 MOS 存储元件

6 个 MOS 管中，4 个构成一对正负反馈门电路，即**双稳态触发器**；另外 2 个像「守门员」，控制数据进出。只要不断电，互相拉扯的平衡状态就永远保持，**不需要任何额外动作维持**——这就是「静态」的含义。

- 优点：速度快（直接读触发器状态）；**不用刷新**；读写简单、控制逻辑少。
- 缺点：面积大（6 个管子）、集成度低、成本高、功耗较大。
- 应用：**Cache（L1/L2/L3）**、DRAM 的行缓冲。

#### DRAM：单管动态 MOS 存储单元

只由 **1 个 MOS 管 + 1 个电容 $C_S$** 构成，用**电容上有无电荷**表示 1/0。写 1 给电容充电，写 0 放电。

读出时 $C_S$ 上的电荷被稀释放电，电位下降，所以是**破坏性读出**，读后必须**重写（再生）**。电容会漏电，几毫秒内电荷就漏光，所以**必须定期刷新**。

- 优点：面积极小、集成度高、成本低、静态功耗小。
- 缺点：速度慢（读写要充放电）；必须刷新；断电或不刷新即丢数据。
- 应用：**主存（DDR 内存条）**、显存。

| 特性 | SRAM（六管） | DRAM（单管） |
|---|---|---|
| 存储原理 | 双稳态触发器（电路自锁） | 电容充放电（保存电荷） |
| 核心元件 | 6 个 MOS 管 | 1 个 MOS 管 + 1 电容 |
| 读出后是否需重写 | 不需要 | **需要**（破坏性读出） |
| 是否需要刷新 | 不需要 | **必须定期刷新** |
| 读写速度 | 快（纳秒级） | 较慢（需充放电） |
| 集成度 | 低 | 高 |
| 成本 / 功耗 | 高 / 较大 | 低 / 小 |
| 典型应用 | Cache | 主存、显存 |

:::warn SRAM 与 DRAM 的三组混淆点
1. **「静态/动态」指的是维持状态的方式**：静态靠电路自锁不需干预，动态靠电荷会衰减、需动态刷新。不是说 SRAM 的数据不变。
2. **两者都是易失性的**。只是 DRAM 更「脆弱」——不断电但停止刷新同样会丢数据。
3. **DRAM 的「读操作」和「刷新操作」不是一回事**。刷新本质上是一次**没有第 5 步（数据输出）的读操作**：行地址由芯片内部刷新计数器给出，不发列地址，不向 CPU 输出数据。读操作则必须给行、列地址并把数据送上数据总线。
:::

### DRAM 的刷新

#### 刷新的基本规则

- **按行进行**：每次刷新的单位是**一行**，该行所有列同时完成「破坏性读出 + 内部重新充电恢复」。因此刷新**只需要行地址，不需要列地址**。
- **占用一个存取周期**：刷新一行的耗时等于一次正常读写的时间，记为 $t_c$。
- **地址由内部计数器生成**：刷新行地址不是 CPU 提供的，而是 DRAM 芯片内部（或内存控制器）的**刷新地址计数器**自动产生并逐行加 1。芯片内部有一个多路选择器 MUX，正常读写时切到外部行地址缓冲器，刷新周期时切到刷新计数器，屏蔽外部地址。
- **与 CPU 争用**：刷新期间不能响应 CPU 的读写请求，这就产生了「内存争用」问题。
- **优化方向**：为减少刷新总开销，芯片设计趋向**减少行数、增加列数**（如 $128$ 行 $\times 2048$ 列 而非对称矩阵），因为刷新开销只与行数有关。

#### 三种刷新方式

**统一算例**：DRAM 为 $128$ 行 $\times 128$ 列，读写周期 $t_c = 0.5\ \mu\text{s}$，最大刷新间隔 $2\ \text{ms}$。

$2\ \text{ms}$ 内需完成全部 128 行刷新；$2\ \text{ms} / 0.5\ \mu\text{s} = 4000$ 个时隙，从中选出 128 个时隙，每时隙刷新一行即可。

| 方式 | 原理 | 优点 | 缺点 |
|---|---|---|---|
| **集中刷新** | 前 $4000-128=3872$ 个周期全部用于读写，最后 128 个周期集中刷新所有行 | 读写期间不受刷新打扰，存储器速度快 | 存在长时间**死区**，期间 CPU 完全无法访存；**行数越多死区越长** |
| **分散刷新** | 把存取周期拉长一倍：前半段读写或保持，后半段强制刷新一行，$t_s = 0.5+0.5=1\ \mu\text{s}$ | 彻底消除集中死区 | 刷新过于频繁，**严重拖慢系统速度**（每 $1\ \mu\text{s}$ 刷新一行，$2\ \text{ms}$ 内刷新约 15 遍，远超必要） |
| **异步刷新** | 把 128 行**均匀平摊**到 $2\ \text{ms}$ 内：相邻两行刷新间隔 $= 2\ \text{ms} / 128 = 15.625\ \mu\text{s}$，每次耗时 $0.5\ \mu\text{s}$ | 既保证每行在 $2\ \text{ms}$ 内刷新一次，又把死区打散成 $0.5\ \mu\text{s}$ 的微小停顿 | 需要刷新定时逻辑；**现代内存最常用的方式** |

:::key 刷新计算三个必背量
设芯片有 $r$ 行，存取周期 $t_c$，最大刷新间隔 $T_{\text{max}}$：
- 刷新总次数 $= r$；刷新总耗时 $= r \cdot t_c$。
- **集中刷新死区时间** $= r \cdot t_c$，死区率 $= \dfrac{r\cdot t_c}{T_{\text{max}}}$。
- **分散刷新**下存取周期变为 $2t_c$，有效访存速度降为原来的一半。
- **异步刷新**下相邻两行刷新间隔 $= \dfrac{T_{\text{max}}}{r}$，每次停顿 $t_c$。

统一算例：$r = 128$，$t_c=0.5\ \mu\text{s}$，$T_{\text{max}}=2\ \text{ms}$。集中刷新死区 $=128\times0.5=64\ \mu\text{s}$，死区率 $=64/2000 = 3.2\%$；异步刷新间隔 $=2000/128=15.625\ \mu\text{s}$。
:::

:::exam 刷新与引脚数的统考考法
【2015-17】工作期间需要刷新的是（ ）。答案 **B. SDRAM**——凡基于电容存储的 DRAM 家族（含 SDRAM、DDR）都需要刷新；SRAM、ROM、Flash 都不需要。
【2018-17】$2\text{K}\times1$ 位 DRAM，要求**地址引脚数最少**且**刷新开销尽量小**，求行数 $r$、列数 $c$。答案 **C.（32，64）**。推导分两步：① DRAM 地址复用，地址引脚数 $=\max(\log_2 r,\ \log_2 c)$，要使它最小须让 $r$、$c$ 尽量接近，$2\text{K}=2048=2^{11}$，故 $r\cdot c=2048$，选项 B（$64\times32$）与 C（$32\times64$）的引脚数都是 6，满足「最少」；② 刷新开销只与**行数**有关，$r$ 越小越好，故选 $r=32$。
:::

### DRAM 的地址复用

DRAM 芯片引脚数直接决定封装成本，所以采用**行列地址分两次传送**：同一组地址引脚先接收**行地址**（由 $\overline{RAS}$ 行地址选通信号锁存），再接收**列地址**（由 $\overline{CAS}$ 列地址选通信号锁存）。

$$\text{逻辑地址位数} = \log_2(\text{存储单元数}) = \text{行地址位数} + \text{列地址位数}$$

$$\text{物理地址引脚数} = \max(\text{行地址位数},\ \text{列地址位数}) \approx \left\lceil \frac{\log_2 M}{2} \right\rceil$$

其中 $M$ 为芯片的存储单元数（字数）。

**算例 1**：$4\text{M}\times8$ 位 DRAM 芯片的地址引脚与数据引脚总数是多少？

- 逻辑地址位数 $=\log_2(4\text{M}) = \log_2(2^{22}) = 22$ 位。
- 复用后物理地址引脚 $= 22 / 2 = 11$ 根（行地址 11 位 + 列地址 11 位分时复用同一组 11 根引脚）。
- 数据引脚 $= 8$ 根（芯片位宽为 8）。
- **总数 $= 11+8 = 19$ 根**。（本题即【2014-15】，答案是 19。）

**算例 2**：$256\text{K}\times8$ 位 DRAM 芯片。

- 逻辑地址 $=\log_2(2^{18}) = 18$ 位 → 物理地址引脚 $18/2 = 9$ 根。
- 数据引脚 8 根。**总数 $=17$ 根**。

**算例 3**：$8192\times8192\times8$ 位 DRAM 芯片。

- 逻辑地址 $=13+13 = 26$ 位；但行列已明确各 13 位，故物理地址引脚 $=\max(13,13)=13$ 根（不是 26 根！）。
- 数据引脚 8 根，总数 $=21$ 根。芯片内**行缓冲**容量 $=8192\times8$ 位（激活一整行时导出到读出放大器的数据量）。

:::warn DRAM 引脚计算的三个坑
1. **只要题目出现「DRAM」，地址引脚就必须除 2（或取行列最大值）**；SRAM 不复用地址，引脚数就是完整逻辑地址位数。$4\text{M}\times8$ 的 SRAM 需要 22 根地址引脚，DRAM 只需 11 根。
2. **问的是「芯片」的引脚数，与系统总容量无关**。「$256\text{MB}$ 存储器由若干 $4\text{M}\times8$ 位 DRAM 芯片构成」这个总容量只用于算芯片片数，不影响单片引脚数。
3. **行列不等时要取最大值**。$32\times64$ 的阵列，行地址 5 位、列地址 6 位，复用后引脚数是 $\max(5,6)=6$ 根，而不是 $11/2=5.5\to6$ 以外的任何数。
:::

### 只读存储器 ROM 与 Flash 存储器

#### ROM 的演进

| 类型 | 写入方式 | 擦除方式 | 特点 |
|---|---|---|---|
| **MROM**（掩膜式） | 厂家制造时写入，固定掩膜 | 不可擦除 | 内容出厂固定，可靠性高，灵活性最差 |
| **PROM**（可编程） | 用户用编程器写入（熔丝/反向二极管击穿） | 不可擦除 | **只能一次性编程**，写错即报废 |
| **EPROM**（可擦除可编程） | 编程器写入，浮置栅 MOS 管 | **紫外线照射**，约 8～20 分钟 | 可多次修改，但**必须整片擦除** |
| **EEPROM / E²PROM**（电可擦除） | 加电写入 | **电擦除** | 可**精确到字节**删除/重写，写入时间远长于读取 |
| **Flash 闪存** | 在线擦除和重写（写命令到命令寄存器） | **电擦除** | **以「块 Block」为基本单位擦除**；读快写慢 |
| **SSD 固态硬盘** | 基于闪存芯片阵列 | 电擦除 | 广义属于 ROM，但已无「只读」限制 |

记忆口诀：**名字带 E 的都能改写**（E 代表 Erasable）；**有两个 E（EEPROM）说明用最方便的电来擦除**。擦除粒度：EPROM 整片 > Flash 按块 > EEPROM 按字节。

#### Flash 存储器的特点

Flash 兼有 RAM 和 ROM 的优点：**高密度、非易失、功耗低、集成度高、不需后备电源**。它沿用 EPROM 的浮栅/热电子注入写入方式，又具备 E²PROM 的可擦除特点，因此又叫**快擦型电可擦除重编程 ROM**。常见应用：BIOS、U 盘、存储卡、SSD。

工作方式有读、编程、擦除、功耗下降四种，编程与擦除通过写命令到命令寄存器来管理。

:::key Flash 最核心的一条：读快写慢，且写前必须先擦
- **读**直接感应浮栅 MOS 管的导通/截止，速度与半导体 RAM 相当（纳秒级）。
- **写**必须先**擦除**（按块施加高压使电子隧穿），再**编程**（注入电子），速度与硬盘相当（微秒～毫秒级）。
- 因此「信息可读可写，并且读写速度一样快」是**错误**的表述（【2012-16】的答案就是这一句）。
- 擦除单位是**块**，块内所有页一起被擦；擦干净的块中每页可写一次、读无限次。
:::

#### NOR Flash 与 NAND Flash

| 维度 | NOR Flash | NAND Flash |
|---|---|---|
| 读出方式 | 随机存取，可直接按地址取任一字节 | 按页读出，随机存取粒度粗 |
| 读出速度 | 快，支持片内执行（XIP） | 较慢，但顺序/页读吞吐高 |
| 写入与擦除速度 | 慢 | 快 |
| 集成度与位价格 | 低、贵 | 高、便宜 |
| 耐久性（擦写次数） | 约 $10^4\sim10^5$ 次 | 早期约 $10^3\sim10^4$ 次，现代 3D NAND 显著提高 |
| 典型用途 | 存放固件代码（BIOS、嵌入式 boot） | U 盘、SSD、存储卡等大容量存储 |

:::warn Flash 的擦写寿命与「先擦后写」
Flash 的每个块可擦除次数有限，反复写同一个块会把它写坏（机械硬盘的扇区不会因为写得多而损坏）。此外，**要写某页信息时必须先擦除该页所在的整块**；若该块内其他页有数据，得先把它们复制到一个擦除过的新块中，再写入目标页。这就是 SSD 写放大与需要「垃圾回收 + 磨损均衡」的根本原因。
:::

## 主存储器

### DRAM 芯片与内存条

现代内存条由多片 DRAM 芯片按**低位交叉编址 + 同时启动**的方式组装，并配以 64 位（或更宽）的存储器总线。

**典型结构算例**：用 8 片 $16\text{M}\times8$ 位 DRAM 芯片扩展成一个 128 MB 内存条，按字节编址。每片内部是 $4096\times4096\times8$ 位阵列，行列地址各 12 位（$2^{12}=4096$），含 8 个位平面。

- 主存地址共 27 位（128 MB $=2^{27}$ B），高 24 位为行、列地址，低 3 位用于选择 8 片中的哪一片。
- 读数据时，高 12 位行地址**同时**送到 8 片芯片，把对应行读入各自的**行缓冲**；再把列地址同时送到 8 片，各取 8 位，组合成 **64 位**送上总线。
- CPU 再根据主存地址低 3 位，从存储控制器缓冲区中取出自己需要的那一个字节。

这一结构直接解释了**数据对齐**的必要性：一次访存固定取出第 $0\sim7$、$8\sim15$、……、$8k\sim8k+7$ 号单元。一个 `int`（4 B）若从**地址 8** 开始存放（对齐，起始地址是 4 的倍数），只需访问主存 **1** 次；若跨在**地址 6、7、8、9** 上（不对齐），则跨越了两个 8 字节块，需访问 **2** 次。

### 存储器容量的扩展

当单片芯片的字数或字长不够时，需要在**位**（字长）和**字**（地址空间）两个方向扩展。

$$\text{位扩展片数} = \frac{\text{目标数据位宽}}{\text{单片数据位宽}}, \qquad \text{字扩展组数} = \frac{\text{目标地址空间}}{\text{单片地址空间}}$$

$$\text{总片数} = \text{位扩展片数} \times \text{字扩展组数} = \frac{\text{目标总容量}}{\text{单片容量}}$$

以「目标 $M\times N$ 位，单片 $m\times n$ 位」为通用记号：

$$\text{位扩展片数} = \frac{N}{n}, \qquad \text{字扩展组数} = \frac{M}{m}, \qquad \text{总片数} = \frac{N}{n}\times\frac{M}{m} = \frac{M\times N}{m\times n}$$

#### 位扩展法

适用：**芯片数据位宽 < 目标数据位宽**（地址空间已够）。目的：加宽字长，地址空间不变。

| 信号线 | 连接方式 |
|---|---|
| 地址线 | **全部并联**，接系统地址总线 |
| 片选 CS | **全部并联**，同时选中 |
| 读写控制线 | **全部并联** |
| 数据线 | **各芯片单独引出**，分别接数据总线的不同位 |

**核心特征：所有芯片同时工作，共同提供一个完整的字。**

**算例**：用 4 片 $4\text{K}\times1$ 位 SRAM 构成 $4\text{K}\times4$ 位存储器。
- 位扩展片数 $= 4 / 1 = 4$ 片；地址空间不变，仍为 4K，需 12 根地址线 $A_0\sim A_{11}$。
- 4 片地址线并联、片选并联、WE 并联；第 1 片的数据线接 $D_0$，第 2 片接 $D_1$，第 3 片接 $D_2$，第 4 片接 $D_3$。

#### 字扩展法与片选方式

适用：**芯片字数 < 目标字数**（位宽已够）。目的：扩大地址空间，每单元位数不变。

| 信号线 | 连接方式 |
|---|---|
| 地址线低位 | 全部并联，作**片内寻址** |
| 地址线高位 | 接**译码器**（或直接接片选），作**片间选择** |
| 数据线 | 全部并联 |
| 读写控制线 | 全部并联 |
| 片选 CS | **各芯片独立**，由高位地址译码后分别控制 |

**核心特征：各芯片分时工作，同一时刻只有一片被选中。**

**片选方式一：线选法**

取字选之外的高位地址线**直接**接到各芯片的 CS 端。规定某根高位地址线为 0 时选中对应芯片，其余高位必须为 1。

- 优点：不需译码器，电路简单。
- 缺点：**地址空间不连续**，存在大量空洞；片选线必须满足「每次只有一位有效」。

**算例**：用 4 片 $8\text{K}\times8$ 位 SRAM 组成 $32\text{K}\times8$ 位，采用线选法。
- 字扩展 4 片，数据位宽已满足。芯片地址线 13 根（$2^{13}=8\text{K}$）。
- 若只用 4 根高位线 $A_{13}\sim A_{16}$ 分别接 4 片的 CS，且要求同一时刻只有一根为低，则 CPU 需要 17 根地址线。
- 各片地址范围（**地址不连续**）：

| 芯片 | 高位 $A_{16}A_{15}A_{14}A_{13}$ | 最低地址 | 最高地址 |
|---|---|---|---|
| 第 1 片 | 111**0** | 1110 0000 0000 0000 | 1110 1111 1111 1111 |
| 第 2 片 | 11**0**1 | 1101 0000 0000 0000 | 1101 1111 1111 1111 |
| 第 3 片 | 1**0**11 | 1011 0000 0000 0000 | 1011 1111 1111 1111 |
| 第 4 片 | **0**111 | 0111 0000 0000 0000 | 0111 1111 1111 1111 |

**片选方式二：译码片选法（主流）**

把高位地址线送入**地址译码器**，由译码器输出产生片选信号。

- 优点：**地址空间连续**，充分利用地址资源。
- 缺点：需要译码器，电路略复杂。

**算例**：用 4 片 $8\text{K}\times8$ 位 SRAM 组成 $32\text{K}\times8$ 位，采用译码片选法。
- CPU 需 15 根地址线（$2^{15}=32\text{K}$）、8 根数据线；芯片 13 根地址线、8 根数据线。
- 高位地址线 $= 15-13 = 2$ 根（$A_{14}$、$A_{13}$），接 **2-4 译码器**。
- $A_0\sim A_{12}$ 并联到 4 片芯片作片内寻址；译码器输出 0/1/2/3 分别接 4 片的 CS。

| 芯片 | $A_{14}A_{13}$ | 地址范围（十六进制） |
|---|---|---|
| 第 1 片 | 00 | 0000H ～ 1FFFH |
| 第 2 片 | 01 | 2000H ～ 3FFFH |
| 第 3 片 | 10 | 4000H ～ 5FFFH |
| 第 4 片 | 11 | 6000H ～ 7FFFH |

#### 字位同时扩展法

适用：**字数和字长都不够**。分两步走：

```plain
第一步：先按【位扩展】把若干芯片组成一个"逻辑组"，满足数据位宽要求
第二步：再按【字扩展（译码片选）】把多个"逻辑组"连接，满足地址空间要求
```plain

- **组内**：地址线、片选线、控制线并联，数据线按位独立引出（位扩展特征）。
- **组间**：片选由高位地址译码后各自控制，同一时刻只有一组工作（字扩展特征）。

**算例**：用 8 片 $8\text{K}\times4$ 位 RAM 构成 $32\text{K}\times8$ 位存储器。

- 位扩展片数 $= 8/4 = 2$ 片一组（两片拼成 $8\text{K}\times8$ 位）。
- 字扩展组数 $= 32\text{K}/8\text{K} = 4$ 组。
- 总片数 $= 2\times4 = 8$ 片 ✓。
- 组内：芯片①②为第 1 组，地址线、CS、WE 并联，①的数据线接 $D_0\sim D_3$、②接 $D_4\sim D_7$。
- 组间：CPU 高位 $A_{14}$、$A_{13}$ 接 2-4 译码器，4 个输出分别控制 4 组 CS；$A_0\sim A_{12}$ 并联到所有芯片。

各组地址分配：第 0 组 0000H～1FFFH，第 1 组 2000H～3FFFH，第 2 组 4000H～5FFFH，第 3 组 6000H～7FFFH。

三种扩展方式对比：

| 扩展方式 | 解决的问题 | 数据线 | 地址线低位 | 地址线高位 | 片选线 | 时序 |
|---|---|---|---|---|---|---|
| **位扩展** | 数据位宽不够 | **各自独立**引出 | 全部并联 | 全部并联 | **全部并联** | 同时工作 |
| **字扩展** | 地址空间不够 | **全部并联** | 全部并联 | 接译码器 | **各自独立** | 分时工作 |
| **字位同时** | 两者都不够 | 组内并联、按位独立 | 全部并联 | 接译码器 | 组内并联、组间独立 | 组内同时、组间分时 |

### 主存与 CPU 之间的连接

主存与 CPU 之间通过三类总线连接：

- **地址总线** $A_0\sim A_{k-1}$（单向）：低若干位送片内地址、高若干位送译码器。
- **数据总线** $D_0\sim D_{w-1}$（双向）：位扩展时按位分组接不同芯片。
- **控制总线**（单向）：读/写命令 WE、访存控制信号 MREQ、片选信号 CS。CPU 访问 I/O 与访问主存共用地址线与数据线，靠 MREQ 区分。

#### 存储器扩展设计题的完整步骤

**已知**：单片芯片规格 $m\times n$ 位，目标主存规格 $M\times N$ 位（或给定地址范围）。

```plain
Step 1  算芯片总数与组织方式
        位扩展片数 = N ÷ n        （片/组）
        字扩展组数 = M ÷ m        （组数）
        总片数 = 位扩展片数 × 字扩展组数

Step 2  分配地址线
        CPU 地址线总根数 = log2(M)（或按题目给定地址空间取 log2(地址空间大小)）
        片内地址线根数   = log2(m)      → 接各芯片地址引脚（全部并联）
        片选译码所需位数 = log2(组数)   → 接译码器输入

Step 3  分配数据线
        每组内各芯片数据线独立引出，拼满 N 位

Step 4  选片选方式
        组数少、对地址连续性要求低 → 线选法
        组数多、地址需连续         → 译码片选法（主流）

Step 5  画连接图并写出各片地址范围
        组内：地址/CS/WE 并联，数据线按位独立
        组间：低位地址并联，高位地址→译码器→各组 CS
        地址范围 = [组号<<log2(m) , (组号+1)<<log2(m) - 1]
```plain

:::key 通用模板题
**目标** $M\times N$ 位，**单片** $m\times n$ 位（$M$、$m$ 为字数，$N$、$n$ 为位宽，均取 2 的幂）：

$$\text{总片数}=\frac{N}{n}\times\frac{M}{m},\quad \text{片内地址线}=\log_2 m,\quad \text{片选译码位数}=\log_2\frac{M}{m},\quad \text{CPU 地址线}=\log_2 M$$

**算例**：$32\text{K}\times8$ 位由 $8\text{K}\times4$ 位芯片组成。
总片数 $=(8/4)\times(32\text{K}/8\text{K}) = 2\times4=8$ 片；片内地址线 $=\log_2 8\text{K}=13$ 根；片选译码 $=\log_2 4=2$ 位（用 2-4 译码器）；CPU 地址线 $=\log_2 32\text{K}=15$ 根。
:::

:::exam 扩展类真题只考几件事
【2009-15】主存 64 KB，ROM 区 4 KB、其余为 RAM 区，用 $2\text{K}\times8$ 位 ROM 与 $4\text{K}\times4$ 位 RAM 设计。答：**D（2、30）**。ROM 片数 $=4\text{KB}/2\text{KB}=2$；RAM 区 $=64-4=60\text{ KB}$，$4\text{K}\times4$ 位需 2 片一组凑 8 位，$60\text{KB}/4\text{KB}=15$ 组，共 $15\times2=30$ 片。
【2010-15】若干 $2\text{K}\times4$ 位芯片组成 $8\text{K}\times8$ 位，地址 `0B1FH` 所在芯片的最小地址。答：**D（0800H）**。位扩展 2 片一组 → $2\text{K}\times8$；字扩展 4 组。`0B1FH` = `0000 1011 0001 1111`，高 2 位 `01` 决定组号 1，该组最小地址 = `0100 0000 0000 0000` = `0800H`。
【2011-15】按字节编址，主存**地址空间** 64 MB，实际装 $4\text{M}\times8$ 位 RAM 共 32 MB，问 MAR 位数。答：**D（26 位）**。**MAR 位数由主存地址空间决定，与实际安装容量无关**：$\log_2 64\text{M}=26$。
【2016-16】64 KB 按字节编址，`4000H～5FFFH` 为 ROM 区，其余 RAM，用 $8\text{K}\times4$ 位 SRAM。答：**C（14 片）**。ROM 区 $=2000\text{H}=8\text{ KB}$，RAM 区 $=56\text{ KB}$；$8\text{K}\times4$ 位需 2 片一组，$56/8=7$ 组，共 14 片。
【2021-15】24 位地址线、32 位数据线、按**字**编址、字长 32 位，`000000H～3FFFFFH` 为 RAM，用 $512\text{K}\times8$ 位芯片。答：**C（32 片）**。先注意「按字编址」：地址范围 $400000\text{H}=2^{22}$ 个字 × 4 B = 16 MB；片数 $=16\text{MB}/512\text{KB}=32$。
【2023-15】CPU 30 根地址线，按字节编址，须占满全部地址空间，RAM:ROM $=3:1$，RAM 在低地址、ROM 在高地址。答：**C（30000000H～3FFFFFFFH）**。总空间 $2^{30}=1\text{ GB}$，ROM $=256\text{ MB}$ 位于最高段，起始地址 $=1\text{GB}-256\text{MB}=768\text{MB}=30000000\text{H}$。
:::

:::warn 扩展题高频失分点
1. **「按字编址」还是「按字节编址」看漏**。按字编址时地址单元数 × 每字字节数 = 总容量，与按字节编址的换算完全不同。
2. **把「主存地址空间」当成「实际安装容量」**。MAR 位数（以及 CPU 地址线根数）由**地址空间**决定，装多少内存不影响 MAR。
3. **算完总容量就忘了位扩展**。$4\text{K}\times4$ 位芯片装 8 位宽的内存，必须先 2 片一组，否则永远算少一半。
4. **地址范围算错**。RAM 在**低**地址段时从 0000H 起；ROM 在**高**地址段时从「总空间 − ROM 容量」起。把两者顺序搞反直接全错。
5. **译码器位数算成组数**。$n$ 个组需要 $\log_2 n$ **根**高位地址线，接 $n$ 输出的译码器。
:::

### 多模块存储器

CPU 速度远快于主存。**多模块（多体）存储器**是一种**空间并行技术**：用多个结构完全相同的存储模块并行工作，提高**吞吐率**，而不改变单个模块的存取速度。

#### 两种编址方式

| 对比维度 | 连续编址（高位交叉 / 顺序编址） | 交叉编址（低位交叉） |
|---|---|---|
| 地址结构 | [高位：模块号][低位：模块内地址] | [高位：模块内地址][**低位：模块号**] |
| 相邻地址 | 在**同一模块**内 | 在**不同模块**中 |
| 体号公式 | 模块号 $=\lfloor \text{地址} / m \rfloor$（高位） | **体号 $=\text{地址} \bmod m$**（低位） |
| 能否并行 | **不能**，无法提高吞吐率 | **能**，可实现流水线并行访问 |
| 适用场景 | 扩充容量（内存条插槽） | **突发顺序访问**（CPU 取指、DMA、Cache 调块） |

高位交叉为什么并行不了：程序具有局部性和连续性，连续执行的指令和数据基本落在**同一个存储体**里，该体访问频繁、其余体空闲，多体形同虚设。

低位交叉为什么有效：连续地址分散在不同体，各体有**独立的读写电路**，可以不用等前一个体准备好就开始下一个体，各体并行准备数据。

:::warn 编址方式与扩展方式不是一回事
- 高位交叉 = 顺序编址，等价于**字扩展**的思路（分时工作）。
- 低位交叉的「同时启动」方式在连接上就是**位扩展**（多个芯片同时工作，各自提供总线的一部分位）。名字侧重不同：位扩展强调容量扩展，多模块交叉强调编址方式。
:::

#### 低位交叉的流水存取时间

设存储周期为 $T$、总线传输周期为 $\tau$、交叉模块数为 $m$。访存分三个阶段：$T_1$ 送地址与命令、$T_2$ 存储器准备数据（即存取时间）、$T_3$ 总线传输一次数据（$\tau$）。

教材与真题默认**忽略恢复时间**，令存储周期 $\approx$ 存取时间，即经过一个 $T$ 后数据才送上数据线。

**轮流启动方式**：每个模块一次读写的位数 = 总线数据位数（每次只传一个模块的数据），流水条件是

$$T = m\tau$$

即每隔 $\tau$ 启动下一个模块。

$$t_{\text{准备}}(n) = T + (n-1)\tau$$

$$\boxed{\,t_{\text{总}}(n) = \underbrace{\tau}_{\text{送首地址与命令}} + \underbrace{T+(n-1)\tau}_{\text{存储器准备 } n \text{ 个字}} + \underbrace{\tau}_{\text{传送最后一个字}} = T + (n+1)\tau\,}$$

**逐步推导**（以 $m=4$、$T=4\tau$、连续读 $n$ 个存储字为例）：

1. $t_0$：CPU 发出首地址与读命令，耗时 $\tau$。
2. $t_1 = \tau$：启动体 $M_0$；此后每间隔 $\tau$ 依次启动 $M_1$、$M_2$、$M_3$、$M_0$……
3. $M_0$ 经过完整存储周期 $T=4\tau$ 后，在 $t_2 = \tau + T$ 时刻把第一个数据送上数据线并开始传送。
4. 从此进入**流水线稳定状态**：每经过一个 $\tau$ 就有一个数据准备好送出。第 $n$ 个字在 $\tau + T + (n-1)\tau$ 时刻准备好。
5. 最后加上传送第 $n$ 个字所需的一个 $\tau$。

$$t_{\text{总}}(n) = \tau + T + (n-1)\tau + \tau = T + (n+1)\tau$$

**平均准备一个字的时间**：

$$\bar{t} = \frac{T+(n-1)\tau}{n} \xrightarrow{\ n\to\infty\ } \tau$$

即 $n$ 很大时，存储器平均每个存储周期（每 $\tau$）就能向 CPU 提供一个字——稳定流水时**一个存储周期内向 CPU 提供 $m$ 个数据**。

对比**高位交叉**（连续编址）：连续地址都在同一个体，两次读之间必须间隔 $T$，故

$$t_{\text{准备}}(n) = nT, \qquad \bar{t} = T \quad (\text{与 } n \text{ 无关})$$

**统一算例**：$m=4$ 体低位交叉，$\tau$ 为总线传输周期，$T=4\tau$，连续读取 5 个地址连续的存储字 $W_0\sim W_4$。

- 低位交叉：$t_{\text{准备}} = T+(5-1)\tau = 4\tau+4\tau = 8\tau$；总耗时 $=\tau+8\tau+\tau = 10\tau = 2.5T$。
- 高位交叉：$t_{\text{准备}} = 5T = 20\tau$；总耗时 $=\tau+20\tau+\tau = 22\tau = 5.5T$。
- 加速比约 $2.2$；若 $n$ 更大，低位交叉趋近于每 $\tau$ 出一个字（加速比趋近 $m=4$）。

:::key 低位交叉计算必背四条
1. 流水条件：$T = m\tau$（每隔 $\tau$ 启动一个体）。
2. 准备 $n$ 个字的时间：$T+(n-1)\tau$。
3. 含总线开销的总时间：$T+(n+1)\tau$（送首地址 $\tau$ + 准备 + 送尾数据 $\tau$）。
4. 稳定流水时：**一个存储周期内提供 $m$ 个字**，平均每字耗时 $\tau$。
:::

:::exam 低位交叉的统考考法
【2015-18】4 体交叉编址，主存地址序列 `8005,8006,8007,8008,8001,8002,8003,8004,8000`，问**可能**发生访存冲突的地址对。答：**D（8000 和 8004）**。体号 $=\text{地址}\bmod4$：`8004` 体 0、`8008` 体 0 但相隔 4 步（不冲突）；`8000` 与 `8004` 同为体 0 且相邻（相隔 1 步 $<4$），必然冲突。
【2017-13】4 片 $64\text{M}\times8$ 位 DRAM 交叉编址构成主存，总线宽 32 位，每次最多读写 32 位，`double` 型变量 x 地址为 `804001AH`，读取 x 需要几个存储周期。答：**C（3）**。每片 8 位、4 片并行正好 32 位，符合**同时启动**条件。`double` 占 8 B，起始地址低 2 位为 `10`（体号 2），8 个字节跨越 $8000\sim8007$、$8008\sim800F$ 等 8 字节边界，需 **3** 次并行读取。
【2013-43】32 位机，主存 8 体交叉，每体存储字长 32 位、存储周期 40 ns，总线宽 32 位、时钟 200 MHz（周期 5 ns），突发传送 32 B。一次读突发事务 $=5\ \text{ns}$（送地址）+ $40\ \text{ns}$（准备首个数据）+ $8\times5\ \text{ns}$（传送 8 次数据）$= 85\ \text{ns}$。注意「准备数据」只算**第一个**数据的时间，后续数据靠流水线补上。
:::

#### 访存冲突

**冲突条件**：$m$ 体交叉存储器中，两次连续访问落在**同一个体**，且时间间隔**小于存储周期 $T$**（即访问步数差 $< m$）。

**判断步骤**：
1. 对每个地址求 $\bmod\ m$，得到体号；
2. 在访问序列中找体号相同的地址对；
3. 检查它们在序列中的**间隔步数**是否 $< m$。

**无冲突的理想条件**：相邻 $m$ 个访问地址分别属于 $m$ 个不同的体（体号连续不重复）。

:::warn 冲突题的两个陷阱
1. **只看体号相同就判冲突是错的**，必须同时满足「间隔步数 < m」。`8004` 与 `8008` 都是体 0，但序列中相隔 4 步（$=m$），不冲突。
2. **「可能」二字很关键**。题目问「可能发生冲突的地址对」，只要存在某种时刻安排让其冲突即可，不需要它在给定序列中真的紧邻。
:::

## 外部存储器

### 磁盘存储器

#### 组成与物理结构

磁盘存储器由**磁盘控制器、磁盘驱动器、盘片**三大部分组成。

- **磁盘控制器**：磁盘与主机的 I/O 接口，含控制逻辑、时序电路、「并→串」与「串→并」转换电路。
- **磁盘驱动器**：读写电路、读写转换开关、读写磁头与磁头定位伺服系统。
- **盘片与盘面**：每个盘片的**两个面各有一个磁头**，因此**磁头号 = 盘面号**。

关键术语：
- **磁道（Track）**：磁头与盘片相对运动形成的同心圆。磁道从外向里编号，最外圈为 0 号磁道。
- **柱面（Cylinder）**：多个盘片上**相同编号的磁道**构成一个柱面，所以**磁道号 = 柱面号**。
- **扇区（Sector）**：每个磁道被分成的若干等长区域，**磁盘读写的最小单位**（传统 512 B，现代常用 4 KB）。

写入顺序：写完一个柱面上所有磁道后才移动到下一个柱面。

#### 磁盘的物理地址与读写过程

地址结构：`[驱动器号][柱面(磁道)号][盘面(磁头)号][扇区号]`。

:::key 为什么是「柱面号在前、盘面号在后」
若地址结构是 `(盘面号, 柱面号, 扇区号)`，读完盘面 0 的整条磁道后，要继续读相邻磁盘区域就**必须启动磁头臂移动到下一个磁道**；而 `(柱面号, 盘面号, 扇区号)` 下，同一柱面的不同盘面**柱面号相同**，只需激活相邻盘面的磁头即可，**不必移动磁头臂**，省下大量寻道时间。这就是柱面号必须放在盘面号之前的根本原因。
:::

磁盘读写共三步：**寻道 → 旋转等待 → 读写**。

- **寻道**：磁盘控制器把盘地址送到驱动器后，启动磁头定位伺服系统，按磁头号与柱面号把指定磁头移到指定柱面，完成后发出寻道结束信号。
- **旋转等待**：盘片旋转，扇区计数器每收到一个扇区标志脉冲加 1，与地址寄存器中的扇区地址比较，一致时输出扇区符合信号。
- **读写**：写操作把数据送写入电路生成写电流脉冲；读操作由读出放大电路读出内容送控制器。

磁盘既不能像 RAM 那样按地址随机访问任一单元，也不是完全按顺序存取，而是**先定位磁道、再在磁道内顺序查找**，因此属于**直接存取（DAM）**。

#### 性能指标

**（1）记录密度**

- **道密度**：沿磁道分布方向上单位长度内的磁道数目。
- **位密度**：沿磁道方向上单位长度内存放的二进制信息数目。

低密度存储方式下所有磁道扇区数相同 → 每个磁道位数相同 → **内道位密度比外道高**；高密度存储方式下各磁道位密度相同 → 外道扇区数多于内道 → 整盘容量大得多。

**（2）存储容量**

$$\text{非格式化容量（未格式化容量）} = \text{位密度} \times \text{内圈周长} \times \text{总磁道数}$$

$$\text{格式化容量} = \text{每扇区字节数} \times \text{每磁道扇区数} \times \text{磁道数（柱面数} \times \text{盘面数）}$$

$$\text{磁盘总容量} = \text{柱面数} \times \text{磁头数（盘面数）} \times \text{每磁道扇区数} \times \text{每扇区字节数}$$

**非格式化容量 > 格式化容量**：低级格式化要在每扇区加头部（扇区号、同步信息）、尾部（ECC 纠错码）以及扇区间隔，这些都要占用磁介质空间。

**算例**：某磁盘 8 个柱面、4 个盘面、每磁道 16 个扇区、每扇区 512 B。

格式化容量 $= 8 \times 4 \times 16 \times 512\ \text{B} = 256\ \text{KB}$。

**（3）平均存取时间**

磁盘出队后要经历寻道、旋转等待、读写数据传输三个过程：

$$\text{响应时间} = \text{排队延迟} + \text{控制器时间} + \text{寻道时间} + \text{旋转等待时间} + \text{数据传输时间}$$

$$\boxed{\ \text{存取时间} = \text{寻道时间} + \text{旋转（等待）延迟} + \text{传输时间}\ }$$

- **寻道时间** $T_s = p + m\cdot n$：$p$ 为启动磁头臂的时间，$m$ 为每跨越一个磁道的耗时，$n$ 为需跨越的磁道数。
- **旋转延迟（平均）**：

$$T_r = \frac{1}{2}\times\frac{1}{r} = \frac{1}{2r}\quad (r:\text{转/秒}), \qquad T_r = \frac{1}{2}\times\frac{60}{r} = \frac{30}{r}\ \text{s}\quad (r:\text{转/分})$$

  定位过程中最多转 1 圈、最少 0 圈，平均需半圈，所以除以 2。

- **传输时间**（读 $b$ 字节，每磁道 $N$ 字节，转速 $r$ 转/秒）：

$$T_t = \frac{b}{N}\times\frac{1}{r} = \frac{b}{rN}$$

  因为读写一条完整的磁道恰好需要转一圈的时间 $1/r$。等价形式：访问一个扇区的传输时间 $= \dfrac{\text{一圈时间}}{\text{每磁道扇区数}} = \dfrac{\text{扇区容量}}{\text{数据传输率}}$。

:::key 旋转延迟只有两种算法，别混
- 转速单位是 **r/min**（如 7200 rpm）：$T_r = \dfrac{60}{2r} = \dfrac{30}{r}\ \text{s}$。
- 转速单位是 **r/s**：$T_r = \dfrac{1}{2r}\ \text{s}$。
题目给「r 秒/转」这种反着写的单位要特别小心——先统一成转/秒或转/分再算。
:::

**算例 A**（【2013-21】）：转速 10000 rpm，平均寻道 6 ms，传输速率 20 MB/s，控制器延时 0.2 ms，读一个 4 KB 扇区。

- 转一圈 $= 60/10000 = 6\ \text{ms}$ → 平均旋转延迟 $=6/2=3\ \text{ms}$。
- 传输时间 $=4\text{KB}/20\text{MB/s} \approx 0.2\ \text{ms}$。
- 总时间 $=6+3+0.2+0.2 = 9.4\ \text{ms}$。（答案 B）

**算例 B**（【2015-20】）：转速 7200 rpm，平均寻道 8 ms，每磁道 1000 个扇区，访问一个扇区。

- 转一圈 $=60/7200 = 8.333\ \text{ms}$ → 平均旋转延迟 $=4.167\ \text{ms}$。
- 一个扇区的传输时间 $=8.333/1000 \approx 0.0083\ \text{ms}$（可忽略）。
- 总时间 $=8+4.167+0.0083 \approx 12.2\ \text{ms}$。（答案 B）

**（4）数据传输率**

$$\text{内部数据传输率} = \frac{\text{转速(转/分)}}{60} \times \text{内圈周长} \times \text{最内道位密度}$$

因为同一时刻只有一个磁头在读写，所以内部传输率由**内圈**（周长最小、位密度最高）决定。

:::warn 磁盘的两个易错断言
1. **「磁盘的最小读写单位是一字节」错误**，最小读写单位是**扇区**。哪怕只读 1 个字节，也要把包含它的整个扇区读出来（【2019-20】答案）。
2. **「格式化容量比非格式化容量小」正确**。格式化要写扇区头、尾和间隔，占用空间；非格式化容量是按道密度与位密度算出的全部磁化单元总数。
3. 磁盘是机械设备，读写**串行**：不可能同一时刻既读又写，也不可能同时读两组数据。
:::

**（5）减少延迟的硬件手段**

对一个盘面内的扇区采用**交替编号**，对不同盘面的扇区采用**错位命名**（均在低级格式化时完成），可以显著减少连续读写多条记录时的磁头等待时间。软件层面则靠磁盘调度算法减少寻道时间。

#### 磁盘阵列 RAID

RAID（廉价冗余磁盘阵列）把多个独立物理磁盘组成一个逻辑盘，数据交叉存储、并行访问。基本思想三点：组织成阵列以**增加容量**；用类似主存多模块交叉的技术让多盘**并行工作提高传输率**；用**冗余**技术提高可靠性。

| 级别 | 定义 | 要点 | 类别 |
|---|---|---|---|
| RAID0 | 无冗余、无校验 | 条带化交替存放、并行读写，容量与速度都提升，**无容错** | 条带化 |
| RAID1 | 镜像磁盘阵列 | 两盘同写互为备份，可靠性高，**容量减半** | 镜像 |
| RAID2 | 海明码纠错阵列 | 多个冗余校验盘，冗余开销大，已不再使用 | 并行访问 |
| RAID3 | 位交叉奇偶校验 | 单个冗余盘 + 小条带交叉 | 并行访问 |
| RAID4 | 块交叉奇偶校验 | 大数据块交叉，各盘操作独立 | 独立访问 |
| RAID5 | 无独立校验盘的奇偶校验 | 校验块分布在各个磁盘中，成本不高效率高，广泛使用 | 独立访问 |

:::exam RAID 的考法
【2013-20】用于**提高 RAID 可靠性**的措施有：Ⅰ 磁盘镜像 ✓、Ⅱ 条带化 ✗（只提速不提供冗余）、Ⅲ 奇偶校验 ✓、Ⅳ 增加 Cache ✗（只提性能，写缓存掉电还可能丢数据）。答案 **B（仅Ⅰ、Ⅲ）**。
:::

### 固态硬盘 SSD

#### 结构与读写特性

SSD 基于闪存 Flash 技术，属于电可擦除 ROM（EEPROM）。组成：

- **闪存翻译层**：负责把逻辑块号翻译成物理页地址，相当于磁盘控制器。
- **存储介质**：闪存颗粒。多个**闪存芯片（Flash Chip）** → 每芯片含多个**块（Block）** → 每块含多个**页（Page）**。

:::key SSD 的四条读写特性
1. **以页为单位读写**（页相当于磁盘的扇区）；**以块为单位擦除**。
2. **写某页前必须先擦除该页所在的整块**。若块内其他页有数据，要先把它们复制到另一个已擦除的空块，再写入目标页——这就是 SSD 的「写放大」。
3. **支持随机访问**：给定逻辑地址，闪存翻译层可通过电路迅速定位物理地址，没有寻道与旋转延迟。
4. **读快写慢**：擦干净的块中每页可写一次、读无限次；读速度与 RAM 相当，写速度与硬盘相当。
:::

#### 与机械硬盘的对比

| 维度 | 机械硬盘 HDD | 固态硬盘 SSD |
|---|---|---|
| 访问定位方式 | 移动磁臂 + 旋转盘片（电路控制） | 纯电路译码定位 |
| 寻道时间 / 旋转延迟 | 有，且是主要开销 | **没有** |
| 随机访问性能 | 差 | **极好** |
| 顺序读写性能 | 中等 | 高 |
| 噪音 / 抗震 / 功耗 | 有噪音、怕摔、功耗高 | 安静、耐摔抗震、功耗低 |
| 单位容量价格 | 低 | **高** |
| 寿命特性 | 扇区不因写入次数多而损坏 | **块擦除次数有限，反复写同一块会写坏** |

#### 磨损均衡

**思想**：把「擦除」操作平均分布到各个块上，避免某些块被反复擦写而提前失效，从而延长整盘寿命。

- **动态磨损均衡**：写入数据时，优先选择**累计擦除次数少**的新闪存块。
- **静态磨损均衡**：SSD 主动监测并自动做数据分配与迁移——让**老旧的块承担以读为主**的存储任务，让**较新的块承担更多的写任务**。效果更优，是现代 SSD 的标配。

:::warn SSD 不一定比 HDD 快——这句话要看场景
SSD 的随机访问性能碾压 HDD（没有寻道和旋转延迟），但**写操作**因必须先擦块、可能触发数据搬迁（垃圾回收），写入延迟可能反而高于顺序写磁盘。所以「SSD 读写都比磁盘快」不严谨；正确的说法是「SSD 随机访问性能高、读快，写涉及擦除会慢」。
:::

## 高速缓冲存储器（Cache）

### Cache 的基本原理

Cache 是 CPU 与主存之间的小容量高速缓冲层，用来弥补二者速度鸿沟。它由**SRAM**构成（无需刷新），L1/L2 集成在 CPU 核内，L3 为多核共享。

**核心工作逻辑**：程序运行时，硬件基于**局部性原理**把即将用到的、主存中相邻的一批数据/指令**预先成批拷贝到 Cache**。**Cache 的内容是主存部分内容的副本（镜像），因此不会增加系统总容量。**

术语澄清：**主存块（Block）≠ 页（Page）**。主存块是 Cache-主存层次的传输单位（8～128 B），纯**硬件**实现；页是虚存-主存层次的单位（4 KB～64 KB），面向**操作系统内存管理**。

Cache 行除数据区外还有两个核心标识位：

- **有效位 V（Valid Bit）**：标识该行数据是否合法有效。系统上电/复位时所有行 V 清零；装入合法主存块后置 1；淘汰时清 0。**V=0 时无论 Tag 是否匹配都判为缺失。**
- **标记位 Tag**：标识该行存放的是哪个主存块。**只有 Tag 匹配且 V=1 才算命中。**采用写回策略时还需 **1 位脏位**。

**访问流程**：CPU 给出主存地址 → 按映射规则定位候选行 → 比较 Tag 与 V → 命中则从 Cache 取数并按块内地址选出字/字节；缺失则访问主存取块，同时把整块调入 Cache（必要时先替换）。

整个流程——判命中、取数、调块、替换——**必须由硬件在一条指令的执行周期内完成，对程序员完全透明**。因此 **Cache 缺失不会引发 CPU 陷入内核，不会引起进程切换**；而缺页必须由操作系统处理。

#### 性能指标

- **命中率 $h$**：$h = \dfrac{\text{命中次数}}{\text{总访存次数}}$，$0\le h\le 1$。
- **缺失率** $=1-h$。
- **命中时间 $t_c$**：Cache 命中的访问延迟（即 Cache 自身的访问时间）。
- **主存访问时间 $t_m$**：$t_m$ 通常是 $t_c$ 的几十到上百倍。

**平均访问时间**：两种模型写法不同，**看题目是串行还是并行访问**。

串行访问模型（先查 Cache，未命中再访主存）：

$$T_a = h\cdot t_c + (1-h)(t_c+t_m) = t_c + (1-h)\,t_m$$

并行访问模型（同时访问 Cache 与主存，命中则立即取消主存请求）：

$$T_a = h\cdot t_c + (1-h)\,t_m$$

**访问效率**：

$$e = \frac{t_c}{T_a}$$

:::warn 两个平均访问时间公式不能乱用
教材常写 $T_a = t_c + (1-h)t_m$（串行：无论命中与否都要花一个 $t_c$）；也有题目按 $T_a = h t_c + (1-h)t_m$（并行：同时发起，命中就赢）。**区别在于缺失时是否还要额外计入 $t_c$**。读完题先确认组织方式，再选公式；如果 $t_c \ll t_m$，两者差别不大，但选项往往就卡在这个差别上。
:::

**算例**：$t_c = 4\ \text{ns}$，$t_m = 100\ \text{ns}$。

- 若 $h = 95\%$，串行模型：$T_a = 4 + 0.05\times100 = 9\ \text{ns}$，$e = 4/9 \approx 44.4\%$。
- 并行模型：$T_a = 0.95\times4 + 0.05\times100 = 8.8\ \text{ns}$。

**两级 Cache 算例**：L1 命中率 95%、访问时间 2 ns；L1 缺失时访 L2，L2 命中率 80%、访问时间 10 ns；L2 也缺失则访主存，主存访问时间 100 ns。

$$T_a = 2 + 0.05\times10 + 0.05\times0.20\times100 = 2+0.5+1 = 3.5\ \text{ns}$$

三级分解检验：L1 命中贡献 $0.95\times2=1.9$；L2 命中贡献 $0.05\times0.8\times(2+10)=0.48$；主存贡献 $0.05\times0.2\times(2+10+100)=1.12$；合计 $3.5\ \text{ns}$ ✓。

#### Cache 设计要考虑的四类问题

1. **地址映射与变换**：主存块按什么规则放到 Cache 行？如何快速定位？（直接映射、全相联、组相联）
2. **块替换**：Cache 满时淘汰哪一行？（FIFO、LRU、LFU、随机）
3. **写一致性**：写操作如何保证 Cache 与主存一致？（写直达、写回、写分配、非写分配）
4. **地址划分**：如何把主存地址切成 `Tag | Index | Offset` 供硬件并行匹配。

### Cache 与主存之间的映射方式

三种映射方式在**命中率**（可选位置越多越高）、**查找速度**（可选位置越多越慢）、**冲突率**（可选位置越少越高）之间权衡。

**主存块大小的统一约定**：设块内地址占 $w$ 位，则块大小 $=2^w$ 字节。**块内地址位数 $w=\log_2(\text{块大小})$，永远是地址的最低位段。**

#### 直接映射

**映射规则**：

$$\text{Cache 行号} = \text{主存块号} \bmod \text{Cache 行数}$$

等价说法：把主存按 Cache 大小分区，每个区内的块数与 Cache 行数相同；主存地址分成**标记 Tag（区地址）+ 行号 Index（区内行索引）+ 块内地址 Offset** 三部分。Index 字段就是上式中的余数。

地址字段位数（设主存地址 $n$ 位，块大小 $2^w$ B，Cache 行数 $C=2^c$）：

$$w = \log_2(\text{块大小}), \qquad c = \log_2(\text{Cache 行数}), \qquad t = n - c - w$$

$$\text{Cache 行数} = \frac{\text{Cache 数据区容量}}{\text{块大小}}$$

**特点**：每个主存块只有**唯一确定**的 1 个可放位置；只需**一个共享的比较器**；需要行号译码器；硬件成本最低；**不需要替换算法**（冲突时直接替换）；命中率最低、冲突率最高（Cache 未满也可能冲突）。适用于大容量 Cache。

#### 全相联映射

**映射规则**：一个主存块可装入 Cache 的**任意一行**。

地址只有**标记 Tag + 块内地址 Offset** 两个字段（没有行号/组号）：

$$w = \log_2(\text{块大小}), \qquad t = n - w$$

$$t = \log_2(\text{主存块数}) = \log_2\left(\frac{\text{主存容量}}{\text{块大小}}\right)$$

**特点**：Tag 最长；利用率最高、命中率最高、冲突率最低（只有 Cache 全满才需要替换）；需要**每一行一个比较器并行比较**，硬件成本最高；替换算法复杂。适用于小容量 Cache，**如快表 TLB**。

全相联的硬件实现要点：主存 Tag 广播到所有行的比较器，比较结果与各行的有效位 V 送入**与门**（Tag 相等 **且** V=1 才输出 1），所有与门输出送入**或门**产生全局 `hit`；命中行打开三态门，数据经 MUX 按块内地址选出字/字节输出；`hit=0` 时阻断 MUX 输出，CPU 转而访问主存。缺失时需从主存取块、按替换算法选牺牲行、写入并更新 Tag 与 V。

#### 组相联映射

**映射规则**：Cache 分成若干组，**每组 $k$ 行，称 $k$-路组相联**。主存块先用直接映射定位到**固定的组**，再在**组内全相联**映射到任意一行：

$$\text{Cache 组号} = \text{主存块号} \bmod \text{Cache 组数}$$

地址分三段：**标记 Tag + 组索引 Index + 块内地址 Offset**。

$$\text{组数} = \frac{\text{Cache 总行数}}{\text{路数 }k} = \frac{\text{Cache 数据区容量}}{\text{块大小} \times k}$$

$$d = \log_2(\text{组数}), \qquad w=\log_2(\text{块大小}), \qquad t = n-d-w$$

**查找流程**：用组索引经译码器定位到**唯一一组**（这一步把查找范围大幅缩小）→ 组内 $k$ 路的 Tag 与有效位并行比较（$k$ 个比较器）→ 命中路的与门打开三态门 → MUX 按块内地址选出数据。

**组相联统一了另外两种映射**：

- $k = 1$（每组 1 行，共 $m$ 组）→ 退化为**直接映射**（只有 1 个比较器）。
- $m = 1$（只有 1 组，共 $k=n$ 行）→ 退化为**全相联映射**（无需组号译码器）。

:::key 组索引位数只由组数决定，与路数无关
这是最容易错的一点。**$2^d$ 组就占 $d$ 位**，不论每组有几路。增加路数 $k$ 会减少组数，从而减少组索引位数、增加 Tag 位数，但**不会**改变组索引与路数的直接对应关系。
:::

#### 三种映射方式对比

| 对比项 | 直接映射 | 全相联映射 | $k$-路组相联 |
|---|---|---|---|
| 映射规则 | 行号 $=$ 块号 mod 行数 | 任意行 | 组号 $=$ 块号 mod 组数，组内任意 |
| 可放位置数 | 1（唯一确定） | $n$（全部行） | $k$（组内） |
| 地址字段 | Tag + 行号 + 块内 | **Tag + 块内** | Tag + 组号 + 块内 |
| Tag 长度 | **最短** | **最长** | 居中 |
| 比较器 | **1 个**（共享） | $n$ 个（每行一个） | $k$ 个（每组 $k$ 个） |
| 需要译码器 | 需要（行号） | **不需要** | 需要（组号） |
| 硬件成本 | 最低 | 最高 | 居中 |
| 命中率 / Cache 利用率 | 低 | **最高** | 较高 |
| 冲突率 | **最高**（未满也可能冲突） | 最低（全满才冲突） | 居中 |
| 替换算法 | **不需要** | 复杂 | 仅组内，需要 |
| 适用 | 大容量 Cache | 小容量（TLB） | **最常用**（L1/L2/L3） |

关联度（路数）与性能的关系（Cache 大小、块大小固定时）：

- **关联度越低** → 命中率越低、判命中开销越小、**命中时间越短**、Tag 额外空间开销越小。
- 直接映射命中时间最短、额外开销最小；全相联命中时间最长、额外开销最大。

这解释了现代 CPU 为何普遍使用 4 路、8 路、16 路组相联：路数增加时命中率迅速逼近全相联，而硬件成本仍可控；路数为 1 冲突率过高，路数等于总行数则硬件代价过大。

#### 地址划分与容量计算的解题流程

```plain
Step 1  由【Cache 数据区容量 ÷ 块大小】求 Cache 总行数
Step 2  由【总行数 ÷ 路数 k】求组数（直接映射时组数 = 行数，全相联时组数 = 1）
Step 3  Offset 位数 w = log2(块大小)
        直接映射：Index 位数 c = log2(行数)
        组相联  ：Index 位数 d = log2(组数)
        全相联  ：无 Index
Step 4  Tag 位数 t = 主存地址位数 n − Index 位数 − w
Step 5  每行总位数 = 数据位数 + Tag 位数 + 有效位(1)
                     + 脏位(写回时要算，直写时不算)
Step 6  Cache 总容量 = 行数 × 每行总位数
```plain

**通用容量公式**（设块大小 $2^w$ 字节、Cache 行数 $n$、主存地址位数由 $w$ 与 Tag 位数 $s$ 决定）：

$$\text{直接映射：} \quad C = n\times\left(1 + t_{\text{tag}} + 8\times 2^w\right)\ \text{位},\quad n=2^c,\ t_{\text{tag}} = s-c$$

$$\text{全相联：} \quad C = n\times\left(1 + s + 8\times 2^w\right)\ \text{位}$$

$$k\text{ 路组相联：} \quad C = kn\times\left(1 + s-d + 8\times 2^w\right)\ \text{位},\quad \text{组数}=n=2^d$$

（若采用写回策略，括号内还要再加 1 位脏位。）

**算例 1（直接映射）**：主存地址 32 位，按字节编址，块大小 16 B，Cache 数据区容量 64 KB，直接映射。

- 行数 $=64\text{KB}/16\text{B} = 2^{12}=4096$ 行 → $c=12$ 位；$w=\log_2 16=4$ 位。
- Tag $=32-12-4 = 16$ 位。
- 每行 $=$ 1 位 V + 16 位 Tag + 4 个 32 位字 $=1+16+128=145$ 位。
- Cache 总容量 $=4096\times145 = 580\text{ Kbit} = 72.5\text{ KB}$；数据占比 $=64/72.5\approx 88.3\%$。

**算例 2（直接映射 + 写回，即【2015-15】）**：主存地址 32 位、按字节编址、块大小 4 个字（每字 32 位 = 4 B，故块 16 B）、写回、能存 4K 字数据，求 Cache 总位数。

- 数据容量 $=4\text{K}\times4\text{B}=16\text{ KB}$；行数 $=16\text{KB}/16\text{B}=1024$ → $c=10$；$w=4$。
- Tag $=32-10-4=18$ 位。
- 每行 $=1(\text{V})+1(\text{脏})+18(\text{Tag})+128(\text{数据}) = 148$ 位。
- 总容量 $=1024\times148 = 148\text{ Kbit}$。（答案 C）

**算例 3（直接映射 + 写回，即【2021-16】）**：主存地址 32 位、按字节编址、Cache 数据区 32 KB、块大小 32 B、直接映射、写回，求**每行**位数。

- 行数 $=32\text{KB}/32\text{B}=1024$ → $c=10$；$w=5$；Tag $=32-10-5=17$。
- 每行 $=1+1+17+32\times8 = 275$ 位。（答案 A）

**算例 4（组相联，即【2022-16】）**：主存地址 32 位、按字节编址、Cache 数据区 32 KB、块大小 64 B、**8 路组相联**，问比较器个数与位数。

- 行数 $=32\text{KB}/64\text{B}=512$；组数 $=512/8=64$ → $d=\log_2 64=6$；$w=\log_2 64=6$。
- Tag $=32-6-6=20$ 位。
- 访问时用组索引选定一组，组内 **8 路并行比较** → 比较器个数 $=8$，每个宽度 $=$ Tag 位数 $=20$ 位。（答案 A）

:::warn 地址划分题的五个高频错点
1. **把「Cache 容量」当成「数据区容量」**。题目给的行数/组数由**数据区**容量算；Tag 字段与总容量才需要加元数据位。
2. **组索引位数按路数算**。$2^d$ 组就 $d$ 位，与每组几路无关。
3. **写回忘加脏位、直写多加了脏位**。**看写策略**决定这一位要不要算。
4. **「每行位数」与「总容量」问法不同**。前者只乘一次，后者乘行数。
5. **主存块大小单位是「字」时忘记换算成字节**。4 个字 × 32 位 = 16 B，$w=4$ 而不是 $\log_2 4$。
:::

:::exam 命中与映射的统考考法
【2009-21】访存 1000 次、缺失 50 次，命中率？$h=(1000-50)/1000=95\%$（答案 D）。
【2009-14】Cache 16 块、2 路组相联、块大小 32 B、按字节编址，主存 129 号单元所在块装入哪个组号？块号 $=\lfloor129/32\rfloor=4$，组数 $=16/2=8$，组号 $=4\bmod 8=4$（答案 C）。也可直接看地址 129 = `100 00001`：低 5 位是块内地址、接着 3 位是组号 `100` $=4$。
【2022-16】同算例 4；【2021-16】同算例 3；【2015-15】同算例 2。**这一类型是必拿分项，公式背熟 + 单位换算细致即可。**
:::

### Cache 中主存块的替换算法

Cache 行数远少于主存块数，多个主存块会映射到同一行/组。新块调入而位置已满时必须淘汰一个。适用性提醒：

- **直接映射不需要任何替换算法**——每个块只有唯一位置，调入即覆盖。
- **全相联**的替换涉及全部 Cache 行。
- **组相联**的替换只在特定组内进行。

**统一算例**：某 **4 路组相联** Cache 的第 0 组初始为空，依次访问映射到该组的块号序列

$$1,\ 2,\ 3,\ 4,\ 1,\ 2,\ 5,\ 1,\ 2,\ 3,\ 4,\ 5$$

前 4 次访问把组内 4 个空位填满，状态为 `[1, 2, 3, 4]`；接着访问 1、2 均命中；访问 **5** 时冲突，需按算法淘汰一个。

| 算法 | 核心思想 | 实现机制 | 本例淘汰谁 | 优点 | 缺点 |
|---|---|---|---|---|---|
| **FIFO** 先进先出 | 谁先进入谁先被淘汰（认老不认新） | 计数器或循环队列 | 淘汰 **1**（最早进入） | 硬件最简单 | 性能差，**可能产生 Belady 异常**；不反映局部性 |
| **LRU** 最近最少使用 | 淘汰**最久未被访问**的块 | 每行一个计数器/时间戳：命中行清零，其余加一；替换时选值最大者 | 淘汰 **3**（访问历史 …3, 4, 1, 2 中最久） | **最符合时间局部性，命中率最高，主流采用** | 硬件开销大，每次访问都要更新计数器 |
| **LFU** 最不经常使用 | 淘汰过去**被访问次数最少**的块 | 每行一个访问计数器，命中加 1；替换时选值最小者 | 3 与 4 次数并列（各 1 次），需配合 FIFO 打破平局 → 淘汰 **3** | 体现长期高频热点 | 受「历史包袱」影响：曾经狂热的块赖着不走；成本高 |
| **随机替换** | 随机挑一个淘汰 | 随机数发生器 | 任意（如摇到 2 就淘汰对应行） | 硬件最简单、速度最快 | 完全不用局部性，命中率不稳定 |

**LRU 位位数**：

$$\text{每块的 LRU 替换位} = \log_2(\text{组内块数})\ \text{bit}$$

2 路组相联需 1 位，4 路需 2 位，8 路需 3 位。

**LRU 手工模拟的标准做法**（必考题型）：在组内维护一个「最近访问顺序」队列，每次访问（无论命中还是缺失）都执行两步：

1. **命中**：把被命中的块移到队列**最前端**（标记为最新）。
2. **缺失**：淘汰队列**最末端**的块，把新块放到最前端。

初始时若组内有空位，直接填空位，不算替换。判断最终命中次数时，逐项走一遍即可。

:::warn 替换算法模拟的三个坑
1. **命中的访问也要更新 LRU 顺序**。很多同学只在缺失时动队列，导致后续淘汰对象选错。
2. **FIFO 与 LRU 在「命中是否影响顺序」上完全不同**：FIFO 的进入顺序不受命中影响；LRU 受。
3. **LFU 的计数器只在命中时加 1**，缺失调入的新块计数器从 1（或 0）开始，且并列时必须说明用什么规则打破平局。题目没给就按 FIFO 处理。
:::

### Cache 写策略

Cache 中存放的是主存的**副本**。写操作若只改 Cache 不改主存，就会出现不一致：DMA 设备读到旧数据、多核中另一个核读到过期值、程序崩溃后主存状态错误。解决靠**写策略**，分写命中与写缺失两种情形。

#### 写命中时的策略

**写直通法（Write-Through，又称全写法、写穿法）**

- 写操作**同时更新 Cache 与主存**，任何时刻两者保持一致。
- 优化：配置**写缓冲（Write Buffer）队列**。CPU 写完 Cache 后把写请求放入写缓冲，由写缓冲异步更新主存，CPU 不必等待主存写完。

| 维度 | 说明 |
|---|---|
| 一致性 | **始终一致**，主存任何时刻都是最新值 |
| 写速度 | **慢**（每次写都要访问慢速主存，靠写缓冲缓解） |
| 实现复杂度 | **简单**，**不需要脏位** |
| 总线带宽 | 占用多（每次写都产生主存访问） |

**写回法（Write-Back，又称回写法）**

- 写操作**只更新 Cache**，不立即写主存；只有当该行被**替换**时才写回主存。
- 关键机制：**脏位（Dirty Bit）**，每行 1 位。
  - 脏位 = 1：该行被 CPU 修改过，与主存不一致，**淘汰前必须先写回主存**。
  - 脏位 = 0：该行与主存一致，可直接覆盖，无需写回，节省主存带宽。

| 维度 | 说明 |
|---|---|
| 一致性 | **不能保证实时一致**，存在「脏数据窗口」 |
| 写速度 | **快**（绝大多数写操作只访问 Cache） |
| 实现复杂度 | **较复杂**，需要维护脏位 |
| 总线带宽 | 占用少（只有替换脏块时才写主存） |

**两种写命中策略对比**

| 对比维度 | 写直通法 | 写回法 |
|---|---|---|
| Cache 与主存一致性 | **实时一致** | 存在不一致窗口 |
| 每次写是否访问主存 | **必须访问** | 通常不访问 |
| 是否需要脏位 | **不需要** | **需要** |
| 适用场景 | 对一致性要求高（多核共享、DMA 频繁） | 对性能要求高（**主流 CPU**） |
| 是否配写缓冲 | **可以** | 不需要 |

#### 写缺失时的策略

**写分配法（Write-Allocate）**：写缺失时先把目标块从主存**调入 Cache**，再在 Cache 中执行写。设计动机是时间局部性——这个地址被写了，接下来很可能还会被读或再次被写。**通常搭配写回法。**

**非写分配法（No Write-Allocate）**：写缺失时**直接写主存**，不把该块调入 Cache。若写完之后短期内不再访问该地址，调块进来反而浪费空间、挤占更有价值的块。**通常搭配写直通法。**

| 对比维度 | 写分配法 | 非写分配法 |
|---|---|---|
| 写缺失时的处理 | 调块入 Cache 再写 Cache | 直接写主存，不动 Cache |
| 后续读命中率 | **更高**（块已在 Cache 中） | 较低 |
| Cache 空间利用 | 可能引入不常用块 | 不引入新块，节省空间 |
| 通常搭配 | **写回法** | **写直通法** |

#### 策略组合

实际系统中两种策略**成对使用**：

| 组合 | 逻辑链 | 定位 |
|---|---|---|
| **写回法 + 写分配法** | 写回法要把写操作留在 Cache 里 → 写命中直接改 Cache；写缺失就先把块调进来再改 | **主流 CPU，性能优先** |
| **写直通法 + 非写分配法** | 写直通法已保证每次写都到达主存，调块进来的意义很小 | **一致性优先** |

:::exam 写策略的统考考法
【2015-16】指令 `add xaddr, 3`，页式虚存 + TLB，Cache 采用**直写**，完成该指令**至少**访问主存几次？答：**B（1 次）**。取指时若 TLB 命中且 Cache 命中，访主存 0 次；取操作数同样假设 TLB 与 Cache 都命中，访主存 0 次；但**写回结果时直写策略要求同步写主存**，故至少 1 次。这正是「写直达法无法避免主存访问」的直接体现。
:::

:::warn 写策略四条易错
1. **写直通法不需要脏位，写回法必须要有脏位**。算 Cache 每行位数时，脏位是否计入完全取决于写策略。
2. **脏位 = 1 才需要写回**；脏位 = 0 的行被淘汰时直接覆盖，不产生主存写。
3. **写分配与写回、非写分配与写直通是「通常」搭配，不是强制**。理论上可以交叉，但那样会自相矛盾（写回 + 非写分配意味着写缺失时既不更新 Cache 又要等替换才写回，逻辑失效）。
4. **写缓冲只解决「CPU 等待」问题，不改变一致性语义**。它让 CPU 不必阻塞，但主存最终一定会被更新。
:::

## 虚拟存储器

### 虚拟存储器的基本概念

虚拟存储器不是独立的物理硬件，而是一套**硬件与操作系统协同实现**的内存管理技术。它要解决三个痛点：

1. **突破物理主存容量限制**：为程序员提供远超物理主存大小的连续、统一的编程地址空间。
2. **弥合 CPU 与外存的效率鸿沟**：以主存（DRAM）作为外存的高速缓存，减少对低速外存的直接依赖。
3. **支撑多进程安全并发**：为每个进程提供私有、隔离的虚拟地址空间。

**核心构件**：
- **虚拟地址 VA（Virtual Address，逻辑地址）**：应用程序视角的地址。
- **物理地址 PA（Physical Address）**：硬件实际用来寻址内存单元的地址。
- **MMU（Memory Management Unit，存储管理部件）**：集成在 CPU 内，负责地址转换与合法性校验。
- **页表基址寄存器 PTBR**：记录页表在主存中的首地址。**进程切换时只需改 PTBR**，即可完成页表切换。多级页表下 PTBR 存的是最顶层页表（页目录）的物理基址。

:::warn 「地址转换由谁完成」必须分清
- **OS（软件）负责**：创建页表、写入映射关系；修改 PTBR；处理缺页异常。
- **MMU（硬件）负责**：每次访存时查 TLB、翻译地址、做权限检查；TLB 缺失时遍历页表（硬件页表漫游器）。

一句话：**页表是软件写的，但「查页表」这个动作每次都是硬件做的**。所以「地址转换由 MMU 硬件完成」是正确的表述。
:::

**两类异常**：
- **缺页异常**：目标数据未载入主存。MMU 检测到后触发异常，CPU 从用户态陷入内核，由缺页处理程序完成外存→主存的页面调入并更新页表，之后**重新执行触发缺页的那条指令**（不是下一条！）。
- **存储保护异常**：地址越界、访问权限不符，由操作系统处理（终止进程或报错）。

**虚拟页与物理页**：虚拟页 VP（虚页/逻辑页）与物理页 PP（实页/**页框、页帧**）大小完全相等，故两者**页内偏移位数相同**。因虚拟存储器容量大于主存，**虚拟页号位数 > 物理页号位数**。

$$\text{虚拟地址} = \text{虚拟页号 VPN} + \text{页内偏移}, \qquad \text{物理地址} = \text{物理页号 PPN} + \text{页内偏移}$$

:::warn MMU 转换过程中「不会」检测的事件
【2024-18】下列事件**不是**在 MMU 地址转换过程中检测的是（ ）。答：**B. Cache 缺失**。MMU 负责虚→实转换，会检测访问越权、页面缺失、TLB 缺失。**Cache 缺失是在 MMU 完成地址翻译、CPU 拿着物理地址访问主存数据时才检测的**，二者不在同一环节。
:::

### 页式虚拟存储器

#### 基本原理

主存与虚拟地址空间都被划分为大小相等的**页**，内外存以页为单位交换信息。采用**请求分页**：只把活跃页面调入主存，非活跃页面留在辅存；访问到不在主存的页面时触发缺页异常。

页式虚拟存储器采用**全相联映射**（每个虚拟页可放到主存中任意一个空闲物理页框），因为缺页代价极高，必须把冲突缺失降到最低。

**Cache-主存与主存-辅存的定量对比**：Cache 容量 $\ll$ 主存 $\ll$ 辅存；Cache 访问速度 $\gg$ 主存 $\gg$ 辅存（主存比 Cache 慢 10～100 倍，辅存比主存慢约 10000 倍）。因此页面（4 KB～64 KB）远大于主存块（16/32/64 B），主存-辅存层次必然用全相联 + 写回。

#### 页表与页表项

每个进程由操作系统建立**独立**的页表，记录虚拟页到物理页/磁盘位置的映射。页表每一行是一个**页表项 PTE**：

| 字段 | 别名 | 作用 |
|---|---|---|
| **有效位（装入位）** | 存在位 | =1：虚页已调入主存，存放位置字段即物理页号；=0：未调入，若存放位置为 NULL 表示未分配，否则记录该页在磁盘上的起始地址 |
| **脏位（修改位）** | — | =1：页面已被修改，替换时需写回辅存；=0：可直接替换 |
| **引用位（使用位）** | 替换控制位 | 记录页面访问情况，LRU 算法中作为 LRU 位 |
| **访问权限位（保护位）** | 保护位 | 定义可读可写 / 只读 / 可执行，实现存储保护 |

#### 地址转换过程

**页表项地址的生成**：

$$\text{页表项地址} = \text{PTBR} + \text{虚拟页号} \times \text{页表项大小}$$

**完整过程（页面命中）**：

1. CPU 送出指令中的虚拟地址，交 MMU 转换；
2. MMU 用 PTBR 与虚拟页号生成页表项地址，访问主存中对应页表项；
3. 主存向 MMU 返回页表项；
4. 有效位 = 1，确认页面在主存，把**物理页号 + 页内偏移**拼接成物理地址，访问主存对应数据；
5. 主存向 CPU 返回目标数据。

**页面缺失（缺页）**：

1. 步骤 1～3 同上；
2. 有效位 = 0，MMU 触发**缺页异常**，调用操作系统缺页异常处理程序；
3. 主存已满时按替换算法选定待淘汰页面；若其脏位 = 1，需先写回磁盘，否则直接丢弃；
4. 缺页处理程序从磁盘把目标页面调入主存，更新页表项；
5. 返回原进程，**重新执行**触发缺页的指令，此次按命中流程完成访存。

**虚实地址转换算例**（【2022-15】）：主存地址 24 位，虚拟地址空间 4 GB，页大小 4 KB，按字节编址。访问虚拟地址 `00082840H`。

- 页大小 4 KB $=2^{12}$ → **页内偏移 12 位**；虚拟地址 32 位（4 GB）→ **虚页号 20 位**。
- 拆 `00082840H`：低 12 位 `840H` 是页内偏移，高 20 位 `00082H` 是虚页号。
- `00082H` $=8\times16+2 = 130$。查表：虚页号 130 的存在位 = 1，实页号 = `018H`。
- 主存地址 24 位，实页号占高 $24-12=12$ 位；查得的实页号位数正好，高 4 位补 0，拼接得 `018H` + `840H` = **`018840H`**。（答案 C）

**再算一例**（【2013-16】）：主存地址空间 256 MB，虚拟地址空间 4 GB，页大小 4 KB，TLB 全相联 4 项。虚拟地址 `03FFF180H`。

- 页内偏移 12 位 → 虚页号 = `03FFFH`。
- 在 TLB 中找标记为 `03FFFH` 的表项：有效位 = 1，页框号 = `0153H`。
- 物理地址 $= \text{页框号} \times 4\text{KB} + \text{偏移} = \text{`0153180H`}$。（答案 A）

:::warn 虚实转换题的三步固定套路
1. **先由页大小定页内偏移位数** $=\log_2(\text{页大小})$，其余高位是虚页号；
2. **拆地址、算虚页号、查表**（十六进制先转十进制或直接按位看，注意别数错位数）；
3. **物理地址 = 页框号 << 偏移位数 + 原偏移**，同时要检查「页框号位数 + 偏移位数」是否等于物理地址位数，不足补 0、多余则本身信息量不够（此时题目通常会设计得刚好）。

**缺页的返回点**：缺页属于内部异常中的**故障（Fault）**，处理完成后必须**重新执行原指令**，这一点【2019-14】考过——选项「回到发生缺页的指令的下一条指令执行」是错的。
:::

#### 使用快表 TLB 加速地址转换

Cache 虽能缓存部分页表块，但块粒度较大，不能充分利用虚存访问的局部性。于是处理器维护**转换旁路缓冲区 TLB（Translation Look-aside Buffer）**，专门缓冲经常访问的**页表项**。

$$\text{TLB 的关键字} = \text{虚拟页号 VPN}$$

TLB 本质是一个容量很小的 Cache：
- **大多采用全相联或组相联**方式，且多采用**随机替换**算法。
- TLB 离 CPU 更近、更快，称**快表**；主存中的页表称**慢表**。
- 典型容量 32～1024 项（1～2 级）。

**全相联 TLB 的工作逻辑**：虚拟地址分为「虚拟页号 + 页内偏移」。MMU 把虚拟页号与 TLB 内**所有表项的 Tag 并行比较**，若 Tag 匹配且有效位 = 1 则命中，直接取物理页号与页内偏移拼接。

**组相联 TLB 的工作逻辑**（以 2 路为例）：虚拟地址的 VPN 部分划分为「**TLB 标记 + TLB 组索引**」。MMU 用组索引定位到对应组（每组 2 项），把 TLB 标记与组内 2 项的标记**并行比较**，结果与有效位做逻辑与，生成选择信号，选中的物理页号与页内偏移拼接。

:::key TLB 表项的位数计算
$$\text{VPN 位数} = \text{虚拟地址位数} - \log_2(\text{页大小})$$
$$\text{组索引位数} = \log_2\left(\frac{\text{TLB 表项数}}{\text{路数}}\right)$$
$$\text{TLB 标记位数} = \text{VPN 位数} - \text{组索引位数}$$
$$\text{物理页号位数} = \text{主存地址位数} - \log_2(\text{页大小})$$
:::

**算例**（【2024-17】）：虚拟地址 32 位，主存地址 30 位，页大小 1 KB，TLB 共 32 个表项，**4 路组相联**，求 TLB 标记字段至少几位。

- 页内偏移 $=\log_2 1\text{KB}=10$ 位 → **VPN $=32-10=22$ 位**。
- 组数 $=32/4=8$ → **组索引 3 位**。
- **TLB 标记 $=22-3=19$ 位**。（答案 C）

#### TLB、页表、Cache 的组合访问

主存数据分两类：存储页表内容的**页表块**与存储程序数据的**数据块**。页表块同样会被 Cache 缓存（Cache 硬件不区分内容，只按访问频度缓存）。

**三种典型情形**：

- **理想情况（不访问主存）**：页表项在 Cache 中命中，数据也在 Cache 中命中。只需 2 次 Cache 访问（第一次拿页表项，第二次拿数据）。
- **较糟糕情况（访问主存 2 次）**：无缺页（页在主存），但页表项在 Cache 中缺失、数据也在 Cache 中缺失。需 2 次主存访问，并把两个块分别调入 Cache。
- **最糟糕情况**：在最糟糕情况基础上，访问目标数据触发**缺页**，需要访问磁盘。

**TLB、页、Cache 命中/缺失组合的可行性**：

| 场景 | TLB | 页 | Cache | 可行性 | 说明 |
|---|---|---|---|---|---|
| 最好：不访主存 | 命中 | 命中 | 命中 | 可能 | TLB 命中则页必命中 |
| 访主存 1 次 | 命中 | 命中 | 缺失 | 可能 | 数据在主存但不在 Cache |
| 访主存 1 次 | 缺失 | 命中 | 命中 | 可能 | TLB 缺失但页仍在主存 |
| 访主存 2 次 | 缺失 | 命中 | 缺失 | 可能 | 两次主存：查页表 + 取数据 |
| 最糟：访磁盘 | 缺失 | 缺失 | 缺失 | 可能 | 页不在主存，数据必然不在 Cache |
| **不可能** | **命中** | **缺失** | 缺失 | **不可能** | 页缺失说明信息不在主存，TLB 中不可能有有效表项 |
| **不可能** | **命中** | **缺失** | 命中 | **不可能** | 同上 |
| **不可能** | 缺失 | **缺失** | **命中** | **不可能** | 页缺失则数据不在主存，必然不在 Cache |

:::key 一句话记住「不可能」：TLB 命中 ⇒ 页必命中
TLB 是页表的缓存，只有当一个页面已经调入主存（页命中）时，它的有效映射才可能被缓存到 TLB 中。所以「**TLB 命中而页缺失**」永远不可能出现。同理，**页缺失 ⇒ Cache 必然缺失**（数据根本不在主存）。
:::

#### TLB 与 Cache 的对比

| 对比维度 | Cache | TLB |
|---|---|---|
| 缓存对象 | 主存中的**数据/指令块** | 内存页表中的**页表项** |
| 查询 key | **物理地址**（块号部分） | **虚拟页号 VPN** |
| 输出结果 | 数据内容 | **物理页号 PPN + 权限** |
| 解决的问题 | CPU 与主存的速度差 | 每次地址翻译都要访主存查页表的开销 |
| 位置 | CPU 芯片内（L1/L2/L3） | MMU 内部 |
| 典型容量 | 32 KB～32 MB（多级） | 32～1024 项（1～2 级） |
| 映射方式 | 直接 / 组相联 / 全相联 | **全相联或组相联** |
| 缺失处理 | **硬件自动完成** | **硬件或 OS（视架构）** |
| 组成器件 | **SRAM** | **SRAM / CAM** |
| **进程切换** | **无需刷新**（key 是物理地址，全局唯一） | **需要刷新**（key 是虚拟地址，不同进程同 VA 映射不同 PA） |

一句话区分：**Cache 加速「取数据」，TLB 加速「找地址」。**

:::exam TLB 与 Cache 的统考考法
【2010-17】不可能发生的命中组合？答 **D（TLB 命中、Cache 命中、Page 未命中）**——理由同上。
【2020-15】关于 TLB 和 Cache 的错误叙述？答 **D（都由 DRAM 组成）**。两者都由 **SRAM/CAM** 组成（追求与 CPU 匹配的速度）；只有主存才由 DRAM 组成。其余 A（命中率都与局部性有关）、B（缺失后都要访主存）、C（缺失处理都可由硬件实现）都正确。
【2024-18】见前文「MMU 不检测 Cache 缺失」。
:::

#### 多级页表

单级页表要求**整张页表在主存中连续存放**，当虚拟地址空间很大而实际使用的页面很少时会浪费大量主存。多级页表把页号**分级**，每级页表自身也存成一个页面，**按需分配**。

**虚页号位数与页表大小**：设虚拟地址 $n$ 位、页大小 $2^p$ 字节、页表项 $e$ 字节：

$$\text{虚页号位数} = n-p, \qquad \text{页表项数} = 2^{n-p}, \qquad \text{单级页表大小} = 2^{n-p}\times e \ \text{字节}$$

$$\text{一级页号位数} = p - \log_2 e, \qquad \text{页表级数} = \left\lceil \frac{n-p}{p-\log_2 e} \right\rceil$$

**算例**：虚拟地址 32 位，页大小 4 KB，页表项 4 B。

- 虚页号 $=32-12=20$ 位 → 页表项数 $=2^{20}=1\text{M}$ 项 → 单级页表 $=1\text{M}\times4\text{B}=4\text{ MB}$，且必须**连续**分配 4 MB。
- 采用两级页表：每级页表自身占一个 4 KB 页面 = 1024 个页表项 → **每级页号 10 位**（$10+10=20$ ✓）。
- 一级页表（**页目录**）只占 4 KB；每个二级页表也只占 4 KB，只为**实际用到**的虚页号区间分配二级页表。

**算例**：虚拟地址 48 位、页大小 4 KB、页表项 8 B。$p=12$，$\log_2 e = 3$，每级页号 $=12-3=9$ 位；虚页号 $=48-12=36$ 位；级数 $=\lceil 36/9\rceil = 4$ 级。这与 x86-64 实际使用的 4 级页表一致。

:::warn 多级页表的两点澄清
1. **多级页表降低的是「页表本身占用的连续主存空间」，不是「一次地址转换的访存次数」**。相反，级数越多、TLB 缺失时遍历页表的访存次数越多（4 级页表在 TLB 缺失时最多需 4 次读主存）。实际中靠 TLB 命中 + Cache 缓存页表块把开销压下来。
2. **能装下页面的最小单位就是「页」**。页表项数不得超过一页能装下的项数，即每级页号位数 $= p - \log_2 e$，因为一级页表必须正好占一个页面。
:::

### 段式虚拟存储器

**基本原理**：按程序的**逻辑结构**（函数、代码段、数据段、堆、栈等）把虚拟地址空间划分为**长度不等**的段。每段从 0 开始编址，段内地址连续。

**虚拟地址结构**：`[段号 S][段内偏移 W]`。

**段表**：每个进程一张，每个段一个段表项。段表项含：

| 字段 | 含义 |
|---|---|
| **段长** | 该段的长度（用于越界检查） |
| **段基址** | 该段在主存中的起始物理地址 |
| 有效位 / 装入位 | 该段是否已调入主存 |
| 访问权限 | 可读 / 可写 / 可执行 |
| 修改位、访问位 | 供替换使用 |

**地址转换**：

$$\text{物理地址} = \text{段表项中的段基址} + \text{段内偏移}$$

转换时**必须检查段内偏移是否超过段长**，超过则触发越界异常（这是段式存储管理的核心保护机制，页式则不需要，因为页内偏移位数天然不会越界）。

**优点**：按逻辑单位划分，便于**共享**（多个进程段表项指向同一段基址）、便于**保护**（按段设权限）、便于**动态链接**与**动态增长**（段长可变）。
**缺点**：段长不等导致主存分配复杂，易产生**外部碎片**；需要拼接段基址与段内偏移。

### 段页式虚拟存储器

**基本思想**：先按逻辑结构**分段**，再把每段**分页**。兼取段式「便于共享保护」与页式「无外部碎片、分配简单」的优点。

**虚拟地址结构**：`[段号 S][段内页号 P][页内偏移 W]`。

**查找过程（两次查表）**：

1. 用段号查**段表**，得到该段**页表的起始地址**与段长（用于越界检查）；
2. 用段内页号查**页表**，得到**物理页号（页框号）**；
3. 物理页号与页内偏移拼接成物理地址。

**地址转换效率问题**：

$$\text{段页式一次访存的主存访问次数} = 3\ \text{次（查段表} + \text{查页表} + \text{取数据）}$$

所以段页式必须配 TLB。**TLB 中直接缓存「段号 + 段内页号 → 物理页号」的完整映射**，命中时一次即可得到物理页号，避免两次查表。

:::warn 段页式题目的两条注意
1. **地址字段是三段，不是两段**。只写「段号 + 页内偏移」是错的，必须包含段内页号。
2. **越界检查在段这一级做**（用段表中的段长），页这一级不需要。
:::

:::exam 虚拟存储器的统考考法汇总
| 年份题号 | 考点 | 答案要点 |
|---|---|---|
| 2010-17 | TLB/页/Cache 组合 | 不可能：TLB 命中而页缺失 |
| 2013-16 | TLB 全相联查表 | `03FFF180H` → `0153180H` |
| 2015-16 | 虚存 + 直写访存次数 | 至少 1 次（写回结果必须写主存） |
| 2019-14 | 缺页处理 | 返回**原指令**重新执行 |
| 2020-15 | TLB 与 Cache 对比 | 都由 SRAM/CAM 组成，不是 DRAM |
| 2022-15 | 页式地址转换 | 页内偏移 12 位，`00082H`=130 → `018840H` |
| 2024-16 | 两个层次的对比 | 主存-外存层次是**全相联**，不是直接映射 |
| 2024-17 | TLB 标记位数 | VPN 22 位 − 组索引 3 位 = 19 位 |
| 2024-18 | MMU 检测的事件 | Cache 缺失不在 MMU 阶段检测 |
:::

:::key Cache-主存与主存-辅存四条对照（【2024-16】的核心）
1. **交换单位**：Cache-主存用**块**，主存-辅存用**页** ✓
2. **实现者**：Cache-主存的替换由**硬件**实现，主存-辅存的替换由**软件（OS）**实现 ✓
3. **写策略**：Cache-主存可回写或直写；主存-辅存**必然回写** ✓
4. **映射方式**：Cache-主存可用直接/组相联/全相联；主存-辅存**通常用全相联**——所以说「主存-外存层次通常采用直接映射方式」是**错的**。
:::

| 知识点 | 核心结论 |
|---|---|

| DRAM 刷新 | 按行、不需列地址、地址由内部计数器产生；集中/分散/异步三种 |

| 集中刷新死区 | $=\text{行数}\times t_c$；行数越多死区越长 |

| 芯片扩展 | 位扩展片数 $=N/n$，字扩展组数 $=M/m$，总片数 $=(N/n)(M/m)$ |
| 位扩展连接 | 地址/CS/WE 全并联，**数据线各自独立**，各片同时工作 |
| 字扩展连接 | 数据/低位地址/WE 全并联，**片选各自独立**，各片分时工作 |
| 线选法 | 无译码器、地址空间**不连续**、有空洞 |
| 译码片选法 | 需译码器、地址空间**连续**、主流方案 |
| MAR 位数 | 由**主存地址空间**决定，与实际安装容量无关 |
| 多模块编址 | 高位交叉（顺序）：相邻地址同体，不能并行；低位交叉：相邻地址异体，可流水 |
| 低位交叉体号 | $\text{体号} = \text{地址} \bmod m$ |
| 低位交叉时间 | 准备 $n$ 个字：$T+(n-1)\tau$；总时间 $T+(n+1)\tau$；流水条件 $T=m\tau$ |
| 低位交叉吞吐 | 稳定流水时一个存储周期提供 $m$ 个字，平均每字 $\tau$ |
| 访存冲突 | 同体且序列间隔步数 $<m$ |
| 磁盘组成 | 磁盘控制器 + 磁盘驱动器 + 盘片；**磁头号 = 盘面号**，**磁道号 = 柱面号** |
| 磁盘地址结构 | （驱动器号，柱面号，盘面号，扇区号）；柱面号在前以省寻道 |
| 平均存取时间 | 寻道时间 + 旋转延迟 + 传输时间（+ 控制器延迟） |
| 旋转延迟 | $T_r = 1/(2r)$（r 转/秒）$= 30/r$ 秒（r 转/分） |
| 传输时间 | $T_t = b/(rN)$，$b$ 为字节数、$N$ 为每磁道字节数、$r$ 转/秒 |
| 容量 | 格式化容量 $<$ 非格式化容量；格式化容量 $=$ 柱面 $\times$ 盘面 $\times$ 每道扇区 $\times$ 每扇区字节 |
| 磁盘读写单位 | **扇区**，不是字节 |
| RAID | 镜像与奇偶校验提高可靠性；条带化只提性能，不提供冗余 |
| SSD 读写 | 以页读写、以块擦除；写前必擦；随机访问快、无寻道与旋转延迟 |
| 磨损均衡 | 动态：优先选擦除次数少的块；静态：自动迁移数据，老块承担读任务（更优） |
| Cache 组成 | SRAM；内容为主存副本，**不增加系统总容量**；对程序员透明 |
| Cache 标识位 | 有效位 V + 标记 Tag（+ 写回时脏位） |
| 命中率与平均访问时间 | 串行：$T_a=t_c+(1-h)t_m$；并行：$T_a=h t_c+(1-h)t_m$ |
| 访问效率 | $e = t_c / T_a$ |
| 直接映射 | 行号 $=$ 块号 mod 行数；Tag 最短；1 个比较器；**无需替换算法** |
| 全相联 | 任意行；只有 Tag + 块内地址；$n$ 个比较器；命中率最高 |
| 组相联 | 组号 $=$ 块号 mod 组数，组内任意；$k$ 个比较器；**最常用** |
| 退化关系 | $k=1$ 退化为直接映射；组数 $=1$ 退化为全相联 |
| 地址划分 | $c=\log_2$ 行数（或 $d=\log_2$ 组数），$w=\log_2$ 块大小，$t=n-c-w$ |
| 每行位数 | Tag + 有效位 1 + 数据（+ 写回时脏位 1） |
| FIFO | 淘汰最早进入者；简单；可能 Belady 异常 |
| LRU | 淘汰最久未访问者；命中率最高；LRU 位 $=\log_2$ 组内块数 |
| LFU | 淘汰访问次数最少者；有历史包袱；并列需打破平局 |
| 写直达 | 同时写 Cache 与主存；**不需脏位**；可配写缓冲 |
| 写回 | 只写 Cache，替换时写回；**需要脏位**；主流 |
| 写分配 / 非写分配 | 写缺失时调块（配写回）/ 不调块直接写主存（配直写） |
| 页式虚存映射 | **全相联**；交换单位是页（4 KB～64 KB） |
| 虚实转换 | 页表项地址 $=$ PTBR $+$ VPN $\times$ 页表项大小；物理地址 $=$ 页框号 + 页内偏移 |
| 缺页返回点 | **重新执行原指令**，不是下一条 |
| TLB | VPN 作关键字；全相联或组相联；随机替换；**进程切换需刷新** |
| TLB 标记位数 | VPN 位数 $-$ 组索引位数 |
| TLB 与 Cache | Cache 用物理地址查、加速取数；TLB 用虚拟地址查、加速找地址 |
| 不可能组合 | TLB 命中而页缺失；页缺失而 Cache 命中 |
| 多级页表 | 每级页号位数 $=p-\log_2 e$；级数 $=\lceil (n-p)/(p-\log_2 e)\rceil$；按需分配、节省连续主存 |
| 段式 | 段长可变；地址 = 段号 + 段内偏移；需**越界检查**；便于共享保护，有外部碎片 |
| 段页式 | 段号 + 段内页号 + 页内偏移；查段表、页表两次，需 TLB 加速 |

## 易错清单

:::warn 本章最容易被扣分的地方
1. **以为 ROM 采用顺序存取**。ROM 与 RAM **都采用随机存取方式**，差别只在能否随意改写。
2. **把「半导体存储器都采用随机存取」当成正确**。全相联 Cache 的比较器、快表 TLB 是按内容访问（CAM）。
3. **把 CD-ROM 归入 ROM、把 SSD 归入磁盘**。CD-ROM 是光存储器；SSD 是半导体 Flash（EEPROM）。计算机术语中的 ROM 特指半导体芯片。
4. **混淆存取时间与存取周期**。算带宽、算连续读取最小间隔、算流水线启动间隔，必须用**存取周期 $T_C$**。
5. **把 MAR 位数与实际安装容量挂钩**。MAR 位数由**主存地址空间**决定，与装了多少内存无关（【2011-15】）。
6. **DRAM 地址引脚忘了除以 2**。$4\text{M}\times8$ 位 DRAM 只有 11 根地址引脚，不是 22 根；行列不等时取 $\max$。
7. **DRAM 引脚数被系统总容量干扰**。题目问「芯片」引脚数时，总容量只用于算片数。
8. **认为刷新需要列地址**。刷新按行进行，**只需行地址**，且由芯片内部刷新计数器给出，不需要 CPU 提供。
9. **集中刷新的死区与行数关系记反**。行数**越多**（矩阵越「高」），死区越长；所以设计上倾向减少行数、增加列数。
10. **把分散刷新的存取周期当成不变**。分散刷新把存取周期**拉长一倍**（读写 + 刷新各半），有效访存速度减半。
11. **字扩展时忘记位扩展**。$4\text{K}\times4$ 位芯片装 8 位宽内存必须先 2 片一组，否则片数少一半。
12. **SRAM 与 DRAM 的地址引脚混算**。SRAM 不复用地址，引脚数就是完整逻辑地址位数。
13. **低位交叉的体号算成高位**。体号 $=\text{地址} \bmod m$；若按地址除以 $m$ 取整，就变成高位交叉了。
14. **低位交叉时间公式漏掉总线开销**。准备 $n$ 个字是 $T+(n-1)\tau$，含送首地址与传送末字的总时间是 $T+(n+1)\tau$，两者别混用。
15. **访存冲突只比较体号**。必须同时满足「同体」且「序列间隔步数 $<m$」。
16. **磁盘旋转延迟的单位算错**。转速给 r/min 时用 $30/r$ 秒；给 r/s 时用 $1/(2r)$ 秒。题目用「r 秒/转」这类反向单位时要格外小心。
17. **把磁盘最小读写单位当成字节**。是**扇区**（传统 512 B）。
18. **认为格式化容量大于非格式化容量**。格式化要在每扇区加头、尾与间隔，所以**格式化容量更小**。
19. **Cache 映射时把「行数」与「组数」搞混**。组索引位数由**组数**决定，与路数无直接关系：$2^d$ 组就是 $d$ 位。
20. **写回忘加脏位、直写多算了脏位**。脏位只在写回策略下存在。
21. **地址位数计算时把 Cache 总容量当成数据区容量**。行数由**数据区**容量算；Tag 与元数据位只在算**总容量/每行位数**时才加。
22. **LRU 模拟时命中不更新顺序**。每次访问（无论命中与否）都要把被访问块移到「最新」位置。
23. **以为直接映射需要替换算法**。每个主存块只有唯一位置，调入即覆盖，**不需要任何替换算法**。
24. **认为 TLB 缺失与缺页是同一回事**。TLB 缺失只是快表里没有该表项，页可能仍在主存（此时只需查慢表）；缺页是页根本不在主存，必须访磁盘。
25. **写出「TLB 命中而页缺失」的组合**。这**不可能**发生——TLB 命中意味着该页已在主存。
26. **以为多级页表降低了一次地址转换的访存次数**。恰恰相反，级数越多，TLB 缺失时遍历页表的访存次数越多；多级页表省的是**页表本身占用的连续主存空间**。
27. **段式虚存忘了越界检查**。段长可变，必须检查段内偏移是否超过段长；页式不需要。
28. **段页式地址漏掉「段内页号」**。结构是 `段号 + 段内页号 + 页内偏移` 三段。
29. **认为缺页处理完成后执行下一条指令**。缺页属于**故障（Fault）**，处理完必须**重新执行原指令**。
30. **以为 Cache 缺失会陷入内核**。Cache 缺失完全由硬件处理，对程序员透明，不引起进程切换；只有缺页才由操作系统处理。
31. **说「Cache 增加了系统存储容量」**。Cache 只是主存的副本，**不增加总容量**；增加容量是虚拟存储器（主存-辅存层次）的目标。
32. **主存-辅存层次误以为用直接映射**。因缺页代价极高，主存-辅存层次采用**全相联**，且写操作**只回写**（【2024-16】）。
33. **认为 SSD 的读和写都比磁盘快**。SSD 随机访问性能与读性能优异，但**写操作要先擦块**，还可能触发数据迁移，不一定快。
34. **把「透明」理解成「看得见」**。体系结构中**透明 = 看不见 = 不需要管**。Cache 对程序员透明，是指程序员不用写任何调度 Cache 的代码。
:::

## 本章公式速查

| 公式 | 表达式 | 说明 |
|---|---|---|
| 存取周期 | $T_C = T_A + T_R$ | 恢复时间 $T_R$ |
| 存储器带宽 | $B_m = W / T_C$ | $W$ 为数据位宽（字节） |
| 硬件元数据 | $\text{元数据比例} = \dfrac{\text{每行位数}-\text{数据位数}}{\text{每行位数}}$ | 衡量 Tag 开销 |
| DRAM 地址引脚 | $p = \lceil \log_2 M / 2 \rceil$ 或 $\max(\log_2 r, \log_2 c)$ | $M$ 为字数 |
| 集中刷新死区 | $T_{\text{死区}} = r\cdot t_c$ | $r$ 为行数 |
| 异步刷新间隔 | $\Delta = T_{\text{max}} / r$ | $T_{\text{max}}$ 通常 2 ms 或 64 ms |
| 芯片总数 | $N_{\text{片}} = (N/n)(M/m)$ | 目标 $M\times N$、单片 $m\times n$ |
| 片内地址线 | $\log_2 m$ | 并联到所有芯片 |
| 片选译码位数 | $\log_2(M/m)$ | 接译码器 |
| 低位交叉准备时间 | $T+(n-1)\tau$ | 流水条件 $T=m\tau$ |
| 低位交叉总时间 | $T+(n+1)\tau$ | 含送首地址与传送末字 |
| 高位交叉准备时间 | $nT$ | 与并行无关 |
| 磁盘旋转延迟 | $1/(2r)$ 秒（r 转/秒）；$30/r$ 秒（r 转/分） | 平均半圈 |

| 组数 | $=\text{总行数} / \text{路数}$ | — |
| 地址字段 | $w=\log_2$ 块大小，$c$ 或 $d=\log_2$ 行数/组数，$t=n-c-w$ | — |

| LRU 位 | $\log_2(\text{组内块数})$ | — |
