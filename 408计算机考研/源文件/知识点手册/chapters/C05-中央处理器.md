## CPU 的功能和基本结构

### CPU 的功能

CPU（Central Processing Unit）由**运算器**和**控制器**两大部分构成。现代 CPU 还把 Cache、MMU（存储管理部件）、浮点运算部件、异常与中断处理逻辑集成到片内，但按「数据通路 + 控制部件」的两分法理解，任何复杂的 CPU 都不例外。

CPU 的四个基本功能：

- **指令控制**：控制指令的执行顺序。程序是指令的有序集合，CPU 必须保证指令按序取、按序执行，由 PC 保证。
- **操作控制**：产生每条指令的操作控制信号序列（即微命令序列），送到各执行部件的控制端。
- **时间控制**：对各种操作信号进行时间调制，规定每条控制信号的**产生时刻与持续时间**，即「什么时候送操作数、什么时候发运算控制、什么时候送结果」。
- **数据加工**：对数据进行算术运算、逻辑运算与逻辑测试。

:::key 一句话记住四条功能
**指令控制（顺序）+ 操作控制（命令）+ 时间控制（时序）+ 数据加工（算术逻辑）**。
:::

### 运算器的组成与各部件的作用

运算器的核心任务是「对数据进行加工」，由下列部件组成：

| 部件 | 英文/缩写 | 作用 |
| :--- | :--- | :--- |
| 算术逻辑单元 | ALU | 完成算术运算、逻辑运算；输出运算结果与标志 |
| 通用寄存器组 | GPRs / GR | 存放操作数、中间结果、地址信息；对**汇编程序员可见** |
| 暂存寄存器 | X、Y、Z 等 | 暂存 ALU 的输入操作数或输出结果；对程序员**透明** |
| 累加寄存器 | ACC | 通用寄存器之一，常作为 ALU 的一个输入端与结果的落点 |
| 移位器 | — | 对操作数或运算结果进行移位（左移、右移、算术/逻辑移位） |
| 程序状态字寄存器 | PSW / PSR / FLAGS | 保存 OF、SF、ZF、CF 等状态标志与中断、系统状态信息 |
| 计数器 | — | 控制乘、除运算的操作步数 |

需要特别说明的是**暂存寄存器为什么必需**。在单总线数据通路中，ALU 是纯组合逻辑部件，做一次运算时必须保证两个输入端**同时有效**。若第一个操作数从主存读出后直接放在总线上，等第二个操作数再经总线送出时前一个操作数已被总线上的新数据破坏，因此必须先把先到的操作数锁存到暂存寄存器 X（另一端固定接 ALU 输入）。同理，ALU 的输出端**不能直接连总线**，否则输出会经总线反馈到输入端形成竞争，所以运算结果要先锁存到暂存寄存器 Z（或 Y）。

- 暂存寄存器对应用程序员**透明**，不参与指令系统，不能用汇编指令直接访问。
- **累加寄存器 ACC 是通用寄存器**，与「暂存寄存器」性质不同：ACC 程序员可见，暂存寄存器不可见。
- 移位器不是所有运算器都必备，有的机器把移位功能做进 ALU，或让 ALU 输出直接接数据总线/地址总线。**做题时必须按题目给的框图判断**，不能想当然。

PSW 的作用有两个层次：

1. 保存算术逻辑运算或测试指令所产生的状态信息——**溢出标志 OF、符号标志 SF、零标志 ZF、进位/借位标志 CF、辅助进位 AF、奇偶标志 PF**。条件转移指令正是根据 PSW 的内容判定是否转移。
2. 保存**中断与系统工作状态**信息，如中断允许标志 IF、陷阱标志 TF、方向标志 DF、处理器工作状态位（内核态/用户态）。操作系统靠它判断 CPU 当前所处状态。

:::warn PSW 的两个高频陷阱
- **PSW 可能只在某些指令执行后改变**。普通传送指令（如 `MOV`）通常不改变标志位，因此「某指令执行后 ZF=1」这类判断要先看该指令是否影响标志。
- 「标志位由 ALU 产生」并不等于「ALU 是时序元件」。**ALU 仍是组合逻辑元件**，标志位只是它的组合输出，需要由 PSW 这个时序元件锁存才得以保存。
:::

### 控制器的组成与各部件的作用

控制器的任务是「根据指令、时序信号和状态条件产生控制信号」。

| 部件 | 英文/缩写 | 作用 |
| :--- | :--- | :--- |
| 程序计数器 | PC / IP | 存放**下一条**待执行指令的地址 |
| 指令寄存器 | IR | 存放**当前正在执行**的指令，其位数 = 指令字长 |
| 指令译码器 | ID | 把 IR 中的操作码翻译成译码信号，同一时刻只有一路有效 |
| 存储器地址寄存器 | MAR / AR | 存放将要访问的主存单元地址，经地址总线送主存 |
| 存储器数据寄存器 | MDR / DR | 存放从主存读出或将要写入主存的数据，是 CPU 与主存间的缓冲 |
| 微操作信号发生器 | CU | 综合译码信息、时序信号与状态条件，产生微命令序列 |
| 时序系统 | — | 产生时钟脉冲、机器周期、节拍电位等定时信号 |

各部件的工作脉络是：**PC → MAR → 主存 → MDR → IR → 译码器 → 微操作信号发生器 → 各部件控制端**。IR 中的地址码部分还要经地址生成逻辑（按寻址方式）加工，产生的地址按需要送入 PC、MAR 或运算部件。

### 各寄存器的位数与地址、字长的关系

这是选择题每年都可能出现的一类题，必须区分清楚「哪个寄存器由谁决定」。

**PC 与 MAR 由主存地址位数决定。**

- **MAR 的位数等于主存地址总线的位数**，即 $ \text{MAR 位数}=\log_2(\text{可寻址单元总数}) $。它反映的是最多能寻址多少个存储单元。无论取指令还是取操作数，地址都必须先送 MAR。
- **PC 的位数一般与主存地址总线位数相等**，因为 PC 保存的就是一个主存地址。

但如果题目问的是「**至少**需要多少位」，就要看指令在内存中的存放方式：

:::key 地址对齐如何压缩 PC 位数
若按字节编址、指令字长 32 位（4 B）且**按字边界对齐**存放，则任何一条指令的起始字节地址的低 2 位恒为 `00`。此时 PC 只需保存「对齐位置」的编号共 $ 2^{30} $ 个，即 **30 位**；形成真实字节地址时在低位补两个 0 即可。而 **IR 必须完整保存一条 32 位指令，至少需要 32 位**。

这就是「主存 4 GB、字长 32 位、按字节编址、32 位定长指令字、按字边界对齐」时答案取 **PC = 30 位、IR = 32 位**的原因。
:::

**MDR/IR 与机器字长、存储字长的关系。**

- **IR 的位数 = 指令字长**。定长指令系统中它等于机器字长（或者说指令字长）；变长指令系统中 IR 要能装下**最长**的指令。
- **MDR 的位数 = 存储字长**，因为 MDR 是 CPU 与主存之间一次数据交换的宽度。常见配置中存储字长与机器字长相等，所以有「MDR 位数 = 存储字长 = 机器字长」的说法；但**这一等式并不必然成立**。若主存的存储字长与机器字长不等（例如机器字长 64 位、存储字长 32 位），则 MDR 只需 32 位。

:::warn 位数关系的四个易错点
- **MAR 只看「可寻址单元个数」，不看编址方式本身**。按字节编址的 4 GB 主存，地址 32 位，MAR 就是 32 位；若按字（4 B）编址，则地址位数减 2，MAR 也随之减 2。
- **PC 与 MAR 一般都等于地址总线位数，但在「至少」类问题中 PC 可以更短**（靠地址对齐省掉低位）。
- **MDR 由存储字长决定，不由机器字长决定**，两者只是常常相等。
- **通用寄存器的位数 = 机器字长**（反映一次能处理的数据位数），与地址位数无关。32 位机中 GPR 32 位，但主存可能有 4 GB 即地址 32 位，两者数值相同只是巧合；若主存是 64 GB，则地址 36 位而 GPR 仍是 32 位。
:::

:::exam 真题考法
- 「汇编语言程序员可见的寄存器」——PC、通用寄存器、基址/变址寄存器、PSW 可见；**MAR、MDR、IR、微指令寄存器、暂存寄存器、控制存储器（CM）不可见**。可见性的判据是「程序能否通过指令语义观察或改变它的状态」，而不是「能否把它直接当操作数写在汇编里」。
- 「PC 和 IR 的位数至少是多少」——按上面对齐法算。
- 「时钟脉冲信号」的性质：时钟周期由机器脉冲源经整形分频产生，其倒数是主频；同步时序电路要求的时钟周期不短于「寄存器之间最长组合逻辑路径传播时间 + 寄存器建立时间」。但**「每来一个时钟脉冲就执行一条新指令」是错的**：多周期 CPU 中一条指令占多个时钟周期，流水线被阻塞时也可能没有新指令进入。
:::

## 指令执行过程

### 指令周期的层级：指令周期、机器周期、时钟周期

一条指令从主存取出到执行完毕所需的全部时间称为**指令周期（instruction cycle）**。它是 CPU 执行一条指令的时间，是本章时序分析的最高层级。指令周期可以划分为若干**机器周期（CPU 周期）**，每个机器周期又可以划分为若干**时钟周期（节拍脉冲 / 振荡周期）**。三者是层层包含的关系：

$$ \text{指令周期} \supset \text{机器周期} \supset \text{时钟周期},\qquad T_{\text{指令}}=\sum_{i} T_{\text{机器}i},\qquad T_{\text{机器}}=\sum_{j} T_{\text{时钟}j} $$

| 层级 | 定义 | 能完成的工作 | 由什么决定 |
| :--- | :--- | :--- | :--- |
| 指令周期 | 取出并执行一条指令的全部时间 | 一条完整指令 | 指令功能、寻址方式、是否发生中断 |
| 机器周期 | 从主存读出一个指令字所需的最短时间 | 一个较复杂的基本操作（如一次存储器读或写） | **通常以主存工作周期为基础确定** |
| 时钟周期 | 主频的倒数（$ T=1/f $） | 一次微操作 | 机器脉冲源经整形分频 |

关于机器周期的宽度，考纲与统考的口径是：**机器周期的宽度通常以主存工作周期为基础来确定**。原因是主存的读/写周期比 CPU 内部的一次运算操作长得多，若以 CPU 内部操作为准，则存储器根本来不及响应。

**不同指令的指令周期长度不同**，这是理解取指、间址、执行、中断四周期的关键：

- 空操作指令 NOP：只包含取指周期（但仍会改变 PC 与 IR）。
- 无条件转移指令 JMP：包含取指周期 + 执行周期。
- 采用间接寻址的指令：多出一个**间址周期**。
- 在指令结束时若检测到中断请求：多出一个**中断周期**。

因此，一个完整的指令周期可能包含 **取指周期、间址周期、执行周期、中断周期** 四个阶段，其中执行周期可以有 0～n 个机器周期。

:::key 三条必背结论
1. **任何指令的指令周期都至少包含一个机器周期，也至少包含一个时钟周期**，即 $ T_{\text{指令}}\ge T_{\text{机器}}\ge T_{\text{时钟}} $。因此「指令周期一定大于或等于一个 CPU 时钟周期」是正确的。
2. **只要不采用 Cache 和不采用指令预取，每条指令的指令周期中 CPU 至少访问内存一次**（取指）。
3. **指令周期的长度由功能决定，不由时钟周期数固定**。单周期 CPU 中所有指令都占 1 个时钟周期，但那个时钟周期必须覆盖最慢指令的完整通路，所以周期很长、主频很低。
:::

### 取指周期的流程与数据通路

取指周期的任务是「按 PC 从主存取出指令送入 IR，并形成下一条指令地址」。用寄存器传送语言（RTL，Register Transfer Language）描述为：

```plain
(PC)   → MAR          ；现行指令地址送地址寄存器
(MAR)  → MDR  等价于 M(MAR) → MDR   ；按地址读出指令字
(MDR)  → IR           ；指令送指令寄存器
(PC)+1 → PC           ；形成下一条指令地址（"1" 表示一条指令的长度）
```

对应的控制信号序列（以单总线数据通路为例）：

| 时钟 | 数据通路（微操作） | 控制信号 |
| :--- | :--- | :--- |
| C1 | (PC) → MAR | PCout，MARin |
| C2 | M(MAR) → MDR；(PC)+1 → PC | read，MDRinE，PCinc（+1） |
| C3 | (MDR) → IR | MDRout，IRin |

操作控制器在取指周期要发出 `PCout`、`MARin`、`read`、`MDRinE`、`MDRout`、`IRin`、`PCinc` 等信号。注意第三步不能与第二步合并：数据从主存读出并稳定地出现在 MDR 上需要时间，同一时钟周期内不能既完成访存又完成经总线向 IR 的传送。

### 间址周期的流程与数据通路

间址周期的任务是「**取出操作数的有效地址**」。它在取指周期结束后，由译码器分析 IR 确定该指令使用了间接寻址才进入。以 `MOV R1, (05H)` 这类源操作数采用间址寻址的指令为例：

```plain
Ad(IR) → MAR          ；把形式地址（05H）送地址寄存器
1      → R            ；发读命令
M(MAR) → MDR          ；从主存读出有效地址
(MDR)  → Ad(IR)  或者  (MDR) → MAR   ；有效地址送回地址码字段或直接送 MAR
```

| 时钟 | 数据通路（微操作） | 控制信号 |
| :--- | :--- | :--- |
| C4 | Ad(IR) → MAR | AD(IR)out，MARin |
| C5 | M(MAR) → MDR | read，MDRinE |
| C6 | (MDR) → MAR | MDRout，MARin |

**间址周期每增加一次间接寻址，就要多访问一次主存。**一次间址需要一个完整的机器周期（因为必须访存一次）。

:::key 取指微程序与间址微程序的关系
取指周期的微程序是**公共的**，对每条机器指令都相同，微程序控制器直接提供；而间址周期与执行周期的微程序是在取指结束后、由指令译码器分析操作码**一次性**生成的，然后在各自阶段的时钟到来时分别启动。这一点是理解微程序控制器「下地址逻辑」的关键。
:::

### 执行周期的流程与数据通路

执行周期的任务是「根据 IR 中指令字的操作码和操作数，经 ALU 处理后产生执行结果」。**不同指令的执行周期操作不同，没有统一的数据流向**，这是它与其他三个周期的根本区别。

仍以「`MOV R1, (05H)`，源操作数间址」为例：间址周期已取得有效地址并放入 MAR，执行周期要把该地址中的数据写入 R1：

| 时钟 | 数据通路（微操作） | 控制信号 |
| :--- | :--- | :--- |
| C7 | M(MAR) → MDR | read，MDRinE |
| C8 | (MDR) → R1 | MDRout，R1in |

各类指令在执行周期中的典型微操作（单总线结构、只涉及单次传送的示例）：

- 寄存器之间传送：`(R1) → R2`，一个时钟周期，`R1out`、`R2in`。
- 加法运算并写回：`(R1)→Y`；`(ACC)+(Y)→Z`；`(Z)→ACC`，**需 3 个时钟周期**，因为任何时刻总线上只能有一个数据。
- 存数：`(R1)→MDR`；`(R2)→MAR`；`MDR→M(MAR)`，通常 3 个时钟周期。
- 转移：`Ad(IR) → PC`，一个时钟周期，`IRout`、`PCin`。

### 中断周期的流程与数据通路

中断周期发生在一条指令执行结束、且检测到中断请求并允许响应时，任务是**保存断点并转去中断服务程序**。若将断点保存在栈中、SP 指向栈顶、进栈操作为「先修改指针后送入数据」，则：

```plain
(SP)-1 → SP           ；栈指针先减 1（若约定 SP 指向栈顶空单元则改为 (SP)→MAR 后再 (SP)-1→SP）
(SP)   → MAR          ；断点要存入的存储单元地址送 MAR
1      → W            ；发写命令
(PC)   → MDR          ；把断点（当前 PC）送 MDR
(MDR)  → M(MAR)       ；断点写入主存
向量地址 → PC         ；中断服务程序入口地址送 PC，转向服务程序
```

中断周期的微操作可概括为：**关中断、保存断点、引出中断服务程序**。这三件事由**中断隐指令**完成（详见异常与中断机制一节）。

### 各周期微操作的通用分析方法

综合题的答题步骤可以固定为：

1. **列时序**：先确定这条指令要经历哪几个周期（取指？间址？执行？中断？）。
2. **标数据流**：每个周期写出所有必须在同一时刻完成的 RTL 微操作。
3. **查冲突**：同一时钟周期内检查三条「一」规则——同一寄存器只出现一次、同一总线只使用一次、主存/ALU 只访问一次。
4. **数周期**：每个时钟周期完成一次不冲突的数据传送，周期数即为时钟数。

:::warn 指令执行过程的常见陷阱
- **「空操作指令的指令周期中任何寄存器内容都不改变」是错的**。NOP 不完成显式数据运算，但取指仍会改变 PC（自增）和 IR。
- **「每个时钟周期都开始执行一条新指令」是错的**（多周期、流水线阻塞都不成立）。
- **外中断在指令执行结束后检测，内中断（异常）在指令执行过程中检测**。混用这两句几乎必错。
:::

## 数据通路的功能和基本结构

### 数据通路的定义与组成元件

**数据通路（datapath）**：指令执行过程中数据所经过的路径，以及路径上涉及的部件。数据通路由**操作元件**和**状态元件**两类元件组成，二者必须分清：

| 类别 | 别名 | 特性 | 典型部件 |
| :--- | :--- | :--- | :--- |
| 组合逻辑元件 | 操作元件 | 输出只取决于当前输入，不受时钟控制，无记忆 | ALU、加法器、移位器、多路选择器 MUX、译码器、扩展器 |
| 时序逻辑元件 | 状态元件 | 能保存状态，受时钟驱动，有记忆 | PC、IR、MAR、MDR、通用寄存器组、暂存寄存器、PSW、流水段寄存器、存储器 |

:::key 判据
「**这个部件会不会记住上一次的结果**」——会记住的是状态元件，不记住的是操作元件。

- ALU、MUX、扩展器、加法器：操作元件。
- PC、GPRs、暂存寄存器 X/Z、流水段寄存器：状态元件。
- 通用寄存器组的**读操作是组合逻辑**（给地址就有数据输出），**写操作是时序逻辑**（要时钟沿触发），因此 GPRs 可以在同一个时钟周期内完成一次「读 + 写」。
:::

数据通路由控制部件产生的控制信号控制：寄存器的写使能、MUX 的选择端、ALU 的功能选择、存储器的读写控制，都来自控制器。

:::warn 容易混淆的两条
- **生成控制信号的控制部件本身不属于数据通路**。所以「指令流水线的数据通路包含生成控制信号的控制部件」是错的。
- **数据通路要包含（或配合）异常事件的检测与响应电路**：如运算溢出检测、地址越界/对齐检测、以及异常入口所需的状态保存和 PC 选择通路。所以「数据通路不包含用于异常事件检测及响应的电路」是错的。
:::

### 单总线结构的数据通路

把 ALU 和所有寄存器都连到**一条**内部公共总线上，就是单总线结构。

- 由于单总线上某一时刻只能有一个部件输出数据，运算器必须配置暂存寄存器 **X**（暂存 ALU 的一个操作数）与 **Z**（暂存运算结果）；ALU 的另一个操作数直接来自内总线。
- 所有向总线输出的部件都通过**三态门**控制，防止总线冲突；`PCout`、`MDRout`、`IRout`、`Rout`、`Zout` 等是互斥的。
- **单总线结构不能用来实现单周期处理器**：一条稍复杂的指令需要多次总线传送，一个时钟周期内根本做不完。因此单周期 CPU 必须使用专用数据通路。

在单总线结构中，「某一时刻总线上只有一个数据有效」决定了**每一组必须前后相继的传送各占一个时钟周期**。

### 多总线结构与专用数据通路

- **多总线结构**：CPU 内部有两条或更多条总线。三条总线时，总线 A、B 分别传送两个源操作数，总线 C 传送结果，因此**暂存寄存器 Y、Z 可以取消**（三条总线各传不同数据，不会冲突）。配合双口通用寄存器组，`R[R3] ← R[R1] op R[R2]` 只需**一个时钟周期**。
- **专用数据通路**：按指令执行过程中数据与地址的流动方向安排专门连接，不使用共享总线。优点是**避免资源竞争、性能高、便于实现流水线**；缺点是**硬件量大**。现代处理器普遍采用专用数据通路。

在专用通路中，若要把一个寄存器的内容传送到另一个寄存器，通常**借道 ALU 完成**（控制 ALU 做「直送」操作）。

:::exam 真题考法
「单周期处理器为什么不能采用单总线结构」几乎每年都以不同形式出现。答题要点是：单总线一次只能完成一次数据传送，而单周期要求所有指令在一个时钟周期内完成（CPI=1），两者矛盾。单周期的代价是**时钟周期必须按最慢指令的关键路径确定，主频低**；其好处是控制信号在整条指令执行期间保持不变，不需要复杂的时序控制。
:::

### 数据通路的数据传送过程与时钟周期数计算

这是主频最高的大题考点。核心方法论只有一句：**一个时钟周期完成一次不发生冲突的数据传送；凡是必须在不同时刻发生的传送，就要各占一个时钟周期。**

给出两条硬性规则（可直接用于排节拍）：

1. 同一节拍中，**同一寄存器只能出现一次**（不能既读又写同一寄存器作为源和目的）。
2. 同一节拍中，**同一条总线只能使用一次**；同一节拍中**只访问主存一次、只访问 ALU 一次**。

**完整算例：单总线数据通路执行 `MOV R1, (R2)`（源操作数间址寻址），计算所需时钟周期数。**

设按字节编址、指令字长 32 位、按边界对齐，PC 自动加 1（表示加一个指令字长）。执行这条指令的全部微操作序列为：

| 阶段 | 节拍 | 微操作 | 控制信号 | 说明 |
| :--- | :--- | :--- | :--- | :--- |
| 取指 | T1 | (PC) → MAR | PCout，MARin | 送指令地址 |
| 取指 | T2 | M(MAR) → MDR；(PC)+1 → PC | read，MDRinE，PCinc | 访存取指，同时改 PC |
| 取指 | T3 | (MDR) → IR | MDRout，IRin | 指令入 IR |
| 间址 | T4 | Ad(IR) → MAR | AD(IR)out，MARin | 形式地址送 MAR |
| 间址 | T5 | M(MAR) → MDR | read，MDRinE | 取出有效地址 |
| 间址 | T6 | (MDR) → MAR | MDRout，MARin | 有效地址留在 MAR |
| 执行 | T7 | M(MAR) → MDR | read，MDRinE | 按有效地址取操作数 |
| 执行 | T8 | (MDR) → R1 | MDRout，R1in | 写入 R1 |

**结论：单总线数据通路执行该指令共需 8 个时钟周期。** 其中取指 3 拍、间址 3 拍、执行 2 拍。

**对照：若采用三总线专用数据通路**，且执行周期中的取数与写回都能并行安排，则取指仍为 3 拍（受主存访问限制），但间址可压缩为 2 拍、执行可压缩为 1 拍，总计约 6 拍。这说明**数据通路结构直接决定指令所需的时钟周期数**，做题必须按题目框图上「哪些部件之间有直接通路」逐拍判定。

:::key 时钟周期数计算的四句口诀
1. 数**访存次数**：每次主存读/写各占一拍（或题目规定的存储器等待周期数）。
2. 数**总线传送次数**：单总线上每次「一个源 → 一个目的」占一拍，且要检查是否冲突。
3. 数**ALU 运算次数**：涉及 ALU 的运算另占一拍（输入已就绪的前提下）。
4. **能并行就并行**：多总线结构下同一拍可以同时完成多次传送，能省则省，但受上面两条硬性规则约束。
:::

## 控制器的功能和工作原理

### 时序与控制

控制器要在正确的时刻发出正确的控制信号，所以必须有**时序系统**。时序信号的作用是对微操作控制信号进行时间调制，严格规定每条信号的产生时刻与持续时间。基本层次为：**时钟脉冲（节拍）→ 机器周期 → 指令周期**。

- **同步控制方式**：所有操作由统一的时钟节拍控制，实现简单，但机器周期长度必须按最慢操作确定，效率较低。
- **异步控制方式**：不给操作规定固定节拍，靠「回答信号」串联，效率高但控制复杂。
- **联合控制方式**：多数操作按同步方式，少数慢操作（如访存）用异步回答，是实际机器的常见做法。

### 硬布线控制器

**硬布线控制器（组合逻辑控制器）**：用专门的组合逻辑电路直接产生控制信号。它的输入是**指令译码信号、时序信号（机器周期/节拍电位）和状态条件**，输出是各部件所需的微命令。

**设计思路（可按此复述）：**

1. **分析微操作命令**：对每条机器指令、每个机器周期，列出所有微操作，确定每条微操作对应哪个微命令、在哪个节拍发出。
2. **列出逻辑表达式**：把「微命令 = 该微命令在哪些指令、哪个机器周期、什么条件下需要发出」写成布尔表达式。可用**与阵列（译码器）— 或阵列**结构或可编程逻辑阵列 PLA 实现。
3. **时序**：用节拍电位（机器周期状态）+ 节拍脉冲共同控制，保证信号按正确的时间顺序出现。

**特点：**

| 比较项 | 硬布线控制器 | 微程序控制器 |
| :--- | :--- | :--- |
| 控制信号来源 | 组合逻辑电路直接产生 | 执行控制存储器中的微指令产生 |
| 速度 | **快**（省去了读微指令、译码微指令的时间） | **慢**（每条微命令要多一次访存 CM 和译码） |
| 规整性 | 差，是一个多输入/多输出的巨大逻辑网络 | 规整，逻辑上与「程序设计」类似 |
| 修改与扩展 | **困难**（要重新设计硬件逻辑） | **容易**（只需改写控制存储器中的微程序） |
| 适用场合 | 指令系统简单规整（典型是 RISC、MIPS） | 指令系统复杂的 CISC 处理器 |
| 实现方式 | 组合逻辑（可用有限状态机描述） | 存储技术 + 程序设计技术，属「软件时序」 |

### 微程序控制器

**基本思想**：仿照程序设计的方法，把每条机器指令的执行过程分解为若干步，每一步的微命令序列**预先编制**好并存放起来；执行指令时按顺序取出这些「微命令集合」去控制硬件。这就是「**存储程序**」思想在控制器设计上的应用。

**一组术语必须分清（这是选择题高频区）：**

- **微命令（micro-command）**：控制部件向执行部件发出的控制信号，如 `PCout`、`MARin`、`ADD`、`read`。
- **微操作（micro-operation）**：执行部件收到微命令后所进行的操作，如 PC 把内容送上总线、ALU 完成加法。**微命令与微操作一一对应。**
- **相容性 / 互斥性微操作**：能在同一个节拍内并行执行的微操作为相容，不能并行为互斥。例如 `read` 与 `write` 互斥，各部件的「输出到总线」控制信号互斥（同一时刻总线上只能有一个数据），而各寄存器的「从总线锁存数据」使能信号可以相容（可同时有多个模块接收）。
- **微指令（micro-instruction）**：同一节拍内发出的、**相容的一组微命令**的集合，即「一个状态」的全部控制信号。
- **微程序（micro-program）**：完成一条机器指令所需的一组微指令序列。**每条机器指令对应一段微程序。**
- **控制存储器（Control Storage，CS/CM）**：位于 CPU 内部、存放全部微程序的只读存储器。**CS 按地址访问**，不是按内容访问。
- **微地址**：微指令在控制存储器中的地址。
- **微指令寄存器（μIR）**：在微指令执行期间暂存微指令。
- **微地址寄存器（μAR / μPC）**：存放将要执行的微指令的微地址。
- **微周期（micro-cycle）**：从控制存储器中读取并执行一条微指令所需的全部时间，通常为一个时钟周期。

:::key 微命令 / 微指令 / 微程序的三层关系
**微命令（1 个控制信号）→ 微指令（同拍内相容的微命令集合）→ 微程序（实现一条机器指令的微指令序列）**

由此得到两条极重要的等价关系：

- **一条机器指令需要多少个时钟周期，它的微程序就包含多少条微指令**（反之亦然）。
- **机器指令与微指令是两个层次的东西**。CPU 能直接理解并执行的是**机器指令（以及微程序控制器内部的微指令）**；伪指令、汇编指令都必须先由汇编器翻译成机器指令。
- **只有相容的微命令才能出现在同一条微指令中**，这直接决定了微指令的并行能力。
:::

#### 控制存储器与主存的比较

| 项目 | 主存储器 MM | 控制存储器 CS |
| :--- | :--- | :--- |
| 存放内容 | 机器指令与数据 | 微程序（微指令） |
| 位置 | CPU **外部** | CPU **内部** |
| 存储容量 | 大 | 小 |
| 存储字长 | 存储字长（常等于机器字长） | **微指令长度** |
| 存取速度 | 慢 | 快（与 CPU 同周期量级） |
| 实现介质 | ROM 与 RAM 均可 | 一般是 ROM（只读型） |
| 访问方式 | **按地址访问** | **按地址访问** |

:::warn CS 与 MM 的常见错误说法
「控制存储器按内容访问」是**错的**——它和主存一样按地址访问。按内容访问的是相联存储器（如 TLB 的实现方式）。
:::

### 微指令的格式与编码方式

微指令的基本格式包含三部分：

1. **操作控制字段**（微命令字段）：给出本条微指令要发出的所有微命令。
2. **顺序控制字段**（下地址字段 / 转移控制字段）：给出下一条微指令的微地址，或指明如何形成下一条微地址。
3. **判别测试字段**（P 字段）：表示按什么条件进行分支判断，如按指令操作码无条件分支（P0）、按 PSW 的相等标志条件分支（P1）。

#### 按操作控制字段的组织方式分类

- **水平型微指令**：一次能定义并执行**多个可并行的微命令**。微指令字较长，微程序短，并行能力强、执行速度快，但微指令字长浪费大、编写困难。
- **垂直型微指令**：一条微指令只能完成**一个微操作**（或 1～2 个），类似机器指令的格式，要用微操作码 + 操作数地址。微指令字短、编码空间利用率高，但微程序长、并行能力差、执行速度慢。

:::key 水平型微指令的并行能力
「水平型微指令并行操作能力强」这一结论的根据是——**它把同一条微指令中的操作控制字段分成若干段，同一段内的微命令互斥、不同段之间的微命令相容，因此一次可以同时发出多条相容微命令**。判断一条微指令能发出几个微命令，看的就是它的操作控制字段里「能同时置为有效」的位数。
:::

#### 微指令的编码方式

**直接编码（直接控制法）**：操作控制字段中**每一位对应一个微命令**，置 1 发该微命令，置 0 不发。

- 优点：不必译码，控制信号直接产生，**速度最快**，微命令可任意组合（并行能力最强）。
- 缺点：机器微命令个数很多时微指令字极长，而一条微指令中有效的微命令很少，**编码空间利用率低**。

**字段直接编码（字段直接编码法）**：把操作控制字段划分成若干小字段，**互斥的微命令编在同一个字段，相容的微命令编在不同字段**。每个字段经译码后产生该字段内的一个微命令。

- 关键规定：**每个字段必须能够表示「本字段不发出任何微命令」这一状态**，因此含 $ n $ 个互斥微命令的字段至少需要 $ \lceil \log_2(n+1)\rceil $ 位。
- 总位数公式：

$$ W_{\text{op}}=\sum_{i=1}^{m}\left\lceil \log_2\left(n_i+1\right)\right\rceil $$

其中 $ m $ 为字段（互斥类）个数，$ n_i $ 为第 $ i $ 个字段内的互斥微命令数。

- 优点：在保持一定并行能力的同时显著缩短微指令字长。
- 缺点：要经过译码，速度比直接编码慢一点。

**字段间接编码（字段间接编码法）**：一个字段中的微命令含义还要**由另一个字段（或另一个字段的某几位）决定**，简称「间接编码」。它能进一步缩短微指令字长，但译码电路更复杂、微指令并行能力进一步下降。统考只要求知道它的定义与「进一步缩短字长、并行性更差」这一结论。

:::exam 完整算例：字段直接编码的位数计算（对照 2012 年统考真题）
某计算机采用微程序控制方式，操作控制字段采用字段直接编码法，共有 33 个微命令，构成 5 个互斥类，分别包含 7、3、12、5、6 个微命令，求操作控制字段至少多少位。

$$ \lceil\log_2(7+1)\rceil+\lceil\log_2(3+1)\rceil+\lceil\log_2(12+1)\rceil+\lceil\log_2(5+1)\rceil+\lceil\log_2(6+1)\rceil $$
$$ =3+2+4+3+3=15\ \text{位} $$

注意 $ \lceil\log_2 13\rceil=4 $（因为 $2^3=8<13\le16=2^4$），$ \lceil\log_2 7\rceil=3 $。**答案 15 位**。若误以为不需要「全 0 不操作」状态，就会算成 $3+2+4+3+3$ 之外的错误结果或漏掉一位；若误用直接编码则得到 33 位。
:::

### 微地址的形成方式

1. **计数器方式（增量方式）**：微地址寄存器带计数功能，微指令按 `μPC+1` 顺序执行；遇到转移时用转移地址字段修改 μPC。
   - 优点：微指令中不必设置下地址字段，字长较短。
   - 缺点：不能实现多路条件分支，只能二路分支；编制微程序时不灵活。
2. **断定方式（下地址字段法）**：微指令中直接给出下一条微指令的地址（下地址字段），由判别测试字段决定是否按该字段转移。
   - 优点：可实现多路分支，微程序编制灵活。
   - 缺点：每条微指令都要带下地址字段，微指令字较长。
3. **结合方式（混合方式）**：把以上两者结合，顺序执行时用计数器，需要分支时用下地址字段，兼顾字长与灵活性。

**微程序入口地址的形成**（结合前面「转移微指令」的概念）：

- 取指微程序是所有指令**公共**的，其入口地址固定（如 0000）。取指结束后的第一条微指令是**转移微指令**，它的作用就是「根据机器指令的操作码，跳转到该指令对应微程序的入口地址」。
- 转移微指令通常通过一个专门的小型 ROM（记为 ROM1）实现：以 IR 中的操作码为输入（即索引），输出即该指令微程序的入口地址。
- 同一入口下再分支的情形（如 `lw`/`sw` 首地址相同但后续流程不同）可用第二个 ROM（ROM2）实现，也可用**断定法**的硬件逻辑实现。例如下地址字段给出 `1010`，当机器指令操作码的某一位为 1 时用异或门把它变成 `1001`：$1010\oplus0011=1001$，即可用极少的硬件实现二路分支。
- 微程序的**最后一条微指令**通常取「取下一条机器指令的取指微程序首地址」，从而回到取指，形成循环。

:::key 判别测试字段（P 字段）的作用
P 字段本身的位数由「有多少种判别测试条件」决定，因此 $ \text{P 字段位数}=\lceil\log_2(\text{测试条件数}+1)\rceil $。若微程序共有 25 个状态（微指令），则下地址字段至少 $ \lceil\log_2 25\rceil=5 $ 位。
:::

### 微指令条数与控制存储器容量的计算

这是「数量主线」的核心题型。三条计算步骤：

1. **算微指令条数**：
$$ N_{\mu}=N_{\text{公共取指微程序}}+N_{\text{各指令微程序总和}} $$
2. **算微指令字长**（位数）：$ W_{\mu}=W_{\text{操作控制字段}}+W_{\text{判别测试字段}}+W_{\text{下地址字段}} $。
3. **算控制存储器容量**：$ C = N_{\mu}\times W_{\mu} $（单位 bit）或 $ C=\dfrac{N_{\mu}\times W_{\mu}}{8} $（单位 B）；反之，**下地址字段位数** $ \ge \lceil\log_2 N_{\mu}\rceil $。

**完整算例一（对照 2014 年统考真题）：** 某计算机采用微程序控制器，共有 32 条机器指令，公共取指微程序包含 2 条微指令，各指令对应的微程序平均由 4 条微指令组成，采用断定法（下地址字段法）确定下条微指令地址，求下地址字段至少多少位。

- 各指令微程序微指令数：$ 32\times4=128 $ 条。
- 控制存储器至少容纳：$ 2+128=130 $ 条。
- $ 2^7=128<130\le256=2^8 $，故下地址字段至少 $ \lceil\log_2 130\rceil=8 $ 位。

**完整算例二（自编，用于练容量）：** 某机有 60 条机器指令，公共取指微程序 3 条微指令，各指令微程序平均 6 条微指令；微指令字长为操作控制字段 24 位、判别测试字段 2 位、下地址字段（由算例一的方法确定为 9 位）。求控制存储器容量。

- 微指令条数：$ 3+60\times6=363 $ 条。
- 微指令字长：$ 24+2+9=35 $ 位。
- 控制存储器容量：$ 363\times35=12705 $ 位 $ =12705/8\approx1588.1 $ B，取整为 **1589 B**（工程上按整数个存储字，即 363 字 × 35 位）。

:::warn 微程序计算题的三个陷阱
- **公共取指微程序只算一次**，不要按指令条数重复计算。
- **下地址字段位数由「微指令总条数」决定，不是由机器指令条数决定**。先算总条数再取对数。
- **单位**：题目问「多少位」就不要答字节；问「多少字节」时要注意是否进位取整。
:::

## 异常和中断机制

### 异常和中断的基本概念与区别

**异常（exception）**，又称**内中断**：CPU 在**执行当前指令的过程中**，由 CPU 内部检测到的、与当前指令**同步**的意外事件。

**中断（interrupt）**，又称**外中断**：CPU **外部**的设备或部件提出的、与当前指令**异步**的服务请求。

| 对比项 | 内部异常（exception） | 外部中断（interrupt） |
| :--- | :--- | :--- |
| 来源 | CPU 内部，由当前指令或其执行过程引起 | CPU 外部设备或部件（定时器、键盘、网卡……） |
| 与当前指令的关系 | **同步**：由当前指令引起 | **异步**：与当前指令无关 |
| 检测时机 | **在指令执行过程中**实时检测 | **在一条指令执行结束后**采样中断请求引脚 |
| 能否屏蔽 | 不能用中断屏蔽位屏蔽 | 分为可屏蔽中断与不可屏蔽中断 |
| 典型例子 | 除数为 0、非法操作码、缺页、越权访问、自陷、溢出 | 键盘输入、定时器到时、网络数据包到达、打印机缺纸 |

:::key 判断外部中断的唯一标准
问自己一句：**「这个事件是不是由当前这条指令同步引起的？」**

- 「键盘输入」→ 外部中断；「除数为 0」→ 内部异常。
- 「访存缺页」→ 发生在访存指令的地址转换过程中，属内部**故障**，**不是**外部中断。
- 「浮点运算下溢」→ 由当前浮点指令引起，属内部异常。

**不要**用「事件发生在内存里还是设备外」来判断——缺页发生在内存管理部件里，但它仍是内部异常。
:::

**为什么外部中断必须在指令结束后才能检测？** 若在指令执行中途响应中断，指令被部分执行，CPU 无法保存一个「精确且可恢复」的中间状态；而异常发生的时刻和引发它的指令是确定的，处理完后可以准确地重新执行或跳过该指令，所以异常可以在指令执行过程中检测并响应。

### 异常和中断的分类

#### 内部异常的三类

| 类型 | 英文 | 含义 | 指令完成情况 | 返回位置 | 典型例子 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| 故障 | fault | 指令执行中发现的、可能被修复的错误 | 指令**尚未成功完成** | 返回**本条指令重新执行** | 缺页、缺段、访问权限违例、某些对齐错误 |
| 自陷 | trap | 程序**主动**执行陷阱指令（如 `INT n`、`syscall`）引发 | 指令**已经完成** | 返回**下一条指令** | 系统调用、断点、单步跟踪、调试 |
| 终止 | abort | 严重且通常不可恢复的硬件错误 | 发生严重错误，程序状态不可靠 | **一般不返回**原程序 | 硬件故障、总线错误、电源故障 |

:::warn 三类异常的分辨要点
- **自陷（trap）属于内部异常，不是外部中断**。「自陷是通过陷阱指令预先设定的一类外部中断事件」是**错误**说法——它与当前指令同步。
- **不能说「内部异常处理后都返回发生异常的指令继续执行」**。fault 返回原指令重执行，trap 返回下一条指令，abort 不返回。三者返回位置不同。
- 自陷可在**用户态**由程序主动执行陷阱指令触发（如 `INT n` 产生软中断），转而进入内核态执行相应处理程序——这是「用户态 → 内核态」的一条正规途径。
:::

#### 外部中断的两类

- **可屏蔽中断（maskable interrupt，`INTR`）**：主要来自 I/O 设备。CPU 可通过在中断控制器中设置**屏蔽字**来屏蔽或不屏蔽它；被屏蔽的中断请求信号不会送到 CPU。一般外设中断都属于可屏蔽中断。
- **不可屏蔽中断（non-maskable interrupt，`NMI`）**：通常是非常紧急的硬件故障，如电源掉电、内存校验错、硬件看门狗超时、时钟中断、硬件线路故障。它通过专用 `NMI` 请求线提出，**不受中断允许标志 IF 和中断屏蔽字控制**，任何情况下都会被送到 CPU。

:::key 不可屏蔽中断（NMI）的四条结论
1. **CPU 处于关中断状态（IF=0）时，仍能响应 NMI 请求**。
2. **NMI 的优先级高于所有可屏蔽中断**，通常仅低于硬件复位。
3. NMI **同样需要**保存断点、**同样需要**通过中断向量表（或 IDT）寻址服务程序（x86 中向量号固定为 2）。所谓「NMI 没有中断响应周期」是错误说法。
4. 响应 NMI 时 CPU 会自动**屏蔽可屏蔽中断**（等效于隐式 `CLI`），但**不屏蔽 NMI 自身**，即 NMI 可以嵌套；这种屏蔽持续到执行中断返回指令为止。

统考中若题目未提 NMI，**外部中断一律按可屏蔽中断处理**；讨论「多重中断」时也只针对可屏蔽中断。
:::

**中断优先级的两个层次**（务必区分）：

- **响应优先级（中断判优）**：由中断查询程序或硬件判优电路决定的优先级，反映「多个中断同时请求时先响应谁」。它由硬件连线或固定逻辑决定，**软件不易改动**。经验顺序为：**不可屏蔽中断 > 内部异常 > 可屏蔽中断**；内部异常中，硬件故障 > 软件中断；I/O 设备按速度高低排序，速度高的优先级高（因为速度高的设备数据容易丢失）。
- **处理优先级（中断屏蔽）**：由各自的中断屏蔽字**动态设定**，反映「正在处理某个中断时，允许谁打断它」。**可以用中断屏蔽字改变的是处理优先级，不是响应优先级。**

### 异常和中断的检测与响应

**可屏蔽中断的响应条件（三条同时满足）**：

1. 有中断请求（中断请求信号有效，且该请求未被屏蔽）；
2. CPU 处于**开中断**状态（IF=1）；
3. **当前指令执行结束**，且没有更高优先级的请求正在处理。

:::warn 「请求有效」不等于「立即响应」
「一旦可屏蔽中断请求信号有效，CPU 将立即响应」是**错误**的。中断响应是「异步但不立即」的：即使信号有效，若 IF=0、或当前指令尚未执行完、或有更高优先级事件正在处理，CPU 都不会响应。
:::

**响应时机与流程**：CPU 在每条指令执行结束、取下一条指令之前，采样中断请求引脚（如 `INTR`）。若发现有效且满足响应条件，则进入中断响应过程。中断控制器根据各设备的中断请求和屏蔽情况，结合**中断响应优先级**，识别出当前请求的**中断类型号**，并通过**数据总线**送给 CPU。

**中断隐指令**：CPU 在中断响应过程中由硬件自动执行的一系列操作。它不是一条真实的机器指令（在指令系统中找不到它，也无操作码），但功能上等价于一条指令，称为「隐指令」。其内容为：

1. **关中断**（将中断允许触发器清 0），防止在保存现场时被新的可屏蔽中断打断；
2. **保存断点**——保存 PC（有的机器还同时保存 PSW）到栈或专用寄存器（如 MIPS 的 EPC）；
3. **引出中断服务程序**——根据中断类型号从中断向量表取出**中断向量**（中断服务程序的入口地址）送 PC。

:::key 硬软件分工的一句话
**硬件负责：关中断、保护断点、引出服务程序（中断隐指令）**
**软件负责：保护现场（保存通用寄存器）、设置新屏蔽字、中断事件处理、恢复现场、开中断、中断返回**
:::

**中断向量与中断向量表**：**中断向量**是中断服务程序的入口地址（有的体系结构中还包含初始 PSW）；**中断向量表**是存放所有中断向量的表格，位于内存固定区域，以中断类型号为索引。「中断类型号 → 查表 → 中断向量 → 送 PC」是硬件完成的寻址过程。

**断点保存位置**：为支持嵌套处理，多数处理器把断点保存在**栈**中（如 80x86）；若不支持多重中断嵌套，可以把断点保存在**专用寄存器**中（如 MIPS 用 EPC 存放断点）。后者开销小，因为访问寄存器比访问栈（实际是访问主存）快。

**单重中断的中断服务程序执行顺序**（因为题目问的是「服务程序内」，硬件已在隐指令阶段完成关中断与保存断点）：

```plain
保护现场 → 中断事件处理 → 恢复现场 → 开中断 → 中断返回
```

支持多重中断（中断嵌套）时的完整顺序为：

```plain
关中断（隐指令）→ 保存断点（隐指令）→ 引出服务程序（隐指令）
→ 保护现场和屏蔽字 → 设置新屏蔽字 → 开中断 → 中断事件处理
→ 关中断 → 恢复现场和屏蔽字 → 开中断 → 中断返回
```

:::warn 断点与现场不是一回事
- **保护断点**：保存 PC（及 PSW），由**硬件**（中断隐指令）完成。
- **保护现场**：保存通用寄存器等用户可见工作寄存器的内容，由**中断服务程序（软件/操作系统）**完成。

因此「由操作系统保存的」是**通用寄存器的内容**，不是 PC；「中断隐指令完成的」不包括「保存通用寄存器」。
:::

### 多重中断与中断屏蔽

**单重中断**：CPU 在执行中断服务程序过程中，对新的中断请求一律不予响应。**多重中断（中断嵌套）**：CPU 暂停现行中断服务程序，转去处理新的更高优先级的中断请求。

CPU 要具备多重中断功能，必须满足两个条件：

1. 在中断服务程序中**提前设置开中断指令**（在保护现场之后开中断）；
2. 优先级别高的中断源有权中断优先级别低的中断源。

**中断屏蔽技术**：每个中断源配一个**屏蔽触发器**，所有屏蔽触发器组合成一个**屏蔽字寄存器**，其内容称为**屏蔽字**。CPU 可通过执行相应的 I/O 指令修改屏蔽字的内容，从而**动态改变中断处理的先后次序**。

**屏蔽字的约定与规律：**

- 一般约定 **1 表示屏蔽（禁止），0 表示开放（允许申请）**。
- 每个中断源对应一个屏蔽字——即处理该中断源的中断服务程序运行期间，屏蔽字寄存器中的内容。
- **屏蔽字中 1 越多，该中断的处理优先级越高**。
- **每个屏蔽字中至少要有 1 个 1**（至少要能屏蔽自身，防止同一中断源反复打断自己）。
- 屏蔽字中各位的顺序要与中断源一一对应（题目通常会说明第几位对应哪个中断源）。

**「改变中断处理次序」的屏蔽字构造方法（可直接照做）：**

1. 把中断源按**题目要求的处理优先级从高到低**排成一队，例如 $ A>B>C>D $。
2. 写出第 $ X $ 个中断源的屏蔽字时：**自身位填 1**；**处理优先级比它低的所有中断源，对应位填 1**；**处理优先级比它高的所有中断源，对应位填 0**。
3. 换个说法：**某中断源 $ S $ 的屏蔽字中，凡是「处理优先级不高于 $ S $ 」的中断源（含 $ S $ 自己）对应的位都是 1。**

:::exam 完整算例：按改变后的处理次序写出屏蔽字
**题设**：某中断系统有 4 个中断源 `1#`、`2#`、`3#`、`4#`，其中断**响应优先级**为 $ 1\#>2\#>3\#>4\# $。现要求把**中断处理优先级**改成 $ 1\#>4\#>3\#>2\# $。设屏蔽字中一位对应一个中断源，位序自左至右为 $ 1\#2\#3\#4\# $，**1 表示屏蔽，0 表示开放**。求各中断源对应的屏蔽字。

**解**：按处理优先级 $ 1\#>4\#>3\#>2\# $，逐个来写。

- `1#` 的处理优先级最高，它不仅屏蔽自身，还必须能屏蔽所有**处理优先级比它低**的 $ 4\#,3\#,2\# $：$ \Rightarrow \mathbf{1111} $。
- `4#` 处理优先级第二。比它高的只有 `1#`（对应位为 0），它屏蔽自身及更低的 $ 3\#,2\# $（对应位为 1）：$ \Rightarrow \mathbf{0111} $。
- `3#` 处理优先级第三。比它高的有 `1#`、`4#`（两位为 0），它与更低的 `2#` 为 1：$ \Rightarrow \mathbf{0011} $。
- `2#` 处理优先级最低。比它高的有 `1#,4#,3#`（三位为 0），只有自身为 1：$ \Rightarrow \mathbf{0001} $。

**验算**：每个屏蔽字中 1 的个数依次是 4、3、2、1，与处理优先级从高到低严格对应，符合「1 越多优先级越高」的规律；且每个屏蔽字都至少含一个 1（都不为 0），满足「必须能屏蔽自身」的要求。

**接着算「CPU 完成各中断服务程序的过程」**：设 CPU 执行主程序时，`1#`、`3#`、`4#` **同时**发生请求，随后在执行 `3#` 的中断服务程序过程中，`2#` 又提出请求。

- 主程序：三请求同时到达，按**响应优先级** $ 1\#>3\#>4\# $ 选 `1#` 先响应。运行 `1#` 时屏蔽字为 1111，其余三者全被屏蔽。
- `1#` 服务程序结束 → 恢复旧屏蔽字，剩下 `3#`、`4#` 待响应，按响应优先级选 `3#`。运行 `3#` 时屏蔽字为 0011，`4#`、`2#` 都被屏蔽。
- 此时 `2#` 提出请求但被 0011 屏蔽，**不能打断** `3#`。
- `3#` 服务程序结束 → 恢复旧屏蔽字，此时 `2#`、`4#` 都已请求且未被屏蔽；按处理优先级 $ 4\#>2\# $（`2#` 的屏蔽字 0001 允许 `4#` 打断），标为「`3#`→恢复点」后先响应 `4#`。
- `4#` 运行期间屏蔽字 0111，`2#` 被屏蔽，不能嵌套。
- `4#` 结束 → 再按处理优先级响应 `2#`，`2#` 运行期间屏蔽字 0001。
- `2#` 结束 → 返回到最早被挂起的 `3#` 服务程序的断点处继续执行剩余部分。
- `3#` 结束 → 返回主程序。

**最终处理先后次序为：**`1#` 全部 → `3#` 前半 → `4#` 全部 → `2#` 全部 → `3#` 后半 → 主程序。

**若把处理优先级改成 $ 1\#>2\#>3\#>4\# $**（与原响应优先级一致），则屏蔽字变为：

| 中断源 | 处理优先级 1#>2#>3#>4# 时的屏蔽字 | 处理优先级 1#>4#>3#>2# 时的屏蔽字 |
| :--- | :--- | :--- |
| `1#` | 1111 | 1111 |
| `2#` | 0111 | 0001 |
| `3#` | 0011 | 0011 |
| `4#` | 0001 | 0111 |

对照可见：**只有 `2#` 与 `4#` 的屏蔽字互换**，正是这一次互换把两者的处理次序颠倒过来。这也说明——**不改屏蔽字时处理优先级就等于响应优先级；改屏蔽字只能改变处理次序，不能改变响应优先级本身。**
:::

:::warn 多重中断的四条易错点
- **「中断处理期间 CPU 一直处于关中断状态」是错的**。那是单重中断；多重中断在保护现场之后要**开中断**。
- **「中断屏蔽字用于确定中断响应的优先级」是错的**。屏蔽字改变的是**处理优先级**（能否被打断），响应优先级由硬件判优电路固定决定。
- **「只有在用户态才能检测和响应中断」是错的**。内核态同样可以响应中断，这正是中断嵌套的机制。
- **每个屏蔽字必须至少有一个 1**（屏蔽自身），写屏蔽字题时若某行为全 0，一定是错的。
:::

## 指令流水线

### 指令流水线的基本概念

**指令流水线（instruction pipeline）**：把一条指令的执行过程划分为 $ k $ 个功能段（流水段），让多条指令在不同功能段中**同时**工作、重叠执行，从而提高单位时间内完成的指令数。它利用的是**时间并行性**。

经典五段划分（MIPS 风格）：

| 流水段 | 缩写 | 主要工作 | 主要功能部件 |
| :--- | :--- | :--- | :--- |
| 取指 | IF | 按 PC 从指令存储器取指令，同时计算 PC+4 | 指令存储器 IM、PC、加法器、MUX |
| 译码/取数 | ID | 译码，按 Rs、Rt 从寄存器堆读出操作数 | 寄存器堆读口、控制器 |
| 执行 | EX | ALU 运算、计算访存有效地址、分支比较与目标地址 | ALU、扩展器、加法器 |
| 访存 | MEM | 读/写数据存储器；分支指令在此更新 PC | 数据存储器 DM |
| 写回 | WB | 把结果写回寄存器堆 | 寄存器堆写口、MUX |

**流水寄存器（流水段寄存器）**：在相邻流水段之间插入的状态元件，保存上一段的中间结果供下一段使用。它们的作用是**把各段的工作隔离开，使得不同指令可以同时在各自的功能段中工作**。

- **IF/ID**：保存取出的**指令**和 **PC+4**（分支指令后面要用 PC+4 计算相对转移地址）。
- **ID/EX**：保存 $ R[R_s] $、$ R[R_t] $、$ R_t $、$ R_d $、$ imm16 $、$ func $、**PC+4** 以及**译码产生的控制信号**。指令本身不必再保存（需要的信息已经提取出来）。
- **EX/MEM**：保存 ALU 结果（或有效地址）、Zero 标志、Overflow 标志、要写回的目的寄存器号、要存入 DM 的数据 $ R[R_t] $、以及继续往后的控制信号。
- **MEM/WB**：保存从 DM 读出的数据与 ALU 结果、目的寄存器号、以及写回所需的控制信号。

**为什么指令系统要在意规整性**（有利于流水的指令系统特点）：指令格式规整且长度一致（如 MIPS 32 位定长，PC+4 计算方便）、指令和数据按边界对齐存放、**只有 Load/Store 指令才能访问存储器**、源寄存器位置固定（指令未完成译码即可开始读寄存器）。这四点使各段的行为统一、延迟稳定，便于流水。

**流水线设计的两个原则**：流水段个数以**最复杂指令**所用的功能段个数为准；流水段长度以**最复杂的操作**所花时间（关键路径）为准。这也解释了为什么流水线会「延长单条指令的执行时间」——所有指令都要按最慢指令的节奏走，还要加上流水段寄存器的开销。

:::key 二阶段流水线为什么不能成倍提速
① 执行阶段因各指令耗时不同，必须以最慢者为准，故执行阶段很长；② 为统一节拍，取指阶段也要拉长到与最慢执行阶段同长；③ 流水段寄存器的读写增加额外延迟；④ 各种冒险会引入阻塞。所以流水线深度不能无限增加，当段间缓冲开销占比过大时再加深就没有意义。
:::

### 指令流水线的性能计算

设流水线有 $ k $ 段，每段执行时间为 $ \Delta t $，连续执行 $ n $ 条指令。

**时钟周期**：若忽略流水段寄存器延时，则 $ T_{clk}\ge \max(t_1,t_2,\ldots,t_k) $；若段间寄存器延时为 $ t_r $，则 $ T_{clk}\ge \max(t_1,\ldots,t_k)+t_r $。

**总时间**：不留空隙时，第一条指令用 $ k\Delta t $，此后每个 $ \Delta t $ 流出 1 条结果，共流出 $ n-1 $ 条：

$$ T=k\Delta t+(n-1)\Delta t=(k+n-1)\Delta t $$

若无阻塞时的理想周期数为 $ k+n-1 $，而实际额外插入了 $ s $ 个阻塞周期，则 $ T=(k+n-1+s)\Delta t $。

**吞吐率**（单位时间完成的指令数）：

$$ TP=\frac{n}{T}=\frac{n}{(k+n-1)\Delta t} $$

当 $ n\to\infty $ 时，理想最大吞吐率 $ TP_{\max}=\dfrac{1}{\Delta t} $，即流水线充满后每周期完成一条指令。

**加速比**（相对非流水线串行执行；串行执行 $ n $ 条指令需 $ nk\Delta t $）：

$$ S=\frac{nk\Delta t}{(k+n-1)\Delta t}=\frac{nk}{k+n-1} $$

当 $ n\to\infty $ 时 $ S\to k $，即**理想最大加速比等于流水段数 $ k $**。

**效率**（流水线设备的实际利用率。$ k $ 个段共 $ k\cdot T $ 的时空区，完成 $ n $ 条指令占用 $ nk $ 个「段·周期」）：

$$ E=\frac{nk}{k(k+n-1)}=\frac{n}{k+n-1},\qquad E=\frac{S}{k} $$

:::exam 完整算例：五段流水线的四项指标
**题设**：某处理器采用 5 段指令流水线，每段执行时间为 $ \Delta t=2\ \text{ns} $，段间流水寄存器延时已计入这 2 ns 内。连续执行 100 条指令，执行过程中无任何阻塞。求总时间、吞吐率、加速比、效率。

- 总周期数：$ k+n-1=5+100-1=104 $ 个。
- 总时间：$ T=104\times2\ \text{ns}=208\ \text{ns} $。
- 吞吐率：$ TP=\dfrac{100}{208\ \text{ns}}\approx0.4808\times10^{9} $ 条/秒 $ \approx4.81\times10^{8} $ 条/秒。
- 理想最大吞吐率：$ \dfrac{1}{2\ \text{ns}}=5\times10^{8} $ 条/秒（因为 $ n=100 $ 有限，实际吞吐率略低于它）。
- 加速比：$ S=\dfrac{nk}{k+n-1}=\dfrac{100\times5}{104}\approx4.81 $（理想上限为 $ k=5 $）。
- 效率：$ E=\dfrac{n}{k+n-1}=\dfrac{100}{104}\approx96.2\% $，验证 $ E=S/k=4.81/5\approx96.2\% $。

**变式**：若每条指令之间都额外插入 1 个阻塞周期（$ s=99 $），则周期数变为 $ 104+99=203 $，$ T=406\ \text{ns} $，$ TP\approx2.46\times10^{8} $ 条/秒，$ S\approx2.46 $。
:::

:::warn 性能计算的四个陷阱
- **单位**：$ \Delta t $ 常用 ns、ps，吞吐率是「条/秒」，别把 $ 1/\Delta t $（$ \text{s}^{-1} $）与「条/秒」混算但忘记换算 $ 10^{-9} $。
- **理想最大加速比是 $ k $，但有限 $ n $ 条指令时的实际加速比一定小于 $ k $**（因为流水线要填充，有 $ k-1 $ 个周期是「装填开销」）。
- **$ n $ 很大时才能近似用 $ TP_{\max}=1/\Delta t $ 与 $ S=k $**。选择题常给「某机主频 1.03 GHz、4 级流水、执行 100 条指令」这类小数据，必须老老实实算 $ k+n-1 $。
- **理想 CPI：单周期 = 1，基本流水线 = 1，超流水线 = 1，多周期 > 1，超标量 < 1**。别把「超流水线 CPI<1」写对（那是错的，超流水线不改变 CPI，它靠提高主频提速）。
:::

### 结构冒险、数据冒险和控制冒险的处理

**冒险（hazard）**是指使流水线不能在预定的时钟周期内继续推进（需要阻塞）的情形。

#### 结构冒险（structural hazard）

**成因**：多条指令在同一时钟周期争用**同一硬件资源**。典型情形：

- 单存储器时，Load 指令在 MEM 段取数据，同时 IF 段要取指令，两者争用同一个存储器；
- 寄存器堆只有单端口时，ID 段读寄存器与 WB 段写寄存器冲突；
- ALU 未流水化时，多条指令同时要用 ALU。

**处理方法**：

1. **规整功能段的划分原则**：每个功能部件在每条指令中只使用一次，且只能在特定的流水段中使用（例如 ALU 只在 EX 段用、寄存器写口只在 WB 段用）。
2. **增加或分离资源**：把**寄存器堆的读口和写口独立开来**（利用时钟上升沿写、下降沿读，使前半周期写、后半周期读）；把**指令存储器 IM 与数据存储器 DM 分开**——这正是**指令 Cache 与数据 Cache 分离的主要目的：减少指令流水线的资源冲突**，而不是为了提高命中率。
3. **阻塞（stall）**：资源不足时让后到的指令等待。代价是流水线出现气泡。

#### 数据冒险（data hazard）

**成因**：后面指令要用前面指令的结果，但该结果尚未产生。

三类数据相关：

| 类型 | 全称 | 含义 | 基本按序流水线中是否出现 |
| :--- | :--- | :--- | :--- |
| RAW | 写后读（真相关） | 前指令写、后指令读同一位置 | **会**，是必须处理的类型 |
| WAR | 读后写（反相关） | 前指令读、后指令写同一位置 | 不会（按序执行不颠倒次序） |
| WAW | 写后写（输出相关） | 两条指令写同一位置 | 不会（按序写回不颠倒次序） |

在**按序发射、按序执行、按序写回**的经典五段流水线中只可能出现 RAW；WAR 与 WAW 只会在乱序执行、多发射的处理器中成为真正的冒险。

**处理方法**：

1. **转发 / 旁路（forwarding / bypassing）**：流水段寄存器中已经有了后续指令需要的值，通过增加 MUX 把 EX/MEM 或 MEM/WB 寄存器中的结果直接送回 ALU 输入端，无需等写回。转发是**解决冒险的手段，本身不会引起阻塞**。
2. **暂停、插入气泡（stall / bubble）**：硬件检测到相关时冻结 PC 和 IF/ID 寄存器，让后续指令重复一次或插入 nop，直到数据可用。代价是 $ s $ 个阻塞周期。
3. **编译调度（软件方法）**：由编译器把无关指令调到相关指令之间填充空隙；若无合适指令则插入 `nop`。

:::key Load-use 冒险：转发解决不了的那一类
`load` 指令的数据在 **MEM 段末**才从 DM 读出，而紧随其后的指令在**同一周期就要在 EX 段**使用它，时间上来不及，因此**即使有转发也必须至少阻塞 1 个周期**。这就是典型的「装入—使用数据冒险（load-use data hazard）」。

**结论：转发不能解决所有数据冒险**，所以「所有数据冒险都可以通过加入转发电路解决」是**错误**的。与之相对，「所有数据冒险都能通过调整指令顺序和插入 nop 解决」是**正确**的（前提是保持程序语义）。
:::

**相关指令对的快速判定法**（用于「下列指令对中不存在数据冒险的是」这类题）：把每条指令写成「写哪些寄存器、读哪些寄存器」，若「前一条写」与「后一条读」有交集，则为 RAW 真相关；若后一条只是**写**了同一寄存器而并不读它，则不构成 RAW。相邻的两条指令若只共享「被写」的寄存器而不存在「先写后读」关系，就不是数据冒险。此外，**两条指令访问同一主存地址但处于基本按序流水线中时不构成冒险**（较早的 load 必然先于较晚的 store 到 MEM 段，访存次序不会颠倒）。

#### 控制冒险（control hazard）

**成因**：遇到会改变指令执行顺序的情形（各类转移指令、调用与返回指令、异常和中断），PC 的更新值来不及在取下一条指令之前准备好，导致流水线中已取出的若干条指令是错的。

**延迟损失时间片 $ C $**：由于流水线阻塞而带来的延迟执行周期数。它由「分支结果和目标地址在第几段才确定」决定——**越早算出并送回 PC，$ C $ 越小**。在经典数据通路中分支在 MEM 段才更新 PC，$ C=3 $（要丢弃/填充 3 个周期）；若在 ID 段就完成译码并送回转移目标地址，$ C=1 $；若在 IF 段就能算出目标地址（如 `j` 指令按 PC+4 高 4 位与 26 位立即数拼接），则 $ C=0 $。

**处理方法**：

1. **阻塞 / 插入气泡或 nop**：在分支指令后插入 $ C $ 个气泡或 $ C $ 条 `nop`。效率极低，一般不单独采用。
2. **分支预测**：
   - **静态预测**：总是预测「条件不满足（not taken）」，即继续执行顺序指令。若转移概率约 50%，正确率也只有约 50%。
   - **动态预测**：根据程序执行的历史动态调整预测，正确率较高，现代处理器几乎都采用。核心结构是**分支历史记录表 BHT**（记录分支的历史方向）与**分支目标缓冲 BTB**（缓存分支目标地址，使 IF 段就能得到目标地址），每个表项用分支指令地址的低位作索引，因此在 IF 阶段就能取到预测位，从而**不必等分支结果算出**。
3. **延迟槽 / 分支延迟时间片的调度（静态调度）**：由编译程序把分支指令前面与分支无关的指令调到分支指令**后面**执行，用来填充延迟时间片（称为**分支延迟槽，branch delay slot**），不够时用 `nop` 填充。
4. **预取两个方向的目标指令、加快并提前形成条件码、提高转移方向的猜准率**。

:::exam 真题考法
- 「不会引起流水线阻塞的是」——**数据旁路（转发）**。数据相关、条件转移、资源冲突都会引起阻塞。
- 「采用指令 Cache 与数据 Cache 分离的主要目的」——**减少指令流水线的资源冲突**（结构冒险），不是提高命中率，也不是降低缺失损失。
- 「无转发机制的五段流水线中，存在数据冒险的指令对是」——按上文的「写/读集合」判定，且注意**没有转发时，距离 2 条以内的 RAW 都需要阻塞**。
- 「采用转发处理数据冒险、硬件阻塞处理控制冒险时，哪些指令发生阻塞」——关键是识别出 **load-use 必须阻塞 1 拍**，以及**分支指令之后的指令必须等待分支结果**。
:::

### 超标量和动态流水线的基本概念

**指令级并行（Instruction Level Parallelism，ILP）**：单一指令流内部存在的、可同时执行的指令之间的并行性。提高 ILP 有两条基本途径：**增加流水线级数**（超流水线）和**在一个周期内发射多条指令**（多发射）。

**超流水线（super-pipelining）**：通过**增加流水线级数**，把每段的工作量切得更小，从而缩短时钟周期、提高主频。它**不改变 CPI（理想仍为 1）**，靠主频提速；代价是流水段寄存器开销增大、分支预测失败的代价更大、气泡的负面影响更明显。

**超标量（superscalar）**：处理器内部设置**多个独立的功能部件**，使得**一个时钟周期内可以同时发射并执行多条指令**，理想 $ \text{CPI}<1 $（即 IPC>1）。它常与**动态调度**技术结合以提高指令执行的并行性。要注意：**超标量的本质是「一个周期发射多条指令」，它并不缩短流水线功能段的处理时间**（那是加深流水线或提频要做的事）。

**多发射的两种实现方式**：

| 比较项 | 静态多发射（超长指令字 VLIW） | 动态多发射（超标量） |
| :--- | :--- | :--- |
| 指令打包由谁决定 | **编译器**在编译时完成（生成超长指令字，「发射包」） | **硬件**在执行时动态决定 |
| 冒险处理 | 完全或主要由编译器通过代码调度、插入 nop、静态分支预测消除 | 硬件检测数据冒险并阻塞，结合动态分支预测 |
| 可移植性 | **差**：编译结果与具体处理器结构紧密相关，换机器往往要重新编译 | **强**：编译后的代码可在不同超标量处理器上运行 |
| 硬件复杂度 | 简单（把最难的调度交给编译器） | 复杂 |

**推测（speculation）**：由编译器或处理器**猜测**指令的执行结果，并据此调整指令执行顺序，使指令执行达到最大可能的并行。它依赖于「指令间相关性分析」和「分支方向预测」，一旦推测错误必须有**检测与回滚机制**，因此推测错误会增加额外开销。

**动态调度与乱序执行**：动态流水线的重要思想是「**在等待解决阻塞时，到后面找指令提前执行**」。其通用模型为：

- 一个指令预取和译码单元：**有序发射**；
- 多个并列执行的功能单元：**乱序执行**；
- 一个提交单元：**有序提交**（保证异常精确、程序状态正确）。

**为什么有了编译器调度还需要硬件动态调度**：并非所有阻塞都能事先确定（如 **Cache 缺失**就是不可预见的阻塞）；动态分支预测必须依据真实执行情况；动态调度还能把处理器细节屏蔽起来，使同一份编译结果在不同处理器上都可用。

**寄存器重命名（register renaming）**：把指令中引用的体系结构寄存器（逻辑寄存器）映射到一组物理寄存器上，从而**消除 WAR 与 WAW 这类「假相关」**，只保留真正的 RAW 相关，让乱序执行能挖掘更多并行性。

**推测执行（speculative execution）**：在分支结果未确定时，按预测方向继续取指并执行，把结果暂时保存在不被提交的位置；预测正确则提交，预测错误则丢弃并回滚。

:::warn 超标量的三条易错说法
- 「超标量能缩短流水线功能段的处理时间」——**错**。
- 「超流水线的 CPI 小于 1」——**错**，超流水线 CPI 仍为 1。
- 「超标量通过一个周期发射多条指令使 CPI 可以小于 1」——**对**。
:::

## 多处理器基本概念

### Flynn 分类法与向量处理器

1966 年 Flynn 提出的分类法按**指令流（instruction stream）数量**和**数据流（data stream）数量**两个维度划分计算机体系结构：

| 类型 | 指令流 | 数据流 | 核心原理 | 典型硬件 | 并行层次 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **SISD** | 单 | 单 | 顺序处理 | 传统单核 CPU、微控制器 | 无显式并行（内部靠 ILP） |
| **SIMD** | 单 | 多 | **数据级并行** | GPU、CPU 向量单元（AVX/NEON）、**向量处理器** | 数据级并行 |
| **MISD** | 多 | 单 | 冗余或流水线处理 | 容错系统（如航天飞机飞控计算机）；**袁书认为现实中不存在这种计算机** | — |
| **MIMD** | 多 | 多 | **线程级 / 任务级并行** | 多核 CPU、多处理器、集群、超级计算机 | 线程级及以上 |

要点：

- **SISD**：仅包含一个处理器和一个存储器，一段时间内只执行一条指令流，每条指令最多处理两个数据（双目运算）或一个数据（单目运算）。现代单核 CPU 在宏观上仍是 SISD，但在微观上通过**流水线、超标量、超流水线、VLIW** 等技术挖掘**指令级并行**，从而在 SISD 框架内压榨单指令流的性能。
- **SIMD**：一个指令控制部件 + 多个处理单元 + 多个（局部）存储器，所有处于执行状态的处理单元**同时执行同一条指令**，但各自处理**不同的数据**。适合循环体向量化、图像/音频处理、图形学渲染、科学计算、神经网络等高度规整的数据级并行任务。
- **MIMD**：一定包含多个计算机或多个处理器，是目前大多数并行处理系统的处理方式。它可以同时支持数据并行（同一程序的多个副本处理不同数据，即 SPMD）和任务并行。

**向量处理器（vector processor）属于 SIMD**，专门面向向量型数据的并行计算。它与普通 SIMD 的差别在于：

1. 拥有专门的**向量指令集**：一条 `VADD` 指令即可完成两个含几十到上百个元素的向量相加，而普通 CPU 必须写循环。
2. 拥有**大容量向量寄存器**，一个向量寄存器存放一整个向量。
3. 计算单元是**高度流水化**的向量功能单元，可以每周期送入一组数据并每周期产出一组结果，吞吐率极高。
4. 拥有专门优化的 Load/Store 单元，可在主存与向量寄存器之间**流式传输**整块连续数据。

向量处理器多采用**流水线方式**（也有阵列方式，以流水线为主），主存储器容量限定了机器的解题规模，因此需要**大容量集中式公共存储器**，并常用**多端口同时读取的交叉多模块存储器**来维持高速运算所需的数据供给。

**MISD** 在实际中极为罕见，其价值不在加速计算而在**提高可靠性与容错**：用多个处理器以不同的算法/实现处理**同一个**关键数据流，再通过表决机制比较输出，从而屏蔽单机的硬件瞬时故障或软件缺陷。

### 硬件多线程

**问题背景**：现代处理器经常要等待较慢的存储器。当遇到 Cache 缺失或长流水线暂停时，处理器进入**停顿（stall）**，成百上千个时钟周期被浪费。

**硬件多线程（hardware multithreading）**：允许**单个物理处理器核心**同时管理**多个线程的状态**，操作系统会把这一个物理核心看成多个「逻辑核心」。当一个线程因停顿时无法继续时，核心快速切换到另一个已就绪的线程，用原本会被浪费的周期执行它的指令。其核心思想是**用线程级并行（TLP）掩盖延迟和停顿**，提高核心资源利用率与整体吞吐量。

硬件上的改造：**复制线程状态**（为每个线程提供独立的 PC、通用寄存器等）；**共享执行资源**（ALU、FPU、Cache、流水线等由所有线程共享）。

| 特性 | 细粒度多线程 FGMT | 粗粒度多线程 CGMT | 同时多线程 SMT |
| :--- | :--- | :--- | :--- |
| 线程切换时机 | **每个时钟周期**都切换 | **只在发生高成本长停顿**（如 L2/L3 缺失）时切换 | 不切换，同一周期执行**多个线程**的指令 |
| 是否清空流水线 | 不涉及 | 需要清空流水线，切换开销较大 | — |
| 主要优点 | 能掩盖**所有类型**的延迟 | 单线程性能几乎不受影响，实现相对简单 | 资源利用率与吞吐量最大化 |
| 主要缺点 | **降低单线程执行速度**，必须轮流分享执行周期 | **无法掩盖短延迟**（数据依赖、分支预测失败等） | 硬件设计最复杂，存在资源竞争与安全问题 |
| 典型实现 | — | — | Intel 超线程（HT）、AMD SMT |

:::warn 硬件多线程的三条易错点
- **硬件多线程不只用于多核处理器**。它是核心内部的技术，**单核处理器同样可以采用**。所以「硬件多线程技术只可用于多核处理器」是错的。
- **SMT 下操作系统看到的是多个逻辑核心**（如 4 核 8 线程的 CPU，OS 认为有 8 个可用处理器），由操作系统把软件线程调度到这些逻辑核心上，硬件再在微观层面执行。
- **细粒度多线程与粗粒度多线程不能混淆**：「每个时钟周期轮流」是细粒度；「只在长停顿时才切换」是粗粒度。
:::

### 多核处理器

**多核（multi-core）处理器**：把**多个处理器核**集成在**同一个芯片**上。每个核有自己独立的控制部件、运算部件、寄存器和私有 Cache（L1，通常还有 L2），多个核共享片上的 L3 Cache、内存控制器等资源，并通过片上互连网络通信。

- 多核处理器中，各核可以执行**不同的指令流**、处理**不同的数据**，因此多核处理器属于 **MIMD 结构**。
- 多核的并行主要是**线程级并行**，需要操作系统的调度与并行编程配合；而流水线、超标量挖掘的是**指令级并行**，对软件透明。
- 多核相比多处理器系统（多个独立芯片）的优势：通信延迟低、带宽高、共享资源、功耗与体积更优。
- 多核带来的新问题：**Cache 一致性**、共享资源的竞争与同步、以及编程模型上对任务分解与负载均衡的要求。

### 共享内存多处理器（SMP）与 UMA/NUMA、Cache 一致性问题

**共享内存多处理器**：多个处理器共享同一物理主存，通过互连网络（总线、交叉开关、网络）连接。

**对称多处理器（SMP）**：将多个**相同类型**的 CPU 通过总线互连，并以**等同地位**共享系统所有资源，多个 CPU 对称工作，**无主次或从属关系**，共享**单一物理地址空间**。因为每个 CPU 访问内存中任何地址所需时间相同，**SMP 就是一种 UMA 结构**。

按「处理器访问存储单元的时间是否一致」划分：

| 结构 | 全称 | 特征 | 说明 |
| :--- | :--- | :--- | :--- |
| **UMA** | 一致性内存访问 | 所有处理器访问**任何**存储单元的**时间一致** | 也就是 SMP。所有 CPU 通过共享总线/交叉开关连到主存。实现简单，但 CPU 个数多时会产生访存冲突、总线成为瓶颈，可扩展性受限 |
| **NUMA** | 非一致性内存访问 | 处理器对**不同**存储单元的访问时间**可能不一致**，取决于位置：访问本地存储器快，访问其他处理器的存储器慢 | 把物理内存分布到各处理器附近形成「节点」。所有共享存储模块**统一编址**、形成单一地址空间，非本地内存也用 Load/Store 访问，因此 NUMA 上运行 UMA 程序无需改动，但同主频下性能不如 UMA |

NUMA 的两个细分形态：

- **NC-NUMA**（No Cache NUMA）：处理器**不带**高速缓存。
- **CC-NUMA**（Cache-Coherent NUMA）：处理器**带一致性高速缓存**，必须解决 Cache 一致性，最常见的是**基于目录（directory）的 Cache 一致性机制**——每个存储器中有一个存放目录信息的存储区，每个主存块对应一个目录项，目录项中有有效位等字段，记录该主存块与各 Cache 行的对应关系。

**Cache 一致性问题**：在共享内存多处理器中，同一主存块可能同时驻留在多个处理器的私有 Cache 中。若某处理器修改了自己 Cache 中的副本，而其他处理器 Cache 中的旧副本仍然有效并被读取，就会读到**过期数据**。这就是** Cache 一致性（cache coherence）问题**。

解决思路：

- **监听 / 总线侦听（snooping）协议**：各 Cache 通过共享总线监听其他处理器发出的访存事务；某个 Cache 中的副本被修改时，将修改信息广播到所有核的 Cache，若其他核的 Cache 中有该数据则将其置为**无效**，同时把主存中的数据同步更新。**MESI 协议**就是这类协议的典型代表（每个 Cache 行处于 M/E/S/I 四种状态之一）。
- **基于目录的协议**：适用于互连网络不是共享总线、处理器数量较多的情形（如 CC-NUMA），由目录记录每个主存块被哪些 Cache 缓存、是否被修改，从而只向相关节点发送一致性维护消息，避免广播。

**多计算机系统（multicomputer）**与多处理器系统的区别：多计算机的每个节点有**自己私有的地址空间**，「共享内存」是靠消息传递在软件层模拟的。因为没有共享内存总线瓶颈和 Cache 一致性问题，多计算机系统具有**极高的可扩展性**，可扩展到成千上万个节点，当代顶级超级计算机几乎都采用这种架构。

:::exam 真题考法
「下列关于并行处理技术的叙述中，不正确的是」——注意四个判据：**多核处理器属于 MIMD**（对）；**向量处理器属于 SIMD**（对）；**硬件多线程只能用于多核**（**错**，单核也可）；**SMP 中所有处理器共享单一物理地址空间**（对）。
:::

## 易错清单

:::warn 必须逐条自检的易错点
1. **MAR 由可寻址单元个数决定，不由机器字长决定**；MDR 由存储字长决定，不必然等于机器字长。
2. **PC 在「至少多少位」的题目里可以不等于地址位数**（按字边界对齐时省掉低位，4 GB 主存 + 32 位定长指令 → PC 30 位、IR 32 位）。
3. **汇编程序员可见**的是 PC、通用寄存器、基址/变址寄存器、PSW；**MAR、MDR、IR、微指令寄存器、暂存寄存器、控制存储器不可见**。
4. **空操作指令的指令周期中 PC 和 IR 都会改变**，不能说「任何寄存器都不改变」。
5. **机器周期通常以主存工作周期为基准**，而不是以 CPU 内部运算时间为基准。
6. **ALU 是组合逻辑（操作）元件**，PSW、GPR、暂存器是时序逻辑（状态）元件；**数据通路不包含控制部件，但包含（或配合）异常检测与响应电路**。
7. **单周期处理器不能采用单总线结构**；单周期的 CPI=1，多周期 CPI>1，基本流水线 CPI=1，超标量 CPI<1，超流水线 CPI=1。
8. **微命令与微操作一一对应**；只有**相容**的微命令能出现在同一条微指令中；一条微指令的并行能力由操作控制字段决定。
9. **控制存储器按地址访问**，不是按内容访问；CS 在 CPU 内、用 ROM、存微指令、字长 = 微指令长度。
10. **字段直接编码必须为每个字段留出「全 0 不操作」编码**，故含 $ n $ 个互斥微命令的字段要 $ \lceil\log_2(n+1)\rceil $ 位。
11. **下地址字段位数由微指令总条数决定**（含公共取指微程序），不是由机器指令条数决定。
12. **公共取指微程序的微指令只计入一次**，不要按指令条数重复累加。
13. **异常是同步的、在指令执行过程中检测；外部中断是异步的、在指令执行结束后检测**。
14. **自陷（trap）是内部异常**，不是外部中断；fault 返回原指令重执行，trap 返回下一条，abort 不返回。
15. **中断隐指令 = 关中断 + 保护断点 + 引出中断服务程序**，由硬件完成；**保存通用寄存器是软件（OS）的事**。
16. **可屏蔽中断请求有效 ≠ 立即响应**；必须同时满足「有未屏蔽请求 + 开中断 + 当前指令执行结束」。
17. **NMI 在关中断状态下也能响应**，且优先级高于所有可屏蔽中断；「NMI 没有中断响应周期 / 不需要保存断点」都是错的。
18. **中断屏蔽字改变的是处理优先级，不是响应优先级**；每个屏蔽字必须**至少含一个 1**（屏蔽自身）；某中断源的屏蔽字中，所有「处理优先级不高于它」的源对应位均为 1。
19. **多重中断中 CPU 不是一直关中断**：保护现场前后要按「开中断—处理—关中断」的顺序配合。
20. **转发（旁路）是解决冒险的手段，本身不引起阻塞**；但 **load-use 冒险即使有转发也必须阻塞至少 1 拍**，所以「所有数据冒险都能靠转发解决」是错的。
21. **指令 Cache 与数据 Cache 分离的主要目的是减少流水线的结构冒险（资源冲突）**，不是提高命中率。
22. **基本按序流水线中只会出现 RAW**；WAR、WAW 只在乱序/多发射中成为真正冒险，靠**寄存器重命名**消除。
23. **超流水线不改变 CPI（仍为 1）**；**超标量的本质是一周期发射多条指令，不缩短功能段处理时间**。
24. **动态调度与乱序执行的模型是「有序发射、乱序执行、有序提交」**，有序提交是保证异常精确与程序状态正确的关键。
25. **硬件多线程不限于多核**，单核也能实现；SMT 让操作系统看到多个逻辑核心。
26. **多核处理器属于 MIMD，向量处理器属于 SIMD，MISD 通常认为现实中不存在**。
27. **SMP = UMA**（访问任何地址时间一致）；NUMA 中访问本地存储器快于远程；**CC-NUMA** 用基于目录的协议维护 Cache 一致性。
28. **Cache 一致性问题**来自私有 Cache 中同一主存块的多个副本被分别读写；解决途径是侦听（如 MESI）或基于目录的协议。
