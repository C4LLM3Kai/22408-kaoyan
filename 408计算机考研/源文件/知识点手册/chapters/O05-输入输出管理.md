## I/O 管理基础

### 设备

#### 设备的基本概念

**I/O 设备**是能够向计算机输入数据或接收计算机输出数据的外部设备。一个完整的 I/O 设备由两部分组成：

- **设备本体**：执行具体输入/输出操作的物理装置，如磁盘的盘片与磁头、打印机的机械部分。
- **设备控制器（I/O 接口）**：连接在系统总线上的专用电路，负责把操作系统发出的抽象命令（如「读取第 $x$ 个扇区」）转换为设备可识别的电信号，并协调主机与设备之间的数据传送。

把这两部分分开的意义在于：**操作系统只需要面对统一规格的控制器，不必了解成千上万种设备的具体机械细节**。设备本体的差异被控制器封装掉了，这正是整个 I/O 软件能分层的前提。

#### 设备的分类

设备的分类方法有四种，考纲要求的是前三类中的传输速率、信息交换单位和共享属性。

**按传输速率分类**：

| 类别 | 传输速率 | 典型设备 |
|---|---|---|
| 低速设备 | 每秒几字节至数百字节 | 键盘、鼠标 |
| 中速设备 | 每秒数千字节至数十千字节 | 激光打印机 |
| 高速设备 | 每秒数百千字节至数百兆字节以上 | 磁盘、光盘、网卡 |

**按信息交换单位分类**（最重要，直接决定 I/O 接口的类型）：

- **块设备（block device）**：以**固定大小的数据块**为单位进行信息交换，如磁盘、固态硬盘、U 盘、光盘。基本特征是**传输速率较高、可寻址（支持随机访问）**，可以对任意数据块直接读写。块设备的 I/O 通常采用 **DMA 方式**。
- **字符设备（character device）**：以**字符（字节）**为单位进行信息交换，如键盘、鼠标、打印机、串口。基本特征是**传输速率较低、不可寻址**，只能顺序访问，I/O 通常采用**中断驱动**方式。大多数字符设备属于独占设备，因此字符设备接口必须提供「打开」和「关闭」操作以获取和释放访问权限。

:::warn 块设备「隐藏了磁盘的二维结构」
磁盘物理上要用「柱面号 — 盘面号 — 扇区号」三维地址定位，但**块设备接口把磁盘的所有扇区按数据块排成一个线性序列**，上层只需给出「第 $n$ 号逻辑块」即可。这个「二维变一维」的抽象是文件系统能在磁盘上建立的前提，也是块设备接口与字符设备接口最本质的区别。
:::

**按共享属性分类**（决定设备分配策略）：

- **独占设备**：任一时刻只允许一个进程使用。一旦分配给某进程，便由该进程独占，直至其主动释放或终止。典型的独占设备多为低速设备，如打印机、磁带机。**独占设备采用静态分配方式**。
- **共享设备**：允许在一段时间内由多个进程**宏观上同时**访问，**微观上交替**使用。磁盘是典型的共享设备。**共享设备必须是可寻址、可随机访问的设备**，并且采用动态分配方式。
- **虚拟设备**：通过 **SPOOLing 技术**把独占设备改造为多个逻辑设备，使多个进程能并发使用。其实质是用高速共享设备（如磁盘）作缓冲区，实现独占设备的逻辑共享。

:::warn 「宏观同时、微观交替」的准确含义
共享设备是「一段时间内可同时访问」，**不是「同一时刻」**。物理上一个磁盘的磁头在同一瞬间只能在一个位置，它不可能同一时刻既为进程 A 读文件 X、又为进程 B 读文件 Y。操作系统把多个请求排入队列，用磁盘调度算法快速切换服务，因为切换速度远快于人的感知，所以宏观上表现为「同时共享」。**「共享设备可以同一时刻被多个进程访问」是错误说法。**
:::

#### I/O 接口的功能与组成

**I/O 接口（I/O interface）**，又称**设备控制器（device controller）**或**I/O 适配器**，是 CPU 与设备之间的桥梁。它接收 CPU 发来的命令、控制设备工作，使 CPU 从繁杂的设备控制事务中解脱出来。

**主要功能**：

1. **接收和识别命令**：接收 CPU 发来的控制命令，对命令字进行译码，产生相应的控制信号。
2. **数据交换**：实现 CPU 与控制器之间、控制器与设备之间的数据传送。
3. **标识和报告设备状态**：保存设备的状态信息（忙、就绪、错误）供 CPU 查询。
4. **地址识别**：识别 CPU 要访问的是哪个设备、哪个寄存器。
5. **数据缓冲**：用数据缓冲寄存器弥补 CPU 与设备之间的速度差异。
6. **差错控制**：对传送的数据进行校验（如 CRC），发现并报告错误。

**基本组成**：

| 部件 | 作用 |
|---|---|
| **数据缓冲寄存器（DBR）** | 缓冲数据，匹配 CPU 与外设的速度差异。输入时暂存设备送来的数据，输出时暂存 CPU 送来的数据 |
| **状态寄存器** | 反馈设备状态（忙、就绪、错误）。程序查询方式中 CPU 靠读它判断设备是否就绪 |
| **控制寄存器（命令寄存器）** | 接收 CPU 发来的控制命令（复位、识别、读写控制等） |
| **设备存储器** | 非必需部件，用于设备自身的运算处理，如显卡的显存 |
| **地址译码器与 I/O 控制逻辑** | 对命令字译码，产生控制信号送往外设；收集外设状态写入状态寄存器 |

:::key 状态寄存器与控制寄存器可以合并
**状态寄存器和控制寄存器在传送方向上是相反的**（状态寄存器是设备→CPU，控制寄存器是 CPU→设备），而且 **CPU 对它们的访问在时间上一般是错开的**（先写命令，再等状态，不会同时进行），因此有的 I/O 接口把它们合并成一个「控制/状态寄存器」，用同一组地址、靠读写方向区分。
:::

**与 I/O 接口相连的三类总线都是双向的**，它们传输的内容要分清：

- **数据总线**：真正的 I/O 数据、CPU 写入控制寄存器的**命令字（控制字）**、CPU 读出的**状态字**。三者都经数据总线传输。
- **地址总线**：I/O 端口地址（供地址译码器选中寄存器）、DMA 时接口作为主设备发出的主存地址。
- **控制总线**：读/写信号、时钟与总线控制权协商信号（DMA 请求 HOLD、授权 HLDA）、应答信号、中断响应信号。

:::exam 数据线上能传什么
统考考过「在 I/O 总线的数据线上传输的信息包括：I/O 接口中的命令字、状态字、中断类型号」。答案是**三者都包括**。要特别注意**中断类型号也走数据线**，但它不是设备控制器发出的，而是**可编程中断控制器**在中断请求判优之后生成的。另外要区分「通过数据线写入控制寄存器的命令字」与「通过控制总线发送的控制信号」：前者是一个**具体的数据值**（回答「做什么」），后者是**时序与协调信号**（回答「怎么传」）。
:::

#### I/O 端口

**I/O 端口（I/O port）**指设备控制器中的数据缓冲寄存器、状态/控制寄存器等的统称。数据缓冲寄存器简称**数据端口**，状态/控制寄存器简称**状态/控制端口**。所有 I/O 端口编号组成的空间称为 **I/O 地址空间**。

对数据端口、控制/状态寄存器的访问通过**I/O 指令**完成。例如 IA-32 提供 `in`、`ins`、`out`、`outs` 四条专门指令，其中 `in`/`ins` 把控制器中寄存器的内容取到 CPU 通用寄存器，`out`/`outs` 把通用寄存器的内容送到控制器寄存器。**这些 I/O 指令只能在操作系统内核的底层 I/O 软件中使用，因此属于特权指令。**

I/O 端口的编址方式有两种：

| 比较项 | 统一编址（内存映射 I/O） | 独立编址（I/O 映射方式） |
|---|---|---|
| 概念 | 把 I/O 端口当成主存单元一起编址 | I/O 端口地址与存储器地址无关 |
| 访问方式 | 不需要专门的 I/O 指令，用统一的 `LOAD`/`STORE` 访存指令即可 | 需要**专门的输入输出指令**，如 x86 用 `IN`/`OUT` 访问端口、用 `MOV` 访存 |
| 优点 | 端口编址空间大；读写控制逻辑简单；**I/O 保护可由分段或分页存储管理实现，无需专门的保护机制** | 用专用 I/O 指令，程序清晰便于编程；端口地址位数少，**地址译码速度快**；**不占用主存地址空间** |
| 缺点 | **占用主存地址空间**，使主存地址空间变小；地址位数多，**译码速度慢** | I/O 指令类型少，一般只能做传送操作，**程序设计灵活性差**；需要 CPU 提供存储器读写与设备读写两组控制信号，控制逻辑复杂 |
| 如何区分 I/O 与主存 | 靠**不同地址码**区分（看地址落在哪个范围） | 靠**不同指令**区分；由于二者独立编址，部分地址空间会重叠，因此用不同指令生成不同的总线控制信号来标识 |
| 典型处理器 | MIPS、ARM 等 RISC 处理器 | Intel x86 处理器 |

:::warn 统一编址的 I/O 端口不能被 Cache 缓存
I/O 地址虽然映射到了主存空间，但**接口中的数据是动态变化的**，如果被 Cache 缓存，CPU 读到的将是过时的副本，无法了解设备的实时状态。因此统一编址的系统必须把 I/O 区间标记为「不可缓存」。这是统一编址方式下一个容易被忽略的陷阱。
:::

### I/O 控制方式

I/O 控制方式的发展主线只有一条：**尽量减少主机对 I/O 控制的干预，把主机从繁杂的 I/O 控制事务中解脱出来**。从程序查询到中断驱动，再到 DMA 与通道，每一次进步都是让 CPU 少管一点、让硬件多管一点。

#### 轮询方式

**轮询方式（程序查询 / 程序直接控制方式）**指输入输出完全依靠 CPU 执行程序实现。CPU 要与设备交换数据时，先设置接口的命令寄存器启动设备，然后在设备准备数据的过程中**反复读取接口中的状态寄存器**查询设备是否就绪，根据查询结果决定是继续等待还是传送数据。

以简单键盘输入为例：按键按下后，键盘控制器把键值放入数据缓冲寄存器 DBR，并把状态寄存器 DSR 的「数据就绪 Ready」位置 1。CPU 需要取键值时，先读 DSR 并判断 Ready 位，为 0 就继续查询，为 1 才读 DBR，读完后 Ready 位自动清 0。

对于复杂设备，流程多一步：CPU 先查询设备状态，就绪后才向 I/O 接口**发送命令与参数**启动设备，此后设备进入可能较长的**设备准备阶段**，CPU 则不断查询状态，就绪时才进行实际的数据传输。

轮询有两种策略：

- **独占查询（忙等待）**：设备一旦启动，CPU 就一直连续查询，外设与 CPU 完全串行工作，查询期间 CPU 不能执行其他任务。
- **定时查询**：CPU 周期性（每隔固定时间）查询一次接口状态，查询之间可以执行其他任务。**适用于外设不支持中断的多任务系统**。定时查询的难点是定时长度不好确定：太短则数据可能还没准备好、白查一趟；太长则数据可能已就绪而未被及时处理而丢失。

**优点**：只需软件即可实现，硬件开销少，控制简单。
**缺点**：CPU 被独占，大量时间花在等待与查询上，利用率很低。多见于**早期单任务操作系统**，现代计算机在操作系统启动引导至多任务系统之前也采用它。

:::warn 轮询并不一定只适合慢速设备
一般印象里「轮询适合慢速设备、中断适合高速设备」，但这里有反例：对于**极高速设备**，设备准备数据的时间可能比「两次上下文切换 + 中断服务」的开销还短，此时中断反而成为瓶颈，轮询效率更高。所以**程序查询方式在 NVMe 这类超高速固态硬盘上也被采用**。「轮询只适合慢速设备」是错误说法。
:::

:::exam 轮询开销占比计算（高频计算题）
这类题只有一个套路：**先求「每秒必须查询多少次」，再求「每次查询需要多少个时钟周期」，两者相乘除以 CPU 每秒的时钟周期数**。

【例】CPU 主频 50MHz，查询程序运行一次至少 500 个时钟周期，设备每秒至少需查询 200 次，求 CPU 用于该设备的 I/O 时间占比。
每秒查询需 $200\times500=100000=0.1$ M 个时钟周期，占比 $=0.1\text{M}/50\text{M}=0.2\%$。

【例】主频 500MHz、CPI 为 4，设备 A 数据传输率 2MBps，接口中有一个 32 位数据缓冲寄存器，每次输入输出至少执行 10 条指令。求最多间隔多久查询一次、以及占比。
32 位 = 4B，设备准备这 4B 需 $4\text{B}/2\text{MBps}=2\ \mu s$，所以**最多每 $2\ \mu s$ 查询一次**。CPU 每秒查询 $1s/2\mu s=0.5\text{M}$ 次，每次至少 $4\times10=40$ 个时钟周期，占比 $=40\times0.5\text{M}/500\text{M}=4\%$。

做题要注意：**数据传输率按 10 为底**（$1\text{M}=10^6$），不要按 $2^{20}$ 算。
:::

#### 中断方式

**中断方式（中断驱动 I/O）**用中断机制彻底避免 CPU 忙等。完整流程如下：

1. **用户系统调用**：用户进程 P1 通过 `read()` 等系统调用请求从设备读数据，陷入内核态。
2. **驱动程序启动设备**：设备驱动程序把读命令及相关参数通过 I/O 接口发送给设备。
3. **操作系统进程调度**：操作系统把 P1 放入 I/O 等待队列（阻塞态），通过上下文切换调度进程 P2 运行。P2 的执行与设备准备数据**并行**。
4. **设备发出中断请求**：设备准备好数据后**主动**向 CPU 发中断请求，这是中断方式的核心——不需要 CPU 来问，设备自己会报。
5. **CPU 响应并执行中断服务程序**：CPU 暂停当前进程，保存现场，转入设备中断服务程序，在中断服务程序里完成实际的数据传送，并唤醒 I/O 等待队列中的 P1。
6. **恢复运行**：中断服务程序最后一条是中断返回指令，返回断点继续执行；P1 已变为就绪态，等待被调度后完成后续 I/O 操作并返回用户态。

**优点**：设备主动报告，CPU 与外设并行工作，CPU 利用率显著提高；不需要考虑轮询频率问题，实时性更好。
**缺点**：**额外开销是两次进程上下文切换的时间加上中断服务程序本身的开销**。当设备准备数据的时间远长于这些开销时，中断方式收益很大；反之则可能不如轮询。此外，**每次数据传送都要经过 CPU 通用寄存器，且以字（字节）为单位**，对块设备进行大数据量传送时效率很低。

:::warn 谁最先拿到键盘输入的数据
统考考过「本地用户通过键盘登录系统时，首先获得键盘输入信息的程序是」——答案是**中断处理程序**，不是命令解释程序、系统调用服务程序或用户登录程序。键盘产生数据后先发中断，CPU 响应后执行键盘中断处理程序，由它把数据从控制器数据寄存器取走并放入内核缓冲区。**中断服务例程执行结束时，输入数据位于内核缓冲区**（2024 年考过这一点），既不是控制器数据寄存器，也不是用户缓冲区。
:::

:::exam 字符打印的经典过程（2023 年大题原型）
以 `printf("darkmoon")` 为例，可以把整条链路串起来：

1. 用户进程 P 调用库函数，最终执行 `write()` 系统调用，指令序列中有陷阱指令，从用户态陷入内核态。
2. **先把字符串复制到内核缓冲区**。原因是中断服务程序执行时 CPU 仍运行在其他进程（如 Q）的环境中，地址空间是 Q 的，如果数据留在 P 的用户空间就取不到了；而内核空间被所有进程共享映射。
3. 驱动程序查询打印机状态寄存器直到就绪，把**第一个字符**从内核缓冲区经通用寄存器写入打印机控制器的**数据寄存器（I/O 端口）**，再向**控制寄存器**写「启动打印」命令。
4. 执行调度程序，把 P 由运行态改为阻塞态并挂入阻塞队列，切换进程 Q 运行。
5. 打印机取走字符打印完毕后，控制器发出中断请求。CPU 在 Q 执行完一条指令后响应，执行**中断隐指令**（关中断、保存断点、中断服务程序寻址），转入字符打印中断服务程序。
6. 中断服务程序检查是否打印完毕：未完毕就取下一个字符送数据端口并再次启动打印，然后中断返回继续执行 Q；已完毕就把 P 从阻塞队列取出、状态改为就绪态，放入就绪队列。
7. 当调度器选中 P 后，P 执行系统调用的最后阶段，返回用户态继续执行。

**因此：第一个字符是在系统调用服务例程控制下打印的，其余字符都由中断服务程序控制打印。** 这就是 2023 年第 46 题（键盘输入）与 2019 年大题所考的完整链路。
:::

#### DMA 方式

**直接内存访问（Direct Memory Access，DMA）**在总线上设置 **DMA 控制器（DMAC）**，由 DMAC 临时接管总线，代替 CPU 控制外部设备与内存之间的**批量**数据交换。数据**无须经过 CPU 寄存器中转**，直接通过系统总线在设备与内存之间交换，完全消除了程序查询和中断方式中 CPU 进行实际数据传送的开销。

DMA 方式**主要用于高速设备的块数据传输**，磁盘、显卡、网卡、声卡都支持 DMA。它也可以用于内存之间的大批量数据搬移。

**DMA 控制器的组成**：

| 部件 | 作用 |
|---|---|
| **主存地址寄存器（地址计数器 AR）** | 存放交换数据的内存地址。预处理阶段由 CPU 设置，每次传送后自动加 1 或减 1 |
| **字计数器（WC）** | 记录数据块长度。每传送一个字/字节自动减 1，减到 0 时传送完毕并发出 DMA 中断请求 |
| **数据缓冲寄存器（DBR）** | DMAC 作为从设备时接收 CPU 的数据，作为主设备时暂存传输数据。若采用「周期窃取」模式则不经过它，性能更好 |
| **命令寄存器 / 状态寄存器** | 接收 CPU 控制命令 / 向 CPU 反馈 DMAC 状态 |
| **DMA 控制逻辑** | 控制和时序电路，修改地址计数器与字计数器，指定传输方向，协调 DMA 请求与 CPU 响应，并支持中断机制 |

DMAC 需要总线控制权时通过 **HOLD** 信号向 CPU 发总线请求，CPU 允许时用 **HLDA** 信号授权。支持 DMA 的设备用 **DREQ（DMA 请求）** 和 **DACK（DMA 应答）** 两条**专用控制线**与 DMAC 相连（注意：这两条线通常**不属于系统总线**）。一个 DMAC 支持多个通路，每条通路有各自独立的内存地址寄存器和字计数器，可同时为多个设备服务。

**DMAC 在总线上的两种角色**：预处理阶段 CPU 是主设备、DMAC 是从设备；数据传输阶段 DMAC 是主设备、CPU 反而成了旁观者。现代 PC 中 CPU、DMAC、I/O 接口、内存都通过系统总线相连，**不存在所谓的「设备和内存之间的专用数据通路」**。

**DMA 的三种内存争用处理方式**：

| 方式 | 工作方式 | 优点 | 缺点 |
|---|---|---|---|
| **停止 CPU 访问内存** | DMAC 一旦获得总线就连续占用多个存储周期，直到整个数据块传完才归还 | 控制最简单（总线请求/建立/归还各只需一次）；**数据传输率最高** | DMA 期间 CPU 无法响应任何中断，实时性差；CPU 即使不需要访存也被强制暂停，浪费 CPU 时间 |
| **DMA 与 CPU 交替访问内存** | 把每个存储周期固定分为两半，CPU 只用其中一半，DMAC 只用另一半 | 无需总线请求，CPU 感觉不到 DMA 存在 | 硬件代价高；双方各自的空闲时间片都被浪费，**内存带宽实际减半** |
| **周期挪用（周期窃取）** | 设备每准备好一个字，DMAC 就申请并占用**一个**存储周期完成传送，随后立即归还总线 | 按需分配，对 CPU 影响最小；**已成为 DMA 的主流方法** | 总线请求、仲裁、归还本身有额外开销，一次挪用实际需 2～5 个存储周期 |

:::warn 周期挪用的三个易错点
1. **CPU 让出总线的时机是一个存储（总线）周期结束之后，不是「立即暂停当前指令」**。一条指令可能包含多个总线周期，CPU 必须做完当前这个总线周期才能让出总线。这与中断请求在**一条指令执行结束后**响应是两回事。
2. **周期挪用期间 CPU 并不是完全不能访问主存**。DMA 只在需要传数据时「偷走」一个周期，两次窃取之间的间隙 CPU 完全可以正常访存。「整个数据块传送过程中 CPU 不可以访问主存储器」是错误说法——那是「停止 CPU 访问内存」方式的特点。
3. **DMA 操作不修改 CPU 寄存器，因此不存在现场保护和恢复问题**。如果周期挪用发生时 CPU 不需要访存，则对 CPU 执行没有任何性能影响；如果恰好形成访存冲突，则 **DMA 优先访问内存**。
:::

**DMA 传输的三个阶段**：

| 阶段 | 具体操作 | 结束时状态 |
|---|---|---|
| **预处理阶段**（CPU 是主设备，DMAC 是从设备） | ① 用 I/O 指令向 DMAC 写入主存起始地址（地址寄存器 AR）、传输长度（字计数器 WC）、传输方向（控制/命令寄存器标志位）；② 向 I/O 接口发启动命令，写入磁盘扇区号、设备地址等；③ 向 DMAC 控制寄存器写入「启动 DMA」命令位 | 请求进程被**阻塞**，调度其他进程运行 |
| **数据传输阶段**（DMAC 是主设备，CPU 袖手旁观） | 周期挪用循环：设备备好一个字 → 经 DREQ 通知 DMAC → DMAC 经 HOLD 申请总线 → CPU 在**当前机器周期/总线事务结束后**用 HLDA 授权并断开总线连接（驱动器进高阻态）→ DMAC 送主存地址到地址总线、发内存写 `MEMW` 与 I/O 读 `IORD` 控制信号、用 DACK 应答设备，设备把数据字送到数据总线，内存控制器写入 → AR 加 1、WC 减 1，撤销 HOLD 立即归还总线 | WC 减到 0 |
| **后处理阶段**（中断服务程序） | DMAC 经 `INTR` 发「DMA 完成」中断 → CPU 响应中断、保存现场，进中断服务程序 → 读 DMAC 状态寄存器判断是否成功 → 成功则把等待进程由阻塞态改为就绪态并放入就绪队列；失败则执行错误处理程序 → 恢复现场、中断返回 | 进程就绪，等待被调度 |

:::key DMA 传输顺序记忆
**②初始化 DMA 控制器并启动磁盘 → ③从磁盘传输一块数据到内存缓冲区 → ①DMA 控制器发出中断请求 → ④执行「DMA 结束」中断服务程序**（2017 年原题的四个选项就是这个顺序）。口诀：**先配置、再搬运、后中断、最后收尾**。
:::

#### 中断方式与 DMA 方式的区别

| 对比维度 | 中断方式 | DMA 方式 |
|---|---|---|
| 核心思想 | **以 CPU 为核心**，CPU 亲自处理每一次数据传送请求 | **以存储器为核心**，把数据传送「外包」给专业硬件 |
| 数据传送主体 | **软件**（CPU 执行中断服务程序） | **硬件**（DMA 控制器） |
| 数据是否经过 CPU | 每个字/字节都经过 CPU 通用寄存器 | **不经过 CPU 寄存器**，设备与内存直接交换 |
| CPU 介入程度 | **高**，每个数据单位传送都要执行一次中断服务程序 | **低**，只在预处理和后处理阶段介入 |
| 请求的对象 | **CPU 处理时间**（请求中断 CPU） | **总线控制权**（请求系统总线的临时使用权） |
| 响应时机 | **一条指令执行结束后** | **一个总线（机器）周期结束后**，响应更快 |
| 数据传送单位 | 字（字节） | 数据块 |
| 对 CPU 现场的影响 | 完全中止当前程序，需完整**保护现场、恢复现场** | **不改变 CPU 现场**，无需保护和恢复 |
| 中断次数 | 每个数据单位一次，**频繁** | **整个数据块仅一次**（DMA 完成中断） |
| CPU 与外设并行度 | 低（并行性只体现在设备准备数据期间） | 高 |
| 适用设备 | 中、低速设备的少量数据传送，如键盘、鼠标 | **高速设备的批量数据传送**，如磁盘、网卡 |
| 功能范围 | **广泛**，除数据传送外还能处理各种随机事件（时钟中断、电源掉电等） | **功能单一**，只用于成块数据的快速输入输出 |
| 优先级 | 低于 DMA | **优先级高**，DMA 与 CPU 同时访存时 DMA 优先 |

:::warn 关于两者区别的两个常见错误说法
1. 「中断方式适用于**所有**外部设备，DMA 方式仅适用于**快速**外部设备」——太绝对。中断方式对速率极高的设备效率很低，并不适用；DMA 理论上也能用于低速设备，只是浪费资源。
2. 「中断服务程序不直接控制 I/O 硬件」——**错误**。设备驱动程序和中断服务程序**共同**直接控制硬件：驱动程序负责**发起**操作（向命令/数据/地址寄存器写入、启动设备），中断服务程序负责**响应**完成（从状态寄存器读取结果、向硬件发送确认信号清除中断）。
:::

:::exam 三种控制方式的综合使用
在实际系统中，这三种方式常常**配合使用**。以从磁盘读数据为例：

1. 进程 P1 用**程序查询方式**设置传送参数，初始化 DMAC 的相关寄存器；
2. CPU 向磁盘控制器发「寻道」命令，随后切换到其他进程 P2 执行；寻道完成后磁盘发出「寻道结束」中断；
3. CPU 响应中断，在中断服务程序中发「查找扇区」命令，返回 P2；扇区找到后磁盘发出「查找结束」中断；
4. CPU 响应中断，在中断服务程序中**启动 DMA 传送**；
5. DMAC 完成数据块传送后发出「DMA 结束」中断，CPU 在中断服务程序中做数据校验等后处理。

**结论：在用 DMA 方式进行硬盘等高速设备的数据传送时，仍然要用到程序查询和中断方式。**
:::

### I/O 软件层次结构

为使复杂的 I/O 软件具有清晰的结构、良好的可移植性和易适应性，I/O 软件采用**层次式结构**：每层都利用下层提供的服务完成某些子功能，并屏蔽实现细节，向高层提供服务。整个 I/O 软件可视为四层结构。

#### 用户层 I/O 软件

**职责**：实现与用户交互的接口。用户直接调用用户层的、与 I/O 操作有关的**库函数**来操作设备。

**关键点**：

- 大部分 I/O 软件在操作系统内部，但仍有**一小部分在用户层**，包括与用户程序链接在一起的库函数。
- **用户层软件必须通过一组系统调用来获取操作系统服务**。库函数本身运行在**用户态**，它不直接操作硬件，而是通过系统调用陷入内核态，把请求交给下一层的设备独立性软件。
- 这一层的目标是**隐藏所有底层 I/O 操作的复杂性**，为用户提供简单、方便、统一的接口。

**显式 I/O 与隐式 I/O**：通过库函数和系统调用进行的 I/O 是**显式 I/O**（最常见）。此外还有由虚拟内存系统自动触发的**隐式 I/O**：访问一个不在物理内存的虚拟地址会触发缺页异常、自动发起一次磁盘 I/O；用 `mmap` 把文件映射到虚拟地址空间后，首次访问或修改该地址也会触发磁盘 I/O。

#### 设备独立性软件

**设备独立性（设备无关性）**指应用程序独立于具体使用的物理设备。为实现这一点，引入了**逻辑设备**和**物理设备**两个概念：**应用程序用逻辑设备名请求某类设备，系统执行时再把逻辑设备名映射为物理设备名。**

使用逻辑设备名有两大好处：**① 增加设备分配的灵活性；② 易于实现 I/O 重定向**（用于 I/O 操作的设备可以更换，而不必修改应用程序）。

**主要功能可分为两方面**：

- **执行所有设备的公有操作**：设备的分配与回收；将逻辑设备名映射为物理设备名；设备保护（禁止用户直接访问设备）；缓冲管理；差错控制；**提供独立于设备、大小统一的逻辑块，屏蔽设备之间信息交换单位大小和传输速率的差异**；设备命名（把物理名映射为 `/dev/sda1` 这类符号名）。
- **向用户层（或文件层）提供统一接口**：无论何种设备，向用户提供的接口相同，如统一使用 `read`/`write`。

**差错控制的两类错误**：**暂时性错误**（如网络丢包）通常通过**重试**纠正，连续失败才视为持久性错误，主要由驱动程序处理；**持久性错误**（如磁盘划痕）由操作系统记入**坏块表**，后续 I/O 自动绕过。

:::exam I/O 软件四层的排列顺序（2011、2012）
自上而下是：**用户层 I/O 软件 → 设备独立性软件 → 设备驱动程序 → 中断处理程序**。中断处理程序最接近硬件，必须在最底层；驱动程序必须在设备独立性软件之下。一次磁盘 I/O 请求的处理流程是：**用户程序 → 系统调用处理程序 → 设备驱动程序 → 中断处理程序**。

另外，**SPOOLing 技术的归属有争议**：在经典教材（如汤子瀛《计算机操作系统》）中它被划入用户层 I/O 软件，而 **408 大纲把它划入设备独立性软件**。理解上：SPOOLing 的入口和守护进程确实工作在用户态，但它的核心功能（实现设备共享）属于设备独立性软件的职责。统考遇到这类有争议的问题通常会回避，按大纲理解即可。
:::

#### 设备驱动程序

**职责**：与硬件直接相关，接收上层软件发来的**抽象 I/O 请求**（如 `read`、`write`），转换为对设备的**具体要求**后发送给设备控制器，控制 I/O 设备工作；同时把设备控制器发来的信号传送给上层软件，从而为 I/O 内核子系统**隐藏设备控制器之间的差异**。

**具体功能**：

1. **抽象请求到具体操作的转换**：把逻辑盘块号翻译成硬件能识别的柱面号、磁头号、扇区号等参数。
2. **合法性与权限校验**：检查用户请求的操作是否被允许（如只读打开的设备不能写）。
3. **设备状态检查**：读控制器状态寄存器，确认设备处于可接收命令的就绪状态。
4. **参数设置与传送**：向控制器的命令、数据、方式等寄存器写入本次任务所需参数。
5. **发出 I/O 命令并启动设备**：设备空闲则立即启动；设备忙则把请求进程的 PCB 挂到该设备的等待队列上。
6. **响应中断**：及时响应设备控制器发出的中断请求，并按中断类型调用相应的中断处理程序。

**特点**：

- **硬件相关性**：与特定硬件的物理特性紧密耦合，**每类设备配置一个驱动程序**，通常由设备制造厂商提供而非 OS 设计者设计。因此**在系统中增加一个新设备时需要安装厂商提供的新驱动程序**。
- **与 I/O 控制方式紧密相关**：程序查询方式的驱动需要循环查询状态；中断方式的驱动需要启动设备后阻塞进程、由中断唤醒；DMA 方式的驱动需要配置 DMA 地址、计数和方向。**「驱动程序与 I/O 控制方式无关」是错误说法**（2022 年考过）。
- **一部分必须用汇编语言书写**，很多基本部分已固化在 ROM 中。
- **可重入性**：必须在一次调用完成前能被另一个任务（如中断）再次安全调用。典型场景是：驱动代码正在响应 `write` 系统调用执行时，被该设备完成上一次操作产生的硬件中断打断，CPU 转去执行该驱动的另一部分代码（中断服务程序）。如果两部分代码共享全局或静态变量而无保护，就会数据错乱。可重入函数通过不使用这类共享数据或加特殊保护来避免。

**设备处理方式**（不重要，了解即可）：为每类设备设一个进程；为整个系统设一个 I/O 进程（或分设输入进程和输出进程）；不设专门进程，只为各类设备设驱动程序供用户或系统进程调用（目前用得较多）。

#### 中断处理程序

**职责**：保存被中断进程的 CPU 环境，转入相应的中断处理程序进行处理，处理完毕再恢复被中断进程的现场并返回。

**主要任务**：进程上下文切换、对中断信号源进行测试、读取设备状态、修改进程状态等。

**位置**：**由于中断处理与硬件紧密相关，对用户而言应尽量加以屏蔽，因此放在操作系统的底层**，系统的其余部分尽可能少地与它发生联系。

整个中断过程包括**中断响应**和**中断处理**两个阶段：**中断响应完全由硬件完成，中断处理则由 CPU 执行中断服务程序完成**。虽然不同中断源对应的服务程序不同，但所有中断服务程序的结构相同，包括**准备阶段、处理阶段和恢复阶段**。I/O 中断的典型过程是：设备控制器准备好数据后通过中断控制器向 CPU 发中断请求 → 保护被中断进程的 CPU 上下文 → 转入相应的设备中断处理函数 → 进行中断处理 → 恢复被中断进程的上下文。

:::key 以一次 read 命令总结四层各自的分工
1. 用户要读某设备内容，通过操作系统提供的 `read` 命令接口——经过**用户层**。
2. 操作系统给用户的接口一般是统一的通用接口，用户发出的 `read` 先经**设备独立层**解析（确定逻辑块号、检查高速缓存、找到对应驱动程序），然后交给下层。
3. 不同类型的设备对 `read` 的行为不同，需要针对具体设备把 `read` 解析成不同指令——经过**设备驱动层**。
4. 命令解析完毕后需要中断正在运行的进程、转而执行实际的数据传送，这就需要**中断处理程序**。
:::

### 输入/输出应用程序接口

不同类型的设备读写方式差异很大，为便于应用程序访问，操作系统把大量差异隐藏起来，并把设备分成几种常规类型，相应地把 I/O 核心子系统与高层之间的接口也分为若干类。

#### 字符设备接口

字符设备以字符为单位存取和传输，如键盘、打印机、鼠标。特点是**传输速率较低、不可寻址**，I/O 通常采用**中断驱动**方式。具体特征：

- **流式/顺序访问（不可寻址）**：数据只能从当前位置顺序读写，没有「块」也没有地址。由于不可寻址，通常为字符设备建立一个**字符缓冲区**，用户程序通过 `get()` 从缓冲区取字符、通过 `put()` 把字符输出到缓冲区。
- **需要打开和关闭操作**：大多数字符设备属于**独占设备**，接口中必须提供打开和关闭操作来获取和释放访问权限，以实现互斥共享。
- **控制命令丰富**：通常支持特殊的 `ioctl()` 系统调用进行设备特定设置（如设置串口波特率）。

#### 块设备接口

块设备以数据块为单位存取和传输，如磁盘、固态硬盘、U 盘、SD 卡、CD。特点是**传输速率较高、可寻址**，I/O 常采用 **DMA 方式**。具体特征：

- **可寻址/随机访问**：可以直接命令设备「读第 500 号数据块」，**隐藏了磁盘的二维结构**——把磁盘所有扇区按数据块顺序划分，二维结构变为**线性序列**，文件系统因此可以在其上构建。
- **固定大小的数据单元**：无论读写，基本单位都是一个「块」。即使只想读 1 个字节，操作系统也可能从硬件读整个块再提取所需字节。
- **缓冲机制**：操作系统大量使用内存（Buffer Cache）缓存块设备数据。请求的块若已在缓存中就直接从内存返回，极大提高性能；写操作也可能先写缓存，稍后统一刷到设备。
- **将抽象命令映射为低层操作**：用户使用的 `open()`、`read()`/`write()`、`lseek()` 无法被设备直接识别，块设备接口把它们映射为设备能识别的具体操作。

#### 网络设备接口

网络设备接口是专门用于与其他计算机交换数据的接口，不直接与读写相关，而是围绕**数据包的收发和连接的管理**设计，典型设备是以太网卡。关键特征：

- **不使用常规文件 API**：应用程序通常不用 `open` 再 `read`/`write` 的方式操作网卡，而是使用一套独立的 **套接字（Socket）API**。
- **数据包导向**：数据以网络数据包形式封装传输，每个包包含目标地址、源地址等信息。
- **连接管理**：需要处理建立连接（TCP）、无连接通信（UDP）、监听端口、超时处理等网络概念。
- **异步通信**：网络不可靠且有延迟，发送一个数据包后不知道它何时到达、对方何时回复。

主要系统调用：`socket()` 创建通信端点、`bind()` 把地址绑定到套接字、`send()`/`recv()` 收发数据包、`close()` 关闭连接。

#### 阻塞 I/O 与非阻塞 I/O

以一次典型的 `read` 操作为例，I/O 包含两个独立的阶段：**① 等待数据准备**（内核等待数据到达：等键盘输入、等磁盘寻道读出、等网络包到达）；**② 数据从内核复制到用户空间**。**阻塞与非阻塞的核心区别在于它们如何处理第一个阶段。**

| 比较项 | 阻塞 I/O | 非阻塞 I/O |
|---|---|---|
| 数据未就绪时的行为 | 系统调用**不立即返回**，进程由运行态转为**等待（阻塞）态**，CPU 去执行其他进程 | 系统调用**立即返回一个错误码**，进程不进入等待态 |
| 后续处理 | 数据准备好后内核唤醒该进程，系统调用继续把数据从内核复制到用户空间后返回 | 进程需**反复主动调用**该系统调用来检查数据是否就绪，这个过程称为**轮询** |
| 数据就绪后 | 由内核主动唤醒并完成复制 | 仍需进程自己发起调用完成复制，然后才能处理数据 |
| 优点 | 代码逻辑线性、顺序，直观易懂；`read()` 返回后数据一定有效 | **并发潜力高**，一个线程可同时照看多个 I/O 通道，线程利用率高 |
| 缺点 | **并发能力差**，一个线程任一时刻只能处理一个 I/O 请求，等待期间整个线程被挂起 | **编程模型复杂**（要写轮询循环）；轮询本身消耗 CPU（忙等待） |

:::key 为什么非阻塞 I/O 的并发度更高
核心在于**线程资源的释放**。阻塞模型下一个线程与一个 I/O 通道「绑定等死」，线程生命周期被漫长的 I/O 等待占据；非阻塞模型下线程发起 I/O 调用后立即被「释放」，可以转而为其他成千上万个 I/O 通道服务或执行其他计算。就像一个服务员可以同时照看很多张桌子，而不是站在一张桌子旁死等客人吃完。
:::

:::warn 阻塞与非阻塞、同步与异步的层次
**阻塞/非阻塞描述的是「等待数据准备」这一阶段进程的行为**；**同步/异步描述的是「数据复制」阶段由谁完成**。阻塞 I/O 和非阻塞 I/O 在数据复制阶段都是**同步**的——都必须由进程自己发起调用、由内核把数据复制到用户空间后才算完成。真正的**异步 I/O** 是发起请求后立即返回，数据准备和数据复制全部由内核完成，内核在**整个操作完成后**才通知进程，进程在此期间不需要任何轮询或等待。
:::

## 设备独立软件

### 缓冲区管理

#### 为什么需要缓冲

**缓冲（buffer）**是一段临时存储区，可以由专门的硬件寄存器组成，但硬件成本高、容量小，一般只用于速度要求极高的场合（如 TLB、设备控制器中的数据缓冲寄存器），**更多利用内存作为缓冲区**。缓冲区管理的主要功能是组织好这些缓冲区并提供获得和释放的手段。

引入缓冲区的目的有四个：

1. **缓和 CPU 与 I/O 设备间速度不匹配的矛盾**。凡在数据到达速率与离去速率不同的地方都可设置缓冲区。CPU 运算速率远高于 I/O 设备，若在打印机或控制器中设缓冲区，CPU 可快速暂存输出数据后立即去做别的计算，打印机慢慢从缓冲区取数据打印，CPU 效率大幅提高。
2. **减少对 CPU 的中断频率，放宽对 CPU 中断响应时间的限制**。例如速率为 9.6kb/s 的数据通信，若只用一位缓冲接收，则每 100$\mu$s 就要中断 CPU 一次，且 CPU 必须在 100$\mu$s 内响应，否则数据被冲掉。若设置 8 位缓冲寄存器，中断频率降为原来的 1/8；再设一个 8 位寄存器，响应时间可从 100$\mu$s 放宽到 800$\mu$s。
3. **解决数据粒度（数据单元大小）不匹配的问题**。生产者数据粒度小于消费者时，生产者可连续生产几个单元，凑够消费者要求的单元大小后消费者再取走；反之消费者也可分几次取走一个大数据单元。
4. **提高 CPU 与 I/O 设备之间的并行性**，提高系统吞吐量和设备利用率。

#### 缓冲与缓存的区别

两者都是一段临时存储区，都能协调高速设备与低速设备的速度差异，但**工作原理不同：缓冲是一个「中转站」，缓存是数据源的副本**。

| 特性 | 缓冲（Buffer） | 缓存（Cache） |
|---|---|---|
| 核心目的 | 缓和速度/粒度不匹配 | 加速对数据的**重复**访问 |
| 工作模式 | 数据的「中转站」 | 数据源的「高速副本」「快捷方式」 |
| 数据性质 | 中转数据，可能是**唯一**的存在（源方发出后不再保留） | 一定是源数据的**子集（副本）** |
| 数据流向 | 通常是单向的，被消费后即失效 | 可被反复读取 |
| 性能指标 | 关注**吞吐量** | 关注**命中率** |

**磁盘高速缓存**就是这个意义上的缓存：操作系统在内存的内核空间开辟高速缓存，把最近从块设备读出或写入的数据保存在 RAM 中。它**逻辑上属于磁盘，物理上驻留在内存**。读取时先查缓存，命中则直接从内存返回，未命中才发起真正的磁盘 I/O；写入有**写通（直写）**（同时写缓存和磁盘，安全但性能提升有限）和**回写**（只写缓存并标记为脏，之后择机刷回磁盘，性能极高但有数据丢失风险，是现代 OS 普遍采用的策略）两种策略。

:::warn 缓冲区在用户空间还是内核空间
用户进程提出 I/O 请求时指定的缓冲区在**用户空间**（如 `fread(buf, size, num, fp)` 中的 `buf`）。陷入内核后，内核通常会在**内核空间**再开辟一个或两个缓冲区，底层 I/O 软件直接使用**内核空间**的缓冲区存放 I/O 数据。**为什么不直接用用户空间的缓冲区？** 因为外设进行 I/O 期间用户进程被挂起，用户空间的缓冲区所在页面可能被替换出去，那样就无法获得缓冲区中的 I/O 数据；此外还便于解决不同块设备读写单位不一致、便于共享等问题。
:::

#### 单缓冲

假设用户进程请求块设备读入若干块数据，采用单缓冲时操作系统在**主存（内核空间）**中为其分配**一个**缓冲区（若无特别说明，一个缓冲区的大小就是一个块）。

设：从磁盘把一块数据输入到缓冲区的时间为 $T$，操作系统把缓冲区中的数据传送到用户进程工作区的时间为 $M$，CPU 对这一块数据处理的时间为 $C$。

取初始状态为**工作区是满的、缓冲区是空的**（若无明确说明，通常认为缓冲区与工作区大小相等）：

- 若 $T>C$：工作区数据处理完用时 $C$ 时缓冲区还没充满，需再等到 $T$ 时刻缓冲区才满，然后缓冲区向工作区传送数据，工作区满时缓冲区同时为空，用时 $M$。到达下一个相同状态，整个过程用时 $T+M$。
- 若 $T<C$：缓冲区早已充满并等待，工作区处理完才能传送，用时 $C+M$。

:::key 单缓冲处理每块数据的时间
$$\text{单缓冲每块时间} = \max(T,\ C) + M$$
即**「输入」与「处理」可以并行，但「传送」必须串在两者之后**。因为只有一个缓冲区，设备向缓冲区写入数据与 CPU 处理工作区数据可以重叠，但缓冲区向工作区传送时必须独占缓冲区。
:::

处理 $n$ 块数据的总时间为：

$$(n-1)\left[\max(T,C)+M\right] + (C+T+M)$$

即**前 $n-1$ 块按流水节奏并行，最后一块需要完整的串行收尾**（输入、传送、处理各走一遍）。

#### 双缓冲

由于缓冲区是共享资源，生产者与消费者使用缓冲区时必须互斥。如果消费者尚未取走缓冲区中的数据，即使生产者又生产出新数据也无法送入缓冲区，生产者只能等待。设置两个缓冲区便可解决这个问题：设备输入时先把数据送入缓冲区 1，装满后转向缓冲区 2 写入；此时操作系统可从已满的缓冲区 1 取数据送用户工作区并由 CPU 处理。

取初始状态为**工作区空、其中一个缓冲区满、另一个缓冲区空**：

- 若 $T>C+M$：设备输入所需时间大于传送与处理的总时间，设备可连续工作。当缓冲区 2 的数据处理完毕（用时 $C+M$）时缓冲区 1 尚未装满，系统需等待其装满才能把下一块从缓冲区 1 传送到工作区。处理每块数据所需时间为 $T$。
- 若 $T<C+M$：设备输入较快，CPU 无须等待设备。缓冲区 1 很快装满，但系统仍需等缓冲区 2 的数据完全处理完毕才能切换并传送缓冲区 1 的内容。处理每块数据所需时间为 $C+M$。

:::key 双缓冲处理每块数据的时间
$$\text{双缓冲每块时间} = \max(T,\ C+M)$$
即**「处理」与「传送」串行（两者都发生在工作区侧，且传送依赖处理的完成），但「传送+处理」整体与「输入」并行**。
:::

处理 $n$ 块数据的总时间为：

$$(n-1)\left[\max(T,\ C+M)\right] + (C+T+M)$$

**双缓冲在通信中的应用**：两台机器通信时每台需配置发送缓冲区和接收缓冲区。若要实现**全双工通信**（双方同时收发数据），每台机器必须分别设置发送缓冲区和接收缓冲区；若每台只配一个缓冲区，则无法同时进行发送与接收。

#### 循环缓冲

若输入与输出速度相差较大，双缓冲难以充分发挥作用，此时采用多于两个缓冲区的方案。**循环缓冲（环形缓冲）**由若干个大小相等的缓冲区构成，每个缓冲区有一个链接指针指向下一个，最后一个的指针指向第一个，构成一个**循环队列**。系统维护两个指针：**`in` 指向下一个待写入的空缓冲区，`out` 指向下一个待读取的满缓冲区**，输入进程和计算进程分别推进 `in` 和 `out`。

#### 缓冲池

单缓冲、双缓冲、循环缓冲都是**为特定生产者和消费者进程专门设置的专用缓冲**。系统较大时会有许多这样的循环缓冲，既消耗大量内存，利用率又不高。为提高利用率，引入**既可用于输入又可用于输出的公用缓冲池**。

**缓冲池与缓冲区的区别**：缓冲区仅仅是一组内存块的链表，而**缓冲池是包含了一个管理的数据结构及一组操作函数的管理机制**。

缓冲池中**具有相同类型的缓冲区链接成一个队列**，按使用状况形成三个队列：**空白缓冲队列**（空缓冲区链成，用于取空缓冲区写入）、**输入队列**（装满输入数据的缓冲区链成，供用户程序读取）、**输出队列**（装满输出数据的缓冲区链成，等待被输出设备读取）。

另外按缓冲区在实际运算中扮演的功能不同，设置**四种工作缓冲区**（`h` 代表 host/用户进程，`s` 代表 system/设备，`in`/`out` 代表方向）：

| 工作缓冲区 | 用途 |
|---|---|
| `hin`（收容输入） | 缓冲池与 I/O 设备之间，收容输入的数据 |
| `sin`（提取输入） | 缓冲池与用户进程空间之间，提取输入的数据 |
| `hout`（收容输出） | 缓冲池与用户进程空间之间，收容输出的数据 |
| `sout`（提取输出） | 缓冲池与 I/O 设备之间，提取输出的数据 |

**四种工作方式**（规律：**取出操作一律从队头取，挂入队列一律挂到队尾**）：

| 工作方式 | 从哪个队列队首取 | 装满/取空后挂到哪个队列队尾 |
|---|---|---|
| **收容输入**（输入进程） | 空缓冲队列 | 输入队列 |
| **提取输入**（计算进程） | 输入队列 | 空缓冲队列 |
| **收容输出**（计算进程） | 空缓冲队列 | 输出队列 |
| **提取输出**（输出进程） | 输出队列 | 空缓冲队列 |

:::key 缓冲方式的分类归属
**单缓冲、双缓冲、循环缓冲属于生产者消费者进程的专用缓冲；缓冲池属于进程共享缓冲。** 这与内存管理中「请求分页的可变分配全局置换使用系统空页队列」的思想类似，都是把资源集中管理以提高利用率。
:::

:::exam 单/双缓冲时间计算的两个真题
【2011-31】某文件占 10 个磁盘块，逐个读入主存缓冲区并送用户区分析。一个缓冲区与一个磁盘块大小相同，把一块读入缓冲区的时间 $T=100\ \mu s$，缓冲区数据传送到用户区的时间 $M=50\ \mu s$，CPU 分析一块的时间 $C=50\ \mu s$。求单缓冲和双缓冲下读入并分析完该文件的时间。

- 单缓冲：每块 $\max(100,50)+50=150\ \mu s$，总时间 $=(10-1)\times150+(50+100+50)=1350+200=1550\ \mu s$。
- 双缓冲：每块 $\max(100,\ 50+50)=\max(100,100)=100\ \mu s$，总时间 $=(10-1)\times100+(50+100+50)=900+200=1100\ \mu s$。

答案选 **B（1550μs、1100μs）**。

【2013-27】系统缓冲区和用户工作区均采用单缓冲，从外设读入一块到系统缓冲区 $T=100$，从系统缓冲区读入用户工作区 $M=5$，对用户工作区中一块的分析时间 $C=90$。求读入并分析 2 个数据块的最短时间。

代入 $n$ 块公式：$(2-1)\times[\max(100,90)+5]+(90+100+5)=1\times105+195=300$。答案选 **C（300）**。

:::warn 算这类题最容易踩的坑
1. **不要用「$n\times$ 每块时间」**。$n$ 块的总时间必须用 $(n-1)$ 倍的流水时间加上最后一块的完整串行时间 $(C+T+M)$，因为第一块必须先走完「输入→传送→处理」才能开始流水。若题目只问「处理每块的平均时间」才用 $\max(\cdot)+M$ 或 $\max(\cdot)$。
2. **单缓冲的 $M$ 在 $\max$ 之外，双缓冲的 $M$ 在 $\max$ 之内**。这是两者公式唯一的差别，也是判断题目该用哪个公式的关键。
3. **注意题目给的是「系统缓冲区→用户工作区」还是反过来**。$M$ 的方向不影响公式形式，但要确认 $T$ 是设备→缓冲区的时间。
4. 若题目强调「初始状态缓冲区为空、工作区为空」，需按题目给的初始状态重新推一遍，公式给出的是**稳定流水后的每块时间**。
:::

### 设备分配与回收

#### 设备分配的任务与总原则

设备分配的任务是按照一定策略，为提出 I/O 请求的进程分配合适的设备，并分配相应的控制器和通道，确保 CPU 与 I/O 设备之间能正常通信。

**总原则**：充分发挥设备的使用效率，尽可能让设备忙碌，又要避免因不合理的分配方法造成进程死锁。

> **通道**是一种独立于 CPU、专用于 I/O 控制的处理器，可以控制 I/O 设备与内存直接进行数据交换。通道的启动需要 CPU 执行相应指令，操作结束时向 CPU 发中断信号。数据交换过程中 CPU 无需干预，提高了 CPU 与 I/O 的并行程度。

#### 设备分配应考虑的因素

**（1）设备的固有属性**（按共享属性分三类）：

- **独占设备**：一个时段只能分配给一个进程（如打印机），利用率低。
- **共享设备**：一段时间内可同时分配给多个进程使用（如磁盘），各进程**宏观上同时共享、微观上交替使用**，因此要注意对访问先后次序进行合理调度，一般采用**动态分配方式**。
- **虚拟设备**：采用 SPOOLing 技术把独占设备改造成虚拟的共享设备，可同时分配给多个进程使用。

**（2）设备分配算法**：通常只采用**先来先服务（FCFS）**或**优先级高者优先**。FCFS 优先分配给队首进程；最高优先级优先算法把高优先级进程排在队列前方，优先级相同时按 FCFS 排队。

**（3）设备分配中的安全性**：

| 方式 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| **安全分配方式** | 为进程分配一个设备后就将进程**阻塞**，本次 I/O 完成后才唤醒。一个时段内每个进程只能使用一个设备 | **破坏了「请求和保持」条件，不会死锁** | 对一个进程来说 CPU 与 I/O 设备只能**串行工作** |
| **不安全分配方式** | 进程发出 I/O 请求后系统分配设备，进程**可继续执行**并发新的 I/O 请求，只有某个请求得不到满足时才阻塞。一个进程可同时使用多个设备 | 进程的计算任务与 I/O 任务可**并行处理**，进程推进迅速 | 可能具备「请求并保持」条件，**可能发生死锁**（需配合死锁避免、检测与解除） |

**（4）设备分配方式**：

- **静态分配**：进程运行前一次性分配其所需的全部设备、控制器和通道，运行结束后归还。**破坏了「请求和保持」条件，不会发生死锁**，主要用于**独占设备**。缺点是进程可能长期不用已分配的设备而其他进程又用不上，**设备利用率低**。
- **动态分配**：运行过程中按需申请。利用率高，**但有死锁可能**。

:::warn 静态分配与安全分配方式的关系
两者都通过「不让进程同时持有并等待」来破坏死锁条件，但层次不同：**静态分配说的是分配时机（一次性分配全部资源），安全分配方式说的是分配后进程的状态（立刻阻塞）**。另外注意：静态分配「可以提高设备利用率」是**错误**说法，恰恰相反，它降低利用率。
:::

#### 设备分配管理中的数据结构

设备分配的四个数据结构体现了「通道 → 控制器 → 设备」的从属关系。**一个设备控制器可供多个同类设备共享使用，一个通道可供多个设备控制器共享使用。**

| 数据结构 | 数量 | 主要字段 |
|---|---|---|
| **设备控制表 DCT**（Device Control Table） | 系统为**每个设备**配置一张 | 设备类型、设备标识符（物理设备名，系统内唯一）、设备状态（忙/闲）、**指向控制器表的指针**、重复执行次数或时间、**设备队列的队首指针** |
| **控制器控制表 COCT**（Controller Control Table） | **每个设备控制器**一张 | 控制器标识符、控制器状态（忙/闲）、**与控制器连接的通道表指针**、控制器队列的队首/队尾指针 |
| **通道控制表 CHCT**（Channel Control Table） | **每个通道**一张 | 通道标识符、通道状态（忙/闲）、**与通道连接的控制器表首址**、通道队列的队首/队尾指针 |
| **系统设备表 SDT**（System Device Table） | **整个系统只维护一张** | 每个表目对应一个设备，含设备类型、设备标识符、**指向 DCT 的指针**、驱动程序入口 |

:::key 四张表的记忆要点
**SDT 全系统只有一张**，是「总目录」，每个表目指向一个 DCT；**DCT 每个设备一张**，其「指向控制器表的指针」连接到 COCT；**COCT 每个控制器一张**，其「与控制器连接的通道表指针」连接到 CHCT；**CHCT 每个通道一张**。请求流程与这套链式结构一致：**SDT → DCT → COCT → CHCT**。
:::

#### 设备分配的步骤

以独占设备为例：

1. **分配设备**：根据 I/O 请求中的**物理设备名**查找 SDT，找出设备的 DCT，根据 DCT 中的设备状态字段判断状态。**若忙**，把进程 PCB 挂入**设备等待队列**；**若空闲**，把设备分配给该进程。
2. **分配控制器**：设备分配后，根据 DCT 找到对应的 COCT，查询控制器状态。若忙则挂入**控制器等待队列**，空闲则分配给该进程。
3. **分配通道**：控制器分配后，根据 COCT 找到对应的 CHCT，查询通道状态。若忙则挂入**通道等待队列**，空闲则分配给该进程。

**只有设备、控制器、通道三者都分配成功，这次设备分配才算成功**，之后便可启动 I/O 设备进行数据传送。

**用物理设备名分配的三大缺点**：① 用户编程时必须使用物理设备名，底层细节对用户不透明；② 换一个物理设备程序就无法运行（即使有同类型设备也不行）；③ 若请求的物理设备正忙，即使系统中还有同类型设备，进程也必须阻塞等待。

**改进方法是引入设备独立性**：建立**逻辑设备名到物理设备名的映射**，用户编程时只提供逻辑设备名。改进后用逻辑设备名分配时，操作系统根据逻辑设备名在 SDT 中查找**一个用户指定类型且空闲**的设备分配给进程，**只有所有该类型的设备都忙时才需要阻塞该进程**。

**逻辑设备表 LUT**（Logical Unit Table）：每个表项为⟨逻辑设备名，物理设备名，设备驱动程序入口地址⟩。

- 进程**首次**请求设备分配时，系统为其分配一台物理设备，同时在 LUT 中新增一个表项；
- 以后该进程再次通过**相同的逻辑设备名**请求设备时，**直接查表**即可。

**LUT 的两种建立方式**：

- **整个系统只有一张 LUT**：各用户所用的逻辑设备名不允许重复，**适用于单用户操作系统**。
- **每个用户一张 LUT**（存入用户进程的 PCB 中）：不同用户的逻辑设备名可重复，**适用于多用户操作系统**。可类比文件系统中单级目录（不允许重名）与多级目录（不同级可重名）的区别。

:::exam 设备分配相关的三道真题
【2009-32】程序员利用系统调用打开 I/O 设备时，通常使用的设备标识是——**逻辑设备**。用户程序通过系统调用请求设备时使用与具体硬件无关的逻辑设备名，物理设备名、主设备号、从设备号是内核或驱动程序识别具体硬件时使用的信息，不直接暴露给普通应用程序。

【2020-30】关于具备设备独立性的系统，错误叙述是「**更换物理设备后必须修改访问该设备的应用程序**」。设备独立性的目标正是让应用程序用逻辑设备名或文件名访问设备，更换设备时只需修改映射或驱动配置，应用程序通常不需要改变。

【2023-32】设备分配需要考虑的因素包括：**Ⅰ 设备类型、Ⅱ 访问权限、Ⅲ 占用状态、Ⅳ 逻辑设备与物理设备的映射关系**，答案是 D（四项全部）。设备类型决定分配规则，权限决定进程能否使用，占用状态决定能否立即分配，映射关系决定从哪个逻辑请求找到哪个实际设备。

补充：在 UNIX/Linux 中，设备名唯一确定一个特殊文件的 **i 节点**，i 节点中含**主设备号**（确定设备类型，据此定位对应的设备驱动程序）和**次设备号**（作为参数传给驱动程序，确定进行 I/O 操作的具体设备位置）。这就是「一切皆文件」设计的实现基础。
:::

### 假脱机技术（SPOOLing）

#### 为什么需要 SPOOLing

以打印机为例，未引入 SPOOLing 时 CPU 需要亲自处理每一次数据搬运：从内存读数据 → 写入寄存器 → 从寄存器写到 I/O 端口。这带来四个弊端：

1. **CPU 资源被独占，效率极低**。打印机很慢，CPU 每发一小块数据就可能要停下来查询控制器状态，整个打印过程中 CPU 大部分时间花在等待和搬运上。
2. **用户进程长时间阻塞**。发起打印请求的进程在打印任务彻底完成前无法被唤醒，打印几十页文档可能被「冻结」几分钟。
3. **计算与 I/O 无法并行**。对同一进程而言两者严格串行。
4. **系统整体吞吐量低**。慢速 I/O 长时间占用 CPU，其他需要 CPU 的进程也被迫等待。

#### SPOOLing 系统的组成

**SPOOLing（Simultaneous Peripheral Operations On-Line，外部设备联机并行操作）**，又称**假脱机技术**，其思想源于早期的**脱机 I/O 方式**：依赖专用外围控制机，在主机不参与的情况下完成 I/O——输入时外围机把低速输入设备（如纸带机）的数据预先读入高速磁盘；输出时 CPU 先把结果高速写入磁盘，再由外围机送往低速输出设备。由于整个 I/O 过程**脱离主机控制**，因此称为脱机。

随着多道程序设计技术的发展，操作系统不再需要物理外围机，而通过专门的输入进程与输出进程**在主机直接控制下用软件模拟外围机的功能**。这种「以磁盘缓冲、用软件模拟脱机 I/O」的机制正是 SPOOLing 的本质：**「脱机」承袭自早期脱机 I/O 的思想，「假」则体现在用多道程序和磁盘空间替代了物理外围机。**

**SPOOLing 系统的四个组成部分**：

| 组成部分 | 位置 | 作用 |
|---|---|---|
| **输入井和输出井** | 磁盘上的两个专用存储区域 | 输入井模拟脱机输入的磁盘，暂存输入设备的数据；输出井模拟脱机输出的磁盘，暂存用户程序的输出数据。每个进程的数据以**井文件**形式保存，所有文件按顺序链接成输入队列或输出队列 |
| **输入缓冲区和输出缓冲区** | 内存中的两个缓冲区 | 输入缓冲区暂存由输入设备送来的数据，随后传送到输入井；输出缓冲区暂存从输出井读出的数据，随后传送到输出设备 |
| **输入进程和输出进程** | 内存中的系统进程 | 输入进程模拟脱机输入的外围控制机，把输入设备的数据经输入缓冲区送到输入井（CPU 需要输入数据时直接从输入井读）；输出进程模拟脱机输出的外围控制机，把用户程序的输出数据写入输出井，并在输出设备空闲时经输出缓冲区送到输出设备 |
| **井管理程序** | 内核 | 控制作业与磁盘井之间的信息交换 |

:::key SPOOLing 的前提条件
- **需要大容量、高速度的外存（通常为磁盘）作为输入井和输出井**；
- **需要多道程序技术的支持**；
- SPOOLing 是**用软件的方式**、建立在**通道技术和多道程序技术**基础之上的技术。

「SPOOLing 由用户作业控制设备与输入/输出井之间的数据传送」是**错误**说法（2016 年考过）——设备与井之间的数据传送由系统的输入/输出进程（假脱机服务程序）控制，对用户作业是**透明的**。
:::

#### 如何把独占设备改造为共享设备（打印机经典例子）

打印机是典型的独占设备。通过 SPOOLing 技术可把它改造为可供多个用户共享的虚拟设备。

当多个用户进程发出打印请求时，**SPOOLing 系统接受请求但并不真正立即把物理打印机分配给它们**，而是由输出进程为每个进程完成两项操作：

1. 在磁盘**输出井**中为其分配一个空闲盘块，把待打印数据写入其中；
2. 申请一张**用户请求打印表**，记录用户的打印要求，把该表挂到**假脱机打印队列**上。

完成这两步后，**用户进程即认为打印任务已完成**，可继续执行后续代码。实际上真正的打印尚未开始，但这个过程对用户完全透明。真正的打印由后台的**假脱机打印进程**负责：当打印机空闲时，该进程检查假脱机打印队列，若队列非空则取出队首请求表，根据表中信息把对应的输出数据从输出井读入内存缓冲区，再送到物理打印机输出；一个任务完成后继续处理下一个；队列为空则进入等待状态，直至有新的打印请求把它唤醒。

**结果**：由于用户进程只需把数据写入磁盘即可返回，而物理打印由后台进程按队列顺序依次执行，多个用户便可并发提交打印请求。系统为每个请求在输出井中分配独立存储区域，使各进程都以为自己独占了一台打印机。**一台物理打印机被虚拟为多台逻辑设备，实现了高效且透明的共享。**

#### SPOOLing 的三大特点与优点

:::key SPOOLing 系统的三大特点
1. **提高了 I/O 速度**：把对低速 I/O 设备的操作转化为对磁盘输出井中数据的存取，如同脱机输入输出一样，有效缓和了 CPU 与低速 I/O 设备之间速度不匹配的矛盾。
2. **将独占设备改造为共享设备**：在假脱机打印系统中，**实际上并未把物理设备分配给任何进程**。
3. **实现了虚拟设备功能**：每个进程都认为自己独占了一台设备。

SPOOLing 是一种**以空间换时间**的技术：牺牲磁盘存储空间（输入井、输出井），换取显著的时间节省。
:::

**SPOOLing 引入后的具体优点**：

- **提高了用户进程的响应速度**。数据一旦拷贝到输出缓冲区并由井管理程序接管，用户进程的任务就算完成，可立即返回。对用户进程而言，它感觉不是在跟慢速打印机打交道，而是跟高速磁盘打交道，只需把数据快速「甩」到输出井。这种把慢速设备「伪装」成高速设备的技术称为**设备虚拟化**。
- **缓和 CPU 与慢速 I/O 设备的速度矛盾，极大提高 CPU 利用率**。CPU 只参与两次高速传送：从用户空间拷贝到内核缓冲区（内存→内存，极快）、井管理程序把数据写入磁盘输出井（内存→磁盘，很快）。真正的「磁盘井→打印机」由独立的输出进程处理，可通过 DMA 进一步减少对 CPU 的打扰。
- **实现计算与 I/O 操作的真正并行**。CPU 全力执行进程 B 的计算任务，输出进程把磁盘井中进程 A 的打印数据送往打印机，输入进程从读卡器为进程 C 准备输入数据存入输入井——输入、计算、输出宏观上同时进行。
- **提高系统吞吐量**。综合以上优点，单位时间内完成的总任务量得到质的飞跃。

:::warn 关于 SPOOLing 的三个易错判断
1. **SPOOLing 不能缩短物理设备的传输时间**。它并**不改变**打印机本身的速度，只是让 CPU 不必等待这个慢速过程。认为「SPOOLing 缩短了数据在 I/O 设备与内存之间的物理传输时间」是**错误**的。
2. **用户进程的大部分等待时间不发生在对磁盘井的读写上**。恰恰相反，对磁盘井的读写非常快、等待时间极短，这才是 SPOOLing 的优势所在。
3. **输出进程不是由用户作业创建的**，它是一个系统级的后台服务进程（守护进程），由操作系统启动时创建和管理，**通常常驻内存**而非按需创建，数据来源是**输出井**而不是任何用户作业的地址空间。
:::

#### SPOOLing 与脱机 I/O 的区别与联系

| 比较项 | 脱机 I/O | SPOOLing（假脱机） |
|---|---|---|
| 是否需要专用外围机 | **需要**物理的外围控制机 | **不需要**，用输入/输出进程模拟外围机的功能 |
| 由谁控制 | 脱离主机控制，由外围机独立完成 | **在主机直接控制下**由系统进程完成 |
| 依赖的技术 | 外围机硬件 + 磁带/磁盘 | **多道程序设计技术 + 通道技术 + 高速外存** |
| 共同点 | 都用高速外存做缓冲，都实现低速 I/O 与 CPU 计算的并行，都能把一个独占设备虚拟为多个逻辑设备 | 同左 |

一句话总结联系与区别：**SPOOLing 是脱机 I/O 思想的「软件化」——用多道程序和磁盘空间替代了物理外围机，从而在主机直接控制下取得与脱机 I/O 同样的并行效果。**

### 设备驱动程序接口

#### 为什么需要统一接口

外设种类繁多、控制接口不一致，不同外设的设备驱动程序千差万别。如果计算机系统中每出现一种新外设，都要为添加新驱动程序而修改操作系统，会给操作系统开发者和系统用户带来很大麻烦。

因此**操作系统为所有外设的设备驱动程序规定了统一的接口**：新设备驱动程序只要按统一接口规范编制，就可以在**不修改操作系统**的情况下在系统中添加新驱动程序并使用新外设进行 I/O。

#### 统一接口的实现方式

对每种设备类型（如磁盘），操作系统定义一组驱动程序必须支持的函数（磁盘至少包含读、写、格式化等）。**驱动程序中通常包含一张表格，这张表格具有针对这些函数指向驱动程序自身实现的指针**（函数指针表）。装载驱动程序时操作系统记录该表的地址，需要调用某个函数时通过这张表发出**间接调用**。**这个函数指针表定义了驱动程序与操作系统其余部分之间的接口**，给定类型的所有设备都必须服从这一要求。

**工作流程举例**：应用程序需要从某块 SSD 读数据，内核上层软件发出通用的 `read()` 请求，内核根据目标设备查找「该 SSD 驱动的函数指针表」，看到标准 `read()` 接口对应的是 `samsung_ssd_read()` 的地址，于是**间接调用**该函数完成实际的硬件操作。

**统一接口的价值**示例：一台采用统一编址（内存映射）的打印机驱动可能用 `memcpy` 把整页数据拷到大块内存缓冲区，用直接读内存地址的方式获取状态；而一台采用独立编址的打印机驱动则用 `outb` 循环逐字节写数据端口，先发命令再从端口读回状态字节。**但两者向操作系统提供的接口函数签名完全相同**。上层模块调用时完全不知道也不需要关心数据是 `memcpy` 过去的还是一个字节一个字节发出去的。**这就是设备驱动程序接口的强大之处：把上层软件的调用意图与下层硬件的复杂实现彻底解耦。**

#### 设备名到驱动程序的映射

因为采用了统一的设备驱动程序接口，内核中与设备无关的 I/O 软件包含了所有外设统一公共接口中的处理部分。为简化处理，**内核高层 I/O 软件把所有外设都抽象成一个文件**，`设备名`和`文件名`在形式上没有任何差别，称为**设备文件名**。内核中与设备无关的 I/O 软件必须把不同的设备名和文件名映射到对应的设备驱动程序。

在 UNIX/Linux 中，一个设备名唯一确定一个特殊文件的 **i 节点**：i 节点中包含**主设备号**，主设备号用于定位相应的设备驱动程序；i 节点还包括**次设备号**，作为参数传给设备驱动程序，用来确定进行 I/O 操作的具体设备位置。除了普通文件和目录文件，还有一类特殊文件包括设备文件、链接文件等，设备特殊文件又分块设备特殊文件和字符设备特殊文件。

:::exam 关于设备驱动程序的一道辨析题
「对于设备驱动程序的描述，错误的是：**不同型号的同类设备提供给相同上层系统的接口可能不同**。」

解析：**同一个操作系统对同类型的所有设备提出了统一的接口规范要求**，因此不同型号的同类设备为同一个系统提供的接口是**一样**的；而**不同系统提出的接口规范可能不一样**，所以「同一型号的同类设备提供给不同上层系统的接口可能不同」是正确的。此外，设备驱动程序可以通过 I/O 端口访问设备（正确）；用户对设备的访问依靠驱动程序提供的接口，设备自身的中断处理也需要驱动程序接口支持（正确）。

另一道题：「操作系统为所有块设备定义统一的设备驱动程序接口，最主要的目标是——**向上层软件（如文件系统）隐藏不同硬件设备的物理实现差异**」。接口的目的不是提高 CPU 访问寄存器的效率，也与编程语言无关，更不只是简化中断流程。
:::

## 外存管理

### 磁盘

#### 磁盘结构

磁盘存储器由**记录介质（盘片）、磁盘驱动器、磁盘控制器**三大部分组成。

- **磁盘控制器**：磁盘存储器与主机的 **I/O 接口**，包括控制逻辑、时序电路、「并→串」转换和「串→并」转换电路。
- **磁盘驱动器**：包括读写电路、读/写转换开关、读/写磁头与磁头定位伺服系统。
- **盘片**：涂有磁性介质的物理盘片，通过设置磁场方向写入 0 和 1。

**五个基本术语**：

| 术语 | 定义 |
|---|---|
| **盘面（surface）** | 盘片的一个面。每个盘片的两个面各有一个磁头，因此**盘面号就是磁头号** |
| **磁道（track）** | 磁头与盘片相对运动形成的圆。磁头位于不同半径上得到不同磁道。**磁道从外向里编址，最外面的为 0 号磁道** |
| **柱面（cylinder）** | 所有盘面上**相同编号的磁道**构成的圆柱面。因此**磁道号就是柱面号** |
| **扇区（sector）** | 每个磁道被分成的若干圆弧，**是磁盘可寻址的最小单位**，以扇区为单位进行读写 |
| **磁头（head）** | 每个盘面对应一个磁头，同一柱面上所有磁头「共同进退」 |

**关键性质**：

- 读写磁盘时**总是写完一个柱面上所有的磁道后，再移到下一个柱面**。这个性质正是「柱面号在地址高位」的物理原因。
- 一个磁道存储的信息量相同，所以**内磁道的位密度比外磁道大**。
- 硬盘属于机械式部件，读写操作是串行的，**不可能在同一时刻既读又写，也不可能在同一时刻读两组数据或写两组数据**。

**磁盘的分类**（了解）：按磁头相对盘片径向是否固定分为**固定头磁盘**（每个磁道一个磁头）和**活动头磁盘**（磁头臂可伸缩定位磁道）；按盘片是否可更换分为**固定盘磁盘**和**可换盘磁盘**。

#### 格式化与分区

磁盘从出厂到可用，要经过「**低级格式化 → 分区 → 高级格式化 → 安装操作系统**」四步。

**第一步：低级格式化（物理格式化）**

在磁盘能存储数据之前进行，主要工作：

1. **把磁盘划分为扇区**，以便磁盘控制器能读写数据。每个扇区的数据结构包括**头部、数据区域和尾部**，头部和尾部包含**扇区号和纠错代码（ECC）**。控制器写入数据时 ECC 根据数据区域所有字节计算并更新；读取时重新计算并与存储值比较，不一致则表明数据损坏。ECC 能纠正少量错误并报告可恢复的软错误，读写时由控制器自动处理。
2. **检测并标记坏道**，避免存储数据时使用这些损坏区域。
3. **初始化逻辑块号到无损磁盘扇区的映射**，使制造商能够测试磁盘。

**第二步：分区**

把磁盘划分为多个独立部分，每个分区可被独立管理和使用。每个分区由一个或多个柱面组成，**每个分区的起始扇区和大小都记录在磁盘主引导记录的分区表中**。分区类型包括：**主分区**（每个磁盘最多四个，其中一个可标记为活动分区用于引导操作系统）、**扩展分区**（为克服主分区数量限制，可包含多个逻辑分区）、**逻辑分区**（在扩展分区内部创建）。操作系统可把每个分区当作一个单独磁盘，例如一个分区存操作系统可执行代码、另一个存用户数据。**分区对于实现多个 OS 并存是必需的。**

**第三步：高级格式化（逻辑格式化）**

在分区内创建文件系统，包括：

- **创建文件系统**：定义数据在磁盘上的组织方式（FAT32、NTFS、ext4 等）。
- **设置文件系统结构**：设置**超级块（superblock）、inode 表、目录结构**等。
- **初始化目录和文件表**：**设置根目录**和必要的文件表，以及对**保存空闲磁盘块信息的数据结构（如位示图、空闲表）进行初始化**。

为提高效率，大多数操作系统把多个相邻扇区组合成更大的块，称为**簇（cluster）**。一簇只能存放一个文件的内容，文件占用空间只能是簇的整数倍，文件大小小于一簇（甚至 0 字节）也要占用一簇。**磁盘 I/O 按块（扇区）完成，而文件系统 I/O 按簇完成**，这有效确保了 I/O 有更多的顺序访问和更少的随机访问。

**第四步：安装操作系统**（在逻辑格式化之后执行）。

:::exam 格式化各步考什么
【2017-29】磁盘**逻辑格式化**程序所做的工作是：**建立文件系统的根目录（Ⅱ）、对保存空闲磁盘块信息的数据结构进行初始化（Ⅳ）**。

- 「对磁盘进行分区（Ⅰ）」属于**分区**操作；
- 「确定磁盘扇区校验码所占位数（Ⅲ）」属于**低级格式化（物理格式化）**的工作。

答案选 B（仅Ⅱ、Ⅳ）。

【2017-26】某文件系统的簇和磁盘扇区大小分别为 1KB 和 512B，文件大小 1026B，系统分配给该文件的磁盘空间是：需要簇数 $\lceil1026/1024\rceil=2$，分配空间 $2\times1024\text{B}=2048\text{B}$。**按簇分配、不足一簇也占一簇**，答案选 D。
:::

**坏块的处理**：简单磁盘在格式化时扫描并标记坏块，文件系统不再分配它们；正常操作时才变坏的块需人工运行特殊程序搜索锁定，其中数据通常丢失。更复杂的磁盘由**控制器维护坏块列表**，低级格式化时预留一些**备用块**（操作系统看不到），用备用块逻辑地替代坏块，称为**扇区备用（sector sparing）**或**扇区转寄（sector forwarding）**。**总之对坏块的处理实质上就是用某种机制使系统不去使用坏块。**

#### 磁盘地址结构

磁盘的物理地址结构为：

| 驱动器号 | 柱面（磁道）号 | 盘面（磁头）号 | 扇区号 |
|---|---|---|---|
| 一台电脑可能有多个硬盘 | 移动磁头臂（寻道） | 激活某个磁头 | 通过旋转把特定扇区转到磁头下方 |

实际计算题中通常只考虑后三段，即 **（柱面号，盘面号，扇区号）**，三段都从 0 开始编号。把簇号转换成磁盘物理地址的过程由**磁盘驱动程序**完成。

:::key 为什么柱面号在前
假设磁盘有 8 个柱面、4 个盘面、8 个扇区，则需要各 3、2、3 个二进制位。

- **若地址结构是（盘面号，柱面号，扇区号）**：连续读取 $(00,000,000)\sim(00,001,111)$ 时，同一柱面不同盘面的部分可以**不移动磁头**换盘面磁头读完，但要读到下一个柱面 $(00,001,000)$ 起就必须**启动磁头臂把磁头移到下一个磁道**。
- **若地址结构是（柱面号，盘面号，扇区号）**：连续读取 $(000,00,000)\sim(000,01,111)$ 时，柱面号相同、只是盘面号不同，**不需要移动磁头臂，只需激活相邻盘面的磁头**即可，节省大量时间。

**结论：把柱面号放在高位，使逻辑上相邻的块在物理上尽量落在同一柱面内，从而把「寻道」这个最耗时的操作推迟到万不得已时才做。** 这是「柱面号在地址高位」的根本原因。
:::

#### 磁盘的性能指标与访问时间

**（1）记录密度**：沿磁道分布方向上单位长度内的磁道数目叫道密度；沿磁道方向上单位长度内存放的二进制信息数目叫位密度。

- **低密度存储方式**：所有磁道上的扇区数相同，因此**内道的位密度比外道高**。
- **高密度存储方式**：每个磁道上的位密度相同，因此**外道的扇区数比内道多**，整个磁盘容量比低密度盘高得多。

**（2）存储容量**：未格式化容量按道密度和位密度计算，包括头空、ID 域、CRC 码等信息，是可用磁化单元的总数；**格式化后的实际容量只包含数据区**，一般比未格式化容量小 10%～20%。

**（3）数据传输速率**：完成磁头定位和旋转等待后单位时间内读出或写入的二进制信息量。由于磁盘同一时刻只有一个磁头读写，内部数据传输速率等于单位时间内磁头划过的磁道弧长乘以位密度：

$$\text{内部数据传输速率} = \frac{\text{每分钟转速}}{60}\times\text{内圆周长}\times\text{最内道位密度}$$

若转速为 $r$（转/秒）、每条磁道容量为 $N$ 字节，则 **$D=rN$**。

**（4）平均存取时间**：

$$\text{响应时间} = \text{排队延迟}+\text{控制器时间}+\text{寻道时间}+\text{旋转等待时间}+\text{数据传输时间}$$

后三项之和称为**存取时间**：

$$\boxed{\text{存取时间} = \text{寻道时间} + \text{旋转等待时间} + \text{数据传输时间}}$$

| 时间项 | 公式 | 说明 |
|---|---|---|
| **寻道时间 $T_s$** | $T_s = s + m\cdot n$ | $s$ 为启动磁头臂的时间（约 2ms），$m$ 为磁头每跨越一条磁道的耗时（约 0.2ms），$n$ 为需要跨越的磁道数 |
| **旋转延迟（延迟时间）$T_r$** | $T_r = \dfrac{1}{2}\cdot\dfrac{1}{r} = \dfrac{1}{2r}$ | $r$ 为转速（转/秒）。定位过程中最多旋转 1 圈、最少不用旋转，所以**平均需要旋转半圈**，故除以 2。若转速为 $r$ 转/分，则旋转一圈的时间为 $60/r$ 秒 |
| **传输时间（读数据）$T_t$** | $T_t = \dfrac{b}{N}\cdot\dfrac{1}{r} = \dfrac{b}{rN}$ | 转速 $r$（转/秒），本次读/写字节数为 $b$，每条磁道字节数为 $N$。$b$ 字节需 $b/N$ 条磁道，读写一条磁道刚好是转一圈的时间 $1/r$ |
| **传输时间（访问一个扇区）** | $\dfrac{\text{旋转一圈的时间}}{\text{一条磁道的扇区总数}} = \dfrac{\text{一个扇区的容量}}{\text{数据传输率}}$ | 用于求一个扇区扫过磁头的时间 |

:::warn 转速单位的陷阱
转速可以用 $r$ 转/秒或 $r$ 转/分表示，**有些题目会给出「$r$ 秒/转」或「$r$ 分/转」**，此时公式需要相应取倒数。看到「7200rpm」要立刻意识到这是**转/分**，旋转一圈的时间是 $60/7200$ 秒 $=8.33$ ms，平均旋转延迟为 $4.17$ ms。**单位判断错误是这类题失分的第一大原因。**

另外注意：**磁盘的传输速率中 K、M、G、T 一般以 10 为底**（$1\text{K}=10^3$、$1\text{M}=10^6$、$1\text{G}=10^9$、$1\text{T}=10^{12}$），不是以 2 为底。
:::

:::exam 磁盘访问时间完整算例（2022-44 大题原型）
某磁盘驱动器有 4 个双面盘片，每个盘面 20000 个磁道，每个磁道 500 个扇区，每个扇区 512 字节，转速 7200rpm，平均寻道时间 5ms。

**（1）地址信息的三个字段名称及各占多少位**

三个字段是**柱面号、磁头号（盘面号）、扇区号**（CHS）。

- 柱面号：磁道数 20000，需 $\lceil\log_2 20000\rceil = 15$ 位；
- 磁头号：4 个双面盘片共 $4\times2=8$ 个盘面（8 个磁头），需 $\lceil\log_2 8\rceil = 3$ 位；
- 扇区号：每道 500 个扇区，需 $\lceil\log_2 500\rceil = 9$ 位。

**（2）一个扇区的平均访问时间**

转速 7200rpm $=120$ 转/秒，旋转一圈 $1/120\ \text{s}=8.33\ \text{ms}$。

- 平均旋转延迟 $=\dfrac{1}{2}\times8.33\ \text{ms}=4.17\ \text{ms}$；
- 传输时间（一个扇区）$=\dfrac{8.33\ \text{ms}}{500}=0.017\ \text{ms}$（也等于 $512\text{B}/$ 数据传输率）；
- 平均寻道时间 $=5\ \text{ms}$。

$$T_a = 5 + 4.17 + 0.017 \approx 9.19\ \text{ms}$$

**（3）周期挪用 DMA 下总线请求次数**

磁盘控制器数据缓冲区 64 位 $=8$ 字节，一个扇区 512 字节需 $512/8=64$ 次传送，**故一个扇区读写过程中 DMA 控制器向 CPU 发送 64 次总线请求**。若 CPU 检测到 DMA 总线请求时也需要访问主存，**DMA 控制器仍可获得总线使用权**，因为 **DMA 的总线请求优先级高于 CPU**，以防止高速设备的数据来不及传送而被覆盖丢失。

**（4）磁盘容量**

$$\text{容量} = \text{盘面数}\times\text{每面磁道数}\times\text{每道扇区数}\times\text{每扇区字节数} = 8\times20000\times500\times512\ \text{B}\approx 40.96\ \text{GB}$$
:::

#### 磁盘调度方法

**磁盘调度的主要目标是减少平均寻道时间**：寻道时间在存取时间中占主导且直接受调度算法影响；旋转延迟与传输时间都与转速成反比，属于硬件参数，OS 层面难以优化。

下面统一使用一组**经典请求序列**贯穿演示所有算法：**磁头初始位于 100 号磁道**，请求队列（按到达顺序）为

$$55,\ 58,\ 39,\ 18,\ 90,\ 160,\ 150,\ 38,\ 184$$

若算法需要方向，约定**磁头先沿磁道号增大的方向移动**；磁盘磁道号为 $0\sim199$。

**（1）先来先服务（FCFS）**

按进程请求访问磁盘的**先后顺序**进行调度，是最简单的调度算法。

访问顺序：$100 \to 55 \to 58 \to 39 \to 18 \to 90 \to 160 \to 150 \to 38 \to 184$

移动距离：$45+3+19+21+72+70+10+112+146 = 498$ 个磁道，平均寻道长度 $=498/9\approx55.3$。

- **优点**：公平、简单。请求较少且访问的磁道比较集中时，性能尚可。
- **缺点**：大量进程竞争磁盘、请求磁道很分散时，磁头频繁长距离移动，寻道时间长。

**（2）最短寻道时间优先（SSTF）**

每次**优先处理与当前磁头距离最近的磁道**。可以保证每次寻道时间最短，但**不能保证总的寻道时间最短**（本质是贪心）。

访问顺序：$100 \to 90 \to 58 \to 55 \to 39 \to 38 \to 18 \to 150 \to 160 \to 184$

移动距离：$10+32+3+16+1+20+132+10+24 = 248$ 个磁道，平均 $=248/9\approx27.5$。

> 另一种等价的移动距离算法：从 100 先一路减到 18 再跳到 184，即 $(100-18)+(184-18)=82+166=248$。

- **优点**：性能优于 FCFS，平均寻道时间短。
- **缺点**：**可能产生「饥饿」现象**——磁头在一个小区域内来回移动，较远的磁道（如 184 号）长期得不到服务；每次最短不一定全局最短。

**（3）扫描算法（SCAN，电梯调度算法）**

为避免 SSTF 的饥饿问题，规定**磁头只有在到达最外侧磁道后才转向内侧移动，到达最内侧磁道后才转向外侧移动**，在 SSTF 基础上引入了**磁头移动方向的约束**。因为行为像电梯，所以也叫电梯调度算法。

访问顺序（先向磁道号增大方向，抵达 199 后折返）：$100 \to 150 \to 160 \to 184 \to 199 \to 90 \to 58 \to 55 \to 39 \to 38 \to 18$

移动距离：$(199-100)+(199-18) = 99+181 = 280$ 个磁道（**若按「移动到端点」计**）。若按王道教材把端点也算作经过的磁道（即含 200 号），则为 $(50+10+24+16)+(110+32+3+16+1+20)=282$ 个磁道，平均 $282/9\approx31.3$。

- **优点**：寻道性能较好，可避免「饥饿」现象。
- **缺点**：① 只有到达最边上的磁道才能改变方向，而处理完 184 号请求后其实已不需要继续外移；② **SCAN 算法对各个位置磁道的响应频率不平均**，不利于远离磁头当前方向的那一端——刚处理过 90 号的位置下次要等磁头走很长一段距离，而 184 号附近刚被服务过很快又会轮到。

**（4）循环扫描算法（C-SCAN）**

针对 SCAN 响应频率不平均的问题：规定**磁头只朝某个特定方向移动时才处理磁道访问请求，返回时直接快速移动到起始端而不处理任何请求**。

访问顺序（向磁道号增大方向服务，到 199 后快速回到 0，再向增大方向服务）：$100 \to 150 \to 160 \to 184 \to 199 \to 0 \to 18 \to 38 \to 39 \to 55 \to 58 \to 90$

移动距离（按王道含端点计法）：$50+10+24+16+200+18+20+1+16+3+32 = 390$ 个磁道，平均 $390/9\approx43.3$。

- **优点**：比起 SCAN，对各个位置磁道的响应频率很平均，**消除了对两端磁道请求的不公平**。
- **缺点**：① 仍要求到达最边上磁道才改变方向；② 磁头返回时其实只需返回到 18 号磁道即可，不必回到最边缘；③ 平均寻道时间比 SCAN 更长。

**（5）LOOK 与 C-LOOK**

SCAN 和 C-SCAN 都要求磁头严格从磁盘一端移动到另一端。实际上可以改进：**磁头只需移动到当前方向上最远的请求位置即可返回，无须抵达物理端点**。改进后的算法分别称为 **LOOK** 和 **C-LOOK**（因为朝某方向移动前会「查看」该方向是否还有待处理请求）。

**LOOK**：访问顺序 $100 \to 150 \to 160 \to 184 \to 90 \to 58 \to 55 \to 39 \to 38 \to 18$，移动距离 $(184-100)+(184-18)=84+166=250$ 个磁道，平均 $250/9\approx27.5$。

**C-LOOK**：访问顺序 $100 \to 150 \to 160 \to 184 \to 18 \to 38 \to 39 \to 55 \to 58 \to 90$，移动距离 $(184-100)+(184-18)+(90-18)=84+166+72=322$ 个磁道，平均 $322/9\approx35.8$。

:::key 各算法的移动距离对照表（同一请求序列）
磁头初始 100，请求序列 $55,58,39,18,90,160,150,38,184$（9 个请求），磁道范围 $0\sim199$，初始方向为磁道号增大：

| 算法 | 访问顺序 | 移动总距离 | 平均寻道长度 |
|---|---|---|---|
| **FCFS** | 55, 58, 39, 18, 90, 160, 150, 38, 184 | **498** | 55.3 |
| **SSTF** | 90, 58, 55, 39, 38, 18, 150, 160, 184 | **248** | 27.5 |
| **SCAN**（到端点） | 150, 160, 184, 199, 90, 58, 55, 39, 38, 18 | **280**（含端点写法 282） | 31.3 |
| **LOOK** | 150, 160, 184, 90, 58, 55, 39, 38, 18 | **250** | 27.5 |
| **C-SCAN**（到端点） | 150, 160, 184, 199, 0, 18, 38, 39, 55, 58, 90 | **390** | 43.3 |
| **C-LOOK** | 150, 160, 184, 18, 38, 39, 55, 58, 90 | **322** | 35.8 |

**读表要点**：① **SSTF 和 LOOK 在这组数据上移动距离相同（248 vs 250）**，说明「贪心最近」和「带方向的最近」在请求分布均匀时效果接近；② **C-SCAN 因强制回到端点而最差**，C-LOOK 是它的改进；③ **若题目没有特别说明，SCAN 就按 LOOK 理解、C-SCAN 就按 C-LOOK 理解**（见下条提示）。
:::

:::warn 做磁盘调度计算题的四个关键约定
1. **若题目中无特别说明，SCAN 就是 LOOK，C-SCAN 就是 C-LOOK**。反过来，**SCAN 与 C-SCAN 必须到达端点，LOOK 与 C-LOOK 可以跳过端点**。判断依据是题干的措辞：「扫描算法」「电梯算法」通常按 LOOK 处理；明确说「移动到最外侧/最内侧」「到达端点」才按 SCAN 处理。
2. **必须先确定磁头的初始移动方向**。方向不同，访问序列和移动距离都不同。若题目只说「从外侧向内侧移动」，由于磁道号由外向内递增，即**向磁道号增大的方向移动**。
3. **注意「移动距离」是否包含回头到端点的部分**。C-SCAN 必须计入从一端快速回到另一端的距离（如 199→0 距离 199）。
4. **注意请求序列中可能包含与当前磁头位置相同的磁道**（如 2021 年题中当前在 184 且请求序列首项就是 184）。此时访问该磁道移动距离为 0，但**必须计入「已完成的请求」**，且它会被算法安排在某个位置处理（SSTF 会立刻处理它）。
:::

:::exam 磁盘调度真题四个算例
【2009-29】磁头在 105 道、向磁道号增大方向移动，请求序列 $35,45,12,68,110,180,170,195$，采用 **SCAN（电梯）**算法得到的访问序列是：

小于 105 的请求 $12,35,45,68$；大于 105 的请求 $110,170,180,195$。SCAN 先沿当前方向依次处理：$110\to170\to180\to195$（到端点后折返），再按递减顺序访问剩余：$68\to45\to35\to12$。

**答案 A：110, 170, 180, 195, 68, 45, 35, 12。**

【2015-32】硬盘 200 个磁道（$0\sim199$），请求序列 $130,42,180,15,199$，磁头在 58 号磁道**从外侧向内侧移动**（即磁道号增大方向），按 **SCAN** 处理完后磁头移过的磁道数：

先处理当前方向上的请求：$58\to130\to180\to199$，距离 $199-58=141$；到达 199 后折返，处理剩余请求 $42\to15$，距离 $199-15=184$。总距离 $=141+184=325$。

**答案 C（325）。**

【2018-30】磁臂黏着（系统总是访问磁盘的某个磁道而不响应对其他磁道的访问请求）不会出现在哪种算法中？

**答案 A：FCFS。** FCFS 严格按请求到达顺序服务，不会因为某个磁道离当前磁头近而反复优先服务它，已进入队列的请求只需等待有限个更早到达的请求。**SSTF 尤其容易因不断优先处理近距离请求而使远距离请求长期等待**；SCAN 与 C-SCAN 在特定热点请求下也可能黏着（这正是 NStepSCAN 和 FSCAN 要解决的问题）。

【2024-32】磁盘 400 个磁道（$0\sim399$），采用 **C-SCAN** 调度，完成对 200 号磁道的请求后磁头向磁道号**减小**的方向移动，还有 7 个请求：$300,120,110,0,160,210,399$。求磁头移动总距离。

C-SCAN 只沿一个方向扫描，到端点后直接回到另一端再沿原方向继续扫描。

第一步递减扫描：先处理小于 200 的请求，按递减访问 $200\to160\to120\to110\to0$，距离 $200-0=200$。
第二步循环回卷：到达 0 后磁头直接移动到 399，距离 $399-0=399$，399 号本身有请求，到达后立即处理。
第三步继续递减扫描：$399\to300\to210$，距离 $399-210=189$。

完整访问顺序：$160\to120\to110\to0\to399\to300\to210$，总距离 $200+399+189=788$。

**答案 C（788）。**
:::

#### 减少旋转延迟的优化：交替编号与错位编号

磁盘是连续自转设备，**磁头读/写一个物理块后需要经过短暂的处理时间才能开始读/写下一块**。在这个处理时间里，磁盘仍在继续旋转，如果逻辑上相邻的两个扇区在物理上也相邻，那么等 CPU 处理完当前块时，下一个扇区已经转过去了，就必须**再等磁盘转一整圈**才能读到它，造成严重的延迟。

解决办法是在**低级格式化**时做两种编号优化：

1. **交替编号（对一个盘面内的扇区）**：把逻辑上连续的扇区在物理上**隔开存放**，即物理编号按「1, 3, 5, …, 2, 4, 6, …」这类方式排布。这样在读完一个扇区、经过处理时间后，下一个逻辑扇区刚好转到磁头下方，**避免多转一圈**。
2. **错位编号（对不同盘面的相同位置）**：**同柱面不同盘面的扇区错位编号**，连续读/写相邻两个盘面的逻辑记录时也能减少磁头延迟时间。

**一句话记忆**：**交替编号解决「同一盘面内相邻扇区」的延迟，错位编号解决「同一柱面内不同盘面」的延迟。两者都在低级格式化时完成。**

#### 提高磁盘 I/O 速度的其他方法

| 方法 | 做法 |
|---|---|
| **磁盘高速缓存** | 在内存中开辟内核空间缓存最近读写的盘块。逻辑上属于磁盘，物理上属于内存 |
| **调整磁盘请求顺序** | 用磁盘调度算法减少寻道时间 |
| **提前读（预读）** | 顺序访问文件时，读当前块的同时把下一个盘块也读入缓冲区 |
| **延迟写** | 缓冲区数据本应立即写回磁盘，但考虑到可能不久后再被访问，把它挂在**空闲缓冲区队列末尾**。随着空闲缓冲区使用逐渐前移，到达队首并被申请时才真正写回磁盘。只要它仍在队列中，任何访问该数据的进程都可直接读出而不必访问磁盘 |
| **优化物理块分布** | 用位示图时找一片相邻空闲盘块；用空闲盘块链表时把同一磁道上的若干盘块组成一簇，以簇为单位分配。这样访问这几个盘块时不必移动或较少移动磁头 |
| **虚拟盘（RAM 盘）** | 用内存空间仿真磁盘，对用户透明。主要问题是内存易失，掉电或故障数据会丢失，因此常存放临时文件。**与磁盘高速缓存的区别是虚拟盘的内容完全由用户控制，而磁盘高速缓存的内容由 OS 控制** |
| **磁盘阵列 RAID** | 用多个独立物理磁盘组成逻辑盘，数据分割交叉存储、并行访问 |

:::exam 「不能改善磁盘 I/O 性能」的选项
【2012-32】下列不能改善磁盘设备 I/O 性能的是「**在一个磁盘上设置多个分区**」。

设置多个分区的主要目的是逻辑隔离、安装多个文件系统或便于管理，**不能直接减少寻道、旋转延迟或传输次数**。而重排 I/O 请求次序（磁盘调度）、预读与滞后写（延迟写）、优化文件物理块分布都能直接改善性能。

【2015-28】在系统内存中设置磁盘缓冲区的主要目的是「**减少磁盘 I/O 次数**」。缓冲区不能直接缩短平均寻道时间（那是磁盘调度的事），也不是可靠性或设备独立性的主要实现机制。
:::

### 固态硬盘

#### 固态硬盘的结构

**固态硬盘（Solid State Disk，SSD）**基于**闪存（Flash Memory）**技术，属于**电可擦除 ROM（EEPROM）**。其存储介质与 U 盘类似，但容量更大、存取性能更好。

**组成**：

- **闪存翻译层（Flash Translation Layer）**：负责翻译逻辑块号、找到对应的**页（Page）**，相当于磁盘控制器。
- **存储介质（闪存颗粒）**：多个闪存芯片 → 每个芯片包含多个**块（block）** → 每个块包含多个**页（page）**。

**层次关系**：闪存芯片（chip）→ 块（block）→ 页（page）。**读写的单位是页，擦除的单位是块**，块大于页。

#### 读写性能特性

:::key 固态硬盘的五条读写特性
1. **以页为单位读/写**（相当于磁盘的「扇区」）。注意：**需要写某页信息时，必须先对该页所在的块进行擦除操作**。
2. **以块为单位擦除**。擦干净的块，其中的每一页都可以写一次、读无限次。
3. **支持随机访问**。系统给定一个逻辑地址，闪存翻译层可以通过电路迅速定位到对应的物理地址，**没有寻道时间和旋转延迟**。
4. **读快、写慢**。要写的页如果已有数据，则**不能直接写入**，必须先把块内其他页全部复制到一个新的（已擦除的）块中，再写入新的页。这就是**写放大**的根源：一次看似很小的写操作，实际可能触发整个块的搬迁与重写。
5. **容易磨损**。SSD 的一个「块」被擦除次数过多（反复写同一个块）**可能会坏掉**，而机械硬盘的扇区不会因为写的次数太多而坏掉。
:::

**与机械硬盘的对比**：

| 比较项 | 机械硬盘（HDD） | 固态硬盘（SSD） |
|---|---|---|
| 访问方式 | 移动磁臂 + 旋转盘片定位，有**寻道时间和旋转延迟** | 用电路控制访问位置，**随机访问性能高** |
| 随机读性能 | 差（受机械延迟限制） | **远优于机械硬盘** |
| 写性能 | 与读性能接近 | **写比读慢**（需先擦除，有写放大） |
| 噪音与抗震 | 有噪音、怕震动 | 安静无噪音、耐摔抗震 |
| 能耗与价格 | 能耗高、单位容量便宜 | 能耗低、单位容量更贵 |
| 寿命机制 | 扇区不会因写次数多而损坏 | **块被擦除次数过多会损坏** |

:::warn 三组容易混淆的单位与操作
1. **闪存的「擦除」单位是块（block），「读/写」单位是页（page）**。题目常问「写一页需要先擦除什么」，答案是**该页所在的整块**，不是该页。
2. **闪存翻译层不是设备控制器**——它功能上相当于磁盘的磁盘控制器（负责逻辑地址到物理地址的翻译），但它是 SSD 内部的一个软件/固件层。
3. **SSD「读快写慢」不是说它比机械硬盘慢**。SSD 的写速度仍然远快于机械硬盘，只是相对于它自己的读速度而言较慢。
:::

#### 磨损均衡

**为什么需要磨损均衡**：SSD 的块有擦除次数上限，如果反复写同一部分块，这些块会先损坏，而其余块还远未达到寿命，整盘就提前报废。**磨损均衡（Wear Leveling）**的思想就是**把「擦除」平均分布到各个块上，以提升整体使用寿命**。

:::key 动态磨损均衡与静态磨损均衡
- **动态磨损均衡**：**写入数据时，优先选择累计擦除次数少的空闲（新）闪存块**。实现简单，但只对「有写入发生的块」起作用——那些长期只被读、从不被写的数据所占据的块，其擦除次数一直很低，无法参与均衡。
- **静态磨损均衡**：SSD 控制器**监测并自动进行数据分配与迁移**，让**老旧的闪存块承担以读为主的存储任务**，让**较新的闪存块承担更多的写任务**。即使没有新数据写入，控制器也会定期扫描并搬移冷数据，主动制造写入机会来均衡磨损。**静态磨损均衡比动态磨损均衡更优秀、更彻底**，因为它是唯一能解决「冷数据长期占据低磨损块」问题的策略。
:::

**实际效果**：得益于磨损均衡算法，SSD 的实际使用寿命显著提升。例如一块 256GB 的 SSD，若其闪存块的擦除次数上限为 3000 次左右，通过磨损均衡可以使整个盘的总写入量接近「块数 × 单块擦除上限」，而不是由最先损坏的那一小部分块决定。

:::exam SSD 的常考判断
统考考过「下列关于固态硬盘的说法中，错误的是」。常见错误选项有：

- 「固态硬盘的写速度比机械硬盘慢、性能甚至弱于常规硬盘」——**错误**。SSD 的写速度确实比它自己的读速度慢，但仍**远快于**机械硬盘。
- 「固态硬盘不需要磨损均衡」——**错误**。恰恰相反，磨损均衡是 SSD 必不可少的机制。
- 「固态硬盘的擦除单位是页」——**错误**。读/写单位是页，**擦除单位是块**。
:::

## 本章小结表

| 考点 | 核心结论 |
|---|---|
| 设备分类（按信息交换单位） | 块设备（磁盘，可寻址，DMA）；字符设备（键盘打印机，不可寻址，中断驱动） |
| 设备分类（按共享属性） | 独占（打印机，静态分配）；共享（磁盘，动态分配，可寻址可随机访问）；虚拟（SPOOLing 改造） |
| I/O 接口组成 | 数据缓冲寄存器、状态寄存器、控制寄存器、设备存储器、地址译码与 I/O 控制逻辑 |
| 统一编址 vs 独立编址 | 统一：访存指令访问、占主存空间、译码慢、**端口不能 Cache**；独立：专用 I/O 指令、不占主存空间、译码快、程序灵活性差 |
| 轮询方式 | CPU 忙等、设备与 CPU 串行、不用中断；分独占查询与定时查询 |
| 中断方式 | 设备主动请求、CPU 与外设并行、每个字/字节中断一次、需保护恢复现场 |
| DMA 方式 | 请求总线控制权、块传送、不经过 CPU 寄存器、不改变 CPU 现场、整块只中断一次 |
| 中断 vs DMA 响应时机 | 中断：**一条指令执行结束后**；DMA：**一个总线周期结束后** |
| I/O 软件四层（自上而下） | 用户层 I/O 软件 → 设备独立性软件 → 设备驱动程序 → 中断处理程序 |
| 设备独立性软件职责 | 公有操作（分配回收、逻辑→物理映射、保护、缓冲、差错控制、统一逻辑块）+ 统一接口 |
| 字符/块/网络设备接口 | 字符：get/put、需 open/close、不可寻址；块：read/write/seek、线性块序列；网络：socket API、数据包导向 |
| 阻塞 vs 非阻塞 I/O | 区别在**等待数据准备**阶段：阻塞则进程挂起等待；非阻塞则立即返回错误码并轮询 |
| 缓冲的四个目的 | 缓和速度矛盾、减少中断频率、解决粒度不匹配、提高并行性 |
| **单缓冲每块时间** | $\max(T,C)+M$；$n$ 块总时间 $(n-1)[\max(T,C)+M]+(C+T+M)$ |
| **双缓冲每块时间** | $\max(T,C+M)$；$n$ 块总时间 $(n-1)\max(T,C+M)+(C+T+M)$ |
| 循环缓冲 | 多个等大缓冲区连成循环队列，维护 `in`/`out` 指针 |
| 缓冲池 | 三个队列（空白、输入、输出）+ 四种工作缓冲区（`hin`/`sin`/`hout`/`sout`）；规律：队头取、队尾挂 |
| 缓冲 vs 缓存 | 缓冲是「中转站」（数据可能是唯一的）；缓存是数据源副本（求命中率） |
| DCT/COCT/CHCT/SDT | SDT 全系统一张；DCT 每设备一张；COCT 每控制器一张；CHCT 每通道一张。流程 SDT→DCT→COCT→CHCT |
| 安全 vs 不安全分配 | 安全：分配后立即阻塞，破坏「请求和保持」，不死锁但串行；不安全：可继续请求，可并行但可能死锁 |
| 静态 vs 动态分配 | 静态：运行前全部分配，不死锁，利用率低，用于独占设备；动态：按需申请，利用率高，可能死锁 |
| LUT | ⟨逻辑设备名，物理设备名，驱动程序入口地址⟩；首次分配建表，再次请求直接查表 |
| SPOOLing 组成 | 输入井/输出井（磁盘）、输入缓冲区/输出缓冲区（内存）、输入进程/输出进程、井管理程序 |
| SPOOLing 三大特点 | 提高 I/O 速度；把独占设备改造为共享设备；实现虚拟设备（以空间换时间） |
| SPOOLing 条件 | 大容量高速度外存 + 多道程序技术 + 通道技术（软件实现） |
| 脱机 vs 假脱机 | 脱机需物理外围机、脱离主机控制；假脱机用系统进程模拟外围机、在主机控制下完成 |
| 设备驱动程序统一接口 | 用函数指针表定义驱动与 OS 其余部分的接口，新增设备无需修改 OS |
| 磁盘地址结构 | （柱面号，盘面号，扇区号）或（驱动器号，柱面号，盘面号，扇区号）；**柱面号在前，因为同柱面不同盘面换磁头不需寻道** |
| 磁盘管理四步 | 低级格式化（物理格式化）→ 分区 → 高级格式化（逻辑格式化）→ 安装操作系统 |
| 存取时间公式 | $T_a = T_s + \dfrac{1}{2r} + \dfrac{b}{rN}$，其中寻道时间 $T_s=s+mn$ 占主导 |
| FCFS / SSTF | FCFS 公平但寻道长；SSTF 贪心最短，可能饥饿（磁臂黏着） |
| SCAN / LOOK | SCAN 到端点才折返，方向约束避免饥饿，对两端不公平；LOOK 只到最远请求处折返 |
| C-SCAN / C-LOOK | 单向服务、回程不服务，响应频率均匀；C-LOOK 只需回到最远的请求处 |
| 交替编号 / 错位编号 | 同盘面相邻扇区交替编号；同柱面不同盘面错位编号；均在低级格式化时完成 |
| SSD 读写单位 | 读/写以**页**为单位，擦除以**块**为单位；写前需擦除整块 |
| SSD 写放大 | 写有数据的页要先把它所在块的其他页全部复制到新块再写入 |
| 磨损均衡 | 动态：写时优先选擦除次数少的块；静态：控制器主动迁移，让老块承担读、新块承担写（更优秀） |

## 易错清单

:::warn 本章 30 个最容易失分的点
1. **「共享设备可以同一时刻被多个进程访问」是错的。** 共享设备是「一段时间内」可同时访问，微观上交替使用，且必须是**可寻址、可随机访问**的设备。块设备接口把磁盘的二维结构隐藏成线性块序列，这是文件系统能建立在磁盘上的前提。
2. **统一编址的 I/O 端口不能被 Cache 缓存**，因为接口中的数据是动态变化的，缓存会导致 CPU 读到过时状态。
3. **统一编址不需要专门的 I/O 指令，用 `LOAD`/`STORE` 即可；独立编址需要 `IN`/`OUT` 这类专用指令**，且 I/O 指令是**特权指令**。
4. **状态寄存器和控制寄存器可以合二为一**，因为传送方向相反且 CPU 访问时间错开。
5. **中断类型号在数据线上传输，但它不是设备控制器发出的**，而是可编程中断控制器判优后生成的。
6. **中断响应发生在一条指令执行结束后；DMA 响应发生在一个总线周期结束后**，DMA 响应更快。中断方式请求的是 CPU 处理时间，DMA 方式请求的是总线控制权。
7. **DMA 数据传送不经过 CPU 寄存器，不改变 CPU 现场，所以无需保护和恢复现场。**
8. **周期挪用方式下，CPU 在整个数据块传送过程中并非不能访问主存**，只在 DMA 占用那一个周期时让出总线。「CPU 不可以访问主存储器」是「停止 CPU 访问内存」方式的特点。
9. **周期挪用一次实际需 2～5 个存储周期**，因为总线请求、仲裁、归还本身有开销。
10. **DMA 与 CPU 同时访存时 DMA 优先**，这是为了防止高速设备数据丢失。
11. **「中断方式适用于所有外部设备」是错的**；极高速设备用中断反而效率更低，轮询（如 NVMe SSD 的同步 I/O）反而更优。
12. **DMA 方式的数据通路位于「设备接口和主存之间」**，不是 CPU 和主存之间，也不是设备接口和 DMA 控制器之间（2024 年考过）。
13. **I/O 软件四层自上而下是：用户层 I/O 软件 → 设备独立性软件 → 设备驱动程序 → 中断处理程序。** 驱动程序必须在设备独立性软件之下，中断处理程序最接近硬件。一次磁盘 I/O 请求的处理流程是：用户程序 → 系统调用处理程序 → 设备驱动程序 → 中断处理程序。
14. **计算柱面号、磁头号、扇区号（CHS）的是设备驱动程序**，不是用户程序、系统调用程序或中断处理程序（2013 年考过）。
15. **「驱动程序与 I/O 控制方式无关」是错的。** 程序查询、中断、DMA 三种控制方式直接决定驱动程序的编码方式。
16. **程序员的系统调用传的是逻辑设备名**，物理设备名、主设备号/次设备号是内核与驱动程序使用的（2009、2020 年考过）。**主设备号确定设备类型并据此定位驱动程序，次设备号被驱动程序用来确定具体设备。**
17. **单缓冲每块时间 $\max(T,C)+M$，$M$ 在 $\max$ 之外；双缓冲 $\max(T,C+M)$，$M$ 在 $\max$ 之内。** 这是两者唯一差别，也是判断用哪个公式的关键。
18. **$n$ 块数据的总时间不能简单用 $n\times$ 每块时间**，必须用 $(n-1)$ 倍流水时间加最后一块的完整串行时间 $(C+T+M)$。
19. **单缓冲、双缓冲、循环缓冲是专用缓冲；缓冲池是共享缓冲。**
20. **缓冲池四个工作缓冲区 `hin`(收容输入)、`sin`(提取输入)、`hout`(收容输出)、`sout`(提取输出)**，规律是「取出从队头、挂入到队尾」。
21. **SDT 全系统只有一张；DCT、COCT、CHCT 分别是每设备、每控制器、每通道一张。** 分配请求流程是 SDT→DCT→COCT→CHCT，且**只有设备、控制器、通道三者都分配成功，设备分配才算成功**。
22. **静态分配降低设备利用率，不是提高。** 它的优点是破坏「请求和保持」从而避免死锁。
23. **SPOOLing 不能缩短物理设备的传输时间**，也不改变设备本身的速度，它只让 CPU 不必等待。
24. **「SPOOLing 由用户作业控制设备与输入/输出井之间的数据传送」是错的**，由系统的输入/输出进程控制，对用户透明。
25. **SCAN/C-SCAN 必须到端点，LOOK/C-LOOK 可跳过端点；若题目无特别说明，SCAN 即 LOOK、C-SCAN 即 C-LOOK。**
26. **转速单位要看清**：7200rpm 是「转/分」，旋转一圈是 $60/7200\text{s}=8.33\text{ms}$，平均旋转延迟为 4.17ms。若题目给「秒/转」则公式要取倒数。
27. **磁盘传输速率中 K/M/G/T 以 10 为底**（$1\text{M}=10^6$），不要按 $2^{20}$ 算。
28. **「柱面号在前」的原因是同柱面不同盘面换磁头不需要寻道**，这是把最耗时的寻道操作尽量推迟。
29. **逻辑格式化做的是「建根目录 + 初始化空闲块管理结构」**；分区、确定校验码位数分别属于分区和低级格式化（2017 年考过）。
30. **SSD 的读/写单位是页，擦除单位是块；写有数据的页必须先擦除它所在的整块。** 「SSD 的性能弱于机械硬盘」「SSD 擦除单位是页」都是错的。
:::
