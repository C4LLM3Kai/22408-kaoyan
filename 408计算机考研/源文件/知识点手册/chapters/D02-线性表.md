## 一、线性表的基本概念

### （一）线性表的定义与逻辑特征

**线性表（Linear List）** 是具有相同数据类型的 $n$（$n \ge 0$）个数据元素的**有限序列**，通常记作

$$L = (a_1, a_2, \cdots, a_i, \cdots, a_n)$$

其中 $a_1$ 称为**表头元素**，$a_n$ 称为**表尾元素**；$i$ 是元素 $a_i$ 的**位序**（从 1 开始数），$n$ 是**表长**。当 $n=0$ 时称为**空表**。

一句话把握它的逻辑特征：

:::key 线性表的四条逻辑特征
1. **有穷性**：元素个数 $n$ 是有限的。
2. **同类型**：所有元素属于同一数据类型（每个元素占用的存储空间相同，这一点是顺序存储能随机存取的前提）。
3. **有序性**：元素之间有**顺序**关系。除第一个元素外，每个元素有且仅有一个**直接前驱**；除最后一个元素外，每个元素有且仅有一个**直接后继**。
4. **一对一**：$a_1$ 无前驱，$a_n$ 无后继，其余元素恰好一前一后。
:::

线性表是一种**线性结构**，它的逻辑结构只有「一个前驱一个后继」这一种形态，与它采用什么存储方式无关。同一个线性表既可以顺序存储（顺序表），也可以链式存储（链表），二者的**逻辑结构相同、存储结构不同**，因而基本操作的**实现方式与效率不同**。这句话是本章所有对比题的题眼。

从「按逻辑顺序排列」这一点再往下推，可以得到两个必须记牢的推论。第一，**线性表中的每个元素都有一个确定的位置编号**，这个编号就是位序，位序是由逻辑关系决定的，不随存储方式改变：同一个线性表无论是用数组还是用链表存，$a_3$ 永远是 $a_4$ 的直接前驱。第二，**任意两个元素之间的前后关系由它们在序列中的相对位置决定**，因此「插入一个元素」在逻辑上的含义是「使原来的第 $i$ 个元素及其后所有元素的位置编号都加一」，在「删除一个元素」时则是减一。这个逻辑语义，正是顺序存储必须搬移元素、而链式存储只需改指针的根本原因——顺序存储把「位置编号」直接编码成了「物理地址的偏移量」，一旦编号变化，物理位置就必须跟着变；链式存储把「前后关系」编码成了「指针」，编号变化时只要改指针，物理位置完全不用动。

再补充两个常考的相邻概念，避免混淆。

- **线性表与数组**：数组是**存储结构层面**的概念（一段连续的、可随机访问的存储空间），线性表是**逻辑结构层面**的概念。数组可以存线性表，也可以存矩阵、堆、完全二叉树；线性表可以用数组存，也可以用链表存。因此「数组就是线性表」「线性表就是数组」都不成立。
- **线性表与集合**：集合中的元素只要求「互异」，元素之间**没有顺序关系**；线性表要求元素之间有严格的前后次序。所以线性表不是集合，也不能说「线性表是一种特殊的集合」。
- **线性表与串**：串是内容受限的线性表（限定数据元素为字符），本质上是线性表的特例，它的存储和操作都可以沿用本章的方法，只是多了模式匹配这类与「内容」有关的操作。本手册把串的内容放在第三部分展开。

:::warn 「线性表」不等于「顺序表」
常见错误是把「线性表」直接当成数组。线性表是**逻辑结构**（一对一的有序序列），顺序表和链表是它的两种**存储结构**。判断题里出现「线性表只能用顺序存储实现」「线性表的元素必须连续存放」一律是错的。
:::

### （二）线性表的基本操作

统考与教材通用的操作名（务必认清函数名与语义，选择题常在「返回位序还是返回值」上设陷阱）：

| 操作名 | 语义 | 返回值约定 |
|---|---|---|
| `InitList(&L)` | 初始化，构造一个空表 | 成功/失败 |
| `DestroyList(&L)` | 销毁表，释放全部空间 | 无 |
| `ListInsert(&L, i, e)` | 在位序 $i$ 处插入元素 $e$，原第 $i$ 个元素及其后元素依次后移 | 成功/失败 |
| `ListDelete(&L, i, &e)` | 删除位序 $i$ 的元素，用 $e$ 带回它的值 | 成功/失败 |
| `LocateElem(L, e)` | **按值查找**，找第一个值为 $e$ 的元素 | 返回其**位序**；失败返回 0 或 -1 |
| `GetElem(L, i, &e)` | **按位查找**，取位序 $i$ 的元素，用 $e$ 带回 | 成功/失败 |
| `ListLength(L)` | 求表长 | 元素个数 |
| `PrintList(L)` | 按前后次序输出所有元素 | 无 |
| `Empty(L)` | 判空 | 真/假 |

:::warn 位序与下标必须分清
**位序从 1 开始，数组下标从 0 开始**。位序 $i$ 对应的数组下标是 $i-1$。插入的合法位序范围是 $1 \le i \le n+1$（可以有 $n+1$ 个插入位置，因为可以插到表尾之后）；删除的合法位序范围是 $1 \le i \le n$。这两个范围的差别是最容易被扣分的细节。
:::

:::exam 这一部分怎么考
- 选择题：给一段操作语句序列判断其效果（如 2024-01 让判断 `q = p->next; p->next = q->next; q->next = h->next; h->next = q;` 的作用）。
- 选择题：给顺序表 / 单链表判断某操作的平均时间复杂度（如 2023-01 问哪个操作平均时间复杂度是 $O(1)$，答案是「获取第 $i$ 个元素」）。
- 选择题：判断涉及移动元素的操作（如 2026-01 问表头插入、表头删除、表尾插入、表尾删除哪些必然产生元素移动，答案是表头插入与表头删除）。
- 算法设计题：见本章第三节。
:::

在九种操作中，真正需要「设计思路」的只有四类：**插入、删除、按位查找、按值查找**。其余操作（初始化、销毁、求表长、判空、遍历）都是顺序扫描或一次性赋值，两种存储结构下的写法都很直接。因此本章后续所有分析都围绕这四类操作展开，考纲「（二）线性表的实现」实际上就是在讨论这四类操作在两种存储结构下的不同实现代价。

这里还要提醒一个语义细节：教材中 `ListInsert(&L, i, e)` 里的 $i$ 是**位序**，而 `LocateElem(L, e)` 返回的也是**位序**，`GetElem(L, i, &e)` 接收的是**位序**、带回的是**元素值**。这三者对「位序 / 值」的取用方向相反，是选择题的常见设错点——把 `GetElem` 说成「返回位序」、把 `LocateElem` 说成「返回值」都是错的。

## 二、线性表的实现

### （一）顺序存储

#### 1. 定义与两种分配方式

**顺序表**用一组**地址连续**的存储单元依次存放线性表的元素，逻辑上相邻的元素物理上也相邻。

**静态分配**：数组大小在编译时确定，一经定义不能改变。

```c
#define MaxSize 100        // 顺序表的最大容量
typedef int ElemType;      // 元素类型

typedef struct {
    ElemType data[MaxSize]; // 静态数组存放元素
    int length;             // 当前表长（元素个数）
} SqList;

void InitList(SqList *L) {
    L->length = 0;          // 空表长度为 0，无须清空数组内容
}
```

**动态分配**：运行时用 `malloc` 申请空间，空间不够时再申请一块更大的并搬移数据。

```c
#define InitSize 100

typedef struct {
    ElemType *data;  // 指向动态分配数组的指针
    int MaxSize;     // 数组的最大容量
    int length;      // 当前表长
} SeqList;

// 初始化：申请初始容量
void InitList(SeqList *L) {
    L->data = (ElemType *)malloc(sizeof(ElemType) * InitSize);
    L->MaxSize = InitSize;
    L->length = 0;
}

// 扩容：三步骤——申请新空间、搬移旧数据、释放旧空间
void IncreaseSize(SeqList *L, int len) {
    ElemType *p = L->data;
    L->data = (ElemType *)malloc(sizeof(ElemType) * (L->MaxSize + len));
    for (int i = 0; i < L->length; i++) {
        L->data[i] = p[i];        // 逐个搬移，不能整体赋值
    }
    L->MaxSize = L->MaxSize + len;
    free(p);                      // 释放原来那片空间
}
```

:::warn 静态与动态分配的关键差别
静态分配一旦数组满，**无法扩容**，只能插入失败；动态分配可以在满时扩容，但**扩容要搬移全部 $n$ 个元素，时间代价 $O(n)$**，而且必须「先申请、再搬移、最后释放旧空间」，顺序不能反。注意：动态分配虽然可以扩容，但它仍然是**顺序存储**，仍然支持随机访问。
:::

关于扩容还有一个容易忽略的量化结论。若每次扩容只增加固定长度 `len`（即线性增长），插入 $n$ 个元素的累计搬移代价是 $O(n^2)$；若每次扩容把容量**加倍**（倍增策略），第 $i$ 次扩容搬移 $1+2+4+\cdots+2^{i-1} \approx 2^i$ 个元素，而此后至少还能再插入 $2^i$ 个元素，**把搬移代价均摊到每次插入上是常数**，因此 $n$ 次插入的总时间仍是 $O(n)$，单次插入的**均摊时间**是 $O(1)$。统考不要求推导均摊分析，但选择题里出现「动态分配的顺序表插入元素一定是 $O(n)$」这种说法时可以据此判断：**均摊意义下是 $O(1)$，最坏情况（恰逢扩容）才是 $O(n)$**。

再强调一个概念区分：**「动态分配」和「动态存储结构」不是一回事**。动态分配讲的是一块顺序空间如何申请和扩充，它仍然是顺序存储；链式存储才是真正的动态存储结构。把「动态数组」理解成链表是典型错误。

最后一点实现细节：用 `malloc` 申请到的空间里是**未初始化的随机数据**，但顺序表只靠 `length` 判断哪些位置有效，所以初始化时**不必把整个数组清零**，只把 `length` 置 0 即可（本手册给出的 `InitList` 就是这么写的）。反之，若题目明确要求「初始化时清空数组内容」，则要循环赋值。

#### 2. 随机访问特性与地址计算

设第一个元素的存储地址为 $LOC(a_1)$，每个元素占 $d$ 个存储单元，则位序为 $i$ 的元素地址为

$$LOC(a_i) = LOC(a_1) + (i-1) \times d$$

**只要给出位序 $i$，一次乘法加法就能算出地址，访问时间与表长 $n$ 无关**，这就是**随机访问（随机存取）**。因此 `GetElem(L, i)` 的时间复杂度是 $O(1)$。

:::key 一句话记住
顺序表 $\Rightarrow$ 随机访问 $\Rightarrow$ 按位查找 $O(1)$；链表 $\Rightarrow$ 顺序访问 $\Rightarrow$ 按位查找 $O(n)$。
:::

「随机访问」这个特性还带来一个常被忽略的考点：**顺序表可以用折半查找**。前提是表内元素**有序**（按关键字递增或递减排列），此时按值查找的时间可以从线性查找的 $O(n)$ 降到 $O(\log_2 n)$。这是链表做不到的——链表的按位访问是 $O(n)$，无法在 $O(1)$ 时间内取到中间元素，所以**折半查找只适用于顺序存储的有序表**。这一点经常与「查找」那一章联动出题：题干说「有序表」「折半查找」，那它必然是顺序表。

反过来也要注意：**顺序表不一定有序**。顺序表只保证「逻辑相邻 = 物理相邻」，不保证值的大小关系。随机访问是顺序存储天然具备的，折半查找则是「顺序存储 + 有序」两个条件同时具备才有的能力，二者不能混为一谈。

#### 3. 插入与删除：移动次数推导

**插入**：在位序 $i$ 插入，需要把原来的第 $i, i+1, \cdots, n$ 个元素整体后移一位，共移动 $n-i+1$ 个元素；再把 $e$ 放到位序 $i$ 处，表长加 1。

```c
// 在位序 i 处插入元素 e，位序从 1 开始
bool ListInsert(SqList *L, int i, ElemType e) {
    if (i < 1 || i > L->length + 1) return false; // 位序越界
    if (L->length >= MaxSize)        return false; // 表满，不能插入
    for (int j = L->length; j >= i; j--) {         // 从后往前依次后移
        L->data[j] = L->data[j - 1];
    }
    L->data[i - 1] = e;   // 位序 i 对应下标 i-1
    L->length++;
    return true;
}
```

设 $P_i$ 是在第 $i$ 个位置插入的概率（$1 \le i \le n+1$），并假设**在每个合法位置插入的概率相等**，即 $P_i = \dfrac{1}{n+1}$，则插入一个元素所需移动元素的**平均次数**为

$$E_{\text{ins}} = \sum_{i=1}^{n+1} P_i (n-i+1) = \frac{1}{n+1}\sum_{i=1}^{n+1}(n-i+1) = \frac{1}{n+1}\cdot\frac{n(n+1)}{2} = \frac{n}{2}$$

所以插入操作的平均时间复杂度为 $O(n)$，其中**最好情况**（插到表尾，$i=n+1$）移动 0 次，**最坏情况**（插到表头，$i=1$）移动 $n$ 次。

**删除**：删除位序 $i$ 的元素，需要把第 $i+1, i+2, \cdots, n$ 个元素整体前移一位，共移动 $n-i$ 个元素，表长减 1。

```c
// 删除位序 i 的元素，并用 e 带回其值；位序从 1 开始
bool ListDelete(SqList *L, int i, ElemType *e) {
    if (i < 1 || i > L->length) return false;   // 位序越界
    *e = L->data[i - 1];                        // 先保存被删元素
    for (int j = i; j < L->length; j++) {       // 从前往后依次前移
        L->data[j - 1] = L->data[j];
    }
    L->length--;
    return true;
}
```

同样假设 $P_i = \dfrac{1}{n}$（删除时只有 $n$ 个合法位置），平均移动次数为

$$E_{\text{del}} = \sum_{i=1}^{n} P_i (n-i) = \frac{1}{n}\sum_{i=1}^{n}(n-i) = \frac{1}{n}\cdot\frac{n(n-1)}{2} = \frac{n-1}{2}$$

所以删除操作的平均时间复杂度也是 $O(n)$，最好情况（删表尾）移动 0 次，最坏情况（删表头）移动 $n-1$ 次。

:::key 顺序表三种操作的平均次数（必背）
| 操作 | 平均移动 / 比较次数 | 时间复杂度 |
|---|---|---|
| 按位查找 `GetElem` | 0 次（直接算地址） | $O(1)$ |
| 插入 `ListInsert` | $\dfrac{n}{2}$ 次 | $O(n)$ |
| 删除 `ListDelete` | $\dfrac{n-1}{2}$ 次 | $O(n)$ |
| 按值查找 `LocateElem` | $\dfrac{n+1}{2}$ 次（查找成功） | $O(n)$ |
:::

代一组数验证：$n=5$ 时，插入平均移动 $5/2 = 2.5$ 次。手工核一遍：6 个插入位置分别移动 $5,4,3,2,1,0$ 次，和是 15，除以 6 得 2.5，一致。删除平均移动 $(5-1)/2 = 2$ 次；5 个删除位置分别移动 $4,3,2,1,0$ 次，和是 10，除以 5 得 2，一致。

关于这两个公式，有三个必须澄清的点。

**第一，公式里的「平均」是概率意义上的平均。** 推导时用的假设是「插入到每个合法位置的概率相等」且「删除每个位置的概率相等」。如果题目另外给了概率分布（例如「插到表尾的概率是插到其他位置的 2 倍」），就必须按题目给的 $P_i$ 重新代入公式计算，不能直接套 $\dfrac{n}{2}$ 和 $\dfrac{n-1}{2}$。

**第二，「移动次数」和「时间复杂度」是两个层次的东西。** 移动次数是**精确的操作计数**，时间复杂度是**增长速度的量级**。插入平均 $\dfrac{n}{2}$ 次、删除平均 $\dfrac{n-1}{2}$ 次，都是 $O(n)$。考试可能只问次数（填空或选择），也可能问复杂度，看清题干的问法。

**第三，最好情况与最坏情况要记牢。** 插入：插在表尾之后（位序 $n+1$）移动 0 次，是最好；插在表头（位序 1）移动 $n$ 次，是最坏。删除：删表尾（位序 $n$）移动 0 次，是最好；删表头（位序 1）移动 $n-1$ 次，是最坏。一种便于自查的记忆法是：「**移动元素个数 = 需要被跨过的元素个数**」——插入时跨过的是原来第 $i$ 到第 $n$ 个，共 $n-i+1$ 个；删除时跨过的是第 $i+1$ 到第 $n$ 个，共 $n-i$ 个。

**第四，循环里的移动方向不能反。** 插入时循环变量必须**从大到小**（`for (j = length; j >= i; j--)`），因为元素要向后挪，必须先把最后面的挪走，否则会覆盖还没搬的数据；删除时循环变量必须**从小到大**（`for (j = i; j < length; j++)`），因为元素要向前挪，必须先把最前面的挪走，否则同样会覆盖。这是写代码时最实际的一个坑。

**第五，顺序表的插入删除有「移动区间的选择」技巧。** 如果题目要求「删除所有值为 $x$ 的元素」，用逐个删除的办法每次都要搬移其后所有元素，最坏会退化到 $O(n^2)$；正确做法是用双指针一趟扫描（见第三节），把保留的元素一次填好，最后统一改表长，时间 $O(n)$。**「批量删除要用双指针，不要循环调用单次删除」**是统考算法题的重要得分意识。

按值查找的比较次数推导：设要查找的元素在位序 $i$ 的概率为 $P_i = \dfrac{1}{n}$，找到它需要比较 $i$ 次，则

$$ASL_{\text{成功}} = \sum_{i=1}^{n} P_i \cdot i = \frac{1}{n}\cdot\frac{n(n+1)}{2} = \frac{n+1}{2}$$

若要把**查找失败**也算进去（线性表的顺序查找，失败时比较 $n$ 次后还要再比一次才能判失败），教材常给出 $ASL_{\text{失败}} = n+1$ 与 $ASL_{\text{总}} = \dfrac{n+1}{2} + n + 1$ 之类的写法。**统考考「平均查找长度」时若未说明，按查找成功计算**，即 $(n+1)/2$；遇到明确要求算失败的题目，按题目给出的概率模型老老实实列式子。

#### 4. 顺序表的优缺点

- **优点**
  1. **随机访问**：按位查找 $O(1)$，这是顺序表最大的优势。
  2. **存储密度高**：只存数据本身，不需要额外的指针开销（存储密度 $=1$）。
  3. 存储空间是**一整块连续空间**，对 CPU 缓存友好，实际运行速度快。
- **缺点**
  1. 插入、删除平均要移动约一半的元素，平均时间复杂度 $O(n)$。
  2. 需要**预先分配**连续空间：静态分配可能溢出，动态分配扩容要整体搬移。
  3. **存储空间利用率受「连续」约束**：内存里有很多碎片但拼不出一块够大的连续空间时，仍然申请失败。

:::warn 关于「存储密度」
存储密度 $=\dfrac{\text{数据本身占用的存储量}}{\text{结点占用的存储总量}}$。顺序表为 1；单链表每个结点除数据域外还要存一个指针域，所以存储密度小于 1（严格小于 1，除非结点结构里数据域是空的）。**存储密度高不等于效率高**，它只反映「空间换结构信息」的比例。
:::

「随机访问」和「存储密度」是顺序表的两张底牌，而它们都来自「一整块连续空间」这一个事实。正因为空间连续，地址才能用乘法直接算出来（随机访问）；也正因为空间连续且按顺序紧密排列，才没有任何空隙需要额外的结构信息去填充（存储密度为 1）。反过来，空间连续也带来了顺序表最大的软肋——**「连续」是一个很硬的约束**。插入删除要维持连续，就得搬移；预留空间要维持连续，就得整块申请，一旦内存中最大的空闲连续区小于所需容量，即使总的空闲空间足够大也申请不到。这三利三弊是同一个原因的不同侧面，理解了因果关系就不需要死记。

:::exam
2013 年应用题考过顺序存储结构与链式存储结构的 `ASL` 对比，2023-01 考过哪类操作平均 $O(1)$，2026-01 考过「哪些操作必然导致元素移动」。这类题的共同点是**先判断题目描述的是顺序表还是链表**——题干里的「存储空间有足够的空闲空间」「保持元素相对顺序」这类措辞通常指向顺序表。
:::

:::warn 2026-01 那类题怎么想
题目问「在保持表内元素顺序相对不变的情况下，哪些操作会必然导致移动次数」。分析路径是：先确定讨论对象是**顺序表**（因为「充足的连续空闲空间」和「元素移动」是顺序表的话题）；再检查四种操作是否需要给新元素腾位置或填补空隙。表头插入要给首位置腾空间，$a_1 \sim a_n$ 全部后移，必然移动；表头删除会让 $a_2 \sim a_n$ 全部前移填补，必然移动；表尾插入只需在 `data[length]` 处赋值，不移动任何已有元素；表尾删除只需把表长减 1，也不移动。答案是「表头插入、表头删除」。**关键是分清「元素移动」与「指针修改」——链表做这些操作一个元素都不用挪，但题目限制的是顺序表。**
:::

### （二）链式存储

#### 1. 单链表的定义与头结点

**单链表**用一组**任意的**存储单元存放元素，每个结点含数据域 `data` 和指针域 `next`，`next` 指向直接后继。逻辑相邻的元素物理上不必相邻，靠指针串起来。

```c
typedef struct LNode {
    ElemType data;         // 数据域
    struct LNode *next;    // 指针域，指向直接后继
} LNode, *LinkList;
```

**头结点**是附加在第一个数据结点之前的、不存放数据的结点，头指针指向它。为什么要引入头结点：

:::key 头结点的三个作用（常考）
1. **统一了空表和非空表的处理**：空表时 `head->next == NULL`，非空表时 `head->next` 指向第一个数据结点，判空变成一条统一的语句。
2. **统一了第一个位置和其他位置的插入删除**：对第一个数据结点做前插 / 删除时，其前驱是头结点而不是空，不需要单独写「如果插在表头」的分支。
3. 头指针**永远非空**（指向头结点），指针操作不会因为「表空导致头指针为 NULL」而崩溃。
:::

```c
// 带头结点单链表的初始化
bool InitList(LinkList *L) {
    *L = (LNode *)malloc(sizeof(LNode));  // 创建头结点
    if (*L == NULL) return false;         // 内存分配失败
    (*L)->next = NULL;                    // 空表
    return true;
}

// 判空：带头结点判断头结点的 next 是否为空
bool Empty(LinkList L) { return L->next == NULL; }
```

:::warn 无头结点时的补救办法
如果题目给的链表**不带头结点**（如 2026-02 的 `head = cu` 这类题），可以自己申请一个 `dummy` 结点指向第一个数据结点，把它当头结点用，之后所有操作就与带头结点的链表完全一致。**统考的应用题基本都是带头结点的链表**，但选择题里会出现不带头的写法，读题时先确认「头指针指向的是头结点还是第一个数据结点」。
:::

#### 2. 求表长、按位查找、按值查找

```c
// 求表长（不计算头结点）
int ListLength(LinkList L) {
    int len = 0;
    LNode *p = L->next;          // 若有头结点，从头结点的后继开始
    while (p != NULL) { len++; p = p->next; }
    return len;
}

// 按位查找：返回位序为 i 的结点指针；i = 0 时返回头结点
LNode *GetElem(LinkList L, int i) {
    if (i < 0) return NULL;
    LNode *p = L;                // p 从头结点出发（头结点是位序 0）
    int j = 0;
    while (p != NULL && j < i) { p = p->next; j++; }
    return p;                    // i 超长时返回 NULL
}

// 按值查找：返回第一个数据域等于 e 的结点
LNode *LocateElem(LinkList L, ElemType e) {
    LNode *p = L->next;
    while (p != NULL && p->data != e) p = p->next;
    return p;
}
```

**单链表不能随机访问**：要找第 $i$ 个结点，只能从头指针开始顺链逐个走，比较 / 移动次数与 $i$ 成正比。设 $i$ 等概率取 $1 \sim n$，则按位查找的平均比较次数为 $\dfrac{1}{n}\sum_{i=1}^{n} i = \dfrac{n+1}{2}$，按值查找查找成功时也是 $\dfrac{n+1}{2}$，二者时间复杂度都是 $O(n)$。

这里要澄清一个常见的表述混淆。**平均比较次数相同，不代表两种查找「一样快」**——按位查找在顺序表里是 $O(1)$，在链表里是 $O(n)$；只有当两者都在「从头逐个比较」这一情形下（顺序表的按值查找、链表的按位/按值查找）才有相同量级的平均比较次数。做题时先问自己：题目问的是哪种存储结构、哪种查找。

另外，链表的按位查找与按值查找虽然量级相同，**代码结构有一个重要差别**：按位查找是对「位置计数器」做判断（`j < i`），走到第 $i$ 个就停，**不存在找不到的情况**（除非 $i$ 越界，此时返回 `NULL`）；按值查找是对「数据域」做判断（`p->data != e`），可能一路走到表尾都找不到，**必须用 `p != NULL` 作循环条件并在结束后返回 `NULL`**。写代码时把这两个循环条件写反，就会分别导致「多走 / 少走一个结点」和「解引用空指针」。

还要注意单链表的**判空条件与头结点有关**。带头结点时判空看 `L->next == NULL`；不带头结点时判空看 `L == NULL`。**两者的差别不只是少一个空判断**：带头结点时头指针永远指向一个真实的结点，因此「对第一个数据结点做前插或删除」不需要特殊分支；不带头的写法则必须专门处理「表头为空」的情形。这也是统考应用题一律给出带头结点链表的原因——它能让算法描述更简洁、更不容易在边界上出错。

#### 3. 插入与删除的指针操作

**后插（在 $p$ 之后插入 $s$）**：口诀是**「先连后，再连前」**。

```c
s->next = p->next;   // 第一步：新结点先接住 p 原来的后继
p->next = s;         // 第二步：再让 p 指向新结点
```

这两句**顺序绝对不能颠倒**。如果先写 `p->next = s`，那么原来 $p$ 的后继地址就丢了，`s->next` 再也接不上原链表，链表从 $s$ 处断成两截。

**前插（在 $p$ 之前插入）**：如果只给 `p` 而没有给它的前驱，正常做法要先找到前驱，$O(n)$。但有一个 $O(1)$ 的技巧——**「偷梁换柱」**：

```c
// 在 p 之前插入值为 x 的结点，O(1)
void InsertBefore(LNode *p, ElemType x) {
    LNode *s = (LNode *)malloc(sizeof(LNode));
    s->data = p->data;   // 先把 p 的数据复制给新结点
    s->next = p->next;   // 新结点接在 p 后面
    p->next = s;
    p->data = x;         // 再把 x 写回 p，逻辑上等于 x 插到了 p 之前
}
```

**删除**：
- 已知待删结点的**位序 $i$**：调用 `GetElem(L, i-1)` 找到前驱 $p$，再执行

```c
q = p->next;            // q 指向待删结点
p->next = q->next;      // 前驱跳过待删结点
free(q);                // 释放空间
```

  查找前驱需要 $O(n)$，单看删除动作本身是 $O(1)$。
- 已知待删结点的**指针 $p$**：不能直接 `free(p)`，因为无法把 $p$ 的前驱接到 $p$ 的后继上。用同样的「偷梁换柱」：

```c
// 删除 p 所指结点，前提是 p 不是尾结点
void DeleteNode(LNode *p) {
    if (p == NULL || p->next == NULL) return;   // 尾结点无法用此法删除
    LNode *q = p->next;
    p->data = q->data;      // 用后继的数据覆盖自己
    p->next = q->next;      // 再把自己变成「后继的后继」
    free(q);                // 删除的是原来的后继结点
}
```

:::warn 删除自身的两个致命陷阱
1. **尾结点不能用这个技巧**。$p$ 是尾结点时 $p\to next$ 为 `NULL`，`q->data` 会解引用空指针。所以必须先判断 `p->next != NULL`。
2. **指针变量不能改**。这个技巧只能改 `p` 所指结点的**内容**，无法让调用者手里的 `p` 变成别的结点。如果题目说「删除 p 所指结点并让 p 指向其后继」，必须用前驱法或额外返回新的指针。
:::

:::exam 2024-01 的典型考法
给定带头结点链表，`p` 指向非首非尾结点，执行 `q = p->next; p->next = q->next; q->next = h->next; h->next = q;`。逐句读：前两句把 $q$ 从 $p$ 后面摘下来（$p$ 跳过 $q$），第三句让 $q$ 指向原来的第一个数据结点，第四句让头结点指向 $q$。最终效果是**把 $q$ 所指结点移动到链表的头结点之后**。这类题只要耐心逐句画图，不要去背结论。
:::

把插入删除的指针操作归纳成一句总原则：**「先保存，后修改；先连新，后断旧」**。之所以必须这样，是因为链表的一切连接关系都只通过指针保存，而指针赋值是**破坏性**的——一旦 `p->next` 被改成别的值，原来指向的那个结点就失去了唯一的入口，再也找不回来。所以任何一段链表操作代码，都可以用这条原则检查一遍：

- 后插时先写 `s->next = p->next`（保存旧后继），再写 `p->next = s`（修改）。
- 删除时先用 `q` 记住待删结点，再改 `p->next`，最后 `free(q)`（**必须先记住再改**，否则 `free` 的是错的空间）。
- 双链表插入时，凡是要读「邻居的原指针」的语句都排在修改它之前。
- 遍历时若要回头用 `p->next`，先用临时变量 `nxt = p->next` 存下来。这个习惯在反转链表、K 个一组翻转、交叉合并里反复用到，是**链表题不出错的最重要保障**。

同时还要舍得用变量。链表题的代码量不大，但指针关系容易绕晕，**多定义两个临时指针（如 `pre`、`nxt`、`tail`、`dummy`）比省变量划算得多**。统考判分看的是算法正确性和复杂度，不会因为「多用一个指针变量」扣分。相反，把代码压缩成一行套一行，一旦边界错了就是全错。

关于删除还有一点要补充：**被删除的结点必须 `free` 释放**。不释放只是「逻辑上删掉了」，链表的实际占用空间不会减少，若题目要求「空间复杂度为 $O(1)$」或者「释放结点空间」，漏掉 `free` 会直接失分。另外，**不要 `free` 之后还继续访问该结点**（悬空指针），正确顺序总是「先接好前后关系，再 `free`，且 `free` 后不再使用 `q`」。

#### 4. 头插法与尾插法建立单链表

**头插法**：每读入一个元素就插到头结点之后。**输入顺序与链表中的顺序相反**，因此头插法天然可以用来**就地逆置链表**。

```c
// 头插法建立单链表，输入 999 结束
LinkList ListHeadInsert(LinkList *L) {
    *L = (LNode *)malloc(sizeof(LNode));
    (*L)->next = NULL;
    ElemType x;
    scanf("%d", &x);
    while (x != 999) {
        LNode *s = (LNode *)malloc(sizeof(LNode));
        s->data = x;
        s->next = (*L)->next;   // 新结点接住头结点原来的后继
        (*L)->next = s;         // 头结点指向新结点
        scanf("%d", &x);
    }
    return *L;
}
```

**尾插法**：额外用一个尾指针 `r` 指向表尾，每次把新结点接在 `r` 之后并让 `r` 后移。**输入顺序与链表顺序一致**。如果不用尾指针、每次都从头找表尾，总时间会退化到 $O(n^2)$。

```c
// 尾插法建立单链表，输入 999 结束
LinkList ListTailInsert(LinkList *L) {
    *L = (LNode *)malloc(sizeof(LNode));
    (*L)->next = NULL;
    LNode *r = *L;              // r 始终指向表尾结点
    ElemType x;
    scanf("%d", &x);
    while (x != 999) {
        LNode *s = (LNode *)malloc(sizeof(LNode));
        s->data = x;
        s->next = NULL;
        r->next = s;            // 挂到表尾之后
        r = s;                  // 尾指针后移
        scanf("%d", &x);
    }
    return *L;
}
```

:::key 头插法 vs 尾插法的用途
- **头插法**：顺序反转，用于**链表就地逆置**、把升序链表合并成降序链表。
- **尾插法**：保持相对顺序，用于**合并两个升序链表为一个升序链表**、**拆分链表后保持原有次序**。
两种建立方式的时间复杂度都是 $O(n)$（每次插入本身 $O(1)$，共 $n$ 次）。
:::

#### 5. 双链表

```c
typedef struct DNode {
    ElemType data;
    struct DNode *prior, *next;   // 前驱、后继
} DNode, *DLinkList;
```

**在 $p$ 之后插入 $s$**（注意四条语句的顺序，可以这样记：先处理「$s$ 的两根线」，再处理「邻居指向 $s$ 的两根线」）：

```c
s->next = p->next;          // 1. s 的后继指向 p 的后继
if (p->next != NULL)
    p->next->prior = s;     // 2. p 的原后继的前驱改为 s
s->prior = p;               // 3. s 的前驱指向 p
p->next = s;                // 4. p 的后继改为 s
```

**删除 $p$ 的后继结点 $q$**：

```c
q = p->next;
p->next = q->next;
if (q->next != NULL)
    q->next->prior = p;
free(q);
```

:::warn 双链表语句顺序为什么不能乱
关键点：**凡是「读取 `p->next`」的语句，必须写在「修改 `p->next`」的语句之前**。上面的插入写法里第 2 句用到了 `p->next`，第 4 句才改 `p->next`，顺序是对的。2023-02 就是这样考的：题干先给了 `s->next = p->next; p->next = s;`，此时 `p->next` 已经变成 $s$，原来的后继 $r$ 只能通过 `s->next` 找到，所以后续必须写 `s->prev = s->next->prev; s->next->prev = s;`——**不能再写 `p->next->prev = s`**，那会把 $s$ 的前驱指向 $s$ 自己。
:::

#### 6. 循环链表

**循环单链表**：表尾结点的 `next` 不指向 `NULL`，而是指回头结点，整条链形成一个环。

```c
// 初始化空循环单链表
bool InitList(LinkList *L) {
    *L = (LNode *)malloc(sizeof(LNode));
    if (*L == NULL) return false;
    (*L)->next = *L;        // 头结点的 next 指向自己，代表空表
    return true;
}
// 判空
bool Empty(LinkList L) { return L->next == L; }
// 判断 p 是否为表尾结点（循环单链表特有）
bool isTail(LinkList L, LNode *p) { return p->next == L; }
```

**循环双链表**：头结点的 `prior` 指向表尾，表尾的 `next` 指向头结点。

```c
bool InitDList(DLinkList *L) {
    *L = (DNode *)malloc(sizeof(DNode));
    if (*L == NULL) return false;
    (*L)->prior = *L;      // 空循环双链表：两根指针都指自己
    (*L)->next  = *L;
    return true;
}
bool EmptyDList(DLinkList L) { return L->next == L; }  // L->prior == L 等价
```

:::key 循环链表带来的能力
1. **从任一结点出发都能遍历整条链表**；普通单链表从某结点出发只能走到后继方向。
2. 若设置**尾指针 `tail`**，则访问表头 `tail->next` 和表尾 `tail` 都是 $O(1)$；普通单链表找表尾是 $O(n)$。
3. **插入删除本身与普通链表相同**，但在**表头或表尾**操作时要额外维护「环」的性质：删表尾后要改尾指针，环上有结点时要保证「最后一个结点的 next 指回头结点」。
:::

:::exam 2021-01 的经典陷阱
带头结点的非空单循环链表，`h` 是头指针，`p` 是尾指针，删除第一个元素。正确语句是

```c
q = h->next; h->next = q->next; if (p == q) p = h; free(q);
```

要点有两个：**先保存 `q` 再改 `h->next`**（否则 `q` 会指向新的首结点，最终释放错结点）；**当链表只有一个数据结点时 `p == q`**，删除后表空，必须把尾指针 `p` 重新指向头结点，否则 `p` 会指向已释放的空间。这类「边界情形」是循环链表题的固定得分点。
:::

#### 7. 静态链表

**静态链表**借助**数组**来描述链式存储结构：结点仍有数据域和指针域，但指针域里存放的是**数组下标**（称为游标），而不是真正的地址。它适用于**不支持指针的高级语言**。

```c
#define MaxSize 50
typedef struct {
    ElemType data;
    int next;          // 下一个元素的数组下标，-1 表示结束
} SLinkList[MaxSize];
```

数组的 0 号分量通常充当**头结点**（`SLinkList[0].next` 指向第一个数据结点）。插入删除只需修改 `next` 的值，**不需要移动元素**，这一点和动态链表一致；但静态链表**不能随机存取**，只能从头结点顺着下标找，而且**容量固定、不能动态扩容**。

:::key 静态链表的两个特征值
- `next == -1`：本结点是链表最后一个结点（表示「指向 NULL」）。
- `next == -2`（或题目约定的其他特殊值）：本结点**空闲未使用**。

构造静态链表时的通用方法：**从链接地址为 NULL 的那个结点开始反向追溯，就能还原出完整的逻辑顺序**。2016-01 就是先给出一张「地址 / 元素 / 链接地址」表，让你还原链表顺序（`c → a → e → b → d`）后再做插入。
:::

:::exam 2016-01 的解题流程
已知表头元素为 c，按 `c(1008H) → a(1000H) → e(1010H) → b(1004H) → d(100CH) → NULL` 还原出逻辑顺序；把 f 放在 1014H 并插到 a 和 e 之间后变成 `c → a → f → e → b → d`。于是：

- a 的直接后继变成 f，a 的链接地址为 1014H；
- e 的直接后继仍是 b，e 的链接地址仍为 1004H；
- f 的直接后继是 e，f 的链接地址为 1010H。

按题目要求的 **a、e、f 的顺序**输出，得 `1014H, 1004H, 1010H`。注意题干问的顺序（a, e, f）与链表顺序（a, f, e）不一致，**审题时按题干给的顺序作答**，否则会误选。
:::

### （三）顺序表与链表的对比

| 比较项 | 顺序表 | 链表 |
|---|---|---|
| 存储方式 | 连续空间，逻辑相邻即物理相邻 | 任意空间，靠指针建立逻辑关系 |
| 存取方式 | **随机存取**，按位查找 $O(1)$ | **顺序存取**，按位查找 $O(n)$ |
| 按值查找 | $O(n)$，平均比较 $\dfrac{n+1}{2}$ 次 | $O(n)$，平均比较 $\dfrac{n+1}{2}$ 次 |
| 插入 / 删除 | 平均移动 $\dfrac{n}{2}$ / $\dfrac{n-1}{2}$ 个元素，$O(n)$ | 修改指针，本身 $O(1)$；但找位置要 $O(n)$ |
| 空间分配 | 静态分配需预估容量，可能溢出；动态分配扩容要整体搬移 | 按需申请，不需要连续空间，不会溢出 |
| 存储密度 | $=1$（无额外结构开销） | $<1$（每个结点多一个或两个指针域） |
| 逻辑结构 | 均为线性表（一对一），**逻辑结构相同** | 同左 |
| 适用场合 | 表长可预估、**频繁按位访问**、很少插入删除 | 表长变化大、**频繁插入删除**、难以预估规模 |

:::key 选择的判断口诀
**「常查少改」用顺序表，「常改少查」用链表；要按位随机访问用顺序表，要频繁插删用链表。** 若既要求高效按位访问又要求高效插删，那是更复杂结构（如树、跳表）的用武之地，不在本章范围。
:::

把这张表再压缩成三句可判断的话，选择题里可以直接用：

1. **问「能不能 $O(1)$ 取到第 $i$ 个元素」**：只有顺序表（等价说法：随机存取、随机访问、支持下标直接访问）。
2. **问「插入删除是否要移动元素」**：顺序表要，链表不要（链表只改指针）。但要注意，若题目还问「找到位置需要几步」，答案都要加上 $O(n)$ 的定位代价。
3. **问「空间是否可能浪费 / 溢出」**：顺序表有预分配问题（静态可能溢出、动态会搬移、连续空间可能申请不到），链表不会溢出，但每个结点都要付指针域的空间代价。

:::warn 三个常见的对比误区
1. **不能说「链表的插入删除一定是 $O(1)$」**。只有「已经拿到待操作结点的指针」时才是 $O(1)$；若题目给的是位序 $i$，找位置本身要 $O(n)$，整体仍是 $O(n)$。
2. **不能说「链表一定比顺序表省空间」**。链表省去了「预留连续大空间」的浪费，但每个结点都要付指针域的税，存储密度更低。
3. **循环链表和双向链表不改变时间复杂度的数量级**，它们带来的是「能反向走」「从任一结点出发可遍历全程」「插入删除更方便维护」这类**常数级或功能性**的好处。
:::

### （〇）算法设计题的通用解题框架

线性表的算法题看似花样多，实际上绝大多数都能归入下面五种手法之一。拿到题目先判断它属于哪一类，再套相应模板，比从零推导快得多，也稳得多。

| 手法 | 适用特征 | 典型题目 |
|---|---|---|
| **双指针（同向）** | 需要「原地筛选 / 删除 / 合并」，保持相对顺序 | 删重复、删值为 $x$ 的元素、合并有序表 |
| **双指针（前后 / 距离固定）** | 需要「倒数第 $k$ 个」这类定位 | 2009 倒数第 $k$ 个结点、2012 求共同后缀 |
| **快慢指针** | 需要「中间位置」「是否有环」「环的入口」 | 2019 重排链表、判断环、找中点 |
| **就地逆置** | 需要「反转次序」或「借助反转改变顺序」 | 2010 循环左移、链表逆置、升序合并成降序 |
| **辅助数组 / 计数数组** | 题目给了值域范围（如 $data$ 的绝对值不超过 $n$、$0 \le a_i < n$） | 2015 删绝对值重复、2013 主元素、2018 最小正整数 |

判断的关键在题干的两个信号：**一是「空间复杂度」的要求**（要求 $O(1)$ 就不能用辅助数组，只能原地改指针或引用计数）；**二是题目给出的取值范围或有序性条件**（给了值域范围往往暗示可以用数组下标做标记；给了有序性往往暗示可以用双指针一趟扫描）。换句话说，**题目里出现的每一个条件几乎都是有用信息，不会白给**。

写代码时的两条自保策略：**一是先把边界情形在纸上列全**（空表、单结点、全是要删的元素、一个元素都不删、表长恰好等于 $k$ 等），写代码时逐个处理；**二是写完后拿一组 3～4 个元素的小数据手工模拟一遍**，确认指针没有走空、没有成环、没有漏结点。这两步花不了两分钟，但能避免绝大多数失分。

### （一）合并两个有序表（两种存储都考）

**顺序表版本**：把两个升序顺序表合并为一个升序顺序表，用三个下标 $i, j, k$ 从前往后比较，谁小谁先写。若要求**原地**合并且目标数组有足够尾部空间，则改用**从后往前**的双指针，避免覆盖还没比较的数据。

```c
// 将升序顺序表 A、B 合并为升序顺序表 C
void MergeSqList(SqList A, SqList B, SqList *C) {
    int i = 0, j = 0, k = 0;
    while (i < A.length && j < B.length) {
        if (A.data[i] <= B.data[j]) C->data[k++] = A.data[i++];
        else                        C->data[k++] = B.data[j++];
    }
    while (i < A.length) C->data[k++] = A.data[i++];  // A 有剩余
    while (j < B.length) C->data[k++] = B.data[j++];  // B 有剩余
    C->length = k;
}
```

时间复杂度 $O(n+m)$，空间复杂度 $O(1)$（不计结果表本身的空间）。

**链表版本**：

```c
// 将两个带头结点的升序单链表合并为一个升序单链表，用尾插法
LinkList MergeList(LinkList A, LinkList B) {
    LinkList C = (LinkList)malloc(sizeof(LNode));
    C->next = NULL;
    LNode *pa = A->next, *pb = B->next, *r = C;  // r 为新表尾指针
    while (pa != NULL && pb != NULL) {
        if (pa->data <= pb->data) { r->next = pa; r = pa; pa = pa->next; }
        else                     { r->next = pb; r = pb; pb = pb->next; }
    }
    r->next = (pa != NULL) ? pa : pb;   // 剩余部分整段接上，不必逐个插入
    free(A); free(B);                   // 释放两个原头结点
    return C;
}
```

:::key 升序合并成降序 = 头插法
若题目要求「两个升序链表合并为一条**降序**链表」（2013 年选择题的考点），必须改成**头插法**：每次比较取出较小的结点后，用 `s->next = C->next; C->next = s;` 插到结果表头。因为「当前较小」不等于「全体最大」，**不能用尾插法**。全部结点处理完后，每个结点最多被访问一次，最坏时间复杂度是 $O(n+m) = O(\max(m,n))$（$m,n$ 同阶时二者等价，这正是 2013-01 选 D 的理由）。
:::

### （二）就地逆置

**顺序表逆置**：首尾双指针交换，走到中间停止，时间 $O(n)$、空间 $O(1)$。

```c
void ReverseSqList(SqList *L) {
    ElemType tmp;
    for (int i = 0, j = L->length - 1; i < j; i++, j--) {
        tmp = L->data[i]; L->data[i] = L->data[j]; L->data[j] = tmp;
    }
}
```

**链表逆置（迭代法，必须背下来）**：把链表看成「已逆置部分」和「未逆置部分」，逐个把未逆置部分的第一个结点接到已逆置部分的最前面。

```c
// 带头结点单链表的就地逆置
void ReverseList(LinkList L) {
    LNode *pre = NULL, *cur = L->next;
    while (cur != NULL) {
        LNode *next = cur->next;  // 先保存后继，因为下一步要改 cur->next
        cur->next = pre;          // 反转指针方向
        pre = cur;                // pre 后移
        cur = next;               // cur 后移
    }
    L->next = pre;                // 头结点接上新的第一个结点
}
```

:::key 迭代法反转后的一个重要性质
反转某一段结束后：**`pre` 指向这一段的最后一个结点，`cur` 指向这一段之后的第一个结点**（都是在原链表视角下）。这个性质在「反转部分链表」「重排链表」「K 个一组翻转」里反复使用，务必记住。
:::

为什么迭代法比递归法和「入栈法」都好？把三种做法摆在一起看就清楚了：

| 方法 | 时间 | 空间 | 说明 |
|---|---|---|---|
| 迭代法（双指针） | $O(n)$ | $O(1)$ | 原地改指针，最优解，必背 |
| 头插法 | $O(n)$ | $O(1)$ | 依靠待反转段的**前驱结点**；若无前驱需先造一个 `dummy` |
| 递归法 | $O(n)$ | $O(n)$ | 递归栈深度为 $n$，且处理不当容易成环 |
| 入栈法 | $O(n)$ | $O(n)$ | 借助栈的先进后出实现逆序，空间不达标 |

因此**只要题目要求空间 $O(1)$，答案就只能用迭代法或头插法**。递归写法虽然短，但空间复杂度不达标，在「空间复杂度为 $O(1)$」的题目里会被判失分。2019 年重排链表题明确要求 $O(1)$ 空间，就是这一点的直接体现。

**用头插法逆置**也可以，效果相同，本质就是「把结点依次摘下再头插回头结点之后」。为什么迭代法比递归法和「入栈法」都好？把几种做法摆在一起看就清楚了：

| 方法 | 时间 | 空间 | 说明 |
|---|---|---|---|
| 迭代法（双指针） | $O(n)$ | $O(1)$ | 原地改指针，最优解，必背 |
| 头插法 | $O(n)$ | $O(1)$ | 依靠待反转段的**前驱结点**；若无前驱需先造一个 `dummy` |
| 递归法 | $O(n)$ | $O(n)$ | 递归栈深度为 $n$，处理不当容易成环 |
| 入栈法 | $O(n)$ | $O(n)$ | 借助栈的先进后出实现逆序，空间不达标 |

**只要题目要求空间 $O(1)$，答案就只能用迭代法或头插法。** 递归写法虽然短，但空间复杂度不达标，在「空间复杂度为 $O(1)$」的题目里会被判失分。2019 年重排链表题明确要求 $O(1)$ 空间，就是这一点的直接体现。

头插法逆置的一个常见用法是把「就地逆置」写成与「头插法建表」同构的代码：

```c
// 头插法就地逆置带头结点的单链表
void ReverseByHeadInsert(LinkList L) {
    LNode *p = L->next, *r;
    L->next = NULL;              // 先断开，头结点单独作为新表的头
    while (p != NULL) {
        r = p->next;             // 先保存后继
        p->next = L->next;       // 头插：新结点接住当前的第一个结点
        L->next = p;             // 头结点指向新结点
        p = r;                   // 继续处理原来的后继
    }
}
```

对照着看会发现，**「头插法建表」和「头插法逆置」其实是同一段程序**——这正是「输入顺序与链表顺序相反」这一特性的直接应用，也是 2013 年「升序链表合并为降序链表」能用头插法解决的原因。它的一个常见用法是把「就地逆置」和「建立链表」合并成一段代码：

```c
// 头插法就地逆置带头结点的单链表
void ReverseByHeadInsert(LinkList L) {
    LNode *p = L->next, *r;
    L->next = NULL;              // 先断开，头结点单独作为新表的头
    while (p != NULL) {
        r = p->next;             // 先保存后继
        p->next = L->next;       // 头插：新结点接住当前的第一个结点
        L->next = p;             // 头结点指向新结点
        p = r;                   // 继续处理原来的后继
    }
}
```

两段代码对照着看，会发现**「头插法建表」和「头插法逆置」其实是同一段程序**——这正是「输入顺序与链表顺序相反」这一特性的直接应用，也是 2013 年「升序链表合并为降序链表」能用头插法解决的原因。

**「数组循环左移 $p$ 位」（2010 年真题）** 的经典做法是**三次逆置**：先把前 $p$ 个元素逆置，再把后 $n-p$ 个元素逆置，最后把整个数组逆置。

```c
// 将 R[0..n-1] 循环左移 p 位，O(n) 时间、O(1) 空间
void LeftShift(int R[], int n, int p) {
    p = p % n;               // 先取模，避免 p > n 时的无谓搬移
    Reverse(R, 0, p - 1);    // 前 p 个逆置
    Reverse(R, p, n - 1);    // 后 n-p 个逆置
    Reverse(R, 0, n - 1);    // 整体逆置
}
```

自检一下：$R = \langle 1,2,3,4,5 \rangle$，$p = 2$。前 2 个逆置得 $\langle 2,1,3,4,5 \rangle$，后 3 个逆置得 $\langle 2,1,5,4,3 \rangle$，整体逆置得 $\langle 3,4,5,1,2 \rangle$，正是左移 2 位的结果。

为什么三次逆置能得到循环左移？设原序列为 $X Y$，其中 $X$ 是前 $p$ 个元素、$Y$ 是后 $n-p$ 个元素，目标是 $Y X$。记 $X'$ 表示 $X$ 的逆序，则

$$(X'Y')' = Y X$$

即「先分别把两段各自逆置，再把整体逆置」，就能把 $XY$ 换成 $YX$。这是本题的**核心设计思想**，答题时写出这一步变换，比只贴代码更容易得满分。同理，**循环右移 $p$ 位**只需把三段逆置的顺序调整为「整体逆置 → 前 $p$ 个逆置 → 后 $n-p$ 个逆置」即可。

:::warn 循环左移题的常见失分
一是**忘记处理 $p \ge n$ 的情形**（先取模 `p = p % n`）；二是把三次逆置的边界写错（`Reverse` 通常接收下标区间，注意是左闭右闭还是左闭右开）；三是**空间超标**——额外开一个长度 $n$ 的辅助数组搬移虽然结果正确，但空间是 $O(n)$，不满足题目「时空两方面都尽可能高效」的要求。三次逆置法时间 $O(n)$（每个元素被访问常数次），空间 $O(1)$，是最优解。
:::

$$(X'Y')' = Y X$$

即「先分别把两段各自逆置，再把整体逆置」，就能把 $XY$ 换成 $YX$。这是本题的**核心设计思想**，答题时写出这一步变换，比只贴代码更容易得满分。同理，**循环右移 $p$ 位**只需把三段逆置的顺序调整为「整体逆置 → 前 $p$ 个逆置 → 后 $n-p$ 个逆置」即可。

:::warn 循环左移题的常见失分
一是**忘记处理 $p \ge n$ 的情形**（先取模 $p = p \bmod n$）；二是把三次逆置的边界写错（`Reverse` 函数通常接收下标区间，注意是左闭右闭还是左闭右开）；三是**空间超标**——如果额外开一个长度 $n$ 的辅助数组搬移，虽然结果正确但空间是 $O(n)$，不满足题目「时空两方面都尽可能高效」的要求。三次逆置法的时间是 $O(n)$（每个元素被访问常数次），空间 $O(1)$，是最优解。
:::

### （三）快慢指针：找中间结点

**快指针一次走两步，慢指针一次走一步**；快指针到表尾时，慢指针正好在中间。

```c
// 带头结点单链表求中间结点
// 若结点个数为偶数，本模板返回「下中位」（靠后的那个中间结点）
LNode *MiddleNode(LinkList L) {
    LNode *slow = L, *fast = L;      // 都从头结点出发，便于偶数时返回下中位
    while (fast != NULL && fast->next != NULL) {
        slow = slow->next;
        fast = fast->next->next;
    }
    return slow;
}
```

:::warn 中间结点的定义要看清题目
- 快慢指针都从**头结点**出发，$n$ 为偶数时返回的是**下中位**（第 $n/2 + 1$ 个数据结点）。
- 快慢指针都从**第一个数据结点**出发，$n$ 为偶数时返回的是**上中位**（第 $n/2$ 个数据结点）。

2019 年重排链表题明确要求分界点是**下中位数** $\lceil n/2 \rceil$ 个结点，所以要采用第一种起点。题目怎么写，代码就怎么起步，不要凭印象。
:::

### （四）双指针：倒数第 $k$ 个结点（2009 年真题）

**一次遍历**就能完成：设前后两个指针 `p`（前）和 `q`（后），先让 `p` 从头结点出发走 $k$ 步，然后 `p`、`q` 同时后移，当 `p` 到达表尾（`NULL`）时，`q` 所指就是倒数第 $k$ 个结点。

```c
// 查找带头结点单链表中倒数第 k 个结点，找到则输出其数据并返回 1，否则返回 0
int SearchKthFromEnd(LinkList L, int k) {
    LNode *p = L->next, *q = L->next;
    int i = 0;
    while (p != NULL && i < k) { p = p->next; i++; }  // p 先走 k 步
    if (p == NULL && i < k) return 0;                 // 表长不足 k，查找失败
    while (p != NULL) { p = p->next; q = q->next; }   // 同步后移
    printf("%d\n", q->data);
    return 1;
}
```

时间复杂度 $O(n)$（只扫一遍），空间复杂度 $O(1)$。

:::warn 边界：表长不足 $k$
第一个 `while` 结束时若 `i < k`，说明表长小于 $k$，必须返回 0。很多答案漏掉这个判断，在 `p` 已经为 `NULL` 时还接着做同步后移，逻辑上就错了。另一个写法是让 `p` 从**头结点**出发走 $k$ 步、`q` 从头结点出发，最后 `q->next` 是倒数第 $k$ 个——两种写法等价，但要保证前后指针的起始位置与步数匹配。
:::

### （五）判断链表是否有环，并求环的入口

**判环（快慢指针相遇法）**：快指针每次走两步、慢指针每次走一步。若链表无环，快指针会先到 `NULL` 退出；若有环，快指针必然追上慢指针。

```c
// 判断带头结点单链表中是否有环
bool HasCycle(LinkList L) {
    LNode *slow = L, *fast = L;
    while (fast != NULL && fast->next != NULL) {
        slow = slow->next;
        fast = fast->next->next;
        if (slow == fast) return true;   // 相遇即有环
    }
    return false;                        // fast 走到 NULL，无环
}
```

**为什么快慢指针一定会相遇？** 两个指针都进环后，**每移动一轮，快指针与慢指针的距离就减少 1**（快走 2、慢走 1）。这相当于操场上的追及问题，只要一直走，快指针一定追上慢指针。

**为什么慢指针在环内走不完一圈就被追上？** 考虑最坏情况：慢指针刚进环时，快指针正好在它前面一个位置，此时两者相距「环长 $-1$」，因为每轮距离减少 1，所以最多经过「环长 $-1$」轮就相遇；此时慢指针在环内走了「环长 $-1$」步，**不到一圈**。其他情况比这更快。

**求环的入口（第一次相遇后再用双指针）**：设头结点到环入口的距离为 $a$，环入口到第一次相遇点的距离为 $b$，环长为 $L$。相遇时慢指针走了 $a+b$，快指针走了 $a+b+kL$，而快指针路程是慢指针的两倍，于是

$$2(a+b) = a + b + kL \;\Longrightarrow\; a + b = kL \;\Longrightarrow\; a = kL - b$$

即「从头结点到入口的距离 $a$」等于「从相遇点继续沿环走到入口的距离 $kL-b$」。所以：**相遇后，让一个指针从头结点出发、另一个从相遇点出发，二者同速前进，再次相遇的位置就是环的入口**。

```c
// 返回环的入口结点；无环返回 NULL
LNode *DetectCycle(LinkList L) {
    LNode *slow = L, *fast = L;
    while (fast != NULL && fast->next != NULL) {
        slow = slow->next;
        fast = fast->next->next;
        if (slow == fast) {              // 第一次相遇
            LNode *p = L;
            while (p != slow) {          // 同速前进，再次相遇即入口
                p = p->next;
                slow = slow->next;
            }
            return slow;
        }
    }
    return NULL;
}
```

**求环长**：从第一次相遇点出发，沿环走一圈回到该点，走过的步数就是环长，时间 $O(n)$、空间 $O(1)$。

### （六）判断两个链表是否相交（2012 年真题）

**判定依据（必背）**：两个链表如果相交，**从交点之后它们共享同一段存储，因此两个链表的尾结点必然相同**。注意比较的是**结点地址（指针）**，不是数据域的值！数据域相等只是「值相同」，不代表同一个结点。

:::warn 相交题的经典陷阱
看到 `p->data == q->data` 就断言相交是错的。两个链表可以有相同的值而完全不共享结点。判断相交一定要比 `p == q`（指针相等）。另外要注意：若链表带环，情况会更复杂，统考题干一般会明确「整个链式结构中不存在环」。
:::

**方法一（长度差法）**：分别求两个链表长度 $len_1, len_2$，让较长的那个指针先走 $|len_1-len_2|$ 步，使两个指针到表尾的距离相等，然后同步后移，第一次指针相同的位置就是交点。

```c
// 带头结点，求两个单链表的第一个公共结点
LNode *FindFirstCommon(LinkList A, LinkList B) {
    int lenA = 0, lenB = 0;
    LNode *p = A->next, *q = B->next;
    while (p != NULL) { lenA++; p = p->next; }
    while (q != NULL) { lenB++; q = q->next; }
    p = A->next; q = B->next;
    int d = lenA - lenB;
    while (d > 0) { p = p->next; d--; }     // A 长，p 先走
    while (d < 0) { q = q->next; d++; }     // B 长，q 先走
    while (p != q && p != NULL && q != NULL) { p = p->next; q = q->next; }
    return p;                               // 相交返回交点，不相交返回 NULL
}
```

**方法二（路程补偿，代码更短）**：两个指针同时同速前进，走到 `NULL` 时切换到对方的起点继续走。设公共段长度为 $c$，则两指针总路程都是 $a+c+b+c$ 与 $b+c+a+c$，**相等**，因此必然在交点相遇；若不相交，则会在 `NULL` 处相遇。

```c
LNode *GetIntersectionNode(LinkList A, LinkList B) {
    LNode *p = A->next, *q = B->next;
    while (p != q) {
        p = (p == NULL) ? B->next : p->next;   // 走到头就换到对方起点
        q = (q == NULL) ? A->next : q->next;
    }
    return p;   // 不相交时 p、q 会同时为 NULL，返回 NULL
}
```

两种方法都是时间 $O(m+n)$、空间 $O(1)$。**方法二是 2012 年真题的主流解法**，但方法一更符合「先说清设计思想」的答题习惯，建议两种都掌握。

2012 年真题的题干是「两个单词共享相同后缀」，本质就是「两个链表从某个结点起共享同一段存储」，因此求「共同后缀的起始位置」与求「第一个公共结点」完全等价。答题时的设计思想可以这样写：**先分别求出两个链表的长度，算出长度差 $d$；让较长链表的指针先走 $d$ 步，使两个指针到表尾的距离相等；然后两个指针同步后移，第一次指向同一结点时即交点。** 这段文字就是第一小问的完整答案，务必能默写。

:::warn 长度差法的边界
如果两个链表**根本不相交**，那么同步后移时两个指针会同时变成 `NULL`，此时 `p == q` 成立，`while` 循环退出并返回 `NULL`——这恰好是正确的返回值，所以不需要额外判断。但循环条件必须写成 `p != q && p != NULL && q != NULL` 或者只写 `p != q`（依赖「同时为 NULL 时相等」这一性质）。若写成 `while (p != NULL && q != NULL && p != q)`，退出后还要再判断一次 `p == q ? p : NULL`，更啰嗦。**理解「同时为 NULL 也算相遇」这一点，是本题最容易出彩的地方。**
:::

### （七）删除重复元素

**有序顺序表删重复（双指针）**：因为有序，重复元素一定相邻。用快指针 `fast` 扫描，慢指针 `slow` 指向「下一个不同元素应写入的位置」。

```c
// 从有序顺序表中删除重复元素，返回处理后的表长
int DeleteDuplicates(SqList *L) {
    if (L->length == 0) return 0;
    int slow = 1;                            // data[0] 必然保留
    for (int fast = 1; fast < L->length; fast++) {
        if (L->data[fast] != L->data[fast - 1]) {  // 与前一个不同，是新值
            L->data[slow] = L->data[fast];
            slow++;
        }
    }
    L->length = slow;                        // 不要忘记更新表长
    return slow;
}
```

**无序表删除所有值为 $x$ 的元素（双指针）**：同样用快慢指针，把不等于 $x$ 的元素往前填，时间 $O(n)$、空间 $O(1)$。如果题目要求「删除值在 $s$ 到 $t$ 之间的所有元素」，只需把判断条件改成 `if (L->data[i] < s || L->data[i] > t)`；若 $s > t$ 或表空则直接返回（判空和参数合法性是常被漏掉的得分点）。

**有序表删区间 $[s,t]$（两端定位法）**：先找到第一个 $\ge s$ 的元素位置 $i$ 和最后一个 $\le t$ 的元素位置 $j$，若 $i \le j$ 则把 $j$ 之后的所有元素整体前移 $j-i+1$ 位，表长减小 $j-i+1$。因为有序，$[s,t]$ 内的元素必然连续，这个方法比逐个比较更快（仍然是 $O(n)$，但只扫一遍找到边界就整体搬移）。

**链表删除重复结点**：对**有序链表**，只需比较相邻结点：

```c
// 带头结点的有序单链表删除重复元素，每个值只保留一个
void DeleteSame(LinkList L) {
    LNode *p = L->next, *q;
    while (p != NULL && p->next != NULL) {
        q = p->next;
        if (q->data == p->data) {   // 与后继重复
            p->next = q->next;
            free(q);
        } else {
            p = p->next;
        }
    }
}
```

对**无序链表**删重复，若不允许额外空间，则用二重循环（$O(n^2)$）；若允许空间，2015 年真题的做法是**借助一个标记数组**——因为 `|data| ≤ n`，可以开一个长度 $n+1$ 的数组 `flag[]`，扫描时把 `|data|` 作为下标打标记，遇到已标记的结点就删除，这样时间 $O(m)$、空间 $O(n)$，正是题目「时间复杂度尽可能高效」的意图。这类题一定要**结合题目给的取值范围**来设计，题干里的 `|data| ≤ n` 就是给你的提示。

### （八）其他常考算法

**删除单链表中值最小的结点**（假设存在且唯一）：用一个指针 `minPre` 记住最小值结点的**直接前驱**，一趟扫描后直接删除：

```c
void DeleteMin(LinkList L) {
    if (L->next == NULL) return;
    LNode *minPre = L, *p = L->next;
    while (p->next != NULL) {
        if (p->next->data < minPre->next->data) minPre = p;
        p = p->next;
    }
    LNode *q = minPre->next;
    minPre->next = q->next;
    free(q);
}
```

若要「按递增次序输出各结点的值并释放结点空间」，只需在外面套一层 `while (L->next != NULL)`，每次找出最小值输出并删除。两层扫描，时间 $O(n^2)$、空间 $O(1)$。（若允许 $O(n)$ 辅助空间，可以先存入数组排序，时间 $O(n\log n)$——考试时要看题目对时空的要求择优。）

**拆分链表**：把一个线性表 $C = (a_1,b_1,a_2,b_2,\cdots)$ 拆成 $A = (a_1,a_2,\cdots)$、$B = (b_n,\cdots,b_2,b_1)$ 两个表。做法是：奇数位置结点用**尾插法**接到 A（保持相对次序），偶数位置结点用**头插法**接到 B（实现逆序）。这正是「头插法逆序、尾插法保序」这一特性的直接应用。

**重排链表（2019 年真题）**：把 $L = (a_1,a_2,\cdots,a_n)$ 重排为 $(a_1,a_n,a_2,a_{n-1},\cdots)$，要求空间 $O(1)$，是三个基本功的串联：

1. 用快慢指针找到中间结点（本题取**下中位** $\lceil n/2 \rceil$），并把链表从中间断开；
2. 把后半段**就地逆置**；
3. 把前半段与逆置后的后半段**交叉合并**。

```c
// 带头结点单链表重排为先前后尾交替
void ReorderList(LinkList L) {
    if (L->next == NULL) return;
    // 第一步：找下中位结点
    LNode *slow = L, *fast = L;
    while (fast != NULL && fast->next != NULL) {
        slow = slow->next;
        fast = fast->next->next;
    }
    LNode *head2 = slow->next;   // 后半段的第一个结点
    slow->next = NULL;           // 从中间断开
    // 第二步：把后半段就地逆置
    LNode *pre = NULL, *cur = head2;
    while (cur != NULL) {
        LNode *nxt = cur->next;
        cur->next = pre;
        pre = cur;
        cur = nxt;
    }
    head2 = pre;
    // 第三步：交叉合并
    LNode *p1 = L->next, *p2 = head2;
    while (p1 != NULL && p2 != NULL) {
        LNode *n1 = p1->next, *n2 = p2->next;
        p1->next = p2;
        p2->next = n1;
        p1 = n1;
        p2 = n2;
    }
}
```

:::key 重排链表的复杂度
三步各自都是 $O(n)$，总时间复杂度 $O(n)$，空间复杂度 $O(1)$（只用了常数个指针），完全满足 2019 年真题「空间复杂度为 $O(1)$ 且时间上尽可能高效」的要求。暴力解法（把结点存入数组再按下标重建）虽然也是 $O(n)$ 时间，但空间是 $O(n)$，**不满足题目要求**，会被扣分。
:::

**其他常见小题型**（知道思路即可）：
- **数组主元素（2013 年真题）**：摩尔投票法，$O(n)$、$O(1)$。先假设当前元素为候选、计票数为 1，遇见相同加一、不同减一，计票归零则换候选；最后再扫一遍验证候选出现次数是否真的 $> n/2$。**验证这一步不能省**。
- **未出现的最小正整数（2018 年真题）**：利用「$n$ 个元素，未出现的最小正整数必然在 $1 \sim n+1$ 之间」这一结论，用原地交换（或辅助标记数组）把值域内的元素放到对应下标处，再从头扫描找第一个不满足 `A[i] == i+1` 的位置；时间 $O(n)$、空间 $O(1)$。
- **两个等长升序序列的中位数（2011 年真题）**：用类二分的思路，每次同时比较两个序列的中位数，取半区间，逐步把规模缩小一半，时间 $O(\log n)$、空间 $O(1)$。
- **三元组最小距离（2020 年真题）**：三个有序数组各设一个指针，每次计算当前三元组距离并更新最小值，然后把三个指针中**指向最小元素**的那个前移一位，循环直到某个数组走到末尾；时间 $O(n_1+n_2+n_3)$。

关于 2011 年与 2020 年这两道题，值得多写几句设计思想，因为它们的「套路感」很强。

**2011 年求两等长升序序列的中位数**，设计思想可以这样表述：设两个序列为 $A$、$B$，长度均为 $L$。分别取 $A$ 的中位数 $a$ 和 $B$ 的中位数 $b$（第 $\lceil L/2 \rceil$ 个元素）。若 $a = b$，则 $a$ 就是所求；若 $a < b$，则所求中位数一定不在 $A$ 的前半段（可以舍弃 $A$ 的前 $\lfloor L/2 \rfloor$ 个）和 $B$ 的后半段（舍弃 $B$ 的后 $\lfloor L/2 \rfloor$ 个）；若 $a > b$ 则对称地舍弃 $A$ 的后半段与 $B$ 的前半段。**每次把规模缩小一半，且两个序列始终等长**，直到两个序列各只剩一个元素，较小者即为所求。因为规模每次减半，时间 $O(\log_2 n)$，只用了常数个变量，空间 $O(1)$。这类「取中位数、比大小、抛掉不可能的一半」的写法，本质与折半查找同源。

**2020 年求三元组最小距离**，设计思想是：$D = |a-b| + |b-c| + |c-a|$ 这个式子看起来有三个绝对值，但若设 $a \le b \le c$，则 $D = 2(c-a)$——**距离只由最大者和最小者的差决定**。因此要让 $D$ 变小，唯一的办法是把「当前最小的那个元素」换成它所在集合中的下一个更大的元素，从而抬高最小值、缩小极差。于是算法是：三个指针分别指向三个有序数组的第一个元素，循环计算当前 $D$ 并更新答案，然后**把三个指针中指向最小值的那个指针向后移一位**（若并列最小，移动任意一个即可，但通常约定移动其中一个并继续），直到某个指针越界。每个指针最多走完自己那个数组，总时间 $O(n_1+n_2+n_3)$，空间 $O(1)$。**注意题目里的排序条件是「按升序分别存储」，正是它保证了「往后移只会让最小值变大」这一单调性，去掉有序条件这个方法就不成立了。**

这两个例子说明同一件事：**统考算法题的最优解往往来自对题目给定条件的充分利用**（有序、等长、值域范围），而不是来自高级技巧。审题时把每个条件都圈出来，是最有效的解题起点。

### （九）补充：无序表先排序再处理的思路

线性表的算法题里有一类「看起来没有下手处」的题目：给一个**无序数组**，要求找某种满足大小关系的结果。这时一条通用的破题思路是——**先用 $O(n \log n)$ 把它变成有序表，再对有序表用双指针等线性手法**，总时间仍然是 $O(n\log n)$，通常就是这类题的标准答案。

典型例子是「找出数组中未出现的最小正整数」（2018 年真题）。如果直接扫描，很难判断「哪个正整数没出现」；但一旦想到「$n$ 个元素里未出现的最小正整数一定不超过 $n+1$」，就可以用值域做下标打标记，一趟扫描解决问题。再比如「求两个数组的交集」「找出重复出现的元素」「求数组中两数之差的最小绝对值」，排序后相邻比较或双指针一遍即得。

注意事项有两条。**第一，408 考试不允许直接调用 `sort` 等库函数**，需要自己写出排序。建议把快速排序模板背下来备用：

```c
// 快速排序：对 q[l..r] 就地升序排序，平均 O(nlogn)，空间 O(logn)
void QuickSort(int q[], int l, int r) {
    if (l >= r) return;                 // 递归终止：区间内元素不超过 1 个
    int i = l - 1, j = r + 1, x = q[l + r >> 1];  // x 取中间元素作分界点
    while (i < j) {
        do i++; while (q[i] < x);       // i 之前的元素都 <= x
        do j--; while (q[j] > x);       // j 之后的元素都 >= x
        if (i < j) { int t = q[i]; q[i] = q[j]; q[j] = t; }
    }
    QuickSort(q, l, j);
    QuickSort(q, j + 1, r);
}
```

**第二，排序会改变元素的相对位置**。如果题目要求「保持原有次序」，就不能先排序，只能改用双指针一趟扫描或其他不改变次序的方法。审题时务必看清这一点。

```c
// 折半查找：在有序数组 A[low..high] 中查找 x，返回下标，失败返回 -1
int BinarySearch(int A[], int low, int high, int x) {
    while (low <= high) {                  // 左闭右闭区间
        int mid = low + (high - low) / 2;  // 防溢出写法，等价于 (low+high)/2
        if (A[mid] > x)      high = mid - 1;
        else if (A[mid] < x) low = mid + 1;
        else                 return mid;
    }
    return -1;
}
```

折半查找每次把查找区间缩小一半，最多比较 $\lceil \log_2(n+1) \rceil$ 次，时间 $O(\log_2 n)$、空间 $O(1)$。但再次强调：**它要求「有序」且「顺序存储」**——链表无法在 $O(1)$ 时间内取到中间元素，因此不能在链表上做折半查找。这个结论是「顺序表与链表对比」在查找问题上的延伸，常与本章一起出题。

:::warn 「先排序再处理」的两个前提
一是**题目没有要求保持原有次序**（否则排序就破坏了要求）；二是**排序的代价可以接受**（若题目要求 $O(n)$ 时间，那排序的 $O(n\log n)$ 就超标了，此时要另想办法，例如用哈希 / 标记数组把时间压到 $O(n)$）。这两点判断错，方向就全错了。
:::

## 本章小结表

| 知识点 | 核心结论 |
|---|---|
| 线性表定义 | 同类型、有限、有序；除首尾外一前一后 |
| 位序 vs 下标 | 位序从 1 开始，下标从 0 开始；插入范围 $1 \sim n+1$，删除范围 $1 \sim n$ |
| 顺序表地址 | $LOC(a_i) = LOC(a_1) + (i-1)\times d$，随机访问 |

| 删除平均移动 | $\dfrac{n-1}{2}$ 次，时间复杂度 $O(n)$ |
| 按值查找（顺序） | 平均比较 $\dfrac{n+1}{2}$ 次，$O(n)$ |
| 链表按位查找 | 平均比较 $\dfrac{n+1}{2}$ 次，$O(n)$，顺序存取 |
| 头结点作用 | 统一空表/非空表、统一首位置插删、头指针恒非空 |

| 尾插法 | 保持相对顺序，需尾指针，$O(n)$ |
| 后插口诀 | 先连后（`s->next=p->next`）再连前（`p->next=s`） |
| 双链表后插 | 四句顺序：`s->next`、`p->next->prior`、`s->prior`、`p->next` |
| 循环单链表判空 | `head->next == head` |
| 循环双链表判空 | `head->next == head`（且 `head->prior == head`） |
| 静态链表 | 数组 + 游标；`next==-1` 表结束；不能随机存取、容量固定 |

| 2019 重排链表 | 找中点 + 逆置后半 + 交叉合并，$O(n)$、$O(1)$ |

## 易错清单

:::warn 本章最容易被扣分的地方
1. **把「线性表」与「顺序表」混为一谈**。线性表是逻辑结构，顺序表和链表是存储结构。判断题说「线性表只能顺序存储」是错的。
2. **位序与下标混用**。`L.data[i-1]` 对应位序 $i$；插入合法范围是 $1 \le i \le n+1$，删除是 $1 \le i \le n$。写代码时越界判断的两个条件是高频扣分点。
3. **插入移动次数记成 $\dfrac{n-1}{2}$、删除记成 $\dfrac{n}{2}$**。务必用记忆锚点：**插入有 $n+1$ 个位置（含表尾后），删除只有 $n$ 个位置**，所以插入的分母大、平均移动多（$n/2$），删除的平均移动少（$(n-1)/2$）。
4. **把「链表插入删除是 $O(1)$」绝对化**。只有「已拿到结点指针」时才是 $O(1)$；给位序就要 $O(n)$ 找位置。
5. **后插两句顺序颠倒**。先写 `p->next = s` 会丢失原来的后继地址，链表断开。
6. **双链表插入时语句顺序错乱**。核心规则：读 `p->next` 的语句必须写在改 `p->next` 之前。
7. **用「删自身」技巧时忘了判尾结点**。尾结点的 `p->next == NULL`，会解引用空指针；必须 `if (p->next != NULL)`。
8. **循环链表删除时忘记维护环和尾指针**。链表只剩一个数据结点时删掉它，尾指针必须重新指向头结点（2021-01、2016-02 反复考这一点）。
9. **判断相交时比较了 `data` 而不是指针**。数据相等不等于共享结点。
10. **中间结点的上中位 / 下中位搞反**。快慢指针起点决定返回哪一个，必须按题目要求选起点。
11. **快慢指针循环条件写错**。判环、找中点时必须写 `while (fast != NULL && fast->next != NULL)`，只判 `fast` 会在 `fast->next->next` 处解引用空指针。
12. **静态链表误以为可以随机存取**。它虽然用数组，但逻辑顺序由游标决定，只能从头顺着游标找，是顺序存取。
13. **算法题漏写边界与复杂度**。空表、单结点、表长不足 $k$、参数 $s>t$ 等情形要显式判断；三小问（设计思想、代码、复杂度）要分别作答，代码里要有注释。
14. **题目要求 $O(1)$ 空间却用了数组或递归**。递归调用栈算空间（递归法反转链表是 $O(n)$），辅助数组也是空间；不满足时空要求即使结果正确也会失分。
:::
