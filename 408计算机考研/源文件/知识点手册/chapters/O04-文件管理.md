## 文件的基本概念

### 数据项、记录与文件

文件的内部是分层组织的，自底向上依次是：

- **数据项（data item）**：最低级的数据组织形式。**基本数据项**是数据中不可再分的最小逻辑单位，如「学号」「姓名」；**组合数据项**由若干基本数据项组成，如「出生日期」由年、月、日组成。
- **记录（record）**：一组相关数据项的集合，用于描述一个对象在某方面的属性。例如一条学生记录 = 学号 + 姓名 + 出生日期 + 专业。
- **文件（file）**：由创建者定义、具有文件名的一组相关信息的集合。文件可分为**有结构文件**（若干记录组成）与**无结构文件**（字符流）。

:::key 文件的定义与三个视角
从用户角度看，**文件是具有符号名（文件名）的一组相关信息的有序集合**，它可以存储在磁盘等外存上，并且可以被长期保存。

理解文件要抓住三个层次：

- **用户视角**：文件是「按名字存取的信息集合」，通过文件名访问，不必知道数据究竟放在哪个盘块。
- **系统视角**：文件是**外存空间的分配单位**，文件系统为每个文件维护一份元数据（FCB/inode）记录它占用了哪些盘块。
- **进程视角**：文件是**进程可以打开、读写的对象**，打开后以「文件描述符」为句柄操作，与文件名脱钩。
:::

### 文件系统及其功能

**文件系统（File System）**是操作系统中负责管理和存取文件信息的软件机构，也是磁盘上组织文件的方法。它的核心目标只有一个：**实现「按名存取」**，同时保证高效、安全、可靠。

- **从系统角度看**，文件系统负责：文件存储空间的管理、目录管理、逻辑地址到物理地址的映射（文件读写管理）、文件的共享与保护。
- **从用户角度看**，文件系统提供了命令接口（终端里敲 `ls`、`cp`）和程序接口（`open`、`read`、`write` 等系统调用）。

:::warn 文件系统容量不等于磁盘容量
一个文件系统能容纳的文件数量，受**索引节点（inode）总数**限制（搭建文件系统时往往已经固定，格式化时划分了 inode 区）；而**单个文件的最大长度**受 inode 中地址项的个数与结构限制。所以：

- 「文件系统最多能存多少个文件」由 **inode 总数**决定，与磁盘容量无关；
- 「单个文件最大有多长」由 **inode 的索引结构**决定，与 inode 总数无关。

这两句话是 2013 年真题的标准解法。用 RAID 磁盘阵列时，一个文件还可以分散在多块磁盘上，所以「文件必须放在一块盘上」也是错的。
:::

### 文件的属性与分类

常见属性包括：名称、标识符、类型、位置（指向设备和设备上文件的指针）、大小、保护（访问权限）、创建者/所有者 ID、创建与最近修改时间、链接计数等。

按不同角度分类：

| 分类角度 | 类别 |
|---|---|
| 性质和用途 | 系统文件、用户文件、库文件 |
| 数据形式 | 源文件（`.c`、`.java`）、目标文件（编译后的二进制）、可执行文件 |
| 存取控制 | 只读文件、读写文件、可执行文件 |
| 组织形式 | 普通文件、目录文件、索引文件、特殊文件（设备文件、命名管道等） |

## 文件元数据和索引节点

### 文件控制块 FCB

为了能对一个文件进行正确的存取，文件系统必须为文件设置一个描述与控制用的数据结构，称为**文件控制块（File Control Block, FCB）**。**文件与 FCB 一一对应**，FCB 的有序集合称为**文件目录**，其中的每一个 FCB 就是一个**目录项（directory entry）**。目录本身也被视为一种文件，称为**目录文件**。

FCB 通常包含三类信息：

| 类别 | 典型内容 |
|---|---|
| 基本信息 | 文件名、物理位置、逻辑结构、物理结构、文件类型、文件大小 |
| 存取控制信息 | 文件存取权限（文件主、核准用户、一般用户各自的读/写/执行权限） |
| 使用信息 | 文件数据块指针、文件建立时间、上次修改时间、当前使用计数 |

:::key FCB 的作用
**FCB 建立了文件名与文件物理位置之间的映射**，这正是「按名存取」得以实现的根本原因。用户给出文件名，文件系统查目录找到对应的 FCB，从中取出物理地址，再去访问外存。

因此可以记住两个等式：

$$文件目录大小 = FCB 大小 \times 目录项个数$$

$$一个 FCB = 一个文件目录项$$
:::

### 索引节点 inode 与目录项的分离

**为什么要把 FCB 拆开？** 检索目录时，其实只需要用到「文件名」这一个字段：只有文件名匹配成功了，才需要读出文件的其他信息。若每个目录项都是完整的 FCB，目录文件会占据大量盘块，平均检索时间随之飙升。

于是有了**索引节点（index node，简称 i 节点、inode）**方案：把 FCB 中**除文件名以外的所有信息**抽出来，构成一个独立的数据结构 inode；目录项则「瘦身」为 **文件名 + inode 编号（指针）** 两项。

:::key 一个必背的量化例子
设一个 FCB 占 64B，磁盘块大小 1KB，则每块只能放 $1024/64 = 16$ 个 FCB。若目录共有 640 个目录项，则目录文件占 $640/16 = 40$ 个盘块，按文件名检索平均需要比较 $640/2 = 320$ 个目录项，即**平均启动磁盘 20 次**（每次读入一块）。

改用索引节点后，设「文件名 14B + inode 指针 2B」共 16B，则每块可放 $1024/16 = 64$ 个目录项，检索平均只需读入 $320/64 = 5$ 个盘块。

**磁盘 I/O 次数从 20 次降到 5 次**，这就是索引节点机制的价值。
:::

引入 inode 后，目录项与 inode 的关系是：

- **目录项**只记录「文件名 → inode 编号」这一条逻辑映射，它描述的是文件在**文件系统中**的位置（逻辑位置）。
- **inode**记录文件的元数据，其中包括文件在**存储设备上**的物理位置（直接/间接索引），描述的是文件数据实际存放在哪里。

:::warn 区分「磁盘索引节点」与「内存索引节点」
**磁盘索引节点**存放在磁盘的 inode 区，是静态的，主要内容有：文件主标识符、文件类型、文件存取权限、**文件物理地址**（直接与间接索引项）、文件长度、**文件链接计数 count**、文件存取时间。

**内存索引节点**是文件被打开时从磁盘复制（调入）到内存的，除上述内容外还要增加：

- **inode 编号**：标识对应外存 inode 的编号；
- **状态位**：是否被上锁、是否被修改（修改位置位决定关闭时是否需要写回外存）；
- **访问计数**：记录当前有多少个进程打开了该文件；
- **逻辑设备号**：标识 inode 所在的逻辑设备（分区）；
- **链接指针**：分别指向内存空闲链表和散列队列的指针，用于加速查找。

**内存 inode 可以被多个进程共享**，这正是「多个进程打开同一文件时系统打开文件表只有一个表项」的底层原因。
:::

### inode 中的多级索引与最大文件大小计算

UNIX/Linux 混合索引的经典结构是 inode 中设 **13 个地址项** `iaddr[0] ~ iaddr[12]`：

| 地址项 | 类型 | 作用 |
|---|---|---|
| `iaddr[0] ~ iaddr[9]` | 直接地址（10 项） | 直接指向数据块 |
| `iaddr[10]` | 一级间接地址（1 项） | 指向一个索引块，索引块里放数据块号 |
| `iaddr[11]` | 二级间接地址（1 项） | 指向索引块，其中每项再指向一个索引块 |
| `iaddr[12]` | 三级间接地址（1 项） | 三级「套娃」索引 |

:::key 通用解题模板
记：磁盘块（数据块与索引块同大小）大小 $B$，一个地址项占 $p$ 字节，则

$$一个索引块可容纳的地址项数\ n = \left\lfloor \frac{B}{p} \right\rfloor$$

设第 $k$ 级间接地址项个数为 $N_k$（直接地址视为 0 级，$k=0$），则第 $k$ 级可覆盖的数据量为

$$S_k = N_k \times n^k \times B \qquad (k = 0,1,2,3,\dots)$$

单个文件最大长度（即可寻址的数据总量）为

$$S_{max} = \sum_{k} N_k \cdot n^k \cdot B$$

注意：**索引块本身只存放地址，不计入文件的数据长度**。这是「文件最大长度」类题目最容易被扣分的地方。
:::

**完整算例（UNIX 经典参数）。** 设磁盘块大小 $B = 4\text{KB}$，每个地址项 $p = 4\text{B}$，直接地址 10 个、一级/二级/三级间接各 1 个。

- 一个索引块能放的地址项数：$n = 4096\text{B} / 4\text{B} = 1024$ 个。
- 直接地址：$10 \times 4\text{KB} = 40\text{KB}$。
- 一级间接：$1 \times 1024 \times 4\text{KB} = 4\text{MB}$。
- 二级间接：$1 \times 1024^2 \times 4\text{KB} = 4\text{GB}$。
- 三级间接：$1 \times 1024^3 \times 4\text{KB} = 4\text{TB}$。

$$S_{max} = 4\text{TB} + 4\text{GB} + 4\text{MB} + 40\text{KB}$$

**第二组算例（更常考的参数）。** 设 $B = 1\text{KB}$，$p = 4\text{B}$，直接 10 项，一/二/三级间接各 1 项：

- $n = 1024/4 = 256$；
- 直接：$10 \times 1\text{KB} = 10\text{KB}$；一级间接：$256 \times 1\text{KB} = 256\text{KB}$；二级间接：$256^2 \times 1\text{KB} = 64\text{MB}$；三级间接：$256^3 \times 1\text{KB} = 16\text{GB}$。
- 最大文件长度 $= 16\text{GB} + 64\text{MB} + 256\text{KB} + 10\text{KB}$。

**逻辑块所在区间与访问磁盘次数的关系（inode 已在内存）**：以上参数下，逻辑块号（从 0 开始）与访问磁盘块数的对应关系是

| 逻辑块号范围 | 所属区域 | 需要读的磁盘块数 |
|---|---|---|
| 0 ~ 9 | 直接地址 | 1（只读目标数据块） |
| 10 ~ 265 | 一级间接 | 2（索引块 + 数据块） |
| 266 ~ 65801 | 二级间接 | 3（二级索引块 + 一级索引块 + 数据块） |
| 65802 及以上 | 三级间接 | 4（三级 + 二级 + 一级索引块 + 数据块） |

其中二级间接起始块号 $= 10 + 256 = 266$，二级间接可覆盖 $256^2 = 65536$ 块，故其末块号 $= 266 + 65536 - 1 = 65801$。

**第三个算例（对应真题的偏移量定位思路）。** 设 $B=1\text{KB}$、$p=4\text{B}$、直接 10 项、一/二级间接各 1 项，inode 已在内存。求偏移量 1234 与 307400 处所在磁盘块各需访问几个磁盘块。

- 偏移量 1234：$\lfloor 1234/1024 \rfloor = 1$，即第 1 号逻辑块，落在直接地址区，**只需读 1 个磁盘块**。
- 偏移量 307400：$\lfloor 307400/1024 \rfloor = 300$，直接区覆盖 0~9，一级间接覆盖 $10 \sim 10+256-1 = 265$，300 落在二级间接区，**需要读二级索引块、一级索引块、目标数据块共 3 个磁盘块**。

:::warn 计算时最容易错的三处
1. **块号从 0 还是从 1 开始**。题目说「第 3 个逻辑块（块号从 1 开始）」时，要先减 1 再判断落在哪个区。统考题目一般会明确说明起始编号，没说明时按题目中已出现的例子推断，不要凭习惯。
2. **索引块不计入文件数据长度**。求「单个文件最大长度」只累加数据块；求「占用几个索引块」才去数索引块。
3. **把「地址项个数」当成「索引块个数」**。一个一级间接地址项对应**一个**索引块，但这个索引块里装的是 $n$ 个数据块地址。
:::

### inode 位图与数据块位图

磁盘上需要记录两种「哪些编号还能用」的信息，UNIX 风格的文件系统用两张位图分开管理：

- **inode 位图（inode bitmap）**：每一位对应 inode 区中的一个 inode，标记它是否已被分配。创建一个文件时先查 inode 位图找一个空闲 inode。
- **数据块位图（block bitmap）**：每一位对应数据区中的一个磁盘块，标记它是否已被分配。为文件分配数据块时查它。

两张位图都存放在磁盘的固定位置，并在使用时**按需把相关块读入内存**修改，再在适当时机写回。因为一位只表示一个对象，位图**占用空间极小、可常驻内存**，是「0 表示空闲、1 表示已分配」的常用约定（注意不同教材符号可能相反，做题以题目给的约定为准）。

:::key inode 编号到磁盘块的换算
设磁盘块大小 $B$，一个 inode 占 $s$ 字节，inode 区起始块号为 $b_0$，则每个盘块可容纳的 inode 数

$$m = \left\lfloor \frac{B}{s} \right\rfloor$$

inode 编号为 $k$（从 0 开始编号）的 inode，位于

$$盘块号 = b_0 + \left\lfloor \frac{k}{m} \right\rfloor, \qquad 块内偏移 = k \bmod m$$

**算例**：$B=4\text{KB}$，$s=16\text{B}$，inode 区起始块号 6，则 $m = 4096/16 = 256$。编号 1314 的 inode：$\lfloor 1314/256 \rfloor = 5$，$1314 \bmod 256 = 34$，所以它位于 $6+5=11$ 号磁盘块，是该盘块中的第 34 个 inode。

**追问：需要只把这一个 inode 读入内存吗？** 不行。磁盘 I/O 以「块」为最小单位，无法只读块内某一部分，所以必须**把整个 11 号块读入内存**，再从中取用第 34 个 inode。这也是内存 inode 缓存存在的理由——同一块中其他 inode 后续被访问时可直接命中缓存。
:::

## 文件的操作

文件的基本操作可以分成两类：**不涉及打开的「目录级操作」（建立、删除）**和**基于打开表的「句柄级操作」（打开、关闭、读、写）**。

### 建立文件

`create(path)` 在指定路径下建立一个空文件，可以同时指定文件类型与访问权限。步骤如下：

1. 查询磁盘的 inode 位图（或 inode 表），为该文件**分配一个空闲 inode**，在其中登记文件类型、访问权限、创建时间等信息；
2. 打开 `path` 所指示的父目录，在目录中**新增一个目录项**，目录项的文件名取自 `path` 的最后一部分（分量名），文件名关联到刚分配的 inode 编号上。

### 删除文件

`delete(path)` 删除指定路径下的目录项；若该文件已无其他链接，还要回收文件实体。步骤如下：

1. 按路径找到目标文件的目录项，进而找到 inode；
2. 根据 inode 中的访问权限判断「删除」操作是否允许（文件保护）；允许则读取其**链接计数**：
   - 若链接计数为 1，说明这是最后一条链接，**释放该文件占用的所有磁盘块**（修改数据块位图），同时**释放磁盘 inode**（修改 inode 位图）；
   - 若链接计数大于 1，则只把它减 1，文件数据保留（其他硬链接仍然有效）；
3. 在文件所在目录中**删除对应的目录项**。

:::warn 删除文件不等于删除目录
2013 年真题考过：用户在删除某文件的过程中，操作系统**不可能**执行的操作是「删除此文件所在的目录」。删除文件只删除该文件自己的目录项，以及在没有剩余链接、没有进程打开它时回收其 inode 和数据块。目录还包含其他文件，绝不能被连带删除。

另外，删除文件也**不必**去删除该文件的「快捷方式」（符号链接）。符号链接是独立的文件对象，系统并不保证它存在，也不能假定它必须同步删除（2021 年真题考点）。
:::

### 打开文件表与文件描述符

`open(path, mode)` 打开名为 `path` 的文件，成功时返回一个整数——**文件描述符（file descriptor, fd）**。

:::key open 返回的到底是什么
**`open` 返回的是「本进程的文件描述符表」中的表项下标，不是文件内容、不是缓冲区指针、也不是文件大小。**

打开的本质是：系统检索到指定文件的目录项后，**把该文件的元数据（inode/FCB）从外存复制到内存**，并在系统打开文件表和进程打开文件表中登记表项，然后把这个表项的索引号作为 fd 返回给用户。

此后的 `read`、`write`、`close` 全部以 fd 为参数，**不再使用文件名**，也就不再做按名查找。所以 2024 年真题问「哪个系统调用的实现中包含文件按名查找功能」，答案是 `open()`。
:::

**两级打开文件表**的层次结构：

| 层次 | 位置 | 内容 | 特点 |
|---|---|---|---|
| 系统级打开文件表 | 内核，全系统一张 | 每个已打开文件的 inode 副本、文件状态、访问权限、打开计数 | **一个文件只对应一个表项**；多个进程打开同一文件时共享它 |
| 进程级打开文件表（文件描述符表） | 内核，每个进程一张，PCB 中记录其起始地址 | fd、**读写指针（文件偏移量）**、访问模式、指向系统表项的指针 | 每个进程一张，各自独立 |

**`open` 的完整处理过程**（进程 P1 首次以只读方式打开 `/root/dir1/c.mp4`）：

1. **路径查找**：根据路径逐级查找目录。若目录缓存未命中，就把目录文件所在盘块读入内存，逐层比较分量名，直到找到目标文件的目录项。这一阶段只用文件名。
2. **定位 inode**：从目录项取出 inode 编号，去系统打开文件表中检索该 inode 是否已在内存：
   - **未命中**：从磁盘把该 inode（所在的整个盘块）载入内核缓冲区；**检查访问权限**，若越权则打开失败；若不越权，在系统级打开文件表中新增一个表项，打开计数置 1，并记录内存 inode 的位置；
   - **命中**：同样检查访问权限，通过后**打开计数 +1**，不重复读盘。
3. **登记进程表**：在进程 P1 的进程打开文件表中新增一个表项，记录对应的系统打开文件表项索引、访问模式和初始读写指针。
4. **返回 fd**：把该进程表项的下标作为 fd 返回给用户进程。

:::key 三条几乎每年都考的结论
1. **一个文件在系统打开文件表中只有一个表项**（无论多少进程打开它）；但每个进程的打开文件表中都会各有一项，且不同进程的 fd 数值可以不同。
2. **读写指针记录在各进程自己的打开文件表中**，所以多个进程读同一个文件时互不干扰、各读各的位置（2017 年真题：f1、f2 是硬链接，两个进程分别打开，读写指针位置**不一定相同**，但它们共享同一个内存索引节点）。
3. **各进程的访问权限可以不同**：进程 P1 以只读打开、进程 P2 以读写打开同一个文件是完全合法的，各自受自己申请的模式约束。
:::

:::warn open 不一定产生磁盘 I/O
若文件已被其他进程打开、其 inode 已在内存，则本次 `open` 只需在系统打开文件表中把打开计数 +1，并新建一个进程表项，**不需要读磁盘**。因此「open 必然引起文件 I/O」是错的。
:::

### 关闭文件

`close(fd)` 成功返回 0，失败返回 −1。步骤：

1. 根据 fd 找到**进程打开文件表中对应的表项并删除**；
2. 把**系统打开文件表中该表项的打开计数 −1**：
   - 若减后不为 0，说明还有其他进程在使用，直接返回；
   - 若减后为 0，删除该系统表项；若该内存 inode 被修改过，则按操作系统策略**写回外存**（若未修改则直接释放内存 inode）。

**关闭不等于删除。** 关闭只做「把内存中的控制信息同步回外存、释放内存中的打开表项」，它**不会**删除目录项、**不会**释放外存 inode、**也不会**修改磁盘 inode 中的链接计数（2023 年真题：文件 F 仅被进程 P 打开，P 关闭 F 时系统需要完成的是「释放 F 的索引节点所占的内存空间」）。

### 读文件与写文件

`read(fd, buf, count)` 从文件描述符对应的文件中读数据到用户缓冲区，返回实际读到的字节数。处理过程：

1. 用户程序在用户态调用 `read`，通过陷入（trap）进入内核态；
2. 根据 fd 查进程打开文件表，**按访问模式判断是否允许读**；
3. 允许则经系统打开文件表找到内存 inode，依据**读写指针位置 + count** 确定要读的逻辑块区间，再由 inode 中的索引信息把逻辑块号映射为物理块号，把这些盘块读入**内核缓冲区**；
4. 从内核缓冲区把所需那部分数据复制到用户空间 `buf`；
5. 返回实际读取的字节数，并相应推进读写指针。

`write(fd, buf, count)` 的处理过程与之对称：

1. 陷入内核；2. 按 fd 检查是否允许写（只读打开时会失败）；3. 由读写指针和 inode 定位目标盘块的物理位置，先把该盘块**读入内核缓冲区**，用 `buf` 中的数据覆盖缓冲区中的指定区域，**再把该盘块写回磁盘**；4. 返回实际写入的字节数。

:::warn 为什么读/写都要经过内核缓冲区
磁盘是块设备，读写最小单位是**块**；而内存可以按字节随机访问。用户想改一个字节，也必须先把该字节所在的整块读出来、在内存里改、再整块写回。

另外，中断服务程序是在**当时占用 CPU 的那个进程的地址空间**中执行的，它无法直接把数据写进另一个进程的用户空间，所以必须用「映射到每个进程内核空间」的内核缓冲区作为中转。做题时若问「能否直接把数据从磁盘读到用户空间」，答案是不能（除非使用特殊的直接 I/O 机制）。
:::

:::exam 本知识点的统考考法
- **2012-28**：`read` 系统调用的参数包含文件描述符而**不包含文件名**；数据不在内存时进程进入睡眠等待；系统调用导致用户态 → 核心态切换。
- **2014-29**：文件**首次**被打开的过程中，操作系统做的是「将文件控制块读到内存中」，而**不是**把文件内容读入内存。
- **2020-23 / 2017-31 / 2023-31**：系统打开文件表只有一项、进程表各自一份、关闭只减计数。
- **2024-29**：只有 `open()` 包含按名查找。
- **大题**常以「参数已读入内存，访问第 i 个逻辑块需要几次磁盘 I/O」的形式出现，答法见后文物理结构一节。
:::

## 文件的保护

文件保护解决的是**谁能以什么方式访问文件**的问题。首先要区分两类机制：**口令保护与加密保护**是为了防止文件被他人**存取或窃取**；**访问控制**是为了控制用户对文件的**访问方式**。

### 可控制的访问类型

- **读**：从文件中读数据；
- **写**：向文件中写数据；
- **执行**：把文件装入内存并执行；
- **添加（append）**：在文件末尾追加新信息；
- **删除**：删除文件，释放空间；
- **列表清单**：列出文件名和文件属性。

重命名、复制、编辑等高层功能可以由系统程序调用底层系统调用来实现，因此保护只需在底层提供。例如复制文件可以由一系列读请求完成，所以具有读权限的用户同时也就具有了复制、打印权限。

:::warn 写模式与添加模式的区别
以**写模式**打开文件时会**立即把文件截断为 0 字节**，原有内容永久丢失，即使之后一个字节都没写；以**添加模式**打开则保留原有内容，读写指针初始位置在文件末尾，新数据自动追加。
:::

### 访问控制矩阵与访问控制列表

- **访问控制矩阵（Access Control Matrix）**：行是用户、列是文件，矩阵元素表示该用户对该文件的访问权限。优点是用户与文件权限的对应关系记录得非常清晰；缺点是**占用存储空间太多**，且它只起记录权限的作用，无法保证文件系统本身不受损。
- **访问控制列表（Access Control List, ACL）**：在**每个文件和目录的 FCB（或 inode）**中增加一张表，记录各个用户可以对该文件执行哪些操作。这是把访问控制矩阵「按列压缩」得到的稀疏表示。
  - 优点：灵活，可实现复杂的访问方式；
  - 缺点：ACL 的长度**无法预计**，可能导致复杂的空间管理。

为了控制 ACL 的规模，引入了**精简的访问列表**：以「组」为单位标记各类用户可以执行哪些操作。典型的三类用户是：

| 用户类别 | 含义 |
|---|---|
| 拥有者（owner） | 创建该文件的用户 |
| 组（group） | 一组需要共享该文件且具有类似访问需求的用户 |
| 其他（other） | 系统内的其他用户 |

当某用户请求访问文件时，系统检查该用户所属类别是否有相应权限。系统需要管理分组信息，并把**文件主名、所属组名**存放在该文件的 FCB 中。

:::warn 权限位不能用「每类用户 2 位」表示
2017 年真题考过：4 类用户 × 5 种访问权限，若用二进制位串表示权限，**至少需要 $4 \times 5 = 20$ 位**。

原因是：**一个用户对同一个文件可以同时拥有多种权限**（既能读又能写又能执行），所以必须为「每一类用户的每一种权限」各留一个二进制位。把权限压缩成 2 位、认为一种用户只能选一种权限，是典型错误。
:::

### 传统的权限位 rwx

UNIX 风格文件系统用 9 个二进制位表示权限，分成三组，分别对应 **文件主（u）**、**同组用户（g）**、**其他用户（o）**：

| 位 | 含义（普通文件） | 含义（目录） |
|---|---|---|
| `r` 读 | 可以读取文件内容 | 可以列出目录中的文件名 |
| `w` 写 | 可以修改文件内容 | 可以在目录中创建、删除、重命名文件 |
| `x` 执行 | 可以把文件装入内存并执行 | 可以进入该目录（作为路径分量被解析） |

用 `ls -l` 看到的 `-rwxr-xr--` 就是从高到低依次描述 u、g、o 三组权限。

:::key 访问权限 = 用户访问权限 ∩ 文件属性
文件访问控制由**用户访问权限**和**文件属性**共同决定，而不是由用户优先级决定。用户打开文件时申请的权限**不能超过文件允许的权限**；打开成功后，用户对文件的操作**不能超过自己打开时申请的权限**。这两条构成了访问控制的两道关卡。
:::

### 口令保护与加密保护

- **口令（password）保护**：为文件建立 FCB 的同时附上一个口令，并告知允许共享的其他用户；用户请求访问时须提供口令，系统与 FCB 中存储的口令比对。
  - 优点：保存口令的空间开销小，验证口令的时间开销也很小；
  - 缺点：**正确的口令就存放在系统内部**，不够安全。
- **加密（cryptography）保护**：用某个「密码」对文件内容本身进行加密，访问文件时须提供正确的密码才能正确解密。
  - 优点：**保密性强**，不需要在系统中存储密码；
  - 缺点：编码/译码（加密/解密）需要花费一定时间，且对文件的控制不如系统实现的访问控制灵活。

:::warn 目录也要保护
对多级目录结构来说，不仅要保护单个文件，还要保护子目录内的文件，即需要**目录保护机制**。目录操作（搜索、创建、删除目录项）与文件操作不同，因此需要不同的保护机制。
:::

## 文件的逻辑结构

**文件的逻辑结构**是**从用户观点出发**看到的文件组织形式，即文件内部这些逻辑记录是如何被组织起来构成逻辑文件的，它**独立于文件的物理特性**，用户看不见物理存放在哪。

对逻辑结构的基本要求：有利于提高检索速度、方便增删改查、降低存储费用（尽量不要求大片连续存储空间）。

### 无结构文件与有结构文件

- **无结构文件（流式文件）**：文件内部是一系列二进制流或字符流，以字节为单位组织，如 `.txt` 文件。访问时只能通过读写指针穷举搜索。适用于源程序、可执行文件、库函数等。UNIX 系统中绝大多数文件都是流式文件。
- **有结构文件（记录式文件）**：由一组相似的记录组成，每条记录由若干数据项组成，通常有一个数据项作为**关键字**。按记录长度是否相等分为：
  - **定长记录**：检索速度快，第 $i$ 条记录的地址可直接算出，便于处理和修改，广泛用于数据处理；
  - **变长记录**：检索只能顺序进行，速度慢，也不便于处理修改，但能节省空间。

:::key 顺序文件的随机存取条件
$$\text{第 } i \text{ 条记录首地址} = i \times L \quad (i \text{ 从 } 0 \text{ 起}, L \text{ 为定长记录长度})$$

只有当「**定长记录 + 物理上顺序存储**」同时成立时，顺序文件才支持随机存取；再保证记录按关键字排序（顺序结构），才支持折半查找等快速检索。**变长记录无论怎么存，都无法随机存取**；物理上是链式存储时，也无法随机存取。
:::

### 顺序文件

记录一个接一个顺序排列，记录可定长也可变长，物理上可顺序存储或链式存储。按记录顺序与关键字的关系分为：

- **串结构**：记录顺序**与关键字无关**，通常按存入时间决定顺序。检索某记录必须从头顺序查找，较费时。
- **顺序结构**：记录**按关键字顺序排列**。定长时可折半查找，检索效率显著提高。

**适用场合**：对单条记录的增删改查困难、性能差，因此适合**批量**操作（例如磁带这类顺序存储设备上每次读写一大批数据时，顺序文件的存取效率最高）。

### 索引文件

变长记录文件要找到第 $i$ 条记录必须先顺序读前 $i-1$ 条，为了解决这个矛盾，为**主文件的每条记录**在**索引表**中设一个表项，表项内容包括**指向该记录的指针（逻辑起始地址）和记录长度**。

- **索引表本身是定长记录的顺序文件**，所以可以快速定位第 $i$ 个索引项；
- 若索引表中的关键字按顺序排列，还支持按关键字折半查找；
- 每增加/删除一条记录都要修改索引表；
- **可以用不同的数据项建立多张索引表**（如学生信息表可分别按「学号」「姓名」建索引），这就是数据库索引的思想。

**代价**：若每条记录平均只有 8B，而每个索引项占 32B，索引表会比文件内容本身还大数倍，存储空间利用率极低。

### 索引顺序文件

**索引顺序文件**是索引文件与顺序文件思想的结合：为文件建立一张索引表，但**不是每条记录对应一个索引项，而是一组记录对应一个索引项**。每个分组内部就是一个顺序文件（组内不必按关键字排序），索引表与各分组顺序文件（主文件）共同构成索引顺序文件。查找时先在索引表中找组，再在组内顺序找记录。

:::key 索引顺序文件的平均查找次数
设共 $n$ 条记录，平均分成 $i$ 组，每组 $n/i$ 条：

- 纯顺序查找：平均 $\frac{n}{2}$ 次；
- 索引顺序查找：组间平均 $\frac{i}{2}$ 次 + 组内平均 $\frac{n/i}{2}$ 次。

求最优分组，令 $f(i) = \frac{i}{2} + \frac{n}{2i}$ 最小，得 $i = \sqrt{n}$ 时总查找次数约为

$$\frac{\sqrt{n}}{2} + \frac{\sqrt{n}}{2} = \sqrt{n}$$

例如 $n = 10^4$ 时，顺序查找平均 5000 次，索引顺序查找平均约 100 次。
:::

**多级索引顺序文件**：$n = 10^6$ 条记录时，先建低级索引表（每 100 条一组，共 10000 个表项），再对这 10000 个定长表项按每 100 个一组建顶级索引表（共 100 个表项）。

:::key 建 $K$ 级索引的最优分组与平均查找次数
为 $N$ 条记录的文件建 $K$ 级索引，最优分组是每组 $N^{1/(K+1)}$ 条记录，检索一条记录的平均查找次数为

$$\frac{K+1}{2} \cdot N^{\frac{1}{K+1}}$$

例如 $N = 10^6$ 建 2 级索引：最优每组 $10^{6/3} = 100$ 条，平均查找次数 $= \frac{100}{2} \times 3 = 150$ 次。
:::

### 直接文件或散列文件

给定记录的键值，或通过**散列（Hash）函数**转换后的键值，**直接决定记录的物理地址**。

- 优点：存取速度很高，不需要顺序查找，也不需要维护庞大的索引表；
- 缺点：会**引起冲突**（不同关键字的散列函数值相同），需要解决冲突；散列函数设计和空间管理相对复杂。

散列思想同样适合磁盘块的分配与回收：基于 Hash 快速定位空闲物理块，分配效率高；回收时只需标记空闲，后续可快速复用，碎片问题相对不突出。

### 各逻辑结构的查找效率对比

| 逻辑结构 | 记录长度 | 查找方式 | 平均查找次数 | 存储额外开销 |
|---|---|---|---|---|
| 顺序文件（串结构） | 定长/变长 | 从头顺序扫描 | $n/2$ | 无 |
| 顺序文件（顺序结构） | 定长 | 折半查找 | $\log_2 n$ | 无 |
| 索引文件 | 定长/变长 | 查索引表 | 索引表内 $O(1)$~$O(\log n)$，变长索引表内需顺序找 | 每记录一个索引项，开销大 |
| 索引顺序文件 | 定长/变长 | 组间索引 + 组内顺序 | 约 $\sqrt{n}$ | 每组一个索引项，开销较小 |
| 直接/散列文件 | 任意 | 散列函数直接定位 | 接近 $O(1)$ | 需要处理冲突的空间 |

## 文件的物理结构

**文件的物理结构（存储结构）**指系统把文件存放在外存上所形成的存储组织形式，**用户看不见**。它研究两件事：一是**文件的分配方式**（对磁盘非空闲块的管理），二是**文件存储空间管理**（对磁盘空闲块的管理，见后文）。

基础约定：

- 磁盘被划分为一个个**磁盘块（物理块）**，内存与磁盘之间的数据交换以「块」为单位；
- 文件的逻辑地址空间也被划分为一个个**文件块**，因此文件逻辑地址可表示为「**逻辑块号 + 块内地址**」；
- Windows 中称「簇」，UNIX 中称「磁盘块」；**簇是文件的分配单位**，扇区是磁盘上最小的物理单元。

:::key 两类「随机存取」要分清
- **逻辑结构支持随机存取**：能根据记录号直接算出记录对应的**逻辑地址**（逻辑块号 + 块内地址）。
- **物理结构支持随机存取**：能根据**逻辑地址**直接算出记录对应的**物理地址**。

「逻辑上支持随机存取」不等于「物理上支持随机存取」——顺序文件是定长记录且物理顺序存放时两者才同时成立。
:::

### 连续分配

**结构**：每个文件在磁盘上占有一组**连续的块**，逻辑上相邻的块物理上也相邻。

**地址转换**：用户给出逻辑块号，系统找到该文件 FCB 中的**起始块号**，则

$$物理块号 = 起始块号 + 逻辑块号$$

块内地址保持不变。因此 FCB/inode 的物理地址字段只需保存**起始块号 + 总块数**。

**优缺点**：

- 优点：支持顺序访问，也**支持随机（直接）访问**；访问时寻道数与寻道时间最小，顺序存取速度最快；实现简单。
- 缺点：**文件长度不宜动态增加**——文件末尾的盘块可能已分配给其他文件，一旦需要扩展就要大量移动盘块；反复增删后会产生**外部碎片**，存储空间利用率低；记录的插入、删除效率低下。

**最大文件长度**取决于 FCB 中「总块数」字段的位数和盘块大小：$文件最大长度 = 最大块数 \times 块大小$。

:::exam 连续分配的大题套路（插入/删除需要几次磁盘 I/O）
- **访问第 3 个逻辑块**（首块已读入内存、FCB 已在内存）：只需计算物理块号后直接读入，**1 次**。
- **修改某块内容**：读入 1 次 + 写回 1 次，共 **2 次**。
- **删除第 2 块**（file-2）：为减少 I/O，选择把前面较少的块整体后移。若前面只有 file-0、file-1 两块，则需读入 file-1 写入 file-2 位置、读入 file-0 写入 file-1 位置，共 **4 次** I/O；同时要修改 FCB 的**起始块号 +1、总块数 −1**。
- **在第 4 条记录前插入一条记录**（7 条记录、前后都有空闲空间）：把前 3 条记录依次后移（3 次读 + 3 次写 = 6 次），再写入新记录（1 次），共 **7 次** I/O；FCB 的起始块号要 −1，总块数 +1。
:::

### 链接分配

链接分配采用**离散分配**，可以为文件分配离散的磁盘块，分为隐式链接与显式链接。

#### 隐式链接

**结构**：每个盘块（除最后一个）的尾部都有一个**指向下一个盘块的指针**。FCB 中保存**起始块号与结束块号**。

**地址转换**：从起始块号读入 0 号逻辑块，从它的尾部指针知道 1 号逻辑块的物理块号，再读入 1 号块……因此 **访问第 $i$ 号逻辑块（从 0 开始）需要 $i+1$ 次磁盘 I/O**。

**优缺点**：

- 优点：**消除了外部碎片**，提高了磁盘利用率；适合文件长度的动态增长（动态分配块）。
- 缺点：**只支持顺序访问，不支持随机访问**，查找效率低；指向下一块的指针本身要耗费少量存储空间；**可靠性差**——链中任一指针损坏，其后的数据全部丢失。

**最大文件长度**取决于：①一个盘块中用多少位存放链接指针；②盘块大小。例如盘块 1KB、指针占 2B，则每块可链 $\lceil 1024/2 \rceil$ 个关系，理论上限受块号编码位数约束。

**可以引入「簇」**：一个簇 = 若干个连续磁盘块，按簇顺序链接，可减少指针占用、加快查找；代价是增加**内部碎片**，而且分配空间时**必须分配整数个簇**（一个簇 4 块时，即使再要 1 块也必须分配整个簇）。

:::exam 隐式链接的磁盘 I/O 计数（FCB 已在内存）
以 c.mp4 为例，7 个文件块 file-0 ~ file-6：

- 访问第 3 个逻辑块（file-2）：需读入 file-0、file-1 才能拿到 file-2 的块号，再读 file-2，共 **3 次**读盘。
- 修改 file-3 的内容：先读 file-0、file-1、file-2、file-3（4 次），再写回 file-3（1 次），共 **5 次**。
- 删除 file-2：读 file-0、file-1、file-2 拿到 file-3 的地址，修改 file-1 的指针后写回 file-1，共 **4 次**（file-2 的数据块标记为空闲不算磁盘 I/O）。
- 在第 4 条记录前插入：读前 3 块（3 次），把新记录写入空闲块并令其指针指向原第 4 块（1 次写），修改第 3 块的指针并写回（1 次写），共 **5 次**。
:::

#### 显式链接与文件分配表 FAT

**结构**：把所有「指向下一块」的指针从各盘块尾部**抽离出来**，集中存放在内存的一张链接表——**文件分配表（File Allocation Table, FAT）**中。FAT 的第 $i$ 个表项存放「物理块 $i$ 的下一个物理块号」。**文件的第一块（起始块号）作为首地址写入 FCB 的物理地址字段**，后续块通过查 FAT 得到。

:::key FAT 的三个关键性质
1. **一个文件系统只设置一张 FAT**，开机时被读入内存并**常驻内存**。
2. FAT 的各个表项在物理上**连续存储**，且每个表项长度相同，因此「物理块号」字段在表项中是**隐含的**（第 $i$ 项就代表块 $i$）。
3. FAT 用到的数据结构是**静态链表**——用下标代替指针的链表。约定 `-1` 表示文件最后一块，`-2` 表示该块空闲。

因此 **FAT 也可以用于管理空闲磁盘块**（2019 年真题：位图、空闲磁盘块链、FAT 都可以用于管理空闲磁盘块，而**索引节点不行**，索引节点描述的是已存在文件的元数据）。
:::

**地址转换**：从 FCB 取起始块号，若目标逻辑块号 $i > 0$，就在内存中查 FAT 依次得到第 $i$ 块的物理块号。**查 FAT 不需要读磁盘**，因此访问某个逻辑块只需 **1 次访盘**取出记录。

**优缺点**：

- 优点：支持顺序访问，**也支持随机访问**（不必依次访问 0 ~ $i$ 号逻辑块）；块号转换在内存中完成，比隐式链接快很多；不产生外部碎片，文件扩展方便。
- 缺点：FAT 需要占用一定的存储空间，而且**必须是连续空间**。

**FAT 表大小的计算（完整算例）**：

- 磁盘/分区共 $N$ 个盘块，则 FAT 需要 $N$ 个表项；
- 表项位数 $w = \lceil \log_2 N \rceil$（因为要能表示 $N$ 个块号，以及 `-1`、`-2` 等状态，实际实现常向上取整到一个字节的整数倍）；
- FAT 占用空间 $= N \times w$（bit）。

**算例**：某分区 1GB，盘块大小 4KB，则盘块数 $N = 1\text{GB}/4\text{KB} = 2^{30}/2^{12} = 2^{18} = 262144$ 个。表项需 $\lceil \log_2 262144 \rceil = 18$ 位，实际取 3B（或按 24 位）存储，FAT 大小约 $262144 \times 3\text{B} = 768\text{KB}$。

**算例（换一组参数）**：盘块大小 2KB，FAT 每个表项 2B，则表项能表示的块号范围是 $2^{16} = 65536$ 个块，**该文件系统支持的最大文件长度约为 $65536 \times 2\text{KB} = 128\text{MB}$**；若 FAT 表项为 4B，则块号范围 $2^{32}$，最大文件长度约为 $2^{32} \times 2\text{KB} = 8\text{TB}$。这说明**FAT 表项长度直接决定了单个文件的最大长度上限**（也可能受分区容量限制，取二者中较小者）。

:::exam 显式链接（FAT 常驻内存）的磁盘 I/O 计数
同样以 7 个文件块为例，**FAT 已在内存**：

- 访问第 3 个逻辑块：查 FCB 得起始块号，再查内存 FAT 即可定位，**1 次**访盘。
- 修改 file-3：读入 + 写回，**2 次**。
- 删除 file-2：**0 次**——只需修改内存 FAT 中关于该文件的链接关系（把前驱指针指向 file-3），并把 file-2 的表项置为 `-2`（空闲）；由于 FAT 常驻内存，这些修改不需要立即访盘。
- 插入一条记录作为第 4 条：也只需在内存 FAT 中改指针，**0 次**访盘（新数据块本身的写入除外）。
:::

### 索引分配

**实现思想**：打开某个文件时，只需把**该文件**占用的盘块号调入内存即可，完全没必要把整个 FAT 调入内存。于是**为每个文件建立一张索引表**，第 $i$ 个条目指向文件的第 $i$ 个块，表中记录各逻辑块对应的物理块号。存放索引表的盘块称**索引块**，存放文件数据的盘块称**数据块**。

**优缺点**：

- 优点：**支持随机访问**（可直接从索引块中读取想要的盘块号）；**没有外部碎片**问题；文件扩展方便。
- 缺点：由于要为每个文件分配索引块，**增加了存储空间开销**；索引块太大会浪费空间，太小则无法支持大文件；访问文件可能需要多次磁盘 I/O（要先读索引块）。

按索引层次分为三种方案：

- **单级索引（一级索引）**：inode 中放一个索引块地址，指向一个索引块，索引块中依次存放该文件所有数据块号。若 $B=4\text{KB}$、地址项 $4\text{B}$，一个索引块可放 1024 个块号，对应 $1024 \times 4\text{KB} = 4\text{MB}$ 的文件。
- **多级索引**：文件特别大、一个索引块装不下时，用「索引块指向索引块」的方式。一级索引指向的块中，每项再指向一个索引块（二级索引）。$B=4\text{KB}$、$p=4\text{B}$ 时，二级索引最多可管理 $1024 \times 1024$ 个数据块，最大文件 $= 1024^2 \times 4\text{KB} = 4\text{GB}$。
  - 优点的另一半：可以支持更大的文件，加快对大型文件的查找速度；
  - 缺点：**随着索引级数增加，访问磁盘的次数也在变多**。
  - 还有一种**链接索引**方案：把多个索引块用指针链接起来，每个索引块包含指向下一个索引块的指针。
- **混合索引（UNIX 混合索引）**：把直接地址、一级间接、二级间接、三级间接**混在同一个 inode 中**，全面照顾各种大小的文件。小文件用直接地址即可直接从 inode 取盘块号；中型文件用一级间接；大型、超大型文件用二级、三级间接。

:::key 索引分配的最大文件长度通用公式（再强调一次）
$$S_{max} = \sum_k N_k \cdot n^k \cdot B, \qquad n = \left\lfloor \frac{B}{p} \right\rfloor$$

其中 $N_k$ 是第 $k$ 级地址项个数、$B$ 是块大小、$p$ 是地址项大小、$k=0$ 表示直接地址。

以 2010 年真题为例：inode 有 7 个地址项（4 个直接 + 2 个一级间接 + 1 个二级间接），地址项 4B，索引块与数据块均为 256B。则 $n = 256/4 = 64$，

$$S_{max} = 4 \times 256\text{B} + 2 \times 64 \times 256\text{B} + 1 \times 64^2 \times 256\text{B} = 1\text{KB} + 32\text{KB} + 1024\text{KB} = 1057\text{KB}$$

**注意：二级间接里的两个索引层本身占的是索引块，不计入文件数据长度。**
:::

### 三种物理结构的对比

| 对比项 | 连续分配 | 链接分配（隐式） | 链接分配（显式/FAT） | 索引分配 |
|---|---|---|---|---|
| 分配单位 | 一组连续盘块 | 离散盘块 | 离散盘块 | 离散盘块 |
| FCB/inode 需保存 | 起始块号 + 总块数 | 起始块号 + 结束块号 | 起始块号（首块） | 索引块地址（多级） |
| 逻辑地址转换 | `起始 + 逻辑块号` | 沿链逐块读指针 | 查内存 FAT | 查索引块（可能多级） |
| 随机访问 | 支持 | **不支持** | 支持 | 支持 |
| 顺序访问速度 | 最快（寻道最少） | 慢 | 快（FAT 在内存） | 较快 |
| 文件扩展 | **困难**（需大量移动） | 容易 | 容易 | 容易 |
| 外部碎片 | **有** | 无 | 无 | 无 |
| 额外空间开销 | 无 | 每块一个指针 | 一张 FAT（可常驻内存） | 每文件至少一个索引块 |
| 访问第 $i$ 块需读盘（FCB/inode 已在内存） | 1 次 | $i+1$ 次（从 0 开始） | 1 次 | 1 + 间接级数 次 |
| 典型/最佳场景 | 长度基本不变、要求随机读写速度高 | 长度常变、只要求顺序访问 | 长度常变、要求随机读写 | 长度常变、要求随机读写 |

:::key 访问第 $i$ 个逻辑块需要几次磁盘 I/O —— 一份速查表
前提：**FCB / inode 已在内存**（否则还要先读盘装入 inode）。

- **连续分配**：**1 次**（直接算出物理块号）。
- **隐式链接**：**$i+1$ 次**（$i$ 从 0 开始计，必须逐块读指针）。
- **显式链接（FAT 在内存）**：**1 次**。
- **索引分配（单级）**：**2 次**（索引块 + 数据块）。
- **索引分配（混合索引）**：直接区 **1 次**；一级间接 **2 次**；二级间接 **3 次**；三级间接 **4 次**。

若题目说明「FCB 尚未读入内存」，则在上述次数上再加 1 次读 inode/目录项的 I/O。
:::

:::exam 物理结构的统考考法
- **2009-28**：适合随机访问且易于文件扩展的是**索引结构**。连续结构可视为数组——随机访问好但扩展差；链式结构可视为链表——扩展好但随机访问差；索引结构两者兼顾。
- **2013-24**：为支持 CD-ROM 中视频文件的快速随机播放，**连续结构**性能最好（顺序读取介质、连续块寻道最少）。
- **2010-30 / 2015-29 / 2018-31 / 2022 大题**：混合索引的最大文件长度与逻辑块定位。
- **2016 大题**：FAT 相关计算（表项与最大文件长度、I/O 次数）。
- **2013-26**：与单个文件长度**无关**的是「索引接点的总数」（只影响文件个数）。
:::

## 目录的基本概念

**文件目录**是一种数据结构，用于标识系统中的文件及其物理地址，供检索时使用。对目录管理的基本要求是：实现「按名存取」、提高目录检索速度、**允许文件重名**、支持文件共享。

目录与 FCB/inode 的关系有三种表述要保持一致：

- FCB 的**有序集合**称为文件目录，**一个 FCB 就是一个目录项**；
- 引入 inode 后，**目录项 = 文件名 + inode 编号（指针）**，inode 中存放元数据；目录项描述文件在文件系统中的**逻辑位置**，inode 描述文件在存储设备上的**物理位置**；
- 目录本身也是一种文件（**目录文件**），它也有自己的 inode 和数据块，只不过数据块里存的是目录项而不是普通数据。

因此可以记住：**普通文件 = inode + 数据块；目录文件 = inode + 目录块**（目录块中记录了该目录下各文件的名字与 inode 编号）。

常用的目录实现方式：

| 实现方式 | 原理 | 特点 |
|---|---|---|
| 线性列表 | 用数组或链表存放目录项 | 实现简单；数组适合静态目录，链表适合频繁增删；**检索效率低**，需线性扫描 |
| 哈希表 | 用散列函数把文件名映射到索引位置 | 直接按名访问速度快，适合目录项动态变化；容易浪费空间、冲突处理复杂 |
| 键树（Trie） | 按文件名字符逐层建树 | 对大量共享前缀的名字检索极快；实现较复杂，空间需额外优化 |

## 树形目录

### 目录结构演进

- **单级目录结构**：整个系统只有一张目录表，每个文件占一个目录项。实现了按名存取，但**不允许文件重名**，查找速度慢，不适用于多用户系统。
- **两级目录结构**：分为**主文件目录（MFD）**与**用户文件目录（UFD）**。一个文件系统一张 MFD，一个 MFD 表项对应一个用户；每个用户一张 UFD，记录该用户所有文件的 FCB。解决了多用户环境下的重名问题，并提高了检索速度，但**缺乏灵活性，不能对文件分类**。
- **树形（多级）目录结构**：最常用。用户可以创建自己的子目录，形成层次结构。
  - 优点：方便对文件分类，层次清晰，可对不同用户赋予不同存取权限，能有效管理和保护文件；
  - 缺点：需要按路径**逐级访问中间节点**，增加了磁盘访问次数，影响查询速度；**不便于实现文件共享**（这是引入无环图目录结构与链接的原因）。
- **无环图目录结构**：在树形目录基础上增加指向同一节点的有向边，形成有向无环图。可以为不同文件名指向同一文件，甚至指向同一目录。需要为每个共享节点设置**共享计数器 count**，删除时只让计数器减 1，**只有减到 0 才真正删除节点**。
  - 注意：共享文件不同于复制文件——各用户指向的是同一个文件，一个用户修改后其他用户都能看到。

### 绝对路径、相对路径与当前工作目录

- **文件路径名**是由各级目录名与文件名用分隔符（`/`）连接而成的字符串。
- **绝对路径**：从**根目录**出发的路径，例如 `/照片/2015-08/自拍.jpg`。
- **当前工作目录（当前目录）**：由系统为每个进程设置的一个目录，是相对路径的起点。Linux 中用 `.` 表示当前目录，`..` 表示父目录。
- **相对路径**：从当前工作目录出发的路径，例如当前目录是 `/照片` 时，`./2015-08/自拍.jpg`。

设置当前工作目录的**主要作用是加快文件的检索速度**（2010-31 真题），它既不节省外存/内存空间，也不直接提高已定位文件的读写传输速度。

### 路径名解析过程

以绝对路径 `/照片/2015-08/自拍.jpg` 为例：

1. 读入根目录的目录表（目录文件所在盘块）；
2. 在根目录中查找分量名「照片」，得到「照片」目录文件的存放位置（inode 编号），据此读入「照片」目录的目录表——**1 次读盘**；
3. 在「照片」目录中查找「2015-08」，读入该目录的目录表——**1 次读盘**；
4. 在「2015-08」目录中查找「自拍.jpg」，得到该文件的 inode 编号，读出 inode 与数据——**总共约 3 次读盘**。

若把「照片」目录设置为当前工作目录（即把它的目录表留在内存中），用相对路径 `./2015-08/自拍.jpg` 访问，就省去了第 1 ~ 2 步的读盘，**磁盘 I/O 次数减少，访问效率提高**。

:::warn 路径解析中的易错点
1. **每一级中间目录都要读盘**（除非命中目录缓存），所以路径越长，开销越大。这正是引入**目录项缓存（dentry cache）**的原因。
2. **从根目录开始的路径一定是绝对路径**；但相对路径的写法不一定要带 `./`，如 `2015-08/自拍.jpg` 也从当前目录出发。
3. **路径解析的对象是目录项（文件名 → inode 编号），不是 inode 本身**；只有文件名匹配成功后，才需要把 inode 读入内存。
:::

## 目录的操作

统考要求掌握的目录操作：

| 操作 | 说明 |
|---|---|
| 搜索 | 根据文件名搜索目录，找到对应目录项 |
| 创建文件 | 在所属目录中增加一个目录项 |
| 创建目录 | 在树形目录结构中创建新的用户文件目录或子目录 |
| 删除文件 | 在目录中删除相应的目录项 |
| 删除目录 | 两种方式：①**不删除非空目录**——必须先删除目录中所有文件并递归删除所有子目录；②**可删除非空目录**——目录中文件与子目录一并删除 |
| 显示目录 | 列出目录内容（文件名及属性） |
| 修改目录 | 目录项中保存了某些文件属性，属性变化时须修改相应目录项（如重命名） |
| 移动目录 | 需要修改相应的路径名 |
| 链接目录 | 通过链接操作让指定文件具有多个父目录，便于共享（树形目录下每个文件/目录只允许有一个父目录，不适合共享） |

:::warn 重名检查与目录项复用
- 创建文件或目录时，必须**先检查同一目录内是否已有同名文件/目录**，确定不重名后才能建立。不同目录下的文件可以重名，这正是树形目录的优势。
- 删除目录项后，线性列表实现中有三种处理空闲目录项的方法：①把目录项**标记为不再使用**（简单，但搜索需跳过）；②把空闲目录项**加入空闲目录项列表**（便于复用，需额外结构）；③**把目录的最后一个目录项复制到该空位并缩短目录长度**（目录保持紧凑，但涉及数据移动）。
:::

## 硬链接与软链接

文件共享指系统允许多个用户（进程）共享同一份文件，系统中只需保留该共享文件的一份副本。统考只要求两种实现方式：基于索引节点的共享（硬链接）和基于符号链的共享（软链接）。

### 硬链接（Hard Link）

**本质**：多个目录项指向**同一个索引节点**，即多个文件名对应同一份文件数据。UNIX 中用 `ln 原文件 新链接名` 建立。

- **inode 与目录项**：每个链接都是一个正常的目录项（文件名 + inode 编号），所有目录项的 inode 编号相同，指向同一个 inode；**file 数据只有一份**。
- **链接计数 count**：inode 中记录该文件被多少个目录项直接指向。创建文件时 count = 1；每建立一个硬链接，count +1；删除一个目录项，count −1；**只有 count 减到 0 时才真正释放文件数据与 inode**。
- **跨文件系统**：**不能**。inode 编号只在**同一个文件系统内唯一**，每个文件系统有各自的 inode 表，硬链接无法跨越文件系统。
- **指向性**：直接指向 inode，是「同一实体的多个名字」。
- **原文件删除后的行为**：删除其中一个链接不影响其他链接对文件的访问；只要 count 仍大于 0，文件数据就仍可正常读写。因此硬链接不会产生悬空指针。
- **访问开销**：从目录项直接得到 inode，**一次到位，访问速度快**。

:::key count 与「删除」的正确理解
在硬链接下，**每个拥有链接的用户都可以「删除」文件**，但这个删除只是 `count--`；只有当执行 `count--` 之后 **count == 0** 时，系统才真正删除该文件。这就是「硬链接保证原文件被删除后仍能通过其他链接访问数据」的机制。
:::

### 软链接（符号链接，Symbolic Link）

**本质**：创建一个**LINK 类型的新文件**，该文件有**自己独立的 inode 和数据块**，其**文件内容就是目标文件的路径名**。访问这个符号链时，操作系统截获请求，按其中的路径名去查找目标文件，再对它进行操作。相当于 Windows 的快捷方式。UNIX 中用 `ln -s 原文件 新链接名` 建立。

- **inode 与目录项**：软链接是独立文件，有独立的 inode 和至少一个数据块（存放路径名），不与目标文件共享 inode。
- **链接计数**：**建立软链接不改变目标文件的链接计数**；软链接自己的计数为 1，删除软链接不影响目标文件。（若再对该软链接建立硬链接，则按普通文件规则各自加 1。）
- **跨文件系统**：**可以**。因为路径名本质上是一串字符，可以指向任意文件系统、甚至网络上的其他机器。
- **指向性**：指向**路径名**，是「指向名字的另一个名字」，属于间接指向。
- **原文件删除后的行为**：软链接仍然存在，但已成为**无效链接（悬空链接）**，通过它访问会失败；此时可将符号链删除。若文件主删除原文件的同时有另一用户创建了同名路径的新文件，则 LINK 文件仍然「有效」，但访问到的已不是原来那个文件。
- **访问开销**：每次访问都要**按路径名逐级查找目录**，可能多次读盘，开销大；此外每条符号链本身也要占用一个 inode 和磁盘空间。

:::key 硬链接与软链接完整对比
| 对比项 | 硬链接 | 软链接（符号链接） |
|---|---|---|
| 本质 | 多个目录项指向同一个 inode | 一个独立文件，内容是目标文件的路径名 |
| 是否有自己的 inode | **没有**，与目标文件共用 | **有**，独立 inode 与数据块 |
| 目录项内容 | 文件名 + 目标文件的 inode 编号 | 文件名 + 自己的 inode 编号（数据块中存路径） |
| 目标文件的链接计数 | 每建一个硬链接 **+1** | **不变** |
| 能否跨文件系统 | **不能** | **能**，还可跨网络 |
| 指向性 | 直接指向 inode（同一实体） | 间接，指向路径名 |
| 删除原文件后 | 其他链接照常访问；count 归零才真正删除 | 变成悬空链接，访问失败 |
| 谁能删除「共享文件」 | 任一拥有硬链接的用户都可使其 count 减 1 | 只有文件主能删原文件，其他用户只能删自己的 LINK 文件 |
| 访问开销 | 小，直接到 inode | 大，需多次读盘逐级解析路径 |
| 是否产生悬空指针 | 不会 | 会产生（需在访问失败后清理） |
:::

:::exam 链接相关真题
- **2009-31**：F1 计数值为 1，先建软链接 F2、再建硬链接 F3，然后删除 F1。F2 是独立文件，计数恒为 1；F3 与 F1 共享 inode，F1 删除后 count 由 2 减为 1。答案：**F2 与 F3 的引用计数值都是 1**。
- **2017-31**：f1 的硬链接为 f2，两进程分别打开，得 fd1、fd2。则「f1 和 f2 共享同一个内存索引节点」「fd1 和 fd2 分别指向各自的用户打开文件表中的一项」正确；「读写指针位置保持相同」错误——两个独立的 `open` 建立各自的打开文件表项，读写位置互不影响（只有 `fork`/`dup` 共享同一表项时才联动）。
- **2020 相关**：文件共享、打开文件的相关判断。
:::

## 文件系统的全局结构

### 文件系统在外存（磁盘）中的结构

磁盘通常被划分为一个或多个**分区**，每个分区中可以有一个独立的文件系统。整个磁盘与一个分区的典型布局如下：

| 区域 | 位置/内容 | 说明 |
|---|---|---|
| **MBR（主引导记录）** | 磁盘 0 号扇区 | 负责引导计算机；其后紧随**分区表**，记录各分区的起始与结束地址，并标记活动分区 |
| **引导块（boot block）** | 每个分区的第一个块 | MBR 读取活动分区的第一个扇区即引导块，由其中的程序负责加载并启动该分区中的操作系统。**即使该分区没装可启动系统，这一区域也保留**（Windows 中称分区引导扇区） |
| **超级块（super block）** | 分区内固定位置 | **存储文件系统的所有关键信息**，系统启动或首次挂载时被读入内存 |
| **空闲空间管理信息** | 紧随超级块 | 通常以**位示图**或**空闲链表**实现，记录未分配的磁盘块 |
| **inode 区（i 节点表）** | 空闲空间管理信息之后 | 每个文件对应一个 inode，完整描述文件的属性与数据块地址 |
| **根目录** | inode 区之后 | 整个目录树的起点 |
| **数据区（文件和目录）** | 磁盘剩余空间 | 存放所有其他文件与目录的实际数据 |

:::key 超级块的典型字段
超级块是文件系统的核心元数据结构，常见字段包括：

- **校验区**：区分文件系统类型、检测文件系统合法性；
- **inode 区起始块号**、**inode 区总块数**；
- **bitmap 起始块号**、**bitmap 总块数**（若用**两张位图**，则分别对应 **inode 位图**与**数据块位图**）；
- **数据区起始块号**、**数据区总块数**；
- 其他：**磁盘块大小**、**inode 大小**、**根目录的 inode 编号**、空闲块数目及指针、空闲 inode 数目及指针等。

超级块的内容是在**逻辑格式化**（对卷的目录区初始化）时写入的。它坏掉，整个文件系统基本就报废了——所以实际系统中超级块常有多份备份。
:::

:::key 由超级块参数推导文件系统能力（完整算例）
设磁盘块大小 4KB，一个 inode 占 16B，inode 区起始块号为 6、总块数为 16，bitmap 起始块号为 22、总块数为 16。则：

1. **每个盘块可放的 inode 数** $= 4096/16 = 256$ 个；inode 区共 16 块，所以该文件系统**最多可容纳 $256 \times 16 = 4096$ 个文件**。
2. **inode 编号为 1314 的 inode 位置**：$\lfloor 1314/256 \rfloor = 5$，$1314 \bmod 256 = 34$，即位于 $6 + 5 = 11$ 号磁盘块，是该块中的第 34 个 inode。
3. **只读一个 inode 可以吗**：不行，磁盘 I/O 以块为单位，必须把 11 号块整体读入内存，再取其中第 34 个。
4. **数据区最多有多少个磁盘块**：由位图决定。若位图共 16 块、每块 4KB，则位图总位数为 $16 \times 4096 \times 8 = 524288$ 位，故数据区最多可管理 $524288$ 个磁盘块。
:::

### 文件系统在内存中的结构

内存中的结构在**挂载时加载、运行期间更新、卸载时释放**：

| 内存结构 | 内容与作用 |
|---|---|
| **内存中的挂载表（mount table）** | 记录每个已挂载文件系统分区的信息：设备标识、挂载点、文件系统类型、挂载选项等 |
| **目录项缓存（dentry cache）** | 缓存最近访问过的目录内容（目录名与 inode 号的映射），加快路径解析，减少重复读盘 |
| **索引节点缓存（inode cache）** | 缓存最近访问过的 inode，多个进程可共享同一内存 inode |
| **系统级打开文件表** | 每个当前打开的文件一个 FCB/inode 副本，含文件状态、访问权限、读写指针、**打开计数**等全局信息 |
| **进程级打开文件表** | 每个进程一张，含文件描述符、读写指针、访问模式，以及指向系统级打开文件表对应表项的指针；其起始地址记录在进程 PCB 中 |
| **页面高速缓存（Page Cache）** | 缓存文件的具体数据内容，减少磁盘 I/O；配合**延迟写（write-back）**把多次小写合并 |

:::warn 内存结构 ≠ 外存结构
- **外存（磁盘）中**有：MBR/引导块、超级块、空闲空间管理信息（位图/空闲链表）、inode 区、根目录、数据区。
- **内存中**有：挂载表、目录项缓存、inode 缓存、系统/进程打开文件表、页高速缓存。

考纲条目里的「文件系统在外存中的结构」「文件系统在内存中的结构」，问的就是这两组结构不要混淆。
:::

## 外存空闲空间管理方法

先明确两个基本概念：

- **卷（volume）**：文件系统的分区（如 C 卷、D 卷）。它可以是磁盘的一部分，也可以是整个磁盘或 RAID 磁盘阵列。从本质上讲，**卷是逻辑磁盘**，卷中的扇区在物理设备上不必连续。
- **卷的组成**：**目录区** + **文件区**。目录区存放文件目录信息（FCB）和用于磁盘存储空间管理的信息；文件区存放文件数据。对逻辑卷格式化（初始化）的实质就是对卷内目录区进行初始化——建立空闲空间管理表格、超级块等。

### 空闲表法

为所有空闲区建立一张**空闲表**，每个表项记录**空闲区的第一个块号**和**该空闲区的块数**，按磁盘块号顺序排列。这属于**连续分配**的思路。

- **分配**：与内存动态分区分配类似，可采用**首次适应、最佳适应、最坏适应**等算法。系统为新文件分配空间时，顺序检索空闲表各表项，找到第一个大小满足要求的空闲区分配给它，并修改空闲表。
- **回收**：同样类似动态分区回收，需分四种情况处理并**合并相邻的空闲区**：回收区前后都空闲、前后都不空闲、只有前面空闲、只有后面空闲。
- **适用场合**：**仅当空闲区数量较少时**才有效。若存在大量小空闲区，空闲表会变得很大，查询效率很低，因此不适合大型文件系统。适用于建立连续文件。

:::key 外存为什么还用连续分配
内存分配很少采用连续分配，但在外存的一些特殊场景中，连续分配具有较高分配速度、能减少磁盘 I/O 频率与寻道时间：

- 磁盘的**对换区**，为追求换入换出速度采用连续分配；
- 文件系统中，**小文件**采用连续组织方式分配相邻盘块；
- **多媒体文件**（MP3/MP4）为减少寻道时间采用连续组织方式。
:::

### 空闲链表法

把所有空闲盘区拉成一条空闲链，按链中基本元素的不同分为两种。

**空闲盘块链**：以**单个盘块**为单位组成链，每个空闲盘块中存放指向下一个空闲盘块的指针。

- 文件系统中需保存**链头、链尾指针**；
- **分配**：若某文件申请 $K$ 个盘块，从链头开始依次摘下 $K$ 个盘块分配，并修改链头指针；
- **回收**：回收的盘块依次挂到链尾，并修改链尾指针（每个回收块都要先读入内存修改指针再写回，**磁盘 I/O 开销大**）；
- **适用**：适用于**离散分配**的物理结构；
- 优点：单个盘块的分配与回收操作极简单；缺点：为一个文件分配多个盘块需多次访问链表，效率低，且管理粒度细导致空闲盘块链通常很长。
- **最难获得连续的空闲磁盘空间。**

**空闲盘区链**：以**空闲盘区**（一组连续盘块）为单位链接，每个盘区记录**本盘区的盘块数**和**指向下一盘区的指针**。

- **分配**：若申请 $K$ 个盘块，可采用首次适应等算法从链头开始检索，找到满足要求的空闲盘区分配；也可把不同盘区的盘块同时分配给一个文件，分配后可能要修改链指针与盘区大小；
- **回收**：若回收区与某空闲盘区物理相邻则合并，否则作为单独空闲盘区挂到链尾；
- **适用**：既适用于离散分配也适用于连续分配，为一个文件分配多个盘块时效率更高；
- 优点：分配回收效率较高，链较短；缺点：需处理盘区的分割与合并，过程较复杂。
- **最容易获得连续的空闲磁盘空间。**

### 位示图法

**位示图（bitmap）**用二进制的一位表示一个盘块的使用状态。统考沿用的约定是：**「0」表示盘块空闲，「1」表示盘块已分配**。若磁盘块共有 $n$ 个，则位示图至少要有 $n$ 位。

- **分配**：顺序扫描位示图，找到 $K$ 个「0」位（相邻或不相邻皆可），把这些位对应的盘块分配给文件，并把这些位**置 1**。
- **回收**：根据回收的盘块号，把位示图中对应的位**置 0** 即可，不需要像链表那样修改指针，因此回收引起的磁盘 I/O 很少。
- **优点**：查找高效，能快速找到单个或一组相邻的空闲盘块，便于实现连续分配；结构紧凑，占用空间极小，可常驻内存，避免频繁访问磁盘。**占用空间与当前空闲块数量无关**（只要磁盘容量和块大小固定，位图长度就固定）。
- **缺点**：位图大小随磁盘容量增大而增大，更适合小型或中等规模系统。

#### 位示图字号/位号与盘块号的相互换算

设位示图有 $m$ 行、每行 $n$ 位（**$n$ 就是「字号」这一行的位数**，实际系统里常常就是一个机器字长）。**两种编号约定必须分清**：

:::key 从 1 开始编号（王道教材默认约定）
行号 $i$、列号（位号）$j$ 均**从 1 开始**，每行 $n$ 位，则：

$$盘块号\ b = n(i-1) + j$$

反向（由盘块号求行列号）：

$$i = (b-1)\ \text{DIV}\ n + 1, \qquad j = (b-1)\ \text{MOD}\ n + 1$$

其中 DIV 是整除，MOD 是取余。
:::

:::key 从 0 开始编号
行号 $i$、位号 $j$ 均**从 0 开始**，每行 $n$ 位，则：

$$盘块号\ b = i \times n + j$$

反向：

$$i = \left\lfloor \frac{b}{n} \right\rfloor, \qquad j = b \bmod n$$

**做题时先看题目给的编号起点，再选公式。** 统考题目一般会明确写「盘块和块内字节均从 0 开始编号」之类的话。
:::

:::key 算例 1：由盘块号求位示图位置（从 1 开始）
用 8 个字（字长 32 位）组成的位示图管理内存，共 8 行、32 列，行号与列号均从 1 开始，求块号 100 对应的位置。

$$i = (100-1)\ \text{DIV}\ 32 + 1 = 99\ \text{DIV}\ 32 + 1 = 3 + 1 = 4$$

$$j = (100-1)\ \text{MOD}\ 32 + 1 = 99\ \text{MOD}\ 32 + 1 = 3 + 1 = 4$$

即**字号为 4、位号为 4**。
:::

:::key 算例 2：位示图所在盘块与块内字节（从 0 开始）
文件系统用位图法表示磁盘空间分配情况，位图存于磁盘的 **32 ~ 127 号块**中，每个盘块占 1024 字节，**盘块和块内字节均从 0 开始编号**。要释放的盘块号为 **409612**，求位图中要修改的位所在的盘块号和块内字节序号。

第一步，一个位图块能表示的位数：$1024 \times 8 = 8192$ 位。

第二步，位号即盘块号 409612（0 开始编号时直接对应）：

$$409612 \div 8192 = 50 \text{ 余 } 12$$

说明该位位于位图的**第 50 个位图块**（从 0 开始）。

第三步，换算为实际盘块号：位图起始于 32 号块，故

$$32 + 50 = 82$$

第四步，块内偏移 12 位，对应字节号：

$$\left\lfloor \frac{12}{8} \right\rfloor = 1$$

所以应修改 **82 号盘块的第 1 个字节**（该字节中的第 $12 \bmod 8 = 4$ 位，即从高位起的第 5 位，按位序编号约定略有差异，题目只要求到字节序号）。
:::

:::key 算例 3：位示图自身占多大空间
- 容量 10GB 的磁盘分区，簇大小 4KB，用一位标识一个簇是否被分配，则簇数 $= 10 \times 2^{30}/2^{12} = 10 \times 2^{18} = 2621440$ 个，位图大小 $= 2621440/8 = 327680\text{B} = 320\text{KB}$；位图本身也按 4KB 的簇存放，故需 $320\text{KB}/4\text{KB} = \mathbf{80}$ 个簇。
- 页式存储管理中，页大小 4KB、物理内存 16GB，页框数 $= 2^{34}/2^{12} = 2^{22}$，位图大小 $= 2^{22}/8 = 2^{19}\text{B} = \mathbf{512\text{KB}}$。

这两个例子说明：**位图大小 = 被管理对象总数 / 8 字节**。
:::

:::warn 位示图法最常错的两处
1. **位示图中 0 和 1 的含义**。统考约定 0 = 空闲、1 = 已分配；但**内存的位示图（页框分配）在某些教材里相反**。做题时以题目说明为准。
2. **位图的「位」与「字节」「字」的换算**。题目常给「每个盘块 1024 字节」，此时一位图块是 $1024 \times 8 = 8192$ 位，不是 1024 位。
:::

### 成组链接法

空闲表法和空闲链表法都不适用于大型文件系统——管理结构会随磁盘容量增长而过度膨胀。**UNIX 系统**采用**成组链接法**，它融合了两者的思想，有效控制了管理结构的规模。

**基本思想**：把所有空闲盘块划分成若干组（例如每组 100 个盘块）。除最后一组外，**每组的第一个盘块用作索引块**，记录**下一组中所有空闲盘块的块号及其数量**；这些索引块依次链接成一条链。**第一组的空闲盘块信息（块号列表和数量）在文件系统挂载时被预先加载到内存的一个专用栈结构**，称为**空闲盘块号栈**。

**经典例子**：空闲区为 201 ~ 7999 号盘块，每组 100 块，则分组为：第一组 201 ~ 300、第二组 301 ~ 400、……、次末组 7801 ~ 7900、最末组 7901 ~ 7999（最末组只有 99 块）。

- 空闲盘块号栈中，超级块里的结构是：**空闲盘块数 N + 各空闲盘块号**；第一组 201 ~ 300 中，**300 号盘块作为索引块**，记录下一组（301 ~ 400）的块号列表。
- 最末组的块号由前一组的最后一个盘块（7900 号）记录，而该盘块中存放的第一个盘块号为「**0**」，用作整条空闲链的**结束标志**。

:::key 成组链接法的分配过程
1. 从**空闲盘块号栈顶**取出一个盘块号分配给用户，栈指针上移，栈中空闲盘块数减 1；
2. 若栈指针到达栈底（表示当前组已分配完），则需要**读取该栈底盘块号所对应的物理盘块内容**——其中保存的是下一组的空闲盘块号列表；
3. 先把该内容整体**读入空闲盘块号栈**以更新它，再把原栈底所指的盘块（其索引作用已完成）**分配出去**。

以图例说明：系统先依次分配 201 ~ 299 号盘块；当需要分配 300 号盘块时，首先把 300 号盘块的内容（下一组的块号列表）读入空闲盘块号栈，随后把 300 号盘块本身分配给用户。

**关键结论**：**只有当 0 号分组（栈中这一组）的空闲盘块分完，才需要进行一次磁盘 I/O**。
:::

:::key 成组链接法的回收过程
1. 系统把释放的盘块号**压入空闲盘块号栈顶**，栈指针下移，栈中空闲盘块数加 1；
2. 若此时**栈已满**（达到上限，如 100 项），则需要**把当前栈中的全部盘块号写入新回收的这个盘块**，使其成为**新的索引块**；
3. 随后把该盘块号设为**新的栈底**，并把栈中记录的**空闲盘块数重置为 1**。

**关键结论**：**只有当栈满（0 号分组达到上限）时才需要一次磁盘 I/O**。

**两个必背问答**：

- 若 0 号分组中仅剩唯一一个索引块，进行一次空闲盘块分配后：**该索引块的内容被复制到超级块中，然后该索引块被分配给文件使用。**
- 若 0 号分组的盘块数量已达上限，回收一个盘块后：**把新回收的块作为新分组的索引块，并把原 0 号分组（栈）的信息复制过去。**
:::

:::key 成组链接法小结
- 描述空闲空间的数据结构（空闲盘块号栈）以及文件系统的关键信息，都存放在磁盘的**固定位置**；在 UNIX 中这一区域称**超级块**。
- 挂载时把超级块读入内存，并在运行过程中**持续维护内存副本与磁盘副本的一致性**。
- 成组链接法通过「**分组 + 索引 + 链接**」的设计，既避免了长链表的遍历开销，又无须维护完整的空闲表，在可扩展性与性能之间取得了良好平衡。
- 它可以得到连续的空闲磁盘空间，也可得到离散的空闲磁盘空间。
:::

:::warn FAT 也算一种空闲空间管理结构
显式链接中的 **FAT 记录了所有盘块**。若某盘块不属于任何文件，就把它的表项标记为 `-2` 表示空闲；分配时遍历查找值为 `-2` 的表项即可，回收时把表项置回 `-2`。所以 2019 年真题中 FAT 被算作可用于管理空闲磁盘块的数据结构。而**索引节点不是**——它描述的是已存在文件的元数据与数据块地址。
:::

## 虚拟文件系统

### 为什么需要 VFS

现代操作系统通常要支持多种文件系统（ext4、NTFS、FAT 等），它们在磁盘组织方式、元数据格式和操作方法上各不相同。若应用程序为每种文件系统分别编写代码，开发困难且系统可维护性差。

**虚拟文件系统（Virtual File System, VFS）**位于用户程序与具体文件系统之间，是一个**内核软件层**、一个**抽象层**：

- **向上**：提供**统一的文件访问接口**（标准的系统调用 `open`、`read`、`write`、`close` 等），使程序无须关心底层是哪种文件系统、存储在何种设备上；
- **向下**：**兼容并屏蔽**各种不同类型文件系统的差异。

VFS 之所以能衔接各种文件系统，是因为它**定义了所有文件系统都支持的、基本的、概念上的接口和数据结构**。对于任何特定文件系统，都需要一个**映射模块**把它自己的特征转换为 VFS 期望的特征。**一个新的文件系统要在某操作系统上被使用，就必须满足该操作系统 VFS 的规定**：必须实现 VFS 规定的「接口函数集」（打开、读写、关闭等操作的函数），且函数的**参数格式、返回值规则**必须严格符合 VFS 要求。例如 ext4 与 FAT32 的「读文件」实现逻辑完全不同，但输入（文件标识、缓冲区地址、长度）和输出（实际读取字节数）必须统一。

### VFS 的四大对象

VFS 采用**面向对象**的设计思路，用 C 语言的结构体实现「对象」——每个对象包含数据成员和一组**函数指针**。四个主要对象是：

| 对象 | 代表什么 | 关键内容 | 生命周期与存储位置 |
|---|---|---|---|
| **超级块对象（superblock）** | 一个**特定的已挂载文件系统** | 文件系统类型、大小、**所挂载的设备**、操作方法（函数）指针、空闲块数目与索引表、空闲 inode 数目与索引表、封锁标记等 | 内核初始化并注册一个文件系统时在内存分配；**VFS 超级块只存在于内存中**，在文件系统卸载时被自动删除。具体文件系统的超级块（如 ext2 superblock）存放在磁盘上 |
| **索引节点对象（inode / vnode）** | 一个**特定的文件**或目录（物理属性） | 文件字节大小、所有者、读/写/执行权限、时间戳、文件类型、数据块位置 | 具体文件系统的 inode 静态存放于磁盘；使用时**调入内存**并填写 VFS 的索引节点（**vnode**），因此 vnode 也称**动态节点**。同一文件系统内 inode 号唯一 |
| **目录项对象（dentry）** | 路径中的一个**组成部分**（目录名或文件名） | 文件名、指向父/子目录项的指针、指向对应 vnode 的指针 | **不对应磁盘上的固定结构**，是 VFS 在解析路径时**动态生成的内存缓存**，组成逻辑目录树 |
| **文件对象（file）** | 一个**与进程相关的已打开文件** | 当前读/写位置（文件指针）、访问模式、引用计数，指向对应 vnode 与 dentry 的指针，以及 read/write/seek 等操作接口 | 进程调用 `open()` 时创建，调用 `close()` 且引用计数归零时销毁。**同一文件可同时存在多个文件对象**（多个进程各打开一次），但对应的 inode 和 dentry 是唯一的 |

:::key VFS 四个对象的一句话对照
- **超级块**是对一个**文件系统**的描述；
- **索引节点**是对一个文件**物理属性**的描述；
- **目录项**是对一个文件**逻辑属性**的描述；
- **文件对象**是对**当前进程打开的文件**的描述。

另外注意：**普通文件 = inode + 数据块；目录文件 = inode + 目录块**（目录块中记录该目录下各文件的文件名与 inode 编号）。
:::

:::warn vnode 不等于 inode
**vnode 只存在于主存中**，是 VFS 为统一管理各类文件而创建的内存对象；**inode 既会被调入主存，也在外存中存储**（磁盘 inode 是静态的）。两者通过指针关联协同工作：**vnode 提供统一接口，inode 提供实际存储信息**。
:::

### VFS 的工作过程（以 write 为例）

当进程调用 `write(fd, buf, n)` 时：

1. 内核进入 **VFS 层**，执行 `sys_write()`；
2. 根据文件描述符 fd 定位到对应的**文件对象**；
3. 通过文件对象获取其关联的 **vnode**；
4. VFS 利用 vnode 中预置的**写操作函数指针**，调用目标文件系统的具体写方法；
5. 该文件系统把数据写入缓冲区，最终通过设备驱动完成磁盘写入。

因此，对用户程序而言，所有文件操作都通过 VFS 提供的统一接口完成，无须关心底层是 ext4、NTFS 还是其他文件系统。**VFS 本身并不是一种真正的文件系统——它仅存在于内存之中，不占用磁盘空间，随系统启动而建立，随系统关闭而释放。**

:::key VFS 使用的缓存
- **索引节点缓存**：每个目录和文件都由一个 vnode 表示，缓存最近访问过的索引节点，加快访问；
- **目录缓存（dentry cache）**：缓存完整的目录名与其 inode 号之间的映射，加快列出目录与路径解析；
- **页面高速缓存（Page Cache）**：存放文件的具体数据，需要相同数据时直接从内存读取而不访问磁盘。
:::

## 文件系统挂载

如同文件在使用之前必须先打开一样，**文件系统在被进程访问前也必须先安装，也称挂载（Mounting）**。

**挂载的定义**：把一个存储设备（或其分区）上的文件系统「连接」到操作系统目录树中的某个目录上，使其内容可以被访问。用于挂载的那个目录称为**挂载点（mount point）**。

核心要点：

- UNIX/Linux 中**所有文件和设备都组织在一个统一的「目录树」中**，根目录是 `/`；
- 硬盘、U 盘、网络存储上的数据默认**不会自动出现在目录树里**；
- 必须通过挂载操作把设备上的文件系统「嫁接」到目录树的某个挂载点（通常是空目录），才能访问其中的文件；
- **未挂载的设备 = 存在但不可见/不可用**。

### 挂载的过程

1. **识别设备**：如 `/dev/sdb1`（U 盘第一个分区）、`/dev/nvme0n1p2`（SSD 分区）；
2. **识别文件系统类型**：如 ext4、FAT32、NTFS、XFS、Btrfs；
3. **选择挂载点**：一个已存在的空目录，如 `/mnt/usb`、`/media/disk`；
4. **执行挂载命令**：如 `mount /dev/sdb1 /mnt/usb`；
5. **内核注册**：VFS 把该设备的文件系统纳入统一管理，用户即可通过挂载点访问文件。

**不同文件系统挂载时内核做的事不同**：

| 文件系统 | 挂载时内核的动作 |
|---|---|
| **FAT** | ①读取**引导扇区**（位于分区开头，偏移 0），获得每扇区字节数、每簇扇区数、保留扇区数、FAT 表个数、根目录项数或根目录起始簇、总扇区数、FAT 表大小等元数据（作用与 UNIX 超级块类似）；②**把第一份 FAT 表从磁盘整份读取到内存**（因为查 FAT 极其频繁，必须常驻内存）；③读取根目录，填充 dentry 缓存；④完成挂载 |
| **ext4** | ①读取**超级块**；②读取**块组描述符**（ext4 把磁盘划分为多个块组，每组有自己的数据块位图、inode 位图和 inode 表）；③**只读取根目录 `/` 的 inode**（ext4 **不会**把所有 inode 都读入内存，其他文件/目录的 inode 在**被实际访问到时**才按需读入）；④完成挂载 |

挂载完成后的文件访问路径为：

- FAT：路径名 → 目录项 → 获取起始簇号 → 通过内存中的 FAT 表查找后续簇 → 读取数据；
- ext4：路径名 → dentry → inode → 通过 inode 中的块指针（直接/间接/extent）定位数据块 → 读取数据。

:::key 挂载点的选择与语义
- **并不是根目录下任何目录都可以作为挂载点**。挂载操作会**使原有目录中的内容被隐藏**，因此**根目录以及系统原有目录都不要作为挂载点**，否则可能造成系统异常甚至崩溃；**挂载点最好是新建的空目录**。
- 当一个文件系统被挂载到某个目录上时，**在该目录下创建的文件和目录都会被存储在该文件系统中**，而不是原来所在的文件系统。
- **挂载后，访问该目录 = 访问设备上的文件系统**。
- 挂载后原挂载点目录的内容会被「遮盖」，但**不会被删除**；卸载（`umount`）后原内容会重新出现。
- 同一个设备可以被挂载到多个不同的挂载点；但**同一挂载点在同一时刻只能挂载一个设备**。
:::

:::exam 挂载相关考法
- 2025 年统考考查过**虚拟文件系统的原理与特点**（VFS 的抽象层作用、四种对象、vnode 与 inode 的区别）。
- 挂载常与「文件系统在内存中的结构」合并出题：挂载时读入什么（超级块、FAT/块组描述符、根目录 inode），什么留在磁盘（其他 inode、数据块）。
- 卸载（umount）时必须把内存中被修改的超级块等元数据**写回磁盘**（保证一致性），这也是一道常见选择题的选项来源。
:::

## 本章小结表

| 知识点 | 核心结论 |
|---|---|
| 数据项/记录/文件 | 基本数据项 → 组合数据项 → 记录 → 文件，自底向上 |
| FCB | 文件与 FCB 一一对应；FCB = 一个目录项；FCB 有序集合 = 文件目录；实现按名存取 |
| inode | FCB 去掉文件名后的部分；目录项 = 文件名 + inode 编号；节省目录检索的磁盘 I/O |
| 磁盘/内存 inode | 磁盘 inode 静态；内存 inode 增加编号、状态、访问计数、逻辑设备号、链接指针 |
| inode 最大文件长度 | $S_{max} = \sum_k N_k \cdot n^k \cdot B$，$n = \lfloor B/p \rfloor$；索引块不计入数据长度 |
| inode 位图 / 数据块位图 | 分别标记 inode 与数据块是否已分配；0 空闲、1 已分配 |
| 建立文件 | 分配空闲 inode + 在父目录中新增目录项 |
| 删除文件 | 删除目录项；count = 1 时释放数据块与 inode，否则 count−−；**不删除所在目录** |
| 打开文件 | 路径解析 → 载入 inode → 检查权限 → 系统打开文件表（count+1）→ 进程打开文件表 → 返回 fd |
| 关闭文件 | 删进程表项 → 系统表项打开计数 −1 → 为 0 时删除表项并视情况写回 inode |
| 读/写文件 | 经内核缓冲区中转；磁盘按块读写；读写指针在进程打开文件表中 |
| 文件保护 | 访问控制矩阵、ACL（可精简为 拥有者/组/其他）、口令、加密；权限位 rwx |
| 权限位数计算 | $用户类别数 \times 权限种类数$（同类别可同时拥有多种权限） |
| 逻辑结构 | 顺序文件、索引文件、索引顺序文件（约 $\sqrt{n}$ 次查找）、直接/散列文件 |
| 连续分配 | 起始块号 + 总块数；支持随机访问；外部碎片；扩展困难 |
| 隐式链接 | 指针在盘块尾部；只能顺序访问；第 $i$ 块需 $i+1$ 次读盘 |
| 显式链接 FAT | 指针集中在 FAT 且常驻内存；支持随机访问；可用 -2 标记空闲块 |
| 索引分配 | 每文件一张索引表；单级/多级/混合（UNIX 13 个地址项） |
| 目录结构 | 单级（不允许重名）、两级（MFD+UFD）、树形（绝对/相对路径）、无环图（共享计数器） |
| 当前工作目录 | 作用是加快文件检索速度 |
| 硬链接 | 共用 inode、count+1、不能跨文件系统、原文件删除不影响、访问快 |
| 软链接 | 独立 inode、存路径名、不改 count、可跨文件系统、原文件删除后悬空、访问慢 |
| 外存结构 | MBR/分区表、引导块、超级块、空闲空间管理信息（位图）、inode 区、根目录、数据区 |
| 内存结构 | 挂载表、目录项缓存、inode 缓存、系统级打开文件表、进程级打开文件表、页高速缓存 |
| 空闲表法 | 记录起始块号与块数；连续分配；适合空闲区少的场合 |
| 空闲盘块链 | 以单块为单位链接；最难获得连续空间 |
| 空闲盘区链 | 以盘区为单位链接；最容易获得连续空间 |
| 位示图法 | 一位一块；0 空闲 1 已分配；1 起编号 $b = n(i-1)+j$；0 起编号 $b = in+j$ |
| 成组链接法 | UNIX 采用；超级块中的空闲盘块号栈；分组 + 索引 + 链接；只在栈空/栈满时 I/O |
| VFS | 内核抽象层；四对象：超级块、索引节点（vnode）、目录项、文件；vnode 只在内存 |
| 挂载 | 把设备文件系统接到目录树的挂载点；挂载后访问目录即访问该设备；原目录内容被遮盖 |

## 易错清单

:::warn 1. 概念混淆类
- **FCB 与 inode**：FCB 是完整控制块；inode 是 FCB 去掉文件名后的部分。目录项在 FCB 方案中就是 FCB，在 inode 方案中是「文件名 + inode 编号」。
- **目录项与 inode**：目录项描述文件的**逻辑位置**（在文件系统中的位置），inode 描述文件的**物理位置**（在存储设备上的位置）。
- **磁盘 inode 与内存 inode**：内存 inode 多了编号、状态、访问计数、逻辑设备号、链接指针；内存 inode 可被多进程共享。
- **vnode 与 inode**：vnode 只在内存中、是 VFS 的统一封装；inode 磁盘上也有。
- **文件系统在外存/内存中的结构**：位图、超级块、inode 区在外存；挂载表、各类缓存、打开文件表在内存。
:::

:::warn 2. 打开文件表类
- **一个文件在系统打开文件表中只有一个表项**，无论多少进程打开它；每个进程的打开文件表各有一项。
- **读写指针在进程级打开文件表中**（各进程独立）；不同进程的 fd 数值也不相同。
- **open 不一定读盘**：若 inode 已在内存，只需打开计数 +1 并新建进程表项。
- **关闭 ≠ 删除**：关闭不删除目录项、不释放外存 inode、不修改磁盘 inode 的链接计数。
- **删除文件不删除所在目录**，也不必删除该文件的快捷方式/符号链接。
- **open 返回的是文件描述符（进程打开文件表下标）**，不是文件内容、不是缓冲区指针。
:::

:::warn 3. 计算类
- **inode 最大文件长度**：$n=\lfloor B/p\rfloor$，逐级算 $N_k n^k B$ 再求和；**索引块不计入文件数据长度**；题目可能既有「数据块大小」又有「索引块大小」，一般二者相同，若不同要分别代入。
- **访问第 $i$ 块需要几次读盘**：连续 1 次、隐式链接 $i+1$ 次、显式链接 1 次、单级索引 2 次、混合索引按所在区 1/2/3/4 次；前提是 inode 已在内存，否则各加 1。
- **位示图换算**：先确认编号从 0 还是从 1 开始；一位图块的位数 = 块字节数 × 8；位图大小 = 被管理对象数 / 8 字节。
- **FAT 表大小**：表项数 = 盘块数 = 容量/块大小；表项位数 $= \lceil \log_2 盘块数 \rceil$；FAT 空间 = 表项数 × 表项位数。
- **连续分配的插入/删除 I/O 次数**：先判断往哪边移动代价小，读 + 写各算一次。
- **权限位数**：$用户类别数 \times 权限种类数$，不要压缩成「每类用户 2 位」。
- **索引顺序文件平均查找次数**：最优分组 $i = \sqrt{n}$，总次数约 $\sqrt{n}$；多级索引 $(K+1)/2 \cdot N^{1/(K+1)}$。
:::

:::warn 4. 结构与特性判定类
- **随机访问能力**：连续分配支持；隐式链接**不支持**；显式链接（FAT 常驻内存）与索引分配支持。
- **扩展能力**：连续分配差；链接与索引分配好。
- **外部碎片**：连续分配有；链接与索引分配没有。
- **最适合随机读写且易扩展**：索引结构（2009-28）；**CD-ROM 视频快速随机播放最优**：连续结构（2013-24）。
- **哪个与单个文件长度无关**：inode 总数（2013-26，它只决定文件个数）。
- **可用于管理空闲磁盘块的结构**：位图、空闲磁盘块链、空闲盘区链、空闲表、FAT、成组链接法；**inode 不行**。
- **占用空间与当前空闲块数量无关的**：位图法（2024-26）；空闲表、空闲链表、成组链接法都与当前空闲块数量有关。
:::

:::warn 5. 目录与链接类
- **当前工作目录的作用**是加快文件检索速度，不是省内存/省外存/加快读写传输速度。
- **每一级中间目录都要读盘**（除非命中目录缓存），这是路径解析开销的来源。
- **硬链接不能跨文件系统**（inode 号只在文件系统内唯一）；**软链接可以跨文件系统甚至跨网络**。
- **建立硬链接使 count+1；建立软链接不改目标文件的 count**。
- **删除硬链接只是 count−−，count 归零才真正删除**；删除原文件后软链接变悬空。
- **硬链接访问快、软链接访问慢**（需重新按路径逐级查找目录）。
- **树形目录不便于文件共享**，共享要靠无环图目录结构或链接；无环图需要**共享计数器**，计数器归零才删除节点。
:::

:::warn 6. 成组链接法类
- **空闲盘块号栈放在超级块中，挂载时读入内存并常驻**，必须保持内存副本与磁盘副本一致。
- **分配时栈空才需要 I/O**（把栈底盘块中的下一组信息读入栈，再把该盘块分出去）；**回收时栈满才需要 I/O**（把栈中内容写入新回收的盘块，让它成为新索引块）。
- **最末组的结束标志是「0 号盘块」**，表示链的结束。
- 一个分组的第一块用作**索引块**，它记录下一组的块号与数量，**它本身也是空闲块**，最终会被分配出去。
:::
