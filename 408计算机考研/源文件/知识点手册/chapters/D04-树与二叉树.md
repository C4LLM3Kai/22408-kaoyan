## 一、树的基本概念

### （一）树的定义与术语

#### 1. 树的定义

**树（Tree）** 是 $n$（$n\ge 0$）个结点的有限集合。当 $n=0$ 时称为**空树**；当 $n>0$ 时满足：

1. 有且仅有一个特定的结点称为**根（Root）**；
2. 其余结点可分为 $m$（$m>0$）个**互不相交**的有限集合 $T_1,T_2,\cdots,T_m$，其中每个集合本身又是一棵树，称为根的**子树（Subtree）**。

定义本身是递归的，这决定了树上的算法几乎都用递归实现。

从图论角度看，树是**连通无环图**，也是 $n$ 个顶点的极小连通图、极大无环图。因此：

:::key 树的边数与结点数
对含 $n$ 个结点的树，**边数恒为 $n-1$**，即 $e=n-1$。这条结论是后续所有计数性质的出发点。
:::

#### 2. 结点分类

- **根结点**：只有后继没有前驱，非空树中有且仅有一个。
- **叶子结点 / 终端结点**：没有后继，**度为 0**。
- **分支结点 / 非终端结点**：有后继，**度大于 0**。除根之外的 branch 结点也称**内部结点**。

:::warn 易错
「叶子结点」等价于「度为 0 的结点」，但不等于「最后一层的结点」。完全二叉树中最后一层也可能有非叶结点（它还有下一层）；反过来，倒数第二层的结点也可能是叶子。
:::

#### 3. 基本术语（考点密集）

| 术语 | 含义 | 说明 |
|:---|:---|:---|
| 结点的度 | 该结点的孩子个数（子树个数、分支个数） | 叶子结点的度为 0 |
| 树的度 | 树中所有结点度的**最大值** | 度为 $m$ 的树 ⇔ 树中至少有一个结点的度为 $m$ |
| 孩子 / 双亲 | 某结点子树的根 / 对应的上层结点 | 除根外每个结点恰有一个双亲 |
| 兄弟 | 同一双亲的孩子互称兄弟 | 双亲在同一层的结点互称**堂兄弟** |
| 祖先 / 子孙 | 从根到该结点路径上的所有结点 / 以该结点为根的子树中所有结点 | |
| 层次 | 根为第 1 层，根的孩子为第 2 层，依次类推 | |
| 结点的**深度** | 从根到该结点路径上的**结点个数**，即该结点的层次 | 自顶向下累加 |
| 结点的**高度** | 以该结点为根的**子树的高度**（该子树中最长路径上的结点数） | 自底向上累加 |
| 树的高度 / 深度 | 树中结点的**最大层次** | 根的高度 = 树的高度 |
| 有序树 / 无序树 | 各结点的子树从左到右有 / 无次序 | 二叉树是有序树 |
| 森林 | $m$（$m\ge 0$）棵**互不相交**的树的集合 | 树去掉根就变成森林 |
| 路径 | 两结点间所经过的结点序列 | 树中路径**自上向下**，兄弟之间无路径 |
| 路径长度 | 路径上**边的个数** | 不是结点个数 |

:::key 深度与高度的区分与联系
- **深度**从根往下数，**高度**从叶子往上数，同一结点两者可以不等。
- 恒有 $height(v)+depth(v)\le height(T)$，当且仅当 $v$ 位于某条「根到最深叶子」的链上时取等号。
- 若 $p$ 是 $v$ 的双亲，则 $h(p)=\max\{h(\text{所有子结点})\}+1$，故 $h(p)\ge h(v)+1$。
- **树的路径长度**指从根到每个结点的路径长度之和，其最大值等于「树高 $-1$」。它与哈夫曼树的**带权路径长度 WPL** 是两个完全不同的概念，不要混用。
:::

:::exam 真题考法
直接用「深度 / 高度 / 层次」的定义设陷阱：给出某结点的层次，要求最深叶子的层次；或给出一棵树的各度结点数，反求叶子结点数（2010 年统考的经典形式）。此外「路径长度」默认按**边数**计，若题目按结点数计会明确说明。
:::

### （二）树的性质

#### 1. 结点数与度数的关系

设度为 $i$ 的结点数为 $n_i$（$i=0,1,\cdots,m$），$n$ 为结点总数。

:::key 树的第一性质（最常用）
**树中结点总数 = 所有结点的度数之和 + 1。**

$$n=\sum_{i=0}^{m}n_i=\sum_{i=1}^{m} i\cdot n_i+1$$

理由：除根结点外，每个结点**恰好有一条边**连到它的双亲，故边数 $e=n-1$；另一方面每个度为 $i$ 的结点贡献 $i$ 条边，故 $e=\sum\limits_{i=1}^{m} i\cdot n_i$。两者联立即得。
:::

**算叶结点数的标准步骤**：

1. 用非叶结点算出总边数 $e=\sum\limits_{i\ge 1} i\cdot n_i$；
2. 由 $n=e+1$ 得总结点数 $n$；
3. $n_0=n-\sum\limits_{i\ge 1}n_i$。

**例**：某度为 4 的树中，度为 4、3、2、1 的结点数依次为 20、10、1、10，求叶子结点数。

边数 $e=20\times4+10\times3+1\times2+10\times1=80+30+2+10=122$，故 $n=122+1=123$。非叶结点共 $20+10+1+10=41$ 个，所以 $n_0=123-41=82$。

#### 2. 每层最多多少个结点

:::key 度为 $m$ 的树第 $i$ 层最多 $m^{i-1}$ 个结点
第 1 层只有根，$1=m^0$；第 2 层最多 $m$ 个；第 3 层最多 $m^2$ 个……由归纳即得第 $i$ 层最多 $m^{i-1}$ 个结点（$i\ge 1$）。$m$ 叉树同理。
:::

#### 3. 高度为 $h$ 的 $m$ 叉树最多 / 最少多少个结点

:::key 容量与下界
- 高度为 $h$ 的 $m$ 叉树**最多**有 $\dfrac{m^h-1}{m-1}$ 个结点（等比求和 $m^0+m^1+\cdots+m^{h-1}$）。当 $m=2$ 时即 $2^h-1$。
- 高度为 $h$ 的 $m$ 叉树**最少**有 $h$ 个结点（每层只挂 1 个，退化成链）。
- 高度为 $h$、度为 $m$ 的树**最少**有 $h+m-1$ 个结点（前 $h-1$ 层各 1 个，最后一层挂满 $m$ 个孩子）。
:::

#### 4. 具有 $n$ 个结点的 $m$ 叉树的最小高度

:::key 最小高度公式

$$h_{\min}=\left\lceil \log_m\bigl(n(m-1)+1\bigr)\right\rceil$$

**推导**：要让 $n$ 个结点装进尽量矮的树，就应让每层都放满。高度为 $h$ 时最多容纳 $\dfrac{m^h-1}{m-1}$ 个结点，故必须有

$$n\le\frac{m^h-1}{m-1}\;\Longrightarrow\; n(m-1)\le m^h-1\;\Longrightarrow\; m^h\ge n(m-1)+1$$

两边取以 $m$ 为底的对数得 $h\ge\log_m\bigl(n(m-1)+1\bigr)$；$h$ 是整数，取下界即得上式。取 $h_0=\lceil\log_m(n(m-1)+1)\rceil$ 后按层序填满即可达到 $h_0$，故下界可达。
:::

**验证**：$m=3$、$n=244$ 时，$n(m-1)+1=244\times2+1=489$，$\log_3 489\approx 5.65$，取整得 $h_{\min}=6$。（也可直接数：高度 5 的满三叉树最多 $\frac{3^5-1}{2}=121<244$；高度 6 的满三叉树最多 $\frac{3^6-1}{2}=364\ge244$。）

当 $m=2$、$n=1000$ 时，$n(m-1)+1=1001$，$\log_2 1001\approx 9.97$，$h_{\min}=10$。

#### 5. 具有 $n$ 个结点的度为 $m$ 的树的最大高度

:::key 最大高度为 $n-m+1$
除一个结点的度为 $m$ 外，其余 $n-m$ 个结点的度均为 1，这样树能拉得最长：

$$h_{\max}=(n-m)+1=n-m+1$$
:::

#### 6. 度为 $m$ 的树与 $m$ 叉树的区别（高频陷阱）

| 对比项 | 度为 $m$ 的树 | $m$ 叉树 |
|:---|:---|:---|
| 结点度的上限 | 不超过 $m$ | 不超过 $m$ |
| 是否必须有度为 $m$ 的结点 | **必须至少有一个** | 允许所有结点度都 $<m$ |
| 能否为空 | **不能**，至少有 $m+1$ 个结点 | 可以是**空树** |

:::warn 易错
- 「度为 $m$ 的树」是**非空树**，因为「度为 $m$」本身就要求存在一个度为 $m$ 的结点。
- 「$m$ 叉树」可以是空树，所以 $n$ 个结点的 $m$ 叉树高度可以为 0（空树）——但统考一般默认非空，遇到「含 $n$ 个结点」时 $n\ge1$。
- $m$ 叉**树**（有序）与 $m$ 叉**树形**（不考虑左右次序）在计数问题中结果不同。
:::

#### 7. $n$ 个结点能构成多少种不同形态的二叉树 / 树

:::key 卡特兰数

- 含 $n$ 个结点的**不同形态二叉树**数目为第 $n$ 个卡特兰数：

$$b_n=\frac{1}{n+1}C_{2n}^{n}=\frac{(2n)!}{n!(n+1)!}$$

- 含 $n$ 个结点的**不同形态树**（普通有序树）数目为 $t_n=b_{n-1}=\dfrac{1}{n}C_{2n-2}^{\,n-1}$。

**推导（二叉树的递推）**：$n$ 个结点的二叉树可看成「1 个根 + $i$ 个结点的左子树 + $n-i-1$ 个结点的右子树」，于是

$$b_0=1,\qquad b_n=\sum_{i=0}^{n-1}b_i b_{n-i-1}$$

代入得 $b_1=1,\ b_2=2,\ b_3=5,\ b_4=14,\ b_5=42$。

**推导（树的递推）**：任意一棵普通树经「左孩子右兄弟」表示后必对应一棵**根无右子树**的二叉树；而 $n$ 个结点的树去掉根后剩下 $n-1$ 个结点，所以 $t_n=b_{n-1}$。
:::

:::exam 真题考法
「先序序列为 a,b,c,d 的不同二叉树个数」这类题，因为固定先序后每一种树形唯一对应一种填入方式，答案就是**结点数对应的卡特兰数**（$n=4$ 时为 14）。注意区分问的是**二叉树**还是**普通树**，后者要用 $t_n=b_{n-1}$。
:::


## 二、二叉树

### （一）二叉树的定义及其主要特性

#### 1. 定义

**二叉树（Binary Tree）** 是 $n$（$n\ge0$）个结点的有限集合。它或为空树，或由一个根结点及两棵**互不相交**的、分别称为**左子树**和**右子树**的二叉树组成。

:::warn 二叉树 ≠ 度为 2 的有序树
- 二叉树**可以为空**，度为 2 的树不能为空；
- 二叉树的每个结点**至多有两棵子树，且左右次序严格区分**，即使某结点只有一个孩子，这个孩子也**必须明确是左孩子还是右孩子**；
- 度为 2 的有序树中，若某结点只有一个孩子，就不存在「左右次序」问题。

这条差别是「先序 + 后序能否唯一确定二叉树」等问题的根源。
:::

二叉树的 5 种基本形态：空树、只有根、根 + 左子树、根 + 右子树、根 + 左右子树。

#### 2. 几种特殊的二叉树

**满二叉树（Perfect / Full Binary Tree）**：高度为 $h$ 且含 $2^h-1$ 个结点的二叉树，即每一层都填满。按层序从 1 开始编号后，编号 $i$ 的左右孩子为 $2i$、$2i+1$，双亲为 $\lfloor i/2\rfloor$。

**完全二叉树（Complete Binary Tree）**：结点编号与同高度满二叉树的编号**一一对应**（即只允许最下面一层从右往左缺结点）。其特点：

- 只有**最下面两层**可能出现叶子结点；
- **最多只有一个度为 1 的结点**，且该结点只有**左孩子**；
- 按层序从 1 编号后，$i\le\lfloor n/2\rfloor$ 的结点是**分支结点**，$i>\lfloor n/2\rfloor$ 的结点是**叶子结点**。

:::key 满二叉树与完全二叉树的关系
满二叉树一定是完全二叉树；完全二叉树不一定是满二叉树。二者都适合顺序存储。
:::

**二叉排序树 / 二叉搜索树（BST）**：左子树上所有结点关键字 $<$ 根，右子树上所有结点关键字 $>$ 根，左右子树又各是 BST。**中序遍历得到递增有序序列**。（详见 D06 查找章。）

**平衡二叉树（AVL）**：任一结点的左、右子树高度之差的绝对值不超过 1。（详见 D06 查找章。）

**真二叉树 / 严格二叉树 / 正则二叉树**：不存在度为 1 的结点，即结点的度只能是 0 或 2。此时 $n_2=n_0-1$，即内部结点数比叶子结点数少 1。**哈夫曼树一定是真二叉树，但不一定是完全二叉树。**

#### 3. 二叉树的五个重要性质（全部推导）

:::key 性质 1：第 $i$ 层最多 $2^{i-1}$ 个结点
$i=1$ 时只有根，$1=2^{0}$ 个，成立。设第 $i$ 层最多 $2^{i-1}$ 个，则因每个结点至多两个孩子，第 $i+1$ 层最多 $2\cdot2^{i-1}=2^{i}$ 个。由数学归纳法得第 $i$ 层最多 $2^{i-1}$ 个结点（$i\ge1$）。
:::

:::key 性质 2：高度为 $h$ 的二叉树最多 $2^h-1$ 个结点
把各层最大值相加（等比数列）：

$$1+2+4+\cdots+2^{h-1}=\frac{2^h-1}{2-1}=2^h-1$$

恰好达到这个上界的二叉树就是**满二叉树**。反之，高度为 $h$ 的二叉树**至少**有 $h$ 个结点（每层至少 1 个，退化成单链）。
:::

:::key 性质 3：$n_0=n_2+1$
设度为 0、1、2 的结点数分别为 $n_0,n_1,n_2$，则

- 结点总数：$n=n_0+n_1+n_2$；
- 分支（边）总数：由每个度为 $i$ 的结点引出 $i$ 条分支，得 $e=n_1+2n_2$；
- 又因除根外每个结点恰有一条来自双亲的边，$e=n-1$。

于是 $n_1+2n_2=n_0+n_1+n_2-1$，两边消去 $n_1+n_2$ 得

$$n_0=n_2+1$$

**这条性质对任何非空二叉树都成立**，是换算 $n_0$、$n_1$、$n_2$ 的核心。
:::

:::key 性质 4：完全二叉树的编号关系
完全二叉树按层序**从 1 开始**编号为 $1\sim n$，则对编号 $i$ 的结点：

| 关系 | 从下标 1 开始 | 从下标 0 开始 | 存在条件 |
|:---|:---|:---|:---|
| 双亲 | $\lfloor i/2\rfloor$ | $\lfloor (i-1)/2\rfloor$ | 非根结点 |
| 左孩子 | $2i$ | $2i+1$ | $<n$（1 起）/ $\le n-1$（0 起） |
| 右孩子 | $2i+1$ | $2i+2$ | $<n$（1 起）/ $\le n-1$（0 起） |
| 分支结点判据 | $i\le\lfloor n/2\rfloor$ | $i\le\lfloor n/2\rfloor-1$ | —— |
| 叶子结点判据 | $i>\lfloor n/2\rfloor$ | $i>\lfloor n/2\rfloor-1$ | —— |

**推导**：按层序编号时，第 $i$ 层有 $2^{i-1}$ 个结点，其编号区间为 $[2^{i-1},\,2^i-1]$。编号 $j$ 的结点之前共有 $j-1$ 个结点，其中叶子之外的第 $k$ 层（$k\le$ 该结点所在层 $-1$）的结点按「每个分支结点贡献两个孩子」依次编号，逐层推算即得 $j=2i$、$2i+1$、$\lfloor j/2\rfloor=i$ 的对应。$i=\lfloor n/2\rfloor$ 是最后一个有孩子的结点，故 $i>\lfloor n/2\rfloor$ 者必为叶子。

**若数组下标从 0 开始**存储，则编号为 $i$ 的结点：双亲 $\lfloor(i-1)/2\rfloor$，左孩子 $2i+1$，右孩子 $2i+2$。
:::

:::key 性质 5：$n$ 个结点的完全二叉树高度为 $\lceil\log_2(n+1)\rceil$
**推导**：完全二叉树前 $h-1$ 层是满的（共 $2^{h-1}-1$ 个结点），第 $h$ 层至少有 1 个结点，故

$$n_{\min}=(2^{h-1}-1)+1=2^{h-1}$$

当第 $h$ 层也填满时取得最大结点数 $n_{\max}=2^h-1$。因此

$$2^{h-1}\le n\le 2^h-1$$

由左边得 $2^{h-1}\le n<2^h$，取对数 $h-1\le\log_2 n<h$，因 $h-1$ 是整数，故 $h=\lfloor\log_2 n\rfloor+1$。
由右边得 $2^{h-1}<n+1\le 2^h$，取对数 $h-1<\log_2(n+1)\le h$，故 $h=\lceil\log_2(n+1)\rceil$。

**结论**：

$$h=\lfloor\log_2 n\rfloor+1=\lceil\log_2(n+1)\rceil$$

两个式子恒等，考试用哪个都可以。注意这个结论**只对完全二叉树成立**；一般二叉树只知道 $n$ 时，$h_{\max}=n$（单链），$h_{\min}=\lceil\log_2(n+1)\rceil$。
:::

**验证**：$n=768$ 时，$\lfloor\log_2 768\rfloor+1=\lfloor9.58\rfloor+1=9+1=10$，而 $2^9-1=511<768\le1023=2^{10}-1$，一致。

#### 4. 完全二叉树的 $n_0$、$n_1$、$n_2$ 速算

:::key 由 $n$ 直接推出 $n_0,n_1,n_2$
完全二叉树中 $n_1\in\{0,1\}$，结合 $n_0=n_2+1$ 得 $n_0+n_2=2n_2+1$ 必为**奇数**：

- 若 $n=2k$（偶数）：$n_1=1,\ n_0=k,\ n_2=k-1$；
- 若 $n=2k-1$（奇数）：$n_1=0,\ n_0=k,\ n_2=k-1$。

**验证**：$n=768=2\times384$，故 $n_0=384,\ n_1=1,\ n_2=383$，$384=383+1$ 成立。
:::

#### 5. 二叉树的空指针域个数

:::key 二叉链表有 $n+1$ 个空指针域
含 $n$ 个结点的二叉链表共有 $2n$ 个指针域；除根结点外，每个结点**恰好被一个指针指向**，即非空指针数为 $n-1$。故空指针域个数为

$$2n-(n-1)=n+1$$

**这条结论是线索二叉树存在的依据**：用这 $n+1$ 个空域存放前驱 / 后继线索。
:::

:::exam 真题考法
- 由完全二叉树的「第 $k$ 层有 $m$ 个叶结点」求结点总数（2009 年形式）：要让总数最大就把第 $k$ 层剩下的结点都补上两个孩子，算出第 $k+1$ 层最多结点数再相加；要让总数最小就让叶结点尽量靠右。
- 由 $n$ 直接求 $n_0$（2011 年形式）：直接用上面的 $n=2k$ / $n=2k-1$ 结论。
- 「非空完全二叉树所有叶结点同层且非叶结点都有 2 个孩子」（2018 年形式）：这实际是一棵满二叉树，于是 $n=2n_0-1$。
:::

### （二）二叉树的顺序存储结构和链式存储结构

#### 1. 顺序存储结构

用一维数组按**层序**依次存放结点，结点间的父子关系由**下标计算**隐含给出。

:::key 顺序存储的下标约定

**从下标 1 开始**（统考、教材通用）：

- 结点 $i$ 的双亲 $=\lfloor i/2\rfloor$，左孩子 $=2i$，右孩子 $=2i+1$；
- 若 $i>n$ 或该位置为空，则对应孩子不存在。

**从下标 0 开始**（C 语言数组天然形式）：

- 结点 $i$ 的双亲 $=\lfloor (i-1)/2\rfloor$，左孩子 $=2i+1$，右孩子 $=2i+2$。
:::

必须**显式标记空结点**才能唯一表示一棵二叉树：因为层序序列不包含空结点信息，同一个层序序列可能对应多棵不同的二叉树。常用做法是把每个数组元素设计为带 `isEmpty` 标记的结点：

```c
typedef struct TreeNode {
    int data;        // 结点数据元素
    bool isEmpty;    // 该位置是否为空结点
} TreeNode;

// 初始化：全部标记为空
void InitSqBiTree(TreeNode t[], int length) {
    for (int i = 0; i < length; i++)
        t[i].isEmpty = true;
}

// 判断下标为 index 的结点是否为空（下标从 1 开始）
bool isEmpty(TreeNode t[], int length, int index) {
    if (index >= length || index < 1) return true;
    return t[index].isEmpty;
}

// 取下标为 index 的结点的左孩子下标，无则返回 -1
int getLchild(TreeNode t[], int length, int index) {
    int lChild = index * 2;
    if (isEmpty(t, length, lChild)) return -1;
    return lChild;
}

// 取下标为 index 的结点的右孩子下标，无则返回 -1
int getRchild(TreeNode t[], int length, int index) {
    int rChild = index * 2 + 1;
    if (isEmpty(t, length, rChild)) return -1;
    return rChild;
}

// 取下标为 index 的结点的双亲下标，无则返回 -1
int getFather(TreeNode t[], int length, int index) {
    if (index == 1) return -1;              // 根结点无双亲
    int father = index / 2;                 // 整数除法自动向下取整
    if (isEmpty(t, length, father)) return -1;
    return father;
}

// 顺序存储二叉树的先序遍历
void PreOrderSqTree(TreeNode *t, int length, int index) {
    if (isEmpty(t, length, index)) return;
    visitNode(t[index]);
    PreOrderSqTree(t, length, getLchild(t, length, index));
    PreOrderSqTree(t, length, getRchild(t, length, index));
}
```

:::key 顺序存储的优缺点
**优点**：连续内存、缓存友好、不需存指针、支持随机访问（含完全二叉树的 $O(1)$ 找双亲）。

**缺点**：需要连续空间；插入删除代价高；**稀疏时空间浪费严重**。

**关键结论**：顺序存储**只适合完全二叉树（含满二叉树）**——因为空结点只出现在最底层右侧，可省略不存，$n$ 个结点恰好占 $n$ 个单元。一般二叉树最坏情况下，一棵高度为 $h$ 的**单支树**只有 $h$ 个结点，却要占据 $2^h-1$ 个单元。
:::

:::warn 易错：「需要的存储单元数量至少是多少」
题目给定结点数和高度、要求用顺序存储，问最少需要多少单元时：由于树的**形态未知**，必须按**最坏情况**考虑，即最深结点恰好落在编号最大的位置上。此时数组长度由**高度**决定，为 $2^h-1$（从 1 编号）或 $2^h-1$ 个单元（从 0 编号时需能存到下标 $2^h-2$，仍为 $2^h-1$ 个单元）。

例：高度为 5、10 个结点的任意二叉树用顺序存储，最少需要 $2^5-1=31$ 个存储单元（2020 年形式）。**这里的答案是 31，而不是 10 或 15。**
:::

:::warn 易错：从数组反推二叉树是否合法
若给定数组（含 $-1$ 表示空）问「能否表示一棵二叉树」，判据是：**每个非空结点的双亲位置也必须非空**。若某结点下标 $i$ 的值非空，而 $\lfloor(i-1)/2\rfloor$ 或 $\lfloor i/2\rfloor$ 处为空，就出现了「悬空结点」，不合法。

例（从 0 开始编号）：`R[] = {17,20,35,-1,18,45,-1,-1,19,27}` 中下标 8 的结点 19，其双亲下标 $\lfloor(8-1)/2\rfloor=3$，而 `R[3] = -1` 为空，故 19 悬空，该数组不能表示二叉树（2025 年形式）。
:::

#### 2. 链式存储结构

**二叉链表**：数据域 + 左指针 + 右指针。

```c
typedef struct TreeNode {
    int data;                          // 数据域
    struct TreeNode *lchild, *rchild;  // 左、右孩子指针
} TreeNode, *BiTree;
```

**三叉链表**：在二叉链表上增加一个指向双亲的指针，便于找双亲。

```c
typedef struct TreeNode {
    int data;                          // 数据域
    struct TreeNode *lchild, *rchild;  // 左、右孩子指针
    struct TreeNode *parent;           // 双亲指针
} TreeNode, *BiTree;
```

:::key 三种链式结构对比
| 结构 | 域 | 左右指针域中的空域数 | 找双亲 | 全部指针域中的空域数 |
|:---|:---|:---|:---|:---|
| 二叉链表 | data, lchild, rchild | $n+1$ | 需从根遍历 | $n+1$ |
| 三叉链表 | data, lchild, rchild, parent | $n+1$ | $O(1)$ | $2n+1$ |
| 线索链表 | data, lchild, rchild, ltag, rtag | 线索化后为 0 | 中序线索可 $O(1)$ 找前驱后继 | —— |

三叉链表共 $3n$ 个指针域，非空 $n-1$ 个，空 $3n-(n-1)=2n+1$。**注意**：考试若只问「`lchild`、`rchild` 中的空指针」，答案仍是 $n+1$（与二叉链表相同），因为多出来的 `parent` 域不参与计数。
:::

:::exam 真题考法
本考点以「求空指针域个数」「求找双亲的最坏时间」「给出一段找兄弟 / 找堂兄弟的操作问复杂度」等形式出现。**没有双亲指针时，找兄弟必须先从根遍历到双亲**，这是常见的复杂度设陷阱点。
:::

### （三）二叉树的遍历

#### 1. 遍历的定义与四种方式

**遍历**：从根出发，按某种次序**访问**树中所有结点，使每个结点被访问**一次且仅一次**。

以 N 表示根、L 表示左子树、R 表示右子树，「前 / 中 / 后」指的是**根在遍历中的位置**：

| 遍历 | 次序 | 口诀 |
|:---|:---|:---|
| 先序（前序） | N → L → R | 根在最前 |
| 中序 | L → N → R | 根在中间 |
| 后序 | L → R → N | 根在最后 |
| 层次 | 自上而下、自左而右逐层访问 | 用队列 |

前三种属于**深度优先遍历（DFS）**，可用递归或栈实现；层次遍历属于**广度优先遍历（BFS）**，用队列实现。

:::key 四条速记结论
- **先序首个 = 后序末个 = 层次首个 = 根结点**；
- 中序序列中，根左边的全部属于**左子树**，右边全部属于**右子树**；
- 先序 + 中序、后序 + 中序、层次 + 中序均可唯一确定二叉树；**先序 + 后序不行**；
- 一棵二叉树的中序序列唯一，但**不同的二叉树可能有相同的中序序列**（如先序 + 后序的组合）。
:::

#### 2. 递归遍历（三种）

```c
// 先序遍历：根 左 右
void PreOrder(BiTree T) {
    if (T != NULL) {
        visit(T);            // 访问根结点
        PreOrder(T->lchild); // 递归遍历左子树
        PreOrder(T->rchild); // 递归遍历右子树
    }
}

// 中序遍历：左 根 右
void InOrder(BiTree T) {
    if (T != NULL) {
        InOrder(T->lchild);
        visit(T);
        InOrder(T->rchild);
    }
}

// 后序遍历：左 右 根
void PostOrder(BiTree T) {
    if (T != NULL) {
        PostOrder(T->lchild);
        PostOrder(T->rchild);
        visit(T);
    }
}
```

:::key 递归遍历的时空复杂度
- 时间：$O(n)$，每个结点恰好访问一次。
- 空间：$O(h)$，即**递归工作栈的深度**。最好情况（平衡 / 完全二叉树）$h=\lceil\log_2(n+1)\rceil=O(\log_2 n)$；最坏情况（单支链）$h=n=O(n)$。

注意空间复杂度考的是**辅助栈**而非结点本身，故应为 $O(h)$，只有最坏时才写成 $O(n)$。
:::

#### 3. 非递归遍历（栈模拟）

:::key 核心思想
递归调用的本质是「把局部变量、参数、返回地址压入调用栈」。因此用**显式栈**完全可以模拟递归：**递归隐式维护一个栈，迭代显式维护一个栈**，两者等价。

- **先序**：访问与处理顺序一致（都是根），代码最简——出栈即访问，然后把**右孩子先入栈、左孩子后入栈**（保证出栈顺序为「左、右」）。
- **中序**：访问顺序（先到最左下）与处理顺序（根在中间）**不一致**，必须用一个指针 `cur` 负责「访问」、用栈负责「处理」。
- **后序**：最难，因为从左子树返回时**无法判断右子树是否已访问过**，需增加 `pre` 指针记录上一个被访问的结点。
:::

**先序遍历（迭代）**：

```c
void PreOrderIter(BiTree T) {
    if (T == NULL) return;
    BiTree stack[MaxSize];
    int top = -1;
    stack[++top] = T;
    while (top >= 0) {
        BiTree p = stack[top--];   // 出栈即访问
        visit(p);
        if (p->rchild != NULL) stack[++top] = p->rchild; // 右孩子先入栈
        if (p->lchild != NULL) stack[++top] = p->lchild; // 左孩子后入栈
    }
}
```

**中序遍历（迭代）**：

```c
void InOrderIter(BiTree T) {
    BiTree stack[MaxSize];
    int top = -1;
    BiTree cur = T;
    while (cur != NULL || top >= 0) {
        if (cur != NULL) {
            stack[++top] = cur;     // 一路向左，沿途压栈
            cur = cur->lchild;
        } else {
            cur = stack[top--];     // 左子树走完，弹栈处理
            visit(cur);
            cur = cur->rchild;      // 转向右子树
        }
    }
}
```

**后序遍历（迭代，用 `pre` 记录历史）**：

```c
void PostOrderIter(BiTree T) {
    BiTree stack[MaxSize];
    int top = -1;
    BiTree cur = T, pre = NULL;
    while (cur != NULL || top >= 0) {
        while (cur != NULL) {          // 步骤 1：沿左孩子一路入栈
            stack[++top] = cur;
            cur = cur->lchild;
        }
        cur = stack[top--];            // 步骤 2：弹出栈顶，其左子树必已访问完
        // 步骤 3：无右子树，或右子树刚被访问完（pre 指向右孩子），则可访问 cur
        if (cur->rchild == NULL || pre == cur->rchild) {
            visit(cur);
            pre = cur;
            cur = NULL;                // 防止再次进入步骤 1
        } else {
            stack[++top] = cur;        // 右子树未访问，cur 重新入栈
            cur = cur->rchild;         // 先去处理右子树
        }
    }
}
```

**后序遍历的取巧写法**：先按「根 → 右 → 左」的顺序遍历（即把先序代码中左右孩子入栈次序互换），得到「NRL」序列，再把结果**逆序**，即得「LRN」。若不允许用逆序函数，可再设一个辅助栈，访问时压入辅助栈，遍历结束后依次出栈。

:::key 后序非递归遍历的重要性质
在上述后序迭代过程中，**当访问到结点 $p$ 时，栈中恰好是 $p$ 的全部祖先结点，且从栈底到栈顶再加上 $p$ 本身，恰好构成从根到 $p$ 的路径。**

这条性质可用于：求根到某结点的路径、求二叉树的最近公共祖先、求根到叶结点的数字之和。
:::

#### 4. 层次遍历（队列）

```c
void LevelOrder(BiTree T) {
    if (T == NULL) return;
    BiTree Q[MaxSize];
    int front = 0, rear = 0;
    Q[rear++] = T;                 // 根结点入队
    while (front != rear) {
        BiTree p = Q[front++];     // 队头出队
        visit(p);
        if (p->lchild != NULL) Q[rear++] = p->lchild; // 左孩子入队
        if (p->rchild != NULL) Q[rear++] = p->rchild; // 右孩子入队
    }
}
```

若要按层分行输出，可在每轮循环开始时记录 `size = rear - front`，只处理这 `size` 个结点。

:::key 完全二叉树层次遍历的队列规模
完全二叉树做层次遍历时，**辅助队列的最大规模等于叶子结点个数** $=\lceil n/2\rceil$。也就是说，队列容量只要开到叶子结点数就够用。

队列规模在整个遍历过程中是**先增后减、单峰对称**的：从 0 开始逐层上升到达峰值，再逐层回落到 0。峰值出现在最宽的一层（即最后一层）的结点全部入队、而它们尚未出队完毕的时刻。
:::

#### 5. 由遍历序列构造二叉树

:::key 唯一性总表
| 序列组合 | 能否唯一确定 | 原因 |
|:---|:---|:---|
| 先序 + 中序 | **能** | 先序定根，中序分左右 |
| 后序 + 中序 | **能** | 后序定根，中序分左右 |
| 层次 + 中序 | **能** | 层次定根，中序分左右 |
| 先序 + 后序 | **不能** | 单孩子结点无法区分左右 |
| 层次 + 先序 | **不能** | 同上 |
| 层次 + 后序 | **不能** | 同上 |
| 先序 + 后序（**严格二叉树**） | 能 | 无单孩子结点，歧义消失 |
| 层次 + 先序（**完全二叉树**） | 能 | 单孩子必为左孩子，形状受限 |
:::

**（1）先序 + 中序**

构造步骤（设结点值互不相同）：

1. 先序序列的**第一个元素**是当前子树（初始为整棵树）的根；
2. 在**中序序列**中定位该根，根**左边**的元素构成左子树的中序序列，**右边**的构成右子树的中序序列；
3. 由左子树结点个数 $k$，把先序序列**切成**「根 | 左子树先序（$k$ 个） | 右子树先序」；
4. 对左右子树**递归**执行上述过程。

:::warn 关键一步
第 3 步「用左子树的结点数去切分先序序列」是本题型的得分点。很多同学会漏掉这一步，只在中序里切分，导致先序无法继续划分。
:::

**例**：先序 `A B D E C F G`，中序 `D B E A F C G`。

- 先序首元素 `A` 是根；中序中 `A` 的位置把序列分为 `D B E` 与 `F C G`；
- 左子树 3 个结点，故先序中 `A` 之后 3 个 `B D E` 属左子树，其余 `C F G` 属右子树；
- 递归：左子树先序 `B D E`、中序 `D B E` → 根 `B`，左 `D` 右 `E`；右子树先序 `C F G`、中序 `F C G` → 根 `C`，左 `F` 右 `G`。

**（2）后序 + 中序**

与上一情形完全对称，只是**根取后序序列的最后一个元素**：

1. 后序序列的**最后一个元素**是根；
2. 在中序中定位根，划分左右子树的中序序列；
3. 由左子树结点个数 $k$，把后序序列切成「左子树后序（$k$ 个） | 右子树后序 | 根」；
4. 递归。

:::warn 易错
「后序 + 中序」中，左子树的后序序列在下标上位于**前面**，右子树紧随其后。如果切分时把右子树放在前面就会全错。建议每次切分后**手工验证一次后序**（左子树后序 + 右子树后序 + 根 是否等于原序列）。
:::

**（3）层次 + 中序**

1. **层次序列的第一个元素**是整棵树的根；
2. 在**中序序列**中定位该根，根左边是左子树全部结点，右边是右子树全部结点；
3. 从**层次序列**中**筛选**出属于左子树的结点（保持原有相对顺序），得到左子树的层次序列；同理得到右子树的层次序列；
4. 对左右子树**递归**。

:::key 为什么必须「重新筛选」
层次序列是整棵树的层次序，左右子树的结点在原序列中是**交错出现**的，必须各自挑出来组成新的层次序列，才能继续递归。每一步挑出后，**新层次序列的第一个元素就是该子树的根**。
:::

**例**：层次 `A B C D E F`，中序 `D B E A F C`。

- 根为 `A`；中序分左右：左 `D B E`，右 `F C`；
- 从左子树结点集 $\{D,B,E\}$ 在原层次序列中筛选，得到左子树层次 `B D E`；右子树层次 `C F`；
- 左子树：层次首元素 `B` 为根，中序 `D B E` 中 `B` 居中 → 左 `D` 右 `E`；
- 右子树：层次首元素 `C` 为根，中序 `F C` 中 `C` 末尾 → 只有左孩子 `F`。

**（4）先序 + 后序为什么不能唯一确定**

:::key 根本原因：单孩子子树无法区分左右
- 先序去掉根后是「左子树先序 + 右子树先序」；
- 后序去掉根后是「左子树后序 + 右子树后序」；
- **但你不知道左子树有几个结点**，无法据此切分。

当某个结点**同时有左右两个孩子**时，才能通过「先序的第二个元素 = 左子树根」「后序的倒数第二个元素 = 右子树根」确定分界。一旦某结点**只有一个孩子**，该孩子在左在右都不改变先序和后序的结果，歧义就产生了。

**最小反例**：树 1 中 `B` 是 `A` 的左孩子且 `C` 是 `B` 的右孩子；树 2 中 `B` 是 `A` 的右孩子且 `C` 是 `B` 的左孩子。两棵树的先序都是 `A B C`，后序都是 `C B A`，但结构不同。
:::

:::key 什么时候先序 + 后序能唯一确定
在结点值互不相同、且不附加形状限制时：**当且仅当该二叉树是严格二叉树（真二叉树，每个结点度为 0 或 2）**，先序 + 后序才能唯一确定；同理，层次 + 先序、层次 + 后序也只有在这种情况下能唯一。

若附加形状约束，条件可以放宽：例如**完全二叉树**中单孩子只能是左孩子，形状约束本身就消除了歧义，所以「层次 + 先序」对完全二叉树可唯一确定。

**典型应用**：表达式树是一棵真二叉树，因此给出它的先序（前缀表达式）和后序（后缀表达式）就能唯一还原它。
:::

#### 6. 遍历序列相等的条件（高频小题）

:::key 序列相同 ⇔ 形状受限
| 条件 | 等价的结构要求 |
|:---|:---|
| 先序 = 中序 | 每个非叶结点**只有右子树**（不存在左孩子） |
| 后序 = 中序 | 每个非叶结点**只有左子树**（不存在右孩子） |
| 先序 = 后序 | 树中**只有一个结点**（$n=1$） |
| 先序 = 层次 | 每个非叶结点只有右子树，且树是单链 |
| 中序 = 层次 | 每个非叶结点只有右子树（单链） |

**先序 = 中序的推导**：先序为 N L R，中序为 L N R，二者唯一的差别是根与左子树的先后。若某非叶结点有左子树，先序先访问该结点再访问左子树，中序先访问左子树再访问该结点，两序列必然不同。故所有非叶结点都不能有左子树，只能有右子树。

注意：**「所有结点的度均为 1」是不够的**——度为 1 还可能包含「只有左孩子」的情况，此时先序与中序不再相同。
:::

#### 7. 中序序列相邻结点的结构含义

:::key 中序前驱 / 后继的结构性质
- 若 $v$ 有左子树，则 $v$ 的**中序直接前驱**是 $v$ 左子树中**最右下的结点**，且该结点**必无右孩子**；
- 若 $v$ 有右子树，则 $v$ 的**中序直接后继**是 $v$ 右子树中**最左下的结点**，且该结点**必无左孩子**。

**推导**：中序按「左—根—右」进行，访问 $v$ 之前的最后一个结点必在左子树中，且是「最后被访问」的那个，即最右下的结点；若它还有右孩子，则中序还要先访问它的右子树，它就不可能紧邻 $v$。

**这条性质是 2024 年真题「中序序列形如 …,p,v,q,…，$v$ 有两个孩子」的解答关键**：由 $v$ 有左子树知 $p$ 是左子树中最右下结点，故 $p$ 无右孩子；由 $v$ 有右子树知 $q$ 是右子树中最左下结点，故 $q$ 无左孩子。
:::

### （四）线索二叉树

#### 1. 基本概念

在含 $n$ 个结点的二叉链表中，有 **$n+1$ 个空指针域**。传统二叉链表只能体现父子关系，求某结点的前驱 / 后继必须从根重新遍历。**线索二叉树**就是把这些空指针利用起来，指向该结点在某种遍历次序下的前驱 / 后继。

规定：

- 若无左子树，令 `lchild` 指向其**前驱**；
- 若无右子树，令 `rchild` 指向其**后继**。

为了区分指针指向的是孩子还是线索，需增加两个标志域：

| 标记 | 值 | 含义 |
|:---|:---|:---|
| `ltag` | 0 | `lchild` 指向**左孩子** |
| `ltag` | 1 | `lchild` 指向**前驱** |
| `rtag` | 0 | `rchild` 指向**右孩子** |
| `rtag` | 1 | `rchild` 指向**后继** |

```c
typedef struct ThreadNode {
    int data;                            // 数据域
    struct ThreadNode *lchild, *rchild;  // 左、右指针
    int ltag, rtag;                      // 左、右线索标志
} ThreadNode, *ThreadTree;
```

:::key 三个必背结论
- 加上线索的二叉链表称为**线索链表**，对应的二叉树称为**线索二叉树**；
- 线索化的实质是**在遍历过程中把空指针改为前驱 / 后继线索**，所以线索化的过程就是**遍历的过程**；
- 线索二叉树类似于一个**非循环的双向链表**：遍历序列的第一个结点前驱指向 `NULL`，最后一个结点后继指向 `NULL`（不带头结点时）。
:::

#### 2. 线索化的构造过程

核心技巧：设两个指针 `pre`（刚访问过的结点）与 `p`（正在访问的结点），则 **`pre` 是 `p` 的前驱**。遍历到 `p` 时：

- 若 `p->lchild == NULL`，把 `p->lchild` 指向 `pre`，`p->ltag = 1`；
- 若 `pre->rchild == NULL`，把 `pre->rchild` 指向 `p`，`pre->rtag = 1`。

**中序线索化**：

```c
// pre 为全局或引用参数，始终指向刚访问过的结点
void InThread(ThreadNode *p, ThreadNode *&pre) {
    if (p != NULL) {
        InThread(p->lchild, pre);            // 递归线索化左子树
        if (p->lchild == NULL) {             // 左孩子为空，建立前驱线索
            p->lchild = pre;
            p->ltag = 1;
        } else {
            p->ltag = 0;
        }
        if (pre != NULL && pre->rchild == NULL) { // 前驱的右孩子为空，建立后继线索
            pre->rchild = p;
            pre->rtag = 1;
        } else if (pre != NULL) {
            pre->rtag = 0;
        }
        pre = p;                             // 更新 pre
        InThread(p->rchild, pre);            // 递归线索化右子树
    }
}

void CreateInThread(ThreadTree root) {
    ThreadNode *pre = NULL;
    if (root != NULL) {
        InThread(root, pre);
        pre->rchild = NULL;                  // 处理中序最后一个结点
        pre->rtag = 1;
    }
}
```

**先序线索化**：把「建线索 + 更新 pre」的部分提到递归**之前**，并且**递归左子树前必须判断 `p->ltag == 0`**：

```c
void PreThread(ThreadNode *p, ThreadNode *&pre) {
    if (p != NULL) {
        if (p->lchild == NULL) { p->lchild = pre; p->ltag = 1; }
        else { p->ltag = 0; }
        if (pre != NULL && pre->rchild == NULL) { pre->rchild = p; pre->rtag = 1; }
        else if (pre != NULL) { pre->rtag = 0; }
        pre = p;
        if (p->ltag == 0) PreThread(p->lchild, pre);  // 必须判断，否则死循环
        if (p->rtag == 0) PreThread(p->rchild, pre);  // 必须判断，否则死循环
    }
}
```

:::warn 先序线索化的死循环陷阱
先序线索化时，结点 `p` 的左指针**可能刚被改成指向前驱 `pre`**。如果此后不加判断就递归进入 `p->lchild`，程序会顺着线索走回祖先，形成**死循环**。所以 **先序线索化递归左右子树前必须先检查 `ltag` / `rtag`**。中序线索化因为「建线索」发生在左递归**之后**，天然没有这个问题。
:::

**后序线索化**：把「建线索 + 更新 pre」的部分放到左、右递归**之后**。递归左右子树时不需要判断标记（因为进入时线索尚未建立），但**建立线索时要用 `pre`**：

```c
void PostThread(ThreadNode *p, ThreadNode *&pre) {
    if (p != NULL) {
        PostThread(p->lchild, pre);
        PostThread(p->rchild, pre);
        if (p->lchild == NULL) { p->lchild = pre; p->ltag = 1; }
        else { p->ltag = 0; }
        if (pre != NULL && pre->rchild == NULL) { pre->rchild = p; pre->rtag = 1; }
        else if (pre != NULL) { pre->rtag = 0; }
        pre = p;
    }
}
```

**三种线索化只需改动两处**：① 线索化改造代码段的位置；② 递归调用左右子树的位置。顺序为：

| 线索类型 | 代码顺序 |
|:---|:---|
| 先序 | 建线索 → 递归左 → 递归右 |
| 中序 | 递归左 → 建线索 → 递归右 |
| 后序 | 递归左 → 递归右 → 建线索 |

#### 3. 带头结点的线索二叉树

仿照带头结点的链表，可为线索二叉树增设一个**头结点**：

- 头结点的 `lchild` 指向二叉树的**根结点**（`ltag = 0`）；
- 头结点的 `rchild` 指向**中序遍历最后一个访问的结点**（`rtag = 1`）；
- 中序遍历**第一个结点**的 `lchild` 指向头结点；
- 中序遍历**最后一个结点**的 `rchild` 指向头结点。

这样整棵线索二叉树构成一个**双向线索链表**，可以方便地从任一点出发向两个方向遍历：从**头结点的左孩子**出发可正向中序遍历，从头结点出发沿 `rchild` 链可逆向遍历。

```c
ThreadTree CreateInThreadWithHead(ThreadTree root) {
    ThreadNode *head = (ThreadNode *)malloc(sizeof(ThreadNode));
    head->ltag = 0;                  // 左指针指向根
    head->rtag = 1;                  // 右指针始终为线索
    head->rchild = head;             // 先初始化指向自己
    if (root != NULL) {
        head->lchild = root;         // 头结点的左指针指向根结点
        ThreadNode *pre = head;
        InThread(root, pre);         // 中序线索化
        pre->rchild = head;          // 最后一个结点的后继指向头结点
        pre->rtag = 1;
        head->rchild = pre;          // 头结点的后继指向最后一个结点
        head->rtag = 1;
    } else {
        head->lchild = head;         // 空树时左指针指向自己
    }
    return head;
}
```

:::warn 易错
- 先序线索化**不能**用头结点的 `lchild` 作为 `pre` 的初值后再无条件递归，因为先序的第一个结点是根，前驱应为 `NULL`（或头结点）；
- 后序线索化中，**若最后一个结点有右孩子，`pre->rtag` 不能被设为 1**，否则线索化错误。处理「最后一个结点」时必须先判断其右指针是否为空。
:::

#### 4. 在线索二叉树上找前驱 / 后继

**中序线索二叉树：找后继**

- 若 `p->rtag == 1`：后继就是 `p->rchild`；
- 若 `p->rtag == 0`：后继是其**右子树中最左下的结点**（右子树中第一个被中序访问的结点）。

**中序线索二叉树：找前驱**

- 若 `p->ltag == 1`：前驱就是 `p->lchild`；
- 若 `p->ltag == 0`：前驱是其**左子树中最右下的结点**（左子树中最后一个被中序访问的结点）。

```c
// 以 p 为根的子树中，第一个被中序遍历访问的结点（最左下）
ThreadNode *FirstNode(ThreadNode *p) {
    if (p == NULL) return NULL;
    while (p->ltag == 0) p = p->lchild;   // 循环到最左下，不一定是叶结点
    return p;
}

// 以 p 为根的子树中，最后一个被中序遍历访问的结点（最右下）
ThreadNode *LastNode(ThreadNode *p) {
    if (p == NULL) return NULL;
    while (p->rtag == 0) p = p->rchild;
    return p;
}

// 中序线索二叉树中求 p 的中序后继
ThreadNode *NextNode(ThreadNode *p) {
    if (p->rtag == 0) return FirstNode(p->rchild); // 右子树最左下
    else return p->rchild;                          // 直接读线索
}

// 中序线索二叉树中求 p 的中序前驱
ThreadNode *PreNode(ThreadNode *p) {
    if (p->ltag == 0) return LastNode(p->lchild);   // 左子树最右下
    else return p->lchild;                          // 直接读线索
}

// 利用线索做中序遍历（非递归，空间 O(1)）
void InOrderThreadTree(ThreadNode *root) {
    for (ThreadNode *p = FirstNode(root); p != NULL; p = NextNode(p))
        visit(p);
}

// 逆向中序遍历
void RevInOrderThreadTree(ThreadNode *root) {
    for (ThreadNode *p = LastNode(root); p != NULL; p = PreNode(p))
        visit(p);
}
```

:::key 中序线索二叉树的最大优势
**中序遍历不需要栈，空间复杂度为 $O(1)$**（若不计线索化本身的额外标记域）。这是中序线索二叉树被广泛使用的原因。
:::

**先序线索二叉树：找后继**

- 若 `p->ltag == 0`（有左孩子）：左孩子就是其后继；
- 若 `p->ltag == 1` 且 `p->rtag == 0`（无左孩子有右孩子）：右孩子就是其后继；
- 若 `p->ltag == 1` 且 `p->rtag == 1`（叶结点）：`p->rchild` 即线索，直接给出后继。

**先序线索二叉树：找前驱**

- 若 `p->ltag == 1`：前驱 = `p->lchild`；
- 若 `p->ltag == 0`：**先序遍历的顺序是「根—左—右」，因此 `p` 的左右孩子都只能是 `p` 的后继，不可能是前驱**。此时必须**从头（根）重新开始遍历**才能找到 `p` 的前驱。

:::warn 先序线索二叉树找前驱的代价
**先序线索二叉树不便于找前驱**。若确实需要频繁求先序前驱，可把二叉链表改为**三叉链表**（增加 `parent` 域），此时分四种情况：

| 情况 | $p$ 的先序前驱 |
|:---|:---|
| $p$ 是根 | 无前驱 |
| $p$ 是双亲的左孩子 | $p$ 的双亲 |
| $p$ 是双亲的右孩子，且双亲无左孩子 | $p$ 的双亲 |
| $p$ 是双亲的右孩子，且双亲有左孩子 | 双亲左子树中**最后一个被先序访问**的结点（先下左、无左则下右，直至叶子） |
:::

**后序线索二叉树：找前驱**

- 若 `p->ltag == 1`：前驱 = `p->lchild`；
- 若 `p->ltag == 0`（$p$ 必有左孩子）：
  - 若 $p$ **有右孩子**：后序前驱 = **右孩子**（后序为「左、右、根」，最后访问完右子树再访问根）；
  - 若 $p$ **无右孩子**：后序前驱 = **左孩子**。

**后序线索二叉树：找后继**

- 若 `p->rtag == 1`：后继 = `p->rchild`；
- 若 `p->rtag == 0`（$p$ 有右孩子）：**后序中左右子树中的结点都只能是 $p$ 的前驱，不可能是后继**，除非从根重新遍历，或改用三叉链表。

用三叉链表时，$p$ 的后序后继分四种情况：

| 情况 | $p$ 的后序后继 |
|:---|:---|
| $p$ 是根 | 无后继 |
| $p$ 是双亲的右孩子 | $p$ 的双亲 |
| $p$ 是双亲的左孩子，且双亲无右孩子 | $p$ 的双亲 |
| $p$ 是双亲的左孩子，且双亲有右孩子 | 双亲右子树中**第一个被后序访问**的结点（有左走左、无左走右，直至叶子） |
| 附：$p$ 有右孩子（不论位置） | 右子树中第一个被后序访问的结点（有左走左、无左走右） |

:::warn 后序线索二叉树遍历仍需栈
**后序线索二叉树的遍历仍然需要栈**。原因：后序遍历最后访问根结点，若从右孩子返回去访问双亲结点，由于双亲的右孩子指针不一定是空的（它可能指向真实的右孩子而非线索），无法用线索判断「是否已从右子树返回」，因而无法仅靠指针遍历整棵树。
:::

:::key 三种线索二叉树的能力对比（必背）
| 能力 | 中序线索 | 先序线索 | 后序线索 |
|:---|:---:|:---:|:---:|
| 找**前驱** | ✔ 直接可得 | ✘ 需从头遍历 / 三叉链表 | ✔ 直接可得 |
| 找**后继** | ✔ 直接可得 | ✔ 直接可得 | ✘ 需从头遍历 / 三叉链表 |
| 不用栈完成遍历 | ✔ | ✔ | ✘ 仍需栈 |

**记忆口诀**：**「中序两全，先序缺前驱，后序缺后继」**。
:::

:::exam 真题考法
- 给出二叉树的形状与遍历序列，问某结点的左右线索指向谁（2014 年形式）：**先把对应的遍历序列完整写出**，再看该结点在序列中的前后邻居，同时注意「有真实孩子的一侧不建线索」。
- 后序线索二叉树中叶结点 $X$ 有左兄弟 $Y$，问 $X$ 的右线索指向谁（2013 年形式）：$X$ 是右孩子，后序遍历完 $X$ 后两个子树都已处理完，下一个是**双亲**。
- 先序线索二叉树中非根叶结点 $X$ 有左兄弟 $Y$，问 $X$ 的左线索（先序前驱）指向谁：是**以 $Y$ 为根的子树中先序最后访问的结点**。
- 后序线索二叉树中，$X$ 是其双亲 $p$ 的左孩子且 $p$ 存在右子树，问 $X$ 的右线索（后序后继）：**$p$ 的右子树中后序第一个访问的结点**（从 $p$ 的右孩子出发，有左走左、无左走右，直至叶结点），不是「最右下的结点」。
:::


## 三、树、森林

### （一）树的存储结构

树是一对多的逻辑结构，存储时既要保存**数据**，又要保存**父子关系**。三种表示法的本质区别只在于「每个结点额外记录谁」。

#### 1. 双亲表示法

用一维数组顺序存放全部结点，每个结点附一个 `parent` 域记录双亲在数组中的**下标**；根结点的 `parent` 约定为 $-1$。

```c
#define MAX_TREE_SIZE 100

typedef struct {
    ElemType data;                  // 数据域
    int parent;                     // 双亲在数组中的下标
} PTNode;

typedef struct {
    PTNode nodes[MAX_TREE_SIZE];    // 结点数组
    int n;                          // 结点数
} PTree;
```

**操作特性**：

- **找双亲 $O(1)$**，沿 `parent` 链可一路向上找到根——这正是**并查集**的基础；
- **找孩子 $O(n)$**：需扫描整个数组看谁的双亲是自己。

**删除结点的两种策略**（被删结点为叶子；非叶需先递归删子树）：

| 策略 | 做法 | 时间复杂度 | 缺点 |
|:---|:---|:---|:---|
| 打标记 | 把 `parent` 改为 $-2$（区别于根的 $-1$） | $O(1)$ | 结点仍占数组空间 |
| 物理搬移 | 把数组尾部元素前移填补，并修正受影响结点的下标 | $O(n)$ | 删除变慢 |

:::warn 易错
双亲表示法靠 `parent` 域**显式记录**父子关系；二叉树的顺序存储靠**下标计算隐含**父子关系（结点 $i$ 的左孩子为 $2i$）。一般树的孩子个数不固定，**不能直接套用二叉树的顺序存储**。
:::

#### 2. 孩子表示法

把每个结点的所有孩子串成一条**单链表**，$n$ 个结点就有 $n$ 条孩子链表（叶子对应空链表）；所有链表的头指针集中放在一个数组（表头数组）中，数组每个位置同时保存结点数据。

链表结点中保存的是**孩子在表头数组中的下标**，而不是孩子数据本身。

```c
typedef struct CCNode {          // 孩子链表的结点
    int child;                   // 孩子在表头数组中的下标
    struct CCNode *next;         // 下一个孩子
} CCNode;

typedef struct {
    ElemType data;               // 数据域
    CCNode *firstChild;          // 孩子链表头指针
} TreeNode;

typedef struct {
    TreeNode nodes[MAX_TREE_SIZE];
    int n;
} CTree;
```

**操作特性**：找孩子快（沿链表走一遍），找双亲慢（需遍历所有链表，$O(n)$）。

:::key 实用的混合方案
把双亲表示法和孩子表示法**拼在一起**（结点同时带 `parent` 域和孩子链表头），找双亲、找孩子都快，代价是多花一点空间。这就是**带双亲的孩子链表**。
:::

**结构对比记忆**：孩子表示法与**图的邻接表**、**散列表的拉链法**、**基数排序的分配收集**在示意图和结构体定义上高度相似，可放在一起记忆。

#### 3. 孩子兄弟表示法（二叉链表 / 二叉树表示法）

每个结点设两个指针：

- **左指针 → 第一个孩子**（`firstChild`）；
- **右指针 → 下一个兄弟**（`nextSibling`）。

想枚举某结点的全部孩子：先沿左指针找到老大，再沿老大的右指针依次往后找，直到右指针为空。

```c
typedef struct CSNode {
    ElemType data;                     // 数据域
    struct CSNode *firstChild;         // 左指针：第一个孩子
    struct CSNode *nextSibling;        // 右指针：下一个兄弟
} CSNode, *CSTree;
```

**操作特性**：找孩子容易、找双亲难（同孩子表示法）；若需快速回溯双亲，可再加 `parent` 域构成三叉链表。

:::key 孩子兄弟表示法的最大价值
它的存储结构与二叉树的二叉链表**在物理形式上完全一致**，因此同一棵树可以毫不费力地「解读」成一棵二叉树——这正是下一节「树与二叉树相互转换」的物理基础。
:::

#### 4. 三种存储结构对比

| 对比项 | 双亲表示法 | 孩子表示法 | 孩子兄弟表示法 |
|:---|:---|:---|:---|
| 额外记录 | 双亲下标 | 孩子链表头 | 第一个孩子 + 下一个兄弟 |
| 找双亲 | $O(1)$，极快 | 需遍历，慢 | 需遍历，慢 |
| 找孩子 | 需扫描全表，慢 | 沿链表，快 | 沿左指针 + 右链，快 |
| 存储形式 | 顺序（数组） | 顺序 + 链式 | 纯链式（二叉链表） |
| 典型用途 | 并查集等向上回溯场景 | 需要频繁枚举孩子的场景 | 树 / 森林与二叉树的转换 |

### （二）森林与二叉树的转换

树、森林与二叉树之间存在**一一对应**关系：任何一棵树（或森林）都能唯一地转成一棵二叉树，反之亦然。这意味着——**凡是在树上不好做的事，都可以转成二叉树来做**，做完再翻译回去。

#### 1. 树 → 二叉树

:::key 转换规则：左孩子右兄弟
二叉树中结点 $p$ 的**左指针**指向原树中 $p$ 的**第一个孩子**；**右指针**指向原树中 $p$ 的**下一个兄弟**。

**手工三步走**：

1. **断开**：对每个结点，只保留它与**第一个孩子**的连线，其余父子连线全部擦掉；
2. **连线**：把同一双亲的兄弟结点从左到右用线串起来；
3. **整形**：以树根为轴心顺时针旋转约 $45^\circ$，兄弟连线就变成「右指针」。
:::

:::key 重要结论
根结点没有兄弟，所以**由单棵树转成的二叉树，其根结点必定没有右子树**。反过来，一棵二叉树若根结点没有右子树，它才可以还原成「一棵树」。
:::

**逆过程（二叉树 → 树）**：把每个结点的左孩子还原为「第一个孩子」，把沿右指针串起来的一串结点还原为同一双亲的一排兄弟。

#### 2. 森林 → 二叉树

森林是若干棵树的集合，转换建立在单棵树转换的基础上。推荐用**虚构根结点法**：

1. **加虚根**：虚构一个根结点 $r$，把森林中每棵树都当作 $r$ 的子树（于是各棵树的根互为兄弟）；
2. **转换**：对「虚根 + 森林」整体应用「左孩子右兄弟」规则；
3. **删虚根**：把虚根 $r$ 及与它相连的边擦掉，剩下的就是森林对应的二叉树。

**等效的手工画法**（不画虚根）：先把森林中每棵树各自转成二叉树（它们的根都没有右子树），然后把第 2 棵树的根接在第 1 棵树的根的**右指针**上、第 3 棵接在第 2 棵的右指针上……依次串联。**本质上就是「把各棵树的根视为兄弟」。**

**逆过程（二叉树 → 森林）**：

- 若二叉树**根结点无右子树** → 对应**一棵树**；
- 若二叉树**根结点有右子树** → 对应**一个森林**：把根结点的右指针断开，右子链上每断开一处就分离出一棵新树，对每棵分离出的二叉树分别还原。

:::key 两个重要计数结论（真题直接考）
1. **转换前森林中的叶子结点数 = 转换后二叉树中「左孩子指针为空」的结点数**。

   理由：左指针指向第一个孩子，故「有孩子 ⇔ 左指针非空」；叶子 ⇔ 无孩子 ⇔ 左指针为空。右指针反映的是「有没有下一个兄弟」，与是否为叶子无关。

2. **若森林（或树）中有 $n$ 个分支结点，则转换后二叉树中「右孩子指针为空」的结点数恰为 $n+1$。**

   理由：每个分支结点的**最右孩子**没有下一个兄弟，贡献 1 个空右指针，共 $n$ 个；再加上**最后一棵树的根**（在森林中）或**该树的根**（在单棵树中）没有兄弟，贡献 1 个，合计 $n+1$。
:::

**例**：一棵有 2011 个结点、116 个叶结点的树，转成二叉树后无右孩子的结点个数是多少？

分支结点数 $=2011-116=1895$，故无右孩子的结点数 $=1895+1=1896$。（2011 年形式）

**例**：某森林 $F$ 转换为二叉树 $T$，$F$ 中叶子的个数等于 $T$ 中「左孩子指针为空」的结点个数。（2014 年形式）

### （三）树和森林的遍历

#### 1. 树的遍历

树的孩子个数不固定，无法像二叉树那样把根「夹在两棵子树中间」，所以**树没有中根遍历**，只有两种（外加层序）：

- **先根遍历**：先访问根结点，再**从左到右**依次先根遍历根的每一棵子树。
- **后根遍历**：先**从左到右**依次后根遍历根的每一棵子树，最后访问根结点。
- **层次遍历**：借助队列，自上而下、自左而右逐层访问（原理同二叉树层次遍历）。

**例**：树 `X(Y(V), Z(U,T), W)`

- 先根遍历序列：`X Y V Z U T W`
- 后根遍历序列：`V Y U T Z W X`
- 层次遍历序列：`X Y Z W V U T`

#### 2. 森林的遍历

森林的遍历是递归定义的（设森林非空）：

**先序遍历森林**：

1. 访问第一棵树的根结点；
2. 先序遍历「第一棵树的根的所有子树」组成的森林；
3. 先序遍历「去掉第一棵树后剩下的树」组成的森林。

**效果 = 依次对每棵树做先根遍历。**

**中序遍历森林**：

1. 中序遍历「第一棵树的根的所有子树」组成的森林；
2. 访问第一棵树的根结点；
3. 中序遍历「去掉第一棵树后剩下的树」组成的森林。

**效果 = 依次对每棵树做后根遍历。**

**例**：森林 $F$（`A(B(D), C)`、`E(F)`、`G(H)`）

- 先序遍历序列：`A B D C E F G H`
- 中序遍历序列：`D B C A F E H G`

:::warn 术语口径差异
部分教材把森林的「中序遍历」称作「**后序遍历**」（因为对每棵树做的是后根遍历）。两种叫法**指的是同一个序列**。统考以题目采用的口径为准，看到「森林的后序遍历」多数是指对每棵树做后根遍历。
:::

#### 3. 与二叉树遍历的对应关系（必背）

:::key 对应关系总表
| 树 | 森林 | 对应二叉树 |
|:---|:---|:---|
| 先根遍历 | 先序遍历 | **先序**遍历 |
| 后根遍历 | 中序遍历（部分教材称后序遍历） | **中序**遍历 |
| 层次遍历 | —— | （无直接对应） |

**记忆口诀：「先对先，后对中」**——树的先根 / 森林的先序 ≡ 二叉树先序；树的后根 / 森林的中序 ≡ 二叉树中序。
:::

**用例子验证**：

- 树 $T_2$ 先根 `X Y V Z U T W` = 对应二叉树的先序序列 ✔；$T_2$ 后根 `V Y U T Z W X` = 对应二叉树的中序序列 ✔
- 森林 $F$ 先序 `A B D C E F G H` = 对应二叉树先序 ✔；$F$ 中序 `D B C A F E H G` = 对应二叉树中序 ✔

**为什么「后根 = 中序」**：转换后用左指针连第一个孩子、右指针连后续兄弟。对二叉树做中序遍历时，先沿左指针进入第一个孩子，孩子的右兄弟链在遍历子树的过程中依次处理，**所有孩子及其子树处理完成后才访问当前根**——这与原树「先遍历各子树、后访问根」的后根遍历完全一致。

**最小验证例**：原树根 $a$ 有孩子 $b$、$c$。原树后根遍历为 `b c a`。转换后二叉树中 $a$ 的左孩子是 $b$，$b$ 的右孩子是 $c$，其中序遍历同样为 `b c a`。

:::exam 真题考法
- 2009：森林转二叉树后，若 $u$ 是 $v$ 的双亲的双亲，问原森林中 $u$、$v$ 的关系（枚举 $L$-$L$、$L$-$R$、$R$-$L$、$R$-$R$ 四种路径即可）。
- 2019：树 $T$ 转二叉树 $BT$ 后，与 $T$ 的后根遍历序列相同的是 $BT$ 的**中序**遍历。
- 2020：已知森林的**先根**与**后根**序列，求对应二叉树的**后序**序列 —— 先用「先根 = 二叉树先序、后根 = 二叉树中序」还原二叉树，再求后序。
- 2021：给出二叉树 $T$ 的先序与中序序列，问 $F$ 中**树的棵数** —— 森林中树的棵数 = 二叉树根结点沿**右指针链**的结点数（即根到最右下的右链长度）。
:::


## 四、树与二叉树的应用

### （一）哈夫曼树与哈夫曼编码

#### 1. 基本概念

- **结点的权**：赋予结点的、代表某种含义的数值（如字符出现频率、判断概率）。
- **路径长度**：路径上的**分支（边）数目**。
- **结点的带权路径长度**：从该结点到根的路径长度与该结点权的乘积 $w_i\times l_i$。
- **树的带权路径长度 WPL**：

:::key WPL 定义

$$WPL=\sum_{i=1}^{n_0} w_i\, l_i$$

其中 $n_0$ 为**叶子结点**个数，$w_i$ 为第 $i$ 个叶子的权，$l_i$ 为该叶子到根的路径长度。

**WPL 只计算叶子结点，不计算内部结点。**
:::

#### 2. 哈夫曼树的定义

**哈夫曼树（Huffman Tree）** 又称**最优二叉树**：在 $n_0$ 个带权叶子结点构成的所有二叉树中，**WPL 最小**的那棵。

要让 WPL 小，就要让**权大的叶子离根近**（路径短），权小的叶子离根远（路径长）。

#### 3. 构造算法

:::key 构造步骤
1. **初始**：构造含 $n_0$ 棵二叉树的森林 $F=\{T_1,\dots,T_{n_0}\}$，每棵树只有一个权为 $w_i$ 的根结点。
2. **选两个最小**：从 $F$ 中选取根权值最小的两棵树 $T_x$、$T_y$（选两次，可用小顶堆实现）。
3. **合并**：新建结点 $T_j$，权值 $=T_x$ 根权 $+T_y$ 根权，以 $T_x$ 为左子树、$T_y$ 为右子树，把 $T_j$ 加入 $F$。
4. **重复** 2、3，直到 $F$ 中只剩一棵树，即哈夫曼树。
:::

**例**：权值 $\{7,5,2,4\}$ 构造哈夫曼树。

| 步骤 | 森林 $F$ | 操作 |
|:---:|:---|:---|
| 1 | $\{7,5,2,4\}$ | 初始，4 棵树各一个结点 |
| 2 | $\{7,5,6\}$ | 选最小的 2 和 4 合并，新结点权 $2+4=6$ |
| 3 | $\{7,11\}$ | 选最小的 5 和 6 合并，新结点权 $5+6=11$ |
| 4 | $\{18\}$ | 选 7 和 11 合并，根权 $7+11=18$ |

$$WPL_{\text{按叶子算}}=7\times1+5\times2+2\times3+4\times3=7+10+6+12=35$$

:::key WPL 的第二种算法（更快）
**哈夫曼树的 WPL = 所有非叶（内部）结点的权值之和。**

$$\text{WPL}=6+11+18=35$$

**原理**：每次合并产生的新结点权值会被累加进所有子孙叶子的路径长度中；把每个分支结点的权值拆开分配，恰好等于所有叶子的带权路径长度之和。**考试中用这个算法能省一半时间。**
:::

**哈夫曼编码的代码实现**（顺序存储，含选两个最小值）：

```c
typedef struct HTNode {
    int weight;         // 权值
    char data;          // 待编码字符
    int parent;         // 双亲下标
    int lchild, rchild; // 左右孩子下标
} HTNode, *HuffmanTree;

typedef char **HuffmanCode;

// 在 0..n-1 中选出两个根结点的最小值下标（parent == 0 表示尚未被合并）
void Select(HuffmanTree HT, int n, int &min1, int &min2) {
    int i, min;
    for (i = 0; i < n; i++)          // 第一个最小值
        if (HT[i].parent == 0) { min = i; break; }
    for (i = min + 1; i < n; i++)
        if (HT[i].parent == 0 && HT[i].weight < HT[min].weight) min = i;
    min1 = min;
    for (i = 0; i < n; i++)          // 第二个最小值（跳过 min1）
        if (HT[i].parent == 0 && i != min1) { min = i; break; }
    for (i = min + 1; i < n; i++)
        if (HT[i].parent == 0 && i != min1 && HT[i].weight < HT[min].weight) min = i;
    min2 = min;
}

// 构造哈夫曼树：n 个叶子，总结点数 m = 2n - 1
void Huffman_Create(HuffmanTree &HT, int *w, char *data, int n) {
    int m = 2 * n - 1;
    HT = (HuffmanTree)calloc(m, sizeof(HTNode));  // calloc 自动清零 parent/lchild/rchild
    for (int i = 0; i < n; i++) {
        HT[i].weight = w[i];
        HT[i].data = data[i];
    }
    for (int i = n; i < m; i++) {
        int min1, min2;
        Select(HT, i, min1, min2);                // 只在 i 之前（已建好的）中选
        HT[i].weight = HT[min1].weight + HT[min2].weight;
        HT[min1].parent = i;
        HT[min2].parent = i;
        HT[i].lchild = min1;                      // 较小的作左孩子
        HT[i].rchild = min2;
    }
}

// 从叶子向上回溯得到编码（得到的是逆序，从后往前填）
void Huffman_Coding(HuffmanTree HT, HuffmanCode &HC, int n) {
    HC = (HuffmanCode)malloc(sizeof(char *) * n);
    char *code = (char *)malloc(sizeof(char) * n);
    code[n - 1] = '\0';
    for (int i = 0; i < n; i++) {
        int j = i, p = HT[j].parent, start = n - 1;
        while (p != 0) {
            code[--start] = (HT[p].lchild == j) ? '0' : '1';
            j = p;
            p = HT[j].parent;
        }
        HC[i] = (char *)malloc(sizeof(char) * (n - start));
        strcpy(HC[i], &code[start]);
    }
    free(code);
}
```

#### 4. 哈夫曼树的性质

:::key 五条性质
1. **结点总数**：若哈夫曼树有 $n_0$ 个叶结点，则总结点数为 $2n_0-1$，度为 2 的结点数为 $n_0-1$。

   **推导**：哈夫曼树没有度为 1 的结点，故 $n=n_0+n_2$；又 $n_0=n_2+1$，代入得 $n_2=n_0-1$，$n=2n_0-1$。

2. **严格二叉树**：哈夫曼树中结点的度只能是 0 或 2，**没有度为 1 的结点**。
3. **权值单调性**：从根往下，任意非叶结点的权值**不小于**下一层任一结点的权值（越靠近根权值越大）。
4. **两个最小权值必为兄弟**：构造过程中权值最小的两个结点一定在第一次合并时成为同一新结点的两个孩子。
5. **形态不唯一，但 WPL 唯一**：左右子树可以互换、权值相同时合并顺序不同，都会得到不同形态但同为最优的哈夫曼树；**WPL 始终相同且最小**。高度也可能不同。
:::

:::key 哈夫曼树不一定是完全二叉树
哈夫曼树是**严格二叉树**，但**不是完全二叉树**。当权值分布很不均匀时，较小权值会被反复合并，树形可能明显向一侧加深，不满足完全二叉树的层序连续性。（2010 年真题的考点）
:::

#### 5. $m$ 叉哈夫曼树

由 $n_0$ 个初始（叶）结点构造 $m$ 叉哈夫曼树：

:::key 补充虚结点的公式
1. 计算 $t=(n_0-1)\bmod(m-1)$。若 $t\ne0$，需补充 $m-1-t$ 个**权为 0** 的虚叶结点；若 $t=0$ 则不需补充。
2. 每次从所有结点中取出 $m$ 个权值最小的结点，作为新结点的孩子，新结点权值为各孩子权值之和，再加入结点集合。每轮结点数减少 $m-1$ 个。
3. 重复直到只剩一个结点。

**为什么要补**：保证最后一次合并恰好是 $m$ 个结点，使构造出的树是真正的 $m$ 叉哈夫曼树（根结点恰好有 $m$ 个孩子）。虚结点的权为 0，**不影响 WPL**。
:::

**例**：权值 $\{2,3,4,5,6,7\}$ 构造三叉哈夫曼树（2013 年统考形式）。

$n_0=6$，$m=3$，$t=(6-1)\bmod 2=1\ne0$，需补充 $3-1-1=1$ 个权为 0 的虚结点，集合变为 $\{0,2,3,4,5,6,7\}$。

1. 取最小的三个 $0,2,3$ 合并 $\to5$，集合 $\{4,5,5,6,7\}$
2. 取最小的三个 $4,5,5$ 合并 $\to14$，集合 $\{6,7,14\}$
3. 取 $6,7,14$ 合并 $\to27$，根权 27

树的形状：根 27 的三个孩子依次为 6、7、14；14 的三个孩子依次为 4、5、5′；5′ 的三个孩子依次为 0（虚）、2、3。

| 叶子 | 权 | 到根的路径长度 |
|:---:|:---:|:---:|
| 6 | 6 | 1 |
| 7 | 7 | 1 |
| 4 | 4 | 2 |
| 5 | 5 | 2 |
| 2 | 2 | 3 |
| 3 | 3 | 3 |
| （虚） | 0 | 3 |

$$WPL=6\times1+7\times1+4\times2+5\times2+2\times3+3\times3+0\times3=6+7+8+10+6+9=46$$

**用「内部结点权值之和」验证**：$5+14+27=46$ ✔ 两种算法一致（虚结点权为 0，不产生贡献）。

:::warn $m$ 叉哈夫曼树的 WPL 计算
$m$ 叉情况下 **$WPL=$ 所有非叶结点的权值之和** 仍然成立（每次合并产生的权值都是其所有子树中叶子带权路径长度的一份贡献，逐层累加即为 WPL）。这条算法比按叶子逐个数路径长度更可靠。$m=2$ 时两种算法必然一致，可以作为自查手段。
:::

#### 6. 哈夫曼编码

**编码**：把数据转换成 0/1 串的过程。

**前缀编码**：**没有任何一个编码是另一个编码的前缀**。这样译码时从左到右扫描，每遇到一个完整编码即可立即确定一个字符，无需回溯，实现**唯一可译**。

:::key 前缀编码的判定方法
把给出的编码逐个比较：
- 若存在某个编码是另一个编码的**前缀**，则不是前缀编码；
- 等长编码一定是前缀编码；
- 「首位互不相同」或「某一位上已经区分开」都可安全排除前缀关系。

**例**：$\{01,0000,0001,001,1\}$ 是前缀编码；$\{0,100,110,1110,1100\}$ **不是**，因为 `110` 是 `1100` 的前缀。
:::

**哈夫曼编码**：对一棵有 $n_0$ 个叶子的哈夫曼树，**左分支赋 0、右分支赋 1**（也可以反过来），从根到每个叶子的路径上的赋值序列就构成该叶子对应字符的哈夫曼编码。

:::key 哈夫曼编码的四条结论
1. 哈夫曼编码是**最优前缀编码**，能使文件压缩后的**二进制长度最短**；
2. 左右分支的 0/1 赋值**无强制规定**，且权值相同的结点合并顺序可以不同，因此**哈夫曼树形态不唯一 → 哈夫曼编码不唯一**；
3. 但**WPL 唯一且最小**，即**总编码长度唯一**；
4. **出现频率高的字符编码短、频率低的编码长**——这是哈夫曼编码高效的根源。
:::

**例**：文件 $f$ 由字符集 $\{U,V,W,X,Y,Z\}$ 组成，出现次数分别为 $\{8,10,25,12,15,30\}$。

合并过程：$8+10=18$；$12+15=27$；$18+25=43$；$27+30=57$；$43+57=100$。

| 字符 | 出现次数 | 编码（左 0 右 1） | 编码长度 |
|:---:|:---:|:---:|:---:|
| U | 8 | 000 | 3 |
| V | 10 | 001 | 3 |
| W | 25 | 01 | 2 |
| X | 12 | 100 | 3 |
| Y | 15 | 101 | 3 |
| Z | 30 | 11 | 2 |

$$WPL=8\times3+10\times3+25\times2+12\times3+15\times3+30\times2=24+30+50+36+45+60=245$$

**等价的快速算法**：$WPL=18+27+43+57+100=245$ ✔

**与定长编码对比**：6 个字符用定长编码需 $\lceil\log_2 6\rceil=3$ 位，总长 $100\times3=300$ 位。

$$\text{压缩率}=\frac{300-245}{300}\approx18.3\%$$

:::key 加权平均长度
**加权平均长度** $L$ 表示平均每个符号占用的编码位数，衡量单位符号的编码效率：

$$L=\frac{\sum\limits_{i=1}^{n}f_i l_i}{\sum\limits_{i=1}^{n}f_i}=\frac{WPL}{F}=\sum_{i=1}^{n}p_i l_i$$

其中 $f_i$ 为符号频次，$F=\sum f_i$ 为总频次，$p_i=f_i/F$ 为概率。**WPL 是总量，$L$ 是平均值，二者通过 $WPL=L\times F$ 互相换算。**

**例**：频次 $\{3,4,5,6,8,10\}$，$F=36$。按哈夫曼算法合并：$3+4=7$；$5+6=11$；$7+8=15$；$10+11=21$；$15+21=36$。

$$WPL=7+11+15+21+36=90,\qquad L=\frac{90}{36}=2.5$$

（2023 年统考形式）
:::

:::key 一个重要的常数关系
**哈夫曼编码的最长编码长度 $+1$ = 哈夫曼树的最大高度**（按根为第 1 层、高度等于层数的约定）。
:::

:::exam 真题考法（哈夫曼这一节年年出题）
- 判断题：哈夫曼树是否是完全二叉树（**否**）、是否有度为 1 的结点（**无**）、两个最小权值是否必为兄弟（**是**）、非叶结点权值是否不小于下层（**是**）——2010 年形式。
- 给出一组编码问哪个是前缀编码——2014 年形式。**逐个检查是否有编码是另一个的前缀**。
- 给定权值序列求最小 WPL——用「非叶结点权值之和」最快（2021、2023 年形式）。

  **算例**：权值 $\{10,12,16,21,30\}$，合并过程为 $10+12=22$、$22+16=38$、$21+30=51$、$38+51=89$，故

  $$WPL_{\min}=22+38+51+89=200$$

  **注意**：算出来的 $89$ 是**根结点的权值**，不是 WPL。看到选项里有 $89$ 不要直接选——那是典型干扰项（2021 年真题的正确选项为 200）。
- 两级 WPL 的对比：「从根到两个叶子的路径权值序列」，要求每个非叶结点权值 $=$ 孩子权值之和（2015 年形式）。
- 给出哈夫曼编码串要求译码——**从前向后贪心切分**，因为前缀编码的任意前缀都不是完整编码（2017 年形式）。
- 哈夫曼树与定长编码树的对比：定长编码的叶结点**全部位于同一层**（2022 年形式）。
- 同一哈夫曼树上哪些叶子同层：按合并过程画出树，直接读深度（2026 年形式）。
:::

### （二）并查集

#### 1. 定义与核心思想

**并查集（Disjoint Set Union，DSU）** 是处理**不相交集合**的**合并**与**查询**问题的数据结构。

| 操作 | 功能 |
|:---|:---|
| `Initial(S)` | 把集合 $S$ 中每个元素初始化为独立的单元素集合 |
| `Find(S,x)` | 查找 $x$ 所在子集合的**根结点** |
| `Union(S,Root1,Root2)` | 把 `Root2` 并入 `Root1`（要求两者属于不同集合） |

**核心思想**：用**一棵树**表示一个集合，**根结点作为集合的代表**。

- 判断元素属于哪个集合 → 找该元素所在树的根；
- 合并两个集合 → 把一棵树的根挂到另一棵树的根下。

#### 2. 存储结构：树的双亲表示法

用一个数组：

- 数组的**下标**代表元素（结点编号）；
- 数组元素的值代表该元素的**双亲下标**；
- **根结点的值为负数**，其**绝对值**表示该集合的元素个数。

```c
#define SIZE 100

typedef struct {
    int data;      // 元素数据值
    int parent;    // 双亲下标（负数表示根，绝对值表示集合大小）
} UFSType;

typedef struct {
    UFSType *elements;  // 双亲指针数组
    int n;              // 元素个数
} UnionFindSet;
```

:::key 根结点用负数的好处
根结点既标识了集合（谁是代表），又顺带记录了集合大小，**一举两得**。按大小合并时直接比较绝对值即可，无需额外数组。
:::

**例**：数组 `S = [-4, 0, 0, 1, -4, 4, 5, 6]`（下标 0~7）对应：

- 集合一：根 0（`S[0]=-4`），1、2 是 0 的孩子，3 是 1 的孩子 → $\{0,1,2,3\}$
- 集合二：根 4（`S[4]=-4`），5 是 4 的孩子，6 是 5 的孩子，7 是 6 的孩子 → $\{4,5,6,7\}$

数组中只有 2 个负数，故共有 **2 个集合**。

#### 3. 基本操作

```c
// 初始化：每个元素自成一个集合
void Initial(int S[], int n) {
    for (int i = 0; i < n; i++) S[i] = -1;
}

// 查找 x 所在集合的根（朴素版）
int Find(int S[], int x) {
    while (S[x] >= 0) x = S[x];   // 沿双亲链向上，遇到负数即为根
    return x;
}

// 合并：把 Root2 挂到 Root1 下（朴素版）
void Union(int S[], int Root1, int Root2) {
    if (Root1 == Root2) return;
    S[Root1] += S[Root2];         // 累加集合大小
    S[Root2] = Root1;
}
```

:::warn 朴素实现的致命问题
朴素的 `Union` 不考虑两棵树的大小，反复执行 `Union(i+1, i)` 会退化成一条长度为 $n$ 的链，此时 `Find` 的代价为 $O(n)$。**把 $n$ 个元素合并成一个集合的总代价可达 $O(n^2)$。** 这就是必须优化的原因。
:::

#### 4. 优化一：路径压缩

在 `Find` 的过程中，顺便把查找路径上的所有结点**直接挂到根下**，压缩树高。

```c
// 路径压缩 · 递归版
int Find(int S[], int x) {
    if (S[x] >= 0)
        return S[x] = Find(S, S[x]);   // 递归找根，回溯时把 x 挂到根下
    else
        return x;
}

// 路径压缩 · 迭代版（推荐，避免递归深度）
int Find(int S[], int x) {
    int root = x;
    while (S[root] >= 0) root = S[root];   // 第一步：找到根
    while (x != root) {                    // 第二步：把路径上所有结点挂到根下
        int tmp = S[x];
        S[x] = root;
        x = tmp;
    }
    return root;
}
```

:::key 路径压缩的性质
- 路径压缩是**事后优化**：第一次查找仍可能很慢，但之后同一路径上的结点到根的距离变为 1；
- **路径压缩不改变元素所属的集合**（根不变），只是改变同一棵集合树内部的父子关系；
- **仅用路径压缩不保证树高有上界**（单次最坏仍可能 $O(n)$），但均摊效果好。
:::

#### 5. 优化二：按秩 / 按大小合并

合并时把**较小**的树挂到**较大**的树的根下，避免树高增长过快。

```c
// 按大小合并（小树挂大树）
void Union(int S[], int Root1, int Root2) {
    if (Root1 == Root2) return;
    if (S[Root2] < S[Root1]) {      // Root2 的绝对值更大，即集合更大
        S[Root2] += S[Root1];       // 累加集合大小
        S[Root1] = Root2;           // Root1 挂到 Root2 下
    } else {
        S[Root1] += S[Root2];
        S[Root2] = Root1;           // 大小相等时把 Root2 挂到 Root1 下
    }
}
```

:::key 按秩合并的高度上界
采用按大小合并后，**集合树的深度不超过 $\lfloor\log_2 n\rfloor+1$**。

**证明**：关键结论是**秩（高度上界）为 $k$ 的树至少有 $2^k$ 个结点**。归纳：秩首次变为 $k$ 时，必是两棵秩为 $k-1$ 的树合并，结点数 $\ge2^{k-1}+2^{k-1}=2^k$。于是 $n\ge2^k$，得 $k\le\lfloor\log_2 n\rfloor$。
:::

#### 6. 复杂度总表（必背）

| 实现方式 | 单次 Find | 单次 Union | $n$ 个元素合并为 1 个集合 |
|:---|:---|:---|:---|
| 朴素实现 | $O(n)$（最坏树高） | $O(1)$ | $O(n^2)$ |
| 仅按秩合并 | $O(\log_2 n)$（最坏） | $O(1)$ | $O(n\log_2 n)$ |
| 仅路径压缩 | 单次最坏 $O(n)$，均摊 $O(\log_2 n)$ | $O(1)$ | $O(n\log_2 n)$ |
| **路径压缩 + 按秩合并** | **均摊 $O(\alpha(n))$** | $O(1)$ | $O(n\,\alpha(n))$ |

:::key 关于 $\alpha(n)$
$\alpha(n)$ 是 Ackermann 函数的反函数，增长极慢：$n\le10^{80}$ 时 $\alpha(n)\le4$，可视为常数。因此并查集的操作**近乎 $O(1)$**。

**注意 $\alpha(n)$ 是均摊界，不是单次最坏界**：单次 `Find` 最坏仍可能是 $O(\log_2 n)$，只是在整条操作序列上摊薄后接近常数。
:::

:::warn 易错辨析
- 「只要采用路径压缩，任意时刻树高都不超过 $\lfloor\log_2 n\rfloor+1$」——**错**。树高上界是按秩合并带来的保证，路径压缩只压低被访问路径的高度。
- 「路径压缩可能改变元素所属的集合」——**错**。压缩前后元素的根不变。
- 并查集**不支持高效地拆分集合**（不能把一棵子树从集合树中分离出来）。
- $n$ 个元素合并为一个集合时，若不优化会退化成链，`Find` 最坏 $O(n)$。
:::

#### 7. 典型应用

**（1）图的连通性问题**：每个顶点初始为一个集合，每条边对应一次 `Union`，判断两顶点是否连通即比较 `Find(u) == Find(v)`。

**（2）Kruskal 最小生成树**：用并查集**判断新加入的边是否会与已选边构成环**。

1. 把所有边按权值从小到大排序；
2. 依次考察每条边 $(u,v)$：若 `Find(u) != Find(v)`（不连通，不成环），选中该边并 `Union`；否则舍弃；
3. 直到选够 $n-1$ 条边。

**注意**：图不连通时，Kruskal 得到的是**最小生成森林**，而不是最小生成树。

**例**：顶点集 $V=\{0,1,2,3,4,5,6\}$，边按权递增排列为
`e1=(0,1,1) e2=(1,2,2) e3=(3,4,3) e4=(0,2,4) e5=(4,5,5) e6=(2,3,6) e7=(1,5,7) e8=(5,6,8)`

| 边 | 结果 | 原因 |
|:---|:---|:---|
| `e1=(0,1,1)` | 选中 | 0、1 不连通 |
| `e2=(1,2,2)` | 选中 | 1、2 不连通 |
| `e3=(3,4,3)` | 选中 | 3、4 不连通 |
| `e4=(0,2,4)` | 舍弃 | 0、2 已连通，成环 |
| `e5=(4,5,5)` | 选中 | 4、5 不连通 |
| `e6=(2,3,6)` | 选中 | 合并 $\{0,1,2\}$ 与 $\{3,4,5\}$ |
| `e7=(1,5,7)` | 舍弃 | 1、5 已连通，成环 |
| `e8=(5,6,8)` | 选中 | 顶点 6 接入生成树 |

最小生成树为 $\{e1,e2,e3,e5,e6,e8\}$，总权值 $1+2+3+5+6+8=25$。处理完 `e7` 后 $\{0,1,2,3,4,5\}$ 已连通、6 单独成一个连通分量，故有 **2 个连通分量**。

:::exam 真题考法
- 给出并查集数组，问某个 `Find` 之后 `S[x]` 变成什么（**路径压缩后，路径上所有结点都直接指向根**）；
- 给出操作序列要求写最终数组（**按大小合并时要注意「大小相等时第二个根挂到第一个根下」的约定**）；
- 在 Kruskal 算法中并查集的作用（**判环**）。
:::

### （三）堆

#### 1. 定义

**堆（Heap）** 是满足「堆序性」的**完全二叉树**：

- **大根堆（大顶堆）**：任一结点的关键字**不小于**其左右孩子的关键字，即 $a_i\ge\max\{a_{2i},a_{2i+1}\}$；
- **小根堆（小顶堆）**：任一结点的关键字**不大于**其左右孩子的关键字，即 $a_i\le\min\{a_{2i},a_{2i+1}\}$。

:::key 堆的三条基本事实
1. **逻辑上是一棵完全二叉树**，因此**适合顺序存储**：下标从 1 开始时，$i$ 的左孩子 $2i$、右孩子 $2i+1$、双亲 $\lfloor i/2\rfloor$；
2. **堆不是二叉排序树**：堆只要求「父不小于（不大于）孩子」，不要求「左子树全小于根、右子树全大于根」，因此中序遍历**不有序**；
3. **大根堆的次大值一定在根的下一层**（即根的左孩子或右孩子之一，或两者）；同理小根堆的次小值也必在根的孩子中。
:::

```c
#define MAXSIZE 100

typedef struct {
    int elem[MAXSIZE];   // 下标从 1 开始存储，elem[0] 不用
    int n;               // 元素个数
} Heap;
```

#### 2. 建堆：Floyd 自下而上算法 $O(n)$

**关键点**：**一次性先把整个序列按层序摆成完全二叉树，然后从最后一个非叶结点开始向前逐个「下坠调整」，而不是一个一个插入。** 这是考试与代码实现的分水岭。

```c
// 对以 k 为根的子树进行「下坠」调整（大根堆）
void SiftDown(Heap &H, int k) {
    H.elem[0] = H.elem[k];                       // 暂存待调整的根
    int i = k;
    for (int j = 2 * i; j <= H.n; j = 2 * i) {   // 沿关键字较大的孩子往下
        if (j < H.n && H.elem[j] < H.elem[j + 1]) j++;   // j 指向较大的孩子
        if (H.elem[0] >= H.elem[j]) break;       // 已满足大根堆，结束
        H.elem[i] = H.elem[j];                   // 孩子上移
        i = j;
    }
    H.elem[i] = H.elem[0];                       // 就位
}

// 自下而上建堆（Floyd 算法）：时间 O(n)
void BuildHeap(Heap &H) {
    for (int i = H.n / 2; i >= 1; i--)   // 从最后一个非叶结点开始
        SiftDown(H, i);
}
```

:::key 为什么建堆是 $O(n)$ 而不是 $O(n\log_2 n)$
「下坠」的代价与**结点所在高度**成正比。自下而上建堆时，绝大多数结点在底层，下坠距离很短：

- 高度为 $h$ 的结点约有 $n/2^{h+1}$ 个，每个下坠至多 $h$ 层；
- 总代价 $\le\sum\limits_{h=0}^{\lfloor\log_2 n\rfloor}\dfrac{n}{2^{h+1}}\cdot h<2n=O(n)$。

对比：如果从空堆开始**逐个插入**建堆，每个元素平均要上升 $O(\log_2 n)$，总代价 $O(n\log_2 n)$。**两种建堆方式得到的堆不一定相同。**
:::

:::warn 建堆的常见错误
1. **不要从最后一个结点开始**：叶子结点天然满足堆序，从 $n/2$ 开始（最后一个非叶结点）即可；
2. **下坠后要继续探测子树**：把根与较大孩子交换后，被交换的孩子所在的子树可能不再满足堆序，必须**继续沿该路径往下调整**；
3. **不要每交换一次就重新从头扫描**：正确的做法是沿着一条根到叶的路径一次下坠到底，代价 $O(\log_2 n)$。
:::

:::key 建堆比较次数的量级
自下而上建大根堆的过程中，**关键字比较次数最多约 $4n$，时间复杂度 $O(n)$**。这是统考中「建堆比较次数」问题的标准答案量级。
:::

#### 3. 插入元素（向上调整）

**步骤**：把新元素放到**最后（第 $n+1$ 个位置）**，然后沿双亲方向**向上调整**，直到满足堆序。

```c
// 大根堆插入：先放末尾，再向上调整
bool HeapInsert(Heap &H, int x) {
    if (H.n >= MAXSIZE - 1) return false;
    int i = ++H.n;
    H.elem[i] = x;
    while (i > 1 && H.elem[i] > H.elem[i / 2]) {  // 比双亲大就交换
        int tmp = H.elem[i];
        H.elem[i] = H.elem[i / 2];
        H.elem[i / 2] = tmp;
        i = i / 2;
    }
    return true;
}
```

:::key 插入的调整次数
插入时**只需与双亲比较，不需要和兄弟比较**（因为兄弟一定也满足与双亲的大小关系）。比较次数最多为树高 $-1$，即 $\lfloor\log_2 n\rfloor$，时间复杂度 $O(\log_2 n)$。

**这一点要和「排序时的取数调整」区分开**：排序时是从根往下与**孩子**比较（可能还要先比较两个孩子），每次下坠一层最多 2 次比较。
:::

**例**：小根堆 `8,15,10,21,34,16,12` 中插入 3。

第 9 个位置放 3，双亲为 $\lfloor9/2\rfloor=4$ 号元素 21：$3<21$，交换；3 到第 4 位，双亲为 2 号元素 15：$3<15$，交换；3 到第 2 位，双亲为 1 号元素 8：$3<8$，交换。最终根为 3。（2009 年形式）

**例**：大根堆 `25,13,10,12,9` 尾部插入 18，比较次数是多少？

18 放第 6 位，双亲 $6/2=3$ 号元素 10，比较 $18>10$ 交换（第 1 次）；18 到第 3 位，双亲为 1 号元素 25，比较 $18<25$ 停止（第 2 次）。**共 2 次比较。**（2011 年形式）

#### 4. 删除堆顶（向下调整）

**步骤**：取走堆顶（通常与**最后一个元素**交换后，令 $n$ 减 1），再把新的根**下坠调整**。

```c
// 大根堆删除堆顶：把末尾元素补到根，再下坠
bool HeapDeleteMax(Heap &H, int &x) {
    if (H.n == 0) return false;
    x = H.elem[1];
    H.elem[1] = H.elem[H.n--];   // 末尾元素补到根，堆规模减 1
    SiftDown(H, 1);
    return true;
}
```

:::key 删除的调整次数
从根下坠到叶子，最多走树高 $-1$ 层，每层最多 2 次关键字比较（先比两个孩子、再比孩子与根），时间复杂度 $O(\log_2 n)$。
:::

**例**：小根堆 `8,15,10,21,34,16,12` 删除 8 后的比较次数。

用末尾的 12 补到根，有效序列 `12,15,10,21,34,16`：

1. 比较根的两个孩子 15 与 10，选较小的 10（第 1 次）；
2. 比较 12 与 10，$12>10$ 交换（第 2 次）；
3. 12 下移到第 3 位，该位置只有左孩子 16：比较 12 与 16，$12<16$ 停止（第 3 次）。

**共 3 次比较。**（2015 年形式）

#### 5. 堆与堆排序

**堆排序（Heap Sort）** 的两阶段：

1. **建堆**：对 $n$ 个元素的序列自下而上建成大根堆（升序排序用大根堆），时间 $O(n)$；
2. **反复取数**：把堆顶（当前最大）与堆尾交换，堆规模减 1，再对新根下坠调整；重复 $n-1$ 次。每次调整 $O(\log_2 n)$，共 $O(n\log_2 n)$。

:::key 堆排序的时空特性
| 指标 | 值 |
|:---|:---|
| 建堆时间 | $O(n)$ |
| 单次调整 | $O(\log_2 n)$ |
| 总时间 | $O(n\log_2 n)$（最好、最坏、平均均如此） |
| 空间 | $O(1)$，仅需常数辅助空间 |
| 稳定性 | **不稳定**（建堆和堆顶、堆尾交换可能使相等元素跨越移动） |
| 适用存储 | **顺序表**，不适用于单链表 |

**每趟都能确定一个元素的最终位置**——堆排序和简单选择排序、快速排序一样，属于「每趟至少定位一个元素到最终位置」的排序。
:::

:::key 堆的两个实用特性
1. 适合在**海量数据中找出前 $k$ 大 / 前 $k$ 小**的元素（维护一个大小为 $k$ 的堆）；
2. 堆排序的左右子树调整**互不干扰**，可以并行执行。
:::

:::warn 堆排序不稳定的例子
原序列 `1 2 2`。建大根堆后两个 2 中的一个上到根；取数时先取出的必是根上的 2，剩下两个元素中原本在前的 1 反而先被取出，最终顺序变为 `1 2 2`（原来的第二个 2 排到了第一个 2 前面），**稳定性被破坏**。
:::

:::exam 真题考法
- 「逻辑上是完全二叉树」「可以顺序存储」正确，「可以看成二叉排序树」错误（2020 年形式）；
- 依次插入建堆与自下而上建堆结果**不一定相同**（2021 年形式特别注意）；
- 插入 / 删除时的**关键字比较次数**（2011、2015、2024 年形式）——必须逐步模拟；
- 堆排序与外部排序的关系：海量数据（远大于内存）的排序应采用**外部排序**（多路归并），堆排序虽能取前 $k$ 大但不适合整体外排。
:::

## 易错清单

1. **「树的高度」与「结点的深度 / 高度」混用**。深度从根往下数、高度从下往上数；树高 = 根的高度 = 最深层号。路径长度按**边数**计，不是结点数。

2. **「度为 $m$ 的树」当成「$m$ 叉树」**。前者非空且必须有度为 $m$ 的结点（至少 $m+1$ 个结点）；后者可以为空。

3. **顺序存储二叉树时只按结点数估算空间**。若题目强调「任意一棵」二叉树或给了高度，必须按**最深结点编号**（最坏情况 $2^h-1$）开空间。

4. **用「层序序列 + 空结点」反推二叉树时忘了校验双亲**。任何非空结点的双亲位置都必须非空，否则是悬空结点，该数组非法。

5. **误认为「先序 + 后序」能唯一确定二叉树**。只有**严格二叉树**才可以；一般情况会出现「单孩子结点在左还是在右」的歧义。

6. **误认为「先序序列相同 + 结点数相同」的二叉树个数可以随便猜**。答案就是卡特兰数 $\dfrac{1}{n+1}C_{2n}^{n}$；但问普通**树**的形态数时要换成 $t_n=b_{n-1}$。

7. **「先序 = 中序」误答成「结点的度均为 1」**。正确条件是**所有非叶结点只有右子树**（不存在左孩子），必须排除「只有左孩子」的情形。

8. **中序线索二叉树找前驱 / 后继时搞反「最左下」和「最右下」**。后继取右子树的**最左下**，前驱取左子树的**最右下**。

9. **先序线索化递归时不判断 `ltag` / `rtag`**，会顺着刚建立的线索走回祖先，造成**死循环**。

10. **误认为三种线索二叉树都能不用栈遍历**。后序线索二叉树**仍需栈**，因为无法判断是否已从右子树返回。

11. **误认为三种线索二叉树都能直接找前驱和后继**。口诀：**中序两全、先序缺前驱、后序缺后继**；缺的那一侧必须借助三叉链表（`parent`）或从头遍历。

12. **线索二叉树不带头结点时忘了处理首尾**。中序第一个结点的左线索、最后一个结点的右线索应指向 `NULL`；带头结点时则指向头结点，构成双向线索链表。

13. **森林转二叉树后「无右孩子结点数」漏掉 +1**。$n$ 个分支结点贡献 $n$ 个「最右孩子」，还要加上**最后一棵树的根**（它没有兄弟），共 $n+1$。

14. **混淆「森林的叶子数」与二叉树中哪种空指针对应**。森林叶子数 = 二叉树中**左孩子为空**的结点数（不是右孩子为空）。

15. **树 / 森林遍历与二叉树遍历的对应关系记混**。口诀「先对先，后对中」：先根 / 先序 ↔ 二叉树**先序**；后根 / 中序 ↔ 二叉树**中序**。

16. **哈夫曼树当成完全二叉树**。哈夫曼树是**严格二叉树**（无度为 1 的结点），但不一定完全。

17. **构造 $m$ 叉哈夫曼树时忘记补虚结点**。判据是 $(n_0-1)\bmod(m-1)$ 是否为 0；补 $m-1-t$ 个**权为 0**的结点。虚结点不影响 WPL。

18. **WPL 把内部结点也乘路径长度算进去**。WPL 只累加**叶子**；反过来，用「所有**非叶**结点权值之和」也能算出同一个 WPL（哈夫曼树特有两算法）。

19. **把「编码不唯一」和「WPL 不唯一」混为一谈**。哈夫曼树形态不唯一 → 编码不唯一；但 **WPL（总编码长度）唯一且最小**。

20. **插入堆和删除堆的调整方向搞反**。**插入向上调（只与双亲比）**，**删除堆顶向下调（要先比两个孩子）**。

21. **建堆时从最后一个结点开始，或每交换一次就重新扫描整个数组**。正确做法是从 $i=\lfloor n/2\rfloor$ 开始向前，每个结点沿一条路径**一次下坠到底**，总代价 $O(n)$。

22. **认为「逐个插入建堆」与「自下而上建堆」结果相同**。二者得到的堆**不一定相同**，且前者时间 $O(n\log_2 n)$、后者 $O(n)$。

23. **并查集按大小合并时比较方向写反**。根结点的值是**负数**，`S[Root1]`、`S[Root2]` 中**绝对值更大的是更大的集合**，应把小的挂到大的下面。

24. **误认为路径压缩能保证树高 $O(\log_2 n)$**。树高上界来自**按秩合并**；只做路径压缩时单次最坏仍可能是 $O(n)$。

25. **误认为并查集支持高效的集合拆分**。并查集只擅长「合并」与「查询」，不支持拆分。

26. **在 Kruskal 中把并查集的作用说成「排序」或「求最短路径」**。并查集的唯一作用是**判断新加入的边是否会与已选边构成环**；排序是排序算法的工作。
