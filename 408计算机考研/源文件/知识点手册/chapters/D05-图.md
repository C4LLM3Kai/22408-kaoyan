## 五、图

### （一）图的基本概念

#### 1. 图、有向图与无向图

**图（Graph）** 由**顶点集**（Vertex）和**边集**（Edge）组成，记为 $G=(V,E)$。其中 $V$ 是顶点的有限**非空**集合，$E$ 是顶点之间关系的集合。$|V|$ 表示顶点个数，称为图的**阶**；$|E|$ 表示边的条数。要注意图与线性表、树的区别：**线性表可以是空表，树可以是空树，但图不能为空图**，$V$ 一定是非空集（$E$ 可以为空）。

**无向图**（undirected graph）：$E$ 是无向边的有限集合。无向边是顶点的**无序对**，记为 $(v,w)$ 或 $(w,v)$，二者表示同一条边。

**有向图**（directed graph，digraph）：$E$ 是有向边的有限集合。有向边又称**弧**（arc），是顶点的**有序对**，记为 $<v,w>$，其中 $v$ 称为**弧尾**（tail，起点），$w$ 称为**弧头**（head，终点），读作「从 $v$ 到 $w$ 的弧」。显然 $<v,w>\neq<w,v>$。

**邻接**（adjacent）：两顶点之间存在边时称二者邻接。在有向图中要说清方向——$<v,w>$ 表示 $v$ 邻接到 $w$，$w$ 邻接自 $v$。

**简单图**与**多重图**：

1. **简单图**：不存在重复边，也不存在顶点到自身的边（自环）。
2. **多重图**：某两个顶点之间的边数多于一条，或允许顶点通过同一条边与自身关联。

数据结构课程中**只讨论简单图**，后文若不特别说明，「图」一律指简单图。

**带权图（网）**：每条边都标有表示某种含义的数值，该数值称为**权值**（weight）或**代价**（cost），这样的图称为带权图，也叫**网**（network）。一条路径上所有边的权值之和称为该路径的**带权路径长度**。

#### 2. 完全图、稠密图与稀疏图

**完全图**是边数达到上限的简单图：

- **无向完全图**：任意两个顶点之间都存在边，边数为 $\dfrac{n(n-1)}{2}$。
- **有向完全图**：任意两个顶点之间都存在方向相反的两条弧，边数为 $n(n-1)$。

由此可得普通简单图的边数取值范围：$n$ 个顶点的无向图满足 $0\le e\le \dfrac{n(n-1)}{2}$；有向图满足 $0\le e\le n(n-1)$。

:::key 边数上下界（必背）

| 条件 | 边数 |
|---|---|
| $n$ 个顶点的无向图，$e$ 的范围 | $0\le e\le n(n-1)/2$ |
| $n$ 个顶点的有向图，$e$ 的范围 | $0\le e\le n(n-1)$ |
| $n$ 个顶点的**连通**无向图，$e$ **最少** | $n-1$（即生成树） |
| $n$ 个顶点的**非连通**无向图，$e$ **最多** | $\dfrac{(n-1)(n-2)}{2}$，即 $C_{n-1}^{2}$ |
| $n$ 个顶点的**强连通**有向图，$e$ **最少** | $n$（构成一个环） |

「非连通图最多 $C_{n-1}^{2}$ 条边」的含义是：把 $n-1$ 个顶点凑成一个完全图，剩下 1 个顶点孤立，此时边数最多而图仍不连通。

:::

**稠密图**与**稀疏图**：边数很少的图称为稀疏图，边数很多的图称为稠密图。二者**没有绝对的界限**，一般把满足 $|E|<|V|\log|V|$ 的图视为稀疏图。这个区分直接决定了应该用邻接矩阵还是邻接表存储，以及应该用 Prim 还是 Kruskal 求最小生成树。

#### 3. 度、入度、出度与握手定理

**无向图的度**：顶点 $v$ 的度 $TD(v)$ 是指依附于该顶点的边的条数。

**有向图的度**：以 $v$ 为**终点**的弧的数目称为**入度** $ID(v)$，以 $v$ 为**起点**的弧的数目称为**出度** $OD(v)$，二者之和为 $v$ 的度：

$$TD(v)=ID(v)+OD(v)$$

**握手定理（度的总和）**：在具有 $n$ 个顶点、$e$ 条边的无向图中

$$\sum_{i=1}^{n} TD(v_i)=2e$$

即**无向图全部顶点的度数之和等于边数的 2 倍**，因为每条边给两个端点各贡献 1 度。

在有向图中，每条弧给一个起点贡献出度、给一个终点贡献入度，因此

$$\sum_{i=1}^{n} ID(v_i)=\sum_{i=1}^{n} OD(v_i)=e$$

:::warn 由握手定理推出的两个高频结论

1. **无向图中度为奇数的顶点个数一定是偶数。** 因为总度数是偶数，其中偶数度顶点贡献偶数，所以奇数度顶点必须两两配对成偶数个。
2. **无论有向图还是无向图，全部顶点的度数之和都是 $2e$**（有向图中「度」按入度加出度理解）。做题时若已知部分顶点的度数，用这条等式可以反推剩余顶点的度数。

:::

#### 4. 路径、回路、简单路径与距离

- **路径**（path）：顶点 $v_p$ 到 $v_q$ 之间的一条路径是指顶点序列 $v_p,v_{i1},v_{i2},\cdots,v_{im},v_q$。有向图中的路径必须沿弧的方向走。
- **回路**（环，cycle）：第一个顶点和最后一个顶点相同的路径。
- **简单路径**（simple path）：路径序列中**顶点不重复出现**的路径。
- **简单回路**：除第一个顶点和最后一个顶点外，**其余顶点不重复出现**的回路。
- **路径长度**：路径上**边的数目**（不是权值之和）。
- **点到点的距离**：从 $u$ 到 $v$ 的最短路径的长度；若不存在路径，距离记为 $\infty$。

:::warn 「回路」与「简单路径」的关系

**回路不是简单路径**。简单路径要求所有顶点互不重复，而回路的首尾顶点必然相同，本身就已经重复了。类似地要区分「简单回路」的定义：只允许首尾顶点重复，中间顶点不允许重复。做题时把「顶点不重复」当成唯一判据就不会错。

:::

#### 5. 连通性：连通、强连通、连通分量

**无向图的连通性**：

- **连通**：无向图中若从顶点 $v$ 到顶点 $w$ 有路径存在，则称 $v$ 和 $w$ 是连通的。
- **连通图**：无向图中任意两个顶点都是连通的，则称该图为连通图。
- **连通分量**（connected component）：无向图中的**极大连通子图**。「极大」的含义是：子图必须连通，并且包含尽可能多的顶点和边；只要还能再加进一个原图中的顶点（及关联边）而不破坏连通性，就不算极大。

**有向图的连通性**：

- **强连通**：有向图中若从 $v$ 到 $w$、从 $w$ 到 $v$ **都有路径**，则称 $v$ 与 $w$ 强连通。
- **强连通图**：有向图中任何一对顶点都强连通。
- **强连通分量**：有向图中的**极大强连通子图**。

:::key 连通分量的三点判别

1. 一个连通图的连通分量只有 1 个，就是它自己；非连通图至少有 2 个连通分量。
2. **极大连通子图**强调「极大」，不是「最大」。一个包含 3 个顶点的连通分量和一个包含 5 个顶点的连通分量可以同时存在，二者都是极大的。
3. 孤立顶点（度数为 0 的顶点）本身就是一个连通分量，因为它无法再与任何顶点构成连通子图。

:::

#### 6. 子图、生成子图与生成树

**子图**：设有图 $G=(V,E)$ 和 $G'=(V',E')$，若 $V'$ 是 $V$ 的子集且 $E'$ 是 $E$ 的子集，则称 $G'$ 是 $G$ 的子图。

**生成子图**：若子图 $G'$ 满足 $V(G')=V(G)$（顶点集与原图完全相同），则称 $G'$ 是 $G$ 的生成子图。注意「子图」不要求顶点齐全，「生成子图」要求顶点一个不少。

**生成树**：连通图的生成树是**包含图中全部顶点的一个极小连通子图**。「极小」的含义是：边尽可能少，但必须保持连通。

生成树的三条必用性质：

1. $n$ 个顶点的连通图，其生成树**恰好含有 $n-1$ 条边**。
2. 生成树中任意两个顶点之间有**且仅有**一条通路。
3. 对生成树而言，**砍去一条边就变成非连通图，加上一条边就会形成一个回路**。

**生成森林**：非连通图中，各个连通分量的生成树构成该图的生成森林。

推论：$n$ 个顶点的图，如果边数大于 $n-1$，则**一定含有回路**。反过来，边数恰为 $n-1$ 且连通，则必是一棵树。

**为什么生成树恰好是 $n-1$ 条边？** 这可以从两个方向理解。一方面，要让 $n$ 个顶点全部连通，至少需要 $n-1$ 条边（每加一条边最多把两个尚未连通的「块」连起来，从 $n$ 个孤立的块合并成 1 个块需要 $n-1$ 次合并）；另一方面，一旦边数达到 $n$ 条，由「边数大于 $n-1$ 必有回路」可知此时必然出现回路，就不再是极小连通子图。两条合起来就锁定了 $n-1$ 这个数字。生成树的三条性质——边数恰为 $n-1$、任意两点间有且仅有一条通路、删一边即不连通加一边即出回路——其实是同一件事的三种说法，考试中经常把它们打散成判断题来考。

由「极小」与「极大」这一对概念还可以串起本章最容易混的三个术语：**连通分量是极大连通子图**（边尽量多、点尽量多，但不破坏连通性）；**生成树是极小连通子图**（点一个不少，边尽量少）；**最小生成树是代价最小的生成树**（在生成树这个大集合里，再按权值之和挑最小的）。三者都涉及「子图」，但一个求极大、一个求极小、一个求最优，考纲把它们放在不同条目下，答题时务必对号入座。

**树**：不存在回路且连通的无向图。因此 $n$ 个顶点的树必定有 $n-1$ 条边。

**有向树**：一个顶点入度为 0、其余顶点入度均为 1 的有向图。

#### 7. 图的基本概念小结

| 概念 | 无向图 | 有向图 |
|---|---|---|
| 边的记法 | $(v,w)$，无序对 | $<v,w>$，有序对，$v$ 弧尾、$w$ 弧头 |
| 完全图边数 | $n(n-1)/2$ | $n(n-1)$ |
| 顶点的度 | $TD(v)$ 为依附边数 | $TD(v)=ID(v)+OD(v)$ |
| 度数总和 | $\sum TD(v)=2e$ | $\sum ID(v)=\sum OD(v)=e$ |
| 连通性术语 | 连通、连通图、连通分量 | 强连通、强连通图、强连通分量 |
| 连通所需最少边数 | $n-1$ | $n$ |
| 生成树 | 有（仅连通图有） | 无（有向图讲生成树需先转成无向图） |

### （二）图的存储及基本操作

#### 1. 邻接矩阵

**邻接矩阵**（adjacency matrix）用一个 $n\times n$ 的矩阵表示图。设矩阵为 $A$、顶点表为 $V$，则 $A[i][j]=1$ 表示顶点 $V[i]$ 到 $V[j]$ 之间存在边，$A[i][j]=0$ 表示无边。

```c
#define MAXV 100          // 顶点数目的最大值

typedef struct {
    int numVertices;          // 图中实际的顶点数
    int numEdges;             // 图中实际的边数
    char vertexList[MAXV];    // 顶点表
    int edges[MAXV][MAXV];    // 邻接矩阵
} MGraph;
```

**核心性质（必背）**：

1. 主对角线元素没有意义，因为简单图不允许自环。
2. **无向图的邻接矩阵关于主对角线对称**，即 $A[i][j]=A[j][i]$。因此可以只存上三角或下三角区，把空间压缩到约 $n(n+1)/2$ 个元素，对应一维数组下标 $k=n\cdot i-\dfrac{i(i-1)}{2}+(j-i)$（行优先、含主对角线）。
3. 无向图中，**第 $i$ 个顶点的度 = 第 $i$ 行（或第 $i$ 列）的非零元素个数**。
4. 有向图中遵循「**行出列入**」：第 $i$ 个顶点的**出度 = 第 $i$ 行的非零元素个数**，**入度 = 第 $i$ 列的非零元素个数**。

因此在邻接矩阵上求某个顶点的度、出度、入度，都需要扫描一整行或一整列，时间复杂度为 $O(|V|)$。

```c
// 计算顶点 V 的出度（行内非零元素个数）
int OutDegree(MGraph graph, int index) {
    int count = 0;
    for (int j = 0; j < graph.numVertices; ++j) {
        if (graph.edges[index][j] != 0) count++;
    }
    return count;
}

// 计算顶点 V 的入度（列内非零元素个数）
int InDegree(MGraph graph, int index) {
    int count = 0;
    for (int i = 0; i < graph.numVertices; ++i) {
        if (graph.edges[i][index] != 0) count++;
    }
    return count;
}
```

**带权邻接矩阵（网）**：把矩阵元素从 $0/1$ 换成权值。$A[i][j]=k$ 表示从 $V[i]$ 到 $V[j]$ 的边存在且权值为 $k$；$A[i][j]=\infty$（代码中常写 `INT_MAX` 或约定的大数）表示两顶点之间无边。**主对角线元素通常置 0**（自己到自己的距离为 0），也可以置 $\infty$，两种约定统考都出现过，解题时按题目给定的矩阵读即可。

```c
// 带权图的邻接矩阵初始化（无向网）
void initWeightedMatrix(int n, int edges[][MAXV]) {
    for (int i = 0; i < n; ++i)
        for (int j = 0; j < n; ++j)
            edges[i][j] = (i == j) ? 0 : INT_MAX;   // 对角线 0，其余无穷表示无边
}
```

**空间与效率**：邻接矩阵的空间复杂度为 $O(|V|^2)$，与边数无关，因此适合存储**稠密图**。由于可以直接下标寻址，**增删改查一条边的时间复杂度都是 $O(1)$**。代价是当图很稀疏时会浪费大量空间。

**什么时候该用邻接矩阵？** 判断依据只有一条：边数是否接近 $n^2$ 量级。若图是稠密的（例如 $e$ 与 $n(n-1)/2$ 同阶），邻接矩阵不浪费空间，同时还能享受 $O(1)$ 判边、$O(1)$ 改边、天然对称性、以及「用矩阵幂数路径」这些便利；若图是稀疏的（例如 $e$ 与 $n$ 同阶，像道路网、程序调用图），邻接表只花 $O(n+e)$ 空间，而邻接矩阵仍要老老实实开 $n^2$ 个单元。考试中常把这一点包装成一句叙述让你判断对错，记住「邻接矩阵的空间代价只与顶点数有关，与边数无关」这一句就足以应对。

:::key 邻接矩阵的幂与路径数目

设图 $G$ 的邻接矩阵为 $A$（元素为 $0/1$），则 $A^{n}$ 的元素 $A^{n}[i][j]$ **等于由顶点 $i$ 到顶点 $j$ 的长度为 $n$ 的路径的数目**。这个结论对无向图和有向图都成立。

用法：题目给出邻接矩阵让你求 $\sum_i A^{2}[i][i]$（即 2 步回路的数目）、或者判断两点间是否存在长度为 2 的路径时，只需做一次矩阵乘法。注意 $A^{2}[i][j]=\sum_{k}A[i][k]\cdot A[k][j]$，本质上就是枚举中转顶点 $k$，这与 Floyd 算法的思想一脉相承。

:::

#### 2. 邻接表

**邻接表**（adjacency list）对图中每个顶点 $v_i$ 建立一个**单链表**，第 $i$ 个单链表的结点表示依附于 $v_i$ 的边（对有向图则是以 $v_i$ 为弧尾的弧），这个单链表称为顶点 $v_i$ 的**边表**（有向图中称为**出边表**）。

边表的头指针和顶点数据采用**顺序存储**，称为**顶点表**。因此邻接表中存在两种结点：**顶点表结点**和**边表结点**，这一点可以与树的**孩子表示法**对比记忆。

```c
#define MAXV 1000                 // 顶点数目的最大值

typedef struct ArcNode {          // 边表结点
    int adjvex;                   // 该弧所指向的顶点在顶点表中的下标
    struct ArcNode *next;         // 指向下一条弧的指针
    // int info;                  // 网中可加边权值
} ArcNode;

typedef struct VNode {            // 顶点表结点
    char data;                    // 顶点信息
    ArcNode *firstarc;            // 指向第一条依附于该顶点的弧
} VNode, AdjList[MAXV];

typedef struct {
    int numVertices, numEdges;    // 图中实际的顶点数和边数
    AdjList vertices;             // 顶点表
} ALGraph;
```

**空间复杂度**：

- **无向图**：每条边 $(v,w)$ 在 $v$ 的表和 $w$ 的表中各存一次，边结点总数为 $2|E|$，空间复杂度 $O(|V|+2|E|)$。
- **有向图**：只记录出边，边结点总数为 $|E|$，空间复杂度 $O(|V|+|E|)$。

邻接表只存实际存在的边，因此适合存储**稀疏图**。代价是查找一条边需要遍历链表，时间效率不如邻接矩阵。

**有向图的出度与入度**：

- **出度**很容易求：找到该顶点，数它所在链表中的结点个数即可，时间复杂度 $O(1)$（定位）+ $O(d)$（数链）。
- **入度**很麻烦，因为邻接表只记出边。两种方法：
  1. 遍历整个顶点表的所有链表，统计 `adjvex` 等于目标顶点下标的结点个数，时间复杂度 $O(|V|+|E|)$。
  2. 建立**逆邻接表**——每个顶点的链表中记录的是**以该顶点为弧头**的弧。逆邻接表求出度难、求入度容易，正好与邻接表互补。

```c
// 邻接表上求某顶点入度：需要遍历所有顶点的链表
int InDegree(ALGraph graph, int index) {
    int count = 0;
    for (int j = 0; j < graph.numVertices; ++j) {
        for (ArcNode *p = graph.vertices[j].firstarc; p; p = p->next) {
            if (p->adjvex == index) count++;
        }
    }
    return count;
}
```

:::warn 邻接表表示不唯一

**用邻接矩阵存储图，其表示方法是唯一的；用邻接表存储图，其表示方法不唯一。** 因为各条边在单链表中的次序可以任意（头插、尾插、按编号排序都合法）。这一条直接导致后面「邻接表存储时 DFS/BFS 遍历序列不唯一、生成树不唯一」的结论，是选择题的常考陷阱。

:::

#### 3. 十字链表（有向图）

用邻接表存有向图能快速求出度但求入度难，用逆邻接表则相反。**十字链表**（orthogonal list）是一种同时能快速求入度和出度的有向图存储结构。

**核心思想**：把所有顶点存到顺序表中，同时为每个顶点配备**两个链表**——一个链表记录以当前顶点为**弧头**的弧，另一个链表记录以当前顶点为**弧尾**的弧。

- 顶点表结点：`data` 存顶点信息；`firstin` 指向以该顶点为弧头的第一条弧；`firstout` 指向以该顶点为弧尾的第一条弧。
- 边表结点：`tailvex` 存弧尾顶点在顶点表中的下标；`headvex` 存弧头顶点的下标；`hlink` 指向弧头相同的下一条弧；`tlink` 指向弧尾相同的下一条弧；`info` 可存权值。

```c
#define MAXV 1000
typedef struct ArcNode {          // 边表结点
    int tailvex, headvex;         // 该弧的弧尾、弧头顶点在顶点表中的下标
    struct ArcNode *hlink, *tlink;// 分别指向弧头相同、弧尾相同的下一条弧
    // int info;                  // 网中可加边权值
} ArcNode;

typedef struct VNode {            // 顶点表头结点
    char data;                    // 顶点信息
    ArcNode *firstin, *firstout;  // 分别指向第一条入弧、第一条出弧
} VNode, XJList[MAXV];

typedef struct {
    int numVertices, numEdges;
    XJList vertices;
} OLGraph;                        // 十字链表
```

**手工理解十字链表的走法**：以 $<A,B>$ 和 $<A,C>$、$<C,A>$ 和 $<D,A>$ 为例（$A,B,C,D$ 编号为 $0,1,2,3$）：

1. 对 $<A,B>$、$<A,C>$，$A$ 是弧尾，$B$、$C$ 是弧头。顶点表 $A$ 的 `firstout` 指向以 $A$ 为弧尾的第一条弧（即边结点 $B$），边结点 $B$ 的 `tlink` 指向弧尾相同的下一条弧（边结点 $C$），$C$ 的 `tlink` 为空。
2. 对 $<C,A>$、$<D,A>$，$A$ 是弧头。顶点表 $A$ 的 `firstin` 指向以 $A$ 为弧头的第一条弧（边结点 $C$），$C$ 的 `hlink` 指向弧头相同的下一条弧（边结点 $D$），$D$ 的 `hlink` 为空。

因此：

- **沿 `tlink` 链遍历，可找到指定顶点的所有出边**；统计该链的结点数即为**出度**。
- **沿 `hlink` 链遍历，可找到指定顶点的所有入边**；统计该链的结点数即为**入度**。

十字链表的空间复杂度为 $O(|V|+|E|)$，因为每条弧只对应一个边表结点。

#### 4. 邻接多重表（无向图）

无向图中 $(V_i,V_j)$ 与 $(V_j,V_i)$ 是同一条边，但在**邻接表中每条边都要存两份**。如果需要对无向图的边做大量插入、删除操作，邻接表就得处理两次，效率低下。**邻接多重表**（adjacency multilist）就是为解决这个问题而设计的无向图存储结构。

**核心思想**：所有顶点存到顺序表中，每个顶点配备一个链表，**链表的每个结点代表一条与当前顶点直接关联的边**——注意是「一条边一个结点」，而不是「一条边两个结点」。

- 顶点结点：`data` 存顶点数据；`firstedge` 指向依附于该顶点的第一条边。
- 边结点：`i`、`j` 分别存边两端顶点在顶点表中的下标；`ilink` 指向下一条依附于顶点 `i` 的边；`jlink` 指向下一条依附于顶点 `j` 的边；`info` 可存权值。

```c
#define MAXV 1000
typedef struct ArcNode {          // 边结点
    int i, j;                     // 边的两个端点在顶点表中的下标
    struct ArcNode *ilink, *jlink;// 分别指向依附于 i、j 的下一条边
    // int info;                  // 网中可加边权值
} ArcNode;

typedef struct VNode {            // 顶点表头结点
    char data;
    ArcNode *firstedge;           // 指向与该顶点相连的第一条边
} VNode, AdjMuList[MAXV];

typedef struct {
    int numVertices, numEdges;
    AdjMuList vertices;
} AMLGraph;                       // 邻接多重表
```

**查找与某顶点关联的所有边**（以 $A$ 为例）：

1. 由 $A$ 的 `firstedge` 找到第一条与 $A$ 关联的边结点 $(A,B)$。
2. 该边结点的 `i` 域存的是 $A$ 的下标，因此沿 `ilink` 找到下一条边结点 $(A,D)$。
3. $(A,D)$ 的 `i` 域仍是 $A$ 的下标，但其 `ilink` 为空，查找结束。

**邻接多重表与邻接表最大的不同**：无向图中每条边在邻接表要存两份，在邻接多重表只存一份，因此**删除边、删除顶点等操作只需修改指针即可，非常方便**。空间复杂度 $O(|V|+|E|)$。

:::warn 删除顶点时别以为「方便」就等于 $O(1)$

在十字链表和邻接多重表中，一个边结点可能同时被两个顶点的指针链引用。删除顶点时，我们能轻易定位到该顶点关联的边，但**不知道该边结点另一端可能存在的另一个前驱指针在哪**，仍需遍历，最坏时间复杂度为 $O(|V|+|E|)$。只有在「已知边结点的前驱位置」时才能做到 $O(1)$。

:::

#### 5. 四种存储结构的对比

| 比较项 | 邻接矩阵 | 邻接表 | 十字链表 | 邻接多重表 |
|---|---|---|---|---|
| 适用对象 | 稠密图（有向、无向均可） | 稀疏图（有向、无向均可） | 仅**有向图** | 仅**无向图** |
| 空间复杂度 | $O(\lvert V\rvert^{2})$ | 无向：$O(\lvert V\rvert+2\lvert E\rvert)$；有向：$O(\lvert V\rvert+\lvert E\rvert)$ | $O(\lvert V\rvert+\lvert E\rvert)$ | $O(\lvert V\rvert+\lvert E\rvert)$ |
| 每条边存储份数 | 无向图存 2 份（对称） | 无向图存 2 份 | 1 份 | 1 份 |
| 求某顶点出度 | $O(\lvert V\rvert)$ | 容易，$O(1)+O(d)$ | 容易，沿 `tlink` 链 | 无向图不区分出/入度 |
| 求某顶点入度 | $O(\lvert V\rvert)$ | 难，需遍历整个邻接表 | 容易，沿 `hlink` 链 | 无向图不区分出/入度 |
| 找相邻边 | 遍历对应行或列，$O(\lvert V\rvert)$ | 遍历该顶点的边表 | 很方便 | 很方便 |
| 删除一条边 | 很方便，$O(1)$ | 需定位前驱，$O(1)\sim O(\lvert V\rvert)$ | 较方便 | 方便 |
| 删除一个顶点 | 需处理行与列，$O(\lvert V\rvert)$（若要求紧凑移动则 $O(\lvert V\rvert^{2})$） | 无向图不方便 | 不方便 | 方便 |
| 表示是否唯一 | **唯一** | 不唯一 | 不唯一 | 不唯一 |

#### 6. 图的基本操作

考纲「图的存储及基本操作」要求掌握以下接口，并能说出它们在两种主要存储结构下的时间代价：

| 操作 | 含义 | 邻接矩阵 | 邻接表 |
|---|---|---|---|
| `Adjacent(G,x,y)` | 判断是否存在边 $(x,y)$ 或弧 $<x,y>$ | $O(1)$ | $O(1)\sim O(\lvert V\rvert)$ |
| `Neighbors(G,x)` | 列出与 $x$ 邻接的顶点 | $O(\lvert V\rvert)$ | 无向图 $O(1)\sim O(\lvert V\rvert)$；有向图出边易、入边难 $O(\lvert V\rvert+\lvert E\rvert)$ |
| `InsertVertex(G,x)` | 插入顶点 $x$ | $O(1)$ | $O(1)$ |
| `DeleteVertex(G,x)` | 删除顶点 $x$ | $O(\lvert V\rvert)$，需将该行该列清零 | 无向图 $O(\lvert V\rvert+\lvert E\rvert)$ |
| `AddEdge(G,x,y)` | 若无边则插入 | $O(1)$ | $O(1)$（头插法） |
| `RemoveEdge(G,x,y)` | 若有边则删除 | $O(1)$ | $O(1)\sim O(\lvert V\rvert)$ |
| `FirstNeighbor(G,x)` | 求 $x$ 的第一个邻接点 | $O(\lvert V\rvert)$ | $O(1)$ |
| `NextNeighbor(G,x,y)` | 求 $x$ 在 $y$ 之后的下一个邻接点 | $O(\lvert V\rvert)$ | $O(1)$ |

其中 `FirstNeighbor` 与 `NextNeighbor` 是遍历算法的基础原语。它们的语义是：`FirstNeighbor(G,x)` 返回 $x$ 的第一个邻接点编号，不存在则返回 $-1$；`NextNeighbor(G,x,y)` 返回在 $y$ 之后的下一个 $x$ 的邻接点，不存在则返回 $-1$。有了这两个函数，图的遍历就可以写成与存储结构无关的代码。

```c
// 邻接矩阵版：求顶点 v 的第一个邻接点
int FirstNeighbor(MGraph *G, int v) {
    for (int i = 0; i < G->numVertices; ++i)
        if (G->edges[v][i]) return i;
    return -1;
}

// 邻接矩阵版：求顶点 v 在 w 之后的下一个邻接点
int NextNeighbor(MGraph *G, int v, int w) {
    for (int i = w + 1; i < G->numVertices; ++i)
        if (G->edges[v][i]) return i;
    return -1;
}
```

:::exam 出题角度

邻接矩阵与邻接表的存储结构是本章考查次数最多的知识点（历年统考中出现 8 次以上）。常见问法：(1) 给出邻接矩阵，求各顶点的度或入度出度（如按「行出列入」直接数）；(2) 给出邻接表，问求某顶点入度需要多少时间、或问「用邻接表存储的无向图，边结点个数是多少」（答 $2e$）；(3) 判断关于存储结构的叙述正误，典型正确项是「邻接矩阵表示唯一、邻接表表示不唯一」，典型错误项是「存储稀疏图用邻接矩阵比邻接表更省空间」。(4) 给出邻接多重表的示意图，直接问某两个顶点的度——此时要注意每条边只算一次，但每个顶点在边结点中出现的次数就是它的度。

:::

### （三）图的遍历

**图的遍历**是指从某个顶点出发，沿图中的边依次访问每个顶点，**确保每个顶点都只访问一次**。为避免重复访问，需要设置一个 `visited` 数组标记顶点是否已被访问。从某个顶点出发一次遍历只能访问到与它连通的所有顶点，因此对非连通图必须从多个起点出发，调用次数就是连通分量数。

#### 1. 深度优先搜索（DFS）

**深度优先搜索**（Depth First Search，DFS）是一种「**优先走到底、无路可走再回头**」的遍历方式：从某顶点出发，访问它的一个邻接顶点，再从这个邻接顶点继续深入，直到走到尽头时回溯，再换一条没走过的分支继续深入，直到所有顶点都被访问。

**递归实现**：

```c
bool visited[MAXV];

void visit(char v) { printf("%c ", v); }

// 从顶点 v 出发对图 G 做深度优先遍历
void DFS(ALGraph G, int v) {
    visit(G.vertices[v].data);       // 访问顶点 v
    visited[v] = true;               // 标记已访问
    for (ArcNode *p = G.vertices[v].firstarc; p; p = p->next) {
        if (!visited[p->adjvex])     // 邻接点未访问过则继续深入
            DFS(G, p->adjvex);
    }
}

// 遍历整张图（处理非连通图）
void DFSTraverse(ALGraph G) {
    for (int i = 0; i < G.numVertices; ++i) visited[i] = false;
    for (int i = 0; i < G.numVertices; ++i)
        if (!visited[i]) DFS(G, i);   // 每调用一次，就找到一个连通分量
}
```

**非递归实现**（借助显式栈）：递归的本质是系统栈，改成显式栈即可。

```c
// 深度优先遍历的非递归实现（显式栈）
void DFS_NonRecursive(ALGraph G, int v) {
    int stack[MAXV], top = -1;
    stack[++top] = v;                // 起点入栈
    while (top >= 0) {
        int cur = stack[top--];      // 弹出一个顶点
        if (visited[cur]) continue;  // 可能被重复压栈，需判重
        visit(G.vertices[cur].data);
        visited[cur] = true;
        // 邻接点全部压栈（压栈顺序决定遍历序列）
        for (ArcNode *p = G.vertices[cur].firstarc; p; p = p->next) {
            if (!visited[p->adjvex])
                stack[++top] = p->adjvex;
        }
    }
}
```

要特别注意：非递归版本中一个顶点可能被多次压栈，因此**弹出时必须再次检查 `visited`**，否则会重复访问。

**性能分析**：遍历时间 = 访问各顶点的时间 + 探索各条边的时间。

| 存储结构 | 访问顶点 | 探索边 | 总时间复杂度 | 空间复杂度 |
|---|---|---|---|---|
| 邻接矩阵 | $O(\lvert V\rvert)$ | 对每个顶点扫描一整行，共 $O(\lvert V\rvert^{2})$ | $O(\lvert V\rvert^{2})$ | $O(\lvert V\rvert)$（递归深度/栈） |
| 邻接表 | $O(\lvert V\rvert)$ | 每条边被访问 2 次（无向图），共 $O(\lvert E\rvert)$ | $O(\lvert V\rvert+\lvert E\rvert)$ | $O(\lvert V\rvert)$（`visited` 数组 + 递归栈） |

**深度优先生成树**：DFS 过程中经过的边（由「发现新顶点」的那条边构成，即 DFS 树边）和全部顶点组成**深度优先生成树**。对非连通图做 DFS，得到的是**深度优先生成森林**。

#### 2. 广度优先搜索（BFS）

**广度优先搜索**（Breadth First Search，BFS）是一种「**由近及远、层层扩张**」的遍历方式：从某顶点出发，先访问它的所有邻接顶点（第一层），再依次访问第一层各顶点的所有未访问邻接顶点（第二层），以此类推。BFS 借助**队列**实现——队列「先进先出」的性质正好对应「按发现的先后次序逐层处理」。

```c
void BFS(ALGraph G, int v) {
    int queue[MAXV], front = 0, rear = 0;
    visit(G.vertices[v].data);
    visited[v] = true;
    queue[rear++] = v;                       // 起点入队
    while (front < rear) {
        int cur = queue[front++];            // 队头出队
        for (ArcNode *p = G.vertices[cur].firstarc; p; p = p->next) {
            int w = p->adjvex;
            if (!visited[w]) {               // 未被访问过则访问并入队
                visit(G.vertices[w].data);
                visited[w] = true;           // 入队时立即标记，防止重复入队
                queue[rear++] = w;
            }
        }
    }
}

void BFSTraverse(ALGraph G) {
    for (int i = 0; i < G.numVertices; ++i) visited[i] = false;
    for (int i = 0; i < G.numVertices; ++i)
        if (!visited[i]) BFS(G, i);          // 每调用一次找到一个连通分量
}
```

:::warn BFS 中「标记」的位置

BFS 必须在**顶点入队的同时**就置 `visited = true`，而不能等到出队时再标记。否则同一个顶点可能被其多个邻接点先后发现并重复入队，导致队列中出现大量冗余元素，甚至死循环。DFS 中则是在**访问时**立即标记。

:::

**性能分析**：

- **空间复杂度**：两种存储结构都需要一个辅助队列，最坏情况下队列大小为 $O(|V|)$（例如所有顶点都与起点相邻）。
- **时间复杂度**：邻接矩阵为 $O(|V|)+O(|V|^{2})=O(|V|^{2})$；邻接表为 $O(|V|)+O(|E|)=O(|V|+|E|)$。

**广度优先生成树**：BFS 过程中「发现新顶点」的边与全部顶点构成**广度优先生成树**。非连通图的 BFS 得到**广度优先生成森林**。

**BFS 求无权图单源最短路径**：无权图可以看作所有边权都为 1 的带权图。BFS 按层扩展，**第一次访问到某顶点时经过的边数就是它到源点的最短距离**。

```c
// 从源点 u 出发求无权图单源最短路径
void BFSShortestPath(ALGraph G, int u, int d[], int path[]) {
    for (int i = 0; i < G.numVertices; ++i) {
        d[i] = -1; path[i] = -1; visited[i] = false;   // -1 表示不可达
    }
    int queue[MAXV], front = 0, rear = 0;
    d[u] = 0; visited[u] = true; path[u] = -1;
    queue[rear++] = u;
    while (front < rear) {
        int cur = queue[front++];
        for (ArcNode *p = G.vertices[cur].firstarc; p; p = p->next) {
            int w = p->adjvex;
            if (!visited[w]) {
                visited[w] = true;
                d[w] = d[cur] + 1;       // 层数加一即为最短距离
                path[w] = cur;           // 记录前驱，用于还原路径
                queue[rear++] = w;
            }
        }
    }
}
```

注意目的：`d[]` 存距离，`path[]` 存前驱。求 $u$ 到某顶点的具体路径时，从该顶点沿 `path` 反向回溯到 $u$ 再倒序输出即可。

#### 3. BFS 的「层次」与 Dijkstra 的异同

BFS 求无权图单源最短路径的做法，本质上是把图**按层切开**：源点是第 0 层，与源点直接相邻的顶点是第 1 层，再往外是第 2 层……顶点 $v$ 的层号就是它到源点的最短路径长度（以边数计）。Dijkstra 也有「逐轮确定一个顶点」的外壳，而且两者的算法骨架极其相似（都是**维护一个候选距离数组、每轮选出一个最小值、确定它、再用它去松弛邻居**），这正是考生最容易混淆的地方。二者的差异可以归结为三点。

第一，**距离的定义与累加方式不同**。BFS 中 `d[v] = d[u] + 1`，每条边的「代价」固定为 1，所以层号可以直接加一；Dijkstra 中 `dist[v] = dist[u] + w(u,v)`，必须把边权累加进去。正因为标量不同，BFS 可以只用一个整数计数器在层与层之间递增，而 Dijkstra 必须对每个顶点单独维护一个 `dist` 值。

第二，**能否「一次性确定」的依据不同**。BFS 能够一旦发现某顶点就认准它是最短路径，靠的是「所有边权相等」这一前提：先被发现的层号必然不大于后被发现的层号。Dijkstra 之所以能在每轮挑出 `dist` 最小的未确定顶点并宣布它已确定，靠的是「**所有边权非负**」这一前提：任何绕经其他未确定顶点的路径都不可能更短。一旦出现负权边，Dijkstra 的这个依据就崩掉了（见后文反例），而 BFS 的那一层保证也随之失效，因为一条「更深」的路径可能因为负权而总长更短。

第三，**是否保留「层次」这个中间概念**。BFS 天然产生一个层次结构，因此除了求距离，它还能直接用来判断二分图（按层交替染色）、求无权图的直径、做多源泛洪等；Dijkstra 不产生层次，它只输出一组距离值和一棵最短路径树。反过来，Dijkstra 能处理任意非负权值，而 BFS 面对「边权不相等」的图只能给出边数意义下的距离，与题目要求的最短路径无关。

一句话概括：**BFS 是「边权全为 1 时的 Dijkstra」，而 Dijkstra 是 BFS 在「边权非负但可能不等」时的推广。**

#### 4. 遍历手工模拟

设无向图 $G$ 有 6 个顶点 $1\sim 6$，边为 $1$–$2$、$1$–$3$、$2$–$4$、$3$–$5$、$4$–$5$、$5$–$6$，采用邻接表存储且每个顶点的边表都按顶点编号**升序**排列。分别从顶点 1 出发做 DFS 与 BFS：

| 步骤 | DFS（栈/递归） | BFS（队列） |
|---|---|---|
| 起始 | 访问 1 | 访问 1，队 = [1] |
| 第 1 步 | 1 的邻接点中最小未访问者为 2，访问 2 | 1 出队；邻接点 2、3 均未访问，访问 2、3，队 = [2,3] |
| 第 2 步 | 2 的邻接点 1 已访问，取 4，访问 4 | 2 出队；邻接点 1 已访问，4 未访问，访问 4，队 = [3,4] |
| 第 3 步 | 4 的邻接点 2 已访问，取 5，访问 5 | 3 出队；邻接点 1 已访问，5 未访问，访问 5，队 = [4,5] |
| 第 4 步 | 5 的邻接点 3 未访问，访问 3 | 4 出队；邻接点 2、5 均已访问 |
| 第 5 步 | 5 的邻接点 6 未访问，访问 6 | 5 出队；邻接点 3、4 已访问，6 未访问，访问 6，队 = [6] |
| 第 6 步 | 6 的邻接点 5 已访问，回溯至 5、4、2、1，均无未访问邻接点，结束 | 6 出队；邻接点 5 已访问，结束 |
| **序列** | **1, 2, 4, 5, 3, 6** | **1, 2, 3, 4, 5, 6** |

由此得到的两棵生成树也不同：**深度优先生成树**的树边为 $1$–$2$、$2$–$4$、$4$–$5$、$5$–$3$、$5$–$6$（呈现一条长链）；**广度优先生成树**的树边为 $1$–$2$、$1$–$3$、$2$–$4$、$3$–$5$、$5$–$6$（呈现逐层展开的形态）。两棵树都恰好有 $5 = n-1$ 条边，也印证了「生成树边数恒为 $n-1$」。若把邻接表中某两个邻接点的次序对调，上面两个序列都会随之改变——这正是「邻接表表示不唯一 ⇒ 遍历序列不唯一」的直观体现。

#### 5. 遍历与图的连通性

**对无向图**做遍历时：

- **调用 BFS/DFS 函数的次数 = 连通分量数**。
- 若图连通，只需调用 1 次。

**对有向图**做遍历时，调用次数需要具体分析，规律是：

- 若从起始顶点出发能到达其余所有顶点，则只需调用 1 次。
- 对**强连通图**，从任一顶点出发都只需调用 1 次。
- 一般情况下，有向图一次遍历能到达的是「该顶点能到达的所有顶点」集合，与强连通分量并不一一对应。

**求无向图连通分量个数的算法**（统考算法设计题的常见题型）：

1. 初始化 `visited` 数组全为 `false`，计数器 `count = 0`。
2. 依次检查每个顶点 $i$：若 `visited[i]` 为 `false`，则以 $i$ 为起点做一次 DFS（或 BFS），并把 `count` 加 1。
3. 搜索过程中跳过已访问顶点，未访问的顶点必然与 $i$ 属于同一连通分量。
4. 遍历结束后 `count` 即为连通分量个数。

```c
int count = 0;
void CountComponents(MGraph G) {
    for (int i = 0; i < G.numVertices; ++i) visited[i] = false;
    count = 0;
    for (int i = 0; i < G.numVertices; ++i) {
        if (!visited[i]) {          // 每个未访问顶点开启一个新的连通分量
            DFS_Matrix(G, i);       // 泛洪标记整个连通分量
            count++;
        }
    }
}
```

**时间复杂度**：无论 DFS 还是 BFS 实现，最坏情况（完全图）下每个顶点都要询问其余 $|V|-1$ 个顶点是否已访问，因此为 $O(|V|^{2})$；若用邻接表实现则为 $O(|V|+|E|)$。

同一问题也可以用**并查集**解决：遍历邻接矩阵的上三角区，对每条边的两端点做 `Union`；遍历结束后统计父数组中值为 $-1$（即根结点）的元素个数，即为连通分量个数。

#### 6. 遍历序列的唯一性

:::key 遍历序列何时唯一（高频结论）

- **邻接矩阵表示唯一** ⇒ 图的结构与邻接点次序都固定 ⇒ **DFS/BFS 遍历序列唯一，生成树也唯一**（前提是起点固定）。
- **邻接表表示不唯一**（边在链表中的次序可任意） ⇒ **DFS/BFS 遍历序列不唯一，生成树也不唯一**。

**唯一性的充要条件**：给定图 $G$ 和起点 $v$，从 $v$ 出发的 DFS（或 BFS）序列唯一，当且仅当**遍历过程中每一步「当前可选的未访问邻接点」都只有一个**。换句话说，只要途中某个顶点存在两个及以上未访问的邻接点，选择次序不同就会得到不同的遍历序列。

:::

#### 7. DFS 与 BFS 的对比

| 比较项 | 深度优先搜索 DFS | 广度优先搜索 BFS |
|---|---|---|
| 辅助结构 | 栈（递归的系统栈或显式栈） | 队列 |
| 扩展方式 | 一条路走到黑，回溯 | 由近及远，逐层扩散 |
| 邻接矩阵时间复杂度 | $O(\lvert V\rvert^{2})$ | $O(\lvert V\rvert^{2})$ |
| 邻接表时间复杂度 | $O(\lvert V\rvert+\lvert E\rvert)$ | $O(\lvert V\rvert+\lvert E\rvert)$ |
| 空间复杂度 | $O(\lvert V\rvert)$ | $O(\lvert V\rvert)$ |
| 生成树名称 | 深度优先生成树（森林） | 广度优先生成树（森林） |
| 典型用途 | 判断环、求连通分量、逆拓扑序列、割点 | 求无权图单源最短路径、层次遍历、判二分图 |

### （四）图的基本应用

#### 1. 最小（代价）生成树

##### （1）最小生成树的概念与唯一性

**最小生成树**（Minimum-Spanning-Tree，MST）是连通网中**各边权值之和最小的那棵生成树**。

必背结论：

1. 一个连通网的最小生成树**可能有多个**，但**各边权值之和（代价）总是唯一且最小的**。
2. **当图中各边的权值互不相等时，最小生成树唯一**。
3. 若无向连通图的边数比顶点数少 1（$e=n-1$），则它本身就是一棵树，最小生成树就是它自己。
4. 只有连通图才有生成树，**非连通图只有生成森林**。

**MST 唯一的充要条件**：设 $G$ 是无向连通带权图，$T$ 是其一棵最小生成树，则 $T$ 是 $G$ 的**唯一**最小生成树，当且仅当**对于不在 $T$ 中的每一条边 $e$，都有 $e$ 的权重大于 $T+e$ 所产生的圈中其它每条边的权重**。

证明思路：往 $T$ 中加入任一条不属于 $T$ 的边 $e$，必然形成唯一一个圈（因为 $T$ 已经包含全部顶点且连通无环）。若 $e$ 的权小于或等于圈中某条边的权，就可以用 $e$ 替换那条边得到一棵权值和不增大的新生成树，从而 $T$ 不唯一；反之若 $e$ 严格大于圈中所有其它边，任何替换都会使总权值增大，故 $T$ 唯一。

##### （2）Prim 算法（选点）

**算法思想**：从某个顶点开始构建生成树，每次把**与当前生成树顶点集合距离最近的那个新顶点**及其对应边纳入生成树，直到所有顶点都被纳入。

**执行步骤**：

1. **初始化**：设置 `visited[]` 数组标记顶点是否已进入 MST；设置 `dist[]` 数组，`dist[v]` 表示「顶点 $v$ 到当前 MST 顶点集合的最短边长」。任选一个起点 $v_0$，令 `dist[v0] = 0`、`visited[v0] = true`，其余顶点的 `dist` 初始化为 $v_0$ 到它们的直接边长（无边则为 $\infty$）。
2. **选点**：在**所有未加入 MST（`visited` 为 false）的顶点**中挑出 `dist` 值最小的顶点 $u$。
3. **纳入**：令 `visited[u] = true`，把边 $(u, \text{产生 dist[u] 的那个顶点})$ 加入 MST，累加权值。
4. **更新**：对 $u$ 的每个未加入 MST 的邻接顶点 $k$，执行
   $$dist[k]=\min\{dist[k],\ w(u,k)\}$$
   注意这里用的是**边的权值**，不是把路径长度累加。
5. 重复步骤 2～4 共 $n-1$ 次，直到所有顶点都加入 MST。

:::key Prim 的 dist 数组含义（与 Dijkstra 的分水岭）

- **Prim**：`dist[k]` = 顶点 $k$ **到 MST 顶点集合**的最短边权。更新式为 $dist[k]=\min\{dist[k],\ w(u,k)\}$。
- **Dijkstra**：`dist[k]` = 顶点 $k$ **到源点**的最短路径长度。更新式为 $dist[k]=\min\{dist[k],\ dist[u]+w(u,k)\}$。

两者的代码结构几乎相同，但一个「不累加、只看单条边」，一个「累加、看整条路径」，这是考试中最容易被混淆的地方。

:::

```c
void Prim(MGraph G, int v0) {
    int dist[MAXV];
    bool visited[MAXV];
    int sum = 0;
    for (int i = 0; i < G.numVertices; ++i) {
        dist[i] = (i == v0) ? 0 :
                  (G.edges[v0][i] != 0 && G.edges[v0][i] < INT_MAX ? G.edges[v0][i] : INT_MAX);
        visited[i] = false;
    }
    visited[v0] = true;
    for (int i = 1; i < G.numVertices; ++i) {     // 共执行 n-1 轮
        int u = -1, min = INT_MAX;
        for (int j = 0; j < G.numVertices; ++j) { // 找 dist 最小的未访问顶点
            if (!visited[j] && dist[j] < min) { min = dist[j]; u = j; }
        }
        if (u == -1) break;                       // 图不连通
        visited[u] = true;
        sum += min;
        for (int k = 0; k < G.numVertices; ++k) { // 用 u 的边更新 dist
            if (!visited[k] && G.edges[u][k] != 0 && G.edges[u][k] < INT_MAX
                && G.edges[u][k] < dist[k])
                dist[k] = G.edges[u][k];
        }
    }
    printf("MST 总权值 = %d\n", sum);
}
```

**手工模拟**：设有 6 个顶点 A、B、C、D、E、F，无向带权边为 AB=6、AC=1、AD=5、BC=5、BE=3、CD=5、CE=6、CF=4、DF=2、EF=6。从 A 出发运行 Prim：

| 轮次 | 当前 `dist`（未确定顶点的候选值） | 选中的顶点 | 加入的边 | 累计权值 |
|---|---|---|---|---|
| 初始 | B:6, C:1, D:5, E:∞, F:∞ | — | — | 0 |
| 第 1 轮 | 选中最小者 C（1） | C | A–C | 1 |
| 更新 | B:min(6,5)=5, D:min(5,5)=5, E:min(∞,6)=6, F:min(∞,4)=4 | | | |
| 第 2 轮 | 最小者 F（4） | F | C–F | 5 |
| 更新 | B:min(5,∞)=5, D:min(5,2)=2, E:min(6,6)=6 | | | |
| 第 3 轮 | 最小者 D（2） | D | F–D | 7 |
| 更新 | B:min(5,5)=5, E:min(6,∞)=6 | | | |
| 第 4 轮 | 最小者 B（5） | B | C–B | 12 |
| 更新 | E:min(6,3)=3 | | | |
| 第 5 轮 | 最小者 E（3） | E | B–E | 15 |

所得 MST 的边为 {A–C(1), C–F(4), F–D(2), C–B(5), B–E(3)}，总代价 15，共 5 条边，等于 $n-1$。

**复杂度**：外层循环执行 $n-1$ 次，内层两个并列的非嵌套循环各为 $O(|V|)$，因此总时间复杂度为 $O(|V|^{2})$，与边数无关。空间复杂度 $O(|V|)$。**Prim 适合求解边稠密的图**（点少边多）。

##### （3）Kruskal 算法（选边）

**算法思想**：每次选择一条**权值最小的边**，若这条边的两个端点尚未连通则加入 MST，否则**跳过**（因为加入会形成回路），直到所有顶点连通。Kruskal 是**并查集的典型应用**。

**执行步骤**：

1. 把所有边按权值**从小到大排序**。
2. 初始化并查集，每个顶点各成一个集合。
3. 依次取出排序后的每条边 $(u,v)$：查询 $u$、$v$ 的根结点，若**不同**则合并两集合并把该边加入 MST；若**相同**则跳过该边。
4. 当加入 MST 的边数达到 $|V|-1$ 时算法结束。
5. 若所有边都处理完仍未达到 $|V|-1$ 条，说明原图不连通，不存在生成树。

```c
int parent[MAXV];
void initUF(int n) { for (int i = 0; i < n; ++i) parent[i] = i; }
int find(int x) { return parent[x] == x ? x : (parent[x] = find(parent[x])); }  // 路径压缩
bool unite(int x, int y) {
    int rx = find(x), ry = find(y);
    if (rx == ry) return false;      // 已连通，该边会成环
    parent[ry] = rx;
    return true;
}
int cmpEdge(const void *a, const void *b) {
    int wa = ((Edge *)a)->weight, wb = ((Edge *)b)->weight;
    return (wa > wb) - (wa < wb);    // 避免直接相减溢出
}

void Kruskal(MGraph *G, Edge edgeList[]) {
    int cnt = 0, sum = 0;
    initUF(G->numVertices);
    qsort(edgeList, G->numEdges, sizeof(Edge), cmpEdge);   // 按权值升序
    for (int i = 0; i < G->numEdges && cnt < G->numVertices - 1; ++i) {
        if (unite(edgeList[i].u, edgeList[i].v)) {
            sum += edgeList[i].weight;
            cnt++;
        }
    }
    if (cnt == G->numVertices - 1) printf("MST 总权值 = %d\n", sum);
    else printf("图不连通，无生成树\n");
}
```

**手工模拟**：仍用上一小节的 6 顶点图，按下表依次处理排序后的边：

| 序号 | 边 | 权值 | 两端是否已连通 | 处理结果 | 已选边数 |
|---|---|---|---|---|---|
| 1 | A–C | 1 | 否 | 加入 | 1 |
| 2 | D–F | 2 | 否 | 加入 | 2 |
| 3 | B–E | 3 | 否 | 加入 | 3 |
| 4 | C–F | 4 | 否（{A,C} 与 {D,F} 尚未合并） | 加入 | 4 |
| 5 | A–D | 5 | 是（A–C–F–D 已连通） | **跳过** | 4 |
| 6 | B–C | 5 | 否（{B,E} 与 {A,C,D,F} 尚未合并） | 加入 | 5 |
| — | — | — | 已达 $n-1=5$ 条 | **结束** | 5 |

所得 MST 的边为 {A–C(1), D–F(2), B–E(3), C–F(4), B–C(5)}，总代价 15。可以看到 Prim 与 Kruskal 得到了**不同的边集但相同的总代价**——这正说明该图的 MST 不唯一（因为存在权值相同的边）。

**复杂度**：边排序需要 $O(|E|\log|E|)$；每条边做一次并查集查询，路径压缩后近似 $O(1)$，至多 $|E|$ 次，因此总时间复杂度为 $O(|E|\log|E|)$（可写为 $O(|E|\log|V|)$）。空间上需要 $O(|V|)$ 的并查集数组与边表。**Kruskal 适合求解边稀疏而顶点较多的图**。

:::key Prim 与 Kruskal 的选择口诀

- **Prim 选点**（P 开头，Point 也是 P 开头），时间复杂度 $O(|V|^{2})$，只与**顶点数**有关，**适合边稠密的图**。
- **Kruskal 选边**（K 开头，可以联想「快排也是先排序」），时间复杂度 $O(|E|\log|E|)$，只与**边数**有关，**适合边稀疏而顶点较多的图**。

:::

##### （4）两个算法为什么正确

两个算法都是贪心，它们的正确性依赖同一条性质，可以称为**切割性质**（cut property）：把图的顶点任意划分成两个非空集合 $S$ 与 $V-S$，横跨这两个集合的边中**权值最小的那条边**（若权值并列则任取其一）**一定属于某棵最小生成树**。直觉解释是：设 $T$ 是一棵 MST，若这条最小横跨边 $e=(u,v)$ 不在 $T$ 中，把它加入 $T$ 会形成一个圈，而这个圈必然还有另一条横跨 $S$ 与 $V-S$ 的边 $e'$（因为从 $u\in S$ 出发绕圈回到 $v\in V-S$ 至少要横跨一次）。由 $e$ 是最小横跨边可知 $w(e)\le w(e')$，于是用 $e$ 换掉 $e'$ 得到的新生成树权值不增大，仍是 MST，故存在一棵 MST 包含 $e$。

- **Prim 的做法就是反复应用切割性质**：取 $S$ = 当前已加入 MST 的顶点集合，$V-S$ = 尚未加入的顶点集合，此时「横跨 $S$ 与 $V-S$ 的最小边」恰好就是 `dist` 数组中的最小值，所以每轮选 `dist` 最小的顶点是安全的。
- **Kruskal 的做法则是另一种视角**：按权值从小到大逐条考察，当考察到边 $e=(u,v)$ 时，若 $u$、$v$ 已连通就跳过（加入必成环，且圈中已有边的权值都不大于 $w(e)$，换掉任何一条都不会更优）；若未连通就一定要加入（否则这一时刻 $u$ 所在连通分量与 $v$ 所在连通分量之间的所有横跨边权值都 $\ge w(e)$，而最终必须有一条横跨边被选中，选 $e$ 不会比选别的差）。

理解了切割性质，就能解释两个常考的现象：**其一**，同一张图用 Prim 和 Kruskal 可能得到不同的 MST 边集，但它们的总代价必然相同（都等于所有被切割性质「锁定」的边权之和的最小值）；**其二**，只要某条边的权值是全图唯一最小的，它必然出现在每一棵 MST 中；反之若有若干条同样小的边构成环，就不能把它们全部选入，因此「所有权值最小的边一定出现在所有 MST 中」是错误的。

##### （5）最小生成树与最短路径的区别

| 比较项 | Prim（最小生成树） | Dijkstra（单源最短路径） |
|---|---|---|
| 目标 | 使生成树**所有边的权值之和**最小 | 使源点到**每个顶点各自的路径长度**最小 |
| `dist` 含义 | 顶点到**已选顶点集合**的最短边权 | 顶点到**源点**的最短路径长度 |
| 更新方式 | $dist[k]=\min(dist[k],\ w(u,k))$ | $dist[k]=\min(dist[k],\ dist[u]+w(u,k))$ |
| 结果结构 | 一棵包含全部顶点的树 | 一棵以源点为根的最短路径树 |
| 权值要求 | 无限制（无向图） | **不能有负权边** |
| 时间复杂度 | $O(\lvert V\rvert^{2})$ | $O(\lvert V\rvert^{2})$ |

**最关键的区别**：MST 保证「整棵树的总权值最小」，但**不保证**树上源点到某顶点的路径是原图中的最短路径；最短路径树保证「源点到每个顶点的路径最短」，但整棵树的边权之和通常比 MST 大。二者不能互相替代。特别地，即使图的所有边权都为 1，Prim 和 Kruskal 也**不能**用来求单源最短路径。

:::exam 出题角度

最小生成树在历年统考中出现 5 次左右，选择题与应用题都会考。典型问法：(1) 判断关于 MST 的叙述——「最小生成树的代价唯一」正确，「所有权值最小的边一定出现在所有 MST 中」错误（等权边成环时不可能全选），「Prim 从不同顶点开始得到的 MST 一定相同」错误；(2) 给出带权图，问「可能是 Kruskal 第 2 次选中但不是 Prim（从某点开始）第 2 次选中的边」，解法是分别按两种规则手算前两步再取差集；(3) 应用题要求写出 Prim 或 Kruskal 逐次选边过程并计算总代价。

:::

#### 2. 最短路径

##### （1）无权图的单源最短路径——BFS

无权图（或所有边权都相等）的单源最短路径可以直接用 BFS 求。算法过程：

1. 设置队列 `q`、访问标记数组 `visited`、距离数组 `d`、前驱数组 `path`。
2. 源点 $s$ 入队，置 `visited[s] = true`、`d[s] = 0`、`path[s] = -1`。
3. 循环：弹出队头 $u$，遍历 $u$ 的所有邻接点 $v$；若 $v$ 未访问，则置 `visited[v] = true`、`d[v] = d[u] + 1`、`path[v] = u`，并把 $v$ 入队。
4. 队列为空时，`d[]` 即为源点到各顶点的最短距离；若 `d[i]` 仍为无穷，说明 $i$ 从源点不可达。

**时间复杂度**：邻接矩阵 $O(|V|^{2})$，邻接表 $O(|V|+|E|)$。

##### （2）Dijkstra 算法（带权单源最短路，非负权）

BFS 只适用于无权图或各边权值相等的图。当边权不同时，**更深的路径完全可能比更浅的路径更短**，此时必须使用 Dijkstra 或 Floyd 算法。

Dijkstra 算法需要三个辅助数组：

- `dist[]`：`dist[i]` 表示当前已知的从源点到顶点 $i$ 的最短路径长度。
- `path[]`：`path[i]` 表示源点到 $i$ 的最短路径上 $i$ 的**前驱顶点**，用于还原路径。
- `final[]`：`final[i] = true` 表示顶点 $i$ 的最短路径**已经确定**，不会再被更新。

**执行步骤**：

1. **初始化**：`final[]` 全置 `false`；`dist[i] = Edge[s][i]`（源点到 $i$ 的直接边长，无边则 $\infty$）；`path[i] = (Edge[s][i] 存在) ? s : -1`。令 `final[s] = true`、`dist[s] = 0`、`path[s] = -1`。
2. **选点**：在 `final` 为 `false` 的顶点中，找出 `dist` 值最小的顶点 $u$。
3. **确定**：令 `final[u] = true`。此时 `dist[u]` 就是源点到 $u$ 的最短距离。
4. **松弛**：检查所有**由 $u$ 出发的边** $<u,v>$。若 `final[v] == false` 且
   $$dist[u]+w(u,v) < dist[v]$$
   则更新 `dist[v] = dist[u] + w(u,v)`，并令 `path[v] = u`。
5. 重复步骤 2～4 共 $n-1$ 轮，直到所有顶点的最短路径都确定。

```c
void Dijkstra(MGraph G, int v, int dist[], int path[]) {
    bool final[MAXV];
    int n = G.numVertices;
    for (int i = 0; i < n; ++i) {                 // 初始化
        final[i] = false;
        int w = G.edges[v][i];
        bool hasEdge = (w != 0 && w < INT_MAX);
        dist[i] = hasEdge ? w : INT_MAX;
        path[i] = hasEdge ? v : -1;
    }
    final[v] = true; dist[v] = 0; path[v] = -1;
    for (int i = 1; i < n; ++i) {                 // 共 n-1 轮
        int u = -1, min = INT_MAX;
        for (int j = 0; j < n; ++j)               // 选点：找 dist 最小的未确定顶点
            if (!final[j] && dist[j] < min) { min = dist[j]; u = j; }
        if (u == -1) break;                       // 剩余顶点均不可达
        final[u] = true;
        for (int j = 0; j < n; ++j) {             // 松弛：只用「从 u 出发」的边
            if (!final[j] && G.edges[u][j] != 0 && G.edges[u][j] < INT_MAX
                && dist[u] != INT_MAX
                && dist[u] + G.edges[u][j] < dist[j]) {
                dist[j] = dist[u] + G.edges[u][j];
                path[j] = u;
            }
        }
    }
}
```

**手工模拟**：设 5 个顶点 $v_0\sim v_4$，有向边 $v_0\to v_1=10$、$v_0\to v_4=5$、$v_4\to v_1=3$、$v_4\to v_2=9$、$v_4\to v_3=2$、$v_1\to v_2=1$、$v_2\to v_3=4$、$v_3\to v_0=7$、$v_3\to v_2=6$。以 $v_0$ 为源点：

| 轮次 | 已确定集合 | `dist`（`v0,v1,v2,v3,v4`） | 本轮选中 | 本轮 `path` 变化 |
|---|---|---|---|---|
| 初始 | {v0} | 0, 10, ∞, ∞, 5 | — | `path[1]=0, path[4]=0` |
| 第 1 轮 | {v0,v4} | 0, **8**, **14**, **7**, 5 | v4（5） | `path[1]=4, path[2]=4, path[3]=4` |
| 第 2 轮 | {v0,v4,v3} | 0, 8, **13**, 7, 5 | v3（7） | `path[2]=3`（7+6=13<14） |
| 第 3 轮 | {v0,v4,v3,v1} | 0, 8, **9**, 7, 5 | v1（8） | `path[2]=1`（8+1=9<13） |
| 第 4 轮 | 全部 | 0, 8, 9, 7, 5 | v2（9） | 无 |

最终结果：$v_0\to v_1=8$（$v_0\to v_4\to v_1$），$v_0\to v_2=9$（$v_0\to v_4\to v_1\to v_2$），$v_0\to v_3=7$（$v_0\to v_4\to v_3$），$v_0\to v_4=5$。

注意第 1 轮后 `dist[1]` 从 10 被更新为 8、`dist[2]` 从 $\infty$ 变为 14、`dist[3]` 从 $\infty$ 变为 7——这说明**「中转一个顶点」就能让原本不可达的顶点变得可达，让原本较长的路径变短**，这也正是每轮都要重新松弛的原因。

**复杂度**：两层 `for` 循环，外层执行 $n-1$ 轮，每轮选点 $O(|V|)$，松弛 $O(|V|)$，总时间复杂度 $O(|V|^{2})$。空间复杂度 $O(|V|)$（三个一维数组）。若用邻接表加优先队列（堆）优化，可降到 $O(|E|\log|V|)$，但统考按 $O(|V|^{2})$ 理解。

:::warn Dijkstra 为什么不能处理负权边

Dijkstra 的正确性建立在一条贪心性质上：**当前 `dist` 最小的未确定顶点，其最短路径已经确定，此后不会再被任何路径更新**。当所有边权非负时，任何绕路（经过其他未确定顶点）只会让路径更长或持平，因此这条性质成立。

**一旦出现负权边，这条性质就失效了。** 反例：有向图 $1\to 2$ 权值为 3，$1\to 3$ 权值为 4，$3\to 2$ 权值为 $-2$。

- 初始化：`dist[2]=3`，`dist[3]=4`。
- 第 1 轮：`dist` 最小的未确定顶点是 2（值为 3），令 `final[2]=true`，认定 1 到 2 的最短距离是 3。
- 第 2 轮：选中顶点 3（值为 4），尝试用 $3\to 2$ 松弛，得到 $dist[2]$ 应为 $4+(-2)=2<3$——但 `final[2]` 已经是 `true`，**按算法规则不会再更新它**。

于是 Dijkstra 输出 3，而真实最短路径是 $1\to 3\to 2$，长度为 2。**结论：Dijkstra 只适用于所有边权非负的图**；求解带负权（但无负权回路）的图必须用 Floyd 或 Bellman-Ford。

:::

##### （3）Floyd 算法（各顶点对之间的最短路径）

**算法思想**：动态规划。**依次允许经过 $v_0,\ v_1,\ v_2,\ \cdots,\ v_{n-1}$ 中转**，每允许增加一个中转顶点，就检查是否能让某些点对之间的距离变短，若可以就更新。设 $dist[i][j]$ 表示当前已知的从 $i$ 到 $j$ 的最短路径长度，则状态转移为

$$dist[i][j]=\min\{dist[i][j],\ dist[i][k]+dist[k][j]\}$$

**执行步骤**：

1. **初始化**：`dist[][]` 直接取邻接矩阵（**注意 $i=j$ 时置 0，无边时置 $\infty$**）；`path[][]` 初始化为 $-1$（也可初始化为 $i$，表示从 $i$ 直接到 $j$）。
2. **三层循环**：外层固定中转顶点 $k$（$0\sim n-1$），中层固定起点 $i$，内层固定终点 $j$。对每个 $(i,j)$ 判断 $dist[i][k]+dist[k][j]<dist[i][j]$，若成立则更新距离并记录 `path[i][j] = k`。
3. 循环结束时（若无负权回路），`dist[i][j]` 即 $i$ 到 $j$ 的最短路径长度。

```c
void Floyd(MGraph G, int dist[MAXV][MAXV], int path[MAXV][MAXV]) {
    int n = G.numVertices;
    for (int i = 0; i < n; ++i) {                     // 初始化
        for (int j = 0; j < n; ++j) {
            int w = G.edges[i][j];
            if (i == j) dist[i][j] = 0;
            else dist[i][j] = (w != 0 && w < INT_MAX) ? w : INT_MAX;
            path[i][j] = (dist[i][j] != INT_MAX && i != j) ? i : -1;
        }
    }
    for (int k = 0; k < n; ++k) {                     // 外层：中转顶点 k（必须在最外层）
        for (int i = 0; i < n; ++i) {                 // 中层：起点 i
            for (int j = 0; j < n; ++j) {             // 内层：终点 j
                if (dist[i][k] < INT_MAX && dist[k][j] < INT_MAX
                    && dist[i][k] + dist[k][j] < dist[i][j]) {
                    dist[i][j] = dist[i][k] + dist[k][j];
                    path[i][j] = k;                   // 记录中转点
                }
            }
        }
    }
}
```

**手工模拟（十字法）**：设 4 个顶点 $0,1,2,3$，有向边 $0\to 1=1$、$1\to 2=3$、$0\to 2=5$、$2\to 3=1$、$0\to 3=10$、$1\to 3=8$。∞ 表示不可达。

初始 $dist$（$k$ 尚未允许）：

| 从\到 | 0 | 1 | 2 | 3 |
|---|---|---|---|---|
| 0 | 0 | 1 | 5 | 10 |
| 1 | ∞ | 0 | 3 | 8 |
| 2 | ∞ | ∞ | 0 | 1 |
| 3 | ∞ | ∞ | ∞ | 0 |

- **$k=0$**：没有任何顶点能到达 0，矩阵无变化。
- **$k=1$**（允许经 1 中转）：只需检查第 1 列非 ∞ 的行与第 1 行非 ∞ 的列。
  - $dist[0][1]+dist[1][2]=1+3=4<5$ ⇒ $dist[0][2]=4$，`path[0][2]=1`。
  - $dist[0][1]+dist[1][3]=1+8=9<10$ ⇒ $dist[0][3]=9$，`path[0][3]=1`。
- **$k=2$**（允许经 2 中转）：
  - $dist[0][2]+dist[2][3]=4+1=5<9$ ⇒ $dist[0][3]=5$，`path[0][3]=2`。
  - $dist[1][2]+dist[2][3]=3+1=4<8$ ⇒ $dist[1][3]=4$，`path[1][3]=2`。
- **$k=3$**：3 没有出边，无变化。

最终 $dist[0][3]=5$，还原路径：`path[0][3]=2` ⇒ 到 3 之前先到 2；`path[0][2]=1` ⇒ 到 2 之前先到 1；`path[0][1]=0` ⇒ 到 1 之前先到 0。于是路径为 $0\to 1\to 2\to 3$，长度 $1+3+1=5$，与 $dist$ 一致。

:::key Floyd 的三重循环顺序为什么不能换

**$k$ 必须放在最外层。** 因为 $k$ 代表的是「当前允许作为中转的顶点集合」$\{0,1,\cdots,k\}$，这是动态规划的**阶段**；$i,j$ 是同一阶段内的**状态**。只有先固定阶段再枚举状态，转移方程 $dist_k[i][j]=\min(dist_{k-1}[i][j],\ dist_{k-1}[i][k]+dist_{k-1}[k][j])$ 才成立。

如果把 $k$ 放到里层（例如写成 $i,j,k$ 三层），就会在同一阶段内反复使用尚未确定的中间结果，导致某些路径组合被漏算。做题时若题目要求「依次允许 $v_0,v_1,\cdots$ 中转」写出每一轮矩阵，本质上就是在验证这个顺序。

:::

**复杂度**：三重循环，时间复杂度 $O(|V|^{3})$；空间复杂度 $O(|V|^{2})$（距离矩阵 + 路径矩阵）。

**负权支持**：Floyd 可以处理**带负权边但不能有负权回路**的图。原因在于算法会对所有顶点的所有入边做松弛，不受「已确定」限制。若图中存在负权回路，则绕该回路可以无限缩短路径，最短路径不存在（长度趋于 $-\infty$）。

##### （4）三种最短路径算法对比

| 比较项 | BFS | Dijkstra | Floyd |
|---|---|---|---|
| 解决问题 | 无权图单源最短路径 | 非负权图单源最短路径 | 各顶点对之间的最短路径 |
| 边权要求 | 无权或各边权相等 | **所有边权非负** | 允许负权，**不允许负权回路** |
| 算法思想 | 按层扩展 | 贪心，分已确定/未确定两个集合 | 动态规划，逐个允许中转顶点 |
| 辅助数组 | `visited`、`d`、`path` | `dist`、`path`、`final` | `dist[][]`、`path[][]` |
| 时间复杂度 | 邻接表 $O(\lvert V\rvert+\lvert E\rvert)$；邻接矩阵 $O(\lvert V\rvert^{2})$ | $O(\lvert V\rvert^{2})$ | $O(\lvert V\rvert^{3})$ |
| 空间复杂度 | $O(\lvert V\rvert)$ | $O(\lvert V\rvert)$ | $O(\lvert V\rvert^{2})$ |
| 适用场景 | 无权网络、层次关系 | 非负权单源问题 | 需要所有点对距离 |

:::exam 出题角度

最短路径历年考查 5 次以上，是选择题与应用题的双料重点。典型问法：(1) 给出图，问「依次得到的各最短路径的目标顶点是」，需按 Dijkstra 逐轮记录被确定顶点的顺序；(2) 给出图与初始 `dist` 数组，问「求出第 2 条最短路径后 `dist` 中的内容」，需精确模拟两轮松弛；(3) 问「所有边权均为 1 的连通图中，一定能求出单源最短路径的算法」，答案是**只有 BFS**，Prim 和 Kruskal 求的是最小生成树，不保证源点到各顶点的路径最短；(4) 判断「Dijkstra 能否处理负权图」，注意题干若强调「无负权回路」，则能处理的是 Floyd 而不是 Dijkstra。

:::

#### 3. 拓扑排序

##### （1）AOV 网与拓扑序列

**AOV 网**（Activity On Vertex Network）：用**顶点表示活动**、用**有向边表示活动之间的先后制约关系**的有向图。例如课程 $A$ 是课程 $B$ 的先修课，就画一条 $A\to B$ 的弧。

**拓扑排序**（Topological Sorting）：由一个有向无环图的顶点组成的一个线性序列，当且仅当满足以下条件时称为该图的一个拓扑排序——**对图中任意一条弧 $<u,v>$，$u$ 在序列中都排在 $v$ 之前**。

等价说法：拓扑排序是对有向图的一种遍历，在这种遍历中，**对一个顶点 $v$ 的访问只发生在它所有前驱顶点都被访问之后**。

必背性质：

1. 只要图为 **DAG（有向无环图）**，就**至少存在一种**拓扑排序结果。每个 AOV 网都有一个或多个拓扑序列。
2. **有向图存在拓扑序列 ⇔ 图中不存在回路 ⇔ 图是 DAG**。
3. 拓扑排序与图是否连通**无关**。互不连通的分量互不依赖，它们在拓扑序中的相对顺序是任意的。
4. 若某顶点有多个直接后继，拓扑排序结果通常**不唯一**。**唯一的情形**是：每个时刻可选的入度为 0 的顶点只有一个，等价于**图中存在一条包含全部顶点的路径**（哈密顿路径），此时拓扑序就是这条路径上顶点的顺序。
5. 若一个有向图**不能**构成拓扑排序，则该图一定有环，即**一定含有顶点数目大于 1 的强连通分量**。注意此时该图**不一定是强连通图**——有环只是存在强连通分量的充分条件，不是整个图强连通。

**怎么判断拓扑序列是否唯一、怎么数拓扑序列的个数？** 这是选择题的高频操作，方法是**模拟人脑版的 Kahn 算法并做分支统计**：

1. 在草稿纸上写出当前所有入度为 0 的顶点，这就是当前这一步「可选」的集合。
2. 若某个时刻可选集合中只有 1 个顶点，则这一步没有选择余地，只能选它。
3. 若某个时刻可选集合中有 $k\ge 2$ 个顶点，则这里产生了 $k$ 个分支，需要分别往下推演。
4. 把每条分支路上「所有选择都是被迫的」这一情况记为一个完整的拓扑序列，最后统计叶子数即为拓扑序列总数。

由此可以推出两个直接可用的判据：**只要全过程中每一步的可选集合都恰好只有 1 个顶点，拓扑序列就唯一**；而只要出现过一次可选集合大于 1，序列就不唯一。更本质地看，「每一步可选集合都只有 1 个顶点」等价于「图中存在一条依次经过所有顶点的有向路径」，也就是拓扑序恰好是这条路径上的顶点次序。这也解释了为什么「每个顶点都有唯一的前驱和后继」时拓扑序唯一，而「某个顶点有多个直接后继」时通常不唯一。

##### （2）基于入度的拓扑排序（Kahn 算法）

**算法思想**：一个顶点的**入度为 0**，说明它依赖的所有顶点都已被处理，此时就可以输出它。先把所有入度为 0 的顶点入队，然后不断出队、输出，并把出队顶点的所有邻接顶点的入度减 1，若某个邻接顶点入度减到 0 就入队。重复直到队列为空。这是一个**顺序**的拓扑排序过程。

**执行步骤**：

1. 统计每个顶点的入度，存入数组 `indegree[]`。
2. 把所有入度为 0 的顶点入队。
3. 循环直到队列为空：
   1. 队头顶点 $u$ 出队，加入结果序列 `res`，计数 `count++`。
   2. 遍历 $u$ 的所有邻接顶点 $v$，令 `indegree[v]--`。
   3. 若 `indegree[v]` 减到 0，则把 $v$ 入队。
4. 循环结束后判环：**若 `count == n`，则排序成功，`res` 即为一个拓扑序列；否则图中存在环，无拓扑序列**（有环的顶点入度永远减不到 0）。

```c
bool TopologicalSort(ALGraph G, int res[]) {
    int indegree[MAXV] = {0}, cnt = 0, q[MAXV], front = 0, rear = 0;
    for (int i = 0; i < G.numVertices; ++i)          // 1. 统计入度
        for (ArcNode *p = G.vertices[i].firstarc; p; p = p->next)
            indegree[p->adjvex]++;
    for (int i = 0; i < G.numVertices; ++i)          // 2. 入度为 0 者入队
        if (indegree[i] == 0) q[rear++] = i;
    while (front < rear) {                            // 3. 出队并更新邻接点入度
        int u = q[front++];
        res[cnt++] = u;
        for (ArcNode *p = G.vertices[u].firstarc; p; p = p->next) {
            int v = p->adjvex;
            if (--indegree[v] == 0) q[rear++] = v;
        }
    }
    return cnt == G.numVertices;                      // 4. 判环
}
```

**手工模拟**：设有向图顶点 A、B、C、D、E、F，弧为 $A\to C$、$A\to D$、$B\to D$、$B\to E$、$C\to F$、$D\to F$。

| 步骤 | 各顶点入度（A,B,C,D,E,F） | 队列内容 | 输出序列 |
|---|---|---|---|
| 初始 | 0, 0, 1, 2, 1, 2 | A, B | — |
| 出 A | 0, 0, 0, 1, 1, 2 | B, C | A |
| 出 B | 0, 0, 0, 0, 0, 2 | C, D, E | A, B |
| 出 C | 0, 0, 0, 0, 0, 1 | D, E | A, B, C |
| 出 D | 0, 0, 0, 0, 0, 0 | E, F | A, B, C, D |
| 出 E | 0, 0, 0, 0, 0, 0 | F | A, B, C, D, E |
| 出 F | 全部为 0 | 空 | A, B, C, D, E, F |

`count = 6 = n`，拓扑排序成功，得到一个合法序列 A,B,C,D,E,F。由于 A、B 入队次序可交换、C、D、E 的处理次序也有多种选择，该图的拓扑序列不唯一（例如 B,A,E,C,D,F 同样合法）。

**复杂度**：统计入度需扫描所有边，$O(|V|+|E|)$；每个顶点至多入队出队一次，$O(|V|)$；每条弧在出队时被扫描一次，$O(|E|)$。因此**邻接表存储时总时间复杂度为 $O(|V|+|E|)$**；若用邻接矩阵存储，每次找入度为 0 的顶点都要扫描一整行，复杂度升为 $O(|V|^{2})$。空间复杂度 $O(|V|)$。

##### （3）基于 DFS 的拓扑排序

DFS 也能实现拓扑排序：在 DFS 中，顶点 $u$ 的所有后继顶点一定会在 $u$ 之前完成（回溯）。因此只要**按「完成时间」把顶点压入结果栈**（或逆序记录），最后得到的序列就是拓扑序列。若直接按完成次序顺序输出，得到的则是**逆拓扑序列**。

:::warn 逆拓扑序列的判别

把 DFS 中「输出顶点信息」的语句**移到退出递归之前**（即先递归处理所有后继，再输出当前顶点），遍历一个有向无环图，输出结果中每个顶点都排在其所有后继之后，因此得到的是**逆拓扑有序序列**。反过来，要得到正序拓扑序列，需要把完成序列反转（或用栈）。这个「改一行语句」的考法在统考中出现过。

:::

##### （4）拓扑排序与判环

**有向图判环**的常用方法：

1. **拓扑排序法**（最常用）：执行 Kahn 算法后，若出队顶点数 `count < n`，说明存在环。因为环上的顶点入度永远无法减到 0。
2. **DFS 三色标记法**：DFS 中用一个 `state[]` 数组区分「未搜索 (0) / 搜索中 (1) / 已完成 (2)」。若在搜索过程中遇到了一个 `state` 为 1 的顶点，说明回到了当前递归路径上的顶点，即存在环。搜索完成一个顶点后置 `state = 2`，遇到 2 的顶点直接返回（不会重复检测）。
3. **DFS 路径栈法**：用栈记录当前遍历路径上的顶点，若遇到已在栈中的顶点则有环。

**无向图判环**的方法：

1. **DFS/BFS 法**：从某顶点 $v$ 出发搜索，若在搜索过程中再次遇到 $v$，则图有环。对每个顶点都做一次即可找出所有环上的顶点。
2. **剥洋葱法**：把度为 1（或 0）的顶点不断入队并删除，同时更新邻接点的度；若最终出队顶点数 `count < n`，说明剩下的是环，图有环。
3. **并查集法**：依次处理每条边，若边的两端点已在同一集合中，则加入该边会成环。
4. **边数与连通性法**：对 $n$ 个顶点、$e$ 条边的无向图，若 $e>n-1$ 则一定有环；若 $e=n-1$ 且连通则一定是树（无环）。

:::key 拓扑排序与邻接矩阵的三角形态

DAG（AOV 网）中各顶点的地位是平等的，顶点编号是人为的。因此**可以按照拓扑排序的结果对顶点重新编号，使得新编号下所有的弧都从小编号指向大编号，从而新生成的邻接矩阵是（上）三角矩阵**。

反之，**若一个图的邻接矩阵是三角矩阵，则该图必然存在拓扑序列，但拓扑序列不一定唯一**。注意方向：三角矩阵 ⇒ 有拓扑序列（存在性）；但「有拓扑序列 ⇒ 邻接矩阵是三角矩阵」需要允许重新编号后才成立。

典型考法：给出邻接矩阵「主对角线以下元素均为零」，问拓扑序列的结论。此时按矩阵下标编号，只有小编号指向大编号的弧，沿任何有向路径顶点编号都严格增大，故不可能有环，**拓扑序列一定存在**；但由于没有具体图的信息，**无法判断是否唯一**，结论是「存在，可能不唯一」。

:::

**DAG 描述表达式**：有向无环图可以让相同的子表达式**共用同一个顶点**，从而避免重复建立结点，这是 DAG 在编译原理中用于表达式优化的经典应用，也是统考出现过的冷门考点。它之所以能用 DAG 而不是树来描述表达式，正是因为「同一个子表达式在表达式中出现多次」这一情形可以被合并在一个顶点上，而树结构无法共享子树。

以表达式 $(x+y)\cdot((x+y)/x)$ 为例，逐步建图：

1. 操作数 $x$ 一个顶点，操作数 $y$ 一个顶点。
2. 子表达式 $(x+y)$ 一个顶点，接收 $x$、$y$ 两条入弧。它在原表达式中出现了两次，但**只需建一个顶点**。
3. 子表达式 $((x+y)/x)$ 一个顶点，入弧分别来自 $(x+y)$ 顶点和 $x$ 顶点。
4. 最外层的乘法一个顶点，入弧来自 $(x+y)$ 顶点和 $((x+y)/x)$ 顶点。
5. 输出顶点（也可省去）指向该乘法顶点。

因此最少需要的顶点数为 $x$、$y$、加法、除法、乘法共 **5 个**。若改用二叉树表示而不共享子表达式，则需要重复建出第二个加法结点，顶点数会增加到 6 个以上——这正是题目「需要的顶点个数至少是」的考点所在。解题要领是：**先把表达式按树展开，再把所有结构相同的子表达式合并成一个顶点，最后数顶点。**

:::exam 出题角度

拓扑排序历年考查 8 次左右，是本章最高频的考点之一。典型问法：(1) 问「可以得到不同拓扑序列的个数」，解法是逐步枚举当前入度为 0 的顶点，做树形分支统计；(2) 给出邻接表存储的有向图，问拓扑排序时间复杂度，答案是 $O(n+e)$；(3) 判断某个序列是否是该图的拓扑序列，逐个检查每条弧的方向约束即可；(4) 问「仅当图中存在一条包含所有顶点的路径时，拓扑序列唯一」；(5) 结合邻接矩阵的三角形态考查拓扑排序与压缩存储。

:::

#### 4. 关键路径

##### （1）AOE 网与关键路径的概念

**AOE 网**（Activity On Edge Network）：在一个表示工程的带权有向图中，用**顶点表示事件**、用**有向边表示活动**、用**边上的权值表示活动的持续时间**。其中没有入边的顶点称为**源点**（工程的开始），没有出边的顶点称为**汇点**（工程的结束）。

**AOE 网的两条性质**：

1. 只有在某顶点所代表的事件发生后，从该顶点出发的各条有向边所代表的活动才能开始。
2. 只有在进入某顶点的各条有向边所代表的活动都已结束时，该顶点所代表的事件才能发生。另外，**有些活动是可以并行进行的**。

**AOV 网与 AOE 网对比**：

| 比较项 | AOV 网 | AOE 网 |
|---|---|---|
| 顶点含义 | 表示**活动** | 表示**事件** |
| 边含义 | 无权值，仅表示活动之间的先后顺序 | 有权值，表示活动的持续时间 |
| 典型问题 | 拓扑排序、判环 | 关键路径、工程最短工期 |

**路径长度**：路径上各个活动的持续时间之和。**从源点到汇点具有最大长度的路径称为关键路径**，关键路径上的活动称为**关键活动**。关键路径的长度就是完成整个工程所需的最短时间。

必背性质：

1. **关键路径可能不唯一，但所有关键路径的长度都相同**。
2. **增大某个关键活动的持续时间，一定会使关键路径变长**，从而延长工期。
3. **缩短某个关键活动的持续时间，不一定能缩短工期**——因为可能存在多条关键路径，只有同时缩短**所有关键路径上的关键活动**才能缩短总工期。
4. **关键活动不能任意缩短**：一旦缩短到一定程度，该关键活动可能变成非关键活动，关键路径会转移到其他路径上。

##### （2）四个关键量

| 量 | 含义 | 计算公式 |
|---|---|---|
| $ve(k)$ | 事件 $v_k$ 的**最早发生时间**，也是从源点到 $v_k$ 的**最长路径长度** | $ve(\text{源点})=0$；$ve(k)=\max\{ve(j)+w(j,k)\}$，$j$ 取遍 $k$ 的所有前驱 |
| $vl(k)$ | 事件 $v_k$ 的**最迟发生时间**，即在不推迟整个工程的前提下该事件最迟必须发生的时间 | $vl(\text{汇点})=ve(\text{汇点})$；$vl(k)=\min\{vl(j)-w(k,j)\}$，$j$ 取遍 $k$ 的所有后继 |
| $e(i)$ | 活动 $a_i$ 的**最早开始时间**，即该活动弧的**起点**所表示事件的最早发生时间 | 若边 $<v_k,v_j>$ 表示 $a_i$，则 $e(i)=ve(k)$ |
| $l(i)$ | 活动 $a_i$ 的**最迟开始时间**，即该活动弧的**终点**的最迟发生时间减去该活动持续时间 | 若边 $<v_k,v_j>$ 表示 $a_i$，则 $l(i)=vl(j)-w(v_k,v_j)$ |

**时间余量**：$d(i)=l(i)-e(i)$，表示在不增加整个工程总时间的情况下，活动 $a_i$ 可以拖延的时间。

$$d(i)=0 \iff l(i)=e(i) \iff a_i \text{ 是关键活动}$$

关键活动组成的路径就是关键路径。

:::warn 计算 $ve$ 与 $vl$ 的方向不要弄反

- **$ve$ 从源点向汇点正推**，用 **max**（取最长路径，因为事件必须等所有前驱活动都完成）。
- **$vl$ 从汇点向源点倒推**，用 **min**（取最紧的约束，因为不能推迟后面任何一个后继）。

一个常见的错误是算 $vl$ 时误用 max，或算 $ve$ 时误用 min。记住口诀：**正推求最早取最大，倒推求最迟取最小**。

:::

##### （3）标准解法五步

1. **正推求所有事件的 $ve()$**：从源点开始，按拓扑序依次计算 $ve(k)=\max\{ve(j)+w(j,k)\}$。
2. **倒推求所有事件的 $vl()$**：令 $vl(\text{汇点})=ve(\text{汇点})$，按逆拓扑序依次计算 $vl(k)=\min\{vl(j)-w(k,j)\}$。
3. **求所有活动的最早开始时间 $e()$**：对表示活动的边 $<v_k,v_j>$，$e=ve(k)$。
4. **求所有活动的最迟开始时间 $l()$**：对表示活动的边 $<v_k,v_j>$，$l=vl(j)-w(v_k,v_j)$。
5. **求所有活动的时间余量 $d=l-e$**：$d=0$ 的活动就是关键活动，由关键活动连成的源点到汇点的路径就是关键路径。

##### （4）完整手工模拟

设有 AOE 网，顶点 $v_1\sim v_6$，$v_1$ 为源点、$v_6$ 为汇点，活动（边）如下：

| 活动 | 弧 | 持续时间 | 活动 | 弧 | 持续时间 |
|---|---|---|---|---|---|
| $a_1$ | $v_1\to v_2$ | 3 | $a_5$ | $v_3\to v_4$ | 4 |
| $a_2$ | $v_1\to v_3$ | 2 | $a_6$ | $v_3\to v_6$ | 3 |
| $a_3$ | $v_2\to v_4$ | 2 | $a_7$ | $v_4\to v_6$ | 2 |
| $a_4$ | $v_2\to v_5$ | 3 | $a_8$ | $v_5\to v_6$ | 1 |

**第一步：正推求 $ve$（从 $v_1$ 向 $v_6$，取 max）**

$$ve(1)=0$$
$$ve(2)=ve(1)+3=3$$
$$ve(3)=ve(1)+2=2$$
$$ve(4)=\max\{ve(2)+2,\ ve(3)+4\}=\max\{5,\ 6\}=6$$
$$ve(5)=ve(2)+3=6$$
$$ve(6)=\max\{ve(3)+3,\ ve(4)+2,\ ve(5)+1\}=\max\{5,\ 8,\ 7\}=8$$

**第二步：倒推求 $vl$（从 $v_6$ 向 $v_1$，取 min），$vl(6)=ve(6)=8$**

$$vl(6)=8$$
$$vl(5)=vl(6)-1=7$$
$$vl(4)=vl(6)-2=6$$
$$vl(3)=\min\{vl(6)-3,\ vl(4)-4\}=\min\{5,\ 2\}=2$$
$$vl(2)=\min\{vl(5)-3,\ vl(4)-2\}=\min\{4,\ 4\}=4$$
$$vl(1)=\min\{vl(2)-3,\ vl(3)-2\}=\min\{1,\ 0\}=0$$

**第三、四、五步：求 $e$、$l$、$d$（$e=ve(\text{弧尾})$，$l=vl(\text{弧头})-\text{权值}$）**

| 活动 | 弧 | 权值 | $e=ve(\text{尾})$ | $l=vl(\text{头})-\text{权值}$ | $d=l-e$ | 是否关键 |
|---|---|---|---|---|---|---|
| $a_1$ | $v_1\to v_2$ | 3 | 0 | $4-3=1$ | 1 | 否 |
| $a_2$ | $v_1\to v_3$ | 2 | 0 | $2-2=0$ | **0** | **是** |
| $a_3$ | $v_2\to v_4$ | 2 | 3 | $6-2=4$ | 1 | 否 |
| $a_4$ | $v_2\to v_5$ | 3 | 3 | $7-3=4$ | 1 | 否 |
| $a_5$ | $v_3\to v_4$ | 4 | 2 | $6-4=2$ | **0** | **是** |
| $a_6$ | $v_3\to v_6$ | 3 | 2 | $8-3=5$ | 3 | 否 |
| $a_7$ | $v_4\to v_6$ | 2 | 6 | $8-2=6$ | **0** | **是** |
| $a_8$ | $v_5\to v_6$ | 1 | 6 | $8-1=7$ | 1 | 否 |

关键活动为 $a_2$、$a_5$、$a_7$，关键路径为 $v_1\to v_3\to v_4\to v_6$，长度 $2+4+2=8$，与 $ve(6)=8$ 一致。

**结果的工程解读**：整个工程最短需要 8 个时间单位完成。事件 $v_3$ 必须**准时**在第 2 个时间单位发生（$ve(3)=vl(3)=2$），也就是活动 $a_2$ 一天都不能拖；事件 $v_4$ 必须在第 6 个时间单位发生，由 $a_5$ 保障。反观活动 $a_6$（$v_3\to v_6$，时长 3），它的最早开始时间是 2、最迟开始时间是 5，余量为 3，意味着**只要在第 5 个时间单位之前开工即可**，提前或推后 3 个单位都不影响总工期。活动 $a_8$（$v_5\to v_6$，时长 1）余量为 1，$a_1$、$a_3$、$a_4$ 的余量也都是 1。这些余量正是工程调度中「松弛时间」的概念。

**如果要把工期从 8 压缩到 7，应当做什么？** 必须先找出所有关键路径（本例中只有一条：$v_1\to v_3\to v_4\to v_6$），然后缩短这条路径上某个活动的持续时间。但要注意两个约束：其一，如果图中有多条关键路径，必须**同时**缩短每一条关键路径上的活动，只缩短其中一条路径上的活动不会改变总工期（这也是统考反复考查的结论）；其二，缩短幅度受到余量的限制——若把 $a_5$ 从 4 缩到 3，则关键路径长度变为 $2+3+2=7$，此时路径 $v_1\to v_3\to v_4\to v_6$ 仍然是唯一最长路径；但若继续把 $a_5$ 缩到 2，关键路径长度变为 6，而 $v_1\to v_2\to v_5\to v_6$ 的长度为 $3+3+1=7$，关键路径就**转移**到了另一条路上，此时 $a_5$ 反而不是关键活动了。这就是「关键活动不能任意缩短，缩到一定程度会变成非关键活动」的具体含义。

##### （5）快速手算关键路径：删边法

考试时间紧张时可以用下面这个技巧：

1. **只求 $ve(k)$**，从源点开始正推。
2. 观察每个顶点：如果**指向 $k$ 的多条边产生的 $ve$ 值不相等**（即 $ve(j)+w(j,k)$ 有大有小），那么产生**较小值的那条边一定是非关键边，可以把它从图中删掉**；产生最大值的边（可能有两条及以上）保留。
3. 删边后可以继续向源点方向回溯删除，**直到遇到一个出度大于 1 的交叉点为止**。
4. $ve$ 全部求完后，在剩余的边上找出能连通源点和汇点的路径，这些路径就是关键路径。

以本章的模拟为例：$ve(4)=\max\{ve(2)+2,\ ve(3)+4\}$，其中 $ve(2)+2=5<6$，因此边 $v_2\to v_4$（$a_3$）可删；继续向源点回溯，$v_2$ 的入度只有 1，可继续删 $v_1\to v_2$（$a_1$），此时遇到 $v_1$（出度 2 > 1），停止。同理 $ve(6)=\max\{5,8,7\}$，$v_3\to v_6$ 与 $v_5\to v_6$ 可删。剩余边中连接 $v_1$ 与 $v_6$ 的路径只有 $v_1\to v_3\to v_4\to v_6$，即为唯一的关键路径。

:::exam 出题角度

关键路径历年考查 4 次左右。典型问法：(1) 给出 AOE 网，问「活动 $d$ 的最早开始时间和最迟开始时间分别是」，需要完整算出 $ve$、$vl$ 再套 $e$、$l$ 公式；(2) 问「时间余量最大的活动」，余量最大者偏离关键路径最远；(3) 问「加快哪些活动的进度可以缩短工程工期」，答案是必须覆盖**所有**关键路径的公共活动集合；(4) 判断叙述正误，注意「关键路径是从源点到汇点**边数最多**的路径」是**错的**（比的是持续时间之和而不是边数），「缩短任一关键活动一定能缩短工期」也是**错的**（多条关键路径时未必）。

:::

## 本章小结表

**一、核心公式与结论速查**

| 结论 | 表达式 / 内容 |
|---|---|
| 无向图度数之和 | $\sum TD(v_i)=2e$ |
| 有向图入度、出度之和 | $\sum ID(v_i)=\sum OD(v_i)=e$ |
| 无向完全图边数 | $n(n-1)/2$ |
| 有向完全图边数 | $n(n-1)$ |
| 连通图最少边数 | $n-1$（生成树） |
| 非连通无向图最多边数 | $(n-1)(n-2)/2$ |
| 强连通有向图最少边数 | $n$（一个环） |
| 生成树边数 | $n-1$ |
| 最短路径所含边数上限（非负权） | 任意连通图两点间最短路径至多 $n-1$ 条边（最短路径必是简单路径） |
| 度数为奇数的顶点个数 | 必为偶数 |
| 邻接矩阵幂 | $A^{k}[i][j]$ = $i$ 到 $j$ 长度为 $k$ 的路径数目 |

**二、六类应用算法总表**

| 算法 | 算法思想 | 关键数组 / 结构 | 时间复杂度 | 空间复杂度 | 适用 |
|---|---|---|---|---|---|
| Prim | 选**点**，贪心 | `dist`、`visited` | $O(\lvert V\rvert^{2})$ | $O(\lvert V\rvert)$ | 边稠密图 |
| Kruskal | 选**边**，贪心 + 并查集 | 边表排序、`parent` | $O(\lvert E\rvert\log\lvert E\rvert)$ | $O(\lvert V\rvert)$ | 边稀疏、点多 |
| Dijkstra | 贪心，分已确定/未确定集合 | `dist`、`path`、`final` | $O(\lvert V\rvert^{2})$ | $O(\lvert V\rvert)$ | 非负权单源最短路 |
| Floyd | 动态规划，逐个允许中转 | `dist[][]`、`path[][]` | $O(\lvert V\rvert^{3})$ | $O(\lvert V\rvert^{2})$ | 全源最短路，允许负权无负环 |
| 拓扑排序 | 入度为 0 者入队，出队后邻接点入度减 1 | `indegree`、队列 | 邻接表 $O(\lvert V\rvert+\lvert E\rvert)$；邻接矩阵 $O(\lvert V\rvert^{2})$ | $O(\lvert V\rvert)$ | DAG、判环 |
| 关键路径 | 求最长路径，找 $d=0$ 的活动 | `ve`、`vl`、`e`、`l` | $O(\lvert V\rvert+\lvert E\rvert)$ | $O(\lvert V\rvert+\lvert E\rvert)$ | AOE 网工期分析 |

| 结构 | 空间 | 求入度 | 求出度 | 删边 | 删点 | 适用 | 唯一性 |
|---|---|---|---|---|---|---|---|
| 邻接矩阵 | $O(\lvert V\rvert^{2})$ | $O(\lvert V\rvert)$ | $O(\lvert V\rvert)$ | $O(1)$ | $O(\lvert V\rvert)$ | 稠密图 | 唯一 |

## 易错清单

:::warn 概念类易错

1. **回路不是简单路径**。简单路径要求顶点全部不重复，而回路首尾顶点相同，至少重复了两个位置。要区分「简单路径」与「简单回路」。
2. **图的「距离」是边数，不是权值之和**。带权图中两点间的最短路径长度才是权值之和，术语上不要混用。
3. **连通分量是「极大连通子图」，不是「最大连通子图」**，也不是「最小连通子图」。极小连通子图指的是生成树。
4. **强连通图最少 $n$ 条边**（构成一个环），但 $n$ 条边不一定是强连通图（可能只是几个不相交的环加上别的结构）。
5. **有向图存在拓扑序列 ⇔ 无环**，与是否连通无关。有环时一定含顶点数大于 1 的强连通分量，但整个图未必强连通。
6. **非连通图只有生成森林，没有生成树**。生成树只对连通图定义。
7. **稀疏图与稠密图没有绝对界限**，一般以 $|E|<|V|\log|V|$ 为界。不要把它当成严格定义来判定。
8. **有向树要求恰好一个顶点入度为 0、其余顶点入度均为 1**，仅有这一条，出度不限制。

:::

:::warn 存储结构类易错

1. **「存储稀疏图用邻接矩阵比邻接表更省空间」是错的**。邻接矩阵恒为 $O(|V|^{2})$，与边数无关；邻接表为 $O(|V|+|E|)$。稀疏图中后者更省。
2. **邻接表表示不唯一，邻接矩阵表示唯一**。这条决定了遍历序列与生成树是否唯一。
3. **无向图的邻接表边结点数是 $2e$，有向图是 $e$**。无向图每条边存两份；若问「邻接多重表的边结点数」，则是 $e$（每边一份）。
4. **邻接表求有向图的入度需要遍历整个邻接表**，$O(|V|+|E|)$，不是 $O(1)$；求入度快的是**逆邻接表**和**十字链表**。
5. **删除顶点在邻接矩阵中是 $O(|V|)$**（将该行该列清零）；只有当题目要求把矩阵元素移动成紧凑形式时才需要 $O(|V|^{2})$。看清题目问的是哪种。
6. **十字链表用于有向图，邻接多重表用于无向图**，不要写反。
7. 邻接矩阵的带权形式中，**主对角线元素是 0 还是 $\infty$ 要看题目约定**，解题时按给定矩阵读，不要自己假设。

:::

:::warn 遍历类易错

1. **BFS 必须在顶点入队时就标记 `visited`**，不能等到出队时再标记，否则会重复入队。
2. **DFS 非递归实现弹出时要再次判 `visited`**，因为一个顶点可能被多次压栈。
3. **对无向图，调用 BFS/DFS 的次数等于连通分量数**；对有向图不能这样直接下结论。
4. **邻接矩阵存储时遍历序列唯一**（起点固定时），**邻接表存储时不唯一**。生成树同理。
5. **BFS 求单源最短路径只适用于无权图或各边权相等的图**，带不同权值时必须用 Dijkstra。
6. 无论 DFS 还是 BFS，空间复杂度都是 $O(|V|)$——BFS 是队列大小，DFS 是递归栈深度。

:::

:::warn 应用算法类易错

1. **Prim 选点、Kruskal 选边**。Prim 的时间复杂度只与顶点数有关，适合稠密图；Kruskal 只与边数有关，适合稀疏图。写反是最常见的失分点。
2. **MST 唯一性**：只有「各边权值互不相等」才是 MST 唯一的充分条件；等权边存在时可能有多个 MST，但**代价总是唯一的**。
3. **「所有权值最小的边一定出现在所有 MST 中」是错的**。若若干条最小权边构成环，不可能全部选入。
4. **Prim 与 Dijkstra 的 `dist` 含义完全不同**：Prim 是「到已选集合的最短边权」（不累加），Dijkstra 是「到源点的最短路径长」（累加）。代码结构相似但更新式不同。
5. **Dijkstra 不能处理负权边**。原因是贪心性质失效：一个顶点的最短距离一旦被确定就不再更新，而负权边可能让后来确定的顶点提供更短的路径。
6. **Dijkstra 的三层判断中，松弛只用「从 $u$ 出发」的边**，不是「与 $u$ 相连」的边——有向图与无向图的区别就在这里。
7. **Floyd 的三重循环 $k$ 必须在最外层**。$k$ 是 DP 的阶段（允许中转的顶点集合），$i,j$ 是同阶段内的状态。顺序写错结果会出错。
8. **Floyd 允许负权边但不允许负权回路**；存在负权回路时最短路径不存在。
9. **拓扑排序的出队顺序不唯一**，但「每个时刻入度为 0 的顶点只有一个」时唯一，此时图中存在一条包含所有顶点的路径。
10. **关键路径比的是路径上活动持续时间之和，不是边的条数**。$ve$ 正推取 max，$vl$ 倒推取 min，切勿弄反。
11. **缩短关键活动不一定缩短工期**：存在多条关键路径时，只有同时缩短所有关键路径上的活动才行。而**延长任一关键活动一定延长工期**。
12. **关键活动不能任意缩短**，缩短到一定程度它会变成非关键活动，关键路径转移。
13. **AOV 网顶点表示活动，AOE 网顶点表示事件**；AOE 网的边才带权值（活动持续时间）。

:::
