## 一、栈和队列的基本概念

### （一）栈的定义与特点

**栈（Stack）** 是只允许在**一端**进行插入和删除操作的线性表。允许插入和删除的一端称为**栈顶（top）**，另一端称为**栈底（bottom）**。不含任何元素的栈称为**空栈**。

栈的插入操作称为**入栈（push）**，删除操作称为**出栈（pop）**。由于插入和删除都被限制在栈顶，最后入栈的元素必定最先出栈，因此栈是**后进先出（Last In First Out，LIFO）**结构。

需要特别注意：栈是**操作受限的线性表**，这里的「受限」指「只允许在一端操作」，而不是「两端都能操作」。栈的逻辑结构与普通线性表完全相同，仍然是「一对一」的线性关系，改变的只是允许操作的端点。

:::warn 易错点
「栈允许在其两端进行操作」是错误说法。栈只在栈顶一端插入和删除；支持两端插入删除的是**双端队列（deque）**。栈底是固定不动的一端，不能直接对栈底元素操作，想访问栈底元素必须先把上面所有元素弹出。
:::

### （二）队列的定义与特点

**队列（Queue）** 是只允许在**一端插入、在另一端删除**的线性表。允许插入的一端称为**队尾（rear）**，允许删除的一端称为**队头（front）**。不含任何元素的队列称为**空队列**。

队列的插入操作称为**入队（enqueue）**，删除操作称为**出队（dequeue）**。先入队的元素必定先出队，因此队列是**先进先出（First In First Out，FIFO）**结构。

### （三）栈与队列的对比

| 比较项 | 栈 Stack | 队列 Queue |
|---|---|---|
| 操作端点 | 只在一端（栈顶）插入和删除 | 一端（队尾）插入，另一端（队头）删除 |
| 存取特性 | 后进先出 LIFO | 先进先出 FIFO |
| 逻辑结构 | 线性表 | 线性表 |
| 存储实现 | 顺序栈、链栈 | 顺序队列（含循环队列）、链队列 |
| 典型应用 | 括号匹配、表达式求值、递归、进制转换、DFS | 层次遍历、缓冲区、CPU 调度、BFS |

### （四）上溢与下溢

栈和队列在采用**顺序存储**时容量固定，因此存在两种异常状态：

- **上溢（overflow）**：栈满（或队满）时仍执行入栈（入队）操作。对栈来说，满了还往里写就是上溢。
- **下溢（underflow）**：栈空（或队空）时仍执行出栈（出队）操作。空了还往外读就是下溢。

顺序栈的上溢是**真上溢**，只要数组空间确实不够用就必然发生。而顺序队列的上溢可能是**假上溢**：由于出队只把 `front` 后移而不移动元素，数组前面的空位无法再利用，此时虽然数组内还有空位，`rear` 却已到达末尾，再入队就报「满」。循环队列正是为解决假上溢而提出的。

链式存储的栈和队列不存在上溢问题（只要内存还够就能申请新结点），但出队或出栈时仍要判空，否则会产生下溢。

:::warn 易错点
「上溢」「下溢」这两个词只用于顺序存储的讨论语境。链栈、链队列不需要判断「满」，因为结点是动态申请的，所以链式存储不存在上溢。
:::

### （五）共享栈

利用**栈底位置相对不变**的特性，可以让两个顺序栈共享同一个一维数组空间：两个栈的栈底分别设在数组两端，两个栈顶向中间延伸。

设共享数组为 `data[0..MaxSize-1]`，用 `top0` 表示 0 号栈的栈顶，`top1` 表示 1 号栈的栈顶。采用「栈顶指针指向当前栈顶元素」的约定时：

- 初始状态：`top0 = -1`，`top1 = MaxSize`（两个栈都为空）；
- 0 号栈入栈：`data[++top0] = x`；1 号栈入栈：`data[--top1] = x`；
- 判满条件：`top0 + 1 == top1`。

:::key 共享栈的核心结论
两个栈的栈顶指针**相邻**时（`top0 + 1 == top1`），整个数组被占满，此时才会发生上溢。

共享栈的意义是**只有在整个存储空间被占满时才上溢**，让两个栈的空间相互调节。存取数据的时间复杂度仍为 $O(1)$，对存取效率没有影响。

注意区分：共享栈判满用 `top0 + 1 == top1`（**全部**空间可用）；循环队列牺牲一个单元判满用 `(rear+1)\%M == front`（只存 **M-1** 个）。两者形式相似，含义完全相反，考场上极易混淆。
:::

## 二、栈和队列的顺序存储结构

### （一）顺序栈与 top 指针的两种约定

顺序栈用一组地址连续的存储单元依次存放栈底到栈顶的元素。**`top` 指针的含义有两种约定，两种都要掌握**，题目给出哪种就用哪种。

| 比较项 | 约定 A：top 指向栈顶元素 | 约定 B：top 指向栈顶元素的下一个位置 |
|---|---|---|
| 初始化 | `S.top = -1` | `S.top = 0` |
| 判空 | `S.top == -1` | `S.top == 0` |
| 判满 | `S.top == MaxSize - 1` | `S.top == MaxSize` |
| 入栈 | `S.data[++S.top] = x`（**先加后存**） | `S.data[S.top++] = x`（**先存后加**） |
| 出栈 | `x = S.data[S.top--]` | `x = S.data[--S.top]` |
| 取栈顶 | `S.data[S.top]` | `S.data[S.top - 1]` |
| 栈中元素个数 | `S.top + 1` | `S.top` |

代入一组数验证约定 B（`MaxSize = 3`）：初始 `top = 0` 为空；依次入栈 A、B、C 后，写入位置为 0、1、2，`top = 3`，此时 `top == MaxSize` 判满，元素个数为 `top = 3`，正确。再出栈一次，`--top` 得 2，栈顶元素是 `data[2] = C`，正确。

:::warn 易错点
考场上最容易错的不是公式本身，而是**入栈时先自增还是先存值**。判断方法：看 `top` 的含义。若 `top` 指向栈顶元素，则新元素必须放在 `top+1`，所以**先自增再存值**；若 `top` 指向空位（栈顶下一位置），则新元素直接放在 `top`，所以**先存值再自增**。题目里若出现 `top == 0` 表示空栈，说明采用的是约定 B。
:::

顺序栈的完整实现（采用约定 A，`top` 指向栈顶元素）：

```c
#define MaxSize 50
typedef struct {
    int data[MaxSize];   // 存放栈中元素
    int top;             // 栈顶指针，指向栈顶元素
} SqStack;

void InitStack(SqStack &S) { S.top = -1; }              // 初始化：空栈

bool StackEmpty(SqStack S) { return S.top == -1; }      // 判空

bool StackFull(SqStack S) { return S.top == MaxSize - 1; }   // 判满

bool Push(SqStack &S, int x) {                          // 入栈
    if (S.top == MaxSize - 1) return false;             // 栈满，上溢
    S.data[++S.top] = x;                                // 先加后存
    return true;
}

bool Pop(SqStack &S, int &x) {                          // 出栈
    if (S.top == -1) return false;                      // 栈空，下溢
    x = S.data[S.top--];                                // 先取后减
    return true;
}

bool GetTop(SqStack S, int &x) {                        // 读栈顶，不修改栈
    if (S.top == -1) return false;
    x = S.data[S.top];
    return true;
}
```

### （二）顺序队列的 front / rear 约定

顺序队列用数组 `data[0..MaxSize-1]` 存放元素，用 `front` 和 `rear` 两个指针指示队头与队尾。采用「**front 指向队头元素、rear 指向队尾元素的下一个位置**」的约定时：

- 初始化：`Q.front = Q.rear = 0`；
- 判空：`Q.front == Q.rear`；
- 入队：`Q.data[Q.rear] = x; Q.rear++;`（**front 不动，rear 变化**）；
- 出队：`x = Q.data[Q.front]; Q.front++;`（**rear 不动，front 变化**）；
- 元素所在区间：`[front, rear - 1]`。

:::key 一句话记住谁动
**入队时 `front` 指针不会变，变化的是 `rear` 指针；出队时 `rear` 指针不会变，变化的是 `front` 指针。** 选择题里经常用这句话直接排除错误选项。
:::

这种朴素顺序队列的问题在于：不断入队出队后 `front` 和 `rear` 都单调右移，`rear` 到达数组末尾就无法再入队，即便数组前面还有大量空位——这就是**假上溢**。解决办法是把数组在逻辑上首尾相接，即**循环队列**。

### （三）循环队列：三种判满方案

循环队列中所有指针移动都改为 `(x + 1) % MaxSize`。此时的困难在于：**队空时 `front == rear`，队满时 `front` 也可能等于 `rear`**，两种情况无法区分，必须额外增加信息。

#### 1. 方案一：牺牲一个存储单元

规定队列最多存放 `MaxSize - 1` 个元素，即数组中**永远保留一个空位**，用它隔开「满」和「空」两种状态。

约定：`front` 指向队头元素，`rear` 指向队尾元素的后一个位置。

- 判空：`front == rear`；
- 判满：`(rear + 1) % MaxSize == front`；
- 元素个数：`(rear - front + MaxSize) % MaxSize`。

**推导**：队满时，若再入队一个元素，新的 `rear` 会变成 `(rear+1)%MaxSize`，此时它与 `front` 重合，队列就再也分不清是空还是满了。因此我们在「下一个 `rear` 即将等于 `front`」时就判定为满，把那个位置空出来不用。这就是「牺牲一个单元」的由来。

**代入验证**（`MaxSize = 5`）：初始 `front = rear = 0`，判空成立。依次入队 10、20、30，则 `data[0..2] = {10,20,30}`，`rear = 3`。元素个数 $=(3-0+5)\%5=3$，与实际相符。再入队 40，`rear = 4`，`(4+1)\%5 = 0 == front`，判满成立，此时队列中确实是 4 个元素（= `MaxSize - 1`）。

再验证「绕回」的情形：在上面的状态下出队两次，`front = 2`；再入队 50、60，`data[4]=50` 后 `rear=0`，`data[0]=60` 后 `rear=1`。此时元素个数 $=(1-2+5)\%5=4$，队列中实际元素为 `data[2],data[3],data[4],data[0]` 共 4 个，正确。注意这里 **`rear < front`**，正是选择题最爱的陷阱情形。

#### 2. 方案二：增设 size 计数器

在结构体中增设一个 `int size`（有的教材叫 `count`、`queSize`）记录当前元素个数，所有 `MaxSize` 个单元都可以使用。

- 入队：`size++`；出队：`size--`；
- 判空：`size == 0`；
- 判满：`size == MaxSize`；
- 两个指针的判据 `front == rear` 此时已经**不能**用来区分空和满了（两种情况都成立）。

**代入验证**（`MaxSize = 5`）：连续入队 5 个元素，`size = 5` 判满，此时 `front == rear == 0`（`rear` 绕回一圈），说明仅凭指针无法判断，必须依赖 `size`。

#### 3. 方案三：增设 tag 标记

增设一个 `bool tag`，专门记录**最近一次操作是入队还是出队**（也有教材记「最近一次删除的是否为插入」）。

- 初始化：`front = rear = 0`，`tag = false`；
- 入队成功后：`tag = true`；
- 出队成功后：`tag = false`；
- 判空：`front == rear && tag == false`；
- 判满：`front == rear && tag == true`。

**为什么有效**：两个指针相等时，若上一次操作是入队，说明是「刚填满一圈追上 `front`」→ 队满；若上一次操作是出队，说明是「刚把最后一个元素取走」→ 队空。如果入队次数与出队次数恰好相等而互相抵消，则最后一次操作必为出队，`tag` 为 `false`，判空成立，正好符合实际。

三种方案的对比与代码要点：

| 方案 | 判空 | 判满 | 最大容量 | 需要额外变量 | 指针相等时的含义 |
|---|---|---|---|---|---|
| 牺牲一个单元 | `front == rear` | `(rear+1)%M == front` | `M - 1` | 无 | 一定是队空 |
| 设 size | `size == 0` | `size == M` | `M` | `int size` | 不确定，看 `size` |
| 设 tag | `front==rear && !tag` | `front==rear && tag` | `M` | `bool tag` | 由 `tag` 决定 |

```c
// 循环队列：牺牲一个存储单元的写法（rear 指向队尾元素的下一个位置）
#define MaxSize 50
typedef struct {
    int data[MaxSize];
    int front, rear;
} SqQueue;

void InitQueue(SqQueue &Q) { Q.front = Q.rear = 0; }

bool QueueEmpty(SqQueue Q) { return Q.front == Q.rear; }

bool QueueFull(SqQueue Q) { return (Q.rear + 1) % MaxSize == Q.front; }

bool EnQueue(SqQueue &Q, int x) {
    if ((Q.rear + 1) % MaxSize == Q.front) return false;   // 队满
    Q.data[Q.rear] = x;
    Q.rear = (Q.rear + 1) % MaxSize;                       // rear 循环后移
    return true;
}

bool DeQueue(SqQueue &Q, int &x) {
    if (Q.front == Q.rear) return false;                   // 队空
    x = Q.data[Q.front];
    Q.front = (Q.front + 1) % MaxSize;                     // front 循环后移
    return true;
}

int QueueLength(SqQueue Q) {
    return (Q.rear - Q.front + MaxSize) % MaxSize;
}
```

增设 `tag` 的入队、出队要点：

```c
// 设 tag 的写法：front == rear 时由 tag 区分空满
bool EnQueue(SqQueue &Q, int x) {
    if (Q.front == Q.rear && Q.tag == true) return false;  // 队满
    Q.data[Q.rear] = x;
    Q.rear = (Q.rear + 1) % MaxSize;
    Q.tag = true;                                          // 记「刚做过入队」
    return true;
}

bool DeQueue(SqQueue &Q, int &x) {
    if (Q.front == Q.rear && Q.tag == false) return false; // 队空
    x = Q.data[Q.front];
    Q.front = (Q.front + 1) % MaxSize;
    Q.tag = false;                                         // 记「刚做过出队」
    return true;
}
```

:::warn 易错点
（1）**循环队列的容量不等于数组长度**。用「牺牲一个单元」的方案时，`MaxSize = 6` 的数组最多只能存 5 个元素。

（2）**取模的模数永远是数组长度 `MaxSize`**，很多错误选项会写成 `% (MaxSize - 1)`、`% (M-1)`，直接排除。

（3）**元素个数公式必须加 `MaxSize` 再取模**。写成 `(rear - front) % MaxSize` 在 `rear < front`（已绕回）时结果错误。举特例时优先举 `rear < front` 的例子（如 `rear = 1`、`front = 5`），最容易看出哪个含 `mod` 的式子正确。

（4）**要看清题目给的是哪种指针约定**。若题目说「`front` 指向队头元素的**前一个**位置，`rear` 指向队尾元素」，则判空是 `(rear+1)%M == front`、判满是 `(rear+2)%M == front`，与常见写法完全反过来。做法：先按题目约定画出初始空队列，数出两个指针的初始位置，再判断「空」和「满」时指针相差多少格。
:::

:::exam 真题考法
循环队列是本章最高频的选择题点。典型问法有三类：

- 给出一维数组 `A[0..n-1]` 与指针指向约定，问**初始时 `front`、`rear` 的值**（如 2011 年考「第一个元素要存到 `A[0]`，求初始指针」，答案为 `front = 0, rear = n-1`）；
- 给出 `end1`、`end2` 的指向与「最多容纳 M-1 个元素」，问**判空判满条件**（2014 年，答案为「队空 `end1 == end2`；队满 `end1 == (end2+1) mod M`」）；
- 给出队头和队尾指针的当前值，问**队列中元素个数**或**再入队/出队后的状态**。

2019 年还考过一道 10 分的应用题：要求队列「入队时允许增加空间、出队后空间可重复使用、整个队列占用空间只增不减、入队出队均为 $O(1)$」，答案是采用**不设容量上限的循环单链表**，队首指针指向第一个含关键字结点、队尾指针指向队尾元素的下一个空闲结点，判空 `front == rear`、判满 `rear->next == front`，出队时不释放结点只移动 `front`。
:::

### （四）双端队列（受限双端队列）

**双端队列（deque）** 是允许在两端插入和删除的线性表。统考常考它的三种受限形态：

| 形态 | 允许入队 | 允许出队 | 别称 |
|---|---|---|---|
| 输入受限双端队列 | 仅一端 | 两端 | — |
| 输出受限双端队列 | 两端 | 仅一端 | — |
| 标准双端队列 | 两端 | 两端 | — |

判断某输出序列是否可由受限双端队列得到，最稳妥的办法是**从输出序列的第一项倒推**，或用「分段」技巧：

- **一端仅入队、另一端可入可出**（输出受限）：最终输出序列必可分成**前后两段**，前一段相对于入队序列是**逆序**的（这些元素从「可出端」入队，被后来的元素压在后面），后一段是**正序**的（从另一端入队）。
- 判断时先尝试找一个分界点，使前面逆序、后面正序；找不到分界点则该序列不可能。

## 三、栈和队列的链式存储结构

### （一）链栈

采用链式存储的栈称为**链栈**。链栈通常用**不带头结点的单链表**实现，并规定**所有操作都在单链表的表头进行**：表头结点即栈顶，表尾结点即栈底。

链栈的优点是便于多个栈共享存储空间、提高效率，且**不存在栈满上溢**的情况。缺点是每个元素都要额外保存指针域，且在「栈空」时需要特别处理空指针。

| 操作 | 带头结点 | 不带头结点 |
|---|---|---|
| 初始化 | 申请头结点，`S->next = NULL` | `S = NULL`（或 `top = NULL`） |
| 判空 | `S->next == NULL` | `S == NULL` |
| 入栈 | 头插法：`p->next = S->next; S->next = p;` | 头插法：`p->next = top; top = p;` |
| 出栈 | 摘下 `S->next` 并 `free` | 摘下 `top` 并 `free` |

```c
// 链栈：不带头结点，top 直接指向栈顶结点
typedef struct StackNode {
    int data;
    struct StackNode *next;
} StackNode, *LinkStack;

void InitStack(LinkStack &S) { S = NULL; }                   // 初始化
bool StackEmpty(LinkStack S) { return S == NULL; }           // 判空

bool Push(LinkStack &S, int x) {                             // 入栈 = 头插法
    StackNode *p = (StackNode *)malloc(sizeof(StackNode));
    if (p == NULL) return false;                             // 内存不足
    p->data = x;
    p->next = S;                                             // 新结点指向原栈顶
    S = p;                                                   // 更新栈顶指针
    return true;
}

bool Pop(LinkStack &S, int &x) {                             // 出栈 = 头删法
    if (S == NULL) return false;                             // 栈空，下溢
    StackNode *p = S;
    x = p->data;
    S = p->next;                                             // 栈顶指针下移
    free(p);
    return true;
}

bool GetTop(LinkStack S, int &x) {
    if (S == NULL) return false;
    x = S->data;
    return true;
}
```

:::warn 易错点
（1）**链栈的入栈是「头插法」，出栈是「头删法」**，不要在链尾操作——链尾操作需要 $O(n)$ 时间找到尾结点。

（2）链栈出栈时**必须先保存待删结点的地址再移动指针**，否则 `free` 后无法再接上链表。

（3）链栈的存储空间是动态申请的，因此**不需要判满**；但出栈前**必须判空**，否则会对 NULL 解引用。
:::

### （二）链队列（带头结点）

链队列是**同时带有队头指针和队尾指针的单链表**。队头指针指向队头结点（带头结点时指向头结点），队尾指针指向队尾结点。

**带头结点**的链队列判空与出队都比较统一：

- 判空：`Q.front == Q.rear`（队头、队尾指针指向同一个头结点）；
- 入队：新结点接在 `Q.rear` 之后，再让 `Q.rear` 指向新结点；
- 出队：摘下 `Q.front->next`，**若摘下的结点正是队尾结点，还必须把 `Q.rear` 拉回 `Q.front`**，否则 `rear` 会变成野指针。

```c
// 链队列：带头结点
typedef struct QNode {
    int data;
    struct QNode *next;
} QNode;

typedef struct {
    QNode *front, *rear;     // 队头指针、队尾指针
} LinkQueue;

void InitQueue(LinkQueue &Q) {                       // 初始化
    Q.front = Q.rear = (QNode *)malloc(sizeof(QNode));  // 建立头结点
    Q.front->next = NULL;
}

bool QueueEmpty(LinkQueue Q) { return Q.front == Q.rear; }   // 判空

void EnQueue(LinkQueue &Q, int x) {                  // 入队：只动 rear
    QNode *s = (QNode *)malloc(sizeof(QNode));
    s->data = x;
    s->next = NULL;
    Q.rear->next = s;                                // 新结点接到队尾之后
    Q.rear = s;                                      // 更新队尾指针
}

bool DeQueue(LinkQueue &Q, int &x) {                 // 出队：只动 front
    if (Q.front == Q.rear) return false;             // 队空
    QNode *p = Q.front->next;                        // p 指向真正的队头结点
    x = p->data;
    Q.front->next = p->next;                         // 摘下队头结点
    if (Q.rear == p) Q.rear = Q.front;               // 若摘的是最后一个结点，rear 归位
    free(p);
    return true;
}
```

### （三）链队列（不带头结点）

不带头结点时，队空表现为 `Q.front == NULL && Q.rear == NULL`。出队和入队的边界情况都更多：

- 判空：`Q.front == NULL`（等价于 `Q.rear == NULL`）；
- 入队：新建结点后置 `next = NULL`；**若原队列为空，则 `front` 和 `rear` 同时指向新结点**，否则接到 `Q.rear` 之后并只更新 `rear`；
- 出队：**若出队的是最后一个结点，出队后必须把 `front` 和 `rear` 同时置为 NULL**，否则 `rear` 悬空。

```c
// 链队列：不带头结点
void InitQueue(LinkQueue &Q) { Q.front = Q.rear = NULL; }

bool QueueEmpty(LinkQueue Q) { return Q.front == NULL; }

void EnQueue(LinkQueue &Q, int x) {
    QNode *s = (QNode *)malloc(sizeof(QNode));
    s->data = x;
    s->next = NULL;
    if (Q.front == NULL) {          // 队列原本为空
        Q.front = Q.rear = s;       // 首尾指针同时指向新结点
    } else {
        Q.rear->next = s;           // 否则只更新队尾
        Q.rear = s;
    }
}

bool DeQueue(LinkQueue &Q, int &x) {
    if (Q.front == NULL) return false;   // 队空
    QNode *p = Q.front;
    x = p->data;
    Q.front = p->next;                   // 队头指针后移
    if (Q.front == NULL) Q.rear = NULL;  // ★ 出队后为空，rear 也要置空
    free(p);
    return true;
}
```

:::key 带头结点与不带头结点的取舍
**判空判满与边界处理的差别，本质上就是「有没有那个不存数据的头结点」。** 带头结点时，`front == rear` 唯一对应队空，出队永远摘 `front->next`，不用讨论「摘到最后一个」这种特殊情况；不带头结点时，队空的表示、第一个元素入队、最后一个元素出队都要单独处理。

统考选择题里最常考的两句话：
- 「最适合用作链式队列的是**带有队首指针和队尾指针的非循环单链表**」；
- 「只带队首指针的非循环单链表，入队需要遍历到表尾，时间复杂度 $O(n)$，因此不适合」。

另外，**带尾指针的循环单链表**求队头和队尾都在 $O(1)$ 内（`rear->next` 就是队头结点），也可以用作链队列；带首尾指针的**循环**单链表虽然可行，但每次修改指针还要维护循环特性，属于画蛇添足。

链队列同样**不存在队满上溢**，出队前判空是唯一必需的边界检查。与顺序队列相比，链队列的缺点是每个结点都有指针开销，且不能随机访问第 $k$ 个元素。
:::

## 四、多维数组的存储

### （一）数组的定义与一维地址公式

**数组**是由 $n\ (n \ge 1)$ 个**相同类型**的数据元素构成的有限序列。每个元素在 $n$ 个线性关系中的序号称为该元素的**下标**，下标的取值范围称为数组的**维界**。

一维数组 `a[0..n-1]` 中，每个元素占 $L$ 个存储单元，则：

$$LOC(a_i) = LOC(a_0) + i \times L$$

其中 $LOC(a_i)$ 表示元素 $a_i$ 的存储地址（首地址），$LOC(a_0)$ 是数组起始地址，$i$ 是下标，$L$ 是单个元素占用的字节数。

**若下标从 1 开始**（即 `a[1..n]`），则 $a_i$ 前面有 $i-1$ 个元素，公式变为：

$$LOC(a_i) = LOC(a_1) + (i - 1) \times L$$

### （二）二维数组的行优先与列优先

二维数组可以看成一维数组的推广。按「先存哪一维」的不同，有两种映射方式：

- **行优先（行主序）**：先行后列。先存行号较小的元素，行号相同时先存列号较小的元素。
- **列优先（列主序）**：先列后行。先存列号较小的元素，列号相同时先存行号较小的元素。

设二维数组 $A$ 的行下标范围是 $[0, h_1]$、列下标范围是 $[0, h_2]$，每个元素占 $L$ 个单元，则共有 $(h_1+1)$ 行、$(h_2+1)$ 列。

**行优先地址公式**：

$$LOC(a_{ij}) = LOC(a_{00}) + \left[\, i \times (h_2 + 1) + j \,\right] \times L$$

**列优先地址公式**：

$$LOC(a_{ij}) = LOC(a_{00}) + \left[\, j \times (h_1 + 1) + i \,\right] \times L$$

符号说明：$i$ 为行下标，$j$ 为列下标，$h_2 + 1$ 是**每行的元素个数**（即列数 $n$），$h_1 + 1$ 是**每列的元素个数**（即行数 $m$），$L$ 为每个元素占用的存储单元数。

**行优先公式的推导**：$a_{ij}$ 之前有完整的 $i$ 行（第 $0$ 行到第 $i-1$ 行），每行 $h_2+1$ 个元素，共 $i \times (h_2+1)$ 个；本行中列号小于 $j$ 的元素还有 $j$ 个。因此 $a_{ij}$ 是数组中的第 $i(h_2+1)+j$ 个元素（从 0 开始编号），偏移量乘以 $L$ 即为字节偏移。

**列优先公式同理**：$a_{ij}$ 之前有完整的 $j$ 列，每列 $h_1+1$ 个元素，共 $j(h_1+1)$ 个；本列中行号小于 $i$ 的元素有 $i$ 个。

**代入验证**：设 $A$ 为 $4 \times 5$ 的二维数组（$h_1 = 3$，$h_2 = 4$），$L = 2$ 字节，$LOC(a_{00}) = 1000$。

- 行优先求 $LOC(a_{2,3})$：偏移量 $= 2 \times 5 + 3 = 13$，地址 $= 1000 + 13 \times 2 = 1026$。
- 列优先求 $LOC(a_{2,3})$：偏移量 $= 3 \times 4 + 2 = 14$，地址 $= 1000 + 14 \times 2 = 1028$。

两者不同是正确的——同一个元素在两种存储顺序下的位置本来就不一样。再看一个极端情形：行优先下 $LOC(a_{2,0})$ 的偏移量是 $10$，$LOC(a_{1,4})$ 的偏移量是 $9$，确实 $a_{1,4}$ 排在 $a_{2,0}$ 前面，符合「先行后列」。

### （三）下标从 0 与从 1 开始的差异

统考题目经常混用「C 语言数组下标从 0 开始」和「矩阵元素下标从 1 开始」（如 $m_{ij}$ 满足 $1 \le i \le n$），这是最容易丢分的地方。

设矩阵为 $n$ 行 $m$ 列，行优先，每元素占 $L$ 个单元：

- **下标从 0 开始**（$i \in [0, n-1]$，$j \in [0, m-1]$）：
  $$LOC(a_{ij}) = LOC(a_{00}) + (i \times m + j) \times L$$
- **下标从 1 开始**（$i \in [1, n]$，$j \in [1, m]$）：
  $$LOC(a_{ij}) = LOC(a_{11}) + \left[\,(i-1) \times m + (j-1)\,\right] \times L$$

两者的区别仅仅是**每个下标都减 1**，把「下标从 1 起」换成从 0 起的相对编号即可。做题时建议统一换算成「以 0 为基的偏移量」再计算，不要直接背两套公式。

:::exam 真题考法
2021 年考过一道典型题：二维数组 $A$ 按行优先存储，每个元素占 1 个存储单元，$A[0][0]$ 的地址是 100，$A[3][3]$ 的地址是 220，求 $A[5][5]$ 的地址。

解法：设每行 $n$ 个元素，则 $LOC(a_{33}) = LOC(a_{00}) + (3n+3) \times 1 = 100 + 3n + 3$，令它等于 220 解得 $3n = 117$，即 $n = 39$。于是 $LOC(a_{55}) = 100 + (5 \times 39 + 5) = 100 + 200 = 300$。

这类题的关键是**先用已知条件反解出「每行多少个元素」**，再套公式。
:::

## 五、特殊矩阵的压缩存储

### （一）压缩存储的基本思路

**矩阵的压缩存储**：为多个值相同的元素只分配一个存储空间，对零元素不分配空间。

普通二维数组按行优先存放 $n \times n$ 矩阵需要 $n^2$ 个单元；若矩阵中有大量元素相同或为零，就可以只存「有用的部分」，其余部分由映射规则推算出来，从而把空间降到 $O(n)$ 或 $O(n)$ 以下的常数倍。

压缩存储的两步固定套路：

1. **确定存哪些元素、按什么顺序存**，数出一维数组的总长度（一般是一个等差数列求和）；
2. **把矩阵下标 $(i,j)$ 映射为一维数组下标 $k$**，即数出 $a_{ij}$ 之前共有多少个元素。

### （二）对称矩阵

若 $n$ 阶方阵 $A$ 中任意元素都满足 $a_{ij} = a_{ji}$，则称 $A$ 为**对称矩阵**。

对称矩阵关于主对角线对称，因此只需存储**主对角线 + 下三角区**（或主对角线 + 上三角区），共

$$S = 1 + 2 + \cdots + n = \frac{n(n+1)}{2}$$

个元素。一维数组最后一个元素的下标为 $\dfrac{n(n+1)}{2} - 1$（数组下标从 0 开始）。

#### 1. 存主对角线 + 下三角区，按行优先

元素 $a_{ij}$ 满足 $i \ge j$（在下三角区或主对角线上）时，直接取值：

$$k = \frac{i(i+1)}{2} + j$$

下标从 0 开始。**推导**：$a_{ij}$ 之前有完整的第 $0$ 行到第 $i-1$ 行，元素个数为 $1 + 2 + \cdots + i = \dfrac{i(i+1)}{2}$；本行中列号小于 $j$ 的元素还有 $j$ 个（列号 $0, 1, \cdots, j-1$）。所以 $a_{ij}$ 是第 $\dfrac{i(i+1)}{2} + j$ 个元素，从 0 开始编号即为该式。

**代入验证**：$n = 4$，数组下标从 0 开始。求 $a_{2,1}$：$k = \dfrac{2 \times 3}{2} + 1 = 3 + 1 = 4$。逐个手排验证：$a_{00} \to 0$，$a_{10} \to 1$，$a_{11} \to 2$，$a_{20} \to 3$，$a_{21} \to 4$，完全吻合。再验证对角元 $a_{3,3}$：$k = \dfrac{3 \times 4}{2} + 3 = 6 + 3 = 9$，而 $\dfrac{4 \times 5}{2} - 1 = 9$，正好是最后一个元素，吻合。

#### 2. 存主对角线 + 下三角区，按列优先

列优先时，**第 $c$ 列只有 $a_{cc}, a_{c+1,c}, \cdots, a_{n-1,c}$ 共 $n - c$ 个元素**（因为是下三角，第 $c$ 列第一个被存储的元素是主对角线上的 $a_{cc}$）。

$a_{ij}$（$i \ge j$）所在第 $j$ 列的**前面**有第 $0$ 列到第 $j-1$ 列，元素个数为

$$\sum_{c=0}^{j-1}(n-c) = jn - \frac{j(j-1)}{2}$$

$a_{ij}$ 在本列中位于 $a_{jj}$ 之后的第 $i - j$ 个位置。因此

$$k = j\,n - \frac{j(j-1)}{2} + (i - j) \quad (i \ge j,\ \text{列优先})$$

**代入验证**：$n = 4$，数组下标从 0 开始。手排第 0 列 $a_{00},a_{10},a_{20},a_{30}$ 占下标 0～3；第 1 列 $a_{11},a_{21},a_{31}$ 占下标 4～6；第 2 列 $a_{22},a_{32}$ 占下标 7、8。

求 $a_{21}$（$i=2, j=1$）：$k = 1 \times 4 - \dfrac{1 \times 0}{2} + (2-1) = 4 + 1 = 5$。手排中 $a_{21}$ 是第 1 列的第 2 个元素（$a_{11}$ 是第 1 个），下标为 $4 + 1 = 5$，吻合。

再验证一个 $j$ 较大的情形，$a_{32}$（$i=3, j=2$）：$k = 2 \times 4 - \dfrac{2 \times 1}{2} + (3-2) = 8 - 1 + 1 = 8$。手排中第 2 列从下标 7 开始（$a_{22} \to 7$，$a_{32} \to 8$），吻合。同时 $k = 8$ 正好是数组最后一个下标 $\dfrac{4 \times 5}{2} - 1 = 9$ 之前的位置——注意 $a_{33}$ 才是最后一个元素（$k = 3 \times 4 - 3 + 0 = 9$），也对得上。

:::key 对称矩阵总表（下标从 0 开始）
设 $n$ 阶对称矩阵，只压缩存储**主对角线 + 下三角区**，一维数组 $B$ 共 $\dfrac{n(n+1)}{2}$ 个单元：

| 存储顺序 | $i \ge j$ 时 $k$ 的取值 | $i < j$ 时如何取值 |
|---|---|---|
| **行优先** | $k = \dfrac{i(i+1)}{2} + j$ | 利用对称性：$a_{ij} = a_{ji}$，代入 $k = \dfrac{j(j+1)}{2} + i$ |
| **列优先** | $k = jn - \dfrac{j(j-1)}{2} + (i - j)$ | 利用对称性：$a_{ij} = a_{ji}$，代入列优先公式（此时 $j < i$ 视为 $(i',j') = (j,i)$） |

**记忆要点**：行优先的公式 $\dfrac{i(i+1)}{2} + j$ 最好记，也最常考。题目给出「上三角」时不要另背新公式，**先用对称性把元素翻到下三角**再套公式，一条公式包打天下。

**翻下标的验证**：$n = 4$，按列优先存下三角。求 $a_{02}$（$i=0<j=2$，在**上三角**，不属于直接存储区）。用对称性得 $a_{02} = a_{20}$，代入 $i'=2$、$j'=0$：$k = 0 \times 4 - \dfrac{0 \times (-1)}{2} + (2 - 0) = 2$。手排第 0 列是 $a_{00},a_{10},a_{20},a_{30}$（下标 0～3），$a_{20}$ 的下标正是 2，吻合。
:::

#### 3. 存主对角线 + 上三角区

若题目要求存储**主对角线 + 上三角区**，则按行优先时 $a_{ij}$（$i \le j$）之前有完整的第 $0$ 行到第 $i-1$ 行，第 $c$ 行有 $n - c$ 个元素，个数为

$$\sum_{c=0}^{i-1}(n-c) = in - \frac{i(i-1)}{2}$$

再加上本行中列号小于 $j$ 的元素 $j - i$ 个，得

$$k = in - \frac{i(i-1)}{2} + (j - i) \quad (i \le j)$$

**代入验证**：$n = 4$，按行优先存上三角。手排：第 0 行 $a_{00},a_{01},a_{02},a_{03}$ 占下标 0～3；第 1 行 $a_{11},a_{12},a_{13}$ 占下标 4～6；第 2 行 $a_{22},a_{23}$ 占下标 7、8。求 $a_{12}$：$k = 1 \times 4 - \dfrac{1 \times 0}{2} + (2-1) = 4 + 1 = 5$，手排中 $a_{12}$ 是第 1 行第 1 个，下标 $4 + 1 = 5$，吻合。

:::exam 真题考法
对称矩阵的压缩存储是本章计算题第一高频点。统考的常见包装方式是「给 $n \times n$ 对称矩阵，只存上三角（或下三角）部分，按行（或列）优先存入下标从 0 开始的一维数组 $N$，求某元素的下标」。三条实战建议：

1. **先判断该元素属于哪一半**。若元素在下三角而题目只存上三角，用 $a_{ij} = a_{ji}$ 翻过去（如 2020 年题给 $m_{7,2}$，$10 \times 10$ 对称矩阵只存上三角，$7 > 2$ 在下三角，翻成 $m_{2,7}$）。
2. **老老实实数「它前面有几个元素」**，不要临时推导新公式。例如 2018 年题：$12 \times 12$ 对称矩阵只存上三角、按行优先，求 $m_{6,6}$。第 1 行存 12 个、第 2 行存 11 个、……、第 5 行存 8 个，共 $12+11+10+9+8 = 50$ 个；$m_{6,6}$ 是第 6 行第一个元素，故下标为 50。
3. **注意题目用的是 1 起始下标还是 0 起始下标**。题目说「$m_{ij}$，$1 \le i \le j \le 12$」说明矩阵下标从 1 起，而「存入下标从 0 开始的一维数组」说明数组从 0 起，两者各按各的口径数。
:::

### （三）三角矩阵

- **下三角矩阵**：主对角线及下三角区以外的元素（即上三角区）**全部为同一个常数** $c$（通常为 0）。
- **上三角矩阵**：主对角线及上三角区以外的元素（即下三角区）**全部为同一个常数** $c$。

与对称矩阵的关键区别：三角矩阵**不可利用对称性互相转换**，下三角矩阵的零区不能通过下标翻转来访问，必须单独存一个常数。

**压缩策略（以下三角矩阵为例）**：按行优先存主对角线 + 下三角区，并把那个常数存在一维数组的**最后一个位置**。

一维数组长度为

$$S = \frac{n(n+1)}{2} + 1$$

最后一个元素的下标为 $\dfrac{n(n+1)}{2}$。

映射关系（下标从 0 开始）：

$$k = \begin{cases} \dfrac{i(i+1)}{2} + j, & i \ge j \ (\text{下三角区或主对角线}) \\[6pt] \dfrac{n(n+1)}{2}, & i < j \ (\text{上三角区，取常数 } c) \end{cases}$$

**代入验证**：$n = 3$，下三角矩阵

$$A = \begin{pmatrix} a_{00} & c & c \\ a_{10} & a_{11} & c \\ a_{20} & a_{21} & a_{22} \end{pmatrix}$$

手排（行优先，存下三角 + 常数）：下标 0 存 $a_{00}$，1 存 $a_{10}$，2 存 $a_{11}$，3 存 $a_{20}$，4 存 $a_{21}$，5 存 $a_{22}$，6 存常数 $c$。数组长度为 $\dfrac{3 \times 4}{2} + 1 = 7$，最后下标为 6。用公式求 $a_{21}$：$k = \dfrac{2 \times 3}{2} + 1 = 3 + 1 = 4$，吻合。求 $a_{02}$（$i < j$）：$k = \dfrac{3 \times 4}{2} = 6$，取得常数 $c$，吻合。

**上三角矩阵**按行优先存主对角线 + 上三角区时，$a_{ij}$（$i \le j$）的映射为

$$k = i\,n - \frac{i(i-1)}{2} + (j - i)$$

其余位置（$i > j$）取一维数组最后一个单元中的常数。

:::warn 易错点
（1）**对称矩阵与三角矩阵的公式看起来一样，但 $i < j$（或 $i > j$）时的处理完全不同**：对称矩阵靠 $a_{ij}=a_{ji}$ 翻下标访问，三角矩阵直接返回常数区的那个单元。

（2）**三角矩阵的一维数组要多开 1 个单元存常数**，长度是 $\dfrac{n(n+1)}{2} + 1$ 而不是 $\dfrac{n(n+1)}{2}$。考试若问「数组至少需要多少个元素」，答 $\dfrac{n(n+1)}{2}+1$。

（3）用「行优先」还是「列优先」要看清题干，两者的 $k$ 公式不同。若题目没说明，统考默认**按行优先**。
:::

### （四）三对角矩阵（带状矩阵）

**三对角矩阵**又称**带状矩阵**：$n$ 阶方阵 $A$ 中，当 $|i - j| > 1$ 时 $a_{ij} = 0$。也就是说非零元素只集中在以主对角线为中心的 **3 条对角线**上：主对角线、主对角线下方一条、主对角线上方一条。

每行的非零元素个数：第 1 行（下标 $i=1$）只有 2 个，第 2 行到第 $n-1$ 行各有 3 个，第 $n$ 行只有 2 个。总数为

$$2 + 3(n-2) + 2 = 3n - 2$$

一维数组最后一个元素的下标为 $3n - 3$（下标从 0 开始）。

**按行优先压缩存储的映射公式**（下标从 1 开始，即 $1 \le i, j \le n$）：

$$k = 2i + j - 3 \quad (|i - j| \le 1)$$

**推导**：$a_{ij}$ 之前有完整的 $i - 1$ 行。其中第 1 行有 2 个元素，第 2 行到第 $i-1$ 行共有 $i - 2$ 行、每行 3 个，合计 $2 + 3(i-2) = 3i - 4$ 个。$a_{ij}$ 在本行中是第 $j - i + 2$ 个（本行元素依次是 $a_{i,i-1}, a_{ii}, a_{i,i+1}$，对应本行内序号 $1, 2, 3$；下标 $j$ 对应序号 $j - (i-1) + 1 = j - i + 2$）。所以 $a_{ij}$ 是全体中的第 $(3i - 4) + (j - i + 2) = 2i + j - 2$ 个，从 0 开始编号即为 $2i + j - 3$。

**代入验证一**（边界）：$i = 1$，取 $a_{11}$，$k = 2 + 1 - 3 = 0$，正是压缩数组的第 1 个元素，正确。取 $a_{22}$（$i=2,j=2$）：$k = 4 + 2 - 3 = 3$。手排：第 1 行 $a_{11},a_{12}$ 占 0、1；第 2 行 $a_{21},a_{22},a_{23}$ 占 2、3、4，$a_{22}$ 下标为 3，正确。

**代入验证二**（统考真题数据）：$100$ 阶三对角矩阵，元素 $m_{i,j}$（$1 \le i, j \le 100$）按**行优先**压缩存入**下标从 0 开始**的一维数组 $N$，求 $m_{30,30}$ 的下标。用公式：$k = 2 \times 30 + 30 - 3 = 87$。

换一种独立方法核算：第 1 行有 2 个元素；第 2 行到第 29 行共 28 行、每行 3 个，共 84 个；合计 $2 + 84 = 86$ 个元素排在第 30 行之前，故第 30 行第一个元素 $m_{29,30}$ 的下标为 86。第 30 行按 $m_{29,30}, m_{30,30}, m_{30,31}$ 的顺序存放，$m_{30,30}$ 再后移一位，下标为 $86 + 1 = 87$。两种方法结果一致。

**若按列优先存储**（下标从 1 开始），由对称的推导可得

$$k = 2j + i - 3 \quad (|i - j| \le 1)$$

即把行优先公式中的 $i$、$j$ 互换。

:::warn 易错点
三对角矩阵题的三个坑：

1. **下标基数**。公式 $k = 2i + j - 3$ 是**矩阵下标从 1 开始**的形式。若题目给出的是 C 语言风格的 $0$ 起始下标，需要先按 $+1$ 换算，或直接用「数一数前面有几个元素」的方法避免混淆。
2. **首行和末行只有 2 个元素**。若直接按「每行 3 个」算，会多算 1 个，答案偏大。
3. **一维数组的下标是 0 起还是 1 起**。题目说「压缩存入下标从 0 开始的一维数组」时，公式结果直接用；若说「一维数组 $N[1..3n-2]$」，则结果要按 1 起始再调一次。
:::

### （五）稀疏矩阵

**稀疏矩阵**：矩阵中非零元素的个数 $t$ 相对于矩阵元素总数 $s$ 非常少，即 $s \gg t$ 的矩阵。稀疏矩阵中零元素的分布通常没有规律，因此**不能靠下标映射推算**，必须显式记录每个非零元素的位置。

统考要求掌握两种压缩存储结构：

#### 1. 三元组表（顺序存储）

为每个非零元素存一个三元组 `<行下标, 列下标, 值>`，所有三元组按行优先（或列优先）顺序排成一个顺序表。此外还**必须额外保存矩阵的总行数、总列数（通常还有非零元素个数）**。

**为什么必须额外保存行数和列数**：三元组只记录「非零元素出现在哪里」，无法确定矩阵的整体规模。如果最后几行或最后几列全是零，它们不会出现在任何三元组中，只凭三元组无法知道这些全零行、全零列是否存在。

```c
#define MaxSize 1000
typedef struct {
    int i, j;        // 行下标、列下标
    int v;           // 元素值
} Triple;

typedef struct {
    Triple data[MaxSize];   // 非零元素的三元组表
    int mu, nu, tu;         // 矩阵的行数、列数、非零元素个数
} TSMatrix;
```

三元组表**适合顺序存取，但不适合随机存取**：要按行号查找某个元素必须从头扫描。若需频繁按行、按列访问，应改用十字链表。

#### 2. 十字链表（链式存储）

十字链表的每个非零元素对应一个结点，结点内同时挂在**行链表**和**列链表**上，因此可以同时按行、按列遍历非零元素。它是稀疏矩阵的链式压缩存储方式，也是图的「有向图十字链表」的同名不同物结构（图那一章的十字链表用于存弧）。

十字链表的结构要点：

- 每个非零元素结点含 5 个域：`行下标 i`、`列下标 j`、`值 v`、`指向同列下一个非零元素的 down 指针`、`指向同行下一个非零元素的 right 指针`；
- 设立行头指针数组和列头指针数组（或把行头、列头结点也串成一个链表）；
- 整个矩阵用一个总的头结点记录行数、列数、非零元素个数。

**三元组表与十字链表的对比**：

| 比较项 | 三元组表 | 十字链表 |
|---|---|---|
| 存储方式 | 顺序存储 | 链式存储 |
| 每个非零元素的空间 | 3 个域 | 5 个域（含 2 个指针） |
| 按行访问 | 顺序扫描，较慢 | 沿行链 $O(\text{行内非零元个数})$ |
| 按列访问 | 需转置或重建，很慢 | 沿列链，与按行同效 |
| 插入/删除非零元素 | 需移动大量元素 | 修改指针即可 |
| 需要保存的信息 | 行数、列数、非零元个数 | 行数、列数、非零元个数（存在总头结点中） |

:::exam 真题考法
- 2017 年考「适用于压缩存储稀疏矩阵的两种存储结构」，答案是**三元组表和十字链表**。干扰项「邻接矩阵」（需要为所有行列位置分配空间，本质是完整二维数组，不属于压缩存储）和「二叉链表」（不是矩阵的存储结构）都要能排除。
- 2023 年考「用三元组表存储稀疏矩阵，除三元组外还需要保存什么」，答案是**矩阵的总行数和总列数**（「包含非零元素的行数/列数」可以通过扫描三元组统计出来，不是重建矩阵所必需的规模信息）。
- 三元组表还可以考**转置算法**：朴素转置按列扫描，时间复杂度 $O(nu \times tu)$；快速转置先统计每列非零元个数并计算各列起始位置，再一趟扫描直接放到目标位置，时间复杂度 $O(nu + tu)$。
:::

## 六、栈、队列和数组的应用

### （一）栈在括号匹配中的应用

**算法原理**：从左到右扫描表达式。遇到左括号就入栈（后遇到的左括号要先闭合，因此放在栈顶）；遇到右括号时，若栈空说明右括号多余，匹配失败；否则弹出栈顶左括号，检查类型是否相同，不同则失败。扫描结束后栈必须为空，否则说明左括号多余。

**判定的三种失败情形**：右括号到来时栈空（右括号多）；弹出的左括号类型不匹配（如 `[` 配 `)`）；扫描结束时栈非空（左括号多）。

```c
bool BracketMatch(char str[], int n) {
    SqStack S; InitStack(S);
    if (n % 2 == 1) return false;             // 长度为奇数必不匹配
    for (int i = 0; i < n; i++) {
        if (str[i]=='(' || str[i]=='[' || str[i]=='{') {
            Push(S, str[i]);                   // 左括号入栈
        } else {
            if (StackEmpty(S)) return false;   // 右括号多余
            char top;
            Pop(S, top);                       // 弹出栈顶左括号
            if (str[i]==')' && top!='(') return false;
            if (str[i]==']' && top!='[') return false;
            if (str[i]=='}' && top!='{') return false;
        }
    }
    return StackEmpty(S);                      // 栈空才算匹配
}
```

**代入验证**：输入 `{[()]}`。扫描 `{`、`[`、`(` 依次入栈；遇 `)` 弹出 `(` 匹配；遇 `]` 弹出 `[` 匹配；遇 `}` 弹出 `{` 匹配；结束栈空，返回 `true`。输入 `([)]`：遇 `)` 时栈顶是 `[`，类型不同，返回 `false`，正确。

### （二）栈在表达式求值中的应用

#### 1. 前缀、中缀、后缀表达式

- **中缀表达式**：运算符在两个操作数之间，如 `a+b`。中缀表达式需要括号和优先级规则才能确定运算顺序，计算机直接处理不方便。
- **后缀表达式（逆波兰式）**：运算符在两个操作数之后，如 `ab+`。后缀表达式**不需要括号就能唯一确定运算顺序**，最适合用栈求值。
- **前缀表达式（波兰式）**：运算符在两个操作数之前，如 `+ab`。

**手算转换方法（推荐）**：先给中缀表达式**按运算顺序加括号**，再把每个括号内的运算符移到对应位置的后面（后缀）或前面（前缀），最后去掉所有括号。

**例 1**：中缀 `a+b-c*d`。

- 确定运算顺序并加括号：`((a+b)-(c*d))`；
- 后缀：把 `+` 移到 `ab` 后得 `ab+`，`*` 移到 `cd` 后得 `cd*`，`-` 移到最后得 `ab+cd*-`；
- 前缀：`+` 移到 `ab` 前得 `+ab`，`*` 移到 `cd` 前得 `*cd`，`-` 移到最前得 `-+ab*cd`。

**例 2**：中缀 `a/b+(c*d-e*f)/g`。

- 加括号：`((a/b)+(((c*d)-(e*f))/g))`；
- 后缀：`ab/cd*ef*-g/+`；
- 前缀：`+/ab/-*cd*efg`。

**例 3**（统考真题数据）：中缀 `x+y*(z-u)/v`。

- 加括号：`(x+((y*(z-u))/v))`；
- 后缀：`xyzu-*v/+`。

对照 2024 年该题的四个选项，只有 `xyzu-*v/+` 与之一致。

#### 2. 用栈实现后缀表达式的计算

使用**一个操作数栈**，从左到右扫描后缀表达式：

- 遇到**操作数**：直接入栈；
- 遇到**运算符**：连续弹出两个操作数，**先出栈的是右操作数，后出栈的是左操作数**，执行 `左 op 右` 运算，把结果压回栈；
- 扫描结束后，栈中唯一的元素即为表达式的值。

**代入验证**：后缀 `34+5*`（对应中缀 `(3+4)*5`）。

- 遇 `3`，栈 `[3]`；
- 遇 `4`，栈 `[3,4]`；
- 遇 `+`，弹出 4（右）、3（左），算 $3+4=7$，栈 `[7]`；
- 遇 `5`，栈 `[7,5]`；
- 遇 `*`，弹出 5（右）、7（左），算 $7 \times 5 = 35$，栈 `[35]`。

结果为 35，正确。注意**减法、除法必须区分左右操作数**：后缀 `53-` 的值是 $5-3=2$，不是 $3-5=-2$。

#### 3. 中缀转后缀的算法

初始化一个栈，用于保存**暂时还不能确定运算顺序的运算符**。从左到右扫描中缀表达式：

- 遇到**操作数**：直接加入后缀表达式；
- 遇到**左括号 `(`**：直接入栈；
- 遇到**右括号 `)`**：依次弹出栈内运算符并加入后缀表达式，直到弹出 `(` 为止，**`(` 不加入后缀表达式**；
- 遇到**运算符**：
  1. 若优先级**高于**栈顶运算符（或栈空、栈顶是 `(`），当前运算符**直接入栈**；
  2. 若优先级**小于等于**栈顶运算符，则**不断弹出**优先级大于等于当前运算符的栈顶元素加入后缀表达式，直到栈空或栈顶为 `(`，再把当前运算符入栈；
- 扫描结束后，把栈中剩余运算符依次弹出并加入后缀表达式。

**代入验证**：中缀 `a/b+(c*d-e*f)/g`，扫描到 `f` 时栈中的内容（栈底到栈顶）。

- 读 `a` → 输出 `a`；
- 读 `/` → 栈空，入栈。栈：`/`；
- 读 `b` → 输出 `b`；
- 读 `+` → 优先级 1 ≤ 栈顶 `/`（2），弹出 `/` 输出；栈空，`+` 入栈。栈：`+`；
- 读 `(` → 直接入栈。栈：`+, (`；
- 读 `c` → 输出 `c`；
- 读 `*` → 栈顶是 `(`，直接入栈。栈：`+, (, *`；
- 读 `d` → 输出 `d`；
- 读 `-` → 优先级 1 ≤ 栈顶 `*`（2），弹出 `*` 输出；栈顶为 `(`，停止；`-` 入栈。栈：`+, (, -`；
- 读 `e` → 输出 `e`；
- 读 `*` → 优先级 2 > 栈顶 `-`（1），直接入栈。栈：`+, (, -, *`；
- 读 `f` → 输出 `f`（**此时栈底到栈顶依次是 `+`、`(`、`-`、`*`**）。

这个结果与 2014 年真题的答案选项一致。

#### 4. 用栈直接计算中缀表达式

初始化**两个栈**：操作数栈 `num` 和运算符栈 `op`。

- 遇到操作数：压入 `num`；
- 遇到 `(`：压入 `op`；
- 遇到 `)`：不断执行「求值」（弹出一个运算符、弹出两个操作数、运算、结果压回 `num`），直到 `op` 栈顶为 `(`，然后弹出 `(`；
- 遇到运算符：当 `op` 非空且栈顶运算符优先级**大于等于**当前运算符时，不断求值，再把当前运算符压入 `op`；
- 全部扫描完后，继续求值直到 `op` 为空，`num` 栈顶即为结果。

这里的「中缀转后缀」与「后缀求值」两套逻辑被合并在一次扫描中完成，效率和正确性都更好。

```c
// 中缀表达式直接求值：操作数栈 + 运算符栈
void eval(stack<int> &num, stack<char> &op) {
    int a = num.top(); num.pop();      // 先弹出的是右操作数
    int b = num.top(); num.pop();      // 后弹出的是左操作数
    char p = op.top(); op.pop();
    if (p == '+') num.push(b + a);
    else if (p == '-') num.push(b - a);   // ★ 注意是 b - a
    else if (p == '*') num.push(b * a);
    else num.push(b / a);                 // ★ 注意是 b / a
}
```

:::warn 易错点
（1）**减法与除法必须区分左右操作数**。后缀求值时先出栈的是右操作数，写成 `a - b` 就错了。

（2）**中缀转后缀时 `(` 不入后缀表达式**，遇到 `)` 弹出到 `(` 并把 `(` 丢弃。

（3）**中缀转后缀的「弹出」条件是优先级「小于等于」**（同级也要弹出，保证左结合），而「直接入栈」的条件是优先级「大于」。选择题常在这里设置干扰。

（4）**不要声称「消除递归必须使用栈」**。尾递归可以直接用循环改写，迭代法不一定需要显式栈。2017 年真题正是考这个错误说法。

（5）**中缀表达式本身不唯一**。同一个中缀表达式在运算符优先级相同时（如 `a+b+c`）可以由不同的结合顺序得到不同的后缀形式，但**结果值相同**。统考默认按「左优先」原则转换。

（6）**中缀转后缀时不要漏掉扫描结束后的收尾步骤**。全部字符扫描完后，必须把操作符栈中剩余的运算符依次弹出并追加到后缀表达式末尾，否则会丢掉最后几个运算符。选择题常问「扫描到某个字符时栈内还剩哪些运算符」，此时收尾步骤尚未执行。
:::

| 表达式形式 | 例子（中缀 `a+b-c*d`） | 用栈求值的方式 |
|---|---|---|
| 前缀（波兰式） | `-+ab*cd` | 从**右向左**扫描；遇操作数入栈，遇运算符弹两个操作数运算后压回 |
| 中缀 | `a+b-c*d` | 需要**两个栈**（操作数栈 + 运算符栈）同时处理优先级与括号 |
| 后缀（逆波兰式） | `ab+cd*-` | 从**左向右**扫描；遇操作数入栈，遇运算符弹两个操作数运算后压回 |

前缀求值时**先出栈的是左操作数**，后缀求值时**先出栈的是右操作数**——这是因为两者扫描方向相反，弹栈的先后顺序自然也相反。这个对应关系记清了，两类题都不会错。
:::

### （三）栈在递归中的应用

函数调用的特点是**最后调用的函数最先被执行（LIFO）**。调用函数时，系统需要用**函数调用栈**保存三类信息：**调用返回地址、实参、局部变量**。递归调用时，这个栈称为**递归工作栈**。

- 每进入一层递归，就把该层的返回地址、实参、局部变量压入栈顶；
- 每退出一层递归，就从栈顶弹出这些信息，恢复到上一层。

**递归的优缺点**：代码简洁、可读性好；但效率较低，递归层数过多会导致**栈溢出**（栈空间耗尽），且可能存在大量重复计算（如朴素的斐波那契递归）。

**递归与栈的关系（2015 年真题考法）**：程序 `main()` 调用 `S(1)`，`S(1)` 调用 `S(0)`，则递归最深时，从**栈底到栈顶**依次是 `main()`、`S(1)`、`S(0)`。这也解释了为什么「用非递归方式重写递归程序时**不一定必须**使用栈」——尾递归可以改成循环，但**函数调用本身必须用栈保存现场**。

**递归的深度与栈容量的关系**：设递归函数每层占用 $s$ 个字节的栈帧，递归深度为 $d$，则需要的栈空间至少为 $d \times s$ 字节。若系统栈总容量为 $S$，能支持的最大递归深度约为 $\lfloor S / s \rfloor$。这解释了为什么「太深的递归会栈溢出」——是**栈空间不够**，而不是算法逻辑错误。

**用栈把递归改写成迭代的思路**：把递归函数的「参数 + 局部变量 + 返回位置」打包成一个栈元素显式压栈，用循环模拟系统调用栈的行为。二叉树的中序遍历非递归版本（讲义中的 LeetCode 94）就是典型例子：

- 一个结点入栈后有两种处理方式：要么立即出栈（说明该结点没有左孩子），要么让下一个结点入栈（有左孩子）；
- 一个结点出栈后也有两种处理方式：要么继续出栈（该结点没有右孩子），要么把下一个结点入栈（有右孩子）。

### （四）栈在进制转换中的应用

把十进制整数 $N$ 转换为 $r$ 进制，使用**除 $r$ 取余法**：反复用 $N$ 除以 $r$，把每次的余数依次入栈，直到商为 0；再依次出栈，得到的序列即为转换结果。

**为什么用栈**：除 $r$ 取余法得到的余数是**从低位到高位**产生的，而输出需要**从高位到低位**，正好是一次逆序，与栈的 LIFO 特性吻合。

**代入验证**：把十进制的 $1348$ 转换为八进制。

| 步骤 | 除法 | 商 | 余数（入栈顺序） |
|---|---|---|---|
| 1 | $1348 \div 8$ | 168 | 4 |
| 2 | $168 \div 8$ | 21 | 0 |
| 3 | $21 \div 8$ | 2 | 5 |
| 4 | $2 \div 8$ | 0 | 2 |

余数入栈顺序为 4、0、5、2，出栈顺序为 2、5、0、4，故 $1348 = (2504)_8$。验算：$2 \times 8^3 + 5 \times 8^2 + 0 \times 8 + 4 = 1024 + 320 + 0 + 4 = 1348$，正确。

**时间复杂度**：需要做 $\lfloor \log_r N \rfloor + 1$ 次除法，每次入栈和出栈都是 $O(1)$，故总时间复杂度为 $O(\log_r N)$；栈的最大深度也等于这个数量级。

小数部分的转换用**乘 $r$ 取整法**，取整顺序与输出顺序一致，因此**不需要**用栈，直接按顺序输出即可。

### （五）队列在层次遍历中的应用

**树的层次遍历**（广度优先遍历）是队列最经典的应用：从根结点开始，根结点入队；每次取出队头结点并访问，然后把它的所有孩子依次入队；重复直到队空。

```c
void LevelOrder(BiTree T) {
    SqQueue Q; InitQueue(Q);
    BiTree p;
    if (T != NULL) EnQueue(Q, T);        // 根结点入队
    while (!QueueEmpty(Q)) {
        DeQueue(Q, p);                    // 队头结点出队
        visit(p);                         // 访问该结点
        if (p->lchild != NULL) EnQueue(Q, p->lchild);   // 左孩子入队
        if (p->rchild != NULL) EnQueue(Q, p->rchild);   // 右孩子入队
    }
}
```

**为什么层次遍历必须用队列**：队列保证「先被发现（入队）的结点先被访问（出队）」，因此访问顺序自然是从上到下、从左到右的层序。若换成栈，就变成了深度优先遍历（DFS）。

同样的逻辑用于**图的广度优先搜索（BFS）**：队列存待访问的顶点，保证按「距起始顶点的距离」由近到远访问，因此 BFS 可以求**无权图的最短路径**。

### （六）队列在缓冲区与 CPU 调度中的应用

- **缓冲区管理**：为了解决 CPU/主机与慢速外设（打印机、键盘等）速度不匹配的问题，设置数据缓冲区。主机依次写入、外设依次取出，逻辑上就是 FIFO 队列。2009 年真题直接考这一点。
- **CPU 进程调度**：先来先服务（FCFS）调度算法用一个**就绪队列**保存等待处理机的进程，每次把队首进程投入运行，运行结束或时间片用完再挂到队尾，即**轮转（Round Robin）**调度。多级反馈队列、优先级调度同样以队列作为基本组织形式。
- **其他典型场景**：消息传递（异步通信）、线程池任务分发、打印任务排队、电商订单处理等所有需要「先来后到」的场合。

### （七）数组的典型应用：矩阵运算与顺序表

数组在统考中除了「压缩存储的下标计算」，还会以**矩阵运算**和**顺序表操作**的形式出现。常见的两类：

**1. 矩阵的转置**。设原矩阵 $A$ 为 $m \times n$，转置矩阵 $B$ 为 $n \times m$，则 $B[j][i] = A[i][j]$。若两个矩阵都用按行优先的一维数组存储，朴素转置需要对 $A$ 做 $n$ 遍扫描（每遍取一列），时间复杂度为 $O(m \times n)$；而如果只按二维数组逐元素赋值，时间复杂度为 $O(m \times n)$、空间复杂度 $O(m \times n)$。对于稀疏矩阵，转置要用到三元组表，见本章第五节的说明。

**2. 用数组实现「地址计算」类操作**。这类题的核心就是本章第四节的 $LOC$ 公式：给定起始地址、元素大小和行列下标，求目标元素的地址。做题步骤固定为：

- 判断是行优先还是列优先；
- 确定「每行/每列有多少个元素」；
- 数出目标元素前面有多少个元素（这是**偏移量**）；
- 地址 $=$ 起始地址 $+$ 偏移量 $\times L$。

**代入验证**：三维数组 $A[0..1][0..2][0..3]$ 按行优先存储，每个元素占 4 字节，起始地址为 0，求 $A[1][1][2]$ 的地址。先按行优先展开为等效二维数组，每行有 $3 \times 4 = 12$ 个元素（即后两维的长度之积）。$A[1][1][2]$ 的前面有完整的第 0 层（$12$ 个元素）、第 1 层中的第 0 行（$4$ 个元素）、第 1 行中的前 2 个元素（$2$ 个），共 $12 + 4 + 2 = 18$ 个元素。地址 $= 0 + 18 \times 4 = 72$。

一般地，$n$ 维数组按行优先存储时，下标 $(i_1, i_2, \ldots, i_n)$ 对应的一维偏移量为

$$\text{offset} = i_1 \cdot (d_2 d_3 \cdots d_n) + i_2 \cdot (d_3 \cdots d_n) + \cdots + i_{n-1} \cdot d_n + i_n$$

其中 $d_k$ 是第 $k$ 维的长度。这个「多项式求值」形式与行优先的二维公式完全一致，理解来龙去脉后无需死记。

:::exam 真题考法
数组类的统考题目主要有三种包装：

1. **给起始地址和某个元素的地址，反解出每行元素个数，再求另一个元素的地址**（2021 年，见本章第四节）。
2. **问「按行优先存储」「按列优先存储」时某元素的下标或地址**（近年多次出现）。
3. **问数组占用的总存储空间**：$m \times n$ 的二维数组共需 $m \times n \times L$ 字节；若用压缩存储（如对称矩阵），则只需 $\dfrac{n(n+1)}{2} \times L$ 字节。这类问法的关键是**先判断题目问的是压缩前还是压缩后**。
:::

### （八）栈与队列的合法出栈序列

这是本章综合度最高、也最常出选择题的部分。

#### 1. 判断一个序列是否为合法出栈序列

**模拟法（万能方法）**：按入栈序列顺序不断压栈，每压入一个元素后，只要栈顶与目标出栈序列的当前元素相等就弹出并推进目标序列；全部入栈完毕后若栈空且目标序列走完，则该序列合法，否则不合法。

**手算技巧**：不需要写完整模拟。抓住一条核心性质——

:::key 合法出栈序列的判定准则
对任意两个元素 $x$、$y$，若它们在入栈序列中 $x$ 在 $y$ 之前，则在出栈序列中：

- 二者**顺序可以任意**（先出 $x$ 后出 $y$，或先出 $y$ 后出 $x$ 都合法）；
- 但**绝不允许出现这样的模式**：$y$ 已经出栈，而比 $y$ 先入栈的 $x$ 尚未出栈、且 $x$ 与 $y$ 之间的元素也仍未出栈——本质上是「出栈序列中不可能出现跨栈的逆序交叉」。

更实用的判定表述：对于出栈序列中的任意两个元素 $a$、$b$（$a$ 在出栈序列中排在 $b$ 前面），若在入栈序列中 $a$ 排在 $b$ **后面**，则所有在入栈序列中位于 $a$、$b$ **之间**的元素，在出栈序列中也必须排在 $b$ **之前**。
:::

**代入验证**：入栈序列为 `1,2,3`，判断 `3,1,2` 是否合法。$3$ 先出栈，说明 `1,2,3` 全部已入栈，栈内从底到顶为 `1,2`，下一个只能出 `2`，不可能出 `1`。故 `3,1,2` 不合法。

再验证 `2,3,1`：逐一模拟——`1` 入栈，`2` 入栈，弹出 `2`；`3` 入栈，弹出 `3`；弹出 `1`。得到 `2,3,1`，合法。「`3,2,1`」合法（全部入栈后依次弹出）；「`1,2,3`」合法（每入栈一个就立即弹出）。

#### 2. 卡特兰数与出栈序列的个数

$n$ 个**不同**元素依次进栈（进栈顺序固定），其可能的出栈序列个数为**卡特兰（Catalan）数**：

$$N = \frac{1}{n+1}C_{2n}^{n} = \frac{(2n)!}{n!\,(n+1)!}$$

符号说明：$n$ 是元素个数（$n \ge 1$），$C_{2n}^{n}$ 是从 $2n$ 个位置中选 $n$ 个的组合数，$N$ 是不同出栈序列的总数。

:::key 卡特兰数的推导思路
把「入栈」看作 $+1$、「出栈」看作 $-1$，任何时刻**已入栈的元素个数不少于已出栈的元素个数**，即前缀和恒非负（栈不能为空时出栈）。长度 $2n$ 的 $\pm1$ 序列中共有 $C_{2n}^{n}$ 个满足「$n$ 个 $+1$、$n$ 个 $-1$」，其中前缀和非负的序列数为 $\dfrac{1}{n+1}C_{2n}^{n}$。这正是**卡特兰数**。

卡特兰数在数据结构中还有一个用途：**$n$ 个结点的不同形态二叉树（二叉排序树形态数）也是卡特兰数**。因为「先序序列可视为入栈次序、中序序列可视为出栈次序」，二者的对应关系把两个计数问题统一起来。
:::

**代入验证一**：$n = 5$ 时，

$$N = \frac{1}{6}C_{10}^{5} = \frac{1}{6} \times \frac{10 \times 9 \times 8 \times 7 \times 6}{5 \times 4 \times 3 \times 2 \times 1} = \frac{30240}{6 \times 120} = \frac{30240}{720} = 42$$

与逐个模拟的结果一致（$n=1,2,3,4,5$ 时 $N$ 分别为 $1,2,5,14,42$）。

**代入验证二**（先序序列计数）：先序序列为 `a,b,c,d` 的不同二叉树有多少棵？先序序列是入栈次序，中序序列是出栈序列，$n = 4$：

$$N = \frac{1}{5}C_{8}^{4} = \frac{1}{5} \times 70 = 14$$

即共有 14 棵树。

#### 3. 带限制条件的出栈序列计数

统考常在纯卡特兰数的基础上加条件，此时**不能直接套公式**，必须按条件分类讨论。常见限制有两类：

**限制一：指定某个元素为第一个出栈元素**。要让 $d$ 第一个出栈（入栈序列 `a,b,c,d,e`），必须先把 $a,b,c,d$ 全部压栈，再立即弹出 $d$。此时栈内从底到顶为 $a,b,c$，$e$ 尚未入栈。接下来分两类：

- 先弹出 $c$，则剩余 `a,b` 已全在栈中、`e` 未入栈，$e$ 的入栈时机有三种，得到 `d,c,b,a,e`、`d,c,b,e,a`、`d,c,e,b,a`；
- 在弹出 $c$ 之前先把 $e$ 入栈，则 $e$ 必须先出栈，得到 `d,e,c,b,a`。

共 **4** 种，与 2011 年真题答案一致。

**限制二：禁止连续 $k$ 次同类操作**。如 2010 年考「不允许连续三次出栈」。判定方法是**逐项构造操作序列**：若某序列在构造过程中不可避免地要连续弹出 3 次（即栈内积压了 3 个以上元素而没有新的入栈操作可以打断），则该序列不可能。

以入栈序列 `a,b,c,d,e,f`、「不允许连续三次出栈」为例，逐项验证四个候选序列：

| 候选序列 | 构造过程 | 是否可行 |
|---|---|---|
| `d,c,e,b,f,a` | `abcd` 入栈，弹 `d`、`c`（连续 2 次）；`e` 入栈弹 `e`；弹 `b`；`f` 入栈弹 `f`；弹 `a` | 可行 |
| `c,b,d,a,e,f` | `abc` 入栈，弹 `c`、`b`（2 次）；`d` 入栈弹 `d`；弹 `a`；`e` 入栈弹 `e`；`f` 入栈弹 `f` | 可行 |
| `b,c,a,e,f,d` | `ab` 入栈弹 `b`；`c` 入栈弹 `c`；弹 `a`；`de` 入栈弹 `e`；`f` 入栈弹 `f`；弹 `d` | 可行 |
| `a,f,e,d,c,b` | `a` 入栈弹 `a`；`bcdef` 全部入栈（此时栈内积压 5 个元素）；弹 `f` 后，栈顶依次是 `e,d,c,b`，**已无未入栈元素可以打断**，只能连续弹 `f,e,d` 三次 | **不可行** |

表中第四项正是 2010 年真题的答案（选项 D）。这类题的通用做法是：**找出序列中「连续递减且已无剩余元素可入栈」的那一段**，若长度达到 $k$ 就违规。

**限制三：入栈序列与出栈序列的对应关系**（2022 年考法）。给定完整的 `in` 和 `out`，**总是可以用模拟法判断 `out` 是否合法**，因此「不能判断」的说法错误。此外：若每入栈一个就立即出栈，`out` 可以与 `in` **完全相同**；若全部入栈后再依次弹出，`out` 恰为 `in` 的**倒序**。故「`in` 与 `out` 一定不同」错误，「可能互为倒序」正确。

**限制四：双端队列的输出序列计数**。双端队列的两端都能操作，情况比栈复杂，但卡特兰数仍是它的**下界参照**：输出受限（仅一端出）时可行序列更多。判断时先用「分段逆序」技巧筛选，再用模拟法确认。

:::warn 易错点
（1）**卡特兰数公式只适用于「入栈顺序固定、无额外限制、元素互不相同」的情形**。一旦题目加了「不允许连续三次出栈」「以某元素开头」等条件，必须重新分类计数。

（2）**卡特兰数计的是「不同出栈序列的个数」**，不是「不同操作序列的个数」。若问的是「有多少种不同的入栈/出栈操作序列」，答案会更大。

（3）**题目若给的是「栈的入栈序列确定，求可能的出栈序列个数」**，注意栈容量可能有限制。若题目还限制了栈的容量，就不能用卡特兰数。

（4）**判断合法出栈序列时不要只看首尾元素**。要看元素之间的「跨越逆序」关系，或者干脆老老实实按模拟法走一遍。

（5）**卡特兰数的递推公式 $N_n = \sum_{k=1}^{n} N_{k-1} N_{n-k}$（$N_0 = 1$）** 有时也会用到。它对应「最后一个出栈的元素把式子分成左右两部分」的分治思想，与二叉树的形态计数完全一致。
:::

### （九）用栈实现队列、用队列实现栈

统考的应用题与选择题都爱考「受限结构的互相模拟」，核心是**用两个栈/两个队列抵消掉各自的方向性**。

#### 1. 用两个栈实现队列

设 `A` 为**入队栈**，`B` 为**出队栈**：

- **入队**：元素直接压入 `A`；
- **出队**：若 `B` 非空，直接从 `B` 弹栈顶；若 `B` 为空，则把 `A` 中所有元素**依次弹出并压入 `B`**，再从 `B` 弹栈顶；
- **查队头**：同出队逻辑，但不弹出；
- **元素个数**：`A.size() + B.size()`。

**为什么正确**：`A` 中元素从栈底到栈顶是「早入队 → 晚入队」，全部倒入 `B` 后顺序反转，`B` 的栈顶恰好是最早入队的元素，符合 FIFO。

**代入验证**：空队列执行 `push(1), push(2), pop, push(3), pop`。

| 操作 | `A`（底→顶） | `B`（底→顶） | 输出 |
|---|---|---|---|
| `push(1)` | 1 | — | — |
| `push(2)` | 1, 2 | — | — |
| `pop` | — | — | `B` 空，把 `A` 全部倒入 `B`：`B` = 2, 1（底→顶），弹出 1 | 
| `push(3)` | 3 | 2 | — |
| `pop` | 3 | 2 | `B` 非空，直接弹出 2 |

输出序列为 1、2，正确。

**时间复杂度分析（重要考点）**：单个 `pop` 操作最坏为 $O(n)$（需要倒栈），但**每个元素至多被压入 `A` 一次、倒入 `B` 一次、从 `B` 弹出一次**，因此 $n$ 次操作的总时间复杂度为 $O(n)$，**均摊（摊还）时间复杂度为 $O(1)$**。

#### 2. 用两个队列实现栈

设 `Q1` 为**主队列**，`Q2` 为**辅助队列**：

- **入栈**：元素直接入 `Q1`；
- **出栈**：把 `Q1` 中除队尾元素外的所有元素依次出队并转入 `Q2`，剩下的那个队尾元素就是栈顶，出队并返回；然后交换 `Q1` 和 `Q2` 的角色（或把 `Q2` 的元素再转回 `Q1`）；
- **取栈顶**：同出栈过程，但不删除最后那个元素。

**时间复杂度**：单次出栈为 $O(n)$，$n$ 次出栈的总时间复杂度为 $O(n^2)$。用队列实现栈比用栈实现队列代价更高，这是两者的本质差别——栈的 LIFO 特性比队列的 FIFO 更容易「叠加」出来。

:::exam 真题考法
「用两个栈实现队列」是应用题常客，典型四问是：（1）写出结构定义；（2）说明入队出队过程；（3）画出空队列执行 `push(1), push(2), pop, push(3), pop` 的过程；（4）求 $n$ 个元素任意顺序进出后队列为空的**总时间复杂度**。第（4）问的标准答案是 **$O(n)$**——每个元素两次入栈、两次出栈，共 $4n$ 次 $O(1)$ 操作。若答成 $O(n^2)$ 会被扣分，因为那是按「单次最坏」而非「总量」估算的。

另一类常考应用题是**最小栈**：用「数据栈 + 辅助栈」实现 $O(1)$ 取最小值。入栈时，若新元素 $\le$ 辅助栈顶，则**同时压入辅助栈**；出栈时，若弹出的元素等于辅助栈顶，则辅助栈也弹出。这样辅助栈顶永远保存当前最小值。注意条件是「小于等于」而不是「小于」——用「小于」时，遇到重复的最小值会导致出栈后辅助栈提前弹空。
:::

## 本章小结表

| 知识点 | 核心公式 / 结论 | 关键条件 |
|---|---|---|
| 栈的特点 | 后进先出 LIFO，只在栈顶一端操作 | 逻辑结构仍是线性表 |
| 队列的特点 | 先进先出 FIFO，队尾入、队头出 | 入队只动 `rear`，出队只动 `front` |
| 顺序栈（top 指向栈顶元素） | 判空 `top == -1`；判满 `top == MaxSize-1`；入栈 `data[++top]=x` | 先加后存 |
| 顺序栈（top 指向栈顶下一位置） | 判空 `top == 0`；判满 `top == MaxSize`；入栈 `data[top++]=x` | 先存后加；元素个数 = `top` |
| 共享栈 | 判空 `top0 == -1 && top1 == MaxSize`；判满 `top0 + 1 == top1` | 全部 `MaxSize` 个单元可用 |
| 循环队列（牺牲一个单元） | 判空 `front == rear`；判满 `(rear+1)%M == front`；个数 `(rear-front+M)%M` | 容量只有 $M-1$；模数永远是 $M$ |
| 循环队列（设 size） | 判空 `size == 0`；判满 `size == M` | 容量 $M$，指针相等时分不清空满 |
| 循环队列（设 tag） | 判空 `front==rear && !tag`；判满 `front==rear && tag` | 入队置 `tag=true`，出队置 `tag=false` |
| 链队列（带头结点） | 判空 `front == rear`；出队若摘掉尾结点需 `rear = front` | 最适合做链队列 |
| 链队列（不带头结点） | 判空 `front == NULL`；出队至空需 `front = rear = NULL` | 边界情况更多 |
| 链栈 | 入栈头插法、出栈头删法；**无上溢** | 通常在表头操作 |
| 二维数组行优先 | $LOC(a_{ij}) = LOC(a_{00}) + [\,i \times n + j\,] \times L$ | $n$ 为列数 |
| 二维数组列优先 | $LOC(a_{ij}) = LOC(a_{00}) + [\,j \times m + i\,] \times L$ | $m$ 为行数 |
| 对称矩阵（下三角，行优先） | $k = \dfrac{i(i+1)}{2} + j$（$i \ge j$）；$i<j$ 时用 $a_{ij}=a_{ji}$ 翻下标 | 数组共 $\dfrac{n(n+1)}{2}$ 个单元，下标从 0 |
| 三角矩阵（下三角，行优先） | $i \ge j$：$k = \dfrac{i(i+1)}{2} + j$；$i<j$：$k=\dfrac{n(n+1)}{2}$（取常数） | 数组共 $\dfrac{n(n+1)}{2}+1$ 个单元 |
| 三对角矩阵（行优先） | $k = 2i + j - 3$；数组长度 $3n-2$ | 矩阵下标从 1 起，$\lvert i-j \rvert \le 1$；首末行各 2 个 |
| 稀疏矩阵 | 三元组表（顺序，3 域）、十字链表（链式，5 域） | 都需额外保存矩阵的总行数、总列数 |
| 卡特兰数 | $N = \dfrac{1}{n+1}C_{2n}^{n}$ | 元素互不相同、入栈顺序固定、无其他限制 |
| 中缀转后缀 | 运算符优先级 ≤ 栈顶时弹出；`(` 入栈不输出，`)` 弹到 `(` 为止 | 操作数直接输出 |
| 后缀求值 | 遇运算符弹两个操作数，**先出栈的是右操作数** | 结果压回栈，最后栈顶即答案 |

## 易错清单

1. **栈「两端都能操作」是错的**。栈只在栈顶一端操作，两端都能操作的是双端队列。

2. **顺序栈的入栈顺序取决于 `top` 的含义**。`top == 0` 表示空栈 ⇒ `top` 指向栈顶下一位置 ⇒ 入栈是「先存后加」；`top == -1` 表示空栈 ⇒ `top` 指向栈顶元素 ⇒ 入栈是「先加后存」。

3. **共享栈的判满与循环队列的判满形式相似、含义相反**。共享栈 `top0 + 1 == top1` 时是**全部空间用满**；循环队列 `(rear+1)%M == front` 时是**只用了 M-1 个**。

4. **循环队列的取模模数永远是数组长度 `MaxSize`**，不是 `MaxSize-1`，也不是队列容量。

5. **循环队列元素个数必须写成 `(rear - front + MaxSize) % MaxSize`**。不加 `MaxSize` 在 `rear < front`（指针已绕回）时出错。

6. **入队只改 `rear`，出队只改 `front`**。选择题中用这一点能快速排除一半选项。

7. **链队列出队时若摘掉的是队尾结点，带头结点实现要把 `rear` 拉回 `front`，不带头结点实现要同时把 `front`、`rear` 置空**，否则 `rear` 悬空。

8. **带头结点的链队列判空是 `front == rear`**；不带头结点是 `front == NULL`。两者不可混用。

9. **链栈、链队列没有上溢问题**，但出栈、出队前必须判空，否则下溢。

10. **二维数组的行优先偏移用「列数」乘 $i$，列优先偏移用「行数」乘 $j$**，两个数不要搞反。

11. **矩阵下标从 1 开始时每个下标都要减 1**。看到「$m_{ij}$，$1 \le i,j \le n$」先换算成从 0 起的相对编号再套公式最保险。

12. **对称矩阵与三角矩阵的公式形式相同，但 `i<j` 时的处理不同**：对称矩阵靠 $a_{ij}=a_{ji}$ 翻下标，三角矩阵直接返回常数单元。

13. **三角矩阵的一维数组要多开 1 个单元存常数**，长度是 $\dfrac{n(n+1)}{2}+1$。

14. **三对角矩阵的首行、末行各只有 2 个元素**，数「前面有多少个元素」时不能按「每行 3 个」一刀切。

15. **三元组表必须额外保存矩阵的总行数和总列数**。「含非零元素的行数/列数」可以扫描统计出来，不是必需的规模信息。

16. **稀疏矩阵的两种压缩存储是三元组表和十字链表**。邻接矩阵本质是完整二维数组，不属于压缩存储；二叉链表与矩阵无关。

17. **后缀表达式中减法和除法要先出栈的是右操作数**。写成 `a-b`、`a/b` 会得到相反的结果。

18. **中缀转后缀时 `(` 和 `)` 都不进入后缀表达式**，右括号处理完后要把左括号弹出丢弃。

19. **「消除递归必须使用栈」是错误说法**。尾递归可以直接改写成循环；但函数调用本身确实需要用栈保存返回地址、实参、局部变量。

20. **卡特兰数只适用于「入栈顺序固定、元素互不相同、无额外限制」的出栈序列计数**。题目一旦加条件（如禁止连续三次出栈、指定首元素），必须分类讨论。

21. **卡特兰数同时是「$n$ 个结点的不同形态二叉树棵数」**，两处计数问题通过「先序为入栈、中序为出栈」的对应关系统一。

22. **判断出栈序列合法性时，不要只看首尾元素**。必须检查「跨越逆序」关系，或者直接用模拟法逐元素走一遍。
