## 三种交换⚠

电路交换

传输期间的时延小。通信是完整的交互过程（包含建立连接、传输、释放），传输只是通信里的一个阶段。

过程

1. 建立连接：分配通信资源

2. 传输数据：一直占用通信资源

3. 释放连接：归还通信资源

不具备差错检验的能力。（因为数据直接透明传输，中间节点不对数据做任何处理）

报文交换

- 分组交换的前身。报文就是Message，是用户数据加上源地址、目的地址等 信息；

- 交换节点将报文整体接受完成后才能查找转发表，将整个报文转发到下一个节点，不可流水线。

- 报文交换比分组交换带来的转发时延要长很多，需要交换节点具有的缓存空间也大很多。

（转发时延 = +排队+处理  + 传输时延）

分组交换

分组就是报文划分成若干等数据段，前面再加上首部  ；分组交换机根据分组中的目的地址查找自己的转发表；

| 注释： 分组交换机 = 网络层设备 = 看 IP = 路由器 / 三层交换机 |
| --- |

过程：发送方构造分组、发送分组，交换节点缓存分组、转发分组，接收方接收分组、还原分组。普通交换机 = 数据链路层 = 看 MAC = 不叫分组交换机

优点：有更高的通信线路利用率，即信道被有效利用的时间比例更高；

把数据切成小块（分组），不同应用的分组可以交替发送。大家能轮流用链路，不会有人被饿死，实现了公平共享介质。

缺点：分组可能会出现失序和丢失等问题；

分组交换无端到端预留资源，各分组独立路由、动态竞争链路资源负载过大 → 节点队列无限堆积 → 网络拥塞。

分组交换这里是默认了路由器的缓存区够用；若处理某个分组时，有新的分组到达，则存入缓存区

三种交换的原理与计算题结合真题选择题学习

#### 虚电路

- 虚电路服务是OSI参考模型特有的，TCP/IP模型没有

分组交换进一步分为无连接的数据报方式和面向连接的虚电路方式,两种方式都是由网络层提供的。电路交换是真正的物理线路交换，如电话线路。虚电路是多路复用技术，每条物理线路可以进行多条虚电路连接，是逻辑上的连接；通信过程中，每个分组使用短的虚电路号。电路交换才是预分配带宽，但是虚电路的话，它实际上是多个虚电路共享电路带宽的

| 对比维度 | 数据报服务 | 虚电路服务 |
| --- | --- | --- |
| 连接的建立 | 不需要 | 必须有 |
| 目的地址 | 每个分组都有完整的目的地址 | 仅在建立连接阶段使用，之后每个分组使用长度较短的虚电路号 |
| 路由选择 | 每个分组独立地进行路由选择和转发 | 属于同一条虚电路的分组按照同一路由转发 |
| 分组顺序 | 不保证分组的有序到达 | 保证分组的有序到达 |
| 可靠性 | 网络只负责 “尽力转发”，不承诺交付结果，不保证可靠通信，可靠性由上层协议来保证 | 可靠性由网络自身来保证 |
| 对网络故障的适应性 | 可寻找新的路径转发分组，对故障的适应能力强 | 所有经过故障节点的虚电路均不能正常工作 |
| 差错处理和流量控制 | 由用户主机上的上层协议（如 TCP）进行流量控制，不保证数据报的可靠性 | 可由分组交换网负责，也可由用户主机负责 |

| 路由就是指：为了从起点到达终点，决定“经由哪条路”走这个动作，以及最终选出来的那条具体的路。 差错处理和流量控制：数据报服务，路由器不知道发送方和接收方的状态，没法做流量控制；也不维护分组的上下文，没法做差错重传。这些复杂的状态维护，都交给了端主机的传输层。虚电路服务除了节点间的流量控制和差错处理，由主机再做一层，双重保障。 虚电路服务用“节点的状态记忆”换取了“节点的控制能力”； 数据报服务用“节点的无状态”换取了“网络的简单健壮”。 |
| --- |

## 性能指标

- 速率又叫数据率、比特率、⚠️数据传输速率

- 带宽定义：最高数据传输速率

ps： 在模拟信号系统中带宽是频率范围

- 吞吐量是单位时间内成功通过某个网络或接口的实际数据量，该性能指标受网络/链路带宽这个性能指标的限制；吞吐量的最大值就是链路带宽。最大吞吐量使用木桶效应思想秒杀。

此题的负载均衡路由方式参考此题目2010年真题

- 时延是指数据从网络的一端传送到另一端所耗费的时间，由发送时延（传输时延）、传播时延、排队时延、处理时延四部分时延组成。

发送时延=分组长度（b）/发送速率（b/s）

传播时延=信道长度（m）/信号传播速率（m/s）

如果分组等长、链路等长，各节点发送速率相等，则m个分组、n个路由器、A到B：(m+n)*发送+(n+1)*传播

ps:各节点发送速率不同，要区分公式里面不同大小的发送时延

真题练习

绝对不要自行脑补 “分流、负载均衡、多路径”，除非题目明确写出相关条件。

本题的核心陷阱：长路径只会增加转发时延，不会缩短总时间，分流只会让结果更差。

- 时延带宽积是传播时延和带宽的乘积。

- 往返时间RTT是指：从发送端发送数据分组，到发送端收到（接收端发来的相应）确认分组为止，总共耗费的时间。

- 利用率

分为链路利用率和网络利用率两种。网络利用率并不是越大越好，过高的网络利用率会产生非常大的时延。

网络利用率：网络中所有链路的链路利用率的加权平均。

## OSI参考模型、TCP/IP模型

- OSI参考模型（物链网输会示用）、TCP/IP模型、原理参考模型

| OSI 七层模型功能、协议数据单元（PDU）： 应用层：数据（Data）/报文（Message） 表示层：数据（Data）/报文（Message） 数据格式、编码 、解密、压缩 会话层：数据（Data）/报文（Message） 传输层：数据段（Segment）/报文段 网络层：数据包 / 分组（Packet）/IP 数据报 流量控制：端到端.ps:OSI 模型的网络层支持点对点流量控制，TCP/IP 的 IP 层不提供流量控制与可靠传输 拥塞控制：路由器 数据链路层：帧（Frame） 物理层：比特流（Bit） |
| --- |

### 1.物理层

- 物理层任务：实现相邻节点之间比特的传输。物理层不参与数据的封装，透明传输比特流。

| 物理媒体（0 层）：网线、光纤、无线电波（电磁波） 数据：要传的内容（文字、图片） 信号：无论是数字的还是模拟的信号，信号是指数据的具体表现形式。是数据变成电 / 光波形，在 0 层传输介质里跑；处理信号通过介质的传输，能看到传输介质/媒体（第0层）。 信道：物理层里信号通道 物理链路：0 层真实线路连接 逻辑链路：数据链路层，帧可靠通路（以太网IEEE802.3不可靠，但是无线局域网IEEE802.11有ACK可靠机制） 可靠：在数据链路层中，但凡需要实现“高效率可靠传输”的点对点通信，一定会采用滑动窗口协议。但如果对效率要求不高（或帧长很短、RTT极小），也可以使用停-等方式实现可靠传输。 |
| --- |

传输方向（单工、半双工（对讲机）、全双工）是由物理层和数据链路层共同决定的。

物理层是“管道的存在”，数据链路层是“管道里的交通规则”。物理层提供传输能力，数据链路层负责决定使用方式。即物理层：路能不能双向走；链路层：车要不要来回错开走

| 虽然 TCP 本身是全双工通信，数据可双向同时传输。但TCP 三次握手、四次挥手交互逻辑类似对讲机半双工的一问一答。计网 |
| --- |

| 传输介质：多模光纤传输光信号的原理是光的全反射特性 同轴电缆对比双绞线：同轴电缆的铜芯比双绞线粗是能够衰减更小；同轴电缆的阻抗比较标准是减少失真，因为阻抗不同会导致反射而导致失真；同轴电缆具有更高的屏蔽性，从而有更高的带宽，又有更好的抗噪性 |
| --- |

接口特性：电气特征（电压、传输速率 ）、机械特征、过程特征、功能特征；

传输方式：传输方向（单双工）、同步异步、串行并行

网卡（网络适配器）：网络适配器的重要功能是进行数据的串并转换

这里串行或并行传输是计算机组成原理里的总线。

### 2.数据链路层

- 链路层传输以“帧”为单位

- 链路层任务：确保相邻节点之间的链路逻辑上无差错。包含以下功能：

- 一段链路 差错控制：检错+纠错

- 端到端链路 流量控制：协调两个节点的速率

| 流量控制：GBN（后退 N 帧）、SR（选择重传）等。是点对点，所以没有拥塞控制这一网络范围的问题 可靠传输：差错控制+帧编号、确认、重传，保证数据的正确顺序和完整性（差错控制是可靠传输的核心） 数据链路层在分组前加帧头（含目的MAC、源MAC、类型），后加帧尾（FCS帧校验序列）。 |
| --- |

### 3.网络层

- 网络层任务：把"分组"从源节点转发到目的节点。包含以下功能：

- 拥塞控制：发现网络拥塞，并采取措施缓解拥塞。

- 路由选择：构造并维护路由表，决定分组到达目的节点的最佳路径。

- 分组转发：将“分组（数据报）”从合适的端口转发出去。

- 网际互连：实现异构网络互联。

| 异构网络互联：不同的网络虽然在物理层和数据链路层都不同，但在网络层能够剥离这些不同，通过 IP 协议实现互相连接。 如果不同网络在网络层上使用的协议也不同（比如 IPv4 过渡为 IPv6 协议），那么需要通过一些技术来实现连接。计网 |
| --- |

功能：流量控制、可靠传输、拥塞控制、连接建立与释放

| OSI参考模型在网络层支持无连接和面向连接的通信，但在传输层仅支持面向连接的通信。 TCP/IP模型在网络层仅有无连接的通信，而在传输层支持无连接和面向连接的通信。 可靠性区别： OSI 参考模型，可靠性由网络层确定，传输层是一定可靠。 TCP / IP 模型，可靠性由传输层确定，网络层不保证可靠、只转发。 |
| --- |

### 4.传输层

- 传输层任务：实现端到端通信（“端”指“端口”）。包含以下功能：

- 复用和分用：发送端几个高层实体复用一条低层的连接，在接收端再进行分用

- 其他功能：进程之间差错控制、端到端 流量控制、可靠传输、拥塞控制、连接建立与释放

| 流量控制：发送窗口 = min (拥塞窗口 cwnd, 接收窗口 rwnd)。是端到端的 拥塞控制：cwnd拥塞窗口 |
| --- |

### 5.会话层

会话就是为表示层实体或用户进程建立连接，并在连接上有序的传输数据。

- 会话层任务：管理进程间会话。功能：会话管理、同步服务（设置检查点，实现“文件断点续传”）。

- 用检查点维持可靠会话

### 6.表示层

- 表示层任务：解决不同主机上信息表示不一致问题。主要功能包括数据格式转换、加密解密、压缩和编码转换。

应用层：做什么 → 表示层：怎么表示 → 会话层：怎么管理一次进程通信 → 传输层：怎么可靠传输。

## 计算机网络体系结构中的专业术语

| 计算机网络体系结构是网络中层次（分层结构）、协议及层间接口的集合。 |
| --- |

层间接口条件、功能保持不变时，底层功能具体实现方法不会影响整个系统工作。因为：计算机网络采用严格分层模型（OSI 七层 / TCP/IP 五层）：每一层只对上一层提供服务。

| 两层之间的接口就是层间服务访问点 SAP。 同层规则 = 协议 层间规则 = 服务原语 |
| --- |

### 接口

考试时认为接口≈SAP

1. 接口是大框架

2. SAP是接口的具体接入点

3. 服务原语是在SAP上传输的控制命令

### 实体

| 实体，就是一栋大楼里某个部门中，那个具体干活的人。 |
| --- |

- 实体指任何可收发信息的硬件或软件进程（每层里面实际执行协议、收发数据的东西），例如属于物理层和数据链路层的网卡，或属于应用层的浏览器进程。

| 网卡硬件内部含有固件和控制器，它确实能够收发比特流（物理层）和封装数据帧（数据链路层），是一个典型的硬件实体。 |
| --- |

- 对等实体指通信双方相同层次中的实体

- 普通语境：实体 ≈ 载体

OSI 语境：实体 = 每层收发数据、实现协议的软硬件进程

### 协议

| 协议：控制对等实体间逻辑通信的规则的集合。协议内部实现细节不属于网络体系结构，是由具体设备厂家确定 |
| --- |

- 协议的三要素

- 语法：规定数据与控制信息的结构或格式

- 语义：规定了需要发出何种控制信息、完成何种动作以及做出何种响应

- 同步：规定了执行各种操作的条件、时序关系等

### 服务

- 服务：是下层（N 层） 向上层（N+1 层）提供的一组操作

- 在协议的控制下，两个对等实体在水平方向的逻辑通信使得本层能够向上一层提供服务。

要实现本层协议，还需要使用下面一层所提供的服务。

协议是“水平”的，而服务是“垂直”的。

实体看得见下层提供的服务，但并不知道该服务的具体协议。下层协议对上层的实体是“透明”的。

- 上层要使用下层提供的服务，必须通过与下层交换一些命令，这些命令称为服务原语。

- 对等层次之间传送的数据包称为该层的协议数据单元（PDU）

- 同一系统内层与层之间交换的数据包称为服务数据单元（SDU）Service Data Unit

- 在同一系统中相邻两层的实体交换信息的逻辑接口称为服务访问点SAP，它被用于区分不同的服务类型。

## CDM 码分复用

CDMA（Code Division Multiple Access）码分多址

接收方拿到混合信号（所有站点的码片叠加后的序列）。发送方的码片，和接收方接收的这个序列做内积，就可以得到发送方发的比特

- 内积结果 > 0 → 对方发的是 1（因为发 1 时用的是原码片，和自身做内积是正的）

- 内积结果 < 0 → 对方发的是 0（因为发 0 时用的是反码片，和自身做内积是负的）

- 内积结果 = 0 → 对方没发数据（正交码片之间内积为 0，互相不干扰）

## IPv4协议

### IPv4固定首部各字段含义

418首总偏

- 首部长度：长度为4个比特，该字段的取值以4字节为单位，用来表示IPv4数据报的首部长度。

- 区分服务：长度8比特，用来获得更好的服务，实际上一直没有被使用过。

- 总长度：长度为16比特，以1字节为单位，用来表示IPv4数据报的长度（首部长度+数据载荷长度）。

- 标识、标志和片偏移：共 同用于IPv4数据报分片。IP数据报总长度大于链路层MTU（最大传送单元）时分片

- 标识：长度为16比特，属于同一个IPv4数据报的各分片数据报应该具有相同的标识。

- 标志：

最低位MF（More Fragment）：1表示本分片后面还有分片；0表示本分片后面没有分片。中间为DF（Dont Fragment）：DF为1表示不允许分片；0表示允许分片。

最高位为保留位，必须设置为0。

DF为1且分组长度过大时，丢弃该分组，并且向源主机发送ICMP差错报告报文。

- 片偏移：长度为13个比特，该字段的取值以8字节为单位，用来指出分片后某片在原数据报中的相对位置。

除了最后一个分片以外，每个分片的长度一定是8B的整数倍。

- 生存时间TTL：长度为8比特， 以跳数为单位，路由器收到待转发的IPv4数据报时，将其首部中的该字段的值减1，若结果不为0就转发，否则就丢弃。

- TTL的作用是防止被错误路由的IPv4数据报无限制的在因特网中兜圈。

- 协议：长度为8个比特，用来指明IPv4数据报的数据载荷是何种协议数据单元PDU。TCP（6），UDP（17）

- 填充 :用来确保IPv4数据报的首部长度是4字节的整数倍，使用全0进行填充。

### 子网

网络号+子网号+主机号

- 子网掩码可以表明分类IPv4地址的主机号部分被借用了几个比特作为子网号。

子网掩码也是由32比特构成的。用左起多个连续的比特1对应网络号和子网号。之后的0对应主机号。

- 划分子网的IP地址与相应的子网掩码进行逐比特的逻辑与运算，就可得到该IPv4地址所在的子网的网络地址。

- 划分后的子网主机号部分全0和全1依然代表网络地址和广播地址。默认子网掩码是指在未划分子网的情况下使用的子网掩码。

⚠️子网划分并未改变IP地址原有的类别归属，但它通过借用主机位扩展了网络号的概念，使得地址结构从“网络+主机”升级为“网络+子网+主机”，从而突破了分类编制中固定默认掩码的限制。如果说前面的“子网划分”是在分类编制的框架下做一些修修补补，那么 CIDR 就是从根本上推翻了这套框架。

网络前缀+主机号

## 中继器

放大器放大模拟信号，中继器放大数字信号

放大器的原理是放大衰减的信号，中继器是整形再生衰减的信号；

中继器端口仅作用于信号的电气部分；

| 物理层设备没有存储转发功能，所以中继器不能作用于不同速率/不同数据链路层协议的局域网（连接后要能达到正常通信的目的）。 中继器可以连接不同介质的局域网，光纤和双绞线，只要它们具有相同的速率和协议。因为某个网络设备没有存储转发功能，则它不能连接两个不同的协议，中继器没有存储转发功能。 即中继器工作在物理层，无上层解析能力，要求物理层标准、数据链路层局域网协议完全相同。 |
| --- |

| 设备 | 能否不同介质 | 能否不同速率 | 能否不同链路层协议 | 核心原因 |
| --- | --- | --- | --- | --- |
| 中继器 | ✅ 可以 | ❌ 不行 | ❌ 不行 | 无存储转发，只是信号再生，全网同时钟、同协议 |
| 集线器 | ✅ 可以 | ❌ 不行 | ❌ 不行 | 共享冲突域，无缓存，必须同速同协议 |
| 二层交换机（以太网交换机） | ✅ 可以 | ✅ 可以 | ❌ 不行 | 端口独立冲突域+缓存存储转发，能变速率，但不做协议转换 |
| 路由器 | ✅ 可以 | ✅ 可以 | ✅ 可以 | 三层寻址+协议转换，全维度隔离兼容 |

| 物理层卡死速率+协议； 交换机解放介质+速率，卡死协议； 路由器全部自由。 |

## ARP 地址解析协议

工作在网络层

- 在一个局域网内部，通过ARP协议查询到一个IP地址对应的MAC地址。

- ARP表：记录IP地址和MAC地址之间的映射关系。每台主机、路由器都有自己的ARP表。定期更新ARP表项。

- 不能跨网络使用ARP，ARP 只能在【同一个网络 / 同一个广播域】内有效

原理：先查本机ARP 表，有目标 IP 的 MAC 就直接封装成单播帧发送；没有就先广播 ARP 请求，拿到 MAC 再发送。

先查源主机的ARP表，查到目标主机IP，把对应的Mac地址写入Mac帧发送。查不到目标主机的IP，广播发送ARP请求分组（封装在MAC地址为48比特全1、16进制全F的帧，ARP请求分组FF-FF-FF-FF-FF-FF）。

目标主机收到 ARP 请求后，首先缓存源 IP 与源 MAC 映射，确认请求的目标 IP 是自己后，向源主机单播发送 ARP 响应分组；源主机收到响应后，在自身 ARP 缓存（ARP表）中新增 目标 IP ↔ 目标 MAC 映射条目。

ARP 请求携带源 IP、源 MAC，目标主机收到 ARP 广播请求后，把源IP 与 MAC 的映射存入 目标主机的ARP 表；ARP 响应携带目标 IP、目标 MAC，源主机接收单播响应，把目标 IP 与 MAC 的映射存入 源主机的ARP 表。

- ARP报文并不需要IP协议封装，而是直接由数据链路层协议进行封装。

- 找默认网关情况也是一样的。源主机刚开始只知道默认网关的IP，不知道默认网关的MAC。

一开机->Hello 阶段：找直连邻居，建立邻居关系。

洪泛阶段（洪泛法）：和邻居交换链路状态信息，最终全网同步，所有路由器都拿到完整的链路状态数据库 LSDB（全网拓扑图），即数据结构的邻接表。

计算阶段（迪杰斯特拉算法【时间复杂度O（V²）】）：每个路由器以自己为根，运行迪杰斯特拉算法，算出到所有目标网络的最短路径，生成路由表。

OSPF是网络层协议，基于IP的协议。

洪泛：路由器收到一个分组，除了进入的那个接口，向其他所有接口都转发一份 。洪泛不回传，不重复。就是用IP多播地址作为目的地址，OSPF用固定的IP组播地址洪泛。

区域：主干区域相当于中转站。洪泛不跨区域。

代价：RIP就是看跳数，ospf需要参考每条边的权值

## DHCP 动态主机配置协议

可以动态地给主机分配IP地址；基于UDP

顺序：发现（Discover）、提供（Offer）、请求（Request）、确认（ACK）

| IP 层：全部都是广播（255.255.255.255） |
| --- |

- 客户端：发现（Discover）、请求（Request）报文： MAC 为广播。

- 服务器：提供（Offer）、确认（ACK）报文：MAC 为单播（客户端 MAC 地址）。

- 需要被分配的主机：MAC 地址是出厂就确定；DHCP提供报文说明了IP、默认网关和子网掩码

| 因为此时客户端还未完成 IP 配置，需要用 MAC 单播定位，但 IP 层仍使用广播地址。 |
| --- |

| 目的 MAC 用单播（客户端 MAC）：网卡一看目的 MAC 是自己的，就会收下帧，不会在链路层被丢弃。 目的 IP 用广播（255.255.255.255）：客户端的 IP 层此时还没配置 IP，只认广播 IP。 |
| --- |

简单类比：

- Offer = 酒店前台说：“有一间 301 房空着，给你钥匙。”

- Request = 你说：“好，我就要 301，不再看其他房间了。”

- ACK = 前台说：“确认 301 登记在你名下，这是房卡，2 天后中午前退房。”同时系统里锁掉 301

- DHCP 想象成酒店的前台：

房卡号 = 你的 IP 地址

酒店地图 = 子网掩码（告诉你哪些区域在酒店内）

酒店大门 = 默认网关 IP（告诉你离开房间后，要从哪个门出去走到街上）

礼宾部的电话 = DNS 服务器 IP（你打电话问礼宾：“我要去天安门怎么走？”礼宾告诉你“天安门的地址是 X 街 Y 号”）

#### DHCP  源/目的 IP、MAC 对照表

前提：四个报文，目的IP全部为受限广播 255.255.255.255

| 报文 | 发送方 | 源IP | 目的IP | 源MAC | 目的MAC |
| --- | --- | --- | --- | --- | --- |
| Discover（发现） | 客户端 | 0.0.0.0 | 255.255.255.255 | 客户端MAC | 广播MAC(全F) |
| Offer（提供） | 服务器 | 服务器IP | 255.255.255.255 | 服务器MAC | 客户端MAC（二层单播） |
| Request（请求） | 客户端 | 0.0.0.0 | 255.255.255.255 | 客户端MAC | 广播MAC(全F) |
| ACK（确认） | 服务器 | 服务器IP | 255.255.255.255 | 服务器MAC | 客户端MAC（二层单播） |

在offer报文中，会提供IP，默认网关IP，DNS服务器IP

- 这个 0.0.0.0 在 TCP/IP 协议栈中的含义是：

| “我不知道我是谁，但我现在就在这个网络里” |

### HTTP与TCP

|  | 每个HTTP请求都只能请求一个资源。 主机与web服务器之间，始终在进行 TCP 通信（传输层）。而 HTTP 请求和响应，仅仅是这些 TCP 报文段中“应用层载荷”的一部分。 因为HTTP是基于TCP的，所以每个RTT内传送的数据量受TCP发送窗口的限制。当 HTTP 响应携带的文件很大，超过了当前 TCP 连接的发送窗口（swnd，send window，由接收方通告的 rwnd 和拥塞窗口 cwnd 共同决定）时，TCP 会分批次传输。 一个 HTTP 请求对应一个 HTTP 响应（一个文件）。如果该文件太大，超过 TCP 发送窗口，就会被分成多个 TCP 段进行传输。 |
| --- | --- |

持续连接也就是说建立一个TCP连接，然后就一直使用该连接发送HTTP请求报文和响应报文。非持续连接就是每发送完HTTP响应报文之后，就要重新建立TCP连接。

非持续连接分为串行TCP和并行TCP，持续连接分为流水线、非流水线。并行是多个连接，流水线是一个连接上的请求顺序。一定要熟捻于心，这四种连接的过程
