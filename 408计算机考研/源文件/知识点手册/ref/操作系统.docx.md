2018年考察的多任务操作系统可等同于具有交互功能的多道批处理操作系统。

同时自己也混淆了多道批处理操作系统，它的技术本质与硬件无关，无论是单核CPU和多核CPU都可以是多道批处理操作系统，所以也就拥有了并行性和并发性，同时多个任务必须互斥的访问共享资源。

同时多道批处理操作系统不依赖于虚拟存储管理技术，早期的多道批处理操作系统直接就把需要执行的所有进程的数据全都引入内存了。

操作系统的基本类型：批处理、分时和实时

### 2.中断和异常的处理 （判断中断方式可以采用硬件识别法）

1.定义
408中的中断都是外中断，由于外部导致的中断，与指令本身无关，只发生在指令的中断周期。（例如时钟中断CPU时间片到）

异常也叫内中断，由于执行指令时导致的，例如（例如操作码非法、除以0、缺页、地址溢出、运算溢出、专门的陷入指令（例如应用程序请求的用户态转为内核态）），异常是不能被屏蔽的

2.中断的分类

故障就是指令执行过程中跟软件有关的错误。

自陷是程序员自己设计好的“异常”，例如系统调用、条件陷阱指令等，应用程序用户态和操作系统内核态的转换也称为软中断。

终止一般就是内核程序无法修复的错误，强制退出程序、或者控制器出错、存储器校验错，一般都是硬件出了问题。

可屏蔽中断是通过INTR线传送到CPU的中断请求。

不可屏蔽中断比如断电

### 3.中断和异常的处理过程

（1）在该指令i执行过程中发现异常，执行异常处理程序，处理异常后返回第i条指令。

在该指令i执行完成后发现中断，执行中断处理程序处理异常后返回第i+1条指令。

另外：如果发现异常和中断事件时致命错误，则终止该程序。异常和中断处理程序由操作系统完成。

2. 响应中断就是在执行周期结束（一条指令执行结束），而中断处理程序是在中断周期结束

4.中断处理和子程序调用的区别

①中断处理程序与当前执行的程序无关，而子程序与主程序都属于同一个程序的一部分，属于主从关系。

②中断都是随机的、但子程序调用是通过CALL指令实现的，程序员提前设计好的

③调用子程序完全就是软件处理过程，但是中断处理程序必须要结合硬件实现（寄存器、电路等）

④中断处理程序的入口地址是硬件向量法产生向量地址、再有向量地址找到入口，但是子程序的地址是CALL指令的地址码给出的。

⑤两者都需要保护PC计数器、通用数据寄存器、通用地址寄存器的内容，中断程序是由中断隐指令帮忙保存，而调用子程序是CALL指令完成，压入栈中了。子程序不改变程序的状态，所以PSW的值不需要压入堆栈，但是系统调用时是需要压入堆栈的。

⑥响应中断时，会有处理中断的优先级，而调用子程序没有这种操作。

⑦系统调用的被调用过程一定是在内核态、子程序调用的过程可能是用户态也可能是内核态（比如执行中断处理程序时，有需要调用一个小的子程序返回一定的参数，这很正常）

中断处理比系统调用更重要！！！！！

中断的流程

| ①CPU检测到中断信号然后进行中断判优 |  |
| --- | --- |
| ②检查EFLAGS寄存器的IF标志 | 目的是检查是否可以响应可屏蔽中断，若可响应才继续执行 |
| ③硬件在中断向量表中找到该中断信号对应的中断向量 | 中断向量保存的是处理该中断信号的处理程序地址，中断向量表本质就是一个数组，该数组由操作系统初始化 中断向量基址寄存器+中断信号偏移量=中断向量的地址 |
| ④触发了一种特权级校验 | 如果当前是用户态，则允许特权转化成内核态（修改某个特权寄存器的值即可），并且切换了栈指针，即从用户栈切换到内核栈！！！ |
| ⑤保护上下文（此时已经进入内核态） | 硬件压入内核栈区：硬件保存断点（包括PC和PSW） 软件（操作系统）压入内核栈：保存中断屏蔽字（一组二进制编码，每一位对应一种中断类型，关闭该类型的中断，防止同类型优先级的中断嵌套，类型中断而非全局中断！！！保存下来方便恢复上下文环境，恢复到前文的允许中断情况）、通用数据寄存器和通用地址寄存器 |
| ⑥执行中断处理程序 |  |
| ⑦恢复上下文 | 从内核中断栈弹出通用寄存器、用户栈指针等软件手动保存的上下文； 执行IRET指令，硬件自动弹出EIP（x86系统中的下一条指令地址，也叫PC）、CS（用户态代码段）、EFLAGS（含中断屏蔽位），恢复用户态执行流； CPU 继续执行用户程序中被中断的下一条指令 |

执行系统调用之前，需要执行命令解释程序。是在用户态输入我想执行的命令（在cmd这个程序里），相当于命令解释程序 (Shell) 理解了你输入的clear是想运行一个叫clear的程序。它找到这个程序在哪，然后让操作系统执行这个clear程序。程序clear自己内部知道怎么调用操作系统的接口（或发送特定指令）来清屏。所以这就是命令解释程序。程序员在代码中直接调用系统调用 (如 read) 时，根本不会涉及外部的命令解释程序 (Shell)。

## (四)操作系统结构

分层，模块化，宏内核，微内核，外核

### 分层就是分了0、1、2、3.......层，硬件在第0层，应用程序在最高一层。

优点是：便于调试和验证，不同层之间不会干扰、易于扩充和维护

缺点是：如何定义各层的界限？层数太多穿层、效率太低如何定义各层之间通信？

### 模块-接口化就是把操作系统分为进程管理、文件管理、存储器管理等大模块，每个模块内部有小的模块，模块之间需要定义接口

模块大小影响操作系统效率，模块太大，内部太复杂；模块太小，联系太多，系统太乱。

模块独立性影响操作系统效率，内聚性越高，模块内部联系越紧密，模块之间的独立性越好；耦合性越高，模块之间的联系越紧密，独立性越差！

优点是：操作系统的设计偏向于正确的道路了，加速了开发过程

缺点是：接口太难设计

宏内核（单内核、大内核）就是把主要功能模块全都集中在一起
优点是：模块之间沟通顺畅，性能极其强悍
缺点是：随着发展，宏内核臃肿不堪

微内核就是在宏内核基础上把一些非核心功能移到用户空间，目前主流操作系统都采用宏内核＋微内核的混合内核
基本概念：

①最重要的功能保留在内核，不重要的功能被划分为多个服务程序放在用户态执行，服务程序之间通过微内核进行通信，降低设计的复杂性

②操作系统=微内核+多个服务器，每个服务器负责一大类的功能（例如进程管理、内存管理等），微内核与硬件有关、包含一些基本功能、负责客户与服务器之间的通信。
③可靠性高：如果服务器崩溃了，重启就行，与微内核不干扰。但是在宏内核中某个功能崩溃会导致整个系统崩溃。

微内核的基本功能：
①进程、线程管理（进程切换调度属于微内核；如何对进程进行分类、优先级的确认方式属于策略问题，放入服务器当中）

②低级存储器管理（只与硬件有关的部分，例如地址转换过程。而采用何种页面置换算法、如何进行内存分配与回收应该放在存储器管理服务器中）

③中断和陷入处理（微内核负责识别、服务器负责处理）

微内核的特点：2023真题

①扩展、灵活
②可靠性和安全性
③可移植性：其他各种服务器的代码与硬件无关，所以只需要针对不同硬件对微内核进行修改

④分布式计算：微内核和服务器之间采用消息传递机制、更好的支持了分布式系统和网络系统

微内核的缺点：

①在内核态和用户态之间切换、开销较大

②宏内核适用于桌面操作系统、微内核适用于可靠性的工业航空航天军事等领域

外核就是给每个用户分配物理上的空间，互不冲突，记录给每个虚拟机的有关资源，只需要保证虚拟机之间不冲突即可。

# 二、进程管理

## (一)进程与线程

### 1.进程与线程的基本概念

（1）进程的概念：
①进程是一个正在执行程序的实例

②进程是一个程序的代码和数据从磁盘加载到内存，在CPU上的执行过程

③进程是一个具有独立功能的程序在一个数据集合上的运行过程。

④进程是系统进行资源（包括CPU、存储器和其他设备服务于某个进程的时间）分配和调度的一个独立、基本单位！

⑤进程映像=程序段+代码段+PCB
⑥一个进程在其生命周期内不止可以运行一个程序，可以运行多个程序，这个程序不止限于微信等大程序，连脚本、共享库这些都叫程序。但是只能顺序的执行多个程序，不能同时执行多个程序

（2）进程的特征：
动态性、并发性、独立性、异步性

（3）进程的组成：
最重要的就是PCB，它是进程存在的唯一标志，而不是PID！

四大标志：

①PCB的身份证号PID

②运行情况
a.调度上处理机，要查询进程当前状态和优先级

b.进入内存时间用于某个CPU调度算法的参数

c.CPU占用时间可以用于时间片切换

d.代码运行入口地址可以用于找到代码的第一行，发生中断保存上下文时，会把断点地址保存在这里面，方便下一次运行时找到入口

e.程序的外存地址是 “找到程序并加载到内存” 的依据。

③资源分配情况
a.代码段指针是指向内存代码的起始地址，并不会随着代码运行发生改变

b.数据段指针和堆栈段指针同理（指针只用于界定范围，并不用于地址计算）

C.文件描述符保存打开的文件的fd，可以同时保存多个fd

④上下文情况
a.通用寄存器值：保存进程运行时的数据和中间结果等，恢复运行时可继续使用。

b.地址寄存器值：存放内存地址信息，如基址、变址寄存器等，专门用于内存访问和地址计算，与上面数据段指针和堆栈段指针的作用要区分开来。

C.控制寄存器值：记录控制相关状态，如模式位（用户态/内核态）等，决定指令执行权限。

D.标志寄存器值：存储运算结果标志（如溢出、零标志等）。

程序段：多个进程可共用程序段

数据段：原始数据或者进程产生的加工数据
例如只读数据段、可读写数据段

（4）PCB的组织方式

链表链接，按照不同状态甚至不同原因阻塞的，分开链接

索引表，索引指针指向PCB

5. 线程的基本概念

①引入线程是为了减少程序在并发执行时所付出的时空开销
解释一下：假设微信exe是一个程序文件，打开微信就是一个巨大的进程，而发送线程、获取信息线程、监听网络线程、检测鼠标点击这都是一个个线程，他们在宏观上是并行的，微观上是串行的，所以线程是独立调度的基本单位，它是一个基本的CPU执行单元，程序执行流的最小单元。

②线程不拥有系统资源，只拥有一些基本的必要资源

③一个线程可以创建和撤销另一个线程

6. 线程与进程的比较

①进程调度开销大、同进程内的线程调度只需要保存和恢复线程的栈指针、寄存器值等少量上下文，无需切换页表和内存映射。
②线程的并发性会提高系统资源利用率和系统吞吐量（本质都是通过轻量切换过程，减少了浪费的等待时间、使得CPU利用更充分、更多的任务被执行完成）

③线程不拥有系统资源，同一进程的所有线程拥有相同的地址空间

④同一进程的各个线程是由于相互合作或者提高并发性才被创建的
⑤引入线程，则进程可以被同时运行在多个CPU上

线程的属性
①线程=PID+TCB（记录寄存器、栈等现场信息）

②同一进程中的线程共享该进程的资源
③同一个服务程序被不同的用户（这里的用户指的是需求，被不同的功能需求）调用时，操作系统将他们创建成不同的线程：本质是服务程序通过线程的轻量并发能力，高效、低成本地同时处理多个用户的独立请求，这是服务器高并发设计的常见策略。
例如微信内部同时申请上传一张图片、下载一个文件，选择的是创建两个线程，而不是重新打开两个微信进程。

### 2.进程/线程的状态与转换

创建态：
先创建PCB、写入PCB中的信息，然后分配资源（如果所需资源不够，则停留在创建态），分配资源结束后才插入到就绪队列。

阻塞态：

进程因为要等待IO完成或者某个资源，而进入阻塞态。中断时，进程是进入了阻塞态。读磁盘时是一定被阻塞的，因为要让CPU充分利用，把CPU让出去给其他人，不能迷糊，不要认为磁盘是共享设备，可以并发读取，根本原因在于你用着磁盘，CPU就空闲了！

终止态：

执行了exit系统调用，操作系统结束该进程并且回收资源（包括PCB、资源、CPU）。

其中就绪态到运行态：可剥夺操作系统，有更高优先级的进程进入，就会被剥夺CPU

阻塞态→就绪态：当IO结束或者中断结束，由中断处理程序将进程的状态调整为就绪态

运行态→阻塞态是主动行为，阻塞态→就绪态是被动行为
进程因状态转换（如完成打印任务，进入下一执行阶段）而主动放弃资源的结果，请注意是进程状态转换导致释放打印机，而不是因为释放了打印机而导致自身状态转换，这个因果关系一定要弄清楚！

阻塞进程：用户态到内核态，在内核态将该进程阻塞，然后还要处理其他事情，再返回用户态调度新的进程
唤醒进程：先从用户态到内核态，将该进程的状态调整为就绪态，然后处理其他事情，再返回用户态继续执行原进程。

执行CPU调度，之后还要进行上下文切换，然后还要检查各类事情，再返回用户态。

唯独：执行系统调用完成之后立马从内核态到用户态！！！！！（2023真题）

### 3.线程的实现

内核支持的线程，线程库支持的线程

线程的实现方式：

1. 用户级线程
   “从用户视角能看到的线程”，切换撤销等都在用户空间进行，内核意识不到线程的存在，应用程序控制的线程
   ②调度仍然以进程为基本单位，因为操作系统根本看不到线程，所以对于线程来说是调度不公平的，假设有两个进程，第一个进程有100个线程、第二个进程有1个线程，那么第一个进程中的线程所获得CPU的时间是第二个进程中的线程的0.01倍。

③用户级线程的切换不需要转到内核空间、开销小、用户级线程与操作系统无关即可以运行在任何操作系统上面，对线程管理的代码是应用程序而非操作系统。
④进程内部的某个线程被阻塞，内部其他线程也被阻塞；进程每次只能获得一个CPU，所以导致内部的线程无法并行执行。
⑤线程库是为程序员提供创建和管理线程的API接口

⑥在线程同步时，由于线程是由程序控制的，在某些线程需要在其他线程执行完之后才能执行，这过程只是在用户级线程之间切换。但是线程的系统调用、IO处理、异常处理这都涉及到内核
（2）内核级线程
内核级线程是在操作系统的帮助下实现的；内核感知到线程的存在。
①优点是：同一个进程内的不同线程可以并行执行（即一个进程可以同时获得多个CPU）；内核级线程本身切换也快、开销小；

②同一进程中的频繁线程切换需要从用户态转到内核态，开销大（但用户级线程是在用户空间内发生转换的，就没有这样的缺点）；因为此时线程管理是由操作系统完成的

（3）组合方式

为了解决用户级线程“进程内部一个线程阻塞导致其他线程也被阻塞”&内核级线程“同一进程内部线程的切换需要用户态转到内核态”这两大缺点，引进来了组合方式！

内核级线程和用户级线程的关系要梳理清楚：在组合方式中，内核级线程和用户级线程并不一定代表着同一种任务，通常情况下把用户级线程当做具体的任务了，而把内核级线程抽象成一个调度的单位，例如内核级线程A\B共同绑定着用户级的线程任务CDEF（不是固定C 归 A 管、D 归 A 管，E 归 B 管、F 归 B 管，而是线程库会根据情况动态分配），这样CDEF内部可以轻松在用户级别切换，而通过AB（在多CPU系统中）也可以实现CDEF的并行执行

多线程模型：
（1）多对一模型
即内核区的一个核心线程映射到用户区的多个核心线程。线程的调度和管理在用户空间完成，只有在该用户线程需要访问内核区时，才将该用户线程映射到内核线程。
优点和缺点同“用户级线程”
（2）一对一模型
每个用户级线程映射到一个内核级线程，每个进程拥有相同数量的用户级线程和内核级线程，每创建一个用户级线程，就需要创建一个内核级线程，优缺点同“内核级线程”
（3）多对多模型
同组合线程

并发性较好的多线程模型：一对一模型和多对多模型，充分利用多核CPU（真正的并行执行）

### 4.进程与线程的组织与控制

进程控制：（主要包含进程创建、进程终止、进程进程阻塞和唤醒）
进程控制的程序段成为原语，是操作系统内核中实现特定基本功能的、不可分割的程序片段（它只是一些程序代码，属于内核的程序代码，由于需要经常对进程进行控制，所以这些原语常驻内存）、原语执行过程中不允许被中断。

（1）进程创建
父进程与子进程：子进程继承父进程的资源、父进程要回收子进程的资源。但是父进程和子进程并不使用同一片地址空间，子进程只是把父进程的内容复制一份，重新开辟了一片新的空间（2020真题）
孤儿进程与僵尸进程：当父进程提前终止，子进程就成为孤儿进程，通常会被 init 进程收养，所以父进程终止也可能不会终止子进程（2024真题）；而子进程先终止，父进程未及时回收其资源，子进程就会变成僵尸进程。

导致进程创建的操作：

| 终端用户登录系统 | 每个用户登录后都是一个独立的交互主体，需要独立的资源（如内存空间、环境变量）和执行流，进程是系统管理这种 “独立性” 的基本单位。相当于开机登录系统就是一个巨大的进程 |
| --- | --- |
| 作业调度 | 批处理系统中，用户提交的 “作业”（如一个包含多个程序的计算任务）需要被拆分为可执行的进程，由调度器按规则分配 CPU 资源，因此会触发进程创建。 |
| 系统提供服务 | 打印文件（创建新进程是为了“并发处理多个请求”）、访问数据库（客户端进程发起连接请求，服务器会创建一个新进程 / 线程专门处理该连接） 而分配设备并不会造成创建新进程！ |
| 应用程序请求 | 无需多言 |

申请PCB（PCB数量有限，若不足则创建失败）→分配资源（若资源不足则停留在创建态）→初始化PCB（标志信息、CPU状态信息、控制信息、进程优先级）到这一步才算创建完成（2021真题）→插入就绪队列

（2）进程终止

正常结束、异常结束（执行过程中出错）、外界干预（操作员主动关闭、父进程被请求子进程关闭、父进程被撤销）

进程终止时的操作：

①根据PID进程号找到PCB集合链表中找到PCB，确认其状态（运行态、就绪态、阻塞态等）和相关资源信息

②若进程存在子进程，必须先终止所有子进程（或转移其 “父进程” 身份给其他进程，如init进程），但并不是所有系统都要求子进程随着父进程一起死亡

③如果该进程还持有CPU，立即终止执行，将CPU给其他进程

④释放资源：2024真题
用户空间内存（如堆、栈）、页表等

若进程使用了共享内存，需检查引用计数，仅当计数为0时才彻底释放共享内存。

关闭进程打开的所有文件描述符（包括普通文件、管道、设备文件等），若文件引用计数为 0 则释放文件对应的内核数据结构（如inode）。

- 回收进程持有的信号量（同步互斥临界资源等）、消息队列（若进程是消息队列的 “创建者”，需检查队列的引用计数（当前关联的进程数）：
  - 若计数为 0，删除消息队列，释放其占用的内核存储空间（包括消息链表、队列描述符等）。
  - 若计数 > 0，仅解除当前进程与队列的关联，队列继续存在。

）、定时器以及如时间片、寄存器上下文等。
回收该进程所持有的设备

⑤将PCB从各个阻塞、就绪队列中删除

⑥回收PCB

（3）进程阻塞和唤醒
等待队列的是意思是等待资源，而不是等待CPU，所以等待队列=阻塞队列

阻塞过程非常简单：

根据PID找到PCB→检查状态且保护上下文→让出CPU、插入阻塞（等待）队列

唤醒过程：

根据PID找到PCB→从阻塞队列移出，设置为就绪态→插入就绪队列

阻塞原语和唤醒原语必须成对出现，即如果该进程主动调用阻塞原语，另外还需要插入一条唤醒原语到另一个进程，以便后续唤醒，而不是自身唤醒自身。

线程控制：（主要包含进程创建、进程终止、进程进程阻塞和唤醒）

①线程TCB里面几乎不记录线程的所拥有资源，因为几乎都是进程拥有资源
②线程TCB保存CPU上下文（寄存器、栈指针、与进程共享栈空间但有独立栈帧）

③线程创建时不分配新内存/资源

### 5.进程间通信共享内存，消息传递，管道，信号

### 进程通信（进程之间的信息交换）：

低级通信PV操作
高级通信：共享存储、消息传递、管道、信号

1. 共享存储
   ①通过共享存储区来实现信息交换；通过系统调用让操作系统分配内存区并返回标识符

②通过共享数据结构（例如数组），可以最低级的实现信息交换

③通过对映射文件的共享，将磁盘文件映射到多个进程的虚拟地址空间” 来实现内存共享。其重点在于共享的载体是文件

在初始化时，需要一次状态切换，后续通信无需进行状态切换。

2. 消息传递
   操作系统提供消息传递方法，便于两个进程之间直接进行通信，以格式化的消息Message作为单位，通过发送消息原语和接受消息原语进行数据交换，隐藏了通信实现细节，通信过程对用户透明，应用最广。消息队列是内核管理的资源，由内核完成数据复制和队列管理，所以要往消息队列里面写数据，需要用户态转到内核态
   
   发送方：用户态（准备好数据，进行系统调用后进入内核态）→内核态（进入内核态后，将用户区的数据复制到内核态）→用户态（复制完成后，返回用户态）。

接收方：用户态→内核态（接收请求）→用户态（接收完成）
也可以广泛应用于微内核与服务器、多CPU系统、分布式系统、计算机网络

①直接通信：指明对方进程的PID，如进程重启，通信会中断，这种方式灵活性比较差

②间接通信：不需要指明PID，只需指明BOX信箱号码，支持多个进程共用一个信箱

优点是：简单、安全、灵活、对用户透明，无需用户手动处理同步（内核会管理队列的空满状态，自动阻塞 / 唤醒进程）
缺点是：效率较低，切换开销大、复制占用内存开销也大，消息传递需经过内核中转（涉及内存复制、进程切换），速度慢于共享存储（共享存储直接读写内存）。

若需高频、大数据量通信，优先用共享内存（追求效率，共享内存效率更高）。并且共享内存仅适用于同一台机器上的不同进程，需要手动处理同步互斥机制、编程麻烦

若需跨进程解耦、简单安全的通信（如服务间指令传递、分布式系统），优先用消息传递（追求易用性和灵活性）。而消息传递可以在网络环境中适用

3. 管道pipe文件（也叫无名管道，用于血缘关系的进程之间通信，一种特殊的共享文件，一段特殊的内核缓冲区）通信

①管道先进先出

②对管道必须互斥、同步机制，还要确认对方存在性！

③半双工通信，与消息传递不一样，消息传递是全双工通信，所以管道需要两个来实现全双工
④匿名管道仅支持有亲缘关系的进程（如父子、兄弟），因管道创建时无标识，需通过 fork 继承文件描述符；命名管道（FIFO）可支持无亲缘关系的进程（通过路径名标识）。
⑤内核自动管理管道的空满状态（写端满则阻塞，读端空则阻塞），无需用户手动处理同步；这一点与消息队列类似。

⑥管道缓冲区是内核空间的资源，无论是写数据到管道还是读数据，都必须通过系统调用进入内核态，由内核完成数据复制和缓冲区管理

⑦必然涉及多次状态切换和两次数据复制。其效率低于共享存储（无数据复制、少状态切换），但高于信号（仅传递整数），适合传递流式数据
⑧管道仅仅可以由创建进程访问，当父进程创建一个管道后，子进程会继承管道，管道也是子进程与父进程通信的方式，

⑨管道数据一旦被读取，就被释放该数据空间了。

⑩管道本质是占用内存的缓冲区，所以需要受到内存空间限制（2014真题）
11.一个管道可以由多个读进程和写进程对其进行操作，但是同时读和同时写是不被允许的，所以需要用互斥锁加以限制！

最重要的是过程，还是通过系统调用来实现对管道的读写：

写端：用户态→内核态（调用write）→用户态（写完成）。

读端：用户态→内核态（调用read）→用户态（读完成）。

关于管道被阻塞：
若管道未满（缓冲区有剩余空间），则将write_buf中的数据复制到内核管道缓冲区

若管道已满（缓冲区无空间），内核会阻塞写进程 A（或返回错误，取决于管道是否设置为非阻塞），直到读端读取数据后管道有空闲空间。
若管道为空，则读进程被阻塞。

4. 信号
   信号是一种异步通信机制（发送方 “只管发”，接收方 “被动接”，双方无需协调时序，也不存在相互等待，为了应对 “突发事件”），传递的不是大量数据，但是事件标识（整数编号），通信过程同样涉及用户态与内核态的切换，但数据流转路径和开销与管道有显著差异。

进程A：发送信号方

进程 A 在用户态决定发送信号，通过系统调用（如kill(pid, sig)）指定目标进程 B 的 PID 和信号编号（如SIGINT表示中断，编号 2），请求向 B 发送信号。此时信号的 “内容” 仅为一个整数（信号编号），无需复杂数据结构。

进程 A 执行kill()系统调用，进入内核态。

信号的发送和管理是内核职责（需验证权限、查找目标进程、维护信号状态），用户态进程无法直接操作其他进程的信号机制。

内核检查发送权限（如进程 A 是否有权向进程 B 发信号）、信号的有效性（是否为系统定义的信号编号）。

若验证通过，内核在进程 B 的 “信号 pending 队列”（PCB 中的数据结构，记录了位图，即每种信号的标志位都为0，当出现该信号时，标记为1）中记录该信号，标记为 “待处理”。

进程B：信号接收方

进程 B 在执行过程中，每次从内核态切换回用户态前（如系统调用返回、中断处理结束后），内核会检查 B 的 pending 队列。

若存在待处理信号，内核暂停 B 的正常执行流程，触发用户态→内核态切换（进入信号处理上下文）。

内核查找进程 B 注册的信号处理函数、修改进程 B 的用户态栈，设置返回地址为信号处理函数的入口，然后从内核态切换回用户态，执行该处理函数。

进程 B 在用户态执行忽略、默认信号处理程序或者进程自定义处理函数（这是三种情况都可以）（如释放资源、记录日志、退出进程等）。

处理完成后，通过特殊的系统调用（如sigreturn()）再次进入内核态，恢复进程 B 的正常执行上下文。

内核清理 pending 队列中的该信号，从内核态切换回用户态，进程 B 继续执行被中断前的逻辑

发送方：用户态→内核态（kill()调用）→用户态（发送完成）。

接收方：用户态→内核态（检查信号）→用户态（执行处理函数）→内核态（sigreturn()恢复原进程上下文）→用户态（正常执行）。

同时不止进程可以给另一个进程发送信号，内核本身也可以给进程发送信号，也可以进程给自己发信号
但也不是系统中的所有进程都可以发送信号，只有核心和超级用户才可以

信号处理结束后，会返回到进程的下一条指令继续执行

不是每种信号的处理都可以自定义处理函数！
每种信号都有默认处理程序，尽管有些默认处理程序就是忽略它，但它就是有！

（5）socket嵌套字

一、OS视角下Socket的核心作用

在操作系统中，Socket的本质是内核提供的一种“跨进程通信接口”，其核心作用是：

允许同一主机内的不同进程通过“本地Socket”通信。

允许不同主机的进程通过“网络Socket”通信。内核通过网络协议栈（如TCP/IP）将本地进程数据封装为网络包，实现跨主机传输，而其他IPC仅依赖本地内核，唯一一个支持网络跨主机进程通信的机制

对OS而言，Socket的核心是抽象出统一的“通信端点”，让进程无需关心底层是本地还是网络传输，只需通过内核提供的Socket API读写数据。

二、OS中Socket的使用逻辑

1. 创建Socket：进程调socket()系统调用，内核为其分配一个Socket结构体（包含通信协议、缓冲区、状态等信息），返回文件描述符（类似文件句柄）。

2. 绑定/连接：

本地通信：通过bind()绑定到本地文件路径（如`/tmp/socket`），内核维护路径与进程的映射。

网络通信：通过`bind()`绑定IP+端口，内核记录“端口-进程”对应关系。

3. 数据传输：

进程通过read()/write()系统调用，内核将数据从发送方缓冲区复制到接收方缓冲区（类似管道的“内核中转”机制）。

合作进程可以使用的进程通信方式：管道、嵌套字、信号量、消息队列、信号、共享存储，不能通过全局变量和数据库进行通信

## (二)CPU调度与上下文切换

### 1.调度的基本概念

①高级调度任务是从后备队列中挑选一个作业，为其分配内存、IO设备、建立相应进程，让其从创建态到就绪态。而中级调度是挂起态和就绪态之间的转变。

②2022年真题踩坑，在就绪队列为空，刚来第一个进程，直接让该进程上处理机运行，这个也算一次CPU调度！

| 高级调度（作业调度） | 从外存中调度作业进入内存，这个过程是创建新进程PCB，分配资源，每个作业只调入一次、调出一次（撤销PCB） |
| --- | --- |
| 中级调度（内存调度） | 把暂时不运行的进程“挂起”到外存，提高内存利用率和系统吞吐量，具备运行条件时再调入内存，发生频率高 |
| 低级调度（进程调度） | 分配CPU的过程，频率最高 |

### 2.调度的目标

（1）CPU利用率，无需多言，主要关注CPU的使用时间和空闲时间

（2）系统吞吐量：单位时间内完成作业的数量，所以短作业优先调度算法的系统吞吐量最大

（3）周转时间=作业完成时间-作业提交时间

平均周转时间=周转时间总和/作业数量

带权周转时间=作业周转时间/作业实际运行时间，所以它一定≥1

（4）等待时间：等待CPU的时间之和

（5）响应时间：从用户提交申请开始到首次响应的时间

### 3.调度的实现

调度器/调度程序(scheduler),调度的时机与调度方式(抢占式/非抢占式),闲逛进程，内核级线程与用户级线程调度。

排队器的目的是：按照一定策略给就绪进程排队，然后插入就绪队列

分配器是根据调度程序所选的进程，从就绪队列中取出，将CPU分配给它。

上下文切换器：是将上下文环境保存到PCB中，而不是栈中！然后装入分配程序的PCB便于分配程序，再保存分派程序的上下文到PCB，再调入新进程的上下文环境（中间需要执行一次分派进程）

由于中间需要加载load和store指令，以保存寄存器的值，所以，比较耗时间，固然可以采用两组寄存器，一个供内核使用，一个供用户使用，这样只需要再上下文切换时，修改指针即可。

处理机调度的时机：
请求调度的事件、运行调度程序、调度新的就绪程序，按道理这应该是顺序执行的，但是不一定会立马进行调度和切换！

①处于临界区（临界区是指进程中访问共享资源（如共享变量、文件、设备等）的那段代码。由于共享资源在同一时刻只能被一个进程访问，因此操作系统需要确保每次只有一个进程可以进入临界区。进入临界区的进程通常会执行一些对共享资源的读写操作，这些操作要求原子性，即在执行过程中不能被其他进程打断）的进程也可能因为中断或者抢占而被调度。如果进程请求的是一个需要等待的资源例如打印机（这是属于共享资源，进程处于临界区），那么有可能主动放弃CPU，请求调度。
②创建新进程，父子进程选择一个进程上处理机。
③某个进程需求的外设准备完毕， 发出IO中断，此时可以根据优先级来判断让不让该进程重新上CPU执行，或者继续执行中断之前的进程。

④系统调用完成并返回用户态时能进行处理机调度，详细原因解释在模式切换（自己ctrl+f搜索模式切换）那一小部分。

不能进行进程调度的时机：
⑤原子操作过程中也不能进程调度和切换

⑥在处理中断过程中不能进程调度和切换

进程调度的方式：

非抢占式（非剥夺方式）调度：简单、系统开销小、但不适用于分时系统（因为在非抢占式调度中，时间片到了触发中断不会让该进程下处理机）和大多数的实时系统

抢占式调度：抢占必须要遵循一种原则，不能随机

闲逛进程：

没有就绪进程时，调度闲逛进程上处理机运行！

内核级线程调度需要上下文切换、修改内存映像、使高速缓存失效

进程的切换：

任何进程的切换都是依靠内核完成的

调度本身是一种决策行为，而切换是一种执行行为！

上下文切换需要：

①挂起该进程，将环境保存到PCB中，包括计数器和寄存器

②将PCB移入相应的队列

③选择另一个进程，先更新PCB（例如修改该进程从就绪态到运行态，记录该进程本次开始运行的时间用于后续计算 CPU 占用率、响应时间等，重置或更新与调度策略相关的字段（如时间片剩余量，若采用时间片轮转调度，新进程开始运行时需将其时间片重置为系统规定的初始值。）

④将新进程的PCB环境恢复到CPU中

⑤跳转到新进程的程序计数器指向位置并执行！

6. 多级反馈队列调度算法
   规则比较复杂：①分为不同级别的队列，每个级别的队列时间片依次增加。
   ②如果执行完了这个时间片，那么进入到下一级的时间片队列，如果中途被打断，下处理机，重新回去到该就绪队列。
   ③如果有更高级别的队列里面有就绪进程等待被调度，那么先处理它，直到k阶就绪队列为空，才能执行k+1阶的就绪队列的调度算法。
   ④如果已经是最后一层的就绪队列，但是一个时间片还没有运行完，则重新回到该队列排队。

⑤多级反馈队列调度算法MLFQ可以更好地处理优先级不同的进程，因为它不是简单地按时间片平等地分配CPU时间。MLFQ的多级队列设计允许它对不同类型的进程（如CPU密集型和I/O密集型）进行区分对待，从而更有效地利用资源并提高整体性能。可以动态调整优先级，将计算型的进程提高队列。所以要考虑设计进程在就绪队列之间的迁移条件，这样可以让一些低优先级队列中的进程再返回到高优先级的队列中，避免 P2 队列中的进程长时间处于低优先级得不到较好的调度。如果进程 Q 或 S 在 P2 队列中进行了 I/O 操作，由于 I/O 操作完成后进程的执行特性可能发生变化，通常这类进程更适合在较高优先级队列中尽快得到 CPU 资源以继续执行后续任务。所以当进程 Q 或 S 完成 I/O 操作重新进入就绪状态时，按照迁移条件设定，它们可能会被迁移回 P1 队列进行时间片轮转算法。（2020真题）

⑦关于等待时间的问题：2019年真题，先让P1先进行Q1队列的时间片轮转，此时P2在等P1，然后P1进入Q2队列，P2进行时间片轮转，此时P1在等P2（这一步非常容易忘记，不能忘！！！！），然后继续P1\P2都进入了Q2队列，Q2队列才能调度运行。

### 5.多处理机（多CPU）调度

主要解决两个问题：

（1）第一个是亲和性和负载均衡的概念。

亲和性就是让一个进程只在一个CPU上运行，这样保证Cache效率，不用频繁去内存取数据。

负载均衡就是多个CPU工作的频率是不是近似相等的，不能一个CPU一直空闲，另一个CPU一直忙碌。

（2）第二个问题就是调度的方案，主要针对于多CPU的调度队列

①公共就绪队列：所有进程共享一个队列，队列需要上锁（互斥），防止多个CPU同时抢夺进程，天然的解决了负载均衡，亲和性比较差。软亲和是指尽量让进程在一个CPU上运行，硬亲和是写入PCB，该进程只能由某一个CPU运行。

②私有就绪队列：每个CPU拥有一个私有的队列。天然解决了亲和性的问题。推迁移是系统程序让其他CPU的进程来该负载率低的CPU上运行。拉迁移从超载CPU就绪队列中拉一些进程来我这里运行。推迁移和拉迁移可以并行执行。

### 6.上下文及其切换机制

（1）①上下文切换：操作王道P70

CPU上下文（程序计数器、其它寄存器）保存到PCB→→将PCB移入相应队列→→选择另一个进程，激活更新它的PCB内容→→将PCB的内容恢复到CPU里→→跳转到新进程的PCB中的程序计数器的位置重新执行。

②上下文切换消耗大，可以只有一个寄存器组或者多个寄存器组+指针

③模式切换与上下文切换的区别：模式切换（内核态与用户态）可能前后运行同一进程（什么时候不一样呢，例如进程B需要访问磁盘，从用户态转为内核态进行系统调用，内核发现磁盘忙碌，需要等待时间，所以将告诉CPU调度别的程序来运行，在内核态进行进程调度与切换，在返回用户态后，前后运行的不是同一个进程。），上下文切换（CPU调度和切换）只发生在内核态，前后不同进程。

2. 线程切换和进程切换本质上有区别

②对于同一进程的不同线程切换，只需要更新程序计数器（不同线程执行的进度不一样）、寄存器组（不同线程的现场数据不一样），栈基址寄存器（每个线程拥有独立的栈）。同一进程不同线程切换时，进程的地址空间和页目录没有变化，所以PDBR的内容也不会变化。（2018真题）

③对于同一进程的不同线程切换，页基址寄存器不需要改动，因为同一进程的不同线程共用同一个虚拟地址空间，原有的TLB不会失效。

④要理解栈空间和寄存器组保存信息的差异，寄存器组保存的是一些关键的必要的信息，而栈空间保存一些函数调用和数据信息，线程TCB里买呢保存的有栈指针和栈基址寄存器的数据，指向栈空间。

⑤要理解，在进程中可能会存在进程内部的全局变量，这个全局变量供进程内部所有的线程使用，因此，这些线程在并发执行时，对全局变量的操作要互斥进行。（2016统考真题）

补充：
（1）创建态到就绪态的过程是分配资源、写入PCB的过程，属于高级调度；

3. 互斥性是两个进程在访问临界资源的时候不会冲突，这并不是调度算法考虑的因素
4. 处于临界区的进程在退出临界区之前可以被调度；只不过这个临界资源还是被他占有，等待下一次调度即可；
5. 先来先服务算法有利于CPU繁忙进程、不利于IO繁忙进程
6. 再次体会分时和实时的区别：分时系统讲究交互性、要求时间片轮转；实时系统讲究抢占并尽快处理；
7. 在动态优先级中，随着执行时间的增加，其优先权应该降低

## (三)同步与互斥

### 1.同步于互斥的基本概念

①同步就是确定进程执行的先后顺序；互斥就是间接制约关系，阻止两个进程对同一个临界资源进行访问 。

②临界资源的定义：可以被多个进程访问，但一次只允许一个进程访问。不同进程对临界资源的操作是不同的，所以独立的代码段也就不同，所以一个临界资源的相关临界区是由不同进程的临界区构成的。

进入区（在此区检查能否进入临界区，并设置访问临界区的标志）、临界区（critical section能访问临界资源的代码）、退出区（将正在访问临界区的标志清除）、剩余区（代码的其余部分）

磁盘是共享设备，因为可以并发的访问不同磁盘区域

公用队列是临界资源，只能同时有一个进程访问。

私用数据不满足可以被多个进程访问。

可重入的代码程序是指可以被重复调用执行，不会发生错误，中断后重新执行也不会发生错误的。一次可以被多个进程调用，不属于临界资源。并且可重入代码不允许被任何进程修改。

共享代码必须是可重入的，例如进程映像里的程序、数据、PCB组成，其中共享的程序段可以被必须是可重入代码，并且不允许被修改。

③互斥遵循的原则：空闲让进、忙则等待（已有进程进入临界区，则另一个进程需要等待）、有限等待（对于请求访问的进程，应该让其在有限时间内能够进入临界区）、让权等待（当进程不能进入临界区时，应该释放处理机，这条不一定必须遵循，2020真题）

整型信号量S：用整数表示资源数量。

①wait原语，相当于“进入区”，用while（S<＝0）来检测资源是否可用,若资源数不够，则一直轮询，违反让权等待

②signal原语，相当于“退出区”，用S=S+1来释放资源

记录型信号量：

①不存在忙等现象，即不违反让权等待，原因是因为得不到资源就自我阻塞。

②wait原语，相当于进入区，先将S.value减一，如果S.value＜0，那就调用block原语，（先将资源数减了，然后再判断，所以S.value=0时代表资源刚好够用），让该进程主动放弃CPU，由运行态到阻塞态，并将其插入到该资源的等待队列。

③signal原语，相当于退出区，先将S.value加一，如果此时S.value仍然小于等于0，说明仍然有进程在等待该资源，则从等待队列里面wakeup原语唤醒第一个进程并分配资源。

④请注意，这里面的记录性型信号量S=0时代表仍然有资源可以分配，例如资源数S=1，进程B占用一个资源导致S=0，然后进程A又来申请资源导致S=-1并自我阻塞进入等待资源的队列，此时进程B释放了资源，导致S=0，然后A获得了该资源，用完资源后释放S=1；

信号量实现进程互斥：

①设置互斥信号量mutex为1，然后通过semaphore定义，只要通过它定义，说明这是记录型信号量，不存在忙等的情况，即对进程有阻塞的功能。

②申请资源使用P（mutex），释放资源使用V（mutex），必须成对出现。

信号量实现进程同步：

①设置同步信号量S初始值为0，然后通过semaphore定义，只要通过它定义，说明这是记录型信号量，不存在忙等的情况，即对进程有阻塞的功能。

②在前操作之后执行V操作，释放资源。在后操作之前执行P操作，代表取得资源，通过资源来限制执行顺序。这时候是先执行V后执行P，先释放资源，后取得资源。

③同步信号量S初始值不一定必须为0，也可以是一个正整数，取决于期待的那个条件是否已发生例如，初始值为0，期望进程1执行完释放资源后，资源数为1，进程2才能执行。另一种情况，初始值为2，进程1和进程2释放资源后，达到四个资源时，进程3才能执行。

信号量实现前驱关系：

①相当于对进程执行顺序做了限制。如果有多个进程、多个需要限制的执行顺序，那么就需要多个信号量，每个信号量初始值都为0，第一个执行的进程先执行V操作，释放资源，随后第二个进程可以获得该资源，执行P操作，再释放另一个资源（V操作），推动下一个进程执行。

### 5.条件变量（管程）

管程存在的必要性：①由于资源种类比较多，程序员自行安排PV操作容易死锁，提出管程自动实现进程互斥，降低死锁可能性。

②帮助实现进程同步和互斥问题（2016真题）

管程的组成结构：

①名称name

②管程内部的共享数据结构（对应着共享的资源）资源S

③对该数据结构定义的操作函数take_away（），back_away（）

④对共享数据设置的初始值语句 init_source=5

管程的特性：

①将操作函数封装到管程里面（就好像Java的类），外部进程只能调用操作函数来实现对资源的获取和释放。

②每次只允许一个进程使用管程，天然实现互斥。

③管程内的数据只能被管程内的操作函数来修改。

④管程是被进程调用的：进程通过调用管程中定义的操作来访问共享资源。

⑤管程是语法范围：管程是通过编程语言的语法定义的，是一种语言级别的抽象。

⑥无法创建和撤销：管程的生命周期与程序的生命周期一致，不能在运行时动态创建或销毁。

条件变量的定义：

①本质就是进程进入管程后被阻塞，将该进程被阻塞的原因定义为条件变量。

②不同进程被阻塞的原因可能不同，所以有多个条件变量。

③每个条件变量都保存一个等待队列，如果因为该原因被阻塞的进程，就会被插入到该条件1变量的等待队列

④如果资源不够，则执行x.wait，看清楚是先判断资源是否够数，才执行x.wait操作。如果资源够了，则执行x.signal唤醒该等待队列的进程，这里的x代表条件变量，即可被阻塞的原因。

条件变量和信号量的区别：

①操作函数类似，都可以实现进程的阻塞和唤醒。

②信号量有值，代表资源数；条件变量没有值，只实现排队等待和唤醒功能，管程里面的资源数用共享数据结构记录。

③管程的signal操作和信号量的V操作还是有所不同的，V操作一定会引起信号量的改变，signal操作可能不会产生任何影响（这是指在没有进程因为条件变量而阻塞的情况下）。

## (四)死锁

### 1.死锁的基本概念

死锁的定义（互相循环等待+各个进程都被阻塞）

死锁、饥饿、死循环的区别：

①发生饥饿的进程可以只有一个，死锁进程必然≥2个

②饥饿进程可能在等CPU（就绪态）或者其它资源（阻塞态，即获得不到其他资源也叫饥饿），而死锁必然等待其他资源（阻塞态）

③死锁和饥饿是操作系统的问题，死循环是程序员写的代码的问题

产生死锁的2条原因：

①系统资源争夺，只有对不可剥夺资源（打印机、磁带机运转过程中不能被其它进程夺走）的竞争才会导致死锁，可剥夺资源（CPU和主存可以被其它进程夺走）不引发死锁。（这里的不可剥夺限制和可剥夺的宾语可以是基本资源、也可以是CPU）

②进程推进顺序非法，例如两个进程需要同样的资源R1和R2，但互相都持有其中一个资源而等待另一个资源，导致互相等待引发死锁。（本质也就是信号量使用不当也会导致死锁）

产生死锁的4条必要条件：

互斥、不可剥夺、请求与保持条件、循环等待条件

（循环等待和死锁的关系是什么，为什么发生循环等待未必导致死锁？死锁因为各种资源在循环互相等待，形成了一个环，环内的任何一个资源得到释放，死锁才会被解除。但是循环等待是可以等待环外的资源，它得到释放后，环也可以被解除，所以循环等待是死锁的必要条件。这相当于是同类资源数大于1，环外没有资源。但如果同类资源数只有1，那么发生了循环等待一定导致死锁。）

即上面这种等待的环外资源释放之后，这个死循环就解除了，所以这并不是一个死锁

死锁处理三大策略内容、优缺点王道的比较表格。

死锁的避免是在进程运行过程中不断调整安全的顺序，所以需要知道未来的资源需求。

死锁预防就是从根本上限制不存在出现死锁的可能性。

### 3.死锁避免

系统安全状态的定义：

系统能根据已有的资源让进程按照任意一种顺序执行下去，并且顺利完成，这这种顺序叫做安全序列，如果系统无法找到一个安全序列，则称系统处于不安全状态。

注意死锁避免和死锁预防的区别，太重要了！！：

死锁避免是设计安全的执行顺序（银行家算法），来避免死锁。死锁预防是指破坏了四个死锁的必要条件。

不安全性状态和死锁的关系？

①不安全性状态可能会导致死锁，也可能不会导致死锁。可能不会导致死锁的原因是进程被提前终止释放了资源，或者进程在执行过程中主动释放了一部分资源，或者实际需要的资源数小于声明的资源数。

②处于安全状态，一定不会发生死锁。

③发生死锁，一定处于不安全状态。

银行家算法：

特点：

①著名的死锁避免算法。

②分配资源前先试探是否会导致系统不安全状态，若不会，则将资源分配给它。

③按照银行家算法，只要保证系统中进城申请的最大资源数小于或等于系统所拥有的m个同类资源，就一定存在一个安全序列。假设n-1个进程各自拥有一个资源，最后一个进程拥有m个资源，所以系统所需要的最大资源数是n+m-1；

数据结构描述：

①可利用资源向量Avaliable：含有m个元素的数组，代表每个元素i，拥有j个可用的资源

②最大需求矩阵Max：描述每个进程对每类资源的最大需求量

③分配矩阵Allocation：描述给每个进程已经分配的每类资源数量

④需求矩阵Need：描述每个进程还需要多少每类资源数量

### 4.死锁检测和解除

死锁检测和避免的区别：

死锁避免需要知道整个生命周期的所有资源请求，死锁检测是检测某个时刻是否发生死锁，只需要知道当前时刻的资源请求。

死锁定理的作用是帮助系统检测死锁的存在。

为什么死锁检测不关心进程运行所需的资源总量信息？死锁检测只检测系统中是否发生死锁，即循环等待的换路，一旦发现，就要采取接触死锁的措施，因此不关心各个进程所运行的资源总量

资源分配图（属于死锁检测）：

①表示方法：大圆圈表示进程，方框表示一类资源，小圆圈表示资源的数量。请求边表示进程申请某类的一个资源（还未得到），分配边表示该类资源已经拿出一个分配给某个进程。

②简化资源分配图：首先找到一个不阻塞也不孤立的进程，让它执行完毕，随后将它所链接的线撤销掉（意为移出去整个系统），紧接着对下一个进程进行同样的操作。如果直到最后还有边相连的进程，即发生了死锁。

死锁解除的三种方法:

①剥夺资源

②撤销进程：可以撤销部分或者撤销全部；可以根据优先级撤销；代价较大

③进程回退法：让死锁进程回退到避免死锁的底部，这个过程中，进程资源释放资源而非被剥夺；另外还要求进程保留历史信息，设置还原点。

# 三、内存管理

## (一)内存管理基础

### 1.内存管理的基本概念

逻辑地址空间与物理地址空间的地址变换，内存共享，内存保护，内存分配与回收

内存管理的定义：

操作系统对内存的划分和动态分配，内存管理的具体机制是透明的，看不见的。

内存管理的五种功能：

①记录已分配的内存空间和空闲空间，回收进程结束后的空间。

②逻辑地址转为物理地址

③虚拟存储技术实现内存扩充

④内存共享，允许多个进程之间访问同一个内存空间

⑤存储保护，防止进程之间干扰各自的内存空间

逻辑地址与物理地址的转换：

编译→链接→装入

程序编译后，将代码的各个部分行程不同的模块，每个模块地址从0开始。

链接时将各个模块链接起来，形成一个新的地址空间从0开始的大模块，对于64位机器，逻辑地址为064～1，这就叫逻辑地址空间。

操作系统通过MMU部件将逻辑地址转为物理地址的过程称为地址重定位。

用户源程序到内存中可执行程序的过程：

①编译：将代码各个部分编译成若干目标模块

②链接：将目标模块链接起来，链接之后形成最终的逻辑地址

③装入：由装入程序将装入模块装入内存运行

三种链接方式：

①装入内存前静态链接：多个目标模块和库函数链接成一个完整装入模块。需要修改模块内相对地址，变换外部调用符号（函数），将每个模块所用的外部调用符号（函数）都变换成相对地址，以便在内存中被调换位置时，还可以通过相对地址正确调用函数。

②装入时动态链接：边装入边链接（需要用到模块时才将他调入内存并链接），便于修改和更新（链接前单独的模块的大小比较小，便于程序员修改，链接后模块较大也不利于解析并重构修改）、便于对目标模块实现共享（模块小，在内存中调入一个start.so文件模块，就可以供很多文件共享链接）

③运行时动态链接：边运行边链接，运行时才进行链接，加快了程序的装入过程，节省内存。链接过程快，但是执行效率低。（分段存储管理有利于动态链接，方便把不同的段放入磁盘，需要哪个段才引入哪个段）（页式虚拟存储的程序是在运行时动态链接的，因为在运行时需要什么页面才把页面调入内存）

三种装入方式：

①绝对装入：单道程序环境，逻辑地址=物理地址，程序员写程序时就固定了绝对地址，编译汇编时期就绑定了运行时的地址。

②可重定位装入（静态重定位）：多道程序环境分区存储，分配完整的连续全部内存空间，否则不装入，装入后固定位置不移动，只要简单的加法器就能实现静态重定位。（页式存储方式就不适合静态重定位，因为页式不连续而且内存位置动态变化）

③动态运行时装入（动态重定位）：装入内存后程序地址仍为相对地址，需要重定位寄存器帮忙，运行时才转为绝对地址。优点是：分配不连续的内存空间、动态申请空间、部分代码调入即可运行、便于程序段的共享。（动态重定位不依赖目标程序是指完全由操作系统和硬件组成，地址转换过程是透明的，地址重定位只依赖于基址寄存器、可重定位装入程序、重定位寄存器、地址变换机构MMU。）

重定位寄存器如何帮忙实现装入内存后程序地址仍为相对地址？

重定位寄存器保存的是进程的基地址，整个系统中只有一个重定位寄存器，每次切换进程时，顺带切换重定位寄存器的值即可。

为什么不仅仅使用加法器就行，还要去使用MMU，它有什么额外的功能吗？

MMU在加法器的基础上还实现了其他功能

进程的内存映象五个要素：

①代码段：只读文件，可被多个进程共享（调入内存就确定了大小）

②数据段：全局变量和静态变量（调入内存就确定了大小）

③PCB：存放在系统区

④堆：动态分配的变量，malloc函数向高地址空间分配（内存空间动态变化）

⑤栈：函数调用，从最大地址向低地址增长（内存空间动态变化）

内存保护 （防止越界访问，需要操作系统（负责制定保护规则）和硬件（负责执行和检测，例如MMU\页表基址寄存器、异常中断硬件，发生越界了就需要中断处理）共同实现）：

①上下限寄存器，存放进程在内存中的上下限地址，CPU判断进程访问地址是否越界。

②第二种方式是界地址寄存器+重定位寄存器，首先进程给出相对地址，与界地址寄存器（存放的进程最大逻辑地址，也是进程的最大长度）比较，不超过后，才能与重定位寄存器（存放的是进程的首地址）相加，得到物理地址。（重定位寄存器也叫基址寄存器，界地址寄存器也叫限长寄存器）

内存共享：

①只读区域才可共享

②可重入代码：纯代码、允许同时访问但是不允许任何修改，给每个进程配备了局部的数据区，存储可能临时修改的数据

内存分配与回收：

单一连续分配（单道程序，独享内存，内存利用率低）进化为固定分区分配（多道程序，内部碎片，分区固定，无法容纳更大的程序）

固定分区分配进化为动态分区分配（多道程序，外部碎片，根据内存动态分配空间，管理复杂）

连续分配（单一连续、固定分区、动态分区）进化为离散分配（段、页、段页结合）

外部碎片的回收可以通过紧凑技术实现，将每个进程向低地址空间移动，在高地址空间省出大量连续空间。但是需要动态重定位寄存器（界和限寄存器），移动费力，大量耗时。

### 3.页式管理

（引入页式存储器目的是实现离散分配和提高内存利用率）

一些基本概念：

①物理空间和逻辑空间都被划分成大小相等的页（页面），因此分页管理不产生外部碎片。（分页是由操作系统完成的，大小一定是固定不变的）

②主存空间中的页（也叫物理页、实页、页框），对每个实页进行编号叫页框号（物理块号）

③虚拟地址空间中的页（也叫虚拟页、虚页），对每个虚页进行编号叫页号

④页面大小最好是2的整数次幂，页面太小会导致页表太长、占用内存、增加硬件地址转换开销、降低页面换入换出的效率，页面过大导致页内碎片增多，降低内存的利用率。

⑤通过硬件实现，对用户完全透明（包括页号和页内偏移，都是透明的）

⑥页面在物理内存中只能从页面大小的整数倍地址开始存放！！

分页逻辑地址结构：

页号P＋页内偏移量

页表（页面映射表）：

①每个进程一个页表，这个页表驻留在内存中，轮到哪个进程执行了，进程PCB里的页表起始地址和页表长度装入页表寄存器。

为什么页表需要常驻内存？

让页表常驻内存可以加快虚实地址转换，因为CPU去找这个虚拟地址对应的物理地址，就在内存中，直接完成地址转换，顶级页表、二级页表都是通常情况下常驻内存，但是也可能会被调出到磁盘里面，等到地址转换的时候发现页表不在了，会触发中断，把页表调入内存然后执行即可。

逻辑页号与物理块号的映射关系

在页表中，页号（页号就是虚拟页号！！）按照顺序，所以是隐含的，可以不占用存储空间。

分页基本地址变换机构：

①CPU给出逻辑地址拆分成页号P和页内偏移量W

②首先要进行越界检测，检测页号是否大于页表长度，若是，进入越界中断（异常）。

③将逻辑页号加上页表起始地址F去找页表中的映射表。

④物理页号加上页内偏移地址=物理地址

注意点：
①在多道程序并发执行时，进程的页表大多数存留在内存中，被长期阻塞的进程的页表可能会被调出到磁盘中，单CPU系统只有一个页表寄存器PTR（意思是多CPU中有多个PTR，PTR当中存放的是页表的物理起始地址），在进程未被执行时，起始地址和页表长度存放在PCB中，运行时页表的起始地址存放在页表寄存器PTR当中（利用寄存器可以加快转换速度）

②查询页表的这一过程是由硬件MMU来完成的，界比较、拼接、表项比较

页表项的大小：

①页表项的目的是找到该页在内存中的位置。

②页表项仅仅存储物理块号，由于物理块号与内存大小息息相关，以32位内存地址空间为例，代表内存大小为232B，一页是4KB大小，那么就会有232B/4KB=220页，所以需要20位才能容纳一个物理页号的地址，同时由于内存是以字节为单位，所以页表项的大小大于等于3B。

分页管理存在的两大问题以及相应的解决方案？

主要是地址转换效率和页表大小两个问题

①每次进行地址转换都要在内存的页表中逐个查找对应的页表项，如果页表多，页表项多，查询效率较慢。（引入快表）

②如果逻辑空间较大，则页表项的数量较大，导致页表所占内存特别大（页表还必须连续存放，显然占这么大的空间不现实），有时候也没必要把进程的所有页表全都导入内存，影响内存利用率，也增大了系统开销开销。（引入二级页表）

具有快表的地址变换机构：

概念：

①若页表全部在内存里，则取数据或指令需要一次或者两次访存，首先访问CPU中的快表，取出数据或指令的物理地址，然后是根据物理地址从内存中取出数据或指令

②快表存放在相联存储器。

③地址变换机构有了新的进步，即现在快表中查询是否有命中，有命中则直接取出物理地址，然后访存一次取出数据或者指令。若不命中，则再去内存的页表中找，取出数据，访存两次，并且把页表项（而非页表）调入快表。

④快表的命中率一般在90%以上，利用了局部性原理。

为什么提高页面大小可以提高快表的命中率？提高页面大小可以减少页表项，从而让一定容量的快表中覆盖更多的页表项，另外采用多级页表改变不了快表的命中率

两级页表：

解决上述问题的方法有两种，一种是引进二级页表（相当于建立索引），一种是引进虚拟内存技术（将需要的页表导入内存，不需要的页表放在磁盘中。）

下列方法是二级页表，即把页表项也存入一个页表，把不同的页表的页表项整理成一个顶级页表，从顶级页表中去找想要的页表项的页表。

地址转换过程：

①在系统中增设外层页表寄存器（也叫页目录基址寄存器）（一旦出现页目录号，就说明一定是多级页面存储方式！！！！2018真题）存放顶级页表的物理地址。

②通过页目录基址寄存器中的起始物理地址，根据一级页号，在顶级页表中找到对应的二级页表的页表起始物理地址。

③通过二级页表的起始物理地址地址，根据二级页号，对应找到物理页号映射关系。

④通过物理页号（实质上还是一个物理地址，只不过每隔4KB进行一次编号）在内存中找到对应数据或指令。

两级页表的计算问题：

【例】页式存储管理系统，逻辑地址空间256TB，页表项大小为8B,页面大小为4KB，该系统应该采用几级页表？

主存以字节为存储单元，256TB=248个存储单元，页面大小为4KB，即一个页面需要212个存储单元，共有236个存储页面，一个页面可以存储29个页表项，则共需236/29=4级页表。

### 4.段式管理

一些基本概念：

①一个进程只分配一个段表（分清楚段表和段表项的概念，每个段拥有一个段表项，所有段表项构成一个大的段表）

②段内要求连续，段间不连续，进程的地址空间是二维的（段号，段内偏移）。

③分段对低级语言程序员和编译程序都不透明，他们都知道分段的逻辑关系，低级语言程序中段号和段内偏移都由用户提供，高级语言程序由编译程序完成。

④段号和段内偏移量由用户显式提供（在高级语言编程中，由编译程序给出段号，程序员通常不知道如何分段）

⑤用户编程时（汇编语言）决定的如何分段

⑥分段也便于动态链接和动态增长

引入段式存储的目的是满足用户的需求，哪些需求？方便编程、分段共享、分段保护、动态链接和增长。程序运行时动态链接共享库的代码段，而非编译时静态绑定，减少内存占用并支持库的独立更新，递归函数调用导致栈空间不足时，操作系统自动扩展栈段。（实现离散分配并不是分段的目的，而是分页的目的。）

逻辑地址结构：

段号S+段内偏移量W

段表：

段号+段长+本段在主存的起始地址（段表项连续存放，所以段号可省略）

分段基本地址变换机构：

①系统设立了一个段表寄存器，记录段表的起始物理地址

②首先取出段号，与段表长度进行比较，若不越界，则根据段表起始地址＋段号找到对应段表项。

③根据段表项找到段长和物理起始地址，再加上段内偏移量得到最后的物理地址。

2009真题，我自己搞错了概念，一旦有地址长度32位，这表示逻辑地址和物理地址的长度，与段表的段表项长度无关。所以逻辑地址总长32位=段号+段内偏移，段号占8位，段内偏移最大值就等于最大段长

分段与分页的对比：

①页是物理单位，是为了提高内存利用率的系统行为；段是逻辑单位，满足用户需求的用户行为。

②页长固定（系统决定）和段长不固定（代码决定）

③分页管理地址是一维的，分段管理地址是二维的。

段的共享：

①页也可以实现共享，但是实现过程极其复杂，因为页表有可能被分散在内存的不同区域，联构起来比较麻烦。

②段内连续，所以可以按照段进行共享，例如共享代码段。

③系统配置共享段表（实现多个进程共享一段代码或一段数据），不同进程使用共享段表中同一个段表项，这个段表中的段表项，指的是某个代码段、数据段（2019真题）

④某个段被不同进程共享，在进程的段表中是不具有相同的段号的（他们的段号是没有任何联系的）（2019真题）

| 段号 | 段长 | 内存始址 | 状态位 | 外存始址 | 共享进程数 |
| --- | --- | --- | --- | --- | --- |
|  |  |  |  | 共享段未被加载到内存，记录其磁盘地址 | 记录多少个进程共享。当count=0时，回收内存。 |

段的保护：

①段共享时，共享的代码都是可重入代码（不能被任何进程修改），所以每个进程必须配备局部数据区，便于进程修改数据。段共享时配置的是共享段表

②存取控制保护。

③地址越界，需要检测两方面。一方面是检测段号是否大于段表长度，另一方面是检测段内偏移是否大于段长。（页内偏移是不可能大于页长的，因为页内偏移位数最大就等于页长）

### 5.段页式管理

一些基本概念：

①先分段，再分页。

②每个进程一张段表，每个段一张页表（因此段页式管理每个进程可能有多个页表）（页表、段表与上述知识相同）

③系统含有一个段表寄存器（指出段表起始地址和段表长度）

④单独采用分页和分段管理，提供给用户的物理地址空间要减去页表和段表占的空间，因为段表和页表所占空间是不能确定的，所以提供的用户物理空间大小也就不能确定。

为什么段页式分区管理会产生内部碎片？如果一个段是5KB，一个页是4KB，那么就需要给这个段分两个页，那么就会有页内的内部碎片3KB。

逻辑地址：

段号S+页号P+页内偏移量W（段号可隐含）

段页式基础地址转换：

①首先通过逻辑地址分出段号S，先进行越界判断，若无越界，则与段表起始地址相加得到段号，根据段号再段表中找到页表长度和页表起始地址。

②取出逻辑地址中的页号+页表起始地址=逻辑页号的地址，找到物理块号的映射关系，物理块号+页内偏移量=物理地址

## (二)虚拟存储管理

### 1.虚拟内存基本概念

（内存空间扩充有三大技术：覆盖、交换和虚拟内存）

1.传统存储方式的两大特征

①一次性：0 限制不能让大量作业同时运行，并发度下降。

②驻留性：装入内存，如何部分都不会被换出，作业进程结束才调出，甚至遇到IO阻塞也不会调出内存

2.局部性原理

快表、页高速缓存、虚拟内存技术都属于高速缓存技术，他们都依赖了局部性原理

①时间局部性：之前用到的数据马上要再使用，例如循环操作i=i+1

②空间局部性：下一个使用的数据与该数据空间相邻，例如数组，直接从相邻的缓存中取出数据

局部性原理和高速缓存技术有什么联系？时间局部性将近来、使用的指令和数据保存在高速缓冲中，空间局部性是将数组预取机制，需要更大的缓存器

虚拟存储器的三大特征：

①多次性：分多次将页面调入内存

②对换性：不用的页面调出内存

③虚拟性：逻辑上扩充了内存

虚拟存储器的容量大小：

进程的虚拟地址空间寻址由系统的地址结构决定，这决定了虚拟存储器的最大容量，与内存和外存容量无关，若磁盘空间无限大，作业也不能拥有任意大的编制空间，因为受限于硬件设施，比如CPU地址总线位数

虚拟内存的实现方式与技术支持：

实现方式有请求分页存储管理、请求分段存储管理、请求段页存储管理（自己犯了误区，以为只有请求分页存储管理）

技术支持硬件：

①一定容量的内存和外存（ROM和RAM，磁盘）

②页表机制（段表机制），作为数据结构，MMU+寄存器的硬件支持

③中断机构：缺页中断机构硬件（因为是由硬件检测到缺页中断信号、触发缺页中断机制）支持

④地址变换机构：逻辑变物理，地址变换机构MMU硬件

⑤查询快表，快表TLB本身也是硬件

⑥查询页表，先要找到页表的初始地址（存放在页表基址寄存器、段表基址寄存器中，这也是硬件）

### 2.请求页式管理

请求分页系统=基本分页系统+请求调页（外存调入内存）+页面置换（内外存页面调换）

请求页式管理和基本页式管理有什么区别？基本分页是静态、简单的内存管理方案，适合资源受限或实时性要求高的场景，但牺牲了内存灵活性和利用率。请求分页通过按需加载和虚拟内存机制，实现了动态内存分配和高资源利用率，是现代操作系统的基石，尽管引入了缺页中断的开销。

页表机制

请求分页系统的页表项结构：

| 逻辑页号 | 物理块号 | 状态位P | 访问字段 | 修改位M | 外存地址 |
| --- | --- | --- | --- | --- | --- |
|  |  | 是否调入内存 | 访问次数、最近已经多长时间未被访问 | 是否被修改，决定是否写会外存 | 通常是物理块号（磁盘标识） |

页表机制里面已经有了物理块号，为什么还要专门设置一个外存地址数据？页表中的物理块号是内存的划分单元，该数据存在与否，取决于页面是否在内存中。当页面不在时，就需要外存地址来找到它，这样在发生缺页中断时，操作系统才能从正确的磁盘位置调入页面。

缺页中断机构：

①页面不在内存，触发缺页中断，由操作系统的缺页中断处理程序处理，缺页进程阻塞，进入阻塞态，页面调入内存后唤醒，进入就绪态。

②若内存中有空闲页框，则直接调入内存。没有空闲页框，根据置换算法选择一个页面调出，并根据是否修改过来写回外存。

③需要保护CPU环境、分析中断原因转入中断处理程序、恢复CPU环境等步骤

④指令执行过程中发生缺页中断，属于内部异常（内中断），一次指令执行过程中可能发生多次缺页中断

地址变换机构：

在基本分页系统的基础上，增加产生和处理中断、页面置换的功能

主要过程如下：

①MMU检测是越界

②访问CPU中的快表看是否命中

②若快表未命中，则访问页表，若页表命中，取出物理地址同时将页表项写入快表。

③若页表也未命中，则进行缺页中断处理（保护CPU现场、在外存中找到缺页、内存若满了则执行页面置换算法、原页面被修改了则写回外存、OS命令CPU从外存中读入缺页、启动IO硬件、换入成功），操作系统更新页表和快表。

④物理地址=物理块号*物理页面大小+页内地址

### 3.页框分配

驻留集的定义：

给一个进程分配的页框的集合叫做驻留集。
而进程某段时间t间隔内，进程实际访问的页面的集合被称作它的工作集（若工作集窗口大小为6，则过去的t时刻的工作集集合包涵过去的六个页面，且包含重复的，不需要因为页面重复而再往前推进若干个不重复的页面）。

理想情况下，驻留集要包含工作集，这样回有效避免缺页，但是实际情况下，工作集并不是驻留集的子集，有可能工作集需要的页面没有在驻留集内，这就发生了缺页，也有可能驻留集的部分页面不是工作集所需要的页面。

驻留集太大，内存浪费，并发度下降；驻留集太小，驻留在内存中的进程会更多，但缺页率高，消耗大量CPU时间来处理缺页。缺页时，内存中可能有空闲页框，直接调入内存新的页面，不需要淘汰旧的页面

内存分配策略：

| 固定分配+局部置换： ①分配固定数量的物理块 ②从进程内部的页面换入换出 缺点是：难以确定固定数量的物理块，太少太多都不行。 | 固定分配+全局置换 全局置换意味着进程的物理块数必然改变，故该方案不存在！ |
| --- | --- |
| 可变分配+局部置换 ①先分配固定数量物理块，若发生频繁缺页，则再次为其分配物理块，直至缺页率正常。若几乎不发生缺页，也可以剥夺部分物理块。 ②从进程内部换入换出 优点是：保证了并发能力，不会过多的调页。 缺点是：实现复杂，开销大。 | 可变分配+全局置换 ①先分配一定数量物理块，根据情况可以增加或减少。 ②从全局的空闲物理块（不管是否已经被分配出去了）中选一个分配给进程。 优点是：比较灵活，动态增加进程的物理块。 缺点是：可能会盲目给进程增加物理块，导致并发度下降。 |

局部淘汰策略：

只考虑当前进程所拥有的页面，即只在当前进程的合法驻留集（或称为工作集）中进行页面置换。（2009真题）

采用固定分配策略的物理块分配算法：

①平均分配

②按进程大小比例分配

③按进程优先级分配。

有时候也会采用一部分按比例分配，一部分按优先级分配

页面调入的时机：

①预调页策略（进程运行前调入）：预测未来可能被调入内存的页面，主要用于首次调入，可以调入多页，程序员指出应该先调入哪些页。

②请求调页策略（进程运行中调入）：其实就是中断后，调入页面，一次调入一页，增加了磁盘开销。

从何处调入页面：
请求分页系统的外存分为两部分（对换区的磁盘IO速度更快）

①文件区-存放文件-离散分配方式

②对换区-存放兑换页面-连续分配方式

系统调入缺页就有以下三种情况：

①拥有足够的对换区：将整个文件全都复制到对换区，提高调页速度

②缺少足够的对换区：凡是不会被修改的文件都从文件区调入，换出时因为没有修改所以不必写回外存。有可能修改的部分必须从对换区调入调出，因为读的速度比写的快，利用对换区的速度提高平衡一下写的速度。

③UNIX：进程有关的文件放在文件区，曾经运行过但又被换出的页面，放在对换区。进程请求的共享页面若被其他进程调入内存，则不需要再从对换区调入。

如何调入页面：

是由缺页中断处理程序执行的，查找页表得到该页的物理块

### 5.页框回收

页面缓冲算法：

影响页面换入换出效率的因素：

①页面置换算法，低缺页率，减少换入换出的开销

②将已经修改过的页面写回磁盘的频率，写速度太慢，影响速度

③将磁盘内容读入内存的频率。越低越好

页面缓冲算法=页面置换算法+已修改页面链表。

两种链表：

①空闲页面链表：读入一个页面，取出该链表的第一个页框并装入该页。当一个未被修改过的页面被换出时，实际上是将该页面所在的页框挂到空闲链表的表尾。（这些空闲链表中可能存在部分数据，当进程需要是，可直接读走，避免去磁盘读，减少页面开销）

②修改页面链表：将已修改的、需要写会磁盘的页面排成链表，达到一定数量，一起换出，减少页面换出开销。显著降低了页面换入换出的频率，磁盘IO开销减少。

（为什么页缓冲队列长度不影响缺页率，而会影响页面置换的速度？置换操作包括淘汰一个页面、将它写回磁盘，以及从磁盘加载新的页面。如果页缓冲队列长度较短，则会被更快的写回到磁盘中，使用时间比较长，但是里如果队列长度比较长，我可以等一等再一块写回磁盘，2022年真题）

页框回收：

①并非所有页框都可回收，内核页框大部分都不能回收

②系统中设定一个守护进程kswapd，当页框数低于某个阈值，就要启动进程回收页框。

③将物理页面换出的过程即为页框的回收。要区分页面置换和页框回收的区别，前者是磁盘和内存页面的互换，后者是将页面写会磁盘，腾出页框空间。
④回收页框也会进行空闲页框的合并操作

为什么空闲页框数不能为0？因为内核可能需要请求空闲页框，若不能满足要求，会导致系统崩溃。

### 6.内存映射文件(Memory-Mapped Files)

内存映射文件的定义和概念：

①是操作系统给应用进程的一个系统调用，是磁盘文件部分或全部与其他虚拟空间之间建立映射关系，也是可以在内存中直接修改文件内容。

②只是建立了一个映射关系，程序员相当于把文件看成了大的数组，根据逻辑地址来对文件进行访问，而磁盘的读写由OS完成，对进程来说是透明的。

③映射文件时，不会读入文件的页面，只有需要访问时，才把该页读入内存，关闭文件后，OS才把修改的页面写会磁盘。

④各进程对于该文件的虚拟地址都是相互独立的，没有什么关联

内存映射的两条好处：

①程序员编程方便

②多个进程共享文件（文件页面的修改也会被同步看得见）

### 7.虚拟存储器性能的影响因素及改进方式

分页系统性能的影响因素分析（缺页率受页面大小、分配给进程的物理块数、页面置换算法、写回磁盘的频率、程序的局部化程度）

缺页率是主要因素：缺页率大，性能差，而缺页率又受到页面大小、分配给进程的物理块数、页面置换算法以及程序编制方式的影响。

①页面大小

②分配给进程的物理块数

③页面置换算法

④写回磁盘的频率（所以搭建了一个暂时存放不写回磁盘的链表）

⑤程序编制方式：如若数组按行存储，就要按行访问，否则缺页率高。

2.文件控制块和索引节点

文件控制块：

①一个文件拥有一个FCB，一个FCB就是一个文件目录项，文件目录项的有序集合就叫文件目录。（这里需要说明，FCB方案和索引节点方案时两个不同的文件系统采取的方案。第一种是FCB当做文件目录项，第二种是文件名+索引编号=文件目录项）

②一个文件目录也被视为一个文件，称作目录文件。

③典型FCB示例：

| 基本信息 | 文件名 |
| --- | --- |
|  | 物理位置 |
|  | 逻辑结构 |
|  | 物理结构 |
|  | 类型 |
|  | 文件大小 |
| 存取控制信息 | 文件权限（分为文件主、核准用户是指除了文件主之外的合法用户，一般用户） |
| 使用信息 | 文件数据块指针 |
|  | 文件建立时间 |
|  | 上次修改时间 |

FCB属于目录项，必须连续存放

FCB通过文件名和物理地址之间建立映射关系

索引节点：

查找文件目录的过程：

先将存放目录文件的第一个盘块中的目录项调入内存，用给定的文件名与文件目录项逐个比较，若未找到，则调入下一个盘块的目录项。

以上过程只用到了文件名，故而引入了文件名与文件信息分离的方法。让文件索引信息成为一个称为索引节点的数据结构，每个文件目录项仅由文件名和索引节点号（指针）构成。

索引节点与文件容量计算问题：

理解将FCB看作目录项升级为将索引看作目录项的内存优化。索引节点是对文件控制块的优化，极大节省系统开销，把文件控制块的冗余信息放到索引节点里，在目录项中只留下索引节点指针

①索引节点的个数：其实本质就是文件的个数，但2020年出的题具有迷惑性（2020真题），并且索引节点个数与单个文件长度无关（2013真题）。

磁盘索引节点（存放在磁盘里）：

每个文件有唯一的磁盘索引节点，下列是结构状态

| 主标识符 | 拥有该文件的个人或小组ID |
| --- | --- |
| 文件类型 | 普通文件、目录文件、特别文件 |
| 文件存取权限 | 对各类用户的存取权限，不同用户的权限是不同的，可以用ACL表来存储。 |
| 文件物理地址 | 每个索引节点含有13个地址项，iaddr0～iaddr12，他们以直接或者间接方式。 |
| 文件长度 | 以字节为单位的长度 |
| 文件链接计数 | 系统中所有指向改文件的指针计数 |
| 文件存取时间 | 本文件最近被进程存取、修改的时间、索引节点最近被修改的时间 |
| 索引结构 | 记录了文件存储的磁盘块的位置信息的组织形式（读清楚是位置信息的组织形式，而不是位置信息数据）。它可以是连续分配、隐式链接、显式链接、单级索引、多级索引、混合索引等。 |

为什么要有文件链接计数？链接计数记录了一个文件被多少个目录项直接指向，创建文件时仅自身文件名指向它，其链接计数为1，当该数为0时，文件系统会将该文件从磁盘中释放。通过增加硬链接，即使原始文件被删除，仍可通过其他链接访问数据。不同用户通过硬链接指向同一份数据，避免复制文件，节省存储空间，并确保数据一致性。

内存索引节点（存在内存里）：

文件被打开时，需要将磁盘索引节点复制一份到内存的索引节点。

增加了以下内容：

| 索引节点号 | 标识内存索引节点 |
| --- | --- |
| 状态 | 指示该索引节点是否被上锁或修改 |
| 访问计数 | 每当有新的进程访问该节点，则+1 |
| 逻辑设备号 | 磁盘被划为不同的文件分区，每个分区是不同的文件系统，标记逻辑号来区分不同的文件系统，用于指明该文件所在的存储设备如硬盘分区、U盘、网络存储等 |
| 链接指针 | 设置分别指向空闲链表（内存空闲区域）和散列队列（加速查找文件或目录）的指针 |

系统注册表：

系统注册表（System Registry）是Windows操作系统特有的一个核心数据库，用于存储系统和应用程序的配置信息。它是Windows操作系统的"中央信息仓库"。（2009真题）

3.文件的操作：建立，删除，打开，关闭，读，写

文件的基本操作：

①创建文件：分配外存、创建目录项

②删除文件：根据文件名查找目录，删除目录项和FCB控制块，回收内存空间和磁盘空间

③读文件：根据文件名查找目录，读出文件在外存中的地址，在目录项中还有一个指针用于对文件进行读操作。

④写文件：根据文件名查找目录，使用写指针对文件进行写操作。

文件的打开：

①首次打开文件时，先利用系统调用open（）将该文件打开（这个括号里传输的是文件的路径名，对于不同路径，打开的文件实体可能是一样的，因为存在硬链接），系统文件维护一个打开文件表，打开的意思是系统检索到指定文件的目录项后，将该目录项从外存复制到内存的打开文件表的表目里（这就是打开的过程，而查找该目录项的过程并不是文件打开的过程），并将改表目的索引号（文件描述符）返还给用户（不同进程对同一文件操作得到的文件描述符是不同的）。以后系统便可以通过文件描述符（文件句柄）对文件进行操作，而不是通过文件名操作（多年考点）

②在多个进程可以同时打开文件的操作系统中，包涵两个表：整个系统表（存储与进程无关的信息，例如文件大小、磁盘位置、访问日期）和每个进程表（进程对文件的使用信息，当前文件的读写指针、文件访问权限、指向系统表中适当条目的指针）。

③系统打开文件表记录所有被打开的文件目录项信息，包括一个打开计数器。用户打开文件表只记录该进程打开的文件，并且映射索引到系统打开文件表当中的目录项上。

④读写指针是操作系统内核为每个打开的文件描述符维护的一个整数值，表示下一次读写操作的起始位置，不同进程对于同一文件的读写指针位置是不同的

⑤对于用户打开表，open一次，就会有一条表目，因为里面记录了偏移量，防止不同进程发生读文件的错乱。对于系统打开表，open一次，只会建立唯一的表目

⑥open操作不一定会导致文件IO操作，当文件已经被打开时，就不需要在从磁盘输入文件的元数据，因此也就不一定在系统文件打开表中增加一个新的表目

⑦每个打开文件都需要文件指针、文件打开计数、文件磁盘位置、访问权限，具体为什么请自己分析。

文件的关闭：

①当某个进程不再使用该文件，先将文件的控制信息写回磁盘，则从该进程的文件打开表中删除对应条目，并且在系统打开文件表中的打开计数器-1，直到打开计数器为0时，在系统打开文件表中删除该条目。

文件的删除：

①删除文件的FCB（或者是采用索引节点文件系统的话，需要删除索引节点）

②删除文件的目录项（有可能是FCB+其他信息，也有可能是文件名+索引编号），记得是删除文件所在的目录项，而不是所在的目录，因为该目录还存在着其它文件。（2013真题）

③删除文件内容，释放磁盘空间。

文件的读操作：

①由于open文件打开了，所以以后对该文件的操作就是通过文件描述符进行对文件从IO磁盘读入内存了。

文件的写操作：

①不一定在文件关闭时才写入磁盘，在其他情况下，内核会要求写回。

②要注意题目条件，“文件第x条逻辑记录完成修改后，共启动了磁盘几次”，这时候要加上将记录写会磁盘的这一次磁盘IO操作。

设置文件读/写位置：
这个本身也是文件的一种操作方式，避免每次打开文件都从头进行读或写，通过这个操作可实现文件内容的随机存取

③文件的关闭过程（关闭文件不等于写文件，关闭文件只需要把未能的控制信息从内存写回磁盘）

4.文件保护

文件访问类型：

①读写

②执行：文件装入内存并执行

③添加：将新信息添加到文件结尾部分

④删除

⑤列表清单：列出文件名和文件属性

⑥文件重命名：高层功能通过系统程序调用底层系统调用实现

⑦文件复制、打印：通过读请求来完成

⑧文件编辑

①防止系统故障导致文件受损，所以采用备份方式。

②若进入系统时，不同用户需要进行登陆注册，那么该级别是系统级的。

写模式和添加模式有什么区别？

写模式：打开文件时会立即清空文件内容，将文件大小截断为0字节。即使后续没有写入任何数据，原内容也会永久丢失。添加模式：保留文件原有内容，文件指针初始位置位于文件末尾，新写入的数据会自动追加到现有内容之后

访问控制（文件访问权限等于=用户访问权限+文件属性，而不是用户优先级）：

（1）第一种方法是ACL（Acess control list）

实现方法是根据用户身份，为每个文件和目录增加了访问控制列表ACL，来规定每个用户以及访问权限。缺点是长度无法预计，可能导致复杂的空间管理。

下列是精简的访问控制表结构

| 拥有者 | 创建文件的用户 |
| --- | --- |
| 组 | 一组需要共享文件且具有类似访问的用户 |
| 其它 | 系统内的其它用户 |

这个文件权限不能用两位数二进制数代表4种用户，用2位二进制数代表4种访问权限。而是应该建立一个二维表格写清楚每种用户的每种权限的01状况，即不能认为一种用户只能有一个权限，而是它可以拥有多个权限，针对不同的权限，都要不同存储（2017真题）

（1）第二种方法是口令
在用户创建文件时提供一个口令存储在FCB里面，同时告知可以访问该文件的用户，通过口令来访问文件。缺点是不够安全，存储在系统里可能被盗取。

（2）第三种方法是密码

对文件进行加密，访问时需要密钥，保密性强，节省了存储空间，编码和译码需要一定时间。下面两种方法都是防止文件被窃取，并没有限制用户对文件的访问类型。

（3）存取控制矩阵

优点是对用户和文件权限关系记录的非常清晰，但是占用太多存储空间，它也只起到记录权限作用没办法保证文件系统不受损。

5.文件的逻辑结构

文件逻辑结构和物理结构的区别？

文件逻辑结构时用户角度看到文件的组织形式，即数据是如何被组织起来的。物理结构是文件存储在外存的存储组织形式，用户看不见。

无结构文件：

流式文件，字符流构成。

有结构文件：

定义：有一个以上记录构成的文件，根据记录长短，可分为定长和变长。

①变长记录：记录长度不同，检索只能顺序查找，很慢。

②定长记录：检索速度快，相同字节数为一个记录，记录在文件的同一列位置。

③记录成组分解技术，就是一条记录无法填满磁盘块，那就多条记录填充磁盘块，若剩余空间无法填入一个完整的记录，那就空出来或者填充指针之类的。如果一条记录超过了磁盘块的大小，那就多用几个磁盘块来存储该记录。

1. 顺序文件
   ①可定长可变长
   ②串结构（记录顺序与关键字无关，而与记录时间顺序有关，必须从头开始检索，费时）或者顺序结构（按照关键字排序、定长时可以采取折半查找）
   ③顺序文件效率最高，但查找、修改、增删性能较差。
   ④顺序存储＋可变长依然无法实现随机存取
2. 索引文件
   ①可定长（公式查找，长度*条数=地址）可变长（只能顺序查找索引，效率低）
   ②可以建立一张索引表，索引表为定长记录的顺序文件，这样加快了检索，但增大了存储开销。
   ③索引表，每一行为一个索引项。
   ④要理解索引表（对文件内容的索引，记录文件内每一行内容的“小目录”）、索引块也叫索引表（里面存的是文件在磁盘内存储的盘块号）、索引文件（这是一种文件内容的逻辑结构，对索引文件进行存取时，必需先查找索引表）、索引项（是指索引表中的每一行内容，记录索引号+该行内容长度+指针指向逻辑文件中的起始位置，并且只能指向索引文件里的一个内容）
3. 索引顺序文件

①等于组间索引文件（将不同的记录根据相同的键值分为不同的大组，组间建立索引表，索引查找）+组内顺序文件（组内的所有记录有相同的键值，组内无序排列，顺序查找）。

②顺序文件查找时平均查找二分之N次。索引顺序文件查找，N条记录，分为根号N个组，每个组根号N个记录，组间查找为二分之根号N，组内查找为二分之根号N次，所以总共根号N次，有效提高查找效率。

③缺点是，需要建立索引表，增大了存储负担。

4. 直接文件或散列文件
   ①通过散列函数换的键值决定记录的物理地址，很有可能冲突。
   ②哈希存储更适合磁盘块的分配与回收
   动态分配：基于 Hash 函数快速定位物理块，分配效率高，即使大量数据插入，只要合理处理 Hash 冲突，仍能保持高效。与索引存储相比，无需维护庞大索引表；与链接存储相比，不用遍历链表查找位置。

动态回收：回收简单高效，标记空闲后，后续分配可快速利用，因 Hash 结构本身特点，空间利用相对更紧凑，碎片问题相对不突出。

6.文件的物理结构（本质是如何为文件分配磁盘块）（内存与磁盘进行数据交换都是以块为单位，块大小与页面大小通常相同） （逻辑文件存储到存储介质上采用的组织方式与存储介质特性有关）

1.连续分配：

①占有连续的块。

②优点：顺序访问和随机直接访问，寻道数、寻道时间、磁头移动距离最小。

③缺点：分配连续的空间，会产生外部碎片，必须事先知道文件大小，插入删除也需要进行物理移动很麻烦。

④自己犯了一个很大错误，当文件连续分配的磁盘块需要插入一个新的磁盘块时，要先检查尾部是否有空闲的磁盘块，然后将最后一个磁盘块读入内容，向后移动一个磁盘块的位置，重新写入磁盘，以此类推，直到写到插入磁盘块的位置。但是如果尾部没有空闲磁盘块，则要把整个文件全部的磁盘块依次读入内存，写入新的连续空闲磁盘块的位置，磁盘IO巨大！

⑤相对比之下，链接分配、索引分配只需要改动指针或者改动索引块中的磁盘块号即可。

2.链接分配（FAT文件系统）：

（1）隐式链接：

①文件目录项中含有头磁盘指针和尾磁盘指针，对用户透明。

②缺点：只支持顺序访问，从头指针开始查找下一块磁盘，直到找到磁盘块。稳定性差，有一个指针坏了就彻底崩盘。大量指针浪费空间。

③可以引入簇（一个簇等于若干个连续的磁盘块），按照簇来顺序指针查找，减少指针占用空间，加快查询速度，但代价是增加了内部碎片。同时如果引入簇，那么系统给文件分配空间时要分配整数个簇的空间，即如果一个簇=4个磁盘块大小，即使再分配一个磁盘块就够了，也不行，必须只能分配一个簇（2017真题）

（2）显式链接：

①引入文件分配表FAT（File Allocation Table），它本身也是一个文件，也具有FCB，整个文件系统只设置一张，用户只能间接查看。

②文件目录中只引入一个起始块号。

③优点：支持顺序访问和直接访问，FAT在开机系统启动时就被读入了内存（常驻内存），检索记录是在内存中进行的，显著提高检索速度，明显减少访问磁盘次数（隐式链接分配向下探索下一块磁盘块不需要每次都访问磁盘）。还有一个优点就是可以显示磁盘中的空闲磁盘逻辑块号，方便外存空闲磁盘管理，2019真题。

④缺点：FAT需要占用一定空间，并且还必须是连续空间

FAT支持的最大文件长度可以理解为整个分区都是该文件的存储空间（2016真题）

其次，上图给出的FAT文件分配表有所误解，正确的应该是不分配第一列的存储空间的，因为它天然就是有序的，只需要保存指向的下一个磁盘块号即可。

3.索引分配（常用于Linux系统，直接将索引块存储在索引节点当中）：

（1）单级索引

①没必要将整个FAT（存储所有文件的磁盘关系）全都调入内存，只需要将所用文件的占用磁盘块调入内存。所以为每个文件分配一个索引块（表），存储该文件的所有盘块号。

②一个盘块大小为4KB，一个索引号大小为4B，所以可以存储1024个盘块号。对应着1024*4KB=4MB的文件大小空间。

③在索引块里面，盘块号是按照文件存储的顺序排列的，索引块存放的磁盘块号是文件内容在磁盘中存放的物理位置。

④优点：可以直接访问文件存储的第i个磁盘块（从索引块中找第i个条目即可），不产生外部碎片。

⑤缺点：索引块增加了存储开销。文件太小，导致索引块后面空间浪费。文件太大，又需要多个索引块来存储，用指针来链接多个索引块，效率低下。

（2）多级索引

①若文件特别大，可能需要多个索引块，索引块太多，则需要建立多级索引。

②第一级索引称为主索引，主索引存放第一个索引的盘块号，第二个索引的盘块号。

③若一个盘块大小为4KB，一个索引条目大小为4B，则一个盘块可以存储1024个索引条目，那么采用二级索引存储的最大文件=1024*1024*4KB=4GB

④优点：加快查找速度。

⑤缺点：多级索引，访问磁盘数增加，效果并不理想。

（3）混合索引分配方式

根据不同文件大小采取不同的分配方式，UNIX系统采用索引节点中设置13个地址项，即iaddr.0~iaddr.12。

①小文件直接寻址：直接将盘块地址（盘块号）存入FCB，直接从FCB中获取文件的盘块地址，总共分配了十个直接地址，iaddr0～iaddr9，每个格子iaddr存储一个直接地址，每个地址指向一个盘块号，则最大存储10*盘块容量（假设4KB）=40KB。

②中文件一次间址：利用单级索引，FCB存入一个索引块地～～址（iaddr.10），指向一个索引块，该索引块中存储该文件的盘块地址，最大文件大小=4MB+40KB

③大文件多级索引：设置多个地址项，利用iaddr.11存储二级间接地址，可以存储4GB，利用iaddr.12三级间接地址存储4TB，所以文件最大为4TB+4GB+4MB+4KB

### 文件系统的性能

①目录项由FCB升级为文件名+索引编号，这样节省空间，提高查找目录的效率，提高IO速率。

②文件高速缓存：数据读入内存，后续直接从内存读数据，减少磁盘IO；延迟写回磁盘，先将内容写回页缓存中，积攒数量强制触发写回机制，减少磁盘IO。

③磁盘调度算法：影响了写入内存的磁盘块的顺序，自然影响寻道时间，进而影响写入的IO时间。

④异步IO是指，发出IO请求后，CPU去干别的事情，提高CPU的利用率，与磁盘IO没任何关系，所以不会提高文件系统的性能。

## (二)目录

### 1.目录的基本概念

①文件控制块FCB的有序集合称为文件目录，一个FCB就是一个目录项。但是目录项太长占据空间，所以就优化为索引，将名字和索引指针变成索引目录，索引指针指向索引节点（存储文件信息）。

②多用户系统中还要加入对文件的控制访问信息，允许不同用户对不同文件采用相同的名字。

③FCB是文件系统内部用来管理文件的结构，需要知道文件在存储设备上的实际位置才能进行读写操作。目录项是用于描述文件在文件系统中的位置，而不是文件在存储设备上的实际位置，只需要知道逻辑地址。

④有一个非常容易弄混淆的概念：目录项，它记录了文件名+指针与inode的逻辑映射关系，通过逻辑映射找到对应的inode，inode存储的是文件的元数据。

### 2.树形目录及其它三种结构

（树形结构不便于实现文件共享）（文件打开后，通过文件描述符来对文件进行访问）

单级目录结构：

①整个系统只有一张目录表，目录表中记录所有文件的目录项。

②建立新文件时，先检查是否文件名冲突，然后再目录表中新建一项，建立对应FCB。

④删除一个文件时，先按照文件名在目录表中找到对应目录项，回收文件所占空间和删除FCB。

⑤特点：实现按名存取，查找速度慢，不允许重名，不便于文件共享，不适用于多用户操作系统。

⑥读入一个文件的索引节点的访问磁盘次数=查找目录项平均查找次数+1次读入索引节点

两级目录结构：

①分为两层，一层主文件目录MFD（Master File Directory），一层用户文件目录UFD（User File Directory）。

②主文件目录里面存储主文件目录项，主文件目录项=用户名+用户文件目录（这是一个文件）所在存储位置

③用户文件目录记录该用户所有文件的FCB。

④特点：解决了多用户问题，解决重名问题，提高了检索速度，但是两级目录缺乏灵活性，不能对文件进行分类。

树形目录结构 ：

①利用文件路径来查找文件，每个文件唯一路径。

②从根目录出发的路径称为绝对路径，但由于每个进程的文件局限于一个范围，所以每次从绝对路径的根目录查找比较麻烦所以，可以为每个进程设置一个当前目录（工作目录），从当前目录找会更加方便。

③特点：对文件进行分类，系统登陆哪个用户，就会自动进入该用户的工作目录，可以赋予不同存取权限。但是每次逐级访问中间节点，增加了磁盘访问次数，影响查询速度。不便于实现文件共享

④明显提高目录的检索速度和文件系统性能

无环图目录结构：

①在树形目录结构的基础之上，增加有向边，成为一个有向无环图。

②为每共享节点设置一个共享计数器，直到计数器为0才将文件删除。

③特点：实现了文件共享，但是系统管理更复杂。只是把共享文件的盘块号复制到了对应目录，如果一个用户增加内容导致增加了盘块，这个盘块号只有该用户可见，其他共享用户不可见，这就是其弊端。

目录的实现：

1. 线性检索法：
   例如某个一个路径usr/test/2025-7-19/康永万里/OS,就需要先从根目录下顺序找到usr字段所在的目录项，找到usr目录文件所在的盘块号，然后在该盘块号内usr目录文件中顺序查找test字段的目录项......如果有一个文件分量名未能找到，就立即停止查找，返回“文件未找到”信息
2. 哈希方法

建立一张哈希索引文件目录，利用哈希方法进行查询；若目录表中对应的目录项是空的的，则说明无该文件，若与指定文件名相匹配，则可以找到该文件所在的物理位置；如果在目录表的响应目录项中的文件名与指定文件名并不匹配，则发生了冲突，应该在哈希值上加一个常数（与目录长度互质），形成新的索引，继续查找。

### 基于索引节点的共享方式（硬链接）

①目录项=文件名+指针，指针指向索引节点，索引节点存储文件的各种信息，包涵链接计数count。

②当一个用户创建新文件时，它是该文件主人，count此时=1。只有当count=0时才删除整个文件。

③硬链接直接到达，所以查找速度更快。

④创建文件F1，则引用数=1，创建文件F1的硬链接F2，则F1和F2的引用数都等于2，其实本质上F1和F2都是同一个文件，指向的是同一个索引节点。

⑤如果两个进程分别打开了用户A的文件和用户B的文件（这两个文件指向的是同一个索引节点，如下图），第一次打开需要通过用户A的目录找到索引编号，在磁盘中找到对应索引节点并将索引节点读入（复制）内存，请注意此时需要在系统打开表中新建条目：包涵指向内存中的索引节点的指针、打开计数，用户文件打开表也要新建条目。

此时进程2想要打开用户B的文件，查找目录之后发现索引编号是同一个，那么就直接跳过IO，从系统打开表中找到内存中已经加载过的索引节点指针。

⑥上述⑤的问题续集，两个进程对该文件的访问权限可能是不同的。

⑦上述⑤的问题续集，由于进程1已经将文件打开了，那么后续对文件的读取操作都通过文件描述符来进行，而不是绝对路径作为系统参数。两个进程的文件描述符是不同的，但底层都指向同一个索引节点，而且文件描述符都各自指向自己的用户文件打开表中的一项（2017真题）。

⑧上述⑤的问题续集，两个进程虽然对同一文件读取，但是各自拥有独立的读写指针存在用户进程打开文件表（2017真题）。

### 基于符号链接实现文件共享（软连接）

①创建一个LINK新文件，将文件L写入想要共享的用户目录，LINK中写入该文件的路径名。

②此时被软连接的文件的引用数保持不变，而软连接新建的文件（里面写有链接文件的绝对路径）引用数一直都是1。

③当文件主将源文件删除之后，其它共享用户再去通过LINK中的文件路径查找共享文件报错，然后将符号链接删除。

④特点：访问共享文件可能需要多次读盘；LINK本身也是文件，其索引节点要耗费磁盘空间。

⑤当利用符号连接实现网络共享时，只需要提供机器所在网络地址和文件路径名。

## (三)文件系统

### 1.文件系统的全局结构(layout)

文件系统在外存中的结构，文件系统在内存中的结构

文件系统结构：

文件系统模型分为

（1）对象及其属性：文件、目录、磁盘存储空间

（2）管理软件集合：文件存储空间管理、文件目录管理、文件逻辑地址转化成物理地址、文件读写管理、文件共享和保护
实现以上功能用了四层软件结构：

①IO控制层：中断处理、由磁盘驱动程序组成

②基本文件系统层：处理内存与磁盘之间的数据块交换

③基本IO管理层：完成与磁盘IO相关的事务，例如文件逻辑块号转换成物理块号，管理磁盘空闲盘块、IO缓冲指定

④逻辑文件系统：实现按名存取、文件权限验证、文件元数据（详细的元数据或者目录）管理、把文件名转化为文件描述符fd、允许通过fd访问文件和记录、对文件和记录进行存储保护

（3）文件系统接口
命令接口：用户与文件系统直接交互，通过终端直接获得文件系统提供的服务

程序接口：通过系统调用获得文件系统的服务，read、open等

碎碎念：

①在用户看来，引入文件系统的目的是实现按名存取。

②一个文件系统管理的文件数量受限于文件控制块（在文件系统搭建初期，就已经固定了FCB的最大数量，但现代系统可能要求没有那么严格，采用的是动态的FCB数量）的数量，所以文件系统使用的最大文件数量不等于所在磁盘的容量。

③采用RAID磁盘阵列，可以将一个文件分开放在不同的磁盘上，所以不是必须将文件放在一个磁盘上。

④单个文件的大小不是只受磁盘剩余容量大小的限制，而是还受到FAT表、FCB等结构的限制

文件系统在外存中的结构：

每个分区都有一个独立的文件系统，保存有启动存储在那里的操作系统的方式、总的块数、空闲块的数量和位置、目录结构以及各个具体的文件

①主引导记录MBR：位于磁盘0号扇区，引导计算机，后面是分区表（记录每个分区的起始、终止地址）

②MBR执行引导块（这个引导块是指装有操作系统的分区的第一个块）中的程序，该程序负责启动该分区中的操作系统。

③超级块：（用于描述文件系统的）包涵文件系统的所有关键信息，分区块的数量、块的大小、空闲块的数量和指针，空闲的FCB数量和FCB指针

④文件系统中空闲块的信息：用位示图和指针链接的方式给出。

文件系统在内存中的结构：

内存中的信息用于管理文件系统，并且缓存一定的数据来提高系统性能。

①内存中的安装表：包含每个已安装文件系统分区的有关信息。

②目录结构的缓存：存储最近访问的目录的信息

③系统的打开文件表：FCB副本和计数器

④进程的打开文件表：保存有文件描述符、读写指针和对应表项的指针（指向系统的打开文件表）

### 2.外存空闲空间管理办法

基本知识：

①卷：文件系统的分区，C卷、D卷。它可以是磁盘的一部分，也可以是整个磁盘或者RAID磁盘阵列。

②文件区：存放文件数据

③目录区：存放FCB

④物理盘和逻辑盘

空闲表法（这属于空闲磁盘块管理方法）：

①属于连续分配，为所有空闲区建立空闲表，每个表项表示一段连续的空闲区，按照磁盘序号顺序排列。

②分配方法：首次适应算法、最佳适应算法、最坏适应算法等，与内存的动态分配类似。

③回收：回收空间，前后合并。

④优缺点：较高的分配速度和减少磁盘的IO频率，对于小文件可以采取连续分配空闲磁盘的方法。

⑤可以得到连续的空闲磁盘空间，或者离散的空闲磁盘空间。

空闲链表法（这属于空闲磁盘块管理方法）:

空闲链表适用于离散分配、难获得连续空间，因为是随机的不同的盘块被头尾指针链接

1. 空闲盘块链：

①将空闲盘块穿成一条链，需要分配磁盘块时从链上取出，若释放空闲盘块则添加到空闲盘块链的末尾。

②优缺点是：过程简单，但若连续的盘块，需要多次重复操作，效率低，而且空闲盘块链很长。

③最难得到连续的空闲磁盘空间。

2. 空闲盘区链：

①将所有空闲盘区拉成一条链，每个盘区包含若干盘块，每个盘区记录下一个指针和该盘区的盘块数量。

②优缺点是：分配和回收的效率较高，并且链子较短，但分配与回收的过程比较复杂。

③最容易得到连续的空闲磁盘空间。

位示图法（这属于空闲磁盘块管理方法）：

①将所有磁盘行列对应二维数组，若已分配则数组记为1，未分配记为0，位示图适用于离散分配和连续分配。

②优缺点：很容易找到空闲磁盘块或者空闲磁盘区，占用空间很小（一位仅占用1bit，而不是整数型的int占4B，2015和2023真题），可以保存在内存中，节省许多磁盘IO。但也只适用于小磁盘的计算机，大磁盘的计算机位示图太大。

IO接口（也叫设备控制器）

①CPU与设备之间控制的桥梁，实现设备与计算机之间进行数据交换。

②它在某种程度上替代了CPU，即CPU的命令先存在IO接口里，然后CPU抽身去处理别的事情。

③组成结构：

a.CPU与控制器的接口：负责实现CPU与设备控制器之间的通信。数据线传送读写数据、控制信息、状态信息。地址线传送的是访问IO接口中的寄存器编号。控制线传送读写控制信号。

b.设备控制器与设备接口：IO接口可以和多个设备链接，与之链接的设备都有数据、状态、控制信号。

c.IO逻辑：用于实现对设备的控制、通过一组控制线与CPU交互，对CPU发来的IO命令进行译码，接受操作命令和地址命令。

④主要功能：

a.接收命令、翻译命令

b.数据交换：CPU与控制器、控制器与设备之间都可以进行数据交换

c.标识和报告设备的状态：存放某些设备的状态信息供CPU了解，例如只有达到设备就绪状态时，CPU才能启动控制器从设备中读入数据

d.地址识别：识别是指向哪个设备的

e.数据缓冲：CPU与IO设备数据传输差异，IO接口中由缓存装置

f.差错控制：USB接口、网卡保证数据传输正确（校验）

IO接口的类型：

①按数据传送方式：并行接口和串行接口

②按主机访问IO设备的控制方式：查询接口、中断接口、DMA接口

③功能选择灵活性：可编程接口（可以通过变成改变接口功能）、不可编程接口

IO端口（IO接口内的寄存器）：

①数据寄存器：缓存从设备/CPU发来的数据

②状态寄存器：保存设备的执行结果或者状态信息，CPU需要判断设备是否可用

③控制寄存器：由CPU写入，启动命令或者更改设备模式

每个端口都有一个端口地址，供CPU访问来选择对应的寄存器。两种编址方式：

|  | 独立编址 | 统一编址（内存映射IO） |
| --- | --- | --- |
| 特点： | 存储器与寄存器编址范围分开，可能同一个地址1对应两个不同设备。用户程序不能对端口访问只能由操作系统通过特殊IO指令访问。 | 寄存器和内存按照统一编址。 |
| 优点： | IO端口译码简单，只需要少量地址线，寻址速度快。使用专用的IO指令，程序更清晰，便于理解和访问。 | 不需要专门的IO指令，CPU对IO访问更方面，IO访问的保护机制可由虚拟存储管理系统实现，无需专门设置。 |
| 缺点： | IO指令太少，只能简单传输操作，程序的设计灵活性差，CPU需要提供两组独立的存储器和设备的读写控制信号。 | 主存容量变小，需要区分存储器和IO端口，译码电路复杂，译码速度变慢。 |

### 2.I/O 控制方式

1.程序直接控制方式（论询方式）：

①工作流程：CPU向IO接口发送一条IO指令，启动IO设备并读取一个字（这是读命令），然后从IO接口中取出该设备的状态，若准备完成，则从IO控制器中读取一个字（节）。

②独占查询和定时查询

| 独占查询 | 定时查询 |
| --- | --- |
| 一旦设备启动，CPU就一直查询接口状态，外设和接口完全串行工作。 | CPU周期性地查询接口状态，每次等到条件满足才进行一个数据的传送，传送完成后返回用户程序，定时查询等待时间间隔和设备的数据传输速率有关。 |

③优点：软件即可实现，硬件消耗量少，比较简单

④缺点：CPU被独占的话，消耗大量时间等待，CPU的利用率很低。

2.中断驱动方式：

①执行过程：对于CPU来说，它需要请求某个设备传送数据，那么就发出读指令给IO接口，然后该进程被阻塞，保存上下文，转而去运行其它程序。在每个指令周期的末尾，CPU会检查是否有中断信号，若有来自于设备控制器的终端时，CPU保存上下文，转去执行中断处理程序来处理该中断请求，CPU从设备控制器读一个字的数据传送到CPU的寄存器，并存入主存。中断处理完成后，恢复该进程（或者其它进程）上下文，然后继续运行。

对于设备控制器来说，从设备中读入数据到IO端口的数据寄存器，读好之后便向CPU发送中断信号。设备控制器得到CPU的请求取出数据之后，将数据放在数据线上传送到CPU的寄存器。

②优点：主动向CPU报告IO准备完成，CPU和设备并行工作，CPU利用率得到提升。

③缺点：每次传送数据都需要经过CPU寄存器，并且传送方式是以字（节）为单位，若对于块设备的IO操作，效率很低

④中断处理程序是第一个获得字符型设备输入信息的（2010真题）

3.DMA（直接存储器存取）方式：

①执行过程：思想是在IO设备和内存之间开辟直接的数据交换通路，避开CPU。所以采用数据块为单位，从设备直接到内存，不经过CPU，在传送一个或多个数据块的开始和结束才需要CPU干预。CPU收到设备的DMA请求，CPU向DMA控制器发送一个命令，将IO控制权交给DMA，然后给DMA设置MAR和DC初值，DMA控制器直接与内存交换，每次传送一个字，直到全部传送完毕，向CPU发送中断信号。

②四类寄存器：

| 命令/状态寄存器CR | 暂存从CPU发来的IO命令、或者设备的状态信息。 |
| --- | --- |
| 内存地址寄存器MAR | 输入内存时，存放目标内存的起始地址。输出时，存放内存到设备的内存源地址。 |
| 数据寄存器DR | 暂存从内存到设备、设备到内存的数据 |
| 数据计数器DC | 存放本次要传送的字节数 |

③优点：以块为传送单位，CPU介入频率进一步降低，CPU数据传送不再经过CPU的寄存器，CPU和设备的并行操作成都得到了进一步提升。

④缺点：硬件复杂度高、CPU与DMA引发总线竞争、绕过CPU写数据可能引发内存与Cache数据不一致、外部绕过CPU破坏内存数据。

⑤一些注意点：

预处理程序和后处理程序都运行在内核态

预处理程序是请求IO的进程、负责后处理程序的是中断处理程序，但是中断处理程序不是一个单独的进程。

预处理程序需要让CPU参与设置相关调用参数，然后阻塞自身，直到系统调用完成返回，后处理阶段请求IO的进程仍然属于阻塞态。

⑥预处理和后处理

DMA（直接内存访问）的 “预处理阶段”，指的是在数据传输正式开始前，CPU 和 DMA 控制器（DMAC）需要完成的一系列准备工作。这一阶段的核心目标是：明确 “传输什么数据、从哪里传、传到哪里、传多少”，并建立 DMA 传输的基本规则，为后续 “无需 CPU 干预的自主传输” 奠定基础。

### 3.I/O 软件层次结构 （理解不够）☆☆☆☆

## (二)设备独立软件（设备无关软件）

### 1.缓冲区管理

一些基础知识点：

①设备的独立性是指：用户编程使用的设备与实际设备无关，只需要指明使用设备（可以通过文件名来当做逻辑名称）即可，不需要指明具体的物理设备

②设备独立性软件是指：不直接依赖特定硬件设备，而是通过抽象层或标准化接口与硬件交互的软件设计方式。其核心目标是提高软件的可移植性、兼容性和可维护性，使同一套代码能在不同硬件环境中运行而无需大量修改。

例如一些适合用设备独立性软件来管理的是：检查用户是否有权使用设备、缓冲区管理。

而向设备寄存器写命令是由设备驱动器完成的、将二进制整数转换成ASCII格式打印是由IO库函数完成。

磁盘高速缓存：

①把内存的一部分空间当做磁盘（开辟的空间大小固定）、或者把剩余的内存空间当做缓冲池供应分页系统和磁盘IO时共享，因为CPU访问内存速度更快。

②物理上属于驻留在内存的盘块、逻辑上属于磁盘。

③进程正在运行的程序既存储在内存、也存储在磁盘上。

缓冲区：

设立缓冲区的目的：

①缓和CPU和IO设备速度不匹配的问题

②减少对CPU的中断频率（字符型设备每输出一个字符就要请求一次中断，所以引入缓冲区可以填满缓冲区后才请求一次中断），放宽对CPU中断响应时间的限制。

③解决基本数据单元大小（数据粒度）不匹配的问题（例如输出进程每次输出一块的数据，但是IO设备每次只能输入一个字符）

④提高CPU和IO设备之间的并行性

（2）双缓冲

### 3.假脱机技术(SPOOLing)

①用软件方式实现、需要多道程序设计技术（该技术可以提高单机资源利用率）支持、需要外存磁盘开辟“井”、将独占设备改造成共享设备、由系统建立输入输出进程控制设备与井之间数据传送、提高IO速度、实现虚拟设备功能让进程误以为独占设备、以空间换时间、提高独占设备资源利用率。

②引入假脱机技术是为了缓解CPU和IO设备速度的矛盾，将CPU产生的数据先放到一个存储区域“磁盘内”，然后让IO设备慢慢的从磁盘取走数据输出。

③输入井和输出井：

他们本质是磁盘开辟的一段空间，将输入输出数据保存为文件，各个文件之间排成链接队列。用户的产出结果首先被送到磁盘固定区域，尽快中间要经过内存固定区域的缓冲区，但在逻辑上，磁盘固定区域才是逻辑终点。

④输入缓冲区和输出缓冲区：

在内存中开辟空间，目的是将磁盘的数据引入内存并交给IO设备输出。

⑤输入进程和输出进程：

要求数据必须经过输入输出缓冲区（内存），才能交付给输入输出设备，因为没办法之间建立设备与磁盘之间的联系！！！并且这个过程是操作系统控制实现的，用户作业根本不知道这个过程，对它来说是透明的。

⑥井管理程序：

用于控制作业与磁盘井之间的信息交换。

⑦打印机举例：来自不同用户的打印文件先暂存在磁盘空间，然后将用户打印请求表挂在假脱机文件队列上，这样好像每个用户都独占了打印机，但实际是共享了打印机。所以用户进程实际分配到的不是物理设备，而是磁盘空间。整个过程利用到了文件系统（将文件放到磁盘），设备管理程序（控制打印机输出）。

⑧SPOOLing系统由三大部分组成：

| 预输入程序 | 输入井和输出井 |
| --- | --- |
| 井管理程序 | 输入输出缓冲区 |
| 缓输出程序 | 输入进程和输出进程 |

### 4.设备驱动程序接口（理解不够）☆☆☆☆☆

①意思就是：下层的驱动程序要根据上层的设备独立性软件提供的驱动程序接口的规范，来编写自己的驱动程序。上层规定了函数名、参数名、参数个数等，厂商就要根据不同操作系统提供的信息来编写对应的驱动程序。

②设备驱动程序的功能：

a.接收上层应用的抽象IO请求，转化成具体的要求来交给设备控制器，让其执行操作，还要从设备控制器中取出它的设备状态信息和IO操作的完成情况反馈给进程；

b.检查用户IO请求合法性、了解设备工作状态、传递与设备操作有关参数、设置设备工作方式；

发出IO命令，若设备空闲则执行操作，若不空闲则挂到等待队列；

及时响应由设备控制器发来的中断请求，根据终端类型调用响应的中断处理程序。

c.负责处理磁盘调度（磁盘驱动程序）

d.驱动程序不对IO传回来的数据进行分析和缓冲，这个功能是由操作系统完成的。

f.初始化设备（如初始化设备控制器的寄存器值）

g.读写设备的操作是由驱动程序控制完成的（2022真题）

③设备驱动程序的特点：

a.要根据设备的IO控制方式来编写设备驱动程序，常用的是中断驱动和DMA（2022真题）

b.要根据不同的设备硬件来编写驱动程序，所以不同类型的设备拥有不同的驱动程序

c.目前很多设备驱动程序固化在ROM中

d.设备驱动程序允许同时多次调用

e.不同操作系统的相关设备的驱动程序是不同的，要根据不同情况进行定制。

f.驱动程序可以用汇编、部分也可以用高级语言编写。

g.执行驱动程序时可能会发生阻塞（2022真题：若采用直接控制方式，不会发生阻塞，因为一直占用CPU进行轮询操作；但中断控制方式，会把CPU让给其它进程，阻塞自身让其只完成IO过程；驱动程序对DMA控制器初始化后，发出启动DMA传送命令，外设与内存之间传送数据，CPU被让出。）

进程执行键盘scanf系统调用的完整处理流程（2017真题）：
流程如下：

①进程 P 处于运行状态，然后进程 P 在用户态执行代码，调用 scanf() 函数，需要等待用户输入（即缓冲区的内容为空时，触发read系统调用），所以进程P进入阻塞态。

②进入阻塞状态（Blocked）：由于 I/O 设备（键盘）的速度远慢于 CPU，且采用中断控制方式，操作系统会将进程 P 置为阻塞状态（Blocked），等待输入完成。此时，进程 P 不再占用 CPU，操作系统会调度其他就绪进程运行（如果有）。

③状态恢复（Ready）：当键盘输入完成（用户输入了值并按回车键），键盘控制器会触发一个硬件中断。中断处理程序会读取输入数据，并将其传递给进程 P 的缓冲区。然后返回系统调用之后，操作系统随后将进程 P 的状态从阻塞状态（Blocked）改为就绪状态（Ready），等待 CPU 调度。

④重新运行（Running）：当进程 P 被操作系统调度器选中时，它从就绪状态（Ready）进入运行状态（Running），并继续执行后续代码（如调用 f1()）。

因此，进程 P 的状态变化序列为：

Running → Blocked → Ready → Running

CPU 是否会进入内核态？

是的，CPU 会在以下两个关键点进入内核态：

①系统调用执行时：

当 scanf() 触发底层系统调用（如 read()）时，CPU 通过软中断（例如，int 0x80 或 syscall 指令）从用户态切换到内核态。在内核态中（此时CPU执行的还是进程P），操作系统处理 I/O 请求：检查输入缓冲区，发现数据未就绪时，才把进程 P 阻塞，并调度其他进程。

②硬件中断处理时：当键盘输入完成时，硬件（键盘控制器）会发送中断信号给 CPU。CPU 响应中断，立即从当前状态（无论是用户态还是内核态）切换到内核态（此时是“中断态”），执行中断处理程序（此时执行的不是进程P了，因为它被阻塞了，）。中断处理程序在内核态中读取输入数据，唤醒阻塞的进程 P（将其状态改为就绪），并完成 I/O 操作。

进程执行键盘scanf系统调用的数据流向（2024真题）：

①首先键盘输入的数据先被保存到键盘设备控制器的数据寄存器中，键盘控制器通过中断线向CPU发送中断信号，然后触发中断服务程序。

②CPU阻塞当前进程，转为内核态执行中断服务程序，该过程将键盘控制器内的数据传到位于内存的内核态的缓冲区，中断服务程序结束。

③操作系统然后唤醒用户进程，若执行read系统调用，让其将数据从内核态缓冲区传到用户态缓冲区。

④键盘输入的数据只会被保存到用户态的缓冲区，只有当出现下一条指令例如mov R1, 28393012H，才将用户态缓冲区的键盘数据传送到CPU的通用寄存器组。

6. 磁盘的工作过程

寻址、读盘、写盘

每个操作都有一个对应的控制字，取出控制字然后执行这个控制字。磁盘不可能在同一时刻读写同时操作、也不可能同时进行两处位置的读操作或写操作。

磁盘的管理：

1.磁盘初始化（物理格式化、低级格式化）：

①主要目标就是划分扇区，建立磁盘的物理结构，包括磁道、扇区和柱面等。 这个过程将磁盘表面划分成许多小的、可寻址的单元。同时操作系统自动用后备扇区顶替坏扇区，这个过程对用户透明。

②这个过程会写入一些低级别的信息到磁盘，例如引导扇区（包含主引导程序、分区表、结束标志）信息

③每个扇区由头部、数据区域、尾部组成，头部和尾部包含了一些对磁盘控制器的使用信息。

④利用CRC还可以对扇区进行校验。

对磁盘进行分区C、D区：

在逻辑格式化和物理格式化之间还夹杂一个步骤是对磁盘进行分区（C区、D区）（2021真题），每个分区由一个柱面或者多个柱面组成，每个分区的起始扇区和大小都记录在磁盘主引导记录的分区表中。

逻辑格式化：

①逻辑格式化是在物理格式化之后，在磁盘上建立文件系统。它创建文件系统所需的元数据结构，例如文件分配表 (FAT)、目录结构、空闲空间、已分配空间、空目录、根目录以及其他用于管理文件和目录的控制信息，并对这些信息进行初始化，记录在磁盘上！！！。

②这允许操作系统理解和管理磁盘上的数据。具体操作: 创建根目录、文件系统结构，并设置文件系统的参数，例如簇大小，文件系统类型 (NTFS, FAT32, ext4 等)。

③特点: 是高层操作，可以反复进行，并且不会破坏磁盘的物理结构，只会删除文件系统中的数据。

所以流程应该是磁盘物理格式化、对磁盘进行分区、磁盘逻辑格式化、安装操作系统（2021真题）

引导块（王道编写的什么垃圾）：

①计算机启动时需要运行一个初始化程序（自举程序），初始化CPU、寄存器、设备控制器和内存，然后启动操作系统。所以它需要找到磁盘内存储的操作系统，将它加载到内存，并转到起始地址，开始运行操作系统。

②初始化程序保存在ROM中，但是为了避免初始化程序改动而需要修改ROM硬件，所以在ROM中存储的是自举装入程序，即把完整的自举程序放在磁盘的启动块上，把安装自举程序的程序放在rom中。

③启动分区位于磁盘固定位置，具有启动分区的磁盘称为启动磁盘或者系统磁盘。

磁盘调度算法

（1）先来先服务（First Come First Served，FCFS）：按照请求的先后顺序进行磁盘调度。

如果后面来的请求需要等待前面的请求完成后才能执行，会导致平均等待时间较长。优点是公平，只有少量进程，且都访问簇聚的磁盘块是，性能最优；在大量进程访问磁盘是，性能接近于随机算法。

（2）最短寻道时间优先（Shortest Seek Time First，SSTF）：选择当前距离磁头最近的请求先执行。这种算法可以减少等待时间，每次寻道时间最短（但不能保证平均寻道时间最小），但是可能会出现饥饿现象。（半路被打劫，导致一部分磁道永远得不到磁头，因此产生饥饿现象）

（3）扫描算法（SCAN，也叫电梯）：磁头按一个方向移动，直到磁盘一侧末端，哪怕这里没有请求，我也要来，然后返回磁盘的另一端。这种算法可以平均分配磁盘访问的时间，并且会导致磁道访问频率不平均，对扫描过的区域不公平，会导致一些请求长时间等待，偏向于处理最里或者最外的磁道。（比如正在从2号磁道向大磁道行进，但是1号磁道有需求，必须等到一来一回才轮到它）

（4）循环扫描算法（Circular-SCAN）：类似于扫描算法，但是磁头到达磁盘的一端时，会立即返回另一端（这个过程不执行任何操作，即规定了访问磁盘只能从一个方向），正向处理请求，反向回家不工作。这种算法可以避免饥饿现象，并且磁盘的访问频率也比较均匀。

（5）SCAN+LOOK调度：扫描SCAN算法+边移动边观察，即磁盘只需要移动到最远端的一个请求即可返回，不需要到磁盘的端点。

（6）Cirlular_SCAN+LOOK调度：相当于是C-SCAN的优化。只移动到最后一个请求的位置，然后再返回到第一个请求的位置。这种算法可以减少磁头的移动次数，提高磁盘访问效率。

减少延迟的方法：

①由于磁头读取完一个扇区之后需要一定的处理时间，该时间内不允许进行读操作，所以在这个时间内磁盘仍在旋转，就错过了即将要读的下一个扇区，所以采用交替编号，把逻辑上读相邻的扇区物理上分开，这样可以避免多绕一圈的延迟时间。

②同时也要对不同盘面的相同位置的扇区错位编号
