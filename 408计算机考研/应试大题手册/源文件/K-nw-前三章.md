## 时延四兄弟 · 计算模板

**考频**：2010/2011/2015/2017/2019/2021｜不单独命题，但几乎是每道 47 题的第 (1) 问

**必背结论**
- 发送时延 $T = L/b$：把 $L$ bit 推上链路要多久，只与帧长和速率有关，与距离无关。
- 传播时延 $\tau = d/v$：比特在介质里跑 $d$ 米要多久，只与距离和介质有关，与帧长无关；铜缆与光纤 $v \approx 2\times10^{8}$ m/s，无线 $3\times10^{8}$ m/s。
- 处理时延与排队时延：题目不提就当 0；一旦写「路由器同时只能处理一个」，就必须画时间线，套不出公式。
- 时延带宽积 $= \tau \cdot b$，单位是 bit：链路管道里能装下的比特数；给时延带宽积和带宽可以反解 $\tau$。
- 总时延 = 发送 + 传播 + 处理 + 排队；一段链路上有 $k$ 个结点就叠 $k$ 份。
- 分组交换总时间：$n$ 个分组、每个传输时延 $T$、经过 $m$ 个存储转发结点且不计传播时延，为 $nT + mT$。
- 若要计传播时延且路径上 1 个路由器：$nT + \tau + T + \tau$；报文交换经 $m$ 个路由器：$(m+1)T$。
- 计算顺序固定：先全部换成 bit 与 s，再算 $T$ 与 $\tau$，最后才相加；中途换单位必错。
- 计算题里的 RTT 一律当 $2\tau$（往返传播）用，不要搬书上「含发送与确认」的定义来做题。
- 数字例子：$n = 1000$、$T = 0.08$ ms、$m = 2$ 时总时间 $80.16$ ms；同样数据量改用报文交换则只有 $(m+1)T$，但那个 $T$ 要按整个报文算，通常远大于分组。

> 传输时延问「帧多长、口多快」，传播时延问「线多长、跑多快」，两件事没有任何关系。

**模板/流水线**

```c
/* 输入：帧长 L 字节、速率 b bit/s、距离 d 米、结点数 m、分组数 n
   输出：T、tau、时延带宽积、总时间，单位统一 ms */
double v = 2e8;                     /* 铜缆/光纤传播速度 */
double T   = L * 8.0 / b * 1e3;     /* 发送时延 ms */
double tau = d / v * 1e3;           /* 传播时延 ms，单程 */
double pipe = d / v * b;            /* 时延带宽积 bit */

double total(int mode) {
    if (mode == 0) return n * T + m * T;              /* 只算存储转发 */
    if (mode == 1) return n * T + tau + T + tau;      /* 1 个路由器加传播 */
    if (mode == 2) return (m + 1) * T;                /* 报文交换 */
    return -1;                                        /* 有处理时延：画图 */
}

/* 例：L=1518B, b=10Mb/s -> T=1.2144ms；d=2000m -> tau=0.01ms
   两者差 121 倍：同一条线路上，帧的发送时间可以远大于传播时间
   例：980000B 文件、分组 1000B（其中头 20B）、2 个路由器
       n = 980000/980 = 1000，T = 0.08ms，总时间 = 1000T + 2T = 80.16ms */
```

! 争用期是 $2\tau$，不是 $\tau$·速率换算用 10 的幂、容量用 2 的幂，别搞反·题目说「忽略传播时延」时公式里一个 $\tau$ 都不许出现

## 信道容量 · 奈氏与香农

**考频**：选择常考，大题未考｜物理层只出单选，服务于 47 题里「链路带宽、传输速率」的参数设定

**必背结论**
- 奈奎斯特（理想无噪声低通）：波特率上限 $2W$ Baud，比特率上限 $C = 2W\log_2 V$，$V$ 是码元种类数即波形数。
- 香农（有噪声）：$C = W\log_2(1+S/N)$，与波形数无关，是理论上限。
- 信噪比换算：$10\lg(S/N)$ dB；10 dB 对应 $S/N=10$，20 dB 对应 100，30 dB 对应 1000，40 dB 对应 10000。
- 一个码元携带 $\log_2 V$ bit，故 $R = B \cdot \log_2 V$，$B$ 是波特率。
- 两个定理同时给：取小的那个，$C = \min(C_{\text{奈}}, C_{\text{香}})$。
- 香农式里当 $S/N \gg 1$ 时可近似 $\log_2(S/N)$，30 dB 就是每赫兹约 9.97 bit，口算按 10 bit/Hz。
- 求波形数的题：先由香农定上限，再由 $2W\log_2 V$ 不小于目标速率反解最小的 $V$，取 2 的整数次幂。
- dB 速记：3 dB 约 2 倍、6 dB 约 4 倍、10 dB 是 10 倍，考试只给 10 的整数倍，直接用表背四个数最快。
- 香农给的是「超不过」的上限，题目问实际速率还要同时满足调制方式的 $\log_2 V$，两个条件并列写出来。

> 奈氏管「无噪声时码元能画几种」，香农管「有噪声时最多能传多少」，两者都要满足时取小。

**模板/流水线**

```c
/* 已知带宽 W(Hz)、信噪比 db、波形数 V，求最大数据率 */
#include <math.h>
double cap(double W, double db, int V) {
    double snr = pow(10.0, db / 10.0);      /* dB 转倍数，用 10lg 不是 20lg */
    double cn  = 2 * W * log2((double)V);   /* 奈氏：无噪声上限 */
    double cs  = W * log2(1 + snr);         /* 香农：有噪声上限 */
    return cn < cs ? cn : cs;               /* 取小者 */
}

/* 反解波形数：要求速率 R，最小 V 满足 2W*log2(V) >= R */
int minV(double W, double R) {
    int V = 2;
    while (2 * W * log2((double)V) < R) V *= 2;   /* V 取 2 的幂 */
    return V;
}

/* 例：W=3kHz、V=4、30dB
   奈氏 2*3000*2 = 12 kb/s；香农 3000*log2(1001) 约 29.9 kb/s
   答案 12 kb/s，取小者
   例：W=4kHz、30dB，要求 20 kb/s，则 log2(V) >= 20000/8000 = 2.5，
       V 取 8（3 bit 每码元，可达 24 kb/s） */
```

! 信噪比用 $10\lg$，别写成 $20\lg$·波特率上限是 $2W$，比特率才乘 $\log_2 V$·两式都给时一定取 min，相加或相乘都是错

## 编码与调制速查

**考频**：选择常考，大题未考｜曼彻斯特与 4B/5B 只出单选，但 2010/2011 的以太网大题默认「以太网用曼彻斯特编码」

**必背结论**
- 曼彻斯特编码：每个比特中间必有一次跳变，高到低记 1、低到高记 0（也可约定相反），1 bit 用 2 个码元，编码效率 50%，自带位同步，10BASE-T 用它。
- 差分曼彻斯特：看比特开始处有无跳变，有跳变记 0、无跳变记 1，抗干扰强于曼彻斯特，效率仍是 50%。
- 4B/5B：每 4 bit 映射成 5 bit，效率 80%，保证不出现长串 0，100BASE-TX 用它再配 MLT-3。
- NRZ：一个码元一个比特，效率 100%，但没有同步能力；NRZI 用「遇 1 跳变」携带时钟，USB 用它。
- 编码效率 = 数据率 / 波特率；反过来求波特率：曼彻斯特乘 2，4B/5B 乘 1.25。
- 基带传输把数字信号直接送上线路，宽带传输要先用 ASK、FSK、PSK 把数字调成模拟。
- 调制效率：ASK/FSK/PSK 各 1 bit 每码元，QAM-16 是 4 bit，QAM-64 是 6 bit。
- 曼彻斯特每个比特有两种可能的波形，接收端靠中间的跳变提取时钟，因此不需要额外的同步信号。
- 4B/5B 的 5 bit 码里 16 个用于数据、其余作控制码，任何组合都不会出现三个以上连 0，跳变足够密。
- 数字例子：给比特串 1011 画曼彻斯特，每位中间画一次跳变，画完数出 4 次跳变、8 个码元，波特率就是数据率的 2 倍。

> 曼彻斯特的波特率是数据率的 2 倍，4B/5B 是 1.25 倍；给数据率求带宽先换波特率，再用 $2W$ 反解。

**模板/流水线**

```c
/* 已知数据率 R(bit/s) 和编码方式，求波特率 B 与所需基带带宽 W */
double baud(double R, int type) {
    switch (type) {
        case 0: return R;          /* NRZ：1 bit 每码元 */
        case 1: return R * 2;      /* 曼彻斯特与差分曼彻斯特 */
        case 2: return R * 1.25;   /* 4B/5B */
        case 3: return R / 4;      /* QAM-16，4 bit 每码元 */
        case 4: return R / 6;      /* QAM-64，6 bit 每码元 */
    }
    return R;
}
double needW(double R, int type) {
    return baud(R, type) / 2.0;    /* 奈氏：2W 是波特率上限 */
}

/* 例：10 Mb/s 用曼彻斯特 -> 20 MBaud -> 需 10 MHz
      100 Mb/s 用 4B/5B -> 125 MBaud -> 需 62.5 MHz
   这就是「提速必须换编码，否则带宽撑不住」的原因 */
```

! 曼彻斯特效率是 50%，不是 100%·4B/5B 是 4 变 5，波特率比数据率大不是小·码元种类与比特数用 $\log_2 V$ 换算，别按倍数硬记

## 停等 GBN SR 利用率

**考频**：2010/2017/2025｜2010 停等算有效速率、2017 GBN 加捎带确认算利用率、2025 又考 GBN 窗口，三年一轮

**必背结论**
- 停止等待：$W_T = 1$，$W_R = 1$，$U = \dfrac{T_1}{T_1 + 2\tau + T_2}$。
- 后退 N 帧 GBN：$W_T \le 2^{n} - 1$，$W_R = 1$；一帧出错，该帧及其后所有帧全部重发；确认是累计的。
- 选择重传 SR：$W_T + W_R \le 2^{n}$，通常取 $W_T = W_R = 2^{n-1}$；只重发出错那一帧，接收方要有缓冲。
- 通用利用率：$U = \dfrac{K\,T_1}{T_1 + 2\tau + T_2}$，$K$ 是发送窗口；忽略确认帧取 $T_2 = 0$，两帧等长取 $T_1 = T_2$，给 RTT 就取 $2\tau = \text{RTT}$。
- 实际数据率 $= U \cdot b$，也等于「有效数据量除以发送周期」；算「有效」时分子扣掉 18 B 首尾，分母里的 $T_1$ 仍按整帧算。
- 反解：$U = 100\%$ 时 $K = (T_1 + 2\tau + T_2)/T_1$，再取最小 $n$ 满足 $K \le 2^{n} - 1$（GBN）或 $K \le 2^{n-1}$（SR）。
- $U = 100\%$ 的含义：发完第 $K$ 帧的瞬间第 1 帧的确认刚好回来，信道一秒都没停，此时实际速率等于带宽。
- 发送周期 = $T_1 + 2\tau + T_2$，从发出第一帧算到收到它的确认，分子分母都按这个口径，别只算单程。
- 数字例子：帧 1000 B、1 Mb/s、RTT 20 ms、两帧等长，$T_1 = 8$ ms，$K = 1$ 时 $U = 8/36 \approx 22\%$；要 100% 需 $K = 4.5$ 取 5，则 $2^{n}-1 \ge 5$，$n = 3$。
- 停等就是 $K = 1$ 的特例，两个公式不必分开背；GBN 把窗口取满 $2^{n}-1$ 时效率最高。

> 窗口与序号的关系只有两条：GBN 是 $K \le 2^{n}-1$，SR 是 $K \le 2^{n-1}$，背错一个整题就崩。

**模板/流水线**

```c
/* 已知帧长 L(B)、速率 b、单程 tau、窗口 K、确认帧长 L2，求利用率 */
double util(double L, double b, double tau, int K, double L2) {
    double T1 = L * 8.0 / b;                   /* 数据帧传输时延 */
    double T2 = (L2 < 0) ? 0 : L2 * 8.0 / b;   /* 忽略确认帧时传 -1 */
    return K * T1 / (T1 + 2 * tau + T2);
}

/* U=100% 反解窗口，再求最小序号比特 n */
int minBits(double L, double b, double tau, double L2, int isSR) {
    double T1 = L * 8.0 / b, T2 = L2 * 8.0 / b;
    int K = (int)ceil((T1 + 2 * tau + T2) / T1);      /* 需要的窗口 */
    int n = 1;
    while (isSR ? (K > (1 << (n - 1))) : (K > (1 << n) - 1)) n++;
    return n;
}

/* 例（2017 型）：n=3 -> K=7；T1=T2=0.08ms，RTT=0.96ms
   U = 7*0.08/(0.08+0.96+0.08) = 0.56/1.12 = 50%
   例（2010 型）：K=1，T1=1.2144ms，T2=0.0512ms，2tau=0.02ms
   U = 1.2144/1.2856 约 94.5%，有效速率 = 1500*8/1.2856ms 约 9.33 Mb/s */
```

! 「有效数据率」分子用 1500 B、分母用 1518 B，同一题两处不同数字·GBN 是累计确认，确认号 3 表示 0、1、2 都收到了·SR 的窗口上限是 $2^{n-1}$ 不是 $2^{n}-1$

## CSMA/CD 争用期与帧长

**考频**：2010（冲突检测与以太网效率）·2022（冲突域）｜唯一以争用期当第 (1) 问的年份，之后只作小问出现

**必背结论**
- 十六字：先听后发、边听边发、冲突停发、随机重发。
- 传播时延 $\tau = d/v$；争用期 $= 2\tau$；最短帧长 $L_{\min} = 2\tau \cdot b$。
- 检测冲突的时间：最短 $\tau$（双方同时发，各等一个单程），最长 $2\tau$（一方快发完时对方才发）——记「最短 $\tau$、最长 $2\tau$」。
- 以太网最短帧长 $L_{\min} = 64$ B；10 Mb/s 以太网争用期 $= 51.2\ \mu s$，按 $2\tau \cdot v$ 反推最大跨距约 5.12 km。
- 帧必须发满争用期才敢认为「没冲突」：帧太短，发完了冲突才传回来，发送方会误判成功。
- 二进制指数退避：第 $k$ 次重传从 $\{0,1,\ldots,2^{k}-1\}$ 中随机取 $r$，推迟 $r \cdot 2\tau$；$k = \min(\text{重传次数}, 10)$；重传到 16 次仍失败就丢弃。
- 收到小于 64 B 的帧一律当冲突碎片丢弃，不算有效帧。
- 以太网不重传也不确认：冲突后由上层超时重发，链路层只负责「发不出去就退避」。
- 100 Mb/s 与 1000 Mb/s 以太网因跨距缩短，争用期仍按 512 bit 的发送时间设计，所以最短帧长还是 64 B。
- 冲突检测靠边发边听：发完还没听到冲突才算成功，所以「发送时间不小于争用期」是安全线。

> 最短帧长的本质是「发送时间不小于争用期」：$L/b \ge 2\tau$，两边乘 $b$ 就是 $L \ge 2\tau b$。

**模板/流水线**

```c
/* 已知电缆长度 d、传播速度 v、数据率 b，求争用期、最短帧长与退避时间 */
double tau  = d / v;               /* 单程传播时延 */
double win  = 2 * tau;             /* 争用期 */
double Lmin = win * b;             /* 最短帧长 bit，再除 8 变字节 */

/* 给定标准最短帧长反推最大跨距 */
double maxD(double Lmin, double b, double v) {
    return (Lmin * 8 / b) / 2 * v; /* 2tau = L/b，故 d = tau*v */
}

/* 第 k 次重传的平均推迟时间：r 平均取 (2^k - 1)/2 */
double backoff(int k, double win) {
    if (k > 10) k = 10;            /* 超过 10 次不再增大 */
    return ((1 << k) - 1) / 2.0 * win;
}

/* 例（2010 型）：d=2000m、v=2e8 -> tau=10us、2tau=20us、b=10Mb/s
   Lmin = 20us * 10Mb/s = 200 bit = 25 B，小于 64 B
   标准取 64 B 更保守，等效于更长的争用期
   第 4 次重传：r 属于 0..15，平均 7.5*20us = 150us */
```

! 争用期是往返的 $2\tau$，用 $\tau$ 乘速率会算小一半·「最短 $\tau$、最长 $2\tau$」方向别反·$k$ 到 10 封顶、16 次丢弃，这两条每年都有人漏

## 以太网帧逐字段解析

**考频**：2011（帧解析加 ARP 与 IP 转发）·2010（1518 B 与 64 B）｜给一段十六进制就要能切出全部字段

**必背结论**
- 前导码 7 B（10101010）加 SFD 1 B（10101011）：物理层加的，用于位同步，不计入帧长。
- 目的 MAC 6 B、源 MAC 6 B、类型 2 B、数据 46 到 1500 B、FCS 4 B（CRC-32）。
- 首部加尾部共 18 B；最短帧 $46 + 18 = 64$ B，最长帧 $1500 + 18 = 1518$ B；加 802.1Q 标签 4 B 后最长 1522 B。
- 数据段最短 46 B 是由 64 B 反推的：$64 - 6 - 6 - 2 - 4 = 46$，不是独立规定。
- 类型字段：0x0800 是 IP，0x0806 是 ARP，0x8100 是 802.1Q，0x86DD 是 IPv6。
- 目的 MAC 首字节最低位为 1 表示组播或广播，FF-FF-FF-FF-FF-FF 全 1 是广播地址。
- 抓包给的十六进制一般从目的 MAC 开始（不含前导码），此时目的 MAC 偏移 0 到 5，类型字段偏移 12 到 13。
- MAC 地址 48 位即 6 字节，写成 12 个十六进制数；前三字节是厂商号 OUI，后三字节由厂商分配。
- 解析顺序固定：先看前 6 字节定目的，再看类型定上层，最后用总长减 18 得数据长度。

> 帧长 = 数据长度 + 18；只要题里出现 1518、64、1522 这三个数，考的就是这节。

**模板/流水线**

```c
/* f[] 是从目的 MAC 开始的一帧十六进制字节流，len 为总字节数 */
void parse(unsigned char *f, int len) {
    int i;
    printf("目的MAC ");  for (i = 0; i < 6; i++)  printf("%02X-", f[i]);
    printf("\n源MAC  "); for (i = 6; i < 12; i++) printf("%02X-", f[i]);

    int type = (f[12] << 8) | f[13];      /* 类型字段，偏移 12 */
    if (type == 0x0800) printf("\n上送 IP\n");
    if (type == 0x0806) printf("\n上送 ARP\n");
    if (type == 0x8100) {                 /* VLAN 帧，数据整体后移 4 B */
        printf("\nVLAN 标签，VID = %d\n", ((f[14] & 0x0F) << 8) | f[15]);
        type = (f[16] << 8) | f[17];
    }

    int dataLen = len - 18;               /* 减掉 6+6+2+4 */
    if (len < 64)         printf("\n小于 64 B：冲突碎片，丢弃\n");
    if (dataLen > 1500)   printf("\n超长帧，非法\n");
    printf("数据 %d B，FCS %02X%02X%02X%02X\n",
           dataLen, f[len-4], f[len-3], f[len-2], f[len-1]);
}

/* 例：收到 64 B 帧 -> 数据 46 B；收到 1518 B -> 数据 1500 B
      带 VLAN 的 1522 B -> 去掉 4 B 标签后按 1518 B 判最长帧 */
```

! 前导码 8 B 不计入帧长，别加到 64 或 1518 里·VLAN 帧要把类型字段偏移加 4 再读·数据段 46 B 是最小值不是固定值

## 交换机自学习与作用域

**考频**：2019/2021/2022｜2019 交换机与路由器、2021 交换表学习、2022 冲突域判定，连续三年都碰

**必背结论**
- 自学习三步：进来就记「源 MAC 加入口端口」；再查目的 MAC，查到只从该口转发，查不到从除入口外的所有口泛洪；回程时表里已有对方，单口转发。
- 转发表项有老化时间，默认 300 s，老化后重新泛洪。
- 直通式交换：只读到目的 MAC 那 6 B 就开始转发，延迟 $= 48/b$；存储转发：收完整帧校验后再发，时间按最短帧 64 B 算 $= 512/b$。
- 冲突域：集线器不隔离，整个集线器连同其主机算一个冲突域；交换机每个端口一个冲突域；路由器隔离冲突域。
- 广播域：交换机默认不隔离，同一 VLAN 是一个广播域；路由器接口与 VLAN 隔离广播域。
- 数冲突域就是数交换机端口数，把每个集线器并到它所连的那个端口里；数广播域就是数路由器接口数加各 VLAN 数。
- 交换机每个端口是独立冲突域，也是独立带宽：全双工下同一端口可同时收发，不再共享。
- 广播帧在同一广播域内泛洪，路由器不转发广播；所以「能不能收到广播」是判广播域最快的标准。
- 转发只看目的 MAC，与 IP 无关；同一交换机下跨子网也要先把帧发给网关的 MAC。

> 集线器是物理层设备，只放大不判断；交换机是链路层设备，按 MAC 表转发——这一句决定所有作用域题。

**模板/流水线**

```c
/* 转发表：表项 = MAC + 端口 + 老化计时 */
struct item { unsigned char mac[6]; int port; int ttl; } tab[64];

void arrive(unsigned char *src, unsigned char *dst, int in) {
    int i, hit = -1;
    for (i = 0; i < n; i++)                    /* ① 进来先记源 */
        if (same(tab[i].mac, src)) { tab[i].port = in; tab[i].ttl = 300; hit = i; }
    if (hit < 0) add(tab, src, in);

    for (i = 0; i < n; i++)                    /* ② 再查目的 */
        if (same(tab[i].mac, dst)) {           /* 查到：单播 */
            forward(tab[i].port);
            return;
        }
    flood_except(in);                          /* 查不到：除入口外泛洪 */
}

/* 直通与存储转发的时间，b 为端口速率 */
double cutThrough(double b)  { return 6 * 8.0 / b; }    /* 48 bit */
double storeFwd(double b)    { return 64 * 8.0 / b; }   /* 512 bit */

/* 例：100 Mb/s 下直通 0.48us、存储转发 5.12us、整帧 1518 B 则 121.44us
   例：8 口交换机，3 个口各接一个集线器（各带 2 台主机），5 个口各接 1 台主机
       冲突域 8 个、广播域 1 个；把其中一个口换成路由器，广播域变 2 */
```

! 直通按 6 B 算时间、存储转发按 64 B，两者不能混·集线器不隔离冲突域，交换机默认不隔离广播域·回程方向表里已有对方，只走一个口，不要再泛洪

## 802.11 地址四字段

**考频**：2022（802.11 地址含义）｜大题里只作为一个小问出现，选择题偶见

**必背结论**
- 802.11 帧最多四个地址，各 6 B，408 只考前三个，第四个只在无线桥接 WDS 时出现。
- 铁律：地址 1 永远是当前接收方 RA，地址 2 永远是当前发送方 TA，地址 3 是最终对端（源或目的，看方向）。
- 去往 AP（主机 A 发给 AP）：地址 1 是 AP 的 BSSID，地址 2 是主机 A，地址 3 是目的主机 B。
- 来自 AP（AP 发给主机 B）：地址 1 是主机 B，地址 2 是 AP，地址 3 是源主机 A。
- 无线主机之间不能直接发，A 到 B 必须两跳：A 发给 AP 一帧，AP 再发给 B 一帧，两帧的地址组合完全不同。
- 帧头里地址 1 从偏移 4 开始（帧控制 2 B 加持续时间 2 B 之后），地址 2 偏移 10，地址 3 偏移 16。
- 802.11 用 CSMA/CA 而不是 CSMA/CD：无线不能边发边听，改用 ACK 确认；可选 RTS/CTS 解决隐蔽站。
- 帧间间隔固定大小顺序：SIFS 最短，DIFS 次之，退避只在 DIFS 之后进行，这决定了谁先抢到信道。
- 地址 4 出现即表示 WDS 桥接，考卷只问前三个；看到四个地址不必慌，按 1 收 2 发 3 对端照样填。

| 方向 | 地址1 接收方 | 地址2 发送方 | 地址3 对端 |
|---|---|---|---|
| A 经 AP 发往 B | AP 的 BSSID | A 的 MAC | B 的 MAC |
| AP 转发给 B | B 的 MAC | AP 的 BSSID | A 的 MAC |
| 有线侧进入 AP | 目的主机 B 的 MAC | AP 的 BSSID | 有线源主机 MAC |

> 口诀「1 收 2 发 3 对端」：先判这一帧是谁在发给谁，再照表填，从不去猜。

**模板/流水线**

```c
/* 按方向填地址：dir=0 主机 A 到 AP，dir=1 AP 到主机 B，dir=2 有线主机 C 经 AP 到 B */
void fillAddr(int dir, char *A, char *B, char *AP, char *C, char *out[3]) {
    if (dir == 0) {              /* 去往 AP：收方是 AP */
        out[0] = AP;             /* 地址1 = BSSID */
        out[1] = A;              /* 地址2 = 源主机 */
        out[2] = B;              /* 地址3 = 目的主机 */
    } else if (dir == 1) {       /* 来自 AP：收方是主机 B */
        out[0] = B;              /* 地址1 = 目的主机 */
        out[1] = AP;             /* 地址2 = AP 自己 */
        out[2] = A;              /* 地址3 = 源主机 */
    } else {                     /* 有线侧经 AP 发给 B */
        out[0] = B;              /* 地址1 = 无线目的主机 */
        out[1] = AP;             /* 地址2 = AP 自己 */
        out[2] = C;              /* 地址3 = 有线源主机 */
    }
}

/* 例：A=00-AA、AP=00-11、B=00-BB
   A 发 AP 帧：地址1=00-11、地址2=00-AA、地址3=00-BB
   AP 发 B 帧：地址1=00-BB、地址2=00-11、地址3=00-AA
   两帧的地址 1、2 恰好互换，考的就是这个「换位」 */
```

! 地址 1 是接收方不是目的方，两者在 A 发给 AP 时重合，最容易记混·地址 3 去 AP 时是目的、来 AP 时是源·不要漏掉「A 到 B 要两帧」这件事

## PPP与HDLC及VLAN

**考频**：选择常考，大题未考｜服务 47 题里「链路层封装、帧长变化」这一类小问

**必背结论**
- PPP 帧：标志 0x7E、地址 0xFF、控制 0x03、协议 2 B、信息、FCS 2 B（可协商 4 B）。
- PPP 面向字节：异步传输用 0x7D 做字节填充（转义 0x7E 和 0x7D 本身），同步传输用零比特填充。
- PPP 只检错不纠错：无序号、无确认、不保证可靠交付；只支持点对点全双工；用 LCP 建链、NCP 配网络层。
- HDLC 帧：标志 0x7E、地址 1 B、控制 1 或 2 B、信息、FCS 2 或 4 B；面向比特，用零比特填充（连发 5 个 1 插一个 0）。
- PPP 与 HDLC 都以 0x7E 为标志，区别是 PPP 面向字节且不可靠，HDLC 面向比特且可靠（有编号有确认）。
- VLAN：802.1Q 标签 4 B，等于 TPID 0x8100（2 B）加 TCI（2 B，PRI 3 bit、DEI 1 bit、VID 12 bit），插在源 MAC 之后。
- VID 取值 0 到 4095，可用范围 1 到 4094；带标签后最长帧 $1518 + 4 = 1522$ B。
- 交换机端口：Access 口收发都不带标签，Trunk 口跨交换机时带标签。
- 不同 VLAN 之间不能直接通信，必须经路由器或三层交换机，这是 VLAN 隔离广播域的代价。
- PPP 与 HDLC 都是点对点协议，不能用于总线型广播网络；以太网才是广播型链路的代表。
- 零比特填充与字节填充都是透明传输手段，目的是让数据里出现 0x7E 时不被误认成帧标志。

> 看到类型字段 0x8100 就是 VLAN 帧，后面所有偏移整体加 4，这一条能救回一整问。

**模板/流水线**

```c
/* 判断是否 VLAN 帧并给出真实类型，返回数据段起始偏移 */
int vlanCheck(unsigned char *f, int len, int *type) {
    *type = (f[12] << 8) | f[13];
    if (*type != 0x8100) return 14;          /* 普通帧，数据从 14 起 */
    int tci = (f[14] << 8) | f[15];
    int vid = tci & 0x0FFF;                  /* 低 12 位是 VID */
    *type = (f[16] << 8) | f[17];            /* 真实类型后移 4 B */
    printf("VLAN %d, PRI %d\n", vid, tci >> 13);
    return 18;                               /* 数据从 18 起 */
}

/* 零比特填充：连 5 个 1 后插 0（HDLC 与同步 PPP 用） */
void bitStuff(char *in, char *out) {
    int i, cnt = 0, j = 0;
    for (i = 0; in[i]; i++) {
        out[j++] = in[i];
        if (in[i] == '1') { if (++cnt == 5) { out[j++] = '0'; cnt = 0; } }
        else cnt = 0;
    }
    out[j] = 0;
}

/* 例：原串 01111111110（10 个 1）填成 01111101111100
      带 VLAN 的 1522 B 帧，去掉 4 B 标签后按 1518 B 判最长帧 */
```

! 802.1Q 标签插在源 MAC 之后，不是帧首·零比特填充是插 0，接收端对应删 0·PPP 不可靠，别写成「有确认重传机制」
