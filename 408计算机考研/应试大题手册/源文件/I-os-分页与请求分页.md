## 分页拆位总模板
**考频**：2013/2015/2017/2018/2020/2024（OS 大题）｜页大小一换就能再考一次，拆位是所有分页题的第一问，5–8 分
**必背结论**
- 页面大小 $2^k$ 字节 → 页内偏移 $k$ 位（4KB → 12 位，1KB → 10 位，2MB → 21 位）。
- 页号位数 $m = n - k$（$n$ 为逻辑地址位数）；进程页数 = 页表项数 = $2^m$。
- 页表大小 $= 2^m \times e$（$e$ 为页表项长）；页表占页数 $= \lceil 2^m e / 2^k \rceil$。
- 页框号位数 = 物理地址位数 $- k$；页框数 = 内存容量 / 页面大小。
- 页表项里只存页框号，不存物理地址：物理地址 $=$ 页框号 $\times 2^k +$ 偏移。
- 页号与页框号都从 0 编号；页号隐含在「第几项」里，不占表项空间。
- 反向题（408 常考）：偏移 $k$ 位 → 页有 $2^k$ 个地址；页号 $m$ 位 → 最多 $2^m$ 页；页框号 $f$ 位 → 内存最多 $2^f$ 个页框。
- 页表占页数一律向上取整，剩 1 字节也要占整整一页；页表项个数只等于页数，与项多长无关。

| 题目给的条件 | 落笔就写的结论 |
|---|---|
| 页面大小 4KB | 偏移 12 位，页内 2^12 个地址 |
| 页面大小 1KB | 偏移 10 位 |
| 逻辑地址 32 位、页 4KB | 页号 20 位，共 2^20 页 |
| 逻辑地址 20 位、页 4KB | 页号 8 位，共 256 页 |
| 页表项 4B | 一页放 1024 项，一级索引 10 位 |
| 物理内存 256MB | 物理地址 28 位，页框号 16 位 |
| 偏移 2 位、页框号 2 位 | 页 4 个地址、页框 4 个、总地址 16 个 |

> 三步：拆（÷页大小取商余）→ 换（页号换成页框号）→ 拼（页框号×页大小+偏移）；偏移从第一步到最后一步一位都不动。

数字例子：逻辑地址 20 位（虚址空间 $2^{20}$ = 1MB）、页 4KB。$k=12$、$m=8$ → 256 页 → 页表 $256\times 4$B $=1$KB → 占 1 个页框。虚址 `0x1A2B4`：低 12 位 `0x2B4` 是偏移，高 8 位 `0x1A` = 26 是页号；页表第 26 项存页框号 0x05 → 物理地址 `0x052B4`。
同一个进程换成 32 位虚址：页号 20 位 → $2^{20}$ 页 → 单级页表 $4$MB $=1024$ 页，这才逼出二级页表。

**模板/流水线**
```c
/* 拆位流水线：所有分页题共用的前 6 行 */
k = log2(page_size);              /* 4KB->12, 1KB->10, 2MB->21 */
m = n - k;                        /* 页号位数 */
entries = 1 << m;                 /* 页表项数 = 进程页数 */
pt_bytes = entries * e;           /* e = 页表项长，真题多为 4B */
pt_pages = (pt_bytes + page_size - 1) / page_size;

W = addr & ((1 << k) - 1);        /* 页内偏移：低 k 位 */
P = addr >> k;                    /* 页号：其余高位 */
F = pagetable[P].frame;           /* 查表只取页框号 */
pa = (F << k) | W;                /* 拼接：页框号在高、偏移在低 */
```
! 页表项存的是页框号不是物理地址，忘了乘页大小就差 $2^k$ 倍·十六进制里 ×2^12 是加 3 个 0，但 ×4 只是左移 2 位，不是加零·题目不说「按字节编址」时只能写 2^12 个地址，直接写 4KB 不严谨

## 多级页表拆位流水线
**考频**：2013/2015/2017/2018/2020/2024（OS 大题）｜二级页表是内存大题的绝对主力；三级大题未考，只作二级的直接推广
**必背结论**
- 二级地址 $=P_1$（页目录号）＋ $P_2$（页表索引）＋ $W$；三级再加一段 $P_3$，各段位数之和 = 地址总位数。
- 唯一硬约束：最低 $k$ 位永远是偏移，其余高位按题目给的分段从左往右切。
- 每级索引位数 $=\log_2$(一页能放的项数)$=\log_2(2^k/e)$；4KB 页 + 4B 项 $=1024$ 项 $=10$ 位。
- 32 位地址 + 4KB 页 + 4B 项 → 10｜10｜12，两级刚好用完；要三级得 42 位（10｜10｜10｜12）。
- 级数 = 查表访存次数：一级 2 次、二级 3 次、三级 4 次（末次是取数）。
- 名称对应：一级页号 = 页目录号，二级页号就叫页号；页目录项存下一级表的页框号，页表项存数据页的页框号。
- 「访问了几张二级页表」只看页目录号：两个地址页目录号相同 → 只访问 1 张；不同才算 2 张。
- 分段顺序不能颠倒：页目录号占高位、偏移占低位，写反了地址全错，先画一遍二进制再动笔。

| 级数 | 地址结构 | 查表访存 |
|---|---|---|
| 一级 | 页号 + 偏移 | 1 次 |
| 二级 | 页目录号 + 页号 + 偏移 | 2 次 |
| 三级 | 索引1 + 索引2 + 索引3 + 偏移 | 3 次 |

数字例子（正向）：虚址 `0x10801008`、页 4KB、项 4B、结构 10｜10｜12。写成二进制 `0001 0000 1000 0000 0001 0000 0000 1000`，从高位数 10 位 → 页目录号 `0x042`，再 10 位 → 页号 `0x001`，末 12 位 → 偏移 `0x008`。

数字例子（反向，2018 型）：给页目录号 6、页号 6、偏移 8，各写成 10/10/12 位再拼 `0000000110 0000000110 000000001000` $=$ `0x01806008`。

数字例子（三级）：42 位虚址、页 4KB、项 4B → 10｜10｜10｜12；页目录 1 张、二级最多 1024 张、三级最多 $2^{20}$ 张，实际只为用到的那一支建表，走表 3 次加取数 1 次共 4 次访存。

> 10 位、12 位都不是 4 的整数倍，必须先把地址写成完整二进制再切，硬凑十六进制必错。

**模板/流水线**
```c
/* 三级页表走表：每一级都只是「基址 + 索引 * 项长」 */
uint64_t walk(uint64_t va, uint64_t dir_base) {
    int k = 12, s = 10;                 /* 偏移 12 位，每级索引 10 位 */
    uint64_t W  = va & ((1 << k) - 1);
    uint64_t i3 = (va >> k) & ((1 << s) - 1);
    uint64_t i2 = (va >> (k + s)) & ((1 << s) - 1);
    uint64_t i1 = (va >> (k + 2*s)) & ((1 << s) - 1);  /* 剩余高位全给 i1 */
    uint64_t p1 = *(uint32_t *)(dir_base + i1*4);      /* 页目录项 -> 页框号 */
    uint64_t p2 = *(uint32_t *)((p1 << k) + i2*4);     /* 先乘页大小还原首址 */
    uint64_t p3 = *(uint32_t *)((p2 << k) + i3*4);
    return (p3 << k) | W;               /* 页框号在高，偏移原样 */
}
```
! 页目录项里存的是页框号，取下一级表首址必须先乘页大小·三级最少访存 4 次，别照二级的 3 次套·各段位数之和写完先加一遍，不等于地址总位数就是拆错了

## 页表项物理地址计算
**考频**：2013（OS 大题）｜地址拆分之后必问的落地一步，同一套公式连问两问
**必背结论**
- 页表项物理地址 = 页表首地址 $+$ 页号 $\times$ 页表项长度。
- 页目录项物理地址 = 页目录表首地址 $+$ 页目录号 $\times$ 页目录项长度。
- 二级页表首地址 = 上级表项里存的页框号 $\times$ 页面大小，所以二级页表首址不用另存。
- 一级页表（页目录）的首地址必须存：一个进程只有一张，放页表基址寄存器 / PCB 里。
- 页表必须连续存放，否则「首址 + 页号 × 项长」这条公式不成立；这也是二级页表要解决的问题。
- 页号占的位置是「第几项」，像数组下标一样不占存储；但页表本身一定在内存里，要访存。
- 问「某项的地址」分三步写：算项地址 → 读出里存的页框号 → 乘页大小得下一级首址。
- 地址变换靠物理地址访存，所以「这一项在哪」必须先算出来，这一步也是 2013 那道题给分的落脚点。

| 题目问的是 | 套哪条公式 |
|---|---|
| 页表里第 p 项在哪 | 页表首址 + p × 项长 |
| 页目录表第 d 项在哪 | 页目录表首址 + d × 项长 |
| 二级页表在哪 | 页目录项里的页框号 × 页大小 |
| 数据页在哪 | 页表项里的页框号 × 页大小 |

数字例子：页目录表首址 `0x00201000`、页目录项 4B、页目录号 `0x042` → `0x00201000 + 0x042×4 = 0x00201000 + 0x108 = 0x00201108`。该表项存页框号 `0x00301` → 二级页表首址 `0x00301×2^12 = 0x00301000`；二级页号 `0x001` → 页表项地址 `0x00301000 + 4 = 0x00301004`；若该项存 `0x00401`，数据页首址 `0x00401000`，加偏移 `0x008` 得 `0x00401008`。
另一组数：页表首址 `0x00100000`、页号 `0x123`、项长 4B → 项地址 `0x00100000 + 0x48C = 0x0010048C`，因为 `0x123×4` 在二进制里就是左移 2 位。

**模板/流水线**
```c
/* 两级页表：从虚地址一路算出每个表项所在地址 */
pa_dir = dir_base + P1 * e;        /* 页目录项地址 */
f1 = *(uint32_t *)pa_dir;          /* 取出二级页表的页框号 */
pa_pt = (f1 << k) + P2 * e;        /* 二级页表项地址：先乘页大小再加 */
f2 = *(uint32_t *)pa_pt;           /* 取出数据页的页框号 */
pa = (f2 << k) + W;                /* 最终物理地址 */
```
! 十六进制乘 4 不是加两个 0：`0x042×4` 是 `0x108`，要左移 2 位·忘了「页框号 << k」直接把页框号当首址，后面全错·「表项的地址」与「表项里存的页框号」是两个不同的量

## 多级页表占页数估算
**考频**：2015（OS 大题）｜二级页表题必问的第二问，标准答案常是 1025 页
**必背结论**
- 一页能放的项数 = 页面大小 / 页表项长度；4KB / 4B $=1024$ 项，与进程大小无关。
- 单级页表占页数 $=\lceil 2^m e / 2^k \rceil$。
- 二级占页数 $=1$（页目录）$+$ 二级页表张数，张数 $=2^m/1024$。
- 2015 标准数：$2^{20}$ 页 → 1024 张二级页表 $+$ 1 张页目录 $=1025$ 页。
- 反直觉：全满时二级比单级（1024 页）多 1 页，多的就是页目录自己。
- 分级真正省的是「连续性」：单级要 4MB 连续，二级每张表只要 1 页连续。
- 三级同理：页目录 1 张 $+$ 中间层张数 $+$ 末级张数，逐层用上一层项数除以每表项数。
- 题目按「该进程所有页面都已装入」算；实际运行时二级页表只为用到的那一支建。
- 占页数正比于进程页数，只有「每页表项数」这一项与进程大小无关。
- 二级页表的每一项指向一个数据页（不是下一级表），所以张数 = 页数 ÷ 每表项数；只有三级才多出「中间层」。
- 页表项长度按题目给的算：给 4B 就是 4B，题目改成 8B 则每页只放 512 项、索引变 9 位。

| 页大小 / 项长 | 一张表页能放几项 | 对应索引位数 |
|---|---|---|
| 4KB / 4B | 1024 | 10 位 |
| 4KB / 8B | 512 | 9 位 |
| 1KB / 4B | 256 | 8 位 |
| 2MB / 4B | 524288 | 19 位 |

数字例子：页 4KB、项 4B、$2^{20}$ 页。单级页表 $2^{20}\times 4$B $=4$MB $=1024$ 页；二级每张表 1024 项 → 1024 张 $+$ 页目录 1 张 $=1025$ 页。若进程只用到 3 页，二级只需 2 页，单级仍要 4MB。
数字例子二：逻辑地址 22 位、页 4KB → 页号 10 位 → 1024 页 → 单级页表 $1024\times 4$B $=4$KB 恰好 1 页；若改成二级，要 1 张页目录 $+$ 1 张页表 $=2$ 页，分级反而多占 1 页——分级只在进程很大时才划算。

**模板/流水线**
```c
/* 多级页表内存开销：先算项数，再算页数 */
n_entries = 1 << m;                    /* 总页数 = 总表项数 */
per_page  = page_size / e;             /* 一张表页放几项 */
n_tables  = (n_entries + per_page - 1) / per_page;   /* 二级表张数 */
total     = n_tables + 1;              /* 别忘了页目录那一页 */
bytes     = total * page_size;         /* 问内存开销才乘 */
```
! 全满时二级比单级多 1 页，别背成「分级一定更省」·页目录永远只有一张，先把「+1」写上再算张数·问「共占多少页」答页数，问「占多少内存」要再乘页大小

## 访存次数统计模板
**考频**：2009（OS 大题）｜TLB + 缺页 + LRU 三件套那道题的计数部分
**必背结论**
- 查 TLB 不算访存次数（相联存储器，只另计时）；TLB 命中直接得页框号，省掉查页表。
- 查页表每级 1 次访存；取数 1 次访存，Cache 命中则省掉。
- 二级页表：TLB 命中 1 次、未命中 3 次；三级：命中 1 次、未命中 4 次。
- 缺页那一次要另算磁盘 I/O 次数，不进「访存次数」。
- 总式：访存次数 $=N\times[(1-h)L+(1-c)]$，$h$ 为 TLB 命中率，$L$ 为页表级数，$c$ 为 Cache 命中率。
- 命中率、缺页率都按「访问次数」统计；一条指令访存多次就按次算，不按条算。
- TLB 用页号（标记）查，在 MMU 里；Cache 用物理地址查，在 CPU 与内存之间，两者串联不是二选一。
- 无 TLB 时页表访存次数就是级数 $L$，与 Cache 命中率完全解耦，可以分开算。
- Cache 命中与否只影响最后取数那 1 次，一次也不会影响查页表的 $L$ 次。
- 题目问「访问内存几次」时把查 TLB 排除在外；只有问「访问存储系统几次」才把 TLB 一起算进去。
- 缺页处理完重新执行该指令时会再查一次表，题目若把 TLB 更新算进去就按命中处理。

| 情形 | 访存次数 |
|---|---|
| TLB 命中 + Cache 命中 | 0 次 |
| TLB 命中 + Cache 未命中 | 1 次 |
| TLB 未命中 + Cache 命中（二级页表） | 2 次 |
| TLB 未命中 + Cache 未命中（二级页表） | 3 次 |

数字例子一：1000 次数据访问、二级页表、TLB 命中率 0.9、Cache 命中率 0.95 → $1000\times[0.1\times 2+0.05]=250$ 次访存。
数字例子二：没有 TLB、二级页表、Cache 命中率 0.9 → $1000\times[2+0.1]=2100$ 次访存，是前者的 8 倍多。
数字例子三：1000 次访问缺页 12 次 → 缺页率 1.2%；每次缺页换出加换入算 2 次盘访问 → 24 次盘 I/O，这 24 次一律不进访存次数。

**模板/流水线**
```c
/* 访问次数统计：访存与访盘两个计数器，别合并 */
long mem = 0, disk = 0;
for (i = 0; i < N; i++) {
    if (!tlb_hit(va)) {            /* TLB 未命中 */
        mem += L;                  /* 逐级查页表，每级 1 次 */
        if (!present(va)) {        /* 存在位为 0 -> 缺页 */
            disk++;                /* 换入/换出各算一次盘访问 */
            /* 处理完改页表与 TLB，再【重新执行】本条指令 */
        }
    }
    if (!cache_hit(pa)) mem += 1;  /* 取数未命中 Cache 才访存 */
}
```
! 查 TLB 不算访存次数但算时间，两个口径别混·缺页的磁盘 I/O 单列，别塞进访存次数·TLB 命中省掉的是查页表的 L 次，取数那 1 次永远省不掉

## 有效访问时间 EAT
**考频**：2009（OS 大题）｜TLB + 缺页的「访问时间」就是这条公式的代入
**必背结论**
- 主式 $EAT=(1-p)t_a+p\,t_f$，$p$ 为缺页率，$t_a$ 为不缺页的一次访问时间，$t_f$ 为缺页处理时间。
- 有 TLB 时 $t_a=h(t_{tlb}+t)+(1-h)(t_{tlb}+Lt)$，$h$ 为 TLB 命中率。
- 无 TLB 且单级页表 $t_a=2t$；无 TLB 且二级页表 $t_a=3t$ ——先算 $t_a$，再乘 $(1-p)$。
- 缺页处理含磁盘寻道与传输，量级是毫秒，比访存大 4 个数量级。
- 缺页率 $10^{-4}$ 就能把 EAT 拉到 7–10 倍量级，这是「虚拟存储不能滥用」的量化依据。
- 命中率 $=1-p$，两者是同一件事的两面；$h$ 与 $p$ 相互独立，不能相加也不能互推。
- 问「加速比」用不缺页时间除以 EAT，问「慢多少倍」用 EAT 除以不缺页时间。
- 单位先统一：$t$、$t_{tlb}$ 用 ns，$t_f$ 给的是 ms 就先乘 $10^6$ 再代。
- 缺页率每降一个数量级，$p\,t_f$ 就降一个数量级——减少缺页比加快访存有效得多。
- 同时给 TLB 与 Cache 时按「TLB → 页表 → Cache → 内存」四段串起来列，漏掉 Cache 段是最常见的错。
- 口径先统一：$p=1-$命中率；题目给「平均每 100 万次访问缺一次页」就直接取 $p=10^{-6}$。
- 卷面写法三段：先写 $t_a$ 的式子，再写 EAT 的式子，最后代数字——只给一个数最多拿一半分。

$$EAT=(1-p)\left[h(t_{tlb}+t)+(1-h)(t_{tlb}+Lt)\right]+p\,t_f$$

数字例子一（有 TLB）：$t=100$ns、$t_{tlb}=10$ns、$h=0.9$、$L=2$、$p=10^{-4}$、$t_f=8$ms。$t_a=0.9\times 110+0.1\times 210=120$ns；$EAT=0.9999\times 120+0.0001\times 8\,000\,000\approx 920$ns，比不缺页慢约 7.7 倍。
数字例子二（无 TLB、单级）：$t_a=200$ns、$p=10^{-5}$、$t_f=8$ms → $EAT\approx 200+80=280$ns，可见哪怕缺页率再小，$p\,t_f$ 也是主导项。
数字例子三（提高命中率）：$h=0.98$ 时 $t_a=0.98\times 110+0.02\times 210=112$ns，$EAT\approx 112+80=192$ns，比 $h=0.9$ 时的 920ns 好得多——瓶颈已经转回缺页。

| 参数 | 含义 | 常见取值 |
|---|---|---|
| t | 一次访存时间 | 100 ns |
| t_tlb | 查一次 TLB | 10 ns |
| t_f | 缺页处理（含磁盘） | 8 ms |
| p | 缺页率 | 10^-4 到 10^-6 |

**模板/流水线**
```c
/* EAT 代入流水线：先算不缺页的时间，再按概率加权 */
double t_a = h*(t_tlb + t) + (1-h)*(t_tlb + L*t);  /* 命中/未命中两段 */
double eat = (1-p)*t_a + p*t_f;                    /* p 是缺页率 */
double ratio = eat / t_a;                          /* 缺页把性能拉低几倍 */
```
! 缺页率是「每次访问缺页的概率」，不是缺页次数除以页数·$t_f$ 带磁盘时间，先统一成 ns 再代入·$h$ 与 $p$ 是两个独立参数，不能相加也不能互推

## 置换算法填表模板
**考频**：2009/2010/2012（OS 大题）｜置换表是送分块，画错一格后面全错
**必背结论**
- OPT：往后看，淘汰最长时间内不再被访问的；理论下界，不可实现。
- FIFO：队列，淘汰最先进来的；命中不改变队列顺序；唯一会出现 Belady 异常。
- LRU：往前看，淘汰最久没被访问的；要维护访问历史（栈或计数器）。
- CLOCK：访问位 0 就换出，1 就清 0 后移；命中只置 1，指针不动。
- 改进 CLOCK：淘汰顺序 $(0,0)\to(0,1)\to(1,0)\to(1,1)$；新调入页 $A=1$、$M=0$。
- 缺页次数 $\neq$ 置换次数：前几次还有空闲页框，只缺页不置换。
- Belady 异常只发生在 FIFO：同一走向 3 块缺页 9 次、4 块反而 10 次。
- 缺页率 = 缺页次数 / 访问总次数：上表 20 次访 12 次缺页即 60%，FIFO 15 次即 75%。
- 加页框只对 FIFO 可能变差；OPT 与 LRU 都不会出现 Belady 异常。

| 算法 | 淘汰谁 | 往哪看 |
|---|---|---|
| OPT | 未来最久才用到的 | 后 |
| FIFO | 最先进来的 | 队列 |
| LRU | 最久没用过的 | 前 |
| CLOCK | 访问位为 0 的 | 转圈 |
| 改进 CLOCK | 00 先走、11 最后 | 访问位+修改位 |

填表格式（走向 7 0 1 2 0 3 0 4 …，3 个页框，FIFO 前 8 列）：

| 页面走向 | 7 | 0 | 1 | 2 | 0 | 3 | 0 | 4 |
|---|---|---|---|---|---|---|---|---|
| 块1（最旧） | 7 | 7 | 7 | 0 | 0 | 1 | 2 | 3 |
| 块2 | — | 0 | 0 | 1 | 1 | 2 | 3 | 0 |
| 块3（最新） | — | — | 1 | 2 | 2 | 3 | 0 | 4 |
| 缺页 | √ | √ | √ | √ | · | √ | √ | √ |

同一条 20 次走向的总数：OPT 缺页 9 次、FIFO 15 次、LRU 12 次。

> 缺页栏打 √ 求和就是缺页次数；命中率 = 1 − 缺页次数 / 访问总次数；问「置换次数」要减掉还有空闲页框的那几次。

改进 CLOCK 的四步（每次淘汰都从头走一遍）：

1. 扫一圈找 $(A=0,M=0)$，找到就淘汰，本轮不改任何标志位。
2. 若失败，再扫一圈找 $(A=0,M=1)$，把扫过的页 $A$ 清 0。
3. 若仍失败，重复第 1 步（此时所有 $A$ 都已是 0，必能找到）。
4. 若仍失败，重复第 2 步。

数字例子：4KB 页、两个页框放页 3（$A=1,M=0$，在 60H）与页 4（$A=1,M=1$，在 80H），访问 `02A01H` → 页号 `02H` 存在位 0，缺页；第 1、2 步都失败，第 3 步淘汰已变 $(0,0)$ 的页 3 → 物理地址 `60H×4KB + A01H = 60A01H`。

**模板/流水线**
```c
/* 三种算法共用的填表骨架：只换 pick_victim 一行 */
for (i = 0; i < n; i++) {
    v = ref[i];
    if (find(v) >= 0) { fault[i] = 0; touch(v); continue; }  /* 命中 */
    fault[i] = 1;
    if (has_free_frame()) { place(v); continue; }   /* 只缺页，不置换 */
    j = pick_victim();      /* OPT/LRU/FIFO/CLOCK 的唯一差别 */
    evict(j); place(v);
}
faults = sum(fault);                             /* 缺页次数 */
repl   = faults > frames ? faults - frames : 0;  /* 置换次数 */
```
! 前几次缺页有空闲页框，只缺页不置换，两个数必须分开·FIFO 命中不改变队列顺序，改了就全错·CLOCK 命中只把访问位置 1，只有发生淘汰才移动指针

## 请求分页完整访存流程
**考频**：2024（OS 大题·大页分页缺页）｜流程题年年以「这一步谁做、几次访存、什么中断」出现
**必背结论**
- 顺序：拆虚址 → 查 TLB → 查多级页表 → 缺页中断 → 拼物理地址 → 查 Cache → 访主存。
- 请求分页页表项 = 页号 + 页框号 + 状态位 + 访问字段 + 修改位 + 外存地址。
- 存在位 0 → 缺页；修改位 1 → 换出要写回外存；访问位供置换算法用。
- 缺页中断是内中断（内部异常），发生在指令执行期间，一条指令可多次缺页。
- 缺页处理完是「重新执行」被中断的指令，不是执行下一条。
- 无空闲页框时：选牺牲页 → 脏页写回 → 调入新页 → 改页表与 TLB → 重新执行。
- 大页（页变大）的直接后果：偏移位数变多、页表项数变少，其余流程一字不改。
- 驻留集是「页框的集合」、工作集是「页面的集合」，驻留集不能小于工作集，否则频繁缺页。
- 三种分配策略：固定分配局部置换、可变分配全局置换、可变分配局部置换。
- 缺页处理五步：看有无空闲页框 → 无则选牺牲页 → 脏页写回 → 调入新页 → 改页表与 TLB 并重新执行。
- 缺页率与缺页发生在哪一级页表无关，只与访问序列和页框数有关。

| 步 | 做什么 | 谁做 | 访存 |
|---|---|---|---|
| 1 | 拆虚址为页号与偏移 | 硬件 | 0 |
| 2 | 查 TLB 比标记与有效位 | 硬件 | 0 |
| 3 | 逐级查页表取页框号 | 硬件 | L 次 |
| 4 | 判存在位，为 0 发缺页中断 | 硬件 | 0 |
| 5 | 调页 / 置换 / 脏页写回 | 操作系统 | 访盘 |
| 6 | 拼物理地址、查 Cache 取数 | 硬件 | 0 或 1 次 |

数字例子：32 位虚址、页 2MB（大页）→ $k=21$，页号 11 位 → 2048 页，偏移 `0x1FFFFF`，页号 `va>>21`。页变大只改了 $k$，后 6 步一步没变。

**模板/流水线**
```c
/* 一次访存的完整流水线，任何一支都可能被单独提问 */
W = va & (page_size - 1);
P = va >> k;
if (tlb_tag(P) == P && tlb_valid(P)) {
    F = tlb_frame(P);                       /* 命中：1 次访存搞定 */
} else {
    for (s = 0; s < L; s++)                 /* 逐级查表，L 次访存 */
        pte = read_mem(base[s] + idx[s]*4);
    if (!pte.present) {
        page_fault();                       /* 内中断，转内核态 */
        if (pte.modified) write_back(pte);   /* 脏页先写回外存 */
        F = alloc_or_replace(P);            /* 置换算法在这里 */
        pte.present = 1; pte.modified = 0; pte.accessed = 1;
        tlb_fill(P, F);
        retry_instruction();                /* 重新执行本条指令 */
    }
    F = pte.frame; tlb_fill(P, F);
}
pa = (F << k) | W;
if (cache_hit(pa)) return cache_read(pa);
return mem_read(pa);                        /* 未命中再访存并调入 */
```
! 缺页中断是内中断、在指令执行期间产生，写成外中断或「执行后」就错·缺页返回是重新执行本条指令，不是下一条·TLB 与页表必须同步更新，否则会反复缺页

## 软硬件互斥代码模板
**考频**：选择常考，大题未考｜服务于 PV 大题第（1）问「为什么必须互斥」与四准则辨析，PV 大题见总表 2009/2011/2013/2015/2017/2020 各行
**必背结论**
- 临界区四部：进入区、临界区、退出区、剩余区；四准则：空闲让进、忙则等待、有限等待、让权等待。
- 关中断只对单 CPU 有效，多处理机上别的 CPU 照样能进；开关中断是特权指令，用户程序不能用。
- TestAndSet 把「读旧值」与「置 1」做成一条原子指令；Swap 原子交换 lock 与局部 key，二者本质相同。
- 二者都靠 while 空转，只满足前三条，不满足让权等待。
- 只有记录型信号量的 P 操作能实现让权等待；整型信号量仍是忙等。
- 单标志法必须交替用（违空闲让进）；双标志先检查不能互斥；双标志后检查会饥饿。
- 共享变量（如信号量 S 的 value）本身就是临界资源，对它读写必须互斥。
- 判定四步：先看「检查」与「置标志」谁在前 → 再找「两个同时进」或「两个都进不去」的反例 → 再看进不去时是空转还是阻塞 → 最后逐条对四准则。
- 单标志法用 turn 交替、初值就定死谁先进，所以违背空闲让进；双标志后检查两人都置 true 后互相等，会饿死。
- Peterson 的 turn 是「最后写入者吃亏」，能保证至少一个进程进得去，所以不饥饿。

| 方法 | 互斥 | 空闲让进 | 有限等待 | 让权等待 |
|---|---|---|---|---|
| 单标志法 | 能 | 否 | 能 | 否 |
| 双标志先检查 | 否 | 能 | 能 | 否 |
| 双标志后检查 | 能 | 否 | 否 | 否 |
| Peterson | 能 | 能 | 能 | 否 |
| 关中断 | 能 | 能 | 能 | 否 |
| TS 指令 / Swap | 能 | 能 | 能 | 否 |
| 记录型信号量 | 能 | 能 | 能 | 能 |

**模板/流水线**
```c
/* ① 关中断：单 CPU 最省事，多处理机无效 */
void enter_cs(void) { disable_int(); }   /* 特权指令，只能内核态执行 */
void exit_cs(void)  { enable_int();  }

/* ② TestAndSet：硬件保证「读旧值 + 置 1」不可分割 */
int TestAndSet(int *lock) {
    int old = *lock;      /* 读旧值 */
    *lock = 1;            /* 立即置 1，与上一行原子 */
    return old;
}
while (TestAndSet(&lock)) ;   /* 返回 1 表示别人占着，继续空转 */
/* 临界区 */
lock = 0;                     /* 退出区：普通写即可释放 */

/* ③ Swap：原子交换，key 是每个进程自己的局部变量 */
void Swap(int *a, int *b) { int t = *a; *a = *b; *b = t; }
int key = 1;
do { Swap(&lock, &key); } while (key);   /* key 被换成 0 才算拿到锁 */
/* 临界区 */
lock = 0;

/* ④ 记录型信号量：唯一能实现让权等待的 */
void wait(sem *S)  { S->value--; if (S->value < 0) block(S->list); }
void signal(sem *S){ S->value++; if (S->value <= 0) wakeup(S->list); }
```
! 关中断只对单 CPU 有效，多处理机上另一个核照样进临界区·TS 与 Swap 只是写法不同，判定结论完全一样，都是忙等·能互斥不等于四准则全满足，Peterson 就偏偏缺让权等待
