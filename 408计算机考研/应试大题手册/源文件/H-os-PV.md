## PV 大题五步流程
**考频**：2009/2011/2013/2014/2015/2017/2019/2020/2021/2022/2023/2024/2025（第45或46题）｜16 年里考了 13 次，只有 2010/2012/2016/2018 四年的 OS 大题位置被别的考点占掉；7–8 分
**必背结论**
- 判分只看三个点：定义了**几个**信号量、每个的**初值**、P/V 摆的**位置**。分号、花括号、`while` 全是形式分。
- 五步顺序不能乱：数资源 → 定信号量 → 写进程骨架 → 摆 P/V → 检查。
- 总口诀：**互斥初值 1，同步初值 0，资源量初值 n；先发生的后面 V，后发生的前面 P。**
- 卷面统一写 `P()`/`V()`。题面若用 `wait()/signal()`，全文替换为 `wait=P`、`signal=V`，一份答案里绝不许混写两种。
- 题面里的「等」「必须等到」「才能」「若有…则」四个字眼，一律落成 P 操作。
- 动笔前先画图：把约束画成前驱图或资源流向图，图画完信号量个数就自己浮出来了。
> 答题纸先写信号量声明区（含每个信号量的含义注释），再写进程区——顺序反了容易写着写着漏一个。

**模板/流水线**
| 步 | 你要做的动作 | 落笔成什么 |
|---|---|---|
| ① 数资源 | 圈出题里所有「一台/一个/N 个」和「最多/一次只能/必须」 | 一张资源清单，标出哪些被两个以上进程共用 |
| ② 定信号量 | 共用且要独占 → 互斥；有先后 → 同步；有数量 → 计数 | `semaphore` 声明，每个后面跟一句含义 |
| ③ 写进程骨架 | 按题给的进程个数和循环结构逐个写空壳 | 几个 `while(1){ }`，进程数与题面一致 |
| ④ 摆 P/V | 资源/前驱先 P，自己产出或完成后 V，互斥夹在临界区两侧 | 每个 P 前问「我在等什么」，每个 V 前问「我给出了什么」 |
| ⑤ 检查 | 照下面 8 条清单逐条打勾 | 只改错，不重写 |

为什么第一步必须是数资源：408 的 PV 题信号量个数通常落在 3–5 个，个数错一个，后面 P/V 的位置一定跟着错。改卷口径里「定义了哪几个信号量、初值多少」是第一采分点，「P/V 摆在哪」是第二采分点，剩下的都是形式分。所以草稿纸上先写四行清单——资源名、类型（互斥/同步/计数）、初值、谁 P 谁 V，写完再落笔。

### 检查清单（照抄到草稿纸）
- 每个 P 都能一句话回答「我在等什么」；答不出的 P 就是多余的。
- 每个 V 都能一句话回答「我释放了什么」；答不出的 V 就是错的。
- 资源信号量（empty/full）的 P 是否在 mutex 的 P **之前**。
- 初值：互斥是不是 1、同步是不是 0、资源是不是题给的那个数。
- 有没有一个信号量在表达两种含义（缓冲区奇偶混装、一个锁管两个信箱）——该拆。
- 有没有给同一进程内的天然先后写了信号量——该删。
- P 与 V 是否成对、个数是否相等。
- 信号量数组是否用 `for` 循环赋初值（`chopstick[n]=1` 这种写法直接扣分）。

```c
/* ===== 答题纸第 1 段：信号量声明区（先写完，别边写进程边加） ===== */
semaphore mutex  = 1;    /* 互斥量：初值恒为 1，管一个临界资源 */
semaphore empty  = n;    /* 资源量：初值 = 题给的剩余数量，不是容量时要注意减 */
semaphore full   = 0;    /* 同步量：初值 0，或题给的「已有数量」 */

/* ===== 答题纸第 2 段：按题给进程数照抄结构 ===== */
void P1() { while (1) {
    /* ① 先 P 掉自己需要的资源 + 所有前驱的同步量 */
    /* ② 再 P 互斥量进临界区，临界区里只放「取/放」那一下，立刻 V 出来 */
    /* ③ 最后 V 自己产出的资源 + 后继的同步量 */
} }
```
! 只写 mutex 不写同步量（或反之）是最常见的丢分方式，一道题往往两者都要·信号量个数少一个扣一半，宁可多定义也别漏·「说明信号量含义及初值」是白送分小问，别省

## 信号量初值对照表
**考频**：2009/2011/2013/2014/2015/2019/2020（每年改卷最盯这一栏）｜初值写错，整题的逻辑分一起没了
**必背结论**
- 初值只有三个来源：**1**（互斥）、**0**（同步/前驱边）、**题给的那个数**（资源剩余量或已有数量）。
- 互斥量初值不是 1 就不再是互斥，而变成了同步量——改卷老师最认这条判定依据。
- 资源量要分清「剩多少」和「有多少」：空位初值 = 容量 − 已有数，满位初值 = 已有数。
- 同一个信号量不能背两种含义。缓冲区里既有奇数又有偶数，`full` 必须拆成 `odd`/`even`。
- 一个互斥量只管一个临界资源：两个信箱就要两个 `mutex`。
- 信号量数组必须 `for` 循环赋初值，这是形式分里唯一会真扣分的一条。
- 初值决定进程第一次能不能通过：同步量初值 0，没人 V 就永远过不去，顺序的强制力就来自这一点；资源量初值 n，前 n 个进程不用等。

**模板/流水线**
| 类型 | 初值 | 一句话含义 | P/V 摆法 |
|---|---|---|---|
| 互斥量 | 1 | 临界资源只有 1 份 | P 在临界区前、V 在临界区后，把临界区整个包住 |
| 同步量 | 0 | 事件尚未发生 | 先发生的进程**后面**加 V，后发生的进程**前面**加 P |
| 空位资源量 | 容量 n 或 M−x | 现在还能放几个 | 放入前 P，被取走一个后 V |
| 已有数量 | 初始数量 x | 现在已有几个可取 | 取出前 P，放入一个后 V |
| 限流计数 | min(m, n−1) | 至多几人同时抢资源 | 抢资源前 P，全部还清后 V |
| 前驱边 | 0 | 该前驱尚未完成 | 每条**跨进程**边一个，绝不共用 |
| 信号量数组 | 逐个 1 | 每份同类资源一个 | `for` 循环逐个赋 1 |

初值算法只有两种：题面给「容量 M，已有 x 个」→ 空位 M−x、满位 x；题面给「一次只能一个」→ 1。凡是题里出现减法，一定对应「已经有东西占着」。凭感觉写 0 或 1 的，八成是把同步量当成了互斥量。

```c
semaphore mutex = 1;          /* 互斥：出入口/缓冲区/文件，只有 1 份 */
semaphore empty = 500;        /* 资源剩余：馆内还能进 500 人 */
semaphore full  = 0;          /* 同步：初始没有产品可取 */
semaphore odd   = 0;          /* 拆出来的同步量：缓冲区里的奇数个数 */
semaphore even  = 0;          /* 拆出来的同步量：缓冲区里的偶数个数 */
semaphore chop[5];            /* 数组：5 根筷子，每根初值 1 */
int i;
for (i = 0; i < 5; i++) chop[i] = 1;   /* 必须循环赋值，一条语句赋全数组不合法 */
```
! 互斥写成 0、同步写成 1 是零分答案，顺序会整个反过来·`empty` 别一律当容量，题里说「已有 x 个」就要用 M−x·定义了六个信号量错一个初值，老师会判「未掌握同步互斥」

## 生产者—消费者模板
**考频**：2009/2014/2022｜母题，三件套背下来可套六成年份
**必背结论**
- 三件套：`mutex=1`、`empty=缓冲区容量`、`full=0`（初始为空）。
- 单缓冲就是把容量换成 1；多缓冲为 N 就用题给的 N，其余一字不改。
- 铁律：`empty`/`full` 的 P **必须**在 `mutex` 的 P 之前，写反 = 死锁。
- 死锁原因：先 P(mutex) 拿到锁，再 P(empty) 因满而阻塞，锁没释放；消费者想取却拿不到锁，双方僵持。
- `mutex` 一层管三方互斥：生产者之间、消费者之间、生产者与消费者之间。
- V 的先后无所谓，习惯先 `V(mutex)` 再 `V(full)`；但 P 的顺序一个都不能动。
- 2009 变体：缓冲区混装奇偶，一个 `full` 分不出奇偶，必须拆 `odd`/`even`；统计 `countodd()` 在临界区外做，不互斥。
- 为什么 V 可换而 P 不可换：P 是「申请」，稀缺的那个（空位/产品）必须先申请，不够就尽早阻塞；占着锁去等，等于把锁带进了等待队列。

**模板/流水线**
```c
semaphore mutex = 1;      /* 缓冲区互斥：同一时刻只许一个进程碰缓冲区 */
semaphore empty = N;      /* 空位个数，初值 = 缓冲区容量 N */
semaphore full  = 0;      /* 满位个数，初始空，故 0 */

Producer() { while (1) {
    produce();                       /* 生产在临界区外，不互斥 */
    P(empty);                        /* 要用一个空位：满了就在这里等 */
    P(mutex);                        /* 空位已占住，再抢缓冲区锁 */
    put();                           /* 临界区只包「放」这一下 */
    V(mutex);                        /* 放完立刻放锁 */
    V(full);                         /* 多了一个产品，唤醒等产品的消费者 */
} }

Consumer() { while (1) {
    P(full);                         /* 要有产品才能取：空的就在这里等 */
    P(mutex);                        /* 有货了，再抢锁 */
    get();                           /* 临界区只包「取」这一下 */
    V(mutex);
    V(empty);                        /* 腾出一个空位，唤醒等空位的生产者 */
    consume();                       /* 消费在临界区外 */
} }
```

```c
/* 2009 变体：三进程，缓冲区混装奇偶 → 把 full 拆成 odd/even */
semaphore mutex = 1, empty = N, odd = 0, even = 0;

P1() { while (1) {                   /* 生产者 */
    x = produce();
    P(empty); P(mutex); put(x); V(mutex);      /* 放这一步互斥 */
    if (x % 2 == 1) V(odd); else V(even);      /* 按奇偶分派给两个消费者 */
} }

P2() { while (1) {                   /* 取奇数 */
    P(odd);                          /* 缓冲区里有奇数才取 */
    P(mutex); getodd(); V(mutex);    /* 取这一步互斥 */
    V(empty);                        /* 腾出空位 */
    countodd();                      /* 统计不需要互斥，放临界区外 */
} }

P3() { while (1) {                   /* 取偶数，与 P2 完全对称 */
    P(even);
    P(mutex); geteven(); V(mutex);
    V(empty);
    counteven();
} }
```
! 2009 若只用一个 `full`，P2/P3 会在奇数堆里取到偶数·统计类操作放临界区外，加锁反而扣「并发度」·生产者不能用一个信号量管奇偶两种产出

## 读者—写者与计数互斥
**考频**：2019（读者—写者变体）｜「计数＋双锁」是最容易少写一行的那类题
**必背结论**
- 双锁结构：`rw=1` 管文件本身，`mutex=1` 管计数器 `count`；`count` 是普通整型变量，不是信号量。
- 首个读者替全体读者 `P(rw)` 挡住写者；末个读者 `V(rw)` 放行写者；中间读者直接进——这就是「计数型互斥」。
- 读者侧的 `count++` 与 `count--` 前后各要一对 `P(mutex)`/`V(mutex)`。
- 写者只有一对 `P(rw)`/`V(rw)`，因为写者天生独占。
- 2019 的变体只需换皮：把「读文件」换成「占共享资源」，「写文件」换成「独占使用」，骨架一个字不改。
- 写者优先的改法：加门卫 `w=1`，写者先 `P(w)` 再 `P(rw)`，写完 `V(w)`；读者也先 `P(w)`，`count` 更新完立刻 `V(w)`，只要有写者在等，新读者就进不来。
- 独木桥、哲学家、图书馆座位都是这一族的换皮题。
> 判断口诀：**能同时来多个的当读者，只能一个来的当写者。**

**模板/流水线**
```c
int count = 0;                 /* 当前读者数，普通变量，不是信号量 */
semaphore mutex = 1;           /* 只保护 count 的互斥量 */
semaphore rw    = 1;           /* 文件与写者互斥，初值 1 = 当前无人用 */

Reader() { while (1) {
    P(mutex);                  /* 先锁住计数器 */
    if (count == 0) P(rw);     /* 我是第一个读者：挡住所有写者 */
    count++;                   /* 读者数 +1，后来的读者靠 count>0 直接进 */
    V(mutex);                  /* 计数器用完立刻放，别的读者才能进 */
    读文件;                    /* 真正的临界操作在 mutex 之外，读者之间并行 */
    P(mutex);                  /* 离开前再锁计数器 */
    count--;                   /* 读者数 -1 */
    if (count == 0) V(rw);     /* 我是最后一个：放开写者 */
    V(mutex);
} }

Writer() { while (1) {
    P(rw);                     /* 有人读或有人在写就在这里等 */
    写文件;                    /* 独占临界区 */
    V(rw);                     /* 写完放开，读者和写者都可能被唤醒 */
} }
```
! 第二个 `P(mutex)`（`count--` 那一侧）最容易漏，漏了 `count` 会算错·`if (count == 0) P(rw)` 必须在 `P(mutex)` 保护之内·读者优先会让写者饿死，要求「写者优先」时再加一个门卫信号量 `w`

## 前驱图与先后同步
**考频**：2021（流水线装配）/2023/2024/2025（同步 PV）｜纯前驱边是同步的最简形式，几乎每年换皮出现
**必背结论**
- 每条**跨进程**的前驱边一个信号量，初值**全 0**；边的**起点**操作之后 V，边的**终点**操作之前 P。
- 同一进程内的天然先后（A→E→F）**绝对不写**信号量——线程自己就是串行的。
- 一个操作有多条入边 → 前面连续写多个 P；有多条出边 → 后面连续写多个 V。
- n 个操作不一定是 n 个信号量：信号量个数 = **跨进程边数 m**，通常 m 小于 n。
- 2011 银行叫号里「叫号 → 顾客上前接受服务」只有一条跨进程边，就是最小的前驱图。
- 2013 博物馆里「进门 → 参观 → 出门」全在同一个进程内，天然有序，一个信号量都不用写（它要的是限流和门锁）。
- 命名用「起点→终点」：`S_AC` 一眼能对上边，比 `s1`/`s2` 好改卷；题面给 `cobegin/coend` 就照抄，别自创进程名。
- 链式前驱不能合并：S1→S2→S3 是两条边、两个信号量，不能因为「都是顺序」就只写一个，否则 S3 可能在 S2 之前跑。

**模板/流水线**
```c
/* 以 5 个操作 A–E 为例：C 需 A、B 完成后执行；E 需 C、D 完成后执行 */
semaphore a = 0;      /* A→C 这条边：A 未完成则为 0，C 的 P 会阻塞 */
semaphore b = 0;      /* B→C */
semaphore c = 0;      /* C→E */
semaphore d = 0;      /* D→E */

A() { ...; V(a); }                    /* 起点之后 V：宣告「我完成了」 */
B() { ...; V(b); }
C() { P(a); P(b); ...; V(c); }        /* 终点之前 P：等齐全部前驱；完成后 V 自己的出边 */
D() { ...; V(d); }
E() { P(c); P(d); ...; }              /* 两条入边，两个 P 连着写 */
```
! 机械「每条边一个信号量」会把同进程内顺序也写上，2022 就靠这点扣分·一条边一个信号量，两条边共用会让 P 提前通过·V 写在「本操作全部做完」之后，P 写在「第一句要用的东西」之前·初值写成 1 就退化成互斥，顺序完全失效

## 限流容量信号量
**考频**：2013（博物馆限流 500 人）｜只有「进」没有「取」，写成 empty/full 一对就是错的
**必背结论**
- 只有占名额、还名额，没有取走资源的一方 → **只需要一个**计数信号量 `empty=容量`。
- `full` 用不上：没有消费者，不产生「可取数量」这个概念。
- 「出入口一次仅许一人通过」是另一个互斥量 `mutex=1`，进门和出门都要包。
- 顺序：`P(empty)` 必须在 `P(mutex)` 之前。反了就是满员时有人攥着门锁等名额，把出门的人也堵在门外 = 死锁。
- `V(empty)` 必须在出门之后，代表名额真正还回来了。
- 限流与互斥不是一回事：互斥保证「一次只有一个」，限流只保证「总数不超过 N」。500 人的馆里可以同时有 500 人在参观，这就是限流的证据。
- 哲学家变体（n 人、m 个碗、每两人一根筷子）：限流计数 `S = min(m, n−1)`，把同时抢筷子的人压到 n−1，破坏循环等待。

**模板/流水线**
```c
semaphore mutex = 1;        /* 出入口互斥：一次只许一人通过 */
semaphore empty = 500;      /* 馆内剩余容量，初值 = 最大容纳人数 */

Visitor_i() { while (1) {
    P(empty);               /* 馆内没满才允许靠近门口；满了在门外等 */
    P(mutex);               /* 门口一次一人 */
    进门;
    V(mutex);               /* 通过门口即放锁，别把门锁带进参观阶段 */
    参观;
    P(mutex);               /* 出门同样要独占门口 */
    出门;
    V(mutex);
    V(empty);               /* 已离馆，腾出一个名额 */
} }
```

```c
/* 哲学家变体：n 人围桌，m 个碗，每两人一根筷子 */
semaphore S = min(m, n - 1);        /* 至多 n-1 人同时抢，必有人能拿齐 */
semaphore bowl = m;                 /* m 个碗 */
semaphore chop[n];
int i;
for (i = 0; i < n; i++) chop[i] = 1;  /* 每根筷子初值 1 */

Philosopher_i() { while (1) {
    P(S);                           /* 限流：先把同时抢的人数压下来 */
    P(bowl);                        /* 要有碗才能吃 */
    P(chop[i]);                     /* 左筷子 */
    P(chop[(i + 1) % n]);           /* 右筷子 */
    eat();
    V(chop[i]); V(chop[(i + 1) % n]);
    V(bowl);
    V(S);                           /* 全部还清后才放开限流名额 */
    think();
} }
```
! 「最多容纳 N 人」不等于「要 empty/full 一对」，先问有没有取走的一方·`V(empty)` 忘写 = 馆内人数只增不减·限流信号量 P 必须在最外层、V 在最后，夹在中间就等于没限流

## 连续 k 次才释放
**考频**：2014（环形缓冲区，消费者连续取 10 件）｜错误写法最多的一道真题
**必背结论**
- 两层锁缺一不可：`mutex1` 管缓冲区，`mutex2` 管「这一整组 10 次」。
- `P(mutex2)` 在 `for` **外面**，`V(mutex2)` 在 `for` **后面**——这一组才是原子的。
- `P(full)`、`P(mutex1)` 必须在 `for` **内部**：P 一次只保证「至少 1 件」，不保证「连续 10 件」。
- 「下一个取货的必须换人」这个要求靠 `mutex2` 在组与组之间互斥实现，`mutex1` 做不到。
- 环形缓冲区：`in = (in+1) % 1000`、`out = (out+1) % 1000`，取模不能漏。
- 生产者侧完全不受约束：题目只限制消费者，别给生产者套 `mutex2`，那会把并发度砍掉。
- 若题目反过来要求「生产者连续放 k 件、期间别人不许放」，把 `mutex2` 挪到生产者侧，骨架一模一样；两边都要求就是两把外层锁。谁被要求「连续」，锁就套在谁身上。
- 自查只要问一句：缓冲区里只有 3 件产品时这段代码会不会卡住？会卡住就是 `P(full)` 写到循环外了。

**模板/流水线**
```c
semaphore mutex1 = 1;        /* 缓冲区互斥：所有生产者/消费者共用 */
semaphore mutex2 = 1;        /* 消费者之间「连续取 10 件」这一组的互斥 */
semaphore empty  = 1000;     /* 环形缓冲区容量 1000，初始空 */
semaphore full   = 0;        /* 初始无产品 */
int in = 0, out = 0;

Producer() { while (1) {
    P(empty);                /* 有一个空位才放 */
    P(mutex1);               /* 抢缓冲区锁，且必须在 empty 之后 */
    放入产品; in = (in + 1) % 1000;
    V(mutex1);
    V(full);                 /* 多一件产品 */
} }

Consumer() { while (1) {
    P(mutex2);                        /* 外层锁：占住「这一组」的资格 */
    for (int i = 1; i <= 10; i++) {
        P(full);                      /* 每取一件都要单独 P：保证真有 10 件 */
        P(mutex1);                    /* 每件都单独抢缓冲区锁 */
        取出产品; out = (out + 1) % 1000;
        V(mutex1);
        V(empty);                     /* 每件都还一个空位，生产者才能继续放 */
    }
    V(mutex2);                        /* 10 件取完才放开资格 */
} }
```
! 只写一个 mutex：两个消费者能同时进 for，连续 10 件的要求没实现·`P(mutex1)` 提到 for 外面：空缓冲区时持有缓冲区锁去等 full，生产者拿不到锁 = 死锁，而且这 10 件里禁止了生产者插入（题目并未禁止）·`P(full)` 提到 for 外面：只保证有 1 件，缓冲区里只有 3 件时第 4 次循环就卡死

## 对称同步双重信箱
**考频**：2015（两人信箱辩论）｜生产者—消费者的双向包装，两个方向完全镜像
**必背结论**
- 两个信箱 = **两组**信号量，绝不能用同一个 `mutex` 管两个信箱。
- A 信箱：`emptyA = M − x`（剩余空位）、`fullA = x`（已有邮件数）；B 信箱：`emptyB = N − y`、`fullB = y`。
- 初值是**题给的剩余量**，不是容量 M/N——这题最大的坑就在这里。
- A 的代码与 B 完全镜像：把 A/B 互换，一行逻辑都不用改。
- 每个进程做两件事：先从自己信箱取（走 `fullA`＋`mutexA`），再往对方信箱投（走 `emptyB`＋`mutexB`），两组方向不能串。
- 「互相等对方来信」构成对称同步：两人可能同时卡在取信上，谁也没投信 → 必须靠题给的初始邮件 x、y 打破僵局，这就是初值写 x、y 而不是 0 的原因。
- 答题顺序：两组信号量与四个初值写在最上面（主要采分点集中在初值），再完整写 A，最后写「B 与 A 对称」——对称能省一半篇幅，但 A 的每一行必须真的对。

**模板/流水线**
```c
semaphore mutexA = 1, mutexB = 1;          /* 两个信箱各一把锁，不能合并 */
semaphore emptyA = M - x, emptyB = N - y;  /* 剩余空位：容量减已有 */
semaphore fullA  = x,     fullB  = y;      /* 已有邮件数：题给的初始值 */

A() { while (1) {
    P(fullA);                  /* A 信箱里要有对方的信才能取 */
    P(mutexA);                 /* 取信动作互斥 */
    取出对方的问题;
    V(mutexA);
    V(emptyA);                 /* 取走一封，A 信箱多一个空位 */
    回答问题并提出新问题;
    P(emptyB);                 /* B 信箱不满才能投，满了在这里等 */
    P(mutexB);                 /* 投信动作互斥 */
    将新邮件放入 B 信箱;
    V(mutexB);
    V(fullB);                  /* B 信箱多一封信，唤醒在等信的 B */
} }

B() { /* 与 A 完全对称：P(fullB)→取→V(emptyB)；P(emptyA)→投→V(fullA) */ }
```
! 初值写 M、N 而不是 M−x、N−y 是本题零分点·两个信箱共用一个 `mutex` = 互斥范围错·取信用 fullA、投信用 emptyB 与 fullB，串了就是往自己信箱投

## 方向互斥独木桥
**考频**：2017（独木桥）｜读者—写者的换皮题：同方向当读者，反方向当写者
**必背结论**
- 同方向可同时上桥 → 每个方向一套「计数器＋保护计数器的 mutex」；桥本身一个 `bridge=1`。
- 第一个上桥的人 `P(bridge)` 锁住方向，最后一个下桥的人 `V(bridge)` 放行对面。
- 中间的人不碰 `bridge`，只加减计数，所以同向能并行。
- 若题面改成「桥上一次只允许一人通过」，就退化成单个 `mutex=1` 包住「过桥」，不需要计数。
- 两个方向的 `cnt` 和 `mutex` 各一套，共用一个会让两个方向互相串。
- 计数器只在 `mutex` 内加减，`if (cnt == 0)` 的判断也必须在锁内。
- 题面的「桥上不能掉头」或「一次只允许同方向的人通过」是同一句话：方向锁在整段通过期间不许释放；若再加「桥最多承载 8 人」，就在外面再叠一个限流信号量。

**模板/流水线**
```c
int cntA = 0, cntB = 0;           /* 两个方向各自在桥上的人数 */
semaphore mutexA = 1, mutexB = 1; /* 各自计数器的互斥量，不能合并 */
semaphore bridge = 1;             /* 桥的使用权：初值 1 = 桥空 */

GoRight() { while (1) {
    P(mutexA);                    /* 保护 cntA */
    if (cntA == 0) P(bridge);     /* 我是本方向第一个人：把桥从对面手里抢过来 */
    cntA++;                       /* 后续同向的人 cntA>0，不再抢 bridge，直接上桥 */
    V(mutexA);
    过桥;                          /* 同方向可并行通过 */
    P(mutexA);                    /* 下桥也要改计数，先锁 */
    cntA--;
    if (cntA == 0) V(bridge);     /* 本方向最后一人：放开桥给对面 */
    V(mutexA);
} }

GoLeft() { /* 与 GoRight 镜像：mutexB / cntB，桥锁同样是 bridge */ }
```
! `P(bridge)` 写到 `if (cntA == 0)` 外面 = 同方向也只能一人过桥，违背题意的并行要求·`cntA--` 与 `V(bridge)` 都必须在 `P(mutexA)` 内·两个方向共用一套 cnt/mutex 会让「同向并行」失效，还可能死锁

## 售票与流水线变体
**考频**：2020/2021/2022/2023/2024/2025（连续六年）｜近六年全是老朋友换皮，识别出族属就直接默写模板
**必背结论**
- 三问定族属，顺序不能换：**有没有「取走」的一方**？有 → 产消族（empty/full 一对）；没有 → 限流族（只要 empty）。这一问定了这道题的大部分分数，答错后面全白写。
- **有没有「先后」**？有 → 每条跨进程边一个 0 初值同步量；流水线就是「每段传送带 = 一个容量 n 的缓冲区」。
- **有没有「一次只能一个」**？有 → `mutex=1` 包住临界动作。
- 售票是「两向握手」：顾客 V 一个「我来了」、售票员 V 一个「票好了」，两个方向各一个 0 初值同步量，外加窗口互斥量。
- 流水线 = 前驱链 ＋ 产消：K 个工位有 K−1 段传送带，每段一对 `empty=n`/`full=0`，每个工位一个 `mutex`。
- 考场节奏：这道题给 8 分钟——2 分钟判族属并写声明区，5 分钟写进程体，1 分钟逐条过检查清单。族属判对，剩下是默写；族属判错，写满也拿不到位置分。

**模板/流水线**
| 年份 | 变体 | 信号量设置 | 破题点 |
|---|---|---|---|
| 2020 | 售票/服务窗口 | 窗口 `mutex=1` ＋ 两个反向同步量 | 顾客与售票员不互斥，只握手 |
| 2021 | 流水线装配 | 每段传送带 `empty=n` `full=0` | 相邻工位一对同步量，别跨级定义 |
| 2022 | 缓冲区同步 | 产消三件套，容量按题给 | 先看「已有 x 个」还是「初始为空」 |
| 2023 | 同步 PV | 两条反向同步量 ＋ `mutex=1` | 交替执行就是两个 0 初值互锁 |
| 2024 | 同步 PV | 计数 ＋ 同步混搭 | 先数资源个数，再定同步方向 |
| 2025 | 同步 PV | 以同步为主，可能无互斥 | 通篇没有共享变量就别硬加 mutex |

```c
/* 售票：窗口互斥 ＋ 两向握手（顾客与售票员之间不互斥，只同步） */
semaphore mutex = 1;      /* 窗口互斥：同一时刻只有一位顾客在窗口 */
semaphore req   = 0;      /* 顾客已到窗口，初值 0 = 还没人来 */
semaphore resp  = 0;      /* 票已办好，初值 0 = 还没出票 */

Customer_i() {
    P(mutex);                       /* 占住窗口 */
    递上钱和证件;
    V(req);                         /* 通知售票员：我来了（先发生者 V） */
    P(resp);                        /* 等票办好（后发生者 P）；此间仍持窗口锁 = 窗口只服务一人 */
    取走车票和找零;
    V(mutex);                       /* 让出窗口，下一位才能上前 */
}

Clerk() { while (1) {
    P(req);                         /* 有人来才干活，没人就等 */
    收钱、打票;
    V(resp);                        /* 票好了，通知顾客 */
} }
```

```c
/* 流水线装配：3 个工位，2 段传送带，每段容量 1 */
semaphore empty1 = 1, full1 = 0;    /* 工位1 → 工位2 的传送带 */
semaphore empty2 = 1, full2 = 0;    /* 工位2 → 工位3 */
semaphore mutex1 = 1, mutex2 = 1;   /* 两段传送带各自互斥 */

Station1() { while (1) {
    加工零件;                        /* 加工自己干，不互斥 */
    P(empty1);                       /* 传送带 1 有空位才放 */
    P(mutex1); 放到传送带1; V(mutex1);
    V(full1);                        /* 传送带 1 多一件 */
} }

Station2() { while (1) {
    P(full1); P(mutex1); 从传送带1取; V(mutex1); V(empty1);   /* 先取上一段 */
    加工零件;
    P(empty2); P(mutex2); 放到传送带2; V(mutex2); V(full2);   /* 再放下一段 */
} }

Station3() { while (1) {
    P(full2); P(mutex2); 从传送带2取; V(mutex2); V(empty2);
    装配;
} }
```
! 流水线别只写前驱同步量却漏掉传送带容量，上游比下游快时零件会无限堆积·售票题给顾客和售票员之间加 mutex 是过度互斥，扣分·判族属之前不要动笔，写错族属改起来比重写还慢
