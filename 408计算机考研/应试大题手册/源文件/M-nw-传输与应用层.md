## UDP 与 TCP 对比表
**考频**：选择常考，大题未考｜传输层大题的送分入口，服务 2016/2023/2026 的开头（先定协议再算数）
**必背结论**
- UDP 首部固定 8 B，四个字段各 2 B：源端口、目的端口、长度、校验和。
- 长度字段 = 首部 + 数据，$L_{总}=8+L_{数据}$，所以最小值为 8，最大 65535，数据上限 65507 B。
- TCP 首部最小 20 B，带选项最大 60 B（数据偏移 4 位 × 4 B）。
- UDP 无连接、不可靠、保留报文边界；TCP 面向连接、可靠、面向字节流、全双工。
- 选 UDP 的判据是「一句请求一句应答就够」：重传和建连的时延比丢一个报文的代价更贵，所以 DNS、DHCP 这类一次问答的业务宁可自己重发。
- 端口 16 位：0–1023 熟知端口（DNS 53、HTTP 80、FTP 21 与 20）；1024–49151 登记端口；49152–65535 客户端临时端口。
- 复用是按源端口把多进程数据合到传输层，分用是按目的端口把数据交给进程；套接字 = IP + 端口。
- 首部里的「窗口」字段是 TCP 才有的，含义是接收窗口。

| 对比项 | UDP | TCP |
|---|---|---|
| 连接 | 无连接，直接发 | 三次握手建立，四次挥手释放 |
| 可靠性 | 不可靠，出错丢弃不重传 | 确认加重传，可靠有序不重复 |
| 数据单位 | 用户数据报，保留报文边界 | 字节流，不保留边界 |
| 首部开销 | 8 B | 20 B，带选项最多 60 B |
| 流量控制 | 没有 | 滑动窗口，rwnd 由接收方通告 |
| 拥塞控制 | 没有 | 慢开始、拥塞避免、快重传、快恢复 |
| 通信方式 | 一对一、一对多、多对多 | 只能一对一，全双工 |
| 典型应用 | DNS、DHCP、TFTP、实时音视频 | HTTP、FTP、SMTP、Telnet |

**模板/流水线**
```c
/* UDP 首部 8 B = 四个 2 B 字段，按字节定位 */
字节 0-1 : 源端口
字节 2-3 : 目的端口
字节 4-5 : 长度（首部 + 数据，最小 8，最大 65535）
字节 6-7 : 校验和（填 0 表示不校验）

/* 三个必算数 */
长度字段 = 数据长度 + 8;
数据部分 = 长度字段 - 8;
校验和覆盖 = 12 B 伪首部（源 IP 4 + 目的 IP 4 + 0 + 协议 17 + UDP 长度 2）+ 首部 + 数据

/* 与 TCP 的分工速判 */
要可靠 / 有序 / 面向字节流  -> TCP（首部 20 B，端口 80、21）
要低延迟 / 小报文 / 自己重传 -> UDP（首部 8 B，端口 53、67、69）
```
! 把 UDP 的「长度」当成数据长度——它是首部加数据的全长，最小 8·UDP 也算校验和，只是校验和可填 0 表示不校验，别答成 UDP 没有校验和·UDP 8 B、TCP 20 B 这两个数考试不给，必须背

## TCP 首部逐字段
**考频**：2012｜逐字节解析一套十六进制首部是那道 5 分组题的骨架，2016/2023/2026 的握手题也要靠字段定位
**必背结论**
- 序号 32 位：本报文段数据第一个字节的编号，是字节编号，不是第几个报文段。
- 确认号 32 位：期望收到的下一个字节编号 = 已正确收到的最后一个字节 + 1；只有 ACK = 1 时才有效。
- 数据偏移 4 位：首部长度，单位 4 B，$首部字节数=数据偏移值\times 4$；值 5 即 20 B，值 15 即 60 B。
- 六个标志位各 1 位：URG、ACK、PSH、RST、SYN、FIN；握手挥手只动 SYN、ACK、FIN。
- 窗口 16 位：接收窗口 rwnd，单位字节，16 位最大 65535 B，要更大得用窗口扩大选项。
- 校验和 16 位：覆盖首部 + 数据 + 12 B 伪首部（源 IP 4 + 目的 IP 4 + 0 + 协议 1 + TCP 长度 2）。
- 其余字段：源端口 16、目的端口 16、紧急指针 16、选项（MSS、窗口扩大、SACK、时间戳）。
- MSS 选项只在 SYN 里出现，声明「我能收的报文段最大多少字节」；它同时也是拥塞窗口的单位，看到 MSS 就该想到 TCP。
- 数字例子：seq = 100、长度 100 B ⇒ 占用 100–199，对方回 ack = 200。
- 首部里只有三处值得逐位看：标志位判阶段、序号与确认号算字节、窗口判还能发多少；其余字段扫一眼带过即可。
**模板/流水线**
```c
/* 前 40 B = IP 首部 20 B + TCP 首部 20 B，每 4 B 一行共 10 行 */
行 1-5 : IP 首部（版本 + 首部长度 | 总长度 | 标识 | 标志 + 片偏移 | TTL | 协议 = 6 | 校验和 | 源 IP | 目的 IP）
行 6   : 源端口 2 B + 目的端口 2 B
行 7   : 序号 seq 4 B
行 8   : 确认号 ack 4 B
行 9   : 数据偏移 4 bit + 保留 6 bit + 六个标志 6 bit 共 2 B，紧跟窗口 2 B
行 10  : 校验和 2 B + 紧急指针 2 B

/* 三步判定 */
/* 1. 定方向：源 IP 等于主机 IP，就是主机发的 */
/* 2. 定阶段：SYN=1 且 ACK=0 -> 第 1 次握手；SYN=1 且 ACK=1 -> 第 2 次；
 *            只有 ACK=1 且 seq 等于上次的 ack -> 第 3 次握手或数据段 */
/* 3. 定字节：序号与确认号都是字节编号，直接相减或加 1 */
```
! 数据偏移单位是 4 B，不是 1 B，算出 20 别再乘一次·序号是字节编号，seq = 1000 与「第 1000 个报文段」毫无关系·大写 ACK 置位小写 ack 才生效，题目给 ack 先看标志位

## TCP 三次握手流水线
**考频**：2012/2016/2023/2026｜传输层大题第一小问的固定开局，四年都从这里起算
**必背结论**
- 第 1 步：SYN = 1，seq = x，不带数据，消耗 1 个序号。
- 第 2 步：SYN = 1 且 ACK = 1，seq = y，ack = x + 1，不带数据，消耗 1 个序号。
- 第 3 步：ACK = 1，seq = x + 1，ack = y + 1，可以携带数据。
- x 与 y 各自随机独立，两个方向两套编号，互不相干。
- 第 1 个数据字节的序号 $=x+1$：2016 给 x = 100，数据从 101 起；2023 同样 100，数据是 101–18100。
- 第三次握手能捎带数据，所以建立连接只花 1 个 RTT，不是 1.5 个 RTT。
- 客户端发出第 3 步就认为连接已建立，服务器收到第 3 步才进入 ESTABLISHED；这一步既能带数据，也能在 SYN 洪泛里被用作半连接队列的清理点。
- 为什么必须三次：防止已失效的连接请求报文段又传到服务器，使服务器建立无用连接、白占缓存；两次不够（服务器无法确认客户端收到了自己的 SYN 与确认），四次多余（第三次已把双向确认补齐）。
**模板/流水线**
```c
/* 通用流水线，把 x、y 换成题面给的数 */
第 1 步 A->B : SYN=1,            seq=x,   ack 无效    /* 消耗 x，数据从 x+1 起 */
第 2 步 B->A : SYN=1, ACK=1,     seq=y,   ack=x+1     /* 消耗 y，1 个序号 */
第 3 步 A->B : ACK=1,            seq=x+1, ack=y+1     /* 可带数据，不带也消耗 x+1 */

/* 2016：x = 100，MSS = 1 KB，缓存 20 KB，RTT = 200 ms，ssthresh = 32 KB
 * 第 2 步 ack = 101；第 3 步 seq = 101、ack = y+1
 * 数据 101 ~ 20580（20 x 1024 B），下一个待发 = 20581
 */
/* 2023：x = 100，文件 18000 B，MSS = 1000 B
 * 第 1 个字节 = 101，最后一个字节 = 18100
 * 客户端 FIN 再消耗 18101 -> 服务器第 2 次挥手 ack = 18102
 */
```
! ack 写成 x，忘了 SYN 消耗 1 个序号·第 3 步 seq 写成 y+1——seq 用自己的编号，只有 ack 用对方的·答「为什么三次」只写「可靠」两字，要写「防失效的连接请求」

## 四次挥手与 TIME_WAIT
**考频**：2016/2023/2026｜2016 考被动方释放 1.5 RTT，2023 考第二次挥手的 ack，都是纯算数
**必背结论**
- 第 1 步 A→B：FIN = 1，seq = u，FIN 消耗 1 个序号。
- 第 2 步 B→A：ACK = 1，seq = v，ack = u + 1；此后 B 仍可继续给 A 发数据。
- 第 3 步 B→A：FIN = 1 且 ACK = 1，seq = w（B 一直在发数据，从 v 变到 w），ack 仍是 u + 1。
- 第 4 步 A→B：ACK = 1，seq = u + 1，ack = w + 1；A 进入 TIME-WAIT。
- 状态：主动方 FIN-WAIT-1 → FIN-WAIT-2 → TIME-WAIT → CLOSED；被动方 CLOSE-WAIT → LAST-ACK → CLOSED。
- 第 2 步之后连接处于半关闭：A 不再发数据但还能收，B 可以继续把剩下的数据发完，这就是四步不能压成三步的原因。
- 等 2 MSL 两个理由：最后那个 ACK 丢了还能重发；让本连接的残留报文在网中消亡，不污染新连接。
- 谁先发 FIN 谁就是主动关闭方，服务器先关也照样成立，只是两边的时间结论互换；TIME-WAIT 期间这个四元组不能被新连接复用。
- 时间三件套：建立连接 1 RTT；被动方释放 1.5 RTT（第 2、3 步可合并）；主动方释放 1 RTT + 2 MSL。
$$T_{主动}=RTT+2MSL,\qquad T_{被动}=1.5\,RTT$$
- 数字：RTT = 200 ms 时被动方 300 ms；RTT = 50 ms、MSL = 800 ms 时主动方 50 + 1600 = 1650 ms、被动方 75 ms。
**模板/流水线**
```c
/* 挥手流水线：u 是 A 的数据末字节，v 是 B 的数据末字节 */
第 1 步 A->B : FIN=1,            seq=u,   ack 可带    /* FIN 占 1 个序号 */
第 2 步 B->A : ACK=1,            seq=v,   ack=u+1     /* 半关闭，B 仍可发 */
第 3 步 B->A : FIN=1, ACK=1,     seq=w,   ack=u+1     /* ack 不变，A 已不发数据 */
第 4 步 A->B : ACK=1,            seq=u+1, ack=w+1     /* A 进 TIME-WAIT 等 2MSL */

/* 2023 上传场景：数据 101 ~ 18100，FIN 消耗 18101
 * 第 2 步 ack = 18101 + 1 = 18102
 */
/* 时间模板 */
主动方关闭时刻 = 开始挥手 + 1 RTT + 2 MSL
被动方关闭时刻 = 开始挥手 + 1.5 RTT
```
! 第 3 步挥手的 ack 误写成 w+1——A 早已不发数据，ack 恒为 u+1·主动方与被动方时间记反：主动方 1 RTT + 2 MSL，被动方 1.5 RTT·把 MSL 当成 2 MSL 直接乘 2

## 序号与确认号计算模板
**考频**：2023/2026｜2023 考第 1 个字节序号与挥手 ack，2026 考还能再发几个字节，两年同一套加减
**必背结论**
- 序号 = 本报文段第一个字节的编号；确认号 = 期望收到的下一个字节编号。
- 已正确收到多少字节：确认号相减，不加 1（ack 从 101 到 1101 正好 1000 B）。
- 某一段有多少字节：末 − 首 + 1，要加 1（1001–5000 是 4000 B）。
- 下一步该发哪个字节：上一次已发出的最后字节 + 1，按序号走，不按确认号走。
- 消耗序号四处：第 1 次握手 SYN、第 2 次握手 SYN、第 3 次握手（不带数据也消耗）、FIN。
- 于是一个方向传 N 字节数据，编号一共用掉 N + 2 个（SYN 一个、FIN 一个），这正是 2023 那把 18000 B 算成 18102 的原因。
- 发送窗口还能发多少 $=$ 窗口值 $-$ 已发出但未确认的字节数。
$$可用窗口=rwnd-(\text{已发出末字节}-\text{已确认末字节}),\qquad 下次序号=\text{已发出末字节}+1$$
**模板/流水线**
```c
/* 三步走：定起点 -> 定范围 -> 定确认号与可用窗口 */
/* 第 1 步 定起点 */
起点 = 初始序号 + 1;                    /* 初始序号被 SYN 吃掉 */
/* 第 2 步 定范围 */
数据字节 = [起点, 起点 + 长度 - 1];
该段字节数 = 末 - 首 + 1;               /* 要加 1 */
/* 第 3 步 定确认号与可用窗口 */
ack = 已正确收到的最后字节 + 1;          /* 收到 100~199 就回 200 */
已收到字节数 = ack - 起点;               /* 不加 1 */
可用窗口 = 窗口值 - (已发末字节 - 已确认末字节);
下次发送起点 = 已发末字节 + 1;           /* 看序号，不看 ack */

/* 例 1（2023）：x = 100、文件 18000 B、MSS = 1000 B
 * 起点 101，末 18100，共 18000 B = 18 个 MSS
 * FIN 再占 18101 -> 对端 ack = 18102
 */
/* 例 2（窗口）：已发 501~700、收到 ack = 501、窗口 500
 * 未确认 200，可用 300，从 701 发到 1000
 * 若 ack 改成 701 就是全部确认：未确认 0，可用 500，从 701 发到 1200
 */
```
! 「下一次序号 = 上一次确认号」只在三次握手时巧合成立，其余一律按序号接·确认号相减不加 1，范围计数才加 1，两个场景别混·拿到 ack 先看它有没有追平已发数据，没追平的那部分继续占窗口

## 流量控制与滑动窗口
**考频**：选择常考，大题未单独考｜服务 2016第 2、3 问与 2026 的发送窗口问，每题都要先算 rwnd 再取 min
**必背结论**
- rwnd 由接收方决定，写在 TCP 首部的窗口字段，含义是「我还能收多少字节」；窗口通告的是字节数不是段数，题目给 MSS 时先换成段数再比。
- $rwnd=\text{接收缓存}-(\text{已收到}-\text{已交付给应用})$；题目说「只存入不取走」时它只减不增。
- 发送窗口 $=\min(cwnd,rwnd)$，所以发送窗口永远不大于 rwnd。
- 窗口字段 16 位最大 65535 B，长肥管道要靠窗口扩大选项把 rwnd 撑大。
- 收到零窗口通告就启动坚持计时器，周期性发 1 B 探测，窗口一开继续发；零窗口不等于连接断开，已发出的数据仍可重传。
- 2016 数字：缓存 20 KB、MSS 1 KB、收到第 8 个确认 ⇒ rwnd = 20 − 8 = 12 KB，cwnd = 9 KB，发送窗口 = 9 KB。
- MSS = 1000 B、cwnd = 2000 B、rwnd = 4000 B ⇒ 发送窗口 = 2000 B = 2 个段；已发 2 段其中 1 段已确认 ⇒ 还能再发 1000 B。
**模板/流水线**
```c
/* 一行 cwnd、一行 rwnd，逐轮往下推 */
/* 初始 cwnd = 1 MSS，ssthresh = 16 MSS，rwnd = 64 MSS，数据只存不取 */
轮次   cwnd     本轮发出MSS    rwnd 剩余
 0      1           -            64
 1      2           1            63
 2      4           2            61
 3      8           4            57
 4     16           8            49

/* 两条公式 */
rwnd = rwnd0 - 累计已收到的 MSS 数;      /* 任何阶段都能用 */
发送窗口 = min(cwnd, rwnd);
/* 收到 15 个 MSS -> cwnd = 1 + 15 = 16，rwnd = 64 - 15 = 49
 * 收到 31 个 MSS -> cwnd 必须画图（16 之后转拥塞避免，17），rwnd = 33
 */
```
! 把 TCP 首部的窗口当成发送窗口——它是接收窗口·rwnd 与 cwnd 算完忘了取 min·题目说「数据只存入不取走」时 rwnd 不回升，别写成固定值

## 拥塞控制四阶段
**考频**：2016/2023｜两年各有一问推 cwnd，2023 还拿它算平均速率；选择题里窗口题几乎年年有
**必背结论**
- cwnd 单位 MSS，横轴是传输轮次 RTT，纵轴是 cwnd。
- 慢开始：每收到一个确认 cwnd + 1，效果是每轮翻倍，但增长是逐步的（2 → 3 → 4，不是 2 直跳 4）；横轴一格是一个 RTT，翻倍体现在一轮结束时，不是每个确认就跳一格。
- 拥塞避免：cwnd 到 ssthresh 后每轮只 + 1，线性增长。
- 超时：ssthresh ← 当前 cwnd ÷ 2，cwnd ← 1，重回慢开始。
- 3 个冗余 ACK：快重传立即重发丢失的段；快恢复 ssthresh ← cwnd ÷ 2，cwnd ← 新 ssthresh，之后线性增。
- 快重传比超时快，是因为三个冗余 ACK 说明报文还能送到、只是某一段丢了；超时说明连确认都回不来，只能从 1 重来。
- 一步到位法只在慢开始成立：cwnd = 1 + 累计已确认的 MSS 数；跨过 ssthresh 后只能画图。
- 曲线数字：1 → 2 → 4 → 8 → 16（ssthresh = 16）→ 17 → … → 24 超时 ⇒ ssthresh = 12、cwnd = 1 → 1、2、4、8、12（不跳到 16）→ 13、14。
- 2016：阈值 32 KB 未到，收到第 8 个确认 cwnd = 9 KB。2023：阈值 4 MSS，ack = 2101 ⇒ 2 个确认 ⇒ cwnd = 3；ack = 7101 ⇒ 7 个确认 ⇒ 1 → 2 → 4 → 5 MSS。
**模板/流水线**
```c
/* 输入事件序列，输出每轮 cwnd；事件：NORMAL / TIMEOUT / DUPACK */
int cwnd = 1, ssthresh = 16, r;
for (r = 1; r <= n; r++) {
    if (ev[r] == TIMEOUT) {
        ssthresh = cwnd / 2;      /* 减为【当前】cwnd 的一半，不是原门限 */
        cwnd = 1;                 /* 回到慢开始 */
    } else if (ev[r] == DUPACK) {
        ssthresh = cwnd / 2;
        cwnd = ssthresh;          /* 快恢复：直接降到新门限 */
    } else if (cwnd < ssthresh) {
        cwnd = cwnd * 2 > ssthresh ? ssthresh : cwnd * 2;
                                  /* 慢开始：本轮翻倍，越界就停在门限 */
    } else {
        cwnd += 1;                /* 拥塞避免：本轮 +1 */
    }
    printf("RTT %d: cwnd=%d ssthresh=%d\n", r, cwnd, ssthresh);
}
/* ssthresh = 16 的典型输出
 * 1 2 4 8 16 | 17 18 ... 24 | 超时 -> ssthresh = 12、cwnd = 1
 * 1 2 4 8 12（卡在门限 12，不写 16）| 13 14 ...
 */
/* 2023：ssthresh = 4，7 个确认 -> 1, 2, 4, 5（第 4 个确认起转拥塞避免） */

/* cwnd 曲线（横轴 RTT，纵轴 MSS）
 * 24 |                              *
 * 20 |                  *
 * 16 |*        <- ssthresh = 16
 * 12 |                     \  超时后新门限 12
 *  8 |      *
 *  4 |   *
 *  2 | *
 *  1 |*
 *    +---1---2---3---4---5---6---7---8--> RTT
 */
```
! 阈值减半减的是「当前 cwnd」而不是「原 ssthresh」·用 cwnd = 1 + 累计确认数 跨阶段硬算（31 个确认应是 17 不是 32）·慢开始当成一步跳 2 倍，被问「收到第 3 个确认时 cwnd 多少」就露馅

## 吞吐率与传输时间
**考频**：2025｜卫星链路三问：单向传播时延、最大吞吐量、传 4000 B 文件的最短时间；2023 也考平均速率 2.4 Mb/s
**必背结论**
- 单向传播时延 = 距离 ÷ 光速：36000 km ÷ 300000 km/s = 0.12 s = 120 ms，RTT = 240 ms。
- 最大吞吐量取瓶颈：卫星链路每方向 200 kb/s 就是瓶颈，主机接千兆以太网也跑不过 200 kb/s。
- 带宽时延积 BDP = C × RTT = 200 kb/s × 0.24 s = 48 kbit = 6 KB，这是长肥管道要的最小窗口。
- 窗口不够时链路空转，吞吐率被窗口与 RTT 卡住，上限就是 $窗口/RTT$；卫星链路正是典型的长肥管道。
- 文件传输时间 = 传输时延 L×8/C + 单向传播时延；要等确认再加 1 个 RTT。
- 卫星链路那 240 ms 往返是固定的「管道长度」，文件再小也要等满它，所以小文件在这种链路上的有效吞吐率远低于 200 kb/s。
- 4000 B 走 200 kb/s：4000×8 ÷ 200000 = 0.16 s，加 120 ms 传播 ⇒ 280 ms。
- 有效吞吐率 = 应用层数据量 × 8 ÷ 总时间；1 B = 8 bit，k = 1000、M = 1000000，只有存储容量用 1024。
- 单位三步走：先全部换成 bit 与秒，除完再换成 kb/s 或 Mb/s；163840 bit/s 写成 163.84 kb/s 即可，换算是细节、列式才是分。
- 2016：20480 B ÷ 1 s = 163840 bit/s = 163.84 kb/s。2023：18000×8 ÷ 0.06 s = 2.4 Mb/s。
$$T=\frac{L\times 8}{C}+\frac{d}{v},\qquad \eta=\frac{L\times 8}{T},\qquad BDP=C\times RTT$$
**模板/流水线**
```c
tp = d / v;                  /* 传播：36000 km / 300000 km/s = 120 ms */
tt = L * 8 / C;              /* 传输：4000 B * 8 / 200 kb/s = 160 ms */
/* 排队与处理：题目不说就按 0 */
T  = tt + tp;                /* 只要数据到达 = 280 ms */
                             /* 若还要收到确认：再加 1 RTT = 520 ms */
rate = L * 8 / T;            /* bit/s，换 kb/s 除 1000 */
/* 长肥管道：BDP = C * RTT = 200 kb/s * 0.24 s = 48 kbit = 6 KB
 * 窗口 >= BDP 才能跑满 200 kb/s；窗口只有 1 MSS 时吞吐率约 MSS / RTT
 */
/* 2023 复盘：建连 1 RTT + 传 18 个 MSS 用 5 RTT = 6 RTT = 60 ms
 * 18000 * 8 / 0.06 = 2.4 Mb/s
 */
```
! 传播时延用带宽去除，把 d/v 写成 L/C·传文件只算传输时延忘了加传播时延，卫星链路上这是 120 ms 的大头·2023 那种题漏算建连的 1 RTT，6 RTT 写成 5 RTT

## DNS 递归与迭代查询
**考频**：2021｜第 1 问「除 HTTP 外还运行了哪个协议」加逐层封装；查询次数是选择题常客
**必背结论**
- DNS 用 UDP，服务器端口 53，作用是域名到 IP 的映射；响应超过 512 B 或做区域传送时改走 TCP 53。
- 主机 → 本地域名服务器：递归查询，本地服务器替主机跑完全程，只回最终答案。
- 本地域名服务器 → 根 / 顶级 / 权威：迭代查询，每次只告诉你下一个该问谁。
- 层级顺序：根 → 顶级域（.com）→ 权威域名服务器，权威可以有多台。
- 主机和本地域名服务器都有高速缓存，命中就不发查询，所以「最少几次」往往是 0 次。
- 封装链（2021 第 1 问答案）：DNS 报文 → UDP → IP → 以太网帧。
- 查询次数：$n$ 层域名最多 $n+1$ 次（本地递归 1 次，再迭代问根与各级），全部命中缓存则 0 次。
- 时间例子：每次查询 10 ms、建连与请求响应共 2 个 RTT ⇒ 最多 30 + 20 = 50 ms、最少 20 ms。
**模板/流水线**
```c
/* 递归 + 迭代全流程（括号是封装层） */
/* 0. 浏览器缓存 -> hosts 文件 -> 本地 DNS 缓存，命中直接返回，0 次查询 */
/* 1. 递归：H --(DNS 查询 / UDP 53)--> 本地域名服务器 */
/* 2. 迭代：本地 --问根----> 只回 .com 顶级服务器地址
 *          本地 --问.com--> 只回 abc.com 权威服务器地址
 *          本地 --问权威--> 回 www.abc.com 的 IP
 */
/* 3. 回程：本地 --(DNS 应答)--> H，拿到 IP 才能发 TCP SYN */
/* 封装：DNS 报文 | UDP 首部 8 B | IP 首部 20 B | 帧头 14 B + 帧尾 4 B */
/* 次数：最多 = 1 + 层级数；命中缓存最少 = 0 */
```
! 把「主机问本地」说成迭代，或把「本地问根」说成递归，方向一反全错·忘了先有 IP 才能建连，算时间时漏掉整个 DNS 段·默认权威只有一台、忘记缓存，查询次数一定算多

## HTTP 请求响应与连接时间
**考频**：2011/2021｜2011 第 3 问全是 RTT 记账（持续非流水线 5 张图），2021 考 HTTP 报文在协议栈里的位置
**必背结论**
- HTTP 用 TCP，服务器端口 80；HTTP/1.0 默认非持续连接，HTTP/1.1 默认持续连接。
- 请求报文 = 请求行（GET /index.html HTTP/1.1）+ 首部行（Host、Connection、User-Agent）+ 空行 + 实体。
- 响应报文 = 状态行（HTTP/1.1 200 OK）+ 首部行 + 空行 + 实体。
- 格式细节：每个首部占一行，冒号后一个空格；最后一个空行之后才是实体，GET 没有实体，POST 才有。
- 非持续：每个对象一条 TCP 连接，每对象 2 RTT（建连 1 + 请求响应 1）。
- 非持续的代价是每个对象都重新建连、重新慢开始；持续连接把这一笔开销摊到所有对象上，所以对象越多越划算。
- 持续非流水线：共用一条连接，建连 1 RTT，之后每个对象 1 RTT。
- 持续流水线：请求一次全发出，建连 1 RTT + 请求 1 RTT + 响应 1 RTT，约 3 RTT。
- 2011 第 3 问：请求已经发出，页面 + 5 张图共 6 个对象，持续非流水线 ⇒ 6 RTT。
- 数字：RTT = 100 ms、6 个对象 ⇒ 非持续 12 RTT = 1200 ms、持续非流水线 7 RTT = 700 ms、流水线 3 RTT = 300 ms。
- Cookie 存在客户端，补 HTTP 的无状态；条件 GET 用 If-Modified-Since 换 304。
$$RTT_{非持续}=2N,\qquad RTT_{持续非流水线}=1+N,\qquad RTT_{流水线}=3$$
**模板/流水线**
```c
/* 先数对象 N = 1 个 HTML + (N-1) 张图，再选连接方式 */
rtt = 2 * N;                 /* 非持续 */
rtt = 1 + N;                 /* 持续非流水线 */
rtt = 1 + 2;                 /* 持续流水线 */
/* 题目说「请求已经发出」，建连那 1 个 RTT 不再算
 * 2011 第(3)问：rtt = N = 6
 * 题目说「从点击链接开始」，先加 DNS 时间，再加建连 1 RTT
 */
/* 例：N = 6、RTT = 100 ms
 * 非持续 12 RTT = 1200 ms；持续非流水线 7 RTT = 700 ms；流水线 3 RTT = 300 ms
 */
```
! 2011 那道从「Web 请求已发出」起算，多算 1 个建连 RTT 就错·流水线也按 1+N 算，流水线的请求是并行发出的（1+2）·HTTP/1.1 出现 Connection: close 就退回非持续连接

## 从输入网址到页面显示
**考频**：2021｜那道 9 分题就是这条链路：DNS 封装、ARP 与交换表泛洪、帧数统计，一问一段
**必背结论**
- 顺序：查缓存与 hosts → DNS 解析得 IP → ARP 求网关 MAC → TCP 三次握手 → 发 HTTP 请求 → 服务器响应 → 渲染页面。
- 应用层加 HTTP 首部；传输层加 TCP 首部 20 B（端口、序号、窗口）；网络层加 IP 首部 20 B（IP、TTL、协议）；链路层加帧头 14 B + 帧尾 4 B。
- 以太网帧总长 $=L+58$（20 + 20 + 18），不足 64 B 要填充（2012 第 3 问就考这个）。
- MAC 地址逐跳改变，IP 地址端到端不变；TTL 每经一个路由器减 1（2012：64 − 49 = 15 个路由器）。
- 交换机对广播帧和未知目的 MAC 的单播帧一律泛洪，所以同网段其它主机也会收到 ARP 请求，目的 MAC 是 FF-FF-FF-FF-FF-FF。
- ARP 请求是广播、ARP 应答是单播；应答里带着对方 MAC，主机把它存进 ARP 表，过几分钟失效就要重问。
- IP 首部协议字段：TCP 填 6，UDP 填 17，由它决定交给谁。
- 端口定位进程：HTTP 80、DNS 53、FTP 21。
- 这七步里有三处一定被单独拿出来问：DNS 的逐层封装、ARP 请求的目的 MAC、帧长不足 64 B 时的填充。
**模板/流水线**
```c
/* 封装清单，照写就拿封装分；L 为应用层报文长度 */
/* 应用层 */  "GET /index.html HTTP/1.1" + Host + 空行            长 L
/* 传输层 */  + TCP 首部 20 B（源端口随机、目的 80、seq、ack、窗口）L + 20
/* 网络层 */  + IP 首部 20 B（源 IP、目的 IP、TTL=64、协议=6、总长）L + 40
/* 链路层 */  + 帧头 14 B（目的 MAC、源 MAC、类型 0x0800）+ FCS 4 B  L + 58
/*            若 L + 58 < 64 则填充到 64 B */
/* 时间   */  DNS 时间 + 1 RTT 建连 + 1 RTT 请求响应 + 图片等后续对象
/* 地址   */  MAC 每一跳都换；IP 全程不变；TTL 每跳减 1
```
! 封装顺序写反（先 IP 后 TCP），或忘掉帧尾 4 B，帧长少 4·以为 MAC 全程不变，跨路由器必须换·把 DNS 放在建立连接之后，时间和帧数两问一起错
