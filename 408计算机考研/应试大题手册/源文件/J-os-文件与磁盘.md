## 三种物理结构总表
**考频**：2011/2014（各 7 分）｜约三年一次大题，选择几乎每年一问
**必背结论**
- 物理结构只回答一句话：这个文件占了哪些盘块、靠什么记下来。
- 连续分配：FCB 记〈起始块号，块数〉或〈起始块号，结束块号〉；支持随机访问；有外部碎片；插入/删除要整段挪。2011 第(1)问答"连续更合适"，理由是数据一次写入不再修改、连续存放寻道距离最短、随机访问效率最高。
- 隐式链接：FCB 只记起始块号；每块末尾留指针，指针占 $\lceil \log_2 N \rceil$ 位（$N$ 为总块数）；只能顺序访问；无外部碎片，但指针吃空间、断链即全丢。
- 显式链接（FAT）：全盘一张表，行数 = 块数，每行位数 = 块号位数；开机把表读入内存，所以能随机访问；缺点是表占内存。
- 索引分配：每个文件一张索引表，索引块自身也占盘块；可随机访问；无外部碎片。
- 两个量必须分开：FAT 表的大小 ≠ FAT 能表示的文件最大长度。
- FCB 与索引结点分离后，目录项只剩〈文件名，索引结点号〉，所以一个盘块能放更多目录项：设目录项 16B，4KB 块就能放 256 项。
- 2011 第(2)问：FCB 集中存放更好 —— 按名查找时只需读 FCB 所在的那几块，减少磁头移动和访盘次数。
- 统一数字例子：4KB 盘块、4B 块号 → $N=2^{32}$、$n=1024$；隐式链接单块可用 $4096-4=4092$B；FAT 表项 2B → $2^{16}$ 簇 → 最大文件 256MB、表大小 128KB。

| 结构 | FCB 记什么 | 随机访问 | 外部碎片 | 最大文件长度 | 读第 k 块访盘（k 从 1 数） |
|---|---|---|---|---|---|
| 连续 | 起始块号 + 块数 | 可以 | 有 | 受连续空闲区限制 | 1 |
| 隐式链接 | 只记起始块号 | 不行 | 无 | 块数 ×（块大小 − 指针） | k |
| 显式链接 FAT | 只记起始块号 | 可以（查内存表） | 无 | 簇数 × 簇大小 | 1 |
| 索引 | 索引块号 | 可以 | 无 | 见混合索引公式 | 2 |

> 索引结构"读第 k 块"＝索引块 1 次 + 数据块 1 次；题目说索引结点已在内存就只算 1 次。表里的 k 从 1 数，代码里的 k 从 0 数，差 1。

**模板/流水线**
```c
/* 三种结构：访问第 k 个逻辑块(0 起)需要读几个盘块 */
int Reads_Cont(int k) { return 1; }          /* 起始块号 + k，直接算，读 1 次 */
int Reads_Link(int k) { return k + 1; }      /* 第 0 块读 1 次，必须顺着链走到第 k 块 */
int Reads_FAT (int k) { return 1; }          /* 表已在内存，查表得簇号，直接读 1 簇 */

/* 索引：索引结点在内存 → 级别 + 1；不在内存 → 级别 + 2 */
int Reads_Index(int level, int inodeInMem) {
    return level + 1 + (inodeInMem ? 0 : 1);
}

/* 隐式链接最大长度：1KB 块、4B 指针 → 指针 32 位 → 2^32 块 → 单块可用 1020B */
double LinkMaxGB(void) {
    return 4294967296.0 * 1020 / 1073741824.0;   /* = 4080 GB，2014 第(2)问答案 */
}
```
! 隐式链接与显式链接名字常被叫反（FAT 才叫显式）·连续分配"外部碎片"别答成内部碎片·索引结构别漏算索引块本身占的盘块·2011 第(1)问要答连续并给出"一次写入不修改"这个前提

## 连续分配插入删除次数
**考频**：2014（7分）｜两个小问全在这一题里，模板默写即可
**必背结论**
- 铁律：外存不能就地修改，任何"挪一块" = 读 1 次 + 写 1 次 = 2 次访盘。
- 插入为第 $p$ 条（共 $N$ 条）有两条路：把第 $p$ 条之后整体后移（动 $N-p+1$ 条），或把前 $p-1$ 条整体前移。题目给"前后都有空闲空间"就是让你取小的那个。
- 2014：$p=30,N=200$ → 后移 171 条、前移 29 条 → 取 29 → $29\times2=58$ 次。
- 新记录已在内存 → 只写 1 次；总数 $=58+1=59$ 次。
- 插在第 1 条或第 $N+1$ 条时挪动条数为 0，只写 1 次 —— 公式自动覆盖这种边界。
- 删除第 $p$ 条：前移 $p-1$ 条或后移 $N-p$ 条，取小 → $T=\min(p-1,\;N-p)\times2$；删完块数减 1。
- FCB 变化：起始块号和块数都变；若 FCB 记的是〈起始，结束〉，则只改起始块号。
- 链接分配插入：前 $p-2$ 块只读；第 $p-1$ 块读 + 写（改指针）；新块只写 → 合计 $p+1$（$p=30$ → 31 次）。
- 链接分配删除：顺链读到第 $p-1$ 块用 $p-1$ 次读，改指针再写 1 次 → 共 $p$ 次，但一个数据块都不用挪。
- 索引分配插入最省：索引表在内存时只写新数据块 1 次；若索引块也要回写，再加 1 次读 + 1 次写。这就是"为什么大文件用索引"的答题落点。
- 量级感受：每次访盘按 10ms 估，59 次约 0.59s —— 所以连续分配"读得快但改得慢"，答题时要写出这个代价。
- 通用公式：连续插入 $T=\min(p-1,\;N-p+1)\times2+1$；链接插入 $T=(p-2)+2+1$。
- 官方评分说明：2014 第(1)问的 FCB 变化若不含"起始地址"和"文件大小"两项，该小问不给分。

**模板/流水线**
```c
/* 连续分配：内存中的记录插入为第 p 条，共 n 条，每块 1 条 */
int InsCont(int n, int p) {
    int back  = n - p + 1;        /* 第 p 条及之后整体后移的条数 */
    int front = p - 1;            /* 前 p-1 条整体前移的条数 */
    int m = (front < back) ? front : back;   /* 挪的条数取小，最省 */
    return m * 2 + 1;             /* 每条读一次写一次；新记录已在内存只写 1 次 */
}
/* 连续分配：删除第 p 条，共 n 条 */
int DelCont(int n, int p) {
    int back  = n - p;            /* 后面 n-p 条往前填 */
    int front = p - 1;            /* 前面 p-1 条往后填 */
    int m = (front < back) ? front : back;
    return m * 2;                 /* 只挪，没有新记录要写 */
}
/* 链接分配：插为第 p 条（p >= 2） */
int InsLink(int p) {
    int i, t = 0;
    for (i = 1; i <= p - 2; i++) t += 1;  /* 顺链走到第 p-2 块：只读 */
    t += 2;                               /* 第 p-1 块：读出，再写回新指针 */
    t += 1;                               /* 新插入块：只写一次，指针指向原第 p 块 */
    return t;                             /* = p + 1，2014 答案 31 */
}
/* 链接分配最大长度：1KB 块、4B 指针 */
double LinkMax(void) { return 4294967296.0 * (1024 - 4); }  /* ≈ 4080 GB */
```
! 只算读不算写（挪一块必须读写各一次）·"已在内存"的新记录又被算了一次读·把"前移 29 条"算成 30 条（第 p 条本身不动）·FCB 只答块数不改起始块号

## 混合索引最大文件长度
**考频**：2012/2018、2022、2026（文件大题）｜四年重复同一个式子，全书最高频计算
**必背结论**
- 第一步永远先算"一个索引块能放几个地址项"：$n=\dfrac{块大小}{地址项大小}$。4KB/4B → 1024；256B/4B → 64；1KB/4B → 256。
- 最大长度 $=(a_1\times1+a_2n+a_3n^2+a_4n^3)\times 块大小$，最后一步必须乘数据块大小，否则算出来的只是块数。
- 4KB 块 + 4B 项时：一个直接项 = 4KB，一个一级项 = 4MB，一个二级项 = 4GB，一个三级项 = 4TB；记这四个数比记公式更快。
- 2018：8 直接 + 一/二/三级各 1 → $32\text{KB}+4\text{MB}+4\text{GB}+4\text{TB}$。
- 2026 结构：5 直接 + 一/二/三级各 1（4KB 块、4B 项）→ $20\text{KB}+4\text{MB}+4\text{GB}+4\text{TB}$。
- 2010 选择 30：4 直接 + 2 一级 + 1 二级，块 256B、项 4B → $n=64$ → $(4+128+4096)\times256\text{B}=1082368\text{B}=1057\text{KB}$。
- 2012：容量 4TB、块 1KB → 块数 $4\text{TB}/1\text{KB}=2^{32}$ → 块号要 32 位 = 4B；512B 索引区 → 128 项 → 最大 128KB。
- 2012 第(2)问变形：〈起始块号 6B，块数 2B〉+ 504B 直接项（6B/项）→ $2^{16}\times1\text{KB}+84\text{KB}=2^{26}\text{B}+84\text{KB}$；要取最长则起始块号与块数各 4B（各能寻址 $2^{32}$ 块 = 4TB）。
- 反向题（给长度求级数）：$4\text{GB}/4\text{KB}=2^{20}$ 块，而 $n=1024$、$n^2=1048576$，$1+1024<2^{20}<1+1024+1048576$ → 一级、二级都要用，三级不用。
- 2018 第(2)问：inode 总数 $=2^{20}\text{簇}\times4\text{KB}/64\text{B}=2^{26}=64\text{M}$；5600B 文件占 2 簇 → 数据簇够 256M 个 → 受 inode 限制，最多 64M 个文件。
- 2018 第(3)问：6KB 小于 32KB 只读直接项；40KB 超过 32KB 还要多读一个一级索引块 → 时间不同。问"获取最后簇号的时间"就是在问级数。
- 与单个文件长度无关的量只有一个：索引结点总数（2013 选择 26 选 A）。索引块与数据块题目不说就默认同大。
- 回代检验：把答案块数再乘块大小，若量级差 1024 倍就是漏乘或漏除；把 $n$、$n^2$、$n^3$ 依次列出来乘，别跳步。
- 地址项为什么常是 4B：块号空间 $2^{32}$ 就需要 32 位；若盘更大（2012 第(2)问）就得用 6B，索引区能装的项数随之变少，所以"块号占几字节"和"能装几项"是一对反比关系。

| 级别 | 每个地址项管几块 | 4KB 块、4B 项时 |
|---|---|---|
| 直接 | 1 | 4KB |
| 一级 | n = 1024 | 4MB |
| 二级 | n² = 1048576 | 4GB |
| 三级 | n³ = 1073741824 | 4TB |

**模板/流水线**
```c
/* BS 块大小，PS 地址项大小；a1 直接、a2 一级、a3 二级、a4 三级 */
long long MaxFile(int BS, int PS, int a1, int a2, int a3, int a4) {
    long long n = BS / PS;                 /* ① 一个索引块放几个地址项 */
    long long blk = a1;                    /* ② 直接项：每项 1 块 */
    blk += (long long)a2 * n;              /*    一级：每项 n 块 */
    blk += (long long)a3 * n * n;          /*    二级：每项 n^2 块 */
    blk += (long long)a4 * n * n * n;      /*    三级：每项 n^3 块 */
    return blk * (long long)BS;            /* ③ 别忘了再乘数据块大小 */
}
/* 反向：给定块数 m，求最少用几级（a1 直接、a2 一级、a3 二级） */
int LevelOf(long long m, int a1, int n) {
    if (m <= a1) return 1;
    if (m <= a1 + (long long)n) return 2;
    if (m <= a1 + (long long)n + (long long)n * n) return 3;
    return 4;
}
/* 2018 调法：MaxFile(4096,4,8,1,1,1) → 32KB+4MB+4GB+4TB */
/* 2012 第(1)问：块号位数 = log2(4TB/1KB) = 32 位 = 4B；512/4 = 128 项 → 128KB */
```
! 漏乘数据块大小（只报"4228 块"）·把 $n^2$ 算成 $2n$·题目问"哪几级间接地址项"时要排除直接项·2012 的"块号最少占几字节"要用总块数取对数，不是用索引区大小

## 偏移定位与读盘块数
**考频**：2022/2026（文件大题）｜隔年就考，四步模板
**必背结论**
- 逻辑块号（从 0 编号）$K=\left\lfloor \dfrac{\text{偏移}}{\text{块大小}} \right\rfloor$，块内偏移 = 偏移 mod 块大小。用 0 起编号，商就是第几块，不必管余数。
- 定级（0 起）：$K<a_1$ 直接；$K<a_1+n$ 一级；$K<a_1+n+n^2$ 二级；否则三级。
- 读盘块数（索引结点已在内存）＝ 级别 + 1：直接 1、一级 2、二级 3、三级 4；索引结点不在内存再 +1。
- 2026：4KB 块、5 个直接项、$n=1024$；偏移 21460 → $K=5$ → 落在第 6 块（1 起）→ 一级间接 → 读 2 个盘块。
- 索引结点号 ≠ 盘块号：2022 的"10"是结点号，答案要写"10 号索引结点所在的盘块 + 30 号数据块"。
- inode 所在盘块 $=$ inode 表起始块号 $+\left\lfloor \dfrac{inode 号}{每块 inode 数} \right\rfloor$，每块 inode 数 $=\dfrac{块大小}{inode 大小}$，$4096/128=32$。
- 2026：表从 100 号块起连续 4096 块 → 容量 $4096\times4\text{KB}=16\text{MB}$ → inode 总数 $16\text{MB}/128\text{B}=131072=2^{17}$ → 最多存 131072 个文件（受 inode 数限制，不受盘块数限制）。
- 2015 选择 29：10 直接 + 一/二级各 1、1KB 块、4B 项（$n=256$）→ 1234 偏移在第 2 块（直接，1 次）；307400 在第 301 块（二级，3 次）。
- 打开文件读第一个字节的完整链：目录项 → inode 块（1 次）→ 数据块（1 次）；2022 第(3)问 course 目录已在内存 → 就是这 2 块。
- 为什么坚持 0 起编号：1 起编号要判断"余数是否为 0 才进位"，多一个判断就多一处错；0 起直接取商，21460 ÷ 4096 = 5 就是第 5 号块。
- 题目问"最多需要读多少盘块"就按最坏路径答：二级索引要读两个索引块加一个数据块，别心疼，写满 3。
- 2026 第(1)问三小问是三套公式：inode 块号用整除、读盘块数用级别 + 1、最多文件数用 inode 总数；分三行写，别串成一团。

| 级别 | 块序号 K 范围（0 起） | 5 直接 + n=1024 时 |
|---|---|---|
| 直接 | 0 至 a1−1 | 0 至 4 |
| 一级 | a1 至 a1+n−1 | 5 至 1028 |
| 二级 | a1+n 至 a1+n+n²−1 | 1029 至 1049604 |
| 三级 | 余下 | 1049605 起 |

**模板/流水线**
```c
/* 输入文件内偏移 off，返回索引级别 1..4（1 直接、2 一级、3 二级、4 三级） */
int Level(long long off, int BS, int a1, int a2, int a3) {
    long long n = BS / 4;            /* 4B 地址项 */
    long long K = off / BS;          /* ① 逻辑块号，0 起：商就是块号 */
    if (K < a1) return 1;            /* ② 直接 */
    K -= a1;
    if (K < (long long)a2 * n) return 2;             /* ③ 一级 */
    K -= (long long)a2 * n;
    if (K < (long long)a3 * n * n) return 3;         /* ④ 二级 */
    return 4;                                        /* ⑤ 三级 */
}
/* 读盘块数：级别 + 1，索引结点不在内存再 +1 */
int Reads(long long off, int BS, int a1, int a2, int a3, int inodeInMem) {
    return Level(off, BS, a1, a2, a3) + 1 + (inodeInMem ? 0 : 1);
}
/* inode 号 id 所在盘块：表从 start 号块起连续存放 */
long long InodeBlk(long long id, int BS, int IS, long long start) {
    return start + id / (BS / IS);    /* 4096/128 = 32 个 inode 一块 */
}
/* 2026：21460/4096 = 5 → 一级 → 2 块；inode 总数 4096*32 = 131072 */
```
! 把索引结点号当盘块号写（2022 的 10）·用 1 起编号又忘了余数不为 0 要进位·"最多读几个盘块"要含索引块但不含题目已在内存的索引结点·二级索引漏算其中一层索引块

## FAT 表大小与路径查找
**考频**：2016（9分）｜三问全是固定套路，选择也常考空闲块管理结构
**必背结论**
- FAT 就是一个数组：行数 = 簇（块）数，每行位数 = 簇号位数。表项 $t$ 字节 → 最多 $2^{8t}$ 个簇（16 位 → $2^{16}$ 簇）。
- FAT 最大长度 $=2^{8t}\times t$ 字节；2016：$2^{16}\times2\text{B}=2^{17}\text{B}=128\text{KB}$。
- 单个文件最大长度 $=$ 簇数 $\times$ 簇大小；2016：$2^{16}\times4\text{KB}=2^{28}\text{B}=256\text{MB}$。
- 表项值：−1（全 1）表示文件最后一块，−2（0）表示空闲 —— 所以 FAT 顺便管空闲空间，一表两用。
- 目录项只存文件名 + 第一个簇号，其余簇号在 FAT 里；所以"file1 的第 3 簇"要查两次表才能得到。
- 簇链数格子：file1 为 $100\to106\to108\to-1$，则 106 存在 100 号表项、108 存在 106 号表项、108 号表项里是 −1；规律是"表项号 = 前一个簇号，表项内容 = 下一个簇号"。
- 目录本身也是文件：设目录项 16B，4KB 块一块放 256 项；目录文件长大一样要顺着 FAT 找簇。
- 按名存取：查目录项得首簇 → 查 FAT 得后续簇 → 读数据簇。FAT 已在内存，查表不计访盘次数。
- 逐级查找读盘数：路径深度为 $d$ 层目录 → 读 $d$ 个目录文件所在簇 + 1 个数据簇（全无缓存时）；2016 给了"FAT 和 dir 已在内存"，所以只算 2 个。
- 2016 第(4)问：第 5000 个字节 → $5000/4096=1$ 余 904 → 第 2 个簇 → FAT[100]=106 → 要读 48 号簇（dir1 目录文件）和 106 号簇，共 2 个。
- FAT 与索引的分工要一句话说清：FAT 全盘一张表，表的大小只与总簇数有关；索引每个文件一张表，表的大小与文件个数成正比。
- 第(1)问写目录内容时只写〈文件名，首簇号〉两列，把 106、108 也写进目录项就错了，它们在 FAT 里。
- 表项数的上限由表项宽度决定：16 位 → 65536 簇，配 4KB 簇 → 单文件上限 256MB，同时也意味着这个 FAT 最多管 65536 个簇。

| 场景（路径 dir/dir1/file1，第 5000 字节） | 必须读的簇 | 个数 |
|---|---|---|
| FAT 与 dir 已在内存 | 48、106 | 2 |
| 全无缓存（连 dir 都要读） | 1、48、106 | 3 |

**模板/流水线**
```c
/* 表项 t 字节 → 簇数；FAT 表大小；单文件最大长度 */
long long FATClusters(int t) { return 1LL << (8 * t); }        /* t=2 → 65536 */
long long FATSize(int t)     { return FATClusters(t) * t; }    /* 128KB */
long long FATMaxFile(int t, int clusterSize) {
    return FATClusters(t) * clusterSize;                       /* 2^16*4KB = 256MB */
}
/* 第 off 个字节(0 起)落在第 k 个簇：k = off / 簇大小，0 起 */
int FATCluster(int fat[], int start, long long off, int CS) {
    long long k = off / CS, i;
    int c = start;
    for (i = 0; i < k; i++) c = fat[c];   /* 表在内存，查表不算访盘 */
    return c;
}
/* 逐级查找：要读的簇序列 = 每层目录文件所在簇 + 最后数据簇 */
void FATPath(int d1, int d2, int start, int fat[], long long off, int CS) {
    printf("read %d, %d, %d\n", d1, d2, FATCluster(fat, start, off, CS));
}
/* 目录项号与表项号互查：表项号 = 前驱簇号 */
```
! FAT 表大小与单文件最大长度写反·以为目录项里存着全部簇号·第 5000 字节算成第 1 个簇（余数不为 0 要进一位）·把 −2（空闲）当结束标志

## 删除目录的元数据操作
**考频**：2026（文件大题）｜元数据清单题，按"目录项 → 目录块 → inode → 位图 → 超级块"顺序背
**必背结论**
- 删目录 dir1 要动五处：父目录中的目录项、dir1 目录文件占的盘块、dir1 的索引结点、磁盘位示图、索引结点位示图（再加超级块的空闲计数）。
- 顺序固定：先清空（非空则递归删内部所有文件和子目录，自底向上），再删父目录里的目录项，最后回收盘块与 inode。
- 回收盘块 = 磁盘位示图对应位清 0；回收 inode = 结点位示图对应位清 0，结点号可再分配。
- 删目录项 = 把该项标记为空（或让后续项前移覆盖），父目录的文件长度、修改时间随之改变 —— 目录也是文件，长度和时间戳是元数据。
- 目录非空不能直接删；题目说"dir1 为空"才可跳过递归这一步。
- 反向的"创建目录"要对称背：父目录加一项、结点位图置 1、磁盘位图置 1（放"."和".."）、超级块计数减 1。
- 硬链接只删目录项并把计数减 1，计数为 0 才释放 inode 与盘块（2022 考过"inode 号相同即硬链接"）。
- 删除已打开的文件：目录项立刻消失，但只要有进程还打开着，inode 与盘块要等最后一个进程关闭才回收。
- 超级块要同步：空闲盘块数 + dir1 占的块数，空闲 inode 数 + 1。
- 考场就写这四句：在父目录中删除目录项、回收目录文件所占盘块并清磁盘位图、释放 inode 并清结点位图、更新超级块空闲计数。四句齐了就满分。

| 元数据 | 要做的操作 | 记在哪个位图 |
|---|---|---|
| 父目录的目录项 | 删除 dir1 那一项，目录长度改变 | 不涉及 |
| dir1 目录文件占的盘块 | 全部回收 | 磁盘位示图清 0 |
| dir1 的索引结点 | 回收，结点号可再用 | 索引结点位示图清 0 |
| dir1 内部文件（若非空） | 先递归删除，各自同上 | 两张位图都要改 |
| 超级块 | 空闲盘块数、空闲 inode 数增加 | 不涉及 |

**模板/流水线**
```c
/* 删除目录 d（父目录 parent）的元数据操作清单，按此顺序答 */
void DeleteDir(Dir *parent, Dir *d) {
    int i;
    /* ① 非空先清空：自底向上递归删子项 */
    for (i = 0; i < d->n; i++) {
        if (d->item[i].isDir) DeleteDir(d, &d->item[i]);
        else Unlink(d, &d->item[i]);           /* 删文件：回收盘块 + inode */
    }
    /* ② 父目录：删除 dir1 的目录项（文件名 + 索引结点号） */
    RemoveEntry(parent, d->name);
    /* ③ 回收 dir1 目录文件占用的盘块：磁盘位示图对应位清 0 */
    for (i = 0; i < d->nblk; i++) DiskBitmap[d->blk[i]] = 0;
    /* ④ 回收 dir1 的索引结点：结点位示图对应位清 0，结点号可再用 */
    InodeBitmap[d->ino] = 0;
    /* ⑤ 超级块同步 */
    Super.freeBlocks += d->nblk;
    Super.freeInodes += 1;
}
/* 硬链接：Unlink 里只做 link--，link 归零才走 ③④⑤ */
```
! 只删目录项、不释放 inode 和位图（空间泄漏）·漏掉磁盘位示图只改结点位示图·目录非空硬删·硬链接文件删一个目录项就把 inode 释放了（应计数减 1）

## 磁盘调度手算模板
**考频**：2010/2019，各 7 分｜磁头移动量 + 总耗时，隔几年一次
**必背结论**
- 总时间 = 寻道时间 + 请求数 × 旋转延迟 + 请求数 × 传输时间。
- 一圈时间 $T=\dfrac{60}{r}$ 秒（$r$ 为 rpm）；6000rpm → $T=10$ms。给 rpm 先换算再动手。
- 旋转延迟 $=\dfrac{T}{2}$（随机扇区平均找半圈）；传输时间 $=\dfrac{\text{读的扇区数}}{\text{每道扇区数}}\times T$。
- 移动量按相邻磁道逐段累加；CSCAN 的回程（一端 → 另一端）必须算进去。
- 2010：100→120→30→50→90 = 20+90+20+40 = 170 磁道 → $170+4\times5+4\times0.1=190.4$ms。
- 2019 SSTF：簇号 ÷ 1000 = 柱面号 → 100、60、101、110；磁头在 85 → 100(15)→101(1)→110(9)→60(50) = 75 磁道。该题只问次序不问时间，所以就只算柱面距离。
- SSTF 会饥饿；SCAN 是电梯、走到端点（或最大请求）才掉头；CSCAN 方向不变、到端立刻回另一端；LOOK 到最大请求就掉头。
- 按老师口径，真题多半按 LOOK 算（到最大请求就掉头）；题目明确给出磁道号范围（如 0 到 199）时老老实实走到端点。
- 换 Flash/SSD：无寻道无旋转，按到达顺序的 FCFS 最优、最公平（2010 第(3)问的答案）。
- 数格子就画五列：步、当前、下一、移动、累计；每一步都要写，最后一行就是答案。
- 时间占比要有感觉：2010 里寻道 170ms、旋转 20ms、传输 0.4ms —— 机械盘瓶颈全在寻道，所以调度算法只优化寻道，这句话常作为"为什么这样调度"的得分点。
- 若题目给"相邻磁道移动时间 2ms"，就把移动磁道数乘 2；给"每读一个扇区 0.1ms"就直接乘扇区数，不必绕圈数。
- 算 CSCAN 的顺序技巧：先把请求排序，把大于当前磁头的按升序走完，再从最小请求按升序继续走，中间那一段跳跃就是回程。
- 饥饿风险排序：SSTF 最重（远端请求可能永远等），SCAN 次之，CSCAN 与 FCFS 基本没有 —— 选择题常问"哪个会饥饿"。

| 算法 | 服务顺序（磁头 100，向大） | 移动磁道数 |
|---|---|---|
| FCFS | 50、90、30、120 | 240 |
| SSTF | 90、120、50、30 | 130 |
| SCAN（走到 199 端点） | 120、199、90、50、30 | 268 |
| SCAN（真题 LOOK 口径） | 120、90、50、30 | 110 |
| CSCAN | 120、30、50、90 | 170 |

**模板/流水线**
```c
/* 数格子表：步 | 当前 | 下一 | 移动 | 累计（2010 CSCAN 填法）
    1 | 100 | 120 |  20 |  20
    2 | 120 |  30 |  90 | 110   <- 回程，CSCAN 一端直接跳另一端
    3 |  30 |  50 |  20 | 130
    4 |  50 |  90 |  40 | 170          */

/* 算出移动磁道数 d 后统一结算时间（单位 ms） */
double TotalTime(int d, int n, int rpm, int secPerReq, int secPerTrack) {
    double T    = 60000.0 / rpm;                        /* 一圈，6000rpm → 10 */
    double seek = d;                                    /* 相邻磁道 1ms，d 就是 ms */
    double rot  = T / 2.0;                              /* 旋转延迟：半圈 → 5 */
    double xfer = (double)secPerReq / secPerTrack * T;  /* 传输：1/100 圈 → 0.1 */
    return seek + n * (rot + xfer);                     /* 170+4*(5+0.1)=190.4 */
}
```
! CSCAN 漏掉 120→30 这 90 个磁道的回程·旋转延迟按一整圈算（应半圈）·转速 rpm 不换成"每秒圈数"·4 个请求只乘一次旋转延迟（每个请求都要转半圈）

## 磁盘地址与簇号换算
**考频**：2019（7分）｜地址三元组 + 簇号换算，一题三问一次拿满
**必背结论**
- 地址 =〈柱面号，盘面号（磁头号），扇区号〉；柱面号就是磁道号，各盘面上同号磁道组成一个柱面。
- 容量 = 柱面数 × 盘面数 × 每道扇区数 × 扇区大小；2019：$300\times10\times200\times512\text{B}=307200000\text{B}$。
- 每柱面扇区数 = 盘面数 × 每道扇区数 = 2000；每柱面簇数 = $2000\div2=1000$；每磁道簇数 = $200\div2=100$。
- 簇号 → 地址：柱面号 = 簇号 ÷ 每柱面簇数（整除）；余数 $r$ 再 ÷ 每磁道簇数得盘面号；扇区号 =（余数 mod 每磁道簇数）× 每簇扇区数。
- 2019 第(3)问：100530 → 柱面 100，$r=530$ → 盘面 5，$530 \bmod 100=30$ → 扇区 $30\times2=60$。答〈100，5，60〉。
- 反向：簇号 = 柱面号 × 每柱面簇数 + 盘面号 × 每磁道簇数 + 扇区号 ÷ 每簇扇区数。
- 边界校验：簇号 99 与 100 在同柱面不同盘面（一个是〈c,0,198〉，一个是〈c,1,0〉），算完回代一遍最稳。
- 簇号 → 物理地址由 I/O 系统的磁盘驱动程序（设备驱动程序）完成，不是文件系统也不是用户程序。
- 2019 SSTF 只用到柱面号：簇号整除 1000 → 100、60、101、110，调度算法只看柱面。
- 若每簇只有 1 个扇区，簇号就退化成扇区的线性编号，公式照样成立。
- 单位看清：307200000B 约合 293MiB、307MB；题目要 MB 时按题面给的是 $10^6$ 还是 $2^{20}$ 换算。
- 扇区号一律从 0 编号，一个簇占连续 $k$ 个扇区，所以簇在磁道内的起始扇区 = 簇内序号 $\times k$。
- 三步不要合成一条长式子：先整除求柱面、再整除求盘面、最后取模乘 $k$ 求扇区，分步才不会被中间量带错。

| 量 | 2019 的算法 |
|---|---|
| 容量 | 300×10×200×512B = 307200000B |
| 每柱面扇区 | 10×200 = 2000 |
| 每柱面簇 | 2000÷2 = 1000 |
| 每磁道簇 | 200÷2 = 100 |
| 100530 的柱面 | 100530÷1000 = 100 余 530 |

**模板/流水线**
```c
/* 容量：C 柱面、H 盘面、S 每道扇区、sz 扇区大小 */
long long Capacity(int C, int H, int S, int sz) {
    return (long long)C * H * S * sz;              /* 2019: 307200000 */
}
/* 簇号 → 柱面/盘面/扇区，k = 每簇扇区数 */
void Cluster2Addr(long long c, int H, int S, int k,
                  int *cyl, int *head, int *sec) {
    long long perCyl = (long long)H * S / k;       /* 每柱面簇数 1000 */
    long long perTrk = S / k;                      /* 每磁道簇数 100 */
    long long r;
    *cyl  = (int)(c / perCyl);                     /* 100530/1000 = 100 */
    r     = c % perCyl;                            /* r = 530 */
    *head = (int)(r / perTrk);                     /* 530/100 = 5 */
    *sec  = (int)((r % perTrk) * k);               /* 30*2 = 60 */
}
/* 地址 → 簇号（反向核对用） */
long long Addr2Cluster(int cyl, int head, int sec, int H, int S, int k) {
    return (long long)cyl * (H * S / k) + (long long)head * (S / k) + sec / k;
}
```
! 把柱面号答成盘面号（簇号整除得到的是柱面）·扇区号忘乘每簇扇区数（应 60 不是 30）·算每柱面簇数时忘了先乘盘面数·把换算程序答成文件系统或用户程序

## 位示图大小计算
**考频**：2010｜其余以选择出现（2023 选择 25 页框位图、2024 选择 26）
**必背结论**
- 一位管一个盘块（或页框、簇）：位数 = 总块数；字节数 $=\lceil 块数/8\rceil$。
- 2010：16384 块 → 16384 位 = $16384/8=2048\text{B}=2\text{KB}$，正好塞进题目给的 2KB 内存。
- 2010 官方写法：$16384/32=512$ 字，$512\times4\text{B}=2\text{KB}$（按 32 位字组织）。
- 2023 选择 25：页 4KB、物理内存 16GB → 页框 $2^{34}/2^{12}=2^{22}$ 个 → 位图 $2^{22}$ 位 $=2^{19}\text{B}=512\text{KB}$。
- 2024 选择 26：位图法占用的外存空间只与总块数有关，与当前空闲块数无关（位图大小固定）。
- 换算数字：16384 个 4KB 块 → 容量 $16384\times4\text{KB}=64\text{MB}$；131072 个 inode 的位图 $=131072/8=16\text{KB}$；2KB 位图占 1 个 4KB 盘块。
- 按字组织（32 位/字）：$(i,j)$ 从 0 起 → 块号 $=32i+j$；反向 $i=\lfloor 块号/32\rfloor$，$j=块号 \bmod 32$。
- 分配 = 找 0 置 1 并记块号；回收 = 置 0。0 表示空闲、1 表示已用（按题目定义，2026 题面就是这么写的）。
- 找连续多个空闲块（连续分配要的）就顺着位图扫连续 0，扫到就切成一段。
- 与别的空闲管理对比：位图空间固定但整张要占内存/外存；空闲表随碎片变长；成组链接法用栈分批读入。
- 两种单位别混：按位算"位数 = 块数"，按字算"字数 = 块数/32"（字长 32 位）；两种算法的结果必须相等，不等就是字长用错。
- 判断题套路：题目说"用 X KB 内存记录 N 个块"，先用 $X\times8$ 与 $N$ 比，对得上就答位示图，顺手写出位数公式。
- 位图还能反推容量：位数 $\times$ 块大小 = 可管理的总容量，16384 位配 4KB 块刚好 64MB。
- 磁盘位示图与索引结点位示图是两张独立的表（2026 题面明确给了两张），别合成一张算。

| 场景 | 位数（= 块数） | 位图大小 |
|---|---|---|
| 2010：16384 个盘块 | 16384 | 2KB |
| 2023：16GB 内存、4KB 页 | 2^22 | 512KB |
| 2026：2^17 个 inode | 131072 | 16KB |
| 4TB 磁盘、4KB 块 | 2^30 | 128MB |

**模板/流水线**
```c
/* 位示图字节数：N 个块（页/簇） */
long long BitmapBytes(long long N) { return (N + 7) / 8; }
/* 按 32 位字组织：块号 b 与行列 (i,j)，均从 0 起 */
void Block2Pos(long long b, int *i, int *j) { *i = (int)(b / 32); *j = (int)(b % 32); }
long long Pos2Block(int i, int j)          { return (long long)i * 32 + j; }
/* 分配一个空闲块：扫位图，0 为空闲 */
long long Alloc(unsigned int *map, long long N) {
    long long b;
    for (b = 0; b < N; b++)
        if (((map[b / 32] >> (b % 32)) & 1) == 0) {
            map[b / 32] |= (1u << (b % 32));      /* 置 1 = 已用 */
            return b;
        }
    return -1;                                    /* 无空闲块 */
}
/* 回收：map[b/32] &= ~(1u << (b%32)); */
```
! 位图大小按"当前空闲块数"算（应始终按总块数）·字节数忘向上取整·把 16384 位算成 16384 字节·行列编号从 1 起却仍用 32i+j
